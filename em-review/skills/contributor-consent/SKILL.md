# Contributor Consent

muse-spark contributor ティアへの同意は、このスキルを通してだけ記録・撤回できる。
develop フローや review フローの自動処理から呼び出されることはなく、em-review
のどのフェーズドキュメントもこのスキルを参照しない。

対話はガード自身のメッセージと同じ常体（である調）で行う。絵文字・装飾は使わない。

## 手順

### 1. 可用性を確認する

LiteLLM ハーネスの可用性チェックは `references/review-phase.md` の
Phase R0 手順 8 が既に定義している。ここではその定義をそのまま呼び出す —
条件を書き写さない、再実装しない。

`litellm_available` が false のとき、次の行をそのまま出力し、
事実収集・質問・ストアへのアクセスを一切行わずに終了する。

```
vertex-review の LiteLLM ハーネスが見つからない。contributor ティアはこの環境では使えないため、同意の記録は不要。
```

`litellm_available` が true のときだけステップ 2 へ進む。

### 2. 現在の同意状態を確認する

ガード CLI を `--list` で呼び出し、出力の有無で状態を判定する。このスキルは
ストアファイルを直接読まない — 読み取りは常に CLI 経由。

```
python3 "${CLAUDE_PLUGIN_ROOT}"/hooks/muse_guard.py --project-dir "$(pwd)" --list
```

出力が空 → 「未同意」。1 行（プロジェクトキー）が返る → 「同意済み」。

### 3. 対象と事実を提示する

対象を 1 行で示す: 「このリポジトリ」（プロジェクトキーが指す対象）。同意は
リポジトリ単位で、同じリポジトリの別 worktree も同じキーを共有し、同じ記録を
参照する。この対象行は事実の一部ではない — 次に示す 3 つの事実とは別に扱う。

空行を挟んで、提示する 3 つの事実を次の固定順・固定ラベルで示す。

#### 提示する 3 つの事実

1. **リモートの可視性**: public / private / internal / 取得できず
2. **ライセンス**: ライセンス名 / なし（リポジトリに本当にライセンスが無い場合）/ 取得できず
3. **コントリビューター**: あなたのみ / あなたを含む N 名 / 取得できず

事実は機械的に集める。可視性とライセンスはホスティング CLI（例:
`gh repo view --json visibility,licenseInfo`）または同等の手段でリポジトリ
メタデータから取得する。コントリビューター数はリポジトリ履歴から集計する
（例: `git shortlog -sn HEAD | wc -l`、自分だけなら 1）。取得できない事実は
取得できず と表示する — 省略しない、推測しない、会話で聞き直さない。

### 4. 質問を 1 回だけ行う

AskUserQuestion を 1 回だけ、質問 1 件・選択肢 2 件・単一選択で呼び出す。
文言はステップ 2 で判定した状態によって次のどちらかを使う。

#### 未同意のとき

質問: `このリポジトリの差分を muse-spark contributor ティアへ送ることに同意する?`

- 同意する — 同意ストアにこのリポジトリのキーを記録する。以降のレビューで
  contributor ティアが許可される。
- 同意しない — 何も記録しない。contributor ティアは引き続き拒否される。

#### 同意済みのとき

質問: `このリポジトリの contributor ティア同意は記録済み。どうする?`

- 維持する — 記録を変更しない。
- 撤回する — このリポジトリのキーを削除する。contributor ティアが再び
  拒否される。

事実の一部が 取得できず であっても、質問はそのまま行う。事実は判断材料で
あって、質問を打ち切る条件にはしない。

### 5. 回答に応じてコマンドを実行する

同意する → 次のコマンドを実行する。

```
python3 "${CLAUDE_PLUGIN_ROOT}"/hooks/muse_guard.py --project-dir "$(pwd)" --record
```

撤回する → 次のコマンドを実行する。

```
python3 "${CLAUDE_PLUGIN_ROOT}"/hooks/muse_guard.py --project-dir "$(pwd)" --remove
```

同意しない / 維持する → 何も実行しない。

実行したら終了コードを確認し、結果を 1 行で伝える。ストアを再読み込みして
確認せず、再質問もしない。

ストアに触れる経路はこの CLI だけで、ファイルを直接書き換える手段は取らない。

### 6. 無回答・却下は非破壊側として扱う

ユーザーが質問を却下した、または何も答えなかった場合は非破壊側の分岐を取る。
次の行をそのまま出力し、CLI を呼び出さずに正常終了する。

```
同意ストアは変更していない。
```

## このスキルの制約

- インタラクティブなユーザーセッションでのみ実行する。develop フローや
  review フローの自動処理から呼び出すことはない。
- ストアファイルを直接読み書きしない。読み取りは `--list`、書き込みは
  `--record` / `--remove` を自ら実行する。CLI 以外の経路でストアに触れない。
- 提示する 3 つの事実はその場で表示するだけで、どこにも保存しない。
- 非対話モードは提供しない。
