# Task Plan: task0001 — Name-independent per-task-status observation rule for the hook classification pin

## Goal

The hook classification pin observes whether a hook reads per-task status without depending on helper identifier names, so a documented classification that disagrees with the hook implementation fails the pin. Regression tests pin the new rule, including its accepted limits.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR9, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_hook_classification_pin.py` — replace the per-task-status observation rule, remove the name heuristic, rewrite the explanatory text that describes the removed rule, and add the regression tests

## Design

### Observation rule (FR1, FR2, FR3, NFR3)

The observer's contract is pinned in IMPLEMENTATION.md Shared Components (`reads_per_task_status` row). Flow:

1. If `hook_path` does not name an existing file, raise `ClassificationTableError` (existing behaviour, kept).
2. Produce the executable text with the existing `_strip_docstrings` helper (docstrings and comments removed; identifiers and string literals kept). This step is kept as is.
3. Return True when the executable text contains both the substring "workflow.yaml" and the substring "status" (case-sensitive: only lowercase "status" counts); otherwise return False.

Behavioural rules:

- The match runs over the whole executable text. It is not narrowed to string-literal nodes.
- No decision input comes from function names, call relations or reachability.
- The same rule applies to every classification row; there is no per-hook branch (NFR3).

Removal (FR2): delete `_TASK_STATUS_NAME_RE`, the function-name collection (`task_status_fn_names`), the call-name collection (`called_names`), and every import left unused by that deletion (SPEC FR2 names `re`).

The public surface listed in IMPLEMENTATION.md Shared Components keeps its names and signatures.

### Regression tests (FR4-FR8)

Placement: outside `TestHookClassificationPin`, which keeps exactly one test method (NFR3). Put them in the existing observation-test class or in a new dedicated class in the same module.

Every synthetic source:

- is written to a temporary file created through the standard-library temporary-file facility and removed in test cleanup; nothing under `em-workflow/` is written (NFR2);
- is valid Python that `_strip_docstrings` can parse;
- carries "workflow.yaml" in executable code, not only in a docstring or comment.

| Source | Shape | Expected observation |
|--------|-------|----------------------|
| S1 (FR4, FR5) | A helper named `pending_from_workflow` builds a path whose last segment is workflow.yaml, opens it, and extracts each task's status with a line-anchored regular expression for an indented status key. A second function calls the helper. | True. In addition, one classification row that classifies S1's absolute temporary-file path as not reading per-task status, passed to `compare_table_to_sources`, yields exactly one mismatch: (that path, `DOES_NOT_READ_STATUS`, `READS_STATUS`). |
| S2 (FR6) | Modelled on the per-task status read in `em-workflow/hooks/queue_stop_guard.py`, with the helper renamed from `task_statuses_from_workflow` to `statuses_from_workflow`. The helper builds the workflow.yaml path, reads status, and is called. | True |
| S3 (FR7) | Builds a workflow.yaml path and holds status only in uppercase form (for example a constant whose value is the uppercase word). Lowercase "status" appears nowhere in the executable text, including identifiers, string literals and regular-expression text. | False |
| S4 (FR8) | Builds a workflow.yaml path and defines a helper that reads status with a line-anchored regular expression for an indented status key. Nothing calls the helper. | True |

Non-vacuity constraints:

- In S1, S2 and S4, no function name contains "task" and "status" together in one identifier (in either order), so each of these tests would have failed under the removed rule. S4 additionally fails the removed rule's "is called" condition.
- The S3 test asserts, before asserting False, that the stripped text of S3 contains "workflow.yaml" and does not contain lowercase "status", so the False result is attributable to the case-sensitive match.
- The S1 classification row uses the same row shape the existing classification-inversion test in `TestPinIsNotAVacuousCheck` builds. The comparator joins the repository root with the row path, so an absolute temporary-file path is used as is.

### Explanatory text (FR9)
