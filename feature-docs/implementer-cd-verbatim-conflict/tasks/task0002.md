## Design

実行形は IMPLEMENTATION.md の C2 に従う。D3 のとおり、「コマンド全体で cd は 1 つ」とは書かない。

### implementer.md Step 3（Verify the worktree）

- 「cwd は Bash の呼び出し間で残らない」を事実として書く。「リセットされうる」という書き方は使わない。
- git の操作は今のまま `git -C "{worktree_path}"` を使う指示を残す。メイン作業ツリーで素の git commit や merge を実行すると base_branch を変えてしまう、という既存の理由も残してよい。
- テスト・ビルド・フォーマット・merge_script は、`cd "{worktree_path}" && <コマンド>` の 1 回の Bash 呼び出しで実行すると書く。`<コマンド>` の部分は承認された文字列そのままで、環境変数の代入を前置しないと書く。
- 「単独の `cd` 呼び出しを直前に実行する」指示と、「`cd` を `&&` で繋がない」指示を削る。
- 読み書きできる範囲の規則（worktree_path の外を読まない・書かない、例外の列挙）は変えない。

### implementer.md Step 6（Merge）

- merge_script の呼び出しを `cd "{worktree_path}" && "{merge_script}" "{parent_branch}" "{task_id}"` の 1 回の Bash 呼び出しとして示す。
- 「単独の `cd` を実行してから」と「`&&` で繋がない」を削る。
- exit code 0 / 1 / 2 の分岐、3 回の上限、親側採用後の再実行と baseline の更新の文は変えない（`tests/test_implementer_tests_yaml_record_contract.py` が Step 6 の文言を固定している）。

### SKILL.md merge-task.sh contract 節

- 呼び出しの説明を、`cd "{worktree_path}" && "{merge_script}" "{parent_branch}" "{task_id}"` の 1 回の Bash 呼び出しに変える（節の中のコードブロックも同じ形にする）。
- 理由は「cwd は Bash の呼び出し間で残らない。メイン作業ツリーから実行すると違う HEAD をマージする」とする。「単独の `cd`」「`&&` で繋がない」「cwd may have reset」は削る。
- exit code の説明、flock の説明は変えない。

### SKILL.md Command execution gate 節

- 既存の文「Run each `project_commands` string **verbatim** (byte-for-byte).」と「A mutated string no longer matches its approval.」は残す。
- 固定されている文「Never prefix `cd …` or environment assignments」で始まる部分を、新しい規則の文に書き換える。新しい文は次の内容を持つ。許される前置は同じ Bash 呼び出しの中の `cd "{worktree_path}" && ` だけであること、cwd は Bash の呼び出し間で残らないこと、環境変数の代入を前置しないこと。
- deny されたときの規則（再試行しない、notes で報告）と Hard-refuse の文は変えない。
- この節では `(byte-for-byte)` をちょうど 1 回にし、ほかに `byte`・`identical to`・`equal to the line` を書かない（NFR6）。

### 文書全体の制約

- SKILL.md の `AskUserQuestion` の出現数を増やさない（`tests/test_muse_consent_no_new_questions.py` の上限は 1）。
- SKILL.md の Untrusted input 節、Conflict protocol 節、Version exception の文は変えない。
