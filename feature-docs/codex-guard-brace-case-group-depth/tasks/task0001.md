# Task Plan: task0001 — Brace-form case group depth: argument-position `}`, `always` groups, multi-name `function`

## Goal

The substitution reader counts the `{ }` groups of a zsh brace-form case item
body the way zsh does:
- a `{ : }` group whose `}` stands at an argument position no longer leaves an
  interactive launch after the substitution unjudged;
- an `always` group or a multi-name `function` definition no longer makes the
  reader close the statement early and deny a launch that is only quoted text.

## Design

Cross-task rules (layer boundary, edit-once-copy-once, where the added state
lives, row labels) are in IMPLEMENTATION.md and are not repeated here.
"Standalone" below means the pair-stripped standalone-word decision that the
closing words already use: continuation pairs are left out, and an unquoted,
unescaped word stands alone.

### FR1: argument-position `}` in the brace-form item body list itself
- Where it applies: the item body command list itself of a brace-form
  statement. That is the case-statement entry on top of the stack, in the
  body phase, with a brace-form depth value.
- What it applies to: a word that starts with a standalone `}` and is read at
  an argument position. "Argument position" includes redirection targets and
  words inside `[[ ... ]]` (A-6).
- Effect, the same as the command-position `}`:
  - one or more groups open: the depth goes down by one, and the next word is
    at a command position;
  - depth 0: the statement closes as `esac` closes it, and the list that
    holds the statement gets a command position.
- Not counted (A-2, A-7):
  - a `}` in any other list: an in-form body, a subshell, a substitution,
    the top level;
  - a `}` in a function, `for`, `select` or `repeat` name position;
  - a `}` in the middle of a word (`a}`);
  - a word that only starts with `}` (`}a`);
  - a quoted or escaped `}`.
- An argument-position `{` stays an ordinary word.

### FR2: `always` after a group-closing `}`
- Starting `}`: a `}` that closed a group. This covers the standalone
  command-position closing `}` in any command list (p or 8, A-3) and an FR1
  argument-position `}` that lowered the depth.
- Excluded: a `}` that closed a brace-form statement, at a pattern position
  or at body depth 0.
- Condition: the next word comes after only spaces, tabs and continuation
  pairs, and is a standalone `always`. That `always` is read as a reserved
  word, and the word after it is at a command position. In a brace-form item
  body, the `{` after it therefore raises the depth.
- In every other position `always` stays an ordinary word: after a separator
  or a newline, after any other word, quoted, escaped, or as part of a longer
  word (`alwaysx`).

### FR3 / FR4: function names
- FR3, in any command list (A-3):
  - In the function-name state (after the first name of `function`), a word
    for which the command-word decision at a command position gives no kind
    is one more name. The function-name state and the command position are
    kept, so a later `{` or empty `()` ends the head as it does after the
    first name.
  - A quoted name (`function a "b" {`) is such a word.
  - Read as before: a standalone `{` or `}`, the reserved words, the head
    words, `case`, `[[`, an empty `()` and a separator.
- FR4: the standalone `{` right after `function` is zsh's anonymous function.
  It is read in the name position, and the existing special case still
  raises the depth in a brace-form item body.
  - After it the function-name state does not go on, in every command list,
    so the next ordinary word is the first word of a simple command.
