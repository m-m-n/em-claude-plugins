# Task Plan: task0001 — Rewrite the structured-result SSOT and its structural guards

## Goal

`em-workflow/references/batch-terminal-line.md` becomes the sole owner of the
bare eight-key YAML structured result — key set, key order, quoting, escaping,
value domains, reason codes, stop-point coverage, consumer constraints and the
confidentiality boundary — with the legacy prefixed four-field line removed
entirely, and its structural guard module retargeted to the new shape in the

## Design

### What the rewritten SSOT must own

The document is the single definition site (FR1, NFR1). Its nine level-2
sections and their order are fixed by IMPLEMENTATION.md SC2, and
`Stop reason codes` must remain immediately followed by `Stop point coverage`
(an unrelated existing guard slices the document between exactly those two
headings).

| Section | What it states |
|---|---|
| `Purpose` | Why a batch run's terminal state must be machine-readable from the output alone, and that the absence of a result is itself the abnormal-outcome signal (NFR6) |
| `Result format` | The bare-mapping rule (FR2): the final assistant message of a terminal batch turn is one YAML mapping and nothing else — no code fence, no surrounding prose, no document separator, no comments, no extra keys. The key set and key order (FR3, SC1), the double-quoted-scalar rule including the empty value (FR4), and the eight-physical-line invariant with the reason it holds (FR6). That emitting the result needs no external tool and happens only in a batch-mode run |
| `Escaping` | The canonical escaping rule of IMPLEMENTATION.md SC3, as a two-column table plus the residual code-point ranges and the character-by-character / never-re-process statement (FR5, NFR2) |
| `Field values` | One bullet per key, in SC1's order (SC4). `state` and `step` keep their existing domains and every existing precedence rule unchanged in substance (FR13). `reason` names the twelve documented values and marks `context_budget_reached` as never emitted (FR15, D8). `detail` keeps the existing normalization, stated as a step applied BEFORE escaping (FR7), and keeps its non-empty guarantee via the fixed placeholder. `feature`, `branch`, `pr_url`, `resume_conditions` state their derivation rules and empty-string cases (FR9-FR12), consistent with IMPLEMENTATION.md's Canonical derivation outcomes table. The `resume_conditions` bullet states explicitly that `detail`'s normalization is NOT applied to it and that its Markdown newlines, indentation and trailing spaces survive as escapes (FR8) |
| `Stop reason codes` | The unchanged closed set of eleven codes and their eleven meanings, with `none` reserved for the non-stop terminal states, and `context_budget_reached` documented here as the twelfth domain value that em-workflow never emits (FR15, A4) |
| `Stop point coverage` | The unchanged eleven rows, eleven bound codes, third column naming the source document, and the unchanged precedence rule. Plus the named, explicitly-scoped exception sentence stating that exactly one documented code (`context_budget_reached`) has no stop point, intentionally (FR15, D8) |
| `Consumer constraints` | FR14: `stopped` with `none` is rejected; `phase_done` requires `none` and an empty `resume_conditions`; `branch` and `pr_url` must carry no line terminator and no terminal-control code point, with the note that escaping does not help because the consumer rejects the value after parsing; the whole document is at most 64 KiB encoded UTF-8. Plus D7's statement that nothing may be dropped, summarized, counted or pointed-at in order to fit the bound |
| `No result on a wait turn` | The existing general rule, restated for the new shape: a turn that has not reached any terminal state emits no result, with stop condition 5 and the implement launch / wake turns named as instances. Preserves NFR6 |
| `Responsibility boundary` | The existing boundary, with its confidentiality rule extended from `detail` alone to `detail`, `resume_conditions`, `branch` and `pr_url` (NFR5) |

### What must NOT appear

- The literal `EM_WORKFLOW_TERMINAL:`, anywhere (FR16, SC6). It is removed
  from this document, which is its only remaining occurrence under
  `em-workflow/`.
- Any description of a four-field `key=value` line, a prefix, or a dual /
  compatibility emission path.
- Any change to the eleven reason codes, the eleven stop-point bindings, the
  `state` domain, the `step` domain or `step`'s precedence rules (A4, A5) —
  their existing regression guards must stay green with no edit.

### Guard module retargeting

`tests/test_batch_stop_contract.py` is the single module binding this document
(IMPLEMENTATION.md D2, D5). The retargeting:

1. The pinned heading list becomes SC2's nine-heading sequence.
2. The prefix constant stops being a thing the document must contain and
   becomes the literal proved ABSENT from every file under `em-workflow/`. The
   recursive file sweep loses its "only inside this file" carve-out and its
   fenced-block scope test; the non-vacuity grounding becomes "the sweep
   actually read a non-trivial number of files" plus "the constant itself is
   non-empty".
3. The four-field-order assertion is replaced by a structural extraction of
   the key list from `## Result format`, asserted equal to SC1's ordered
   eight-key sequence.
4. New binding assertions (D5): `## Escaping`'s table extracts to SC3's
   canonical mapping; `## Field values` carries one bullet per SC1 key, in
   order; the `resume_conditions` bullet states the not-normalized rule; the
   `detail` bullet states normalization-before-escaping; `## Consumer
   constraints` states each of FR14's five constraints.
5. The `reason` domain assertion grows to twelve documented values while the
   coverage table's bidirectional check stays at eleven, plus an assertion
   that `context_budget_reached` is absent from the coverage table, present in
   the domain, marked never-emitted, and covered by the named-exception
   sentence.
6. The `batch-mode.md` pointer guard's forbidden-literal set becomes SC5, and
   the field-name token check moves from the `key=`-shaped tokens of the old
   line to SC5's full set.
7. Every assertion pinning `state` / `step` domain wording that this change
   does not alter is left untouched (A5).

Each NEW matcher gets a negative proof and a non-vacuity guard, per
IMPLEMENTATION.md's Test authoring convention. Matchers that merely change
their pinned constant (headings, reason-domain size) are pure regression
guards and are exempt.

## Test Notes

- Unit-level (document-structure) assertions dominate: headings, tables and
  bullet extraction from raw file text, reusing the module's existing
  section-splitting and table-row extraction helpers so a literal inside a
  fenced block is still seen.
- The prefix sweep is the one integration-shaped test: it visits every file
  below `em-workflow/` and must stay allowlist-free. Its non-vacuity guard
  replaces the old "the prefix appears in the contract document" test, which
  this change makes false by design — the replacement must prove the sweep is
  doing work, not that the literal exists somewhere.
- Edge case: the escaping-table extractor must distinguish a named token
  (`CR`, `LF`, `TAB`) from a backticked literal character, and must not be
  confused by the backslash characters in the second column. Its negative
  proof forges a table with one mapping altered; its non-vacuity guard proves
  that forged table is otherwise well formed.
- Edge case: the twelve-value `reason` domain and the eleven-row coverage
  table must be extracted by two different extractors; a single extractor
  reused for both would make AC-4's asymmetry untestable.
- TDD order: retarget the module first (it will fail against the old
  document), then rewrite the document until green.
