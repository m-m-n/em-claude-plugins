# Task Plan: task0009 — Re-bind the conformance guards to the contract

## Provenance

- source: `review`
- source_ids: `a6d04e162096915e`, `c370b1ae54e2e93c`
- review_round: 1

Both findings are about the same two modules and the same root cause: the
conformance suite's own copies and samples are not bound to the contract they
claim to verify, so the suite can stay green while verifying nothing. This
feature is documentation plus tests only — the tests are the whole
enforcement mechanism — so a silently hollow guard is the defect itself, not
a cosmetic one.

## Design

### (a) The executed escaping copy is bound to the SSOT (`a6d04e162096915e`, FR5)

The SC3 escaping rule exists in four places: the SSOT's `## Escaping`,
`tests/test_batch_stop_contract.py`'s `SC3_ESCAPING_PAIRS` (bound to the
SSOT), and one executable copy in each of this task's two modules. The
executable copies are the only ones actually applied to produce the documents
PyYAML parses — and neither is bound to anything. A change that updates the
SSOT and its binding module leaves the executable copies on the old rule,
with the suite still green.

Each module that carries an executable copy gains one assertion that its
copy — the direct-escape pairs AND the residual code-point ranges — equals
what the SSOT's `## Escaping` states. Sharing one copy between the two
modules by import is equally acceptable, provided the module that holds it
carries the binding assertion and the other asserts it uses that copy.

Reading the SSOT from these modules is a named, scoped exception to
IMPLEMENTATION.md D5 (recorded as SC12): it is admissible only because
task0008's AC-9 fixes `## Escaping` as byte-identical across this round, so
no concurrent task's unmerged edit can affect what is read.

### (b) Samples and baseline return to the contract (`c370b1ae54e2e93c`, FR13, FR15)

- `reason: "awaiting_user_input"` is not in the SSOT's value domain — the
  string exists only inside these tests. Every occurrence is replaced by a
  code the SSOT's `## Stop reason codes` table actually lists (for a
  `stopped` sample, e.g. `step_stuck`).
- `_baseline_source_values()` combines `state: "completed"` with
  `step: "no-step"`, while FR13 fixes `step` to `retrospect` whenever `state`
  is `completed`. The baseline's `step` becomes `retrospect`.

Both suites are written on the premise that the baseline is otherwise valid
and exactly one violation is injected per case. That premise is what the two
out-of-contract values break, so repairing them restores the meaning of every
rejection case built on them.

- A guard is added asserting that the baseline and the representative samples
  draw `state`, `step` and `reason` only from the SSOT's closed domains, and
  that the completed baseline satisfies FR13's `completed` → `retrospect`
  rule. This is the non-vacuity guard NFR4 asks for, and it is what stops the
  same degradation recurring.

## Test Notes

- The YAML parser import stays guarded exactly as D6 requires; the skip is
  still a FAILED verification item, never a pass.
- `tests/test_structured_result_consumer_constraints.py` currently declares
  in its own docstring that it never reads the SSOT. That docstring must be
  updated together with (a), stating the scoped exception and why it is safe
  — leaving a docstring that contradicts the code is the same class of defect
  this task fixes.
- AC-4's extraction must tolerate the SSOT's Markdown table formatting
  (backticked cells, alignment row) and must fail loudly if the table cannot
  be found, never silently pass on an empty extraction — assert the extracted
  pair count is non-zero as the non-vacuity guard.
- The rejection cases whose baseline changes (`stopped` + `none`,
  `phase_done` without `none`, control characters in `branch` / `pr_url`, the
  64 KiB boundary) must keep asserting exactly one rejection reason each
  after the repair; a case that starts rejecting for two reasons means the
  new baseline is itself invalid.
- TDD order: add the domain guard and the escaping binding first — both
  should fail on the current code — then repair the samples and the baseline.
