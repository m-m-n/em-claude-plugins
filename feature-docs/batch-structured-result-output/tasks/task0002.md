## Design

### "## Terminal line" (FR20, NFR1)

The section is renamed to name the structured result rather than a line, and
keeps doing exactly one job: stating WHEN a result is emitted and that
`references/batch-terminal-line.md` owns the format. It continues to name the
SSOT by path, to instruct a Read of the SSOT immediately before emitting, and
to restate none of SC5's literals — no key-name token set, no `state` value,
no `step` value or sentinel, no reason code, no prefix. The three occasions
(normal completion, every terminating stop, a `--once` phase boundary) remain
described as occasions on which the emission condition holds, not as
additional limits on it.

### "## Batch quiet output" (FR18, FR19, NFR6)

The marker line's own definition is unchanged (FR19): prefix literal
`EM_WORKFLOW_PROGRESS:`, one ASCII space, exactly two `key=value` fields in
fixed order, `phase` then `point`, with their existing domains.

The paragraph that currently justifies prefix disjointness must be rewritten,
because the terminal prefix it compares against no longer exists. The
rewritten paragraph must, without naming any terminal prefix and without
restating any SC5 literal:

1. Name `EM_WORKFLOW_PROGRESS:` (the marker's own prefix is this document's
   to own).
2. Establish non-confusability structurally rather than by prefix comparison —
   a non-terminal turn's whole message is one prefixed marker line, whereas a
   terminal turn's whole message is the structured result the SSOT defines;
   the two message shapes are disjoint, so a consumer applying the SSOT's
   parse to a non-terminal turn's output does not obtain a result.
3. Preserve the "no result = abnormal outcome" signal (NFR6) explicitly: a
   turn that reaches no terminal state produces no result, and a consumer that
   sees no result at the end of a RUN reads that absence as an abnormal
   outcome.

The "Exceptions" bullets that currently say "the terminal line is appended
after it" / "emits the terminal line" are restated in terms of the structured
result, keeping their meaning: Step C's completion report is emitted in full
with the result following it, and a `--once` phase-boundary turn emits the
result and withholds all other narration.

### "## Reporting" (FR17, D7)

The section keeps its existing list of required audit items and adds the value
assignment of IMPLEMENTATION.md SC7: each listed item is carried IN FULL
inside `detail`, and the stop-recovery guidance in full inside
`resume_conditions`. It states that presence by reference — a count alone, or
a pointer alone — does not satisfy this section, and that no new aggregated
report artifact is written because the Audit-item source map already binds
every required item to an already-persisted location. The source map table
itself is unchanged in its rows; it gains the value assignment only.

Naming the two values here is naming two of SC1's key tokens, which SC5 lists
as forbidden. The resolution: this section refers to them as the result's
"human-facing description value" and its "stop-recovery value", citing the
SSOT for their names, so the literal tokens stay out of the file and the
existing whole-file absence guards keep passing. If a reviewer judges that
wording too indirect to be actionable, that is a plan deviation to report,
not to resolve by weakening the guard.

### Guard retargeting (FR22, NFR4, D3)

- `tests/test_batch_quiet_output_discipline.py`: its whole-file absence set
  becomes SC5. It gains one positive matcher over the rewritten
  non-confusability paragraph, asserting points 1-3 above, with a negative
  proof (a forged paragraph that names the marker prefix and claims
  disjointness but drops the absence signal) and a non-vacuity guard (the same
  forged paragraph is otherwise well-formed).
- `tests/test_batch_quiet_output_phase_wiring.py`: its terminal-prefix
  constant is retargeted so the assertion means "this file names no literal
  the SSOT owns" rather than "this file does not contain the old prefix".
- `tests/test_batch_quiet_output_audit_persistence.py`: the pinned
  batch-mode.md sentences that say "terminal line" are updated in this same
  change (FR22); the source-map assertions are extended to require the SC7
  value assignment, with their own negative proof and non-vacuity guard.

This task owns the binding assertion for SC7 (D5): the real `batch-mode.md`
carries the full audit-item list with its value assignment. task0005 declares
the same item list independently and tests containment behaviour against it.

## Test Notes

- All three modules are document-contract tests reading raw file text; no
  runtime behaviour is involved.
- The absence guards are the delicate part: they must be retargeted to SC5
  WITHOUT becoming vacuous. Each retargeted guard needs a proof that its
  literal set is non-empty and that the matcher rejects a forged text
  containing one member of the set.
- Edge case: `batch-mode.md` legitimately uses the ordinary words `completed`,
  `skipped` and `stopped` as workflow.yaml step-status vocabulary. The
  retargeted guards must not false-positive on them — assert the `key=` /
  `key:`-shaped forms and the contract-only tokens, never the bare ordinary
  words, and keep a false-positive proof over a sample using them as status
  words.
- TDD order: retarget the guards and add the new matcher first, then rewrite
  the document until green.
