# Task Plan: task0005 — Derivation-site and audit-containment guards

## Goal

Two new test modules pin the derivation rules for `feature`, `branch`,
`pr_url` and `resume_conditions` across every named site, and pin that every
"## Reporting" audit item is carried in full inside a value rather than by a
count or a pointer.

## Requirements

FR9, FR10, FR11, FR12, FR17, FR22, NFR4

## Scope

### Files to Create

- `tests/test_structured_result_derivation.py` — TS4: the ten derivation
  sites, table-driven.
- `tests/test_structured_result_reporting_containment.py` — TS9: audit-item
  containment, the pointer/count rejection, and the no-new-artifact assertion.

### Files to Modify

None.

## Design

### Derivation sites (FR9-FR12)

The module declares IMPLEMENTATION.md's "Canonical derivation outcomes" table
as its expectation set and exercises a derivation checker against it. Per
IMPLEMENTATION.md D5 the module does not read `batch-terminal-line.md`;
task0001 owns the binding assertion that the SSOT states the same rules.

The checker takes a description of a site — whether the run confirmed or
created the integration branch, whether a slug was ever confirmed, whether a
name was explicitly supplied and whether it matches the slug pattern, whether
Step C created a PR, and the terminal `state` — and yields the four derived
values. The assertions are:

| Group | Assertion |
|---|---|
| `feature` (FR9) | The confirmed slug, or the empty string when no slug was ever confirmed. An explicitly supplied name is usable at a Step 0 abort only when it matches the slug pattern; a non-matching supplied name yields the empty string. No value is ever derived from a task description or from an existing branch — proved by a case where a plausible branch exists and no slug was confirmed, which must still yield the empty string |
| `branch` (FR10) | The integration branch name only when this run confirmed the branch exists or created it; the empty string otherwise, including both the Step 0 git-setup abort and the Step A feature-resolution abort. Constructing the name is not confirming it — proved by a case with a confirmed slug but no branch confirmation, which must yield the empty string. The value is retained after Step C removes the worktree while keeping the branch |
| `pr_url` (FR11) | The bare URL of a PR this run's Step C created successfully; the empty string otherwise. Retained when the run subsequently stops — proved by the created-then-cleanup-failure case and by the verify cap-reached case |
| `resume_conditions` (FR12) | Non-whitespace content only when `state` is `stopped`; the empty string when `state` is `completed` or `phase_done`. A whitespace-only value is treated as empty, not as present |

The ten sites are exactly the rows of IMPLEMENTATION.md's Canonical derivation
outcomes table; the module asserts its own case list covers all ten and that
the list has exactly ten members, so a dropped site fails.

### Audit-item containment (FR17, D7)

The module declares IMPLEMENTATION.md SC7's item list independently as its
expectation set, and asserts:

- a containment checker accepts a sample whose description value carries every
  item of the list in full, and whose stop-recovery value carries the
  stop-recovery guidance in full;
- it rejects a sample in which any single item is replaced by a count
  ("3 commands auto-approved");
- it rejects a sample in which any single item is replaced by a pointer alone
  (a path or an id with no content);
- it rejects a sample in which the stop-recovery guidance sits in the
  description value instead of the stop-recovery value;
- the item list is asserted to have the same number of members as SC7 states,
  so a silently dropped item fails;
- no new aggregated report artifact path appears in this feature's declared
  change set — asserted against the feature's own `workflow.yaml` task `files`
  entries, which is the derivation this SPEC's Declared Change Set section
  points at.

Naming the two values: this module is a test under `tests/`, not a document
under `em-workflow/`, so SC5's restatement ban does not apply to it. It uses
SC1's key names directly.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: the derivation checker produces, for each of the ten sites of
      IMPLEMENTATION.md's Canonical derivation outcomes table, exactly the four
      values that table states; the case list is asserted to hold exactly ten
      members and to cover every site name.
- [ ] AC-2: a confirmed slug with no branch confirmation yields an empty
      `branch`; a plausible existing branch with no confirmed slug yields an
      empty `feature` — proving neither value is ever guessed.
- [ ] AC-3: a Step 0 abort with a supplied name matching the slug pattern
      yields that name in `feature`; with a non-matching supplied name it
      yields the empty string; with no supplied name it yields the empty
      string.
- [ ] AC-4: `pr_url` survives a stop that follows a successful PR creation —
      asserted for both the cleanup-failure case and the verify cap-reached
      case — and is empty for every site where Step C created no PR.
- [ ] AC-5: `resume_conditions` is non-whitespace exactly when `state` is
      `stopped`, and empty for `completed` and `phase_done`; a whitespace-only
      value is rejected as not satisfying "non-whitespace".
- [ ] AC-6: the containment checker accepts a full-content sample and rejects,
      independently, a count-substituted sample, a pointer-only sample and a
      misplaced-stop-recovery sample; the item list is asserted to have SC7's
      member count.
- [ ] AC-7: no aggregated report artifact path appears among this feature's
      task `files` entries in `workflow.yaml`; both modules are discovered by
      `python3 -m unittest discover -s tests` and import the Python standard
      library only.

## Test Notes

- Both modules are pure unit tests over module-local fixtures plus, for AC-7,
  this feature's own `workflow.yaml` — which exists in every worktree, so the
  modules are green inside this task's own worktree (IMPLEMENTATION.md D5).
- Reading `workflow.yaml` for AC-7 must not require a YAML parser: assert over
  the file's task `files` entries using the repository's existing
  standard-library text-scanning convention, so this module stays
  stdlib-only (D6 grants the parser exception to task0004's modules only).
- Edge case: "retained after the worktree is removed" is a statement about
  ordering — the value is derived from what the run DID, not from what still
  exists on disk at emission time. Model the site as a post-removal state and
  assert the value is still present.
- Edge case: a pointer-only presentation and a full presentation can both
  contain the same path string. The rejection must key on the absence of the
  item's own content, not on the presence of a path.
- Edge case: "in full" for a multi-line item (assumptions, take-over guidance)
  means every line present, so the containment check must compare content, not
  a prefix.
- TDD order: write the two expectation tables and the rejection cases first,
  then the checkers until green.
