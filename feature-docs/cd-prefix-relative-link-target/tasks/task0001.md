# Task Plan: task0001 — Judge relative link targets at the resolution stages only

## Goal

In the cd-prefix path check of `em-workflow/hooks/bash_guard.py`, a link
whose target is relative is no longer refused because its target text reads
like `/proc` or `/dev/fd`; it is judged only by the stage checks after being
joined to the directory that holds the link. Absolute targets keep the
lexical refusal, every description of the rule matches the new behavior, and
tests pin the change.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/hooks/bash_guard.py` — the link-target step of the stage walk; the stage-walk docstring; the path item of the module docstring's cd prefix section; the /proc and /dev/fd paragraph of the is_below docstring
- `em-workflow/references/command-execution-protocol.md` — the path item of the Verbatim execution rule
- `tests/test_bash_guard_cd_prefix.py` — added fixture links in Layout, added test cases, an added wording test, a section for this feature in the module docstring

## Design

### Behavior change in the stage walk (FR1, FR2, FR3)

Today `_stage_walk_refuses`, on meeting a link, reads the link's target text
and refuses when that text, read lexically by `_under_proc_or_dev_fd`, is
under /proc or /dev/fd — whether the target is absolute or relative. A
relative text such as `proc`, `./proc` or `dev/fd` is therefore refused even
though it names a location inside the link's own directory.

New flow for a stage that is a link:

1. Count the link against `FOLLOWED_LINK_LIMIT` and refuse beyond it (as
   today).
2. Read the target text (as today; an error while reading is a refusal).
3. Target is absolute (its text starts with `/`): apply the lexical
   /proc–/dev/fd check to the text and refuse when it matches; otherwise
   restart from the root (as today).
4. Target is relative: apply no lexical check to the text. The location
   reached so far — the directory holding the link — stays the base.
5. Put the target's components in front of the remaining components (as
   today) and continue. Every stage reached from those components, including
   the location left after each `..`, passes through the existing per-stage
   check and post-`..` check, which refuse at the first stage under /proc or
   /dev/fd.

Contract of `_stage_walk_refuses` (signature unchanged):

- Precondition: absolute path text (unchanged).
- Postcondition: returns True in exactly the cases it does today, except
  that a relative link target whose text alone reads as under /proc or
  /dev/fd no longer causes a refusal by itself. Such a target is refused
  only when a stage it leads to is under /proc or /dev/fd.

Unchanged (FR4): `FOLLOWED_LINK_LIMIT` and the loop refusal; a resolution
error counts as a refusal, and a missing or non-directory stage ends the walk
without one; the lexical check on the path as written at the start of
`is_below`; the definition of `_under_proc_or_dev_fd`; the parameters and the
caller of `is_below`; no child process; standard-library-only imports.

NFR2: the walk still stops at the first refused stage, so for a relative
target that leads under /proc nothing inside /proc is probed.

### Description updates (FR5)

Four places describe the link-target check. After the change each of them
states: the lexical check of a link's target text applies only to an
absolute target; a relative target is joined to the directory that holds the
link and judged at the resolution stages.

1. The `_stage_walk_refuses` docstring — its clause about following a link
   whose target text is under /proc or /dev/fd.
2. The module docstring, cd prefix section, path item.
3. `command-execution-protocol.md`, Verbatim execution rule, path item.
4. The `is_below` docstring, its paragraph on /proc and /dev/fd. It carries
   the same statement as places 2 and 3, so it is aligned under FR5
   (descriptions match the behavior) as well.

Wording constraints that existing tests depend on:

- In places 2 and 3, every phrase in `PROCESS_DEPENDENT_PATH_NEEDLES` stays
  inside the path item, each as one contiguous phrase after whitespace is
  flattened and the text lower-cased — in particular "the target of each
  link followed" and "final realpath alone". The absolute/relative qualifier
  is added around these phrases, never by splitting one of them.
- The text `/proc/self/root` is not introduced in either place.
- The two-sided path condition wording (logical path, physical path,
  strictly below, otherwise) is left as it is.
- Places 2 and 3 say the same thing.

### Test fixture (tests/test_bash_guard_cd_prefix.py)

Following the module's `Layout` (`procdep/names`, `procdep/links`):

- In `procdep/names/`, which already holds the real directories `proc` and
  `dev/fd`, add three links whose relative targets are `proc`, `./proc` and
  `dev/fd`, and three control links whose absolute targets name the same
  locations: `<names>/proc`, `<names>/./proc` and `<names>/dev/fd`.
- In `procdep/links/`, add a link whose relative target climbs to the root
  with `..` components and then names `proc/self/cwd`. The number of `..`
  is derived from the link directory's own depth (at least as many as its
  path components), never a fixed constant, because the fixture's temporary
  directory depth varies; surplus `..` at the root stay at the root.
- The `Layout` docstring lists the added links.
- The module docstring gains a section for this feature, following the
  per-feature sections already there.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1; TS-1): For the three links in `procdep/names/` whose relative targets are `proc`, `./proc` and `dev/fd`, `is_below(<link>, area)` returns True, and `cd "<link>" && <approved string>` sent through the hook gets the allow decision.
- [ ] AC-2 (FR1; TS-2): For the three control links whose absolute targets are `<names>/proc`, `<names>/./proc` and `<names>/dev/fd`, `is_below(<link>, area)` returns True.
- [ ] AC-3 (FR3, TM-1; TS-3): With the test process's working directory in `procdep/work`, `is_below` returns False for `<climbing link>/shared`, while the fixture guard asserts that this path otherwise names an existing directory strictly below the area.
- [ ] AC-4 (NFR2, TM-1; TS-3): While `is_below` judges the AC-3 path, no file-system probe and no link read is made of a location under /proc or /dev/fd.
- [ ] AC-5 (FR2, TM-2; TS-4): The existing absolute-target tests — the link to `/proc/self/cwd`, the link to `/proc/self` followed by `cwd/<name>`, and the link to `/dev/fd/<N>` — pass with their assertions unmodified, `is_below` returning False.
- [ ] AC-6 (FR4, NFR3; TS-5): `python3 -m unittest discover -s tests` passes with no failure and the same skips as before the change; no existing assertion in `tests/test_bash_guard_cd_prefix.py` or `tests/test_bash_guard_cd_prefix_operators.py` is removed or weakened; the added test code imports standard-library modules only.
- [ ] AC-7 (FR5; TS-5): An added wording test asserts that each of the four places in Design states both halves of the rule (the lexical target check applies to absolute targets; relative targets are judged at the resolution stages), and the existing wording tests (`PROCESS_DEPENDENT_PATH_NEEDLES`, the path-condition wording, the absence of `/proc/self/root`) pass unmodified.

## Test Notes

- Red step: write the AC-1 tests first and confirm that they fail before the
  code change (`is_below` returns False for the three relative forms); this
  is the regression reproduced.
- AC-1 through AC-5 are module-level checks of `is_below`; AC-1 also has one
  hook-level check through the module's existing hook-running case class.
- AC-3 and AC-4 need /proc: use the module's existing skip condition for
  /proc. The relative `dev/fd` case of AC-1 names an in-area directory and
  needs no skip.
- AC-3 uses the same "would have been below" fixture guard as the existing
  absolute-target tests, run from `procdep/work` so that `/proc/self/cwd`
  lands below the area for the test process.
- AC-4: record the paths the walk probes and the links it reads while
  `is_below` judges the AC-3 path, and assert that none of them is under
  /proc or /dev/fd; the recording is limited to the `is_below` call, not the
  fixture guard.
- `Layout` is built by several test classes, so the added links go through
  the module's existing create-once link helper.
- AC-7's wording test is checked against forged text the same way the
  existing wording tests are (a matcher that fires on the statement and
  stops firing when one half is removed).
- The added forms may also be appended to the existing no-child-process path
  list; that test is otherwise unchanged.
