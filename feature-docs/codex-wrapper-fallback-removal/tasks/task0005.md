## Design

### Why this is a task and not a wording correction

`references/rework-task-synthesis.md` Section 9's wording-correction route
requires all three of its conditions. This change fails two of them: it changes
task metadata (`tests/test_reviewer_roles_protocol.py` enters a task's `files`,
which is exactly what makes integrated check 2 hold) and it changes requirement
metadata (TS13 / TS14 join the test mapping). So it is synthesized as a task.

### Integrated check 1, made mechanical (TS13)

The check has two tiers, and both are asserted:

- **Tier A — the surface that must be clean.** Neither removed phrase occurs
  anywhere under `em-workflow/` or `em-review/`. This is stated over the whole
  shipped plugin surface rather than over the four edited documents by name:
  the four documents are what the feature edited, but the property that matters
  is that a user's installed plugin carries neither phrase, and a tree-wide
  statement does not go stale when a fifth document is added later. Enumerate
  the two trees with `os.walk`, following
  `tests/test_reference_sweep.py`'s `_iter_plugin_directory_files`, and skip
  any file whose bytes do not decode as UTF-8 (a `__pycache__` artefact is
  distributed with the plugin per `.claude/rules/core-plugin-structure.md` and
  will be walked).
- **Tier B — containment of the rest.** Every remaining occurrence in the
  repository lies under `feature-docs/`, `test-docs/` or `tests/`. Enumerate
  **git-tracked files** (`git ls-files -z` from the repository root, via
  `subprocess`, following `tests/test_commit_docs.py`'s existing use of git in
  this suite) rather than walking the tree: an untracked sibling integration
  worktree under `.claude/worktrees/` contains a whole copy of
  `feature-docs/...` at a path that Tier B would otherwise have to reject, and
  `git ls-files` is the enumeration that matches what the change-set check in
  check 2 reasons about.

The module necessarily contains both phrases as literals — it is the string's
absence that is being asserted — which is why Tier B admits `tests/` as an
area. `tests/test_reference_sweep.py`'s `SELF_EXCLUDED_PLUGIN_FILE` is the same
situation already handled in this suite.

Tier B's negative proof runs the path-classifying matcher over a forged path
list containing an occurrence at a repository-root path, and over a forged list
whose occurrences are all inside the three areas, so the matcher is shown to
reject the first and accept the second.

### Integrated check 2's durable half (TS14)

The containment failure itself is repaired by declaration: this task's `files`
names `tests/test_reviewer_roles_protocol.py`, which is the only mechanism that
puts a file inside check 2's declared union (a workflow patch appends tasks and
never rewrites task0002's entry, so the declaration lands here). What this task
adds beyond the declaration is the durable record of WHY that module is coupled
to a document it does not own:

- The module declares, as a module-level constant built from its existing
  `PROTOCOL_PATH` / `SCHEMA_PATH` / `REVIEWER_AGENT_PATH` /
  `CODEX_REVIEWER_AGENT_PATH` constants, the set of source documents its
  digests are derived from — no path string is duplicated.
- One sentence states the rule: a task that declares one of those documents in
  its `files` must also declare this module, because an edit to the document
  forces this module's digest to be recomputed.
- The new module reads `tests/test_reviewer_roles_protocol.py` as **text** and
  asserts the declaration names `em-workflow/agents/codex-reviewer.md` and that
  the rule sentence is present. It does not import the module: every module in
  this suite re-declares its constants locally rather than importing another
  test module (`tests/test_wrapper_fallback_doc_realignment.py`'s authoring
  note).

### No-weakening guard, in the baseline direction

The same TS14 module asserts that `tests/test_reviewer_roles_protocol.py`
still declares every test class it declares today (a fixed list of class names)
and **at least** as many 64-hex-digit digest constants as it declares today.
The count is asserted in the not-below direction, never as an equality pin, for
the reason IMPLEMENTATION.md's Version-assertion baseline rule gives: an
equality pin converts the next legitimate addition into a false failure, while
the not-below direction still catches the deletion this guard exists to catch.
No digest VALUE is copied into the new module — copying `788b25fe…` there would
recreate, one level up, the very coupling IC2 is about.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (IC1, FR7/NFR4): the new module asserts that neither
      `whether a fallback provider answered` nor
      `The wrapper's reply may come from a fallback provider` occurs in any
      UTF-8-decodable file under `em-workflow/` or under `em-review/`, and this
      assertion passes against the repository as it stands.
- [ ] AC-2 (IC1): the new module asserts that every git-tracked file in the
      repository containing either phrase has a path whose first segment is
      `feature-docs`, `test-docs` or `tests`, and this assertion passes against
      the repository as it stands.
- [ ] AC-3 (IC1, non-vacuity): the path-classifying matcher behind AC-2 has a
      negative proof — it raises against a forged occurrence list containing a
      path outside the three areas — and a non-vacuity guard showing the same
      matcher accepts a forged list whose occurrences are all inside them. The
      Tier A matcher has the same pair against forged file content.
- [ ] AC-4 (IC2, NFR6): `tests/test_reviewer_roles_protocol.py` declares a
      module-level constant naming the source documents its digests are derived
      from, built from that module's existing path constants, including
      `em-workflow/agents/codex-reviewer.md`, together with the sentence
      stating that a task declaring one of those documents must also declare
      this module.
- [ ] AC-5 (IC2, NFR6): the new module, reading
      `tests/test_reviewer_roles_protocol.py` as text and importing nothing
      from it, asserts AC-4's declaration is present and names that agent
      document; a forged module text missing the declaration is rejected.
- [ ] AC-6 (IC2, no weakening): the new module asserts that
      `tests/test_reviewer_roles_protocol.py` still declares each of the test
      class names it declares today and at least as many 64-hex-digit digest
      constants as today; the count assertion is not-below, not equality; no
      digest value is duplicated into the new module. A forged text with one
      class or one digest removed is rejected.
- [ ] AC-7 (IC2, preservation): the diff to
      `tests/test_reviewer_roles_protocol.py` adds only the declaration and its
      comment — no existing assertion, digest constant, helper or test class is
      changed or removed, and the module's own tests still pass.
- [ ] AC-8 (NFR5): the new module imports only the Python standard library,
      reaches no network and no real provider, and both project test commands
      exit 0: `python3 -m unittest discover -s tests` and
      `python3 em-workflow/hooks/tests/run-destructive-guard.py`.

## Test Notes

- AC-1 and AC-2 pass the moment they are written — the four documents are
  already clean and every current occurrence is already inside the three areas.
  Their value is as regression guards, so the red state to confirm first is the
  matchers' own: AC-3's forged inputs must fail before the matcher is written
  correctly, and each matcher must be run against forged input inside
  `assertRaises`. This is the same TDD-awkward shape
  `tests/test_wrapper_fallback_doc_realignment.py` documents for its
  preservation criteria.
- AC-5 and AC-6 are red before the declaration is added to
  `tests/test_reviewer_roles_protocol.py`; that red state is what proves the
  text-level reader actually reaches the declaration.
- Tier B reads file bytes for every tracked file. Decode with
  `errors="ignore"` or skip undecodable files explicitly rather than letting a
  `UnicodeDecodeError` abort the sweep.
- The `git ls-files` call is the only subprocess in the module; if git is
  unavailable the test should fail loudly rather than silently pass over an
  empty file list (an empty enumeration would make AC-2 vacuously true).
