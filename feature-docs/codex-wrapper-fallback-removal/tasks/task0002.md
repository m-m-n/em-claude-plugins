## Goal

timeout at every invocation site in both plugins, and the consultation
procedure no longer claims the wrapper's own reply may come from a fallback
provider.

## Design

### The nesting

IMPLEMENTATION.md's Timeout nesting contract states the rule; this task
applies it at five locations — two configuration values and three prose
declarations. The caller's value is the maximum the Bash tool accepts, so
there is no headroom above it: the only value that can absorb future growth is
the wrapper's, which is why the margin is taken out of the wrapper's side.

The Bash-tool timeout is a parameter of the tool call, not part of the command
text. It is therefore stated in prose next to the fenced command, and the
fenced command itself is not touched. Restating it as a shell construct inside
the fence would both break the byte-level pin (NFR6) and be wrong.

### The two facts that share one paragraph

The consultation procedure's wrapper-invocation step carries both edits: the
new Bash-tool timeout statement and the removal of the fallback-provider
sentence. They are assigned to one task precisely because they share a
paragraph (IMPLEMENTATION.md D4). Removing the sentence is a deletion, not a
rewrite into the orchestrator's chain walk: that step describes a direct
wrapper call, and no chain walk happens on it, so restating it that way would
document a path that does not exist.

What must survive this file untouched: the Opus escalation prose in its
entirety, the "Unlisted-gate fallback" section name and its rules, every
reference to the routing outcomes, and the untrusted-output rules. Treat the
deletion as a reading task, not a search-and-replace (IMPLEMENTATION.md
Conventions).

### The paired test update

The existing module asserts the sentence is present, in a normalized form
tolerant of line wrapping. After this task the same normalized form must be
asserted absent, from the same section slice, so the assertion keeps proving
something about the consultation procedure specifically and does not decay
into a whole-file substring search. Keep the module's other assertions intact:
they pin unrelated properties of the same document.

### Test module design

All four properties are static text checks over files in the repository:

1. Each configuration file's timeout key reads the wrapper value. Read it as a
   key lookup, not a whole-file substring match, so an unrelated occurrence of
   the number cannot satisfy it.
2. Each of the three invocation sites declares the caller value in
   milliseconds. Scope each check to that site's own section, so one site
   satisfying the assertion cannot cover for another.
3. The nesting relation holds numerically between the two values read in (1)
   and (2) — assert the relation, not just the two literals, so a future edit
   that moves one side without the other fails here rather than in production.
4. Each reviewer prompt's fenced invocation line is unchanged, and the
   em-review wrapper script still shows a single external launch with neither
   fallback marker prefix nor a proxy-profile selection anywhere in its text
   (IMPLEMENTATION.md D6, the positive side of the em-review no-change claim).

Every matcher gets its negative proof against forged text.

## Test Notes

- Every criterion here is a static text assertion; no subprocess and no stub
  is needed. AC-4's byte-level part is delegated to the existing isolation
  module — running it unmodified IS the assertion.
- TDD-awkward point: AC-4 is a "nothing changed" criterion, which a test
  cannot distinguish from "the file was never read". Handle it as the existing
  module already does — assert the exact invocation string is present, and
  prove the matcher fails against a forged variant.
- AC-3 is the criterion worth writing first: it fails today (the values are
  not yet nested) and keeps failing if either side is edited alone, which is
  the regression this feature exists to prevent.
- Edge case: the number 600 appears in prose and comments in several of these
  files. Scope every lookup so an unrelated occurrence cannot satisfy or break
  a check.
