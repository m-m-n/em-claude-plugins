## Design

### R1 content (the single statement)

Inside or directly after the existing bold "Recomputation and comparison
timing" paragraph, keeping that paragraph's existing sentences, R1 states with
the orchestrator as subject:

1. **Condition**: the rule matters for a worker whose `digest_inputs` overlap
   the paths its `write_policy` (targets or allowed write roots) lets it
   write; for any other worker the substitution changes nothing.
2. **Self-write set**: membership per IMPLEMENTATION.md "Self-write membership
   matrix" — the observed change set of the scope verification
   (`references/phases/create-spec-phase.md`, "Scope verification") filtered
   by the covering entry's action; `written_artifacts` never decides
   membership, and neither does a plain intersection with `write_policy`.
   The matrix itself is written out here, once. It maps each action name to
   the change kinds that count as a self-write and cites
   `references/contracts/spec-writer-contract.md` ("The six `write_policy`
   actions") for what the actions mean; it does not restate what each action
   lets the worker do, so the document's opening sentence about not restating
   `write_policy`'s internal structure stays true (adjust that sentence's
   wording only if it would otherwise read as contradicted).
3. **Substitution**: per IMPLEMENTATION.md "Substitution contract"; the
   aggregate comparison is kept; every change outside the self-write set, and
   any change to `value_inputs`, `answers_digest`, `write_policy_digest` or
   `workflow_blob`, still makes the result stale.
4. **Order**: the return-time recomputation runs after the scope verification
   has produced the observed change set (IMPLEMENTATION.md "Return-time
   sequence", steps 1 to 4, stated at rule level, not as site procedure).
5. **Means**: the orchestrator runs `scripts/self-write-digest.py`, writing its
   one JSON input document with its file-writing tool outside the integration
   worktree, never through shell interpolation; an exit code other than `0`
   makes the result stale. The script computes no digest; hashing stays with
   the orchestrator.
6. **Persistence and resume**: the orchestrator persists the dispatch-time map
   and the self-write set per `references/phase-state.md`; on a resumed run it
   takes both from there instead of re-identifying.
7. **Known limit**: when the worker and another actor change the same permitted
   path, the two are indistinguishable; this case rests on the exclusivity
   assumption stated later in the same document.

recomputed from the current input) and adds that the recomputed digest_source
is the one R1's self-write rule substitutes, citing R1 rather than restating
