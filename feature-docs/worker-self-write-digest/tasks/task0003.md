# Task Plan: task0003 — dispatch-site procedures run the self-write script

## Goal

The orchestrator procedures at the three dispatch sites — the design-step
branch, create-plan and rework — record the dispatch-time map, run the
self-write script after scope verification, compare (or validate) with the
substituted digest_source, persist the self-write set, and, on a resumed
create-plan run, apply the persisted substitution.

## Requirements

FR5, FR6, FR7, FR8, FR10, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `tests/test_self_write_digest_wiring.py` — document assertions on the three dispatch-site procedures

### Files to Modify

- `em-workflow/references/phases/create-plan-phase.md` — sections 3, 4, 8 and 9 apply the return-time sequence and the resume substitution
- `em-workflow/references/rework-task-synthesis.md` — section 10 applies the return-time sequence for rework-planner

## Design

Each site cites the rule instead of restating it: `references/contracts/worker-envelope.md`,
Rule R1, "Recomputation and comparison timing" for what to do, and
`references/phase-state.md` for the fields. The steps each site adds follow
IMPLEMENTATION.md "Return-time sequence" and "Phase-state run fields".

### Design step (`skills/develop/SKILL.md`, 「design ステップ分岐」, in Japanese)

- Step 4 (dispatch): when the run's `worker_runs` entry is created in
  `phase-state/design.yaml`, it carries `dispatch_digest_inputs`.
- Step 5 (after the scope verification passes): the orchestrator recomputes
  the current digest_source, runs `scripts/self-write-digest.py`
  (`identify_and_substitute`) per R1, and compares the substituted digest
  with the dispatch-time `input_digest`. A mismatch or a non-zero exit makes
  the result stale, handled by the stale handling the scope verification
  already defines (`references/phases/create-spec-phase.md`, "Scope
  verification"). On a match, layer-5 recording and `self_write_set` go into
  one phase-state write, before the existing artifact verification and status
  transition.

### create-plan (`references/phases/create-plan-phase.md`)

- Section 4: the planner run's `worker_runs` entry carries
  `dispatch_digest_inputs`.
- Section 8: the order becomes scope verification (layer 4) → current
  digest_source recomputed → the script (`identify_and_substitute`) →
  `validate-worker-output.py` run with the substituted digest_source as
  `--digest-source` → layer-5 recording together with `self_write_set`.
- Section 9: the canonical invocation's `--digest-source` is named as the
  substituted digest_source the script returned (the command block itself may
  stay as it is; a sentence after it states this).
- Section 3: the reconcile step's comparison of the recomputed `input_digest`
  with `last_input_digest`, and applying a pending patch on resume, use the
  script's `substitute_only` operation with the persisted fields selected as
  `references/phase-state.md` states; the comparison of artifact bodies with
  their recorded digests stays.

### rework (`references/rework-task-synthesis.md`, section 10)

The "Dispatch input (step 2, all four routes)" paragraph, or a paragraph
directly after it, adds: the run's entry in `phase-state/rework.yaml` carries
`dispatch_digest_inputs`; after scope verification the orchestrator runs the
script per R1 and validates and applies the patch (step 3) against the
substituted digest_source; `self_write_set` is recorded with the layer-5
write.
