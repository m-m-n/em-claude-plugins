# Task Plan: task0001 — self-write digest script and regression tests

## Goal

A standard-library script identifies a dispatch's self-write set and builds the
substituted return-time `digest_source`, and unittest tests reproduce, through
that script, that legitimate designer, implementation-planner and
rework-planner self-writes are not stale while every other change still is.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR10, FR11, NFR1, NFR4, NFR5

## Scope

### Files to Create
- `em-workflow/scripts/self-write-digest.py` — the identification and substitution functions and the CLI
- `tests/test_self_write_digest.py` — unit and scenario tests for the script, including the validator and resume scenarios

### Files to Modify

None.

## Design

The script implements three IMPLEMENTATION.md contracts exactly: "Self-write
script CLI contract", "Self-write membership matrix" and "Substitution
contract". This plan does not restate them.

### Module-level operations (callable from tests by loading the file by path)

| Operation | Inputs | Postcondition |
|---|---|---|
| identify self-writes | observed changes, write_policy, allowed write roots | Returns the ascending, de-duplicated list of paths admitted by the membership matrix. Reads nothing else. |
| substitute self-writes | current digest_source, dispatch-time map, self-write set | Returns a new digest_source per the substitution contract; inputs untouched. |
| identify and substitute | dispatch digest_source, current digest_source, observed changes, write_policy, allowed write roots | Runs the two above, the dispatch-time map being the dispatch digest_source's `digest_inputs`; returns both results. |
| CLI entry | argument vector | Reads the one input document, validates it, runs the selected operation, writes the output object, returns the exit code. |

Input validation happens before any operation runs; every rejection is exit
`2` with a message on standard error and nothing on standard output. An
unexpected exception is caught at the CLI entry and reported the same way.

### Identification flow

1. Build a path-to-target map from `write_policy.targets`; reject a repeated
   path, an unknown action, or a `regenerate` target without `source`.
2. For every observed change whose covering target is not `regenerate`:
   discard it when its path is absolute or has a `..` segment; otherwise look
   up the covering entry (target first, then segment-wise allowed-root
   containment) and admit it when the matrix cell for its kind says member.
3. For every observed change covered by a `regenerate` target: admit it when
   its kind is `modified` and its `source` was admitted in step 2.

### Module docstring

States the CLI contract (as `artifact-digest.py`'s docstring does), and cites
the rule by `references/contracts/worker-envelope.md`, Rule R1,
"Recomputation and comparison timing" — no restatement of the rule beyond the
CLI.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR2, FR3; TS-5, TS-6, TS-7; TM-1, TM-2): Identification returns
      exactly the paths the membership matrix admits. A table-driven test
      covers every cell of the matrix, targets taking precedence over an
      allowed write root, segment-wise containment (a sibling directory whose
      name extends the root's name is not inside it; trailing slash
      irrelevant; the root itself not inside), absolute and `..` paths never
      admitted, a `regenerate` target admitted only when its `source` is
      admitted (and never when the source is itself a `regenerate` target).
      A path that appears only in a worker's `written_artifacts` and not in
      the observed changes is never admitted (the identification has no
      `written_artifacts` input) (TM-1). A modified existing file covered only
      by an allowed write root, a modified `preserve` target and a
      `regenerate` target whose `source` did not change are never admitted
      (TM-2).
- [ ] AC-2 (FR1, NFR1; TS-7, TS-13): Substitution returns an object with
      exactly the current digest_source's top-level members; every member
      other than `digest_inputs` equals the current one; a self-written path
      that was a key at dispatch carries its dispatch-time value; a
      self-written path that was absent at dispatch (for example a `create`
      target) is absent; every other path keeps its current value or absence.
      Inputs are not mutated and repeated calls give identical output.
- [ ] AC-3 (FR1, FR3, FR11; TS-1, TS-2, TS-3): Through identify-and-substitute,
      three scenarios yield a substituted digest_source whose R1-normalized
      digest equals the dispatch-time digest, while the unsubstituted current
      digest_source's digest differs (the pre-fix behaviour): designer
      `extend_only` (`design-system/tokens.yaml` modified under `extend_only`,
      `design-system/tokens.html` modified under `regenerate` with that
      source); implementation-planner re-plan (`IMPLEMENTATION.md`,
      `VERIFICATION.md`, `THREAT-MODEL.md` modified under `replace_own`, a new
      `tasks/task000N.md` created under the `tasks/` allowed write root);
      rework-planner (`IMPLEMENTATION.md`, `VERIFICATION.md` modified under
      `replace_own`, a new file created under `tasks/`).
- [ ] AC-4 (FR4, FR11; TS-4, TS-6): The digest of the substituted
      digest_source differs from the dispatch-time digest when, alongside
      legitimate self-writes, `SPEC.md` (a digest input no entry permits)
      changes; when any one of `value_inputs`, `answers_digest`,
      `write_policy_digest`, `workflow_blob` differs; and when the only
      digest-input change is one of the non-admitted AC-1 cases (an existing
      `tasks/` file modified under the allowed write root alone, a modified
      `preserve` target, `tokens.html` changed without `tokens.yaml`).
- [ ] AC-5 (FR5; TS-2, TS-3): `validate-worker-output.py --kind workflow-patch
      --dry-run-apply`, given as `--digest-source` the script's substituted
      digest_source, reports no `stale-input-digest` error for a
      `replace_planning` patch and for an `append_rework` patch whose
      `base_input_digest` is the dispatch-time digest; given the unsubstituted
      current digest_source instead, it reports `stale-input-digest`.
- [ ] AC-6 (FR6, FR7; TS-8; TM-4): Resume reproduction: a phase-state document
      whose last `worker_runs` entry carries `dispatch_digest_inputs` and
      `self_write_set` (field names per IMPLEMENTATION.md "Phase-state run
      fields") is accepted by `validate-worker-output.py --kind phase-state`;
      `substitute_only` with those two fields and the current digest_source
      reproduces the entry's `input_digest`. After a self-written artifact is
      edited, that substituted digest still matches, but the artifact's digest
      from `artifact-digest.py` differs from its recorded `artifacts[].sha256`,
      so the edit is detected (TM-4).
- [ ] AC-7 (FR10; TM-3): The CLI follows the "Self-write script CLI contract":
      exactly one argument naming the input document (no argument or two
      arguments give exit `2`); both operations produce the documented output
      object with exit `0`; a missing member, an extra member, an unknown
      operation, a malformed `observed_changes` entry, a repeated path or an
      unparsable document gives exit `2` with empty standard output. Paths
      named inside the document need not exist on disk, and no path is ever
      taken from the command line other than the input document's own (TM-3).

## Test Notes

- AC-1, AC-2 and AC-4 are pure unit tests on the loaded module, table-driven
  with `subTest`.
- AC-3 builds each scenario's dispatch and current digest_sources by hand
  (placeholder digest strings are enough; the script never hashes) and
  computes the R1-normalized digest in the test itself, following R1's
  normalization procedure.
- AC-5 and AC-6 run `validate-worker-output.py` and `artifact-digest.py` as
  child processes against files in a temporary directory; reuse the
  validator's existing patch shapes (the `valid-dry-run-apply` fixtures) as a
  starting point rather than inventing a new patch format.
- AC-7 runs the script as a child process with input documents written to a
  temporary directory.
- Edge cases worth covering: an empty observed change set (output equals the
  current digest_source); a self-write path that is not a digest input at all
  (no effect on `digest_inputs`).

## Out of Scope

- Any protocol document, contract or dispatch-site procedure (other tasks).
- Changes to `validate-worker-output.py`, `artifact-digest.py` or
  `check-plugin-invariants.py`.
- Computing any digest inside the script.
- Plugin `version` fields (NFR5): not touched.
