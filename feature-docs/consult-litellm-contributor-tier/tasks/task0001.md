# Task Plan: task0001 — Gate the litellm consultation model on recorded contributor consent

## Goal

The Codex consultation procedure determines `contributor_consented` once per
consultation and picks the litellm invocation from it: the contributor model
when the value is true, the standard model when it is false. A unit test
fails whenever either part disappears from the procedure again.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/references/question-resolution.md` — in the Codex consultation procedure, the litellm item of step 1 (Availability probe) gains the consent determination, and the litellm invocation of step 2 (Wrapper invocation) becomes conditional on it
- `tests/test_consultation_harness_chain.py` — new cases in TestConsultationProcedureChain for step 1, step 2, the fixed value and the fail-closed rule

## Design

### Literals this task's document and tests share

- Step boundaries inside the Codex consultation procedure section: the
  step 1 range runs from `1. **Availability probe.**` up to
  `2. **Wrapper invocation.**`. The step 2 range runs from
  `2. **Wrapper invocation.**` up to `3. **One turn per call.**`.
- Consent-check command: identical to the string pinned by
  CONSENT_CHECK_COMMAND in tests/test_contributor_tier_criteria.py and used
  by review-phase.md Phase R0, namely
  `python3 "${CLAUDE_PLUGIN_ROOT}/hooks/muse_guard.py" --list --project-dir "{project_root}"`.
  The document and the test must not drift from that pinned string.
- Field name: `contributor_consented`.
- Invocations: `--litellm muse-spark-contributor` (the wrapper expands it to
  the litellm provider with the model muse-spark-contributor) and
  `--litellm muse-spark` (expanded to the litellm provider with the model
  muse-spark).

### Step 1: consent determination (FR1, FR3, FR4, TM-1)

The revised litellm item of step 1 states this behavior:

1. The determination runs only when the litellm entry is judged available,
   and it runs before the consultation's first turn.
2. It runs the consent-check command above.
3. Outcome: the command succeeds and prints one line → true. It prints
   nothing, or it fails (non-zero exit, or it cannot run) → false.
4. Failure takes precedence over the one-line rule. A failed run that
   printed one line (for example a single-line error message) still yields
   false (THREAT-MODEL.md TM-1).
5. The value stays fixed for the whole consultation. Every litellm turn of
   that consultation uses it, including turns after a mid-consultation move
   from codex to litellm. It is never re-determined per turn (FR4).

Preserved text (FR3, SPEC.md A-8):
- The chain entry stays `litellm` with the model `muse-spark`. Only the
  reading of that entry changes, not the entry.
- The citation of reviewers.yaml's contributor-tier pre-dispatch criteria
  stays, worded "(cited, not restated)".
- The sentence "the model name written here is never edited to reach that
  tier" stays.
- Step 1 does not restate the contributor-tier rule itself (that consent is
  the only condition). It gains only the determination procedure, the same
  split review-phase.md Phase R0 uses.

### Step 2: invocation (FR2, TM-1)

- Both invocations appear, each tied to the value: true →
  `--litellm muse-spark-contributor`, false → `--litellm muse-spark`. Each
  is shown with the provider/model pair the wrapper expands it to.
- No unconditional single model name remains as the only invocation
  example. The defect was the orchestrator copying the fixed example
  literally and skipping the referenced determination.

### Test cases (FR5, NFR1)

Added to TestConsultationProcedureChain. They use only the Python standard
library.

- Range extraction: cut out the Codex consultation procedure section, then
  the step ranges defined above. Normalize whitespace (collapse every run of
  whitespace) before matching, so line wrapping does not matter. Reuse the
  file's existing section-extraction approach where one exists.
- Step 1 range: contains `contributor_consented` and the consent-check
  command (the pinned string, not a re-typed copy that can drift).
- Step 2 range: contains `contributor_consented`, the contributor
  invocation, and the standard invocation as a standalone flag value. The
  standard string is a prefix of the contributor string, so the
  standard-form check must not be satisfied by the contributor form alone.
  It must find an occurrence that is not immediately followed by the
  contributor suffix.
- Fixed value (FR4): a distinctive fragment of the reuse-across-turns
  sentence, matched in the step 1 to step 2 range (from the step 1 heading
  up to the step 3 heading).
- Fail-closed (TM-1): a distinctive fragment of the failure-precedence
  statement, matched in the step 1 range.

## Test Notes

- Every criterion is a unit test on document text in
  TestConsultationProcedureChain. The TDD order gives AC-5 directly. First
  add the cases. Then run them against the unmodified question-resolution.md
  and record the failures (red). Then revise the document until they pass
  (green).
- Pinned fragments for AC-3 and AC-6: choose the document wording first,
  then pin a fragment short enough to survive line wrapping (after
  whitespace normalization) but specific enough not to match unrelated text
  in the section.
- AC-2's prefix trap: also check the standard-form assertion against a
  contributor-only variant of the step 2 text. That proves it is not
  vacuous.
- If an existing assertion conflicts with the new text (for example, an
  existing check that the procedure never mentions the contributor model
  name), stop and report a plan deviation. Do not edit or weaken the
  existing assertion.
