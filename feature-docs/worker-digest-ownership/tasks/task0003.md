## Design

The owner document `references/artifact-digest.md` and its section names are
fixed by IMPLEMENTATION.md Shared Components; it is produced in parallel, so
this task cites it by path and section name and never restates it.

- **Validator**: the phase vocabulary gains `design`. It is shared by the
  phase-state and question-packet checks and by the gate-ID phase prefix
  helper; the helper attributes a phase only to gates owned by a worker
  contract's "Gate identifiers" section, and no such section names a
  `design.` gate, so the gate registry is unchanged
  (`design-system.reclassify` still resolves to no phase). No other rule
  changes — rejecting `applying_patch` for `phase: design` is not added.
- **phase-state.md**:
  - "File layout" lists `design.yaml`, written by the develop skill's
    「design ステップ分岐」 only when the design step dispatches the
    designer (no file when the step is `skipped`).
  - The `phase` field row includes `design` (still "matches the file name").
  - One statement, placed after the Resume decision table: the designer
    returns no workflow patch, so `design.yaml`'s `status` never becomes
    `applying_patch` and the table's two `applying_patch` rows do not apply
    to it. The table's rows, its two `dispatching` rows and "Legacy feature
    compatibility" are not edited.
  - The `artifacts` row: `sha256` is the digest of
    `references/artifact-digest.md` "Digest definition" — not a git blob
    id — and a value recorded by the earlier git-blob method is handled per
    its "Legacy records".
- **worker-envelope.md**: the `phase` input row adds `design`; "`written_artifacts`
  reporting" adds a citation of `references/artifact-digest.md` ("Layer 5
  recording") for how the orchestrator computes and records digests. The
  sentence beginning "The worker does not compute digests" stays verbatim;
  the token `expect_digest` stays absent from the whole document; the
  Applicability table is not edited.
- **spec-writer-contract.md** "Who verifies `expect_digest`": the heading and
  both pinned sentences stay verbatim, including the line break after
  "cannot" (IMPLEMENTATION.md Shared Components, owner stance sections). The
  middle of the first paragraph is reworded so the verification is stated
  for every dispatch site listed in the owner's "Dispatch sites" — naming
  create-spec, the design step, create-plan and rework — and cites the
  owner's "Pre-dispatch verification" for how it is performed, rather than
  pointing at create-spec-phase.md alone. The second paragraph is left
  unchanged. "How the orchestrator chooses each target's action before
  dispatch" cites the owner's "Calculation" and "Legacy records" for how the
  current digest is computed and compared. No sentence anywhere in the file
  directs the worker to compute, hash, verify or compare a digest
  (IMPLEMENTATION.md Conventions). The "Gate option vocabulary" block is not
  edited.
- **Pin refresh**: `tests/test_gate_option_vocabulary.py`'s validator digest
  pin is updated to the new file digest with a "Refreshed again by
  worker-digest-ownership/task0003" comment describing the `design` phase
  value; `tests/test_validate_worker_output.py` is not edited, so its own pin
  stays valid.
