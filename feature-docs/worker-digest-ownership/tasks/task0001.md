# Task Plan: task0001 — artifact digest script

## Goal

`em-workflow/scripts/artifact-digest.py` exists and is the one
standard-library calculation of the artifact digest, with defined output and
exit behaviour for multiple paths, paths beginning with a hyphen, paths with
spaces or Japanese characters, missing entries, non-regular entries and read
failures.

## Requirements

FR6, FR7, NFR1, NFR3

## Scope

### Files to Create
- `em-workflow/scripts/artifact-digest.py` — the digest script.
- `tests/test_artifact_digest_script.py` — runs the script as a child process
  and checks its output and exit codes.

### Files to Modify

## Design

The script implements IMPLEMENTATION.md "Digest script CLI contract" exactly;
that contract is the specification and is not repeated here.

Processing flow:

1. No argument → usage text on stderr, exit 2, nothing on stdout.
2. For each argument, in order:
   1. No filesystem entry at the path (an empty argument included) →
      element with error `missing`.
   2. An entry that is not a regular file — directory, symlink (dangling or
      not), FIFO, device, socket → error `not_a_regular_file`. The entry is
      never resolved through a symlink and never opened in a way that can
      wait on a FIFO or device.
   3. A regular file → read it in fixed-size chunks and produce the digest.
      The regular-file determination is confirmed on the handle actually
      read, so an entry replaced between inspection and reading cannot make
      the script follow a symlink or block.
   4. A read failure on a regular file (permission denied, I/O error) →
      error `unreadable`.
3. Write the single JSON array (UTF-8 regardless of locale, non-ASCII
   unescaped, trailing newline); exit 0 when no element has an error,
   otherwise 1.
4. Any unexpected internal failure → message on stderr, exit 2, no array on
   stdout.

Other properties:

- No option parsing of any kind; every argument is a path.
- The module docstring states the purpose, cites
  `references/artifact-digest.md` (the protocol-side description of how the
  orchestrator uses the script) and lists the exit codes. It states that this
  digest is not `input_digest` (rule R1) and not a git blob id.
- The file starts with a `python3` shebang consistent with the documented
  `python3 "<path>"` invocation, so the interpreter-mismatch guard hook does
  not reject the call.
- Standard library only; no child process, no external command (no
  `sha256sum`, no `git`).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR7, TS6): For an empty file and for a file containing exactly the
      three bytes `abc`, the element's `sha256` is `sha256:` followed by the
      FIPS 180 sha256 test-vector value for that input, in lowercase
      hexadecimal (64 digits), and the exit code is 0.
- [ ] AC-2 (FR7, TS6): Given several paths (including the same path twice),
      the array has exactly one element per argument, element *i*'s `path`
      equals argument *i* verbatim, order and duplicates are preserved, and
      each element's digest is the digest of that argument's file.
- [ ] AC-3 (FR7, TS6): Files named `-x.md`, `--`, `-` and `--help` are each
      hashed as files (correct digest, exit 0); no argument is interpreted as
      an option and no help or usage text is produced for them.
- [ ] AC-4 (FR7, TS6): Paths containing spaces and Japanese characters (in
      directory and file names) are hashed and echoed so the decoded JSON
      `path` equals the argument; the raw stdout bytes contain those
      characters unescaped as UTF-8, also when the child process runs under a
      non-UTF-8 locale (for example the C locale).
- [ ] AC-5 (FR7, TS7): A path with no entry yields `sha256: null` and
      `error: missing`; the other arguments in the same call still carry
      their digests; the exit code is 1.
- [ ] AC-6 (FR7, TS7, TM-6): A directory, a symlink to a regular file, a
      dangling symlink and a FIFO each yield `error: not_a_regular_file`
      with exit 1, and the call returns well within a short timeout (it never
      waits on the FIFO); a regular file without read permission yields
      `error: unreadable` with exit 1. (TM-6: only regular files are read, no
      symlink is followed, nothing blocks.)
- [ ] AC-7 (FR7, NFR3, TS10): Running with no argument exits 2 with usage
      text on stderr and empty stdout; every module the script imports is a
      standard-library module, and the script imports no process-spawning
      facility.

## Test Notes

- All criteria are unit tests that run the script with the test interpreter
  as a child process, inside a temporary directory.
- AC-1 hard-codes the published test-vector values; it does not recompute
  them with the same algorithm the script uses.
- AC-4 sets the child's locale through its environment.
- AC-6: the FIFO case is skipped only where FIFOs cannot be created; the
  permission case is skipped only when running as root (permission denial
  cannot be produced then) — each skip states its reason. A per-call timeout
  turns a hang into a failure instead of a stuck suite.
- AC-7's import check compares the script's import set with the running
  interpreter's standard-library module list.
- The new test file contains no `subagent_type=` dispatch-looking string.

## Out of Scope

- Path containment or scope checks (layer 4's job); reading paths from stdin
  or a file; hashing directories; computing a git blob id (the legacy method)
  or `input_digest`; any protocol document.
