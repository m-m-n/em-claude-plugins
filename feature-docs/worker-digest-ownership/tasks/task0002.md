## Design

### Owner document

English, titled as an em-workflow SSOT. Level-2 sections, with exactly the
headings pinned in IMPLEMENTATION.md Shared Components:

- **Digest definition** — one definition for `expect_digest`, phase-state
  `artifacts[].sha256` and the layer-5 digest: sha256 of the file's raw
  bytes, `sha256:` + 64 lowercase hex digits. States explicitly that this is
  not the git blob id used by scope verification's post-dispatch comparison,
  and not `input_digest` (rule R1, `references/contracts/worker-envelope.md`);
  `workflow_blob` / `base_workflow_blob` keep their current definitions.
- **Calculation** — the invocation (`python3`, the double-quoted path
  `${CLAUDE_PLUGIN_ROOT}/scripts/artifact-digest.py`, then the target paths);
  the quoting rule of IMPLEMENTATION.md D3 (TM-1); how the orchestrator reads
  the result (positional elements, `path` echo, error tokens) and the meaning
  of each exit code — rendered from IMPLEMENTATION.md "Digest script CLI
  contract", making this section the protocol-side statement of it. Notes
  that the call is not a workflow.yaml command, so the Bash guard hook gives
  no verdict and the normal permission flow applies.
- **Pre-dispatch verification** — when: after the clean-worktree
  precondition and the pre-dispatch snapshot
  (`references/phases/create-spec-phase.md` "Scope verification"),
  immediately before the dispatch (TM-5); which targets: every
  `write_policy.targets` entry whose action requires `expect_digest`
  (`references/contracts/spec-writer-contract.md`, "The six `write_policy`
  actions"); the `expect_digest` values themselves come from the same
  calculation at action-decision time; any mismatch or error element → no
  dispatch, the input is stale, return to the action decision
  (`spec-writer-contract.md`, "How the orchestrator chooses each target's
  action before dispatch"); a `replace_authorized` mismatch re-requests
  approval. The worker never repeats this; the exclusivity assumption
  (`worker-envelope.md`) covers the window to the worker's write, and the
  post-dispatch scope comparison detects any change in it.
- **Layer 5 recording** — after layer 4 passes; one calculation call over
  every `written_artifacts` path; each `{path, sha256, produced_by}` recorded
  into the dispatching phase's phase-state file (`create-spec.yaml`,
  `design.yaml`, `create-plan.yaml`, `rework.yaml`) under
  `references/phase-state.md`'s idempotency rules; a `sha256` the worker put
  in an entry is never read (TM-2); `preserve` targets are not written and so
  not recorded; when `tokens.yaml` and `tokens.html` are both written, both
  are recorded; any error element fails layer 5.
- **Legacy records** — IMPLEMENTATION.md D4 (TM-3): the legacy git blob id of
  the current file is computed with `git hash-object --` (same quoting rule);
  equality after dropping an optional `sha256:` prefix is the only test;
  length or format never decides (a SHA-256 git repository's blob ids are 64
  digits too); a non-match goes to the `{phase}.artifact-overwrite` gate,
  batch following `references/batch-policies.yaml`. Applies to create-spec,
  the design step and create-plan; rework's action choice is unchanged.
- **Dispatch sites** — the registry table below, plus two notes: every
  create-spec re-entry (rework's spec-change transition, tier upgrade) goes
  through the create-spec site; plan-patch permissions, re-planning
  authorization and rework's action choice are unchanged by this document.

### `dispatch_digest_wiring` check

Pure function of the root; reads the owner document and the
registry-named documents only (IMPLEMENTATION.md "Checker extension
protocol"). Flow:

1. Owner document missing → fail.
2. Its `Calculation` section does not contain an invocation of the form
   `python3` + double-quoted path ending in `scripts/artifact-digest.py` →
   fail.
3. `Dispatch sites` registry missing or without rows → fail.
4. For each row: the document exists under `em-workflow/`; a heading whose
   text equals `Section` exists; that section (to the next heading of the
   same or higher level), whitespace-normalized, contains
   `references/artifact-digest.md` and every owner section name in
   `Covers`; and does not contain `git hash-object`. Any miss → fail naming
   document, section and what is missing.
5. For each worker named in the registry: `em-workflow/agents/{worker}.md`
   exists, and the union of `Covers` over its rows contains both owner
   section names. Otherwise → fail naming the worker.

The synthetic helper for `build_passing_repo` writes a minimal owner document
(sections, invocation, a registry naming the fictional `wiring-worker`), the
cited site sections (appending to the synthetic `create-spec-phase.md`
without removing its existing gate-ID and dispatch lines), the
`wiring-worker` agent file, and a dispatch line for it so agent/dispatch
parity still passes.
