# Task Plan: task0004 — Phase R2 / R2b shard dispatch, chain walk and spec rescue

## Goal

Phase R2 measures the review input and dispatches each perspective per shard
within the cap, and Phase R2b walks the chain per shard, routes
`review_data_too_large`, fails the fixed litellm empty results, and runs spec
rescue runs only after spec's full-diff path failed.

## Design

Cross-task rules: IMPLEMENTATION.md D1 (run_id), D2 (shards and cap), D4
(`perspective_count`), D6 (litellm rule), D7 (retryable sets), D8 (spec order and
rescue), D9 (failure handling), D10 (this task owns Phase R2 and Phase R2b).

**Phase R2, new step before the fan-out.** The orchestrator builds the
review-shards input from Phase R0's values: `project_root`, `review_mode`,
`diff_base` (develop-driven: `base_commit`; standalone: `HEAD`; whole-codebase:
null), `changed_files` as validated in Phase R0 step 3, project-relative, and
`perspective_count` per D4. It writes the document and runs the script as the
Conventions state, and keeps the output as the loop-0 pass manifest (D3). A
non-zero exit aborts the review phase (D9). The same step serves develop-driven
and standalone runs, diff and whole-codebase modes, and Phase R4 (task0005 cites
it from Phase R4).

**Dispatch.**
- `split` false: dispatch exactly as today, with the round's full
  `changed_files` and `diff_cmd_quoted` and unchanged Phase R2 run_ids (NFR1).
- `split` true: each non-spec perspective is dispatched once per index in
  `dispatched_shards`. Each shard dispatch carries the same input block, except
  that `changed_files` is that shard's paths, normalized to project_root-based
  absolute paths as today, and `diff_cmd_quoted` is built from those same paths,
  taken from the Phase R0 step 3 validated set, with the same quoting and the
  same command form R0 uses. No input field is added (NFR5).
- Excess shards are not dispatched; Phase R5 discloses them.
- spec is dispatched once on the full diff in both cases (D8).
- All Task calls still go in one message.
- The pinned sentences "Dispatch exactly ONE primary reviewer" and "Exactly one
  primary reviewer runs per selected perspective" stay, qualified as "per shard
  when the round is split".
- The run_id paragraph states the whole D1 grammar, including the Phase R4
  `loop{N}.{chain_index|fallback}` part, and no longer names the form
  `{perspective}#loop{N}`.

**Phase R2b.**
- After the existing opening sentence, a paragraph states that when the pass is
  split, every rule of this section applies per shard: the walk, the "**At most 2
  fallback dispatches per perspective**" budget, the Claude fallback and the
  last-result replacement. A result of one shard never replaces another shard's.
  All perspectives and shards falling back at the same hop go in one message.
- The routing table gains a fourth row: `review_data_too_large` (the assembled
  prompt exceeds the model's context) advancing to the next entry of a
  **different** harness. The three existing rows stay byte-identical.
- The non-retryable paragraph states that a kept skip leaves that unit without a
  completed run and that Phase R5 discloses it.
- The schema-validity paragraph gains the D6 exception. For each schema-valid,
  non-skipped result of a run whose recorded harness is litellm, the orchestrator
  runs the `classify_results` operation (one call per hop). A `failed` result is
  recorded `status: failed`, gets no `skip_reason`, and takes the malformed-result
  path with one Claude fallback. A script failure counts every result of that
  call as failed (D9).
- A spec paragraph states D8: the full-diff path first, and rescue runs only when
  the whole path, Claude fallback included, ends with no completed run and the
  pass is split. Rescue runs are dispatched per dispatched shard, at most
  `shard_cap`, with `spec@s{k}` run_ids, each through the per-shard walk.
  Phase R3a waits until every rescue walk has finished.
- The malformed-result and chain-exhaustion sentences that name
  `unreviewed_perspectives` now name the shard or perspective that ends without
  a completed run, and leave the listing to Phase R5's coverage computation.
- The Axis 2 exclusion keeps "never appears in Phase R5's `unreviewed_perspectives`
  list" and "not a candidate for this section's retryable-`skip_reason` table".
  It replaces the clause about the Claude fallback with: those lists hold only
  Task-dispatched perspectives, and axis 2 is not one.

**README.** The primary-reviewer paragraph keeps "1 体だけ起動", "チェーンの全エントリが利用不可" and
"Claude 汎用レビュアーにフォールバック", and adds that a large review input is split
into shards and each shard gets its own reviewer. The R2b paragraph adds
`review_data_too_large` to the values that jump to a different harness, and says
the hop count applies per shard. Neither paragraph adds "R2b" before the chain
table.

**Pins.** In `tests/test_review_phase_llm_led.py`, only
`test_exactly_three_retryable_skip_reasons_unchanged` changes: it pins the four
rows and a count of four. Every other pinned phrase of Phase R2 and R2b listed in
that module stays present.
