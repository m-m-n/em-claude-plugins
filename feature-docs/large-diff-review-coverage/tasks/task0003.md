# Task Plan: task0003 — Result classification and coverage determination script

## Goal

`em-workflow/scripts/review-coverage.py` decides which schema-valid litellm
results count as failed, and computes `unreviewed_perspectives` and
`partially_reviewed_perspectives` from run_ids, run statuses and shard manifests
alone.

## Requirements

FR3, FR4, FR8, FR9, FR11, FR13, FR14, FR18, NFR3, NFR4, NFR6

## Scope

### Files to Create
- `em-workflow/scripts/review-coverage.py` — the classify_results and coverage operations
- `tests/test_review_coverage.py` — unit tests of both operations

## Design

The interfaces are the two review-coverage rows of IMPLEMENTATION.md Shared
Components. The rules are D1 (run_id), D3 (passes), D5 (coverage), D6 (litellm
empty-result rule) and D8 (rescue runs). The script interface follows the
Conventions section.

**`classify_results`.** Validate that every item has exactly `run_id`, `origin`,
`finding_count` and `summary` with the stated types and an `origin` in the
closed set; otherwise exit 2. Apply D6 with a byte-exact comparison: no
trimming, no case folding, no prefix match.

**run_id parsing.** A run_id has the perspective, the optional shard index, the
optional loop number and the last segment of D1. Shard index and loop number are
integers of 1 or more without leading zeros; the chain index is an integer of 0
or more. Exit 2 for a run_id that does not fit, whose perspective part differs
from the row's `perspective`, that repeats an earlier row's run_id, that names a
loop with no pass, that has a shard index on a pass whose manifest is unsplit, or
that names a shard missing from the pass's `dispatched_shards`. A non-spec run
without a shard index on a split pass also exits 2.

**Input checks for `coverage`.** `perspectives` holds unique names and no
`vulnerability`. Each pass has `loop`, `fixed_files` and `manifest`, loops are
unique, and loop 0 is present. Each manifest has the review-shards output keys.
Every path is project-relative (the Conventions path rules). A row for a
perspective outside `perspectives` exits 2. Rows with `role: evaluator` or
`source: tool` are skipped before any of these row checks.

**Coverage flow.**
1. Group the remaining rows by perspective, shard and loop; the last row of each
   group decides it.
2. For each group ending `completed`, mark the files it covers in its pass.
3. For each perspective and each file of the last pass's manifest, decide
   reviewed or unreviewed with the last-change rule of D5.
4. Classify each perspective as unreviewed, partial or fully reviewed (D5), and
   build each partial entry with its sorted unreviewed files and its reason
   tokens in the fixed order.
5. A spec rescue run is any spec row with a shard index. Its presence anywhere in
   the round adds `spec_rescue` to spec's entry, and makes spec partial even with
   no unreviewed file, unless spec is unreviewed.

Only `run_id`, `perspective`, `role`, `status` and `source` of a row are read.
Any other key of a row, such as a reviewer summary, is ignored.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `classify_results` returns `failed` exactly for origin `litellm`, `finding_count` 0 and a summary byte-identical to one of the two fixed strings; origin `codex` or `claude`, a non-zero count, and summaries with added whitespace, changed case, a prefix or a suffix all return `completed`, and results come back in input order (FR3, TM-5).
- [ ] AC-2: Every run_id form of D1 is accepted; malformed forms (for example a zero shard index, a zero loop, a loop without a chain segment, a missing `#` part, a perspective mismatch) and a duplicate run_id exit 2; `vulnerability#tool` and `evaluator` rows are ignored (FR8).
- [ ] AC-3: Within one pass, a skipped or failed last result of one shard leaves another shard's completed result in effect, and the last row of a group decides it; a perspective whose groups all end skipped (retryable or not) or failed, or that has no row, is in `unreviewed_perspectives` (FR9, FR4).
- [ ] AC-4: A perspective with a completed group and an unreviewed file appears once in `partially_reviewed_perspectives` with sorted `unreviewed_files` and the D5 reason tokens in their fixed order, never in both lists; both lists are present and empty when nothing qualifies (FR13).
- [ ] AC-5: A file changed by the fix of loop N counts as reviewed only through a completed group covering it in a pass of loop N or later; a file no fix changed keeps its earlier coverage; a changed file whose re-review did not complete is unreviewed with `changed_after_review` (FR14).
- [ ] AC-6: A spec rescue run makes spec partial with `spec_rescue` even when every rescue shard completes and even when a later pass's full-diff run completes; spec with only failed rescue groups and no completed run is unreviewed (FR11).
- [ ] AC-7: The output has exactly the two keys; an absolute or `..` path in any input exits 2 and no output path is absolute; extra row keys, such as a summary claiming full coverage, do not change the result; repeated runs on the same document give byte-identical output; the test module uses only standard library `unittest` and checks that the script and itself import only standard-library modules (TM-6, TM-9, NFR3, NFR4, NFR6, FR18).
