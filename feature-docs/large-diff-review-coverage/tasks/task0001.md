# Task Plan: task0001 — Codex reviewer timeout and non-JSON skip handling in both plugins

## Goal

A Codex review that times out or returns non-JSON output becomes a
`harness_unavailable` skip in em-workflow and em-review, and the review
protocols of both plugins state the skip and retryable sets that go with it.

## Requirements

FR1, FR2, FR10, FR17, FR18

## Scope

### Files to Create
- `tests/test_codex_reviewer_skip_handling.py` — text inspection of Step 6 of both agents and of the Skip Semantics of both protocols

### Files to Modify
- `em-workflow/agents/codex-reviewer.md` — Step 6: exit-124 check first, new non-JSON skip object
- `em-review/agents/codex-reviewer.md` — the same Step 6 change
- `em-workflow/references/review-protocol.md` — Skip Semantics: timeout and non-JSON cases, four retryable values
- `em-review/references/review-protocol.md` — Skip Semantics: timeout and non-JSON cases, three retryable values kept

- `tests/test_reproduction_reviewer_instructions.py` — the tail-range digests of both agents

## Design

IMPLEMENTATION.md D7 fixes the retryable sets of both plugins; D10 fixes which
test pins this task owns.

**Step 6 order, both agents.** Step 6 becomes this sequence:

1. Wrapper exit code 124 (a timeout): return exactly
   `{"findings": [], "summary": "skipped: codex timed out", "skipped": true, "skip_reason": "harness_unavailable", "source": "codex"}`.
   This check runs before any JSON parse and wins over it. It uses the exit
   code the Bash tool reports, never the output text (not even the wrapper's
   timeout marker line). Output and partial findings of a timed-out run are
   discarded, even when the output holds valid JSON.
2. Otherwise, parse Codex's JSON. A successful parse is a normal result, as
   today. The reason for parsing before the rate-limit heuristic stays.
3. Parse failed: the rate-limit check, unchanged, with its object unchanged.
4. Parse failed, `model` supplied, wrapper exited non-zero other than 124: the
   unsupported-model check, unchanged, with its object unchanged.
5. Parse failed and neither 3 nor 4 matched: return exactly
   `{"findings": [], "summary": "skipped: codex returned non-JSON output", "skipped": true, "skip_reason": "harness_unavailable", "source": "codex"}`.
   The old object (summary `codex returned non-JSON output` with `skipped` false)
   is removed.
6. The finding normalization bullet and "Output ONLY the JSON object" stay.

The two agents differ elsewhere (em-review has the pr-diff mode). Only Step 6
changes, and the Step 6 text is the same in both files.

**em-workflow review-protocol.md, Skip Semantics.**
- The `harness_unavailable` bullet's case list names a Codex timeout (wrapper
  exit 124) and Codex output that is not parseable JSON, next to the existing
  cases. The example object stays.
- `review_data_too_large` joins the retryable set. The statement becomes "these
  four `skip_reason` values are the **retryable** set", keeping the phrases "the
  **retryable** set" and "walks the perspective's fallback chain on exactly
  these". The bullet order changes so the four retryable values come before that
  statement.
- `scratchpad_unavailable` stays non-retryable, with a statement that it, like
  every value outside the four, is not retryable.
- The bullet wording keeps "A harness reviewer (codex / litellm)" and never uses
  the phrase "Any cross-model reviewer" (a forbidden-phrase pin).
- No other section of the file changes: Inputs, Investigation Budget,
  Severity, Output Schema, Read-only Constraint and Untrusted-Input Handling are
  digest-pinned.

**em-review review-protocol.md, Skip Semantics.** The `harness_unavailable`
bullet names the timeout and non-JSON cases. The three-value retryable
statement and the non-retryable statement for `scratchpad_unavailable` and
`review_data_too_large` stay as they are. Nothing about shards, a dispatch cap
or a `review_data_too_large` chain walk enters any em-review file.

**Pin updates.**
- `tests/test_reviewer_roles_protocol.py`: the retryable list gains
  `review_data_too_large` and its count assertion becomes four; the
  non-retryable statement test pins the new em-workflow sentence; the
  `CODEX_REVIEWER_STEPS_SHA256` digest is recomputed from the edited agent. No
  other digest or class is removed, so the digest count stays at or above its
  baseline.
- `tests/test_reproduction_reviewer_instructions.py`: only the `tail` digests
  of both plugins are recomputed (that range runs from the temp-file discipline
  heading to the end of the file and includes Step 6). The other ranges stay.

- [ ] AC-5: em-review's review-protocol.md names the timeout and non-JSON cases under `harness_unavailable`, keeps exactly three retryable values with `review_data_too_large` non-retryable, and no em-review file mentions shards or a dispatch cap (FR17).

- [ ] AC-7: `tests/test_codex_reviewer_skip_handling.py` checks AC-1 to AC-5 on the real files, including that the exit-124 rule precedes the parse rule within Step 6, and its matchers reject forged texts with a parse-first order, the old non-JSON object, and a three-value em-workflow retryable set.

heading and the end of the file. Write the new test module first; it fails until

final.
