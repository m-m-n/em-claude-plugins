# Task Plan: task0002 — Review input measurement, shard split and dispatch cap script

## Goal

`em-workflow/scripts/review-shards.py` measures the review input per file, splits
it into file-level shards above 200,000 characters, and applies the
per-perspective shard cap, returning only paths, character counts and shard
composition.

## Requirements

FR5, FR6, FR7, FR18, NFR1, NFR3, NFR4, NFR6

## Scope

### Files to Create
- `em-workflow/scripts/review-shards.py` — the measurement, split and cap script
- `tests/test_review_shards.py` — unit tests in disposable git repositories

## Design

The interface is the review-shards row of IMPLEMENTATION.md Shared Components;
the rules are D2 (measurement, split, cap) and D4 (`perspective_count`). The
script interface follows the Conventions section.

**Input validation (before any read or `git` run).** Exit 2 when:
- the document is not a JSON object with exactly the five keys;
- `project_root` is not an absolute path of an existing directory;
- `review_mode` is not `diff` or `whole-codebase`;
- `diff_base` is not `HEAD` or 40 lowercase hex digits in diff mode, or is not
  null in whole-codebase mode;
- `changed_files` is not a list of strings, holds a duplicate, or holds a path
  that is absolute, has a `..` segment, holds NUL, CR or LF, or starts with `-`;
- a path, checked without following symlinks, is not a regular file, or its real
  path is not inside `project_root`;
- `perspective_count` is not an integer from 1 to 24.

**Measurement flow, per file in path order.**
1. Whole-codebase mode: count the content.
2. Diff mode: run `git` on `project_root` for that one file against `diff_base`,
   with an argument list and no shell, an end-of-options separator before the
   path, literal pathspecs, and external diff, text conversion and color turned
   off. Count the output.
3. Diff mode, empty output: count the content instead.
4. Diff mode, `diff_base` `HEAD` in a repository that has no commit yet: count
   the content.
5. Any other `git` failure: exit 2.

Counting decodes bytes as UTF-8 with invalid bytes replaced and counts
characters. Diff text is only counted; it is never written to stdout or stderr.

**Split and cap.** As D2. The output object has exactly the eight keys of the
contract, paths project-relative and in code point order, and a stable key
order, so the same input gives the same bytes in any `changed_files` order.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: In a disposable repository, diff mode counts a tracked modified file by its diff text and an untracked file by its content; whole-codebase mode counts content without running `git`; a renamed file and a binary file get their per-path diff text count; a repository with no commit counts content (FR5).
- [ ] AC-2: A total of 200,000 characters or less gives `split` false and one shard with every path; above 200,000, shards follow path code point order, each holds at most 200,000 characters except a shard holding one file over 200,000 alone, every input path is in exactly one shard, and indexes start at 1 (FR6, NFR1).
- [ ] AC-3: For `perspective_count` 1 to 6 and shard counts below, at and above the cap, `shard_cap` is floor(24 / N), `dispatched_shards` are the first `shard_cap` indexes and `excess_shards` the rest (FR7, TM-3).
- [ ] AC-4: The same input with `changed_files` in different orders gives byte-identical stdout across repeated runs (NFR4).
- [ ] AC-5: The output has exactly the eight contract keys, every path in it is project-relative, and a sentinel string placed only inside a file's changed content never appears in stdout (NFR3, TM-9).
- [ ] AC-6: Each invalid input of the Design exits 2 with a stderr message and empty stdout; a FIFO and a symlink are refused before being opened; a file whose name holds pathspec magic characters is measured as that literal file only; a text-conversion driver configured in the test repository to create a marker file never creates it (TM-1, TM-2).
- [ ] AC-7: `tests/test_review_shards.py` uses only standard library `unittest` and temporary git repositories, and checks that the script and the test module import only standard-library modules (FR18, NFR6).

## Test Notes

- Run the script as a subprocess with one input-document argument, and also load
  it by file path for direct checks, as existing script tests do.
- Every subprocess run gets a timeout, so a script that wrongly opens a FIFO fails
  the test instead of hanging it.
- Large inputs: a few files of 100,000 to 250,000 characters are enough to cross
  both limits. Do not generate load beyond that.
- The rename case commits a file, renames it in the working tree and lists the
  new path; the binary case uses a file holding NUL bytes.
- The standard-library check compares imported top-level module names against
  the interpreter's own list of standard-library module names.
