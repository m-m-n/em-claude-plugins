# Task Plan: task0002 — Command-name allowlist and command-level evaluation triggers

## Goal

The command-level reading of a chunk classifies every simple command's name
by an allowlist instead of the old denylist, reads the arithmetic command as
uncertain, and reads the command-level triggers that re-evaluate a value as
uncertain, so the notion-pair exclusion is dropped for them and `--args-json`
is inspected.

## Requirements

FR1, FR2, FR3, FR5, FR6, FR7, FR8, NFR1, NFR3, NFR4, NFR5

## Scope

## Design

### Classification flow of one simple command (`_args_json_declares_nameref()`)

The signature and the postconditions pinned in IMPLEMENTATION.md Shared
Components hold. Per simple command:

1. Redirections are removed (unchanged).
2. The words before the command name are skipped as today: `VAR=value`
   assignment words, the prefixes `builtin`, `command`, `exec`, `time`, `!`,
   the reserved words `if`, `elif`, `then`, `else`, `while`, `until`, `do`,
   each with its own `--`, and the options of `command` and `time` (a `-v` /
   `-V` read as if `command` ran the word). Each skipped assignment word whose
   target name (the part before `=` or `+=`, any subscript left out) is in the
   integer-attribute set or is `PS4` makes the command uncertain.
3. No word left: certain (unchanged).
4. A command name that cannot be restored: uncertain (unchanged). After FR2
   this includes a word holding an arithmetic command.
5. The restored command name is classified by the table below. A name that is
   not in the table is uncertain.

### Allowlist

| Member | Kind | Uncertain when |
|---|---|---|
| `mcp-bridge` | external command | never, whatever its words |
| `echo`, `:`, `true`, `false` | builtins | never, whatever their words |
| `fi`, `done` | reserved words that close a compound command | never |
| `printf` | builtin | a word before the format word starts with `-` and is not a lone `--` (the `-v` option); the format word's restored text holds a conversion whose conversion character is `n` (`%n`, with flags, width or precision between); an option-position word or the format word cannot be restored |
| `test`, `[` | builtins | a word's restored text is `-v`; a word cannot be restored (it may expand to `-v`) |
| `[[` | keyword | a word's restored text is one of `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge`, `-v` (its operators are never expanded, so restored text decides) |
| `declare`, `local`, `typeset` | declaration builtins | an option word holding `n` (unchanged); an option word holding `i` (FR1); a word that cannot be restored (unchanged); an assignment argument whose target name is in the integer-attribute set or is `PS4`; an argument whose restored text holds a `[...]` subscript that is not digits only, `@` or `*` (the lexer gives a declaration-builtin argument's subscript no region) |

- The list is closed: no other name is added in this feature. Each member is
  a builtin, keyword or external command that changes no shell state,
  evaluates no string and takes no variable name as an argument, or is bound
  by the condition in its row.
- Names outside the list include, among others: `let`, `read`, `getopts`,
  `wait`, `unset`, `set` (so `set -x` and `set -o xtrace` are uncertain),
  `shopt`, `fc`, `history`, `enable`, `compgen`, `complete`, `bind`, `eval`,
  `source`, `.`, `trap`, `alias`, `mapfile`, `readarray`, `export`,
  `readonly`, `for` (so `for ((...))` is uncertain), `select`, `case`,
  `function`, `coproc`, and every unclassified name.
- The name after a skipped prefix (`builtin fc`, `command -- read`,
  `exec unset`, `time let`, `! test -v x`) is classified the same way.

### Integer-attribute set

One named set, next to the allowlist, of the shell variables Bash gives the
integer attribute without any declaration. It holds at least `OPTIND`; the
implementer confirms the other members against Bash itself and records only
confirmed names.

### Arithmetic command (FR2)

`_args_json_declaration_word()` no longer keeps an `arithmetic-command` region
as restorable text: a word holding one is not restorable, as for every other
region that is not a quote. Its docstring drops the "no command name and
declares nothing" sentence and states this instead. So `((...))` is uncertain
wherever a simple command stands: on its own, without blanks, as an `if` /
`while` condition, inside a group, a function body or a loop body.

### Function definitions

A definition's name word stands as a simple command of its own before the
`()` boundary, so it is classified like a call: a name not on the allowlist
makes the chunk uncertain, which covers every call of that function in the
chunk. A function defined under an allowlisted name keeps its body read as
statements of the same chunk (SPEC.md Edge Case Notes). The `function`
keyword form is uncertain through `function`.

### Docstrings and placement

- `_args_json_declares_nameref()`'s docstring is rewritten: the skipped words,
  the allowlist with its conditional members, the declaration-builtin rules,
  the integer-attribute and `PS4` targets, and "any other name is uncertain".
  The denylist sentence goes.
- The allowlist, the integer-attribute set and any helper sit between
  `_args_json_declares_nameref()` and `_args_json_strip_redirections()`
  (IMPLEMENTATION.md Conventions).

### Case table entries (inserted before the first `args-json-quoting-bypass review round 3` entry)

Every entry follows IMPLEMENTATION.md Conventions (label prefix, the notion
call, `rule` on deny).

- TS-2: a value split with `$''{`, and an ANSI-C value, each assigned and
  then evaluated by `(( a ))` before the call: deny.
- TS-3: a value `read` from a quoted-delimiter heredoc, and a value `read`
  from a file, each then evaluated, before the call: deny.
- TS-4 (command level): one deny entry each for `((x=1))`, `if ((a)); then
  :; fi`, `for ((i=0; i<1; i++)); do :; done`, `let a`, `[[` with each of
  `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge` and `-v`, `declare -i`,
  `local -i` inside a function body, `typeset -gi`, a prefix assignment to
  `OPTIND`, a prefix assignment to `PS4`, `declare OPTIND=...`, `set -x`,
  `set -o xtrace`, and `declare 'a[$i]=1'`; plus `let a` inside a `{ }`
  group, an `if` body and a `while` body.
- TS-5: `fc`, `history`, `enable`, `compgen`, `complete` and `bind`, each
  alone, after `builtin` and after `command`: deny.
- TS-6: `printf -v x y`, a `printf` format holding `%n`, `read x`,
  `getopts o x`, `wait -p x`, `unset x`, `test -v x`, `[ -v x ]`, a function
  defined and called in the chunk, and an unclassified name: deny.

### Unit tests

- `TestNamerefDeclarations.test_a_declaration_with_no_nameref_option_does_not_make_the_call_uncertain`
  loses its `'arithmetic command without blanks'` subtest; the same command
  moves to a test that expects KIND_INSPECTED. The docstring of the test it
  left no longer names an arithmetic command (FR7).
- New class directly after `TestNamerefDeclarations`: for each TS-2 to TS-6
  form, the notion call's kind is inspected; for each certain form below, it
  stays KIND_NOTHING with `--session "$SID"`: `echo "$(cat x)"`,
  `printf '%s\n' x`, `test -n x`, `[ a = b ]`, `[[ a == b ]]`, `true`, `:`,
  `if true; then echo a; fi`, `while false; do echo a; done`,
  `command -- echo hello`, `declare -a r`.
- NFR1: a command name that cannot be restored, and a `test` word that cannot
  be restored, make the chunk uncertain.

## Test Notes

- AC-1 to AC-4 and AC-7 are case-table entries with unit counterparts; AC-5
  and AC-6 are unit tests; AC-7 also runs both suites.
- The existing deny entries for `eval`, `source`, `.`, `trap` and `mapfile`
  must keep deny with the denylist gone: they now fall under "any other name".
- Write commands as JSON text; escape ANSI-C sequences, heredoc newlines and
  quotes as the existing round-3 entries do.
- A preceding form must not also contain a current-shell substitution opener
  (`${` followed by whitespace or `|`), or the literal check, not this task's
  reading, decides the entry.
- When an entry's decision comes from a rule other than
  `git-branch-force-delete` (a preceding form the hook asks or denies on its
  own), the preceding form is changed, not the expected rule.
