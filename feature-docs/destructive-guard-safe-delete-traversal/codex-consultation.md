## 合意した点（Codex 回答と requirements-analyst 案が一致）

1. **正規化を安全例外の前に行う**（Q1）
   既存の `normalize_candidate()` を再利用する。`~` / `$HOME` / `${HOME}` の展開、
   `os.path.normpath` による `..` / `.` / 連続スラッシュの畳み込み、先頭 `//` の解消まで。
   `realpath` / `stat` / サブプロセスは使わない。ファイルシステムに触れると、
   安全ルートを指すシンボリックリンクを解決してしまい、塞ごうとしている穴が再び開く。

2. **正規化後も先頭に `..` が残る対象は deny**（Q2）
   静的に「外へ出る」ことが確定するため、既存の `rm-recursive` deny に落ちれば足りる。
   新しい分岐は不要。

3. **前方一致をパスコンポーネント比較に置き換える。ただし 2 クラスの非対称は維持する**（Q3）
   - クラス A（ビルド生成物名: node_modules / dist / build / target / .next / coverage）
     — 完全一致とその配下を安全とする
   - クラス B（スクラッチルート: /tmp / /var/tmp / tmp / .cache）
     — 真の子孫のみ安全とし、ルート自身は deny のまま
   非対称を崩すと、クラス B を緩めれば `tmp` / `.cache` / `/var/tmp` の deny が allow に落ち、
   クラス A を締めれば `node_modules` 単体の allow が deny に落ちる。どちらもピン留め済み。

4. **安全ルート一致を ask に降格しない**（Q5）
   `ask` は無人実行で `deny` に降格されるため、誤爆 1 件が走行をその場で止める。
   正規化とコンポーネント比較で危険な false-allow は既に消えており、降格は不要なコスト。

5. **攻撃 3 件と維持すべき deny 3 件の判定**（Q6）
   `/tmp/../home/sakura/valuable` → `/home/sakura/valuable` で deny、
   `build/../src` → `src` で deny、`targets` はコンポーネント不一致で deny。
   `tmp` / `.cache` / `/var/tmp` はクラス B のルート自身なので deny のまま。

## 食い違った点と採用した判断（Q4: DYNAMIC との順序）

- **Codex の回答**: SAFE_DELETE を DYNAMIC より先に判定する現行順序を維持する。
  DYNAMIC を先にすると `*` にマッチするため、ピン留めされた `dist/*` の allow が
  ask に落ちてしまう、という理由。

- **却下した根拠（ケース表の実測）**: Q1 の正規化と組み合わせると、この順序は
  ケース表 110 行・112 行を `ask` から `allow` へ退行させる。

  ```
  110: ask  rm -rf /home/sakura/$DIR/../../../tmp/y
  112: ask  rm -rf ~/$DIR/../../../tmp/y
  ```

  `normpath` は `$DIR/../../../` を字句的に畳み込むため、正規化後の対象は `/tmp/y` になる。
  これはクラス B の真の子孫なので、SAFE_DELETE を先に見ると allow になる。
  `$DIR` の実際の値は静的に決まらないので、これは判定してはいけない形。

- **採用した設計（requirements-analyst の FR-06 / A-03）**: DYNAMIC を
  「脱出しうるか」で 2 分し、安全例外との順序をその区分ごとに決める。
  - 変数展開・コマンド置換（`$VAR` / `${VAR}` / `$( )` / バッククォート）を含む対象は
    安全ルート配下に見えても安全例外に通さず、既存の ask(rm-unresolvable) に落とす
    → 110 / 112 行が ask のまま維持される
  - 純粋なグロブ（`*` / `?` / `[`）は安全例外に通す。グロブは `..` を生成しないため
    安全ルートから脱出しない → 132 行 `dist/*` の allow が維持される
  - ただし `..` に一致しうるドット始まりのグロブ成分（`/tmp/.*` 等）は例外に通さない

- **結論**: Codex の一律順序維持案は `dist/*` を守るが `/tmp/$FOO` 系の脱出を残す。
  2 分割案は両方を満たすため、比較して優れているこちらを採用する。
