# Task Plan: task0002 — Register the Stop hook on every run_codex_exec.sh launch path

## Goal

On every launch path, both `run_codex_exec.sh` wrappers register
`codex-hook-tty-reaper.py` as a Codex Stop hook, with the wrapper's own PID as
the anchor. The PreToolUse registration and the wrapper's existing contract
stay unchanged. The wrapper argument test covers the new registration.

## Requirements

## Design

### Registration value (IMPLEMENTATION.md S1, S2, D1, D2)
- Hook path: the wrapper's own directory (`SCRIPT_DIR`) joined with
  `codex-hook-tty-reaper.py`. It never depends on the caller's working
  directory, and the wrapper does not check that the file exists.
- Command: `python3`, a space, the hook path single-quoted for a POSIX shell
  (the existing quoting helper), a space, the anchor.
- Anchor: the PID of the wrapper's main shell process, which is the process
  that later waits on the launch. Never use the PID of a subshell that runs
  while the value is being built.
- Value: one `-c` argument. It starts with `hooks.Stop=` and holds a TOML
  array of exactly one group. The group has no matcher and holds exactly one
  hook, of type `command`. That hook's command is the command above, written
  as a TOML basic string with the existing encoding helper.
- Placement: the value joins the existing hook flag group, next to the
  PreToolUse registration. This way it reaches both routes and both modes,
  never lands between `-p litellm -m MODEL`, and comes before the prompt. The
  existing single `--dangerously-bypass-hook-trust` covers both hooks and is
  not repeated.
- D1 constraint: the wrapper starts no other process that lives at the same
  time as the codex launch.
- Comment block next to the existing "Interactive-guard hook" block. It
  covers: what the Stop hook does, that its argument is the wrapper's PID used
  as the anchor, and that a missing hook file only means no reaping.

### Unchanged (NFR3, FR6)
- Usage text, accepted flags and error messages. em-review still rejects
  `--litellm`.
- `codex exec` is launched exactly once.
- `--dangerously-bypass-hook-trust` appears exactly once.
- em-workflow keeps capturing standard output and standard error separately,
  with no `2>&1`. em-review keeps its single `2>&1`.
- The prompt is the last argument.
- The isolation flags: `--ignore-rules`, and `--ignore-user-config` except on
  `--litellm`.
- The reasoning-effort and OpenTelemetry overrides.
- The `--litellm` launch home.
- The PreToolUse registration of `codex-hook-interactive-guard.py`.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR2, TM-2): The launch paths are: em-workflow default readonly and readwrite, em-workflow `--litellm` readonly and readwrite, and em-review readonly and readwrite. On each, the argv recorded by the stub holds exactly one `-c` value starting with `hooks.Stop=`. That value parses as TOML into an array of exactly one group, with no matcher and exactly one hook of type `command`. Executed through `sh`, `bash` (and `zsh` when present), that command runs `python3` with exactly two arguments. The first is the absolute path of `codex-hook-tty-reaper.py` in the same plugin's `scripts/`. The second is the decimal PID of the wrapper process itself, which is the TM-2 anchor.
- [ ] AC-2 (FR2): The Stop hook path comes from the wrapper's own location. It does not change when the caller's working directory is the other plugin's `scripts/`. Neither plugin's value names the other plugin's directory. A launch from a `scripts/` copy that lacks the hook file still invokes the stub exactly once.
- [ ] AC-3 (TM-6): Copy each plugin's `scripts/` directory, with `references/codex-cli.yaml` beside it, under a path that contains a space and a single quote. For the em-workflow default path and the em-review path, also use the existing set of hostile directory names. In every case the `hooks.Stop=` value still parses as TOML, and the command passes exactly two arguments to `python3`: the copied hook path and the wrapper's PID.
- [ ] AC-4 (FR6): On every launch path, the existing PreToolUse checks still pass unchanged: exactly one `hooks.PreToolUse=` value, matcher `Bash`, and a command naming the same plugin's `codex-hook-interactive-guard.py`.
- [ ] AC-5 (NFR3): The wrapper contract is unchanged. `--dangerously-bypass-hook-trust` appears exactly once. Usage text and error messages are unchanged, and em-review still rejects `--litellm`. Each run invokes the stub exactly once. The em-workflow wrapper text has no `2>&1`, and em-review keeps exactly one. em-review has `codex exec` once across its non-comment lines. The prompt is the last argument. `-p litellm -m MODEL` stays adjacent. The isolation flags and the reasoning-effort and OpenTelemetry overrides are still present.
- [ ] AC-6 (NFR4): Every wrapper run goes through the existing harness, with a stub `codex` first on PATH and an isolated HOME. The module imports only standard-library modules. The tests never execute the Stop hook and never require its file.

## Test Notes

- Extend the existing module and reuse its harness and copy helper. Update
  its module docstring to cover the Stop registration.
- Add a Stop-value checker beside the existing PreToolUse checker, with the
  same style of non-vacuity proofs. It must reject: a missing value, two
  values, a matcher present, two groups, two hooks, a non-command type,
  another plugin's path, an unquoted path, and a missing, extra or
  non-decimal anchor.
- Anchor check: the test must be able to observe the wrapper's process ID,
  that is, the shell process that runs the wrapper script. Execute the
  recorded command through each available shell, with the existing recorder
  in place of `python3`. The arguments received must equal the hook path
  followed by that process ID in decimal.
- The Stop hook file does not exist in this task's worktree (IMPLEMENTATION.md
  D3). Its absence is expected and is part of AC-2.
