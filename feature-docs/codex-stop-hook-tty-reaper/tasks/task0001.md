# Task Plan: task0001 — Stop hook that stops terminal-bound Codex descendants

## Goal

Deliver `codex-hook-tty-reaper.py` as two byte-identical copies, with its unit
tests. At the end of a Codex turn the hook stops every descendant of the
anchor process whose standard input is `/dev/pts/*`, children first. It never
signals any other process and never disturbs the Codex stop.

## Design

### Interface (IMPLEMENTATION.md S1, S2, D1, D2)
- Inputs: the command-line argument list (the anchor), standard input (the
  Stop payload Codex writes), and the process table under `/proc`.
- Effects: SIGTERM / SIGKILL to targets only. Exit status is always 0.
  Nothing is written to standard output or standard error.

### Processing flow
1. Read standard input until end-of-input, for at most a fixed limit of
   1 second. If it does not complete within the limit, is not UTF-8, or is not
   one JSON object, stop nothing. No field of the object is used after this
   check (TM-1).
2. Accept the anchor only when the argument list is exactly one argument made
   of ASCII digits `0`-`9` only, with a value greater than 1. Otherwise stop
   nothing (TM-2).
3. If the process table is unavailable (its location is missing, or the
   hook's own entry cannot be read), stop nothing (NFR5).
4. Walk the hook's own ancestor chain through parent links up to PID 1. Stop
   nothing if any link of the chain cannot be read, or if the anchor is not on
   the chain as a proper ancestor (TM-2).
5. Take one snapshot of the process table. For every process, record its
   parent, state, start time, and the target of its standard-input link (file
   descriptor 0). Read parent, state and start time from after the last
   closing parenthesis of the process-name field, so a name containing spaces
   or parentheses cannot shift them (TM-4). Leave out any entry that vanishes
   or cannot be read: such an entry never adds a target.
6. The targets are the anchor's descendants (following parent links in the
   snapshot) whose standard-input link names a path under `/dev/pts/`, minus
   the hook itself and every process on its ancestor chain. Session, process
   group and whether the process has children play no part (FR3, FR7). For
   each target, keep its PID, its recorded start time and its depth below the
   anchor.
7. Order the targets by depth, deepest first, with ties broken by ascending
   PID. Every target then comes after all of its target descendants (FR4).
8. SIGTERM phase: go through the targets in order. Confirm each is still the
   same process (entry present, start time equal to the recorded one, not a
   zombie), then send SIGTERM. A no-such-process result is not an error.
   A target that is not the same process gets no signal now or later (TM-3).
9. Wait phase: wait until every target that received SIGTERM is gone (entry
   absent, zombie, or start time changed), or until 0.5 seconds have passed
   since the last SIGTERM, whichever comes first.
10. SIGKILL phase: go through the targets in the same order. Run the same
    identity check, and send SIGKILL to each target that is still the same
    process and not a zombie (FR4, TM-3).
11. Exit with status 0 and no output.

Failure policy (FR5, TM-5): any unexpected error at any step ends the run. No
further signal is sent, the exit status is 0 and nothing is written. Two
things are not failures: a no-such-process result while signalling, and an
entry that vanishes during the snapshot.

### Time bound (NFR2)
The phases are fixed: a standard-input read of at most 1 second, one snapshot
of the process table, and one wait of at most 0.5 seconds. In the TS-5
real-process setting, the tests require the hook's wall-clock time to stay
under 3 seconds.

### Test seams
The hook's main routine can be driven in-process with three substitutable
collaborators: the location of the process table (default `/proc`), the
signal sender, and the clock / sleep. The command-line entry always uses the
real ones. No argument, environment variable or standard-input field selects
a substitute (NFR6). Importing the script performs no action: the run happens
only on command-line execution.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR2, NFR5): `em-workflow/scripts/codex-hook-tty-reaper.py` and `em-review/scripts/codex-hook-tty-reaper.py` both exist and are byte-identical. The script imports only standard-library modules.
- [ ] AC-2 (FR3, FR7, TM-4): The anchor is a pseudo-Codex process the test started. These descendants with a `/dev/pts/*` standard input are all stopped: one that has a child, and one that runs in its own session and process group (as a detached background process would). A descendant whose standard input is a pipe receives no signal. TM-4: in a fabricated process table, a process whose name field contains spaces and parentheses that imitate the following fields keeps its real parent and start time. As a result, an outsider with such a name is not targeted, and a descendant with such a name still is.
- [ ] AC-3 (FR3, FR4): A parent with a `/dev/pts/*` standard input and its child with the same kind of standard input are both stopped. In the signal sequence observed in-process (recording sender over a fabricated process table), each target's signal comes after the signals of all its target descendants, in both the SIGTERM and the SIGKILL phase.
- [ ] AC-4 (FR4, NFR2, TM-3): Every target receives SIGTERM. A target still alive 0.5 seconds after the last SIGTERM receives SIGKILL, and never earlier: observed in-process with a fake clock. A real process that ignores SIGTERM is gone when the hook exits, and the hook's wall-clock time is under 3 seconds. TM-3: if a target's start time differs from the one recorded at enumeration (PID reused), it receives no SIGTERM, or no SIGKILL, from that point on.
- [ ] AC-5 (NFR1, NFR6, TM-2): None of the following receives a signal: a process with a `/dev/pts/*` standard input outside the anchor's tree, including the descendants of a second, parallel pseudo-Codex; and an ancestor of the hook with a `/dev/pts/*` standard input, including the anchor itself and the processes between the anchor and the hook. TM-2: the hook signals nothing when the argument is missing, when there are two or more arguments, when the argument contains anything other than ASCII digits (a sign, whitespace, a hex prefix, non-ASCII digits), when it equals 1, or when it names a process that is not a proper ancestor of the hook (for example, the parallel pseudo-Codex).
- [ ] AC-6 (FR4, FR5, NFR6, TM-1, TM-5): On every path the hook writes nothing to standard output or standard error and exits 0. A target that ended after enumeration (no-such-process) is not an error, and the remaining targets are still processed. Standard input that is not one JSON object (empty, malformed, a JSON array, not UTF-8) stops nothing. TM-1: a JSON object whose fields name other process IDs or paths yields exactly the same targets as an empty JSON object. TM-5: if standard input is kept open without end-of-input, the hook stops nothing and exits within the time bound. An unexpected failure (an unreadable or garbled entry on the hook's own ancestor chain, or a signal error other than no-such-process) leads to no further signal.
- [ ] AC-7 (NFR5): When the process table is unavailable (in-process, a process-table location that does not exist), the hook signals nothing and exits 0 without output.

## Test Notes

- Real-process tests (AC-2, AC-4, AC-5, and the open-stdin case of AC-6):
  the test starts a pseudo-Codex process tree itself. It gives the chosen
  descendants a pseudo-terminal as standard input and the others a pipe. It
  then runs the hook as a separate process that descends from the
  pseudo-Codex, with the pseudo-Codex's PID as the anchor and, unless the
  case says otherwise, a closed standard input that holds a JSON object.
  Afterwards the test checks which of its processes are gone.
- Every process a test starts has a bounded lifetime of its own (it exits by
  itself within a few seconds), so a failed test leaves nothing running.
  Survivors such as the pipe-stdin descendant are reaped by the test that
  started them.
- In-process tests (AC-3 ordering, the AC-4 fake clock and PID reuse, the
  AC-6 failure paths, the AC-2 forged name field, AC-7): use a fabricated
  process table in a temporary directory, a recording signal sender and a
  fake clock. No real signal is sent.
- Anchors are always processes the test started, never the test runner or
  anything above it (NFR4).
- Real-process tests are skipped, with a stated reason, only when the
  platform has no `/proc` or cannot allocate a pseudo-terminal.
- The in-process tests load the hook from its file path with bytecode writing
  disabled.
- The test module's own imports are standard-library only, checked the same
  way `tests/test_codex_hook_wrapper_args.py` checks its imports (TS-14).
- TS-2 is a byte comparison of the two copies.
- Naming follows `test/README.md`.
