## Design

### Function-name recognition (the parser's `_names_function`)

Input: the ordered words of the simple command in progress, read just before an opening parenthesis. Each word carries its text and a dynamic flag. Output: whether those words name a function.

Reserved words for this rule are exactly nine: `!` `do` `elif` `else` `if` `then` `time` `until` `while`. A word matches only by its text, and a dynamic word never matches. Quoted spellings such as a quoted `then` also match, because a word does not record whether it was quoted. Such input is a bash syntax error and never runs.

Flow:
1. Start at the first word. While the current word is a non-dynamic reserved word, step past it.
   - When the word stepped past is `time` and the next word is a non-dynamic `-p`, step past that `-p` as well, then go on stepping past reserved words (`time -p ! f` leaves `f`).
   - Only the single `-p` right after `time` is removed. A second `-p`, or `--`, is not.
2. Removal stops at the first word that is not a reserved word. A reserved word later in the sequence is never removed (`echo then f` keeps three words).
3. If no word remains, judge the original, unstripped sequence by the existing rule. `then` alone is one word, so it names a function. `time -p` is two words, so it does not.
4. Otherwise apply the existing rule to the remaining words. They must be exactly one word, or `function` followed by one word. The name must not be dynamic and must not contain `=`.
5. Return true exactly when step 3 or step 4 accepts.

Constraints:
- Removal is a view over the words, used only inside this recognition (FR4). The parser's own word list, and the words recorded for each simple command, are not modified. The judgment of simple commands is unchanged.
- The pass walks the leading words once and never rebuilds the remaining sequence for each removed word. Its cost is linear in the number of words (NFR4, THREAT-MODEL.md TM-2).
- The function's own description is updated to match this behavior.
- The existing case-keyword detection used inside substitutions keeps its own word list and behavior.

### Documentation (FR6)

Module docstring step 4 and the group `head` attribute description must state four things:
- The words before `(` are judged after the leading run of the nine reserved words is removed.
- A non-dynamic `-p` right after `time` is removed with it.
- When nothing remains, the original words are judged.
- The "three words or more" wording counts the words left after removal.

The existing sentence "only `name()` and `function name()` start a function definition" stays verbatim.
