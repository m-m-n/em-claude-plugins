## Design

### Failure being fixed

Three tests in the full suite fail, and the same three fail on the base branch:

1. `tests/test_reproduction_reviewer_instructions.py::TestCodexReviewerBriefs::test_ac5_unchanged_ranges_are_byte_identical`, for the em-workflow copy of the codex-reviewer agent: the digest of its `[head]` range differs from the pinned value.
2. The same test, for the em-review copy.
3. `tests/test_reviewer_roles_protocol.py::TestCodexReviewerAgentPrimaryRoleStatement::test_frontmatter_fields_unchanged`: it expects `model: sonnet`.

Cause: commit `7656e549` ("chore(codex-reviewer): switch model from sonnet to haiku") changed the `model` frontmatter field of both codex-reviewer agent files from `sonnet` to `haiku`, and did not update these expectations. `model: haiku` is the intended state.

### Change

- The direction of the fix is fixed: the tests follow the agent files. The agent files are the source of truth and are not edited.
- Test 3: the expected `model` value becomes `haiku`. Every other expected frontmatter field keeps its value.
- Tests 1 and 2: the two pinned `[head]` range digests become the digests of that range in the current agent files, computed by the test module's own range extraction and digest method. How the range is cut and how the digest is computed do not change. Every other pinned range and digest in the module keeps its value.
- No assertion is removed, skipped, loosened or made conditional.
