# Task Plan: task0001 — file-tasks survives non-OSError helper failures and unencodable finding text

## Goal

`file-tasks` never ends with a traceback when a filing helper meets a
ValueError (NUL in a launch argument) or a UnicodeEncodeError, nor when a
finding carries text that cannot be encoded as UTF-8: the first case ends
the batch through the existing break-and-return route, the second skips and
records the finding, and either way exactly one JSON summary is printed.
A new regression test module detects a recurrence of both reproductions.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create
- `tests/test_sca_file_tasks_unexpected_exceptions.py` — new regression test module for this feature (standard library only, its own stand-in entry point)

### Files to Modify
- `em-workflow/scripts/scan-dependencies.py` — widen the helper conversion and the writer cleanup from OSError to OSError or ValueError, add the UTF-8 encodability skip to grouping with a new fixed reason constant, and update the affected docstrings and the comment of the existing malformed-reason constant

## Design

All components below live in `em-workflow/scripts/scan-dependencies.py`.
Mitigation IDs refer to THREAT-MODEL.md.

### Filing helpers: `create_security_task` and `append_security_task_references` (FR1; TM-2, TM-3)

- Precondition: unchanged. An entry point that is not an executable regular
  file raises EntryPointError before anything is written or launched.
- Postcondition: the helper returns normally, or raises EntryPointError in
  exactly these cases:
  - the launched process exits non-zero — unchanged: message carries the
    process's stderr, no cause attached;
  - an OSError or a ValueError (UnicodeEncodeError included, being a
    ValueError subclass) is raised while writing the temporary references
    file or while launching the entry point — the original exception object
    itself (identity, not a copy) becomes the EntryPointError's cause.
- Any other exception type raised at those same two points (TypeError, for
  example) is not converted and propagates as it was raised.
- The removal of the temporary file after the launch is unchanged: a
  removal error is reported on stderr only, leaves the result unchanged, is
  attempted once, and an already-absent file is accepted silently.
- Behavioural consequence relied on by FR5: a package name containing NUL is
  never filtered out in advance; launching with it raises ValueError, which
  the create helper converts. A task id containing NUL taken from the
  listing reaches the append helper the same way.

### Shared runner: `_run_entry_point_with_references`

No behaviour change is expected: it lets an OSError or ValueError from the
writer or the launch reach the helpers raw, and keeps its removal handling.
Only its docstring changes (see Docstrings below).

### Temporary references-file writer: `_write_references_tempfile` (FR3)

- When writing fails with an OSError or a ValueError (UnicodeEncodeError
  included), the partially written file is removed before the original
  exception is re-raised unchanged. A failure of that removal itself stays
  suppressed as today.
- The writer itself still raises the raw exception; it never raises
  EntryPointError (conversion is the helpers' job).
- Other exception types keep their current behaviour.

### Grouping: `group_findings_by_package` (FR4; TM-1)

1. Recover package and advisory id from the title as today. A title that
   violates the title contract is still recorded with the existing
   malformed reason constant.
2. Before any truncation of the recovered values, check that each of the
   recovered package, the recovered advisory id and the severity (only when
   the severity is a string) can be encoded as UTF-8.
3. If any of them cannot: append a `{position, reason}` entry to the
   malformed list, with `reason` set to a NEW fixed reason, and skip the
   finding entirely (it joins no group and no de-duplication).
4. Otherwise group, de-duplicate and truncate exactly as today.

- The malformed list stays in input order across both reasons.
- The new reason is a module-level constant placed next to the existing
  malformed reason constant, so tests can refer to it by name. Its wording
  is the implementer's choice, subject to: fixed text written by this
  script, never built from finding content, and different from the
  existing title-contract reason.
- Grouping is shared by the ntd branch, the report branch and the degraded
  report branch, so all three are protected without branch-specific code.

### Filing loop and summary: `file_tasks` (FR2; NFR1; TM-4)

- No structural change is expected: the loop already catches EntryPointError
  from either helper, prints the failure token and the exception text to
  stderr, and breaks; once the helpers convert ValueError, those failures
  take the same route.
- On such a failure: `failed_package` is the package being filed;
  `failure_reason` is `task_create_failed` on the create path and
  `task_update_failed` on the append path; `unattempted_packages` is the
  failed package followed by every later package in group order; packages
  completed before the failure stay in `filed_packages` /
  `appended_packages`.
- Summary contract (NFR1): exactly the existing twelve keys; `failure_reason`
  only ever null or one of the two tokens above; exception text and
  package- / advisory-sourced text never appear in `failure_reason` or in
  any `malformed_findings[].reason`; exception text goes to stderr only. The
  CLI prints exactly one JSON object and exits 0.

### Docstrings and comment (FR6, NFR4)

- The docstrings of `_write_references_tempfile`,
  `_run_entry_point_with_references`, `create_security_task`,
  `append_security_task_references`, `group_findings_by_package` and
  `file_tasks` describe the behaviour above: the helpers convert OSError
  and ValueError (UnicodeEncodeError included) and nothing else; the writer
  removes the partial file on OSError or ValueError and re-raises the raw
  exception; grouping skips findings whose package, advisory id or string
  severity is not UTF-8 encodable, with the new fixed reason; `file_tasks`
  names ValueError among the mid-batch failures that end the batch.
- The comment above the existing malformed reason constant no longer claims
  it is the one reason recorded for every malformed finding.
- Wording constraints (NFR4; sentences are split after a full stop or a
  semicolon followed by whitespace):
  - In the docstrings of `_run_entry_point_with_references`,
    `create_security_task` and `append_security_task_references`, no
    sentence matching remov / delet / unlink (case-insensitive) contains
    `EntryPointError` or `propagat`.
  - The docstrings of `_run_entry_point_with_references` and
    `create_security_task` each keep a sentence about the removal that
    contains both `stderr` and `unchanged`.
  - The `file_tasks` docstring keeps `Five keys are ADDED` followed by the
    five backtick-quoted key names `malformed_findings`,
    `listing_dropped_count`, `failed_package`, `failure_reason`,
    `unattempted_packages`.

### Constraints

- Standard library only, in the script and in the new test module (NFR2).
  The change adds no import to the script.
- `tests/test_sca_file_tasks_oserror.py` and every other existing test
  module stay unmodified and keep passing (NFR3).
- No plugin version change is part of this task (NFR5): the change set
  contains neither `em-workflow/.claude-plugin/plugin.json` nor
  `.claude-plugin/marketplace.json`.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1; TM-2, TM-3): For each of the two filing helpers, called directly against a stand-in entry point: a ValueError, and separately a UnicodeEncodeError, raised by the temporary references-file writer leaves the helper as EntryPointError whose cause is that exact exception object; the same holds when each is raised by the entry-point launch instead, and the temporary file written before that launch no longer exists afterwards. A TypeError raised at either point leaves the helper as TypeError, not EntryPointError. A non-zero exit still raises EntryPointError with no cause, and a non-executable entry point still raises EntryPointError without launching.
- [ ] AC-2 (FR3): Calling the temporary references-file writer directly with the single reference line made of a lone surrogate (U+D800) followed by " (high)" raises UnicodeEncodeError, not EntryPointError, and the temporary file it created does not exist after the call. An OSError raised while writing still surfaces as the raw OSError with no file left behind.
- [ ] AC-3 (FR1, FR2, FR5; TM-2): Running the real CLI as a subprocess on the create path with an empty listing and findings for the packages pkg-a, a name containing NUL (JSON-escaped in the findings file) and pkg-c, in that order: exit code 0; stderr contains no `Traceback` and contains `task_create_failed`; stdout is exactly one JSON object equal to the twelve-key summary with `branch` "ntd", `filed_packages` [pkg-a], `failed_package` the NUL-containing name, `failure_reason` "task_create_failed", `unattempted_packages` [the NUL-containing name, pkg-c], and every other key at its no-op value (empty lists, null `report_path` and `degraded_reason`, `degraded` false, `listing_dropped_count` 0). The stand-in records exactly one create call (pkg-a) and never receives pkg-c.
- [ ] AC-4 (FR1, FR2; TM-2, TM-3): Calling the filing function in-process against the stand-in: (a) append path, all three packages have an incomplete task in the listing and pkg-b's task id contains NUL — `appended_packages` [pkg-a], `failed_package` pkg-b, `failure_reason` "task_update_failed", `unattempted_packages` [pkg-b, pkg-c], and the stand-in receives an update for pkg-a's task only; (b) the writer replaced by a test double that delegates to the real writer but raises UnicodeEncodeError on its second call — on the create path `filed_packages` [pkg-a] with "task_create_failed", on the append path `appended_packages` [pkg-a] with "task_update_failed", both with `failed_package` pkg-b and `unattempted_packages` [pkg-b, pkg-c].
- [ ] AC-5 (FR4; TM-1): Calling grouping directly with a finding whose recovered package, recovered advisory id, or string severity contains a lone surrogate (one case each) raises nothing, puts that finding in no group, groups the other findings normally, and records `{position, reason}` with the new reason constant, which differs from the existing title-contract reason; a mix of title-contract and encoding failures is recorded in input order. Running the real CLI on three packages whose second finding has the JSON-escaped advisory id U+D800: exit code 0, no `Traceback`, stdout is exactly one JSON object containing no surrogate, `filed_packages` are the other two packages, `failed_package` and `failure_reason` are null, `unattempted_packages` is empty, and `malformed_findings` equals [{position: 1, reason: the new constant}]. On the report branch (entry point None, a temporary git repository as project root) and on the degraded report branch (listing unavailable), the report file is written, the summary is returned, and the finding is recorded in `malformed_findings`.
- [ ] AC-6 (NFR1; TM-4): In every run of AC-3, AC-4 and AC-5, the summary has exactly the twelve keys; `failure_reason` is null or one of "task_create_failed" / "task_update_failed"; neither `failure_reason` nor any `malformed_findings[].reason` contains the exception text, the package text or the advisory-id text of that run; and for AC-3 and AC-4 the exception text of the converted failure appears on stderr.
- [ ] AC-7 (FR6, NFR4): The docstrings of the two filing helpers and of the shared runner name ValueError alongside OSError; the writer's docstring states the partial-file removal on OSError or ValueError and the raw re-raise; the grouping docstring states the UTF-8 encodability skip; the `file_tasks` docstring names ValueError among the mid-batch failures; every NFR4 wording constraint listed under Design holds; and the comment above the existing malformed reason constant does not state that it is the only reason recorded for a malformed finding.
- [ ] AC-8 (NFR2, NFR3, NFR5): The new test module imports only standard-library modules; `python3 -m unittest discover -s tests` and `python3 em-workflow/scripts/check-plugin-invariants.py .` both pass from the repository root with `tests/test_sca_file_tasks_oserror.py` unmodified; the change set adds no import to the script and touches neither `em-workflow/.claude-plugin/plugin.json` nor `.claude-plugin/marketplace.json`.

## Test Notes

- Place every new test in the new module. Define the module's own recording
  stand-in entry point there (same technique as the existing OS-error test
  module: an executable script that appends each call to a JSON log and
  replies from a control file), rather than importing helpers from that
  module, so the existing module stays untouched.
- Integration (CLI subprocess): AC-3 and the CLI half of AC-5. Write the
  NUL and the surrogate into the findings file as JSON escapes so the
  findings file itself stays valid UTF-8.
- Unit (in-process): AC-1, AC-2, AC-4, the direct-grouping and report-branch
  halves of AC-5, AC-6 and AC-7. Building a UnicodeEncodeError instance for
  a test double needs its full constructor arguments.
- AC-1's launch cases: replace the process launch with a test double raising
  the chosen exception, and record the writer's returned path to check its
  removal.
- AC-2: record the created temporary file's name through a test double
  around the temporary-file factory, and clean up any leftover in the test's
  own teardown.
- AC-5's report branch needs a project root that is a git repository (the
  report destination is resolved through it); the degraded branch needs a
  stand-in whose listing is unavailable (for example a non-zero listing
  exit).
- AC-6 can be asserted inside the AC-3 / AC-4 / AC-5 tests or as a
  dedicated test over the same runs.
- AC-7's NFR4 checks overlap with existing checks in the OS-error test
  module; the new module asserts the FR6 content checks and may restate the
  NFR4 ones for the append helper.
- AC-8 is checked by an import-scan test in the new module plus the two
  suite commands; the no-new-import and untouched-version-files parts are
  checked against the diff.
- Edge cases worth a test: TypeError not converted (AC-1); severity that is
  not a string is not subjected to the encodability check (AC-5).

## Out of Scope

- Filtering NUL-containing package names before filing (FR5 requires they
  end the batch through break-and-return instead).
- Any change to the summary's key set, the failure tokens, the listing
  validation, the report format or the title contract.
- Checking encodability of finding fields other than package, advisory id
  and string severity.
- Any change to `tests/test_sca_file_tasks_oserror.py` or other existing
  test modules.
- Any change to plugin versions.
