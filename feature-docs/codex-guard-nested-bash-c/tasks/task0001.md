# Task Plan: task0001 — Judge shell -c strings at every level with an explicit work list and a re-read limit

## Goal

Both copies of the guard deny an interactive or program-less launch inside a
literal shell `-c` string at any nesting level, walk nested strings without
recursion, and stop re-reading second-level-and-deeper strings past
1,000,000 characters; `CASES` and dedicated tests pin this behaviour.

FR1, FR2, FR3, FR4, FR5, FR7, NFR1, NFR2, NFR3, NFR4, NFR5

## Design

Implements IMPLEMENTATION.md "Nested-string traversal" (rules T1-T7) and
"Re-read limit constant `NESTED_READ_LIMIT`", within the regions the
"Region ownership" table assigns to this task. Only what is specific to
this task is below.

### Traversal flow

State per traversal: the work list, the running total of re-read characters
(starts at zero), and a limit-reached flag (starts false). Each work-list
entry holds:

| Item | Meaning |
|---|---|
| commands | the simple commands of one string, as the parser returns them |
| next position | the index of the next command to judge |
| inherited | the connection the string inherits from its holder (false at level 0) |
| level | 0 for the hook command, 1 for a first-level string, and so on |

1. Parse the hook command and put one entry on the work list: its
   commands, not inherited, level 0. A hook command the parser cannot read
   passes, as today.
2. Look at the top entry. If it has no command left, remove it; if the
   work list is then empty, return "no launch to deny". Otherwise take its
   next command and advance its position.
3. Skip the command when it is inside a function body. Otherwise work out
   its connection (T2) and judge it with the existing per-command judgment.
4. A launch to deny returns (kind, name) at once.
5. When the command yields a literal `-c` string:
   1. If the entry's level is 1 or more (the string is second-level or
      deeper): when the limit is already reached, or the running total plus
      the string's length exceeds `NESTED_READ_LIMIT`, mark the limit
      reached and go back to step 2 without reading the string. Otherwise
      add its length to the running total.
   2. Parse the string. When it cannot be read, go back to step 2.
   3. Put a new entry on top of the work list: its commands, inherited =
      the holding command's connection, level = the entry's level + 1.
6. Go back to step 2.

The order this produces is T4: the new entry sits on top, so its commands
(and theirs) are judged before the holder's next command.

silent (SPEC TS-2):

| Command | What it pins |
|---|---|
| `echo \| bash -c "bash -c python3"` | a pipe connection reaches the second level |
| `bash -c "bash -c python3" < f` | a stdin redirect reaches the second level |
| `bash -c "bash -c 'echo x \| python3'"` | a pipe inside the second level |
| `bash -c 'bash -c "$CMD"'` | a dynamic second-level operand |
| `bash -c "bash -c 'echo hi'"` | a harmless second-level string |
| a second-level string with an unbalanced quote | undecidable inner string passes |
| `bash -c "bash -c 'f() { python3 -i; }'"` | an inner function body is not judged |

(The `\|` in the two cells above is a Markdown table escape for `|`.)

### Dedicated tests

- **Judgment order (TS-7)**: commands where a launch in a nested string
  and a later launch both qualify. `bash -c "bash -c node"; python3 -i` and
  `bash -c "bash -c node; python3 -i"` deny with a reason that names `node`
  and uses the program-less wording; `bash -c "python3 -i; bash -c node"`
  denies with a reason that names `python3` and uses the `-i` wording.
- **Recursion absence (TS-7)**: a static check over each copy's parsed
  syntax tree, described in AC-4.
- **Limit (TS-4)**: second-level strings of exact lengths, padded with a
  long `echo` argument, around a second-level `python3 -i` string; the
  cases are listed in AC-5.
- **Deep and many nesting (TS-3)**: described in AC-6, asserted with the
  same shape as `TestMalformedAndDeepInput` (exit status 0, empty standard
  error, standard output empty or exactly one deny object, 60-second
  timeout).

## Test Notes

- AC-1 and AC-2 are `CASES` rows; `test_cases_run_against_both_copies`
  runs them on both copies. Write the changed and new rows first and
  confirm the deny rows fail before the traversal changes.
- AC-3 is a dedicated method that reads `permissionDecisionReason`: the
  reason quotes the command word in backticks, and its wording differs
  between the `-i` case and the program-less case (`deny_reason`).
- AC-4: walk the syntax tree of each copy; the checker's own validity is
  shown on small samples, the way `TestStaticConstraints` shows its
  checker flags forbidden calls. Matching method calls only through `self`
  and module-level calls only by bare name keeps the check from confusing
  the module function `parse` with the method `_Parser.parse`.
- AC-5: a string's length is the length of its value after the holding
  level's quote removal. Single-quoted padding without quote characters
  keeps that length easy to compute in the test. The first-level string is
  never counted, so the boundary arithmetic covers only second-level
  strings.
- AC-6: nesting by repeated shell-quoting multiplies the quote characters
  at every level, so the depth the limit admits stays far below Python's
  default recursion limit (SPEC TS-3 allows "the depth the limit admits");
  AC-4 is what pins the absence of recursion. Compute each level's value
  length in the test to choose the depth instead of hard-coding it.
- Runtime: over-limit commands are over a million characters. Keep their
  number small, keep them out of `CASES`, and prefer quoted padding, which
  the parser reads in bulk.
