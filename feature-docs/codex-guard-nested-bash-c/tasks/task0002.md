# Task Plan: task0002 — Rewrite docstring step 7 for every-level judgment, the explicit work list and the re-read limit

## Goal

Step 7 of the module docstring in both copies describes how literal shell
`-c` strings are judged at every level, walked with an explicit work list,
and bounded by the re-read limit, and `TestGuardDocumentation` pins those
sentences.

## Requirements

FR6, FR7, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/scripts/codex-hook-interactive-guard.py` — rewrite step 7 of the module docstring
- `em-review/scripts/codex-hook-interactive-guard.py` — the same change, byte-identical to the em-workflow copy
- `tests/test_codex_hook_interactive_guard.py` — add marker sentences and a stale-sentence test to TestGuardDocumentation

## Design

The source of the description is IMPLEMENTATION.md "Nested-string
traversal" (rules T1-T7) and the value of "Re-read limit constant
`NESTED_READ_LIMIT`". This task edits only the regions the "Region
ownership" table assigns to it and does not depend on how task0001 writes
the traversal.

### Step 7 after the rewrite

Keep, unchanged in meaning and wording where possible:

- a shell reads `-c` as a flag that takes no value (the existing marker
  "`-c` takes no value" stays);
- the letter-by-letter reading of the rest of the bundle, `o` / `O`,
  `--rcfile`, `--init-file`, `--` and a lone `-`;
- the operand inherits the standard input connection of the command that
  holds it, and the words after it are positional parameters;
- "`-c` without an operand -> no output";
- other interpreters keep their reading of `-c` `-m` `-e`.

Replace:

- "the first operand is judged once, the same way, as a command string"
  becomes: the literal first operand is judged as a command string, and a
  literal `-c` operand found inside it is judged too, at every level, with
  the same rules (T1-T3).
- "A literal inside the command string is not judged." is removed.

Add, in the docstring's existing plain style:

- the walk uses an explicit stack (work list), never recursion, and keeps
  the order of T4: the commands of a nested string are judged before the
  commands after the one that holds it, and the first launch to deny
  decides;
- the limit of T6-T7: the characters re-read from second-level-and-deeper
  strings are counted per command up to 1,000,000; first-level strings are
  not counted; once the next string would pass the limit, it and every
  later second-level-or-deeper string pass unread; passing the limit is
  never a reason to deny. Naming `NESTED_READ_LIMIT` is allowed.

### Markers

`TestGuardDocumentation.DOCSTRING_MARKERS` gains one marker sentence per
added point (every level, explicit stack, the limit). The exact wording is
this task's choice; each marker appears verbatim in both docstrings after
`module_docstring` folds whitespace. A new method in the same class asserts
that the two replaced sentences are gone.
