# Task Plan: task0001 — Collapse whitespace in advisory short titles and pin the scan-to-file_tasks round trip

## Goal

Every finding title produced by the four normalizers is recoverable by `recover_package_advisory`, even when the advisory's short-title source spans several lines, so every scanned vulnerability reaches file-tasks as a task or a report entry instead of being classified malformed.

## Requirements

FR1, FR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_sca_finding_title_roundtrip.py` — round-trip tests from each normalizer through title recovery, grouping and file-tasks.

### Files to Modify
- `em-workflow/scripts/scan-dependencies.py` — the title-assembly point collapses whitespace in the short title before the title is composed and truncated.

## Design

Region owned in the script: `_build_finding` and any short-title normalization helper placed next to it (IMPLEMENTATION.md D1). The Finding text-encoding contract in IMPLEMENTATION.md Shared Components is the target shape.

### Where the collapse happens

`_build_finding` is the one point every normalizer (pip, npm, cargo, go) calls to assemble a finding. The collapse is applied there, to the short-title argument only, so all four normalizers are covered by one change (IMPLEMENTATION.md D4).

Processing flow for the title:

1. Take the short title the normalizer supplied.
2. Replace every maximal run of whitespace characters with one ASCII space, then remove leading and trailing whitespace. "Whitespace" is every character the language's Unicode-aware whitespace classification treats as whitespace: at least LF, CR (so CRLF collapses to one space), TAB, vertical tab, form feed, NEL (U+0085), no-break space (U+00A0), line separator (U+2028), paragraph separator (U+2029) and ideographic space (U+3000).
3. Compose the title in the contract shape from the unchanged package, the unchanged advisory id and the collapsed short title.
4. Apply the existing untrusted-text truncation to the composed title (unchanged helper, unchanged 4096-byte cap and marker).

Collapse precedes truncation, so a raw short title that exceeds the cap only because of long whitespace runs is not truncated once collapsed.

### What is not changed

- Package and advisory id are passed through untouched. A package name or advisory id that contains whitespace keeps producing a title that recovery rejects, and stays classified malformed (SPEC assumption a-roundtrip-domain).
- A short title that is empty after the collapse (it was whitespace only) gets no new fallback: the title keeps the contract shape with an empty short title, which recovery still accepts. The existing per-normalizer fallbacks (pip's headline falling back to the advisory id, and so on) are unchanged.
- `_pip_advisory_headline` keeps returning the prose before an embedded CVSS vector; its multi-line output is now collapsed by step 2.
- The recovery pattern and `recover_package_advisory` are unchanged.
- The description and suggestion fields are not collapsed.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-1): For each of the pip, npm, cargo and go normalizers, an advisory whose short-title source contains LF, CRLF, TAB, U+2028 and U+3000 yields a finding whose title contains no line-break character (LF, CR, VT, FF, U+0085, U+2028, U+2029), whose short-title part has every original whitespace run replaced by one ASCII space, and whose short-title part neither starts nor ends with whitespace.
- [ ] AC-2 (TM-1): For every finding produced in AC-1, AC-3 and AC-4, `recover_package_advisory` returns the advisory's original (package, advisory id) pair, and `group_findings_by_package` reports no malformed entry for it.
- [ ] AC-3 (TM-1): A pip advisory whose description has line breaks inside the prose before an embedded CVSS vector yields a title that contains neither a line break nor the CVSS vector text (SPEC AC1).
- [ ] AC-4 (TM-1): A short title made only of whitespace, and a short title long enough that the composed title exceeds 4096 bytes, each yield a title with no line break from which recovery returns the original pair; the over-long one is at most 4096 bytes and ends with the truncation marker. A short title that exceeds 4096 bytes only because of whitespace runs, and fits once collapsed, is not truncated.
- [ ] AC-5 (TM-1): Passing the AC-1 findings of all four normalizers through `file_tasks` produces, for every package, a filed task (stand-in entry point) or a report section (no entry point), and `malformed_findings` is empty. Assertions use only the summary keys that exist before this feature (IMPLEMENTATION.md D3).
- [ ] AC-6: A finding whose package name contains whitespace (for example a line break) is still classified malformed by `group_findings_by_package`.
- [ ] AC-7 (NFR3): The new test module imports only the standard library, and with the collapse step absent the AC-1 / AC-2 tests fail (observed in the red phase and recorded in the implementer report).

## Test Notes

- All criteria are unit/integration tests in the new module, loading the script by file path like the sibling SCA test modules.
- Drive each normalizer through its own entry function with a minimal payload in the shape that normalizer already reads, using the real registry (default registry path) for severity mapping and thresholds. Each finding must pass the normalizer's directness and threshold rules: npm via its per-entry direct flag, cargo via its per-entry direct flag, pip via a requirements file in a temporary project root naming the package plus a high-severity CVSS v3 vector in the description, go via a go.mod in a temporary project root requiring the module (or the synthetic standard-library module) plus a high-severity CVSS v3 vector.
- AC-5's report-branch path needs the temporary project root to be a git repository (report destination resolution reads the worktree list); the stand-in path follows the stand-in executable pattern already used by the file-tasks tests.
- Keep package names and advisory ids short in AC-4 so the cap only ever cuts the short title.

## Out of Scope

- Changing the recovery pattern or `recover_package_advisory` (no multi-line matching).
- Normalizing package names, advisory ids, descriptions or suggestions.
- Anything in the file-tasks filing loop, the summary keys, or run_scan / build_scan_jobs (other tasks own those regions).
- Plugin manifests (`plugin.json`, `.claude-plugin/marketplace.json`) are not edited (NFR4).
