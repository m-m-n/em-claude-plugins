# Task Plan: task0001 — Shared quoted-unit reader for word reading and delimiter ranges

## Goal

The guard reads every backslash pair, single-quoted unit and double-quoted
unit through one shared reader. A delimiter range then keeps double-quoted
backtick, `$( )` and `$(( ))` substitutions verbatim and registers the same
heredoc delimiter as zsh. Ordinary word reading behaves exactly as before.

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4

## Design

The feature-wide frame (call direction, conventions, error policy) is in
IMPLEMENTATION.md. This section holds everything specific to the task.

### Shared quoted-unit reader (contract)

| Aspect | Contract |
|---|---|
| Placement | One module-private function in the guard module. The implementer chooses the name, following the module's existing private naming. |
| Input | The text being read; a start position where a backslash, a single quote or a double quote opens a unit; and a limit position. The limit is exclusive: the unit must end before it. |
| Output | The unit's text after quote removal, the position just after the unit, and a dynamic indication: true when the unit contains a substitution, or a `$` inside double quotes, by the word reader's current rule. |
| Precondition | The start position is before the limit, and the character there is one of the three openers. |
| Postcondition | The returned next position is never beyond the limit. |
| Undecidable | The reader raises the module's existing undecidable signal when (a) the unit does not close before the limit, including a backslash with no following character before the limit; (b) inside double quotes, the position returned by `_skip_substitution` is beyond the limit; or (c) `_skip_substitution` itself reports undecidable (unclosed substitution, or a heredoc or case inside it). Case (c) is passed through unchanged. |

Unit rules:

- **Backslash pair**: a backslash followed by a newline adds no character
  and does not start a word. A backslash followed by any other character
  yields that character.
- **Single quote**: the characters up to the next single quote, verbatim.
  An empty pair yields empty text but still counts as a unit that starts a
  word.
- **Double quote**: the word reader's current rule, which today lives in
  `_double_quoted` and already skips substitutions with
  `_skip_substitution`. Escapes inside double quotes follow the current
  rule, and a `$` marks the unit dynamic. At a backtick, `$(` or `$((`, the
  reader passes the position to `_skip_substitution`, keeps the skipped
  original text verbatim (inner quotes included) and marks the unit dynamic.
  The only additions to today's rule are the limit and the overrun check in
  (b). An empty pair starts a word, like an empty single-quoted pair.

The word reader must still be able to tell a backslash-newline pair (adds
nothing, starts no word) from an empty quoted unit (adds nothing, starts a
word). How is the implementer's choice: an explicit indication in the
reader's result, or the caller checking the unit's opening characters. The
observable behavior must not change (FR5).

### Callers

- **Parse body**: the backslash, single-quote and double-quote branches each
  call the shared reader with the end of the input as the limit. Each
  appends the returned text to the current word and marks the word dynamic
  when the result says so. Each starts the word, except for a
  backslash-newline pair. The parse body keeps no loop of its own for
  reading inside double quotes.
- **Delimiter-range quote removal** (`_remove_range_quotes`): its
  backslash, single-quote and double-quote branches call the shared reader
  with the range's exclusive end as the limit and append the returned text.
  They discard the dynamic indication, because a registered delimiter never
  uses it (SPEC.md Assumptions). This function keeps no loop of its own for
  reading inside double quotes. Everything else in it is unchanged (FR8):
  `$` handling, `${ ... }` outside quotes (inner quotes are still removed),
  the rule that `$'` and `$"` inside a range are undecidable, and the rule
  that `$(` outside quotes is read with `_skip_parens`.
- **`_double_quoted`**: its reading moves into the shared reader. The name
  does not need to survive, because no test refers to it.
- **Backticks inside a delimiter range** do not reach the shared reader:
  `_read_argument_parens` opens such a range as a group, as it does today
  (SPEC.md Assumptions). The shared reader still handles backticks for the
  word reader.

### Call structure (NFR1, NFR2)

Calls go only from a reader, to the shared reader, to `_skip_substitution`.
`_skip_substitution` is not changed to call the shared reader or either
reader, and nothing recurses. Each call to `_skip_substitution` reads only
its own substitution. An overrun ends the whole judgment as undecidable, so
at most one scan runs past a range per input, and the overall reading stays
linear in the input length.

### Docstrings (FR7)

The module docstring's paragraph on delimiter ranges, and the docstring of
`_remove_range_quotes`, state three facts:

- double-quoted `$( )` and `$(( ))` keep their original text;
- a substitution skip that runs beyond the range makes the verdict undecidable;
- the shared reader performs quote removal.

The four sentences checked by DELIMITER_RANGE_MARKERS and the phrase
"inside double quotes" checked by DOCSTRING_MARKERS stay present.

### Test inputs

In this section, a multi-line input means one command string: zsh -c
followed by the lines, joined with newlines and shell-quoted as one
argument. Expected verdicts hold for both copies.

- **Miss side** (expected deny): lines `function { :; } << foo("$(echo "x")")`, `foo("$(echo "x")")`, `foo($(echo "x"))`, `python3 -i`.
- **False-deny side** (expected silent): lines `function { :; } << foo("$(echo "a")")`, `foo($(echo a))`, `python3 -i`, `foo($(echo "a"))`.
- **Arithmetic in double quotes** (expected deny): lines `function { :; } << foo("$((1+2))")`, `foo($((1+2)))`, `python3 -i`.
- **Nested substitution with quotes** (expected deny): lines `function { :; } << foo("$(a "$(b "c")")")`, `foo($(a "$(b "c")"))`, `python3 -i`.
- **Skip beyond the range end** (expected silent): first line `function { :; } << foo("$(echo ")")")`, then a body, then `python3 -i` after the body. `_scan_parens` closes the range at `("$(echo ")`; the substitution skip only closes beyond it.
- **Empty quotes start a word** (expected silent): `python3 '' -i` and `python3 "" -i`.
