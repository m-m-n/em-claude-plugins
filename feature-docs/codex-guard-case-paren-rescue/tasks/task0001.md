# Task Plan: task0001 — Suppress paren rescue for case-marked provisional group chains

## Goal

Both copies of the interactive-launch guard stop reading a case-pattern `)`
as the close of the subshell group just outside a provisional group chain,
so the regression forms TS-1 to TS-4 are denied again while the
genuinely-connected and non-keyword forms TS-5 to TS-8 stay silent, and the
CASES table pins all nine forms (TS-1 to TS-9).

## Requirements

## Scope

### Files to Create

None.

- `em-review/scripts/codex-hook-interactive-guard.py` — the same change, kept byte-identical to the em-workflow copy

## Design

Terms follow REQUIREMENTS.md section 13: the **case mark** is a new field
on `_Group`; the **inherited value** is a second, separate per-group value
fixed when a provisional group opens. Both are additions to the existing
group record; neither replaces nor reuses `outer_blocked`.

### 1. Setting the case mark (FR1)

Owner: the main reader at the point where it appends a word to a simple
command (`_append_word`, or the place the implementer finds equivalent).

Precondition — all four must hold for the word being appended:

1. It is the first word `_append_word` keeps after the leading run of
   reserved words (RESERVED_WORDS such as `!`, `time`, `then`, `do`; a
   non-dynamic `-p` right after `time` counts as part of that run).
2. Its text is exactly `case`.
3. It contains no quoting, no escaping and no expansion (a bare,
   non-dynamic word).
4. The innermost open group is a provisional group.

Postcondition: that innermost provisional group carries the case mark for
the rest of its life (the mark is never cleared). The check and the set are
constant time per appended word.

Not marked: a quoted, escaped or expanded `case`; a `case` in any other
position (for example an argument of another command).

### 2. Inheriting along the provisional chain (FR2)

Owner: `_mark_provisional`.

When it opens a provisional group whose parent is also a provisional group,
it fixes on the child, in constant time, a value determined by the parent
alone: set when the parent carries the case mark or the parent itself
carries the inherited value; unset otherwise. A provisional group whose
parent is not provisional gets the value unset.

Constraints:

- Stored separately from `outer_blocked`.
- The brace rescue (`_closes_after_rescue` / `_close_after_rescue`) never
  reads the case mark or the inherited value; its behavior is unchanged.
- No walk over ancestors at open time or later: the value is a snapshot of
  the parent's two values at the moment the child opens.

### 3. Refusing the paren rescue on marked chains (FR3)

Owner: `_closes_paren_after_rescue`.

New precondition check, evaluated before any existing rescue reasoning:
when the group in question carries the case mark or the inherited value,
the answer is "no rescue" (False). The check reads only that group's own
two values (constant time).

The `)` then falls through to `_close_paren`'s existing reading: when the
innermost open group is a `(` group (here, the provisional group itself) it
closes that group; otherwise the `)` is a separator.

Postcondition on TS-1: the case-pattern `)` closes the marked provisional
group instead of the subshell `(` group outside the chain, so the following
stdin redirect attaches only to that provisional group, the anonymous
function body's interactive launch stays unconnected, and the guard denies.

Expected reading of TS-4 (from SPEC.md, for orientation): the guard reads
the `${v:-${x:-}` word as one dynamic word closed at the first `}`; `case`
marks the provisional group P; `bar(b; ...` opens a provisional child P2
(chain base G1) whose inherited value is set; `x)` closes P2, not G1, so
the redirect attaches only to P2; `y)` closes the marked P; `esac; )` closes
G1. G1 is never connected, so the guard denies.

### 4. What stays unchanged (FR4)

- The brace rescue.
- The end-of-input rescue (`_rescue_argument_groups`).
- The paren rescue for groups carrying neither the case mark nor the
  inherited value.
- Every input that never reads a command-position `case` while a
  provisional group is innermost reads exactly as before.
- The main reader still does not track case-pattern terminators in general
  (TS-9 stays silent).

### 5. Docstrings (FR5)

Describe the case mark, its inheritance and the paren-rescue exception at
each of these places:

- the module docstring, step 4 (the paragraph on the paren rescue)
- the `_Parser` class docstring
- the `_Group` field list
- `_mark_provisional`
- `_append_word` (or wherever the mark is set)
- `_close_paren`
- `_closes_paren_after_rescue`

Every docstring marker the existing tests check stays present verbatim.

### 6. Two copies (FR6, NFR2)

Make the change in the em-workflow copy, then make the em-review copy
byte-identical to it; both files change in the same commit.

### 7. Complexity bound (NFR1)

The parse stays linear in input length and uses no recursion. Marking is
constant time per appended word, inheritance constant time per opened
group, and the paren-rescue check constant time per `)`.

## Test Notes

Tests first: add the nine CASES rows below before changing the guard.
Before the fix, TS-1 to TS-4 are expected to fail (the guard returns
silent) and TS-5 is expected to fail (the guard returns deny); this was
confirmed at the pre-fix HEAD (SPEC.md section 14.1).

CASES row form is `(expected, label, command)` with expected `deny` or
`silent`; the existing harness runs every row against both copies, so no
new harness is needed. Row commands, exactly:

- TS-1, deny: `zsh -c 'setopt nobadpattern; ( function { python3; } foo(a; case x in x) < /dev/null :;; esac; )'`
- TS-2, deny: `zsh -c 'setopt nobadpattern; ( function { python3; } foo(a; ! case x in x) < /dev/null :;; esac; )'`
- TS-3, deny: `zsh -c 'setopt nobadpattern; ( function { python3; } foo(a; time case x in x) < /dev/null :;; esac; )'`
- TS-4, deny: `zsh -c 'setopt nobadpattern; ( function { python3; } foo(a; case ${v:-${x:-}; function { :; } bar(b; x} in x) < /dev/null :;; y) :;; esac; )'`
- TS-5, silent: `zsh -c 'setopt nobadpattern; ( function { python3; } foo(a; case x in x) :;; esac; ) < /dev/null'`
- TS-6, silent: `zsh -c 'setopt nobadpattern; echo x | ( function { python3; } foo(a; case x in x) :;; esac; )'`
- TS-7, silent: `zsh -c 'setopt nobadpattern; ( function { python3; } foo(a; echo case x in x) < /dev/null'`
- TS-8, silent: `zsh -c 'setopt nobadpattern; ( function { python3; } foo(a; "case" x in x) < /dev/null'`
- TS-9, silent, labelled as a known miss: `zsh -c '( python3; case x in x) < /dev/null :;; esac; )'`

Labels should state what each row pins (keyword position, reserved-word
prefix, chain inheritance, connected stdin, argument position, quoting,
known miss) so a future failure points at the broken reading.

After the change, run `python3 -m unittest tests.test_codex_hook_interactive_guard`
from the repository root, then the full project test command
(`python3 em-workflow/hooks/tests/run-destructive-guard.py && python3 -m unittest discover -s tests`).
