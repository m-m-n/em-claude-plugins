# Task Plan: task0002 — Count case marks down at esac and count only bare reserved words

## Goal

Both copies of the interactive-launch guard, as already merged, follow the
revised FR1 to FR7 and NFR1 to NFR2: the case mark is the number of
unfinished `case`s on a provisional group and a bare `esac` at an FR1
position decrements it, the inherited value is the parent's sum and is
decremented the same way, and only bare reserved words form the leading run.
TS-11 to TS-19 are denied (review round 1 findings 285d9bc33784bb3d,
df4afa83e782d56a, b374e6b3c3d4b471), and every existing CASES row keeps its
verdict.

## Scope

## Design

Terms follow REQUIREMENTS.md section 13 (case mark, inherited value, command
position, bare reserved word). A word is **bare** when it contains no
quoting, no escaping and no expansion.

### 0. Starting point

The merged guard already has, on `_Group`, a case mark set at a
command-position `case` on the innermost provisional group, an inherited
value fixed when `_mark_provisional` opens a provisional child of a
provisional parent, and an exception in `_closes_paren_after_rescue` that
refuses the paren rescue for a group carrying either. It was built to the
first SPEC: the mark is never cleared, the inherited value only says whether
the parent was marked, and the leading reserved-word run does not check
quoting or escaping. This task changes those three points and keeps
everything else; confirm the actual merged state in the code before
changing it.

### 1. Values and state

| Item | Kept on | Meaning | Changes when |
|------|---------|---------|--------------|
| Case mark (`case_mark`) | each `_Group` | Number of `case`s counted in this group that no `esac` has closed yet; never negative | +1 at step 3a; −1 at step 3b |
| Inherited value (`case_inherited`) | each `_Group` | Fixed when the group opens (section 4); never negative | −1 at step 3b, only when the own case mark is 0 |
| Bare-run state | the main reader, per simple command | Whether the leading run of bare reserved words is still open, and whether its last word was a bare `time` | Every appended word; reset when a new simple command starts |
| After-in state | the main reader, per simple command | How much of the shape "counted `case`, one word, bare `in`" the current simple command has just read | Every appended word; reset when a new simple command starts |

Constraints:

- Field names `case_mark` and `case_inherited` stay as they are (A8).
- The bare-run state and the after-in state are held apart from the state
  `_names_function` and `_names_anonymous_function` use (`run_open`,
  `after_time`, `lone_function`); those two keep their current decisions
  (FR4).
- The inherited value stays apart from `outer_blocked`; the `}` rescue
  (`_closes_after_rescue` / `_close_after_rescue`) reads neither value (FR2,
  A2).

### 2. The leading run and command position (FR1, A3)

Owner: `_append_word`, or `_start_words` for the per-command reset (if the
run state is placed there, its docstring is updated too, per section 7).

Flow per appended word:

1. While the run is open, a bare word in RESERVED_WORDS stays in the run, and
   so does a bare `-p` immediately after a bare `time`. Neither is at command
   position.
2. Any other word ends the run. This includes a reserved word containing
   quoting or escaping, such as `"time"` or `\!`: it is not counted in the
   run, and the run ends at it.
3. Command position is the first word `_append_word` keeps after the run.
   Postcondition: in `"time" case` and `\! case`, the `case` is not at
   command position and marks nothing (TS-14, TS-15).

### 3. Changing the mark (FR1, A6, A7)

Applies only when the innermost open group is a provisional group; every
change lands on that group.

a. **Increment**: the word is at command position, its text is `case`, and
   it is bare. The case mark goes up by 1, and the after-in state records a
   counted `case`.
b. **Decrement**: the word's text is `esac`, it is bare, and either it is at
   command position, or the after-in state shows that the three words just
   before it in the same simple command were a counted `case`, any one word
   and a bare `in`. Then: if the own case mark is 1 or more, it goes down by
   1; otherwise, if the inherited value is 1 or more, that goes down by 1;
   if both are 0, nothing changes.
c. **Every other word** advances or resets the after-in state: after a
   counted `case`, any word counts as the subject; after the subject, only a
   bare `in` advances, anything else resets; after the bare `in`, any word
   other than a decrementing `esac` resets.

Never decrements:

- an `esac` in argument position (TS-18);
- an `esac` containing quoting, escaping or expansion (TS-19);
- the A9 forms: `case x`, a newline, then `in esac` on the next line (the
  newline starts a new simple command, so the after-in shape is broken), and
  zsh's brace form `case x { ... }` (no bare `in`).

A group whose case mark and inherited value are both 0 — never marked, or
returned to 0 by `esac` — reads exactly like a group that was never marked.

### 4. Inheriting along the chain (FR2)

Owner: `_mark_provisional`.

When it opens a provisional group whose parent is also provisional, it fixes
the child's inherited value as the parent's case mark plus the parent's
inherited value, read once from the parent alone. A provisional group whose
parent is not provisional gets 0. Afterwards the child's inherited value
changes only through step 3b; later changes to the parent's values are not
followed. No walk over ancestors at open time or later.

### 5. Refusing the paren rescue (FR3)

Owner: `_closes_paren_after_rescue`.

It answers no rescue (False) when the innermost group's own case mark or its
inherited value is 1 or more, reading only those two values. The `)` then
follows `_close_paren`'s existing reading: when the innermost open group is a
`(` group (here, the provisional group itself) it closes it; otherwise it is
a separator. Where the merged code tests "carries the mark", the test is now
"is 1 or more".

Expected readings, for orientation (from SPEC.md):

- TS-11: the `esac` right after `case x in` returns the mark to 0, so the
  final `)` rescues the chain and closes G1; the launch stays unconnected and
  the guard denies.
- TS-16: the inner `case` raises the mark to 2 and the inner `esac` lowers it
  to 1, so `z)` closes P without a rescue and the redirect attaches only to
  P.
- TS-17: P2 opens with inherited value 1; the command-position `esac` inside
  P2 finds its own mark at 0 and lowers the inherited value to 0, so the
  final `)` rescues the chain (P2, P) and closes G1.

### 6. What stays unchanged (FR4)

- The `}` rescue.
- The end-of-input rescue (`_rescue_argument_groups`).
- The paren rescue for a group whose case mark and inherited value are both
  0.
- The decisions of `_names_function` and `_names_anonymous_function`.
- Every input in which, while a provisional group is innermost, no bare
  `case` or `esac` is read at an FR1 position.
- Outside provisional groups the main reader does not track case-pattern
  terminators (TS-9 stays silent).

### 7. Docstrings (FR5)

At each of these places, describe that the case mark is the number of
unfinished `case`s, that a bare `esac` at an FR1 position decrements it, how
the inherited value is fixed and decremented, the run of bare reserved
words, and the exception to the paren rescue:

- the module docstring, step 4 (the paragraph on the paren rescue)
- the `_Parser` class docstring
- the `_Group` field list
- `_mark_provisional`
- `_append_word`
- `_close_paren`
- `_closes_paren_after_rescue`
- `_start_words`, if the run state is placed there

Remove every statement that the mark is permanent ("The mark is never
cleared", "It is never cleared", "for the rest of its life", and any other
wording to that effect). Keep every docstring marker the existing tests check
(including `case mark`, `inherited value`, `case_mark`, `case_inherited`).

### 8. Two copies (FR6, NFR2)

Make the change in the em-workflow copy, then make the em-review copy
byte-identical to it; both files change in the same commit.

### 9. Cost (NFR1)

The parse stays linear in input length with no recursion. The mark change,
the bare-run state and the after-in state are constant time per appended
word; fixing the inherited value is constant time per opened group; the
paren-rescue check is constant time per `)`.
