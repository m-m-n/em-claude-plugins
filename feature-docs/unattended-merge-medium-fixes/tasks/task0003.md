# Task Plan: task0003 — merge-pr.py compares the host and accepts HOST/OWNER/NAME

## Goal

`merge-pr.py repo` treats the chosen remote and gh's default repository as the same only when host and owner/name both match, and reports `HOST/OWNER/NAME`. `resolve` and `state` accept that identifier, or the legacy `OWNER/NAME`, and pass it to gh verbatim (FR5).

## Design

**Identifier contract**: IMPLEMENTATION.md C1 (forms, HOST rule, usage-error behavior) and C2 / C3 (outcomes unchanged). This task implements the producer side and the `resolve` / `state` accepting side.

### `repo`
Flow:
1. Resolve the remote's URL and hand it to gh exactly as today. The checks and stops that come before gh is asked are unchanged: a missing remote stops `remote_unresolved`, a URL that is not GitHub-shaped stops `remote_not_github`, and embedded credentials are dropped.
2. Ask gh for the remote side's repository. The query now requests the repository URL alongside owner/name.
   - gh cannot resolve it: stop `remote_not_github` (unchanged).
3. Ask gh for its default repository, naming no repository (unchanged), with the same two fields.
   - gh cannot determine it: stop `remote_unresolved` (unchanged).
4. For each side, validate the answer:
   - owner/name must satisfy the existing rule; otherwise internal failure (unchanged).
   - The URL field must be a string; otherwise internal failure (a malformed gh answer).
   - The host is the text between the first scheme separator and the next `/` or the end. If no host can be extracted, or the host fails the C1 HOST rule (a port, userinfo, empty, a leading non-alphanumeric, a character outside the set, over-long), stop `remote_unresolved`. `detail` says which side's host was rejected and does not echo it.
5. Compare host to host and owner/name to owner/name, both ignoring letter case.
   - Either differs: stop `remote_unresolved`. `detail` names both host-qualified identifiers, default side and remote side.
6. Both match: outcome `github`, with `repo` = remote side's host + `/` + remote side's owner/name, as gh reported them.

The host comes from gh's answer, never from the remote URL text (as-2). That way `ssh.github.com` and ssh-config aliases are not false stops.

### `resolve` / `state`
- `--repo` accepts exactly the two C1 forms. Any other value is a usage error (exit 2, nothing on stdout) raised during argument parsing, before any gh call.
- The accepted value goes to every gh call of the subcommand verbatim.
- Decisions, outcomes, keys and precedence are unchanged (C3).

### Docstring
The module docstring states:
- the `repo` outcome's host-qualified `repo`
- the host comparison and the host rule
- that the two `--repo` forms are accepted

### Test-suite adjustments
- The stub gh answers the repository-view queries in their new request shape, and its fixtures (default, remote and URL mapping) carry a URL as well as owner/name.
- The per-test read-only assertion accepts the new request shape and the three-segment `--repo` value. It still rejects every write-shaped call: the operation-boundary test, which proves the assertion fires on forged calls, keeps passing.
- Existing `repo` tests keep their expectations, with `repo` now in the three-segment form.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR5, TM-2, TS6): The remote URL is `https://ghe.example/acme/service.git`. The stub resolves it to owner/name `acme/service` at `https://ghe.example/acme/service`, and gh's default is `acme/service` at `https://github.com/acme/service`. `repo` then exits 0 with stop `remote_unresolved`, and `detail` contains both `ghe.example/acme/service` and `github.com/acme/service`.
- [ ] AC-2 (FR5, TM-2, TS7): When host and owner/name match on both sides, including a pair that differs only in letter case in each part, `repo` returns `github` with `repo` equal to the remote side's `HOST/OWNER/NAME`. An owner/name mismatch on the same host still stops `remote_unresolved`.
- [ ] AC-3 (FR5, TM-3, TS7): If either side's URL host is malformed (one test value each: a port, userinfo, an underscore, a leading `-` or `.`, an empty host, more than 253 characters), `repo` stops `remote_unresolved`, and `detail` does not contain the rejected host text. A missing or non-string URL field is an internal failure (non-zero exit other than 2, empty stdout).
- [ ] AC-4 (FR5, TM-4, TS8): `resolve` and `state` given `--repo ghe.example/acme/service` exit 0 with their normal decisions, and every gh call they make carries `--repo ghe.example/acme/service` verbatim. Given `--repo acme/service`, they behave as today and pass `acme/service` verbatim.
- [ ] AC-5 (FR5, TM-4, TS8): `resolve` and `state` exit 2 with empty stdout and make no gh call for each malformed `--repo` value: one segment, four segments, an empty segment, a host with a port, a host with `_` or `@`, a host starting with `.` or `-`.
- [ ] AC-6 (FR6, NFR2, NFR4): The tests for AC-1 to AC-4 fail against the pre-change script. AC-5's rejections already hold before the change; their tests pin that the new acceptance keeps them. The suite's operation boundary (read-only gh shapes, explicit repository on every PR call, git used only to read the remote URL, repository state unchanged) is still asserted after every test. The whole `tests/test_merge_pr.py` passes.
