# Task Plan: task0004 — merge-ci-wait.py accepts HOST/OWNER/NAME

## Goal

`merge-ci-wait.py` accepts `--repo` in both identifier forms of IMPLEMENTATION.md C1 and passes the value to gh verbatim. Every other value is a usage error (FR5).

## Requirements

FR5, FR6, NFR1, NFR2, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `test-docs/unattended-merge-medium-fixes/task0004.tests.yaml` — per-task test record (implement-phase format)

### Files to Modify
- `em-workflow/scripts/merge-ci-wait.py` — --repo validation, its help text and error message, the module docstring
- `tests/test_merge_ci_wait.py` — new FR5 tests

## Design

**Identifier contract**: IMPLEMENTATION.md C1. This task implements the accepting side for `merge-ci-wait.py`.

- **Accepted values**:
  - `OWNER/NAME`, under this script's existing owner/name rule (unchanged)
  - `HOST/OWNER/NAME`: the C1 HOST rule for the first segment, and the same owner/name rule for the other two
- **Rejected values**: anything else fails argument parsing, so the script exits 2 with nothing on stdout, before the deadline is computed and before any gh call. The error message and help text name both forms.
- **Pass-through**: the accepted value is used verbatim as the repository selector in both gh reads (PR head view and PR checks).
- **Unchanged**: the polling, the deadline and budget arithmetic, the outcome vocabulary and the output shape.
- **Docstring**: the module docstring's argument list shows both forms.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR5, TM-4, TS8): With `--repo ghe.example/acme/service`, a run that reaches a final outcome (for example `passed` from the stub) exits 0. Every logged gh call carries `--repo ghe.example/acme/service` verbatim.
- [ ] AC-2 (FR5): With the legacy `--repo octo/widgets` (and the existing dotted-name case), behavior and gh arguments are unchanged; the existing tests pass unmodified.
- [ ] AC-3 (FR5, TM-4, TS8): Each malformed `--repo` exits 2 with empty stdout, and the stub logs no gh call. The malformed values are: one segment, four segments, an empty segment, a host with a port, a host with `_` or `@`, a host starting with `.` or `-`, a host over 253 characters.
- [ ] AC-4 (FR5): `--help` output names both `OWNER/NAME` and `HOST/OWNER/NAME`.
- [ ] AC-5 (FR6, NFR2): AC-1, AC-3 (at least the three-segment-valid versus four-segment-invalid pair) and AC-4 fail against the pre-change script. The whole `tests/test_merge_ci_wait.py` passes.
