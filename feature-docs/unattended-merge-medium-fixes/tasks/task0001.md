# Task Plan: task0001 — Merge skill: bind the local merge to head_sha, cd before the HEAD check, re-decide after the lock, host-qualified repo

## Goal

`em-workflow/skills/merge/SKILL.md` gets four changes:
- The local merge only lands the verified `head_sha` and reports a post-merge parent mismatch (FR1).
- The step-10 HEAD check always runs inside the worktree (FR2).
- After the lock is held, the merged decision is repeated (FR3).
- The host-qualified repository identifier is carried to every later `--repo` (FR5).

Each change is pinned by a document-structure test.

## Design

All changes are to the procedure text. No script changes in this task. The skill keeps every existing rule in its 呼び出しの規則 section:
- a standalone `cd` before any call whose result depends on the working directory
- literals only
- a timeout line of at most 600000 before every foreground Bash form
- no loops
- no state file

**Shell-safe forms**: every new git form must be free of characters any common interactive shell treats specially. Besides the characters the existing literal check rejects, this rules out the `^` and `~` revision suffixes, which some shell configurations glob. Reading HEAD's parent list and taking the second entry satisfies this.

### FR1 — step 13.3 (local route)
Flow, in order:
1. The existing `main-tree` check.
2. The existing standalone `cd "<project_root>"`.
3. **New**: a standalone read-only git call that resolves `refs/heads/em-workflow/<feature>/integration`.
   - If the git call fails, the result is `git_failed`.
   - If its output is anything other than exactly `head_sha`, the run ends `verification_failed` without merging. `detail` says the integration branch moved after verification.
4. The existing branch-name merge form, kept unchanged (as-1, unattended-merge FR18). Its failure handling (abort, then `merge_failed`) is unchanged.
5. The existing read of the new HEAD as `merge_commit`.
6. **New**: a standalone read-only git call that reads the second parent of HEAD.
   - If it is not exactly `head_sha`, or cannot be read (call failure, missing second parent, output not 40 lowercase hex), the result stays `merged`.
   - `detail` becomes one line: the `merged` fixed sentence, followed by a fixed-shape note that the second parent differs from the verified `head_sha` (or cannot be read). The note may name only validated 40-hex SHAs.
7. Step 15 cleanup runs exactly as for any `merged` result.

No `cd` to another directory sits between step 2's `cd` and the merge form.

Text updates in 結果の値:
- The `verification_failed` row lists step 13 next to step 10, and its `detail` column covers the moved-branch case.
- The `detail` fixed-text rule states that the FR1 second-parent case is its only exception.

### FR2 — step 10
- Each element of `commands` is still run as cd then `<command>`.
- After the last element, or right away when `commands` is empty, a standalone `cd "<worktree_path>"` block comes immediately before the `git status --porcelain --untracked-files=no` / `git rev-parse HEAD` blocks.
- The text states that this check runs whether or not `commands` is empty.
- The existing statement that `commands` being empty runs no command stays. Rewrite it so it no longer reads as skipping the check.

### FR3 — step 6 (new sub-step after `held`)
Once 6.3 returns `held`, and before step 7's `worktree-state`, repeat the merged decision:
- **Local route**: the `merge-git.py merged` form, the same options as step 4 (C4).
- **PR route**: the `merge-pr.py resolve` form with `--repo <repo> --feature <feature> --base <base_branch> --integration-tip <integration_tip>` (C3).

Outcome handling (as-4):

| Outcome | Route | Handling |
|---|---|---|
| merged | local / PR | Stop the hold task (step 14), then take the already-merged path; PR route keeps `pr_url` / `merge_commit`; ends `already_merged` |
| not_merged | local | Continue to step 7 |
| open | PR | Keep the re-decision's `pr_number` / `pr_url`, continue to step 7 |
| stop | local / PR | Stop the hold task, then end with that stop's reason |
| none | PR | Stop the hold task, then end `internal_error` |

A script failure is `internal_error` under the existing rule, after the hold task is stopped.

Update 6.3's `held` line to point at the new sub-step instead of straight at step 7.
