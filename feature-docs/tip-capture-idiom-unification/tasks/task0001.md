## Design

### The canonical idiom

Defined once in IMPLEMENTATION.md "Shared Components" and stated normatively by
SPEC.md FR1: the tip is resolved from the integration BRANCH REF (never from the
worktree HEAD), the refresh targets the BRANCH NAME (never a captured SHA), and the
capture strictly precedes the refresh. Step I.2.a and Step I.3 already carry this form
in full — they are the reference to copy from, and their content must not change.

### Per-site treatment

| Site | Variable | Today | Target |
|---|---|---|---|
| Step I.1 (baseline commit) | `BASE_COMMIT` | capture from the worktree HEAD; no refresh at all | capture from the branch ref, then ADD a refresh targeting the branch name, then the existing workflow.yaml write, then the existing commit. `$BASE_COMMIT` stays both the recorded `base_commit` value (first-entry-only semantics unchanged) and the commit's third argument; the commit-message literal is unchanged |
| Step I.2.a (launch) | `LAUNCH_TIP` | reference form | unchanged, including the rationale prose explaining why post-refresh capture is unsafe |
| Step I.2.b step 2 (wake reconcile) | `RECONCILE_TIP` | refresh, then capture from HEAD | the capture is inserted immediately BEFORE the `**Refresh the integration worktree FIRST**` sentence; that sentence, step 3 and the commit literal are otherwise untouched (FR6) |
| Step I.2.c route-back | `ROUTEBACK_TIP` | refresh first, then capture from HEAD | capture first, then refresh. The exit-4 unreachability carve-out prose and its proof stay intact — they concern reachability, not capture form |
| Step I.2.c rejected path | `TERMINAL_TIP` | refresh, then capture from HEAD | capture first, then refresh; the single terminal write, its commit literal and the "ONLY side effect" sentence are unchanged |
| Step I.2.c abort phase | `ABORT_TIP` | refresh, then capture from HEAD | capture first, then refresh; the exclusions and stop-condition-3 sentences are unchanged |
| Step I.3 (completion) | `COMPLETION_TIP` | reference form | unchanged |

Each converted site keeps its own variable name, its own commit-message literal and
its own exit-4 cross-reference. No refresh target anywhere becomes a captured value.

### `commit-docs.sh` prose alignment

Two comment blocks change, and only comments change:

1. The `expected_base_tip` argument description, whose current wording describes the
   tip as captured at the caller's last refresh (right after its reset) — the old
   idiom. It must instead describe a tip captured from the branch ref before, and
   independently of, the refresh.
2. The RECOVERY CONTRACT's numbered recovery steps, whose step (1) describes
   refresh-then-implicit-recapture. It must state the same order the canonical idiom
   uses: re-capture from the branch ref, refresh against the branch name, re-apply the
   edits, retry once.

The RECOVERY CONTRACT's carve-out sentence — the one naming `implement-phase.md`
Step I.2.c's route-back commit as the single exempt call site — stays byte-identical,
as do the `RECOVERY CONTRACT` marker and the `# Non-artifact untracked` comment that
follows the block (an existing test slices the block between exactly those two
anchors). No non-comment line of the script changes.

### New module: `tests/test_tip_capture_idiom_uniformity.py`

Reads only `em-workflow/references/implement-phase.md` and
`em-workflow/scripts/commit-docs.sh`. Responsibilities:

1. Locate each of the seven sites by its own variable name and assert, per site: the
   capture resolves the integration branch ref; no capture in the site uses the
   worktree-HEAD form; every refresh target inside the site is the branch name; the
   capture position precedes the refresh position (TS-1).
2. Assert the Branch & Worktree Model exit-4 recovery bullet states re-capture from the
   branch ref before the refresh, i.e. the same capture-before-refresh relation the
   per-site checks assert (TS-2).
3. Assert `commit-docs.sh`'s two prose blocks describe branch-ref capture
   before/independent of the refresh, that the old refresh-time-capture phrasing is
   gone, and that the carve-out sentence survives verbatim (TS-3).
4. Assert `commit-docs.sh`'s executable body is unchanged: compare the
   comment-stripped source against a pinned expectation captured from the PRE-change
   file, so the check proves the change is comment-only and keeps detecting future
   executable drift (TS-4).
5. Pair every new-wording matcher with a negative proof against a verbatim pre-change
   sample, each with a non-vacuity guard (TS-7's drift-detection property).
