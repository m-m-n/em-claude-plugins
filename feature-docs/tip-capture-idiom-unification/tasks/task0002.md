# Task Plan: task0002 — bump the em-workflow plugin version in both manifests

## Goal

Raise the `em-workflow` plugin version by one patch step in both registries, so the
installed plugin cache picks up this feature's changed files under the repository's
plugin-version-bump rule.

## Requirements

FR10, NFR6

## Scope

### Files to Create

None. This task creates no file.

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json`
  — the plugin manifest's `version` field.
- `.claude-plugin/marketplace.json`
  — the `em-workflow` entry's `version` field.

## Design

One shared version value, defined in IMPLEMENTATION.md "Shared Components": the new
string is `0.1.46` — the current `0.1.45` advanced by a single patch step, because no
executable behaviour changes anywhere in this feature (SPEC assumption a6). Both files
carry the byte-identical string.

Only the `version` field of each file changes. The marketplace file's `em-review`
entry keeps its `source` and continues to carry no `version` key; every other field of
both files, and both files' formatting, stay as they are.

Both manifests are owned by this single task precisely so the two values cannot
diverge across parallel worktrees.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `em-workflow/.claude-plugin/plugin.json` reports version `0.1.46`, and
      every other field of the file is unchanged. *(FR10)*
- [ ] AC-2: The root `.claude-plugin/marketplace.json`'s `em-workflow` entry reports
      the same string `0.1.46`; the `em-review` entry and every other field of the file
      are unchanged. *(FR10)*
- [ ] AC-3: `python3 -m unittest discover -s tests` passes in this task's worktree,
      including the existing modules that assert the two manifests agree and that the
      version exceeds each recorded baseline patch. *(FR10, NFR6)*
- [ ] AC-4: No test module is added or modified by this task, and no file outside the
      two manifests is touched. *(NFR6)*

## Test Notes

- This task is TDD-awkward by design: NFR6 caps the change set at one new test module
  and that module belongs to task0001, so no new checker is written here. The planned
  handling is to rely on the checks that already exist — an existing version-bump
  module asserts that the plugin manifest and the marketplace entry carry equal
  version strings and that both are past their recorded baseline patch — and to run
  the full discovered suite as the automated half of the acceptance.
- The "greater than 0.1.45" half is not covered by any existing baseline (the recorded
  baselines are lower), so it is confirmed by directly reading both files; the verify
  phase repeats this as manual item TS-8.
- Verify the JSON stays parseable after the edit — an existing invariant checker
  parses both files rather than pattern-matching them.

## Out of Scope

- Any protocol document, script, or test file (task0001 owns those).
- The `em-review` plugin entry, the plugin description, and every other manifest field.
- A new `test_*_version_bump.py` module: the change set is capped at one new test
  module and it belongs to task0001 (NFR6).
- Regenerating or editing any LICENSE file: `project.license` is `none` and no
  dependency is added.
