# Task Plan: task0002 — プラグイン version の patch 更新

## Goal

em-workflow 配下のファイルが変更されることに合わせて、プラグイン version を 2 箇所
同時に patch 単位で上げ、インストール済みキャッシュが更新される状態を保つ。

## Requirements

FR4, FR6

## Scope

### Files to Create

なし。

### Files to Modify

- `em-workflow/.claude-plugin/plugin.json` — version を 0.1.79 から 0.1.80 へ
- `.claude-plugin/marketplace.json` — plugins[] の em-workflow エントリの version を同一値へ

## Design

`.claude/rules/core-plugin-version-bump.md` の定める 2 箇所同時更新。version は
プラグインごとに独立しているため、同ファイル内の他プラグイン（em-review）のエントリは
動かさない。

刻みは patch。本フィーチャーは判定挙動を変えずファイル内容だけが変わるため、semver 上
patch が妥当（SPEC.md A5）。値の契約は IMPLEMENTATION.md Shared Components の
「プラグイン version 値」に従う: 事前条件は両ファイルとも `0.1.79`、事後条件は両ファイル
とも同一の新しい patch 値。

このタスクは version 文字列以外を変更しない。説明文・キーの順序・整形（インデント、
末尾改行）は現状のままにする。差分が version の 1 行ずつに限られることが、レビュー時に
「配布メタ以外に波及していない」ことの根拠になる。

前提条件として 2 ファイルの現在値が `0.1.79` でない場合（別の変更が先に version を
動かしていた場合）は、`0.1.79` を上書きするのではなく、その時点の値の patch 後継へ
上げ、両ファイルを同一値に揃える。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `em-workflow/.claude-plugin/plugin.json` の `version` が `0.1.79` から
      patch 後継の新しい値に更新されている（FR6）。
- [ ] AC-2: `.claude-plugin/marketplace.json` の em-workflow エントリの `version` が
      AC-1 と同一の値になっている（FR6）。
- [ ] AC-3: 両ファイルとも JSON として妥当であり、`version` 以外のキー・値・順序・整形に
      差分が無い（FR4: 変更対象を 2 種類のファイルに限る）。
- [ ] AC-4: `.claude-plugin/marketplace.json` の em-workflow 以外のプラグインの
      `version` が変更前と同一である。
- [ ] AC-5: `python3 em-workflow/scripts/check-plugin-invariants.py .` が終了コード 0 で
      終わる（プラグイン構造の不変条件が壊れていないこと）。

## Test Notes

- 検証は 2 ファイルの読み取り比較で閉じる。両ファイルから em-workflow の version 値を
  取り出し、(a) 互いに一致すること、(b) 変更前の値より patch が 1 つ進んでいること、
  (c) 他プラグインの値が不変であること、の 3 点を確認する。
- JSON の妥当性は、両ファイルの読み込みが例外なく通ることで確認する。
- 構造不変条件のチェックスクリプトは version を検査しないため、AC-5 は「version 更新が
  他の不変条件を壊していない」ことの確認であり、version 一致の証拠ではない。一致は
  AC-1 / AC-2 で直接確認する。
- 差分が version 行に限られることは、統合後の差分確認で見る（AC-3）。
