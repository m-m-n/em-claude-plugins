## Goal

`resolve-verified-findings.py` can no longer be led by a symbolic link at the feature directory,
at `reviews` or at the round record into reading or replacing another feature's review round
record, including when an entry is swapped while the script runs. Everything else the script does
stays as it is.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

(none)

### Files to Modify
- `em-workflow/scripts/resolve-verified-findings.py` — open the feature directory, reviews and the round record without following links, and read, create, rename and remove relative to the held reviews handle; update the docstring Boundaries section
- `tests/test_resolve_verified_findings.py` — add the tests for the new behaviour, keeping every existing test unchanged in strength

## Design

### Handle chain (FR2, FR3, FR7)

1. **Argument normalization (FR7).** Remove the run of trailing `/` from the `--feature-dir`
   value, unless the value consists only of `/` characters, which is used as given. No other
   element is rewritten: `.` and `..` stay, so `current/.` names `.` as the final element and
   `current` counts as an ancestor (FR5).
2. **Feature directory (FR2).** Open the normalized path as a directory without following a link
   at its final element. Any failure (a link, an absent path, a non-directory) is
   `invalid-workflow`, raised before `workflow.yaml` is read. Ancestors are not checked (FR5).
3. **`workflow.yaml`.** Located through the feature-directory handle. A link at `workflow.yaml`
   itself is still followed, and the existing bounded, regular-file reading and validation apply
   unchanged.
4. **Mapping file.** Unchanged (read by its own path, after `workflow.yaml`).
5. **`reviews` (FR1, FR3).** Opened relative to the feature-directory handle, as a directory,
   without following a link, and held until the run ends. When the open, or the listing below,
   fails, the code is chosen from a no-follow status query of the `reviews` entry, never from the
   operating-system error number (that number differs between POSIX systems for a no-follow open
   of a link):

   | `reviews` entry | Code |
   |---|---|
   | Absent | `missing-round-record` (as today) |
   | A symbolic link, whatever it points to (another feature, outside the repository, nothing) | `invalid-round-record` |
   | Anything else that cannot be opened as a directory or listed (a regular file included), or an entry whose status cannot be queried | `missing-round-record` (as today) |

6. **Round record selection.** The entry names are listed from the `reviews` handle; the C6
   selection rule (largest N of `roundN.yaml`) is unchanged.
7. **Round record read (FR8).** In order, each relative to the `reviews` handle: a no-follow status
   query that must report a regular file (anything else is refused without opening it, as today);
   a read-only open that does not follow a link; a status query of the opened handle that must
   report a regular file; a read from that handle with the existing size bound. Any failed step is
   `invalid-round-record`, and nothing is written. The file mode used for the replacement is taken
   from the opened handle's status.
8. **Replacement (FR3, FR4).** Serialization and the reload check are unchanged. The temporary file
   keeps today's name shape (hidden `.resolve-` prefix, random part, `.tmp` suffix) and is created
   relative to the `reviews` handle, exclusively and without following a link, with a fresh name
   on a collision. Its content is written, flushed and synced; its mode is set to the record's
   mode through the temporary file's own handle; it is renamed over the record with both names
   relative to the `reviews` handle. On any failure after creation the temporary file is removed
   relative to the `reviews` handle, the record is left as it was, and the run fails with
   `invalid-round-record`.
9. **Handles.** Every handle the run opens is released on success and on every failure path.

### Unchanged contract (FR4, NFR4)

- Command line (three options, the `=` form), error-code set, exit statuses, the one-line stdout
  JSON and the rewrite decision and content stay as they are.
- The order of checks stays: arguments, then feature directory and `workflow.yaml`, then mapping,
  then `reviews` and the round record. When several inputs are broken, the reported code is the
  same as today.
- On failure stdout is empty and stderr is exactly the code line; no path, link target or
  operating-system error text is printed (IMPLEMENTATION.md Conventions).
- The serializer is still called through the YAML module at the time of the call, so the TS-4
  wrapper can replace it in the child process.

### Docstring (FR6)

The Boundaries section of the module docstring states that a symbolic link is refused at the
feature directory's final element (also when `--feature-dir` ends in one or more `/`) with
`invalid-workflow`, at `reviews` with `invalid-round-record`, and at the round record with
`invalid-round-record`, and that every read and write after opening `reviews` is made relative to
that directory handle. The rest of the docstring is kept.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR2, FR7, TM-2): With `feature-docs/current` a symbolic link to `feature-docs/other`, where other holds a valid `workflow.yaml` and an eligible deferred high/spec finding, running with `--feature-dir` given as `current`, `current/` and `current//` fails each time with `invalid-workflow` (exit 1, stdout empty, stderr exactly the code line), and other's directory tree is byte-identical with no file added (TS-3, TS-8).
- [ ] AC-2 (FR1, TM-1): With `reviews` of the current feature a symbolic link — to another feature's `reviews` whose `round1.yaml` holds a deferred high/spec finding, to a directory outside the repository, or dangling — the run fails with `invalid-round-record`, the feature directory and the link target are byte-identical with no file added, and, with the other feature committed, the unchanged `merge-preflight.py` on that feature still stops with `unresolved_findings` (TS-1, TS-2).
- [ ] AC-3 (FR3, TM-3): When the path entry `reviews` is moved aside and replaced by a link to another feature's `reviews` at the moment the serializer is called (after the script opened `reviews`), the other feature's `reviews` tree is byte-identical, and no `.resolve-*.tmp` file is left in it or in the moved-aside directory (TS-4).
- [ ] AC-4 (FR8, TM-4): When the round record is moved aside and replaced by a link to another feature's record at the moment the script opens the record (after the pre-check), the run fails with `invalid-round-record` and the other record is byte-identical (TS-10).
- [ ] AC-5 (FR8, TM-5): A round record that is a FIFO fails with `invalid-round-record` within the child-process timeout, without waiting for a writer, and the feature directory is unchanged (TS-11).
- [ ] AC-6 (FR5, FR7): A legitimate feature directory given through a path whose ancestor is a symbolic link to the repository is rewritten as before (exit 0, the eligible finding becomes `fixed`) (TS-5); a feature directory that is not a link, given as `DIR/` and as `DIR//` on fresh fixtures, gives exit 0, the eligible finding `fixed`, and stdout JSON equal to the run with plain `DIR` (TS-9).
- [ ] AC-7 (FR4, NFR4, TM-6): Every existing test of `tests.test_resolve_verified_findings` is kept without being removed or weakened and passes; a new broken-input case where `reviews` is a regular file fails with `missing-round-record`; every new failure case writes nothing to stdout and only the code line to stderr, and a link target or directory name carrying the module's sentinel string never appears in the output (TM-6); `python3 -m unittest tests.test_resolve_verified_findings` and `python3 -m unittest discover -s tests` both succeed (TS-6).
- [ ] AC-8 (FR6): The module docstring's Boundaries section names the three refused links (feature directory final element including the trailing-separator form, `reviews`, round record) with `invalid-workflow`, `invalid-round-record` and `invalid-round-record` respectively (TS-7).
- [ ] AC-9 (NFR1, NFR3, NFR5): The test module imports only standard-library modules and uses PyYAML only inside child processes; the swaps of AC-3 and AC-4 are triggered from wrapper hooks at fixed calls, with no CPU load, loops or sleeps used to win a race; the script's imports are still the standard library plus PyYAML; and `em-workflow/skills/develop/SKILL.md`, `em-workflow/scripts/merge-preflight.py` and `tests/test_merge_preflight.py` have no diff against the base commit.

## Test Notes

- **Two features in one fixture (AC-1, AC-2).** The existing helpers are bound to the fixture's
  default feature. Making the victim ("other") that default feature and adding "current" beside
  it lets the existing preflight helper check the victim unchanged. Existing helpers may gain
  optional parameters, but no existing test may lose an assertion.
- **Link target outside the repository (AC-2).** The broken-input table compares only the feature
  directory and the mapping file, so the outside directory needs its own byte comparison (a
  dedicated test, or a snapshot taken by the case itself).
- **Race hooks (AC-3, AC-4, NFR3).** Each race test runs a small child program with the running
  interpreter in no-bytecode mode: it installs a wrapper, sets the script's arguments as its
  command line and runs the script file as the main module. TS-4 wraps the YAML serializer; TS-10
  wraps the OS-level open and acts only on the call whose name is the round record. Each wrapper
  swaps once and then calls the original. The run's exit status in TS-4 is not fixed by the SPEC;
  assert only the bytes of the other feature and the absence of temporary files.
- **FIFO (AC-5).** The tree snapshot helper reads every file that is not a link, so a FIFO in the
  fixture would block the helper itself. Extend it to record special files by kind without opening
  them (regular files are still compared by bytes). Run the FIFO case with a timeout on the child
  process; a timeout is a test failure.
- **Sentinel (AC-7).** Reuse the module's existing sentinel string in the names of the new link
  targets so that a leaked path would show up in the output assertions.
- **Precedence.** Keep at least one existing case per code passing unchanged; the check order is
  covered by the existing broken-input table.
- **NFR5.** The unchanged-files check is a diff against the base commit made during verification,
  not a test inside the suite (as the existing preflight test class explains).

## Out of Scope

- Changing how a link at `workflow.yaml` or at the mapping file is handled (read-only inputs,
  followed as today).
- New error codes, new options, or any change to the eligibility rules and the rewritten finding
  shape.
- Any change to `em-workflow/skills/develop/SKILL.md`, `em-workflow/scripts/merge-preflight.py` or
  `tests/test_merge_preflight.py` (NFR5).
- Syncing the directory after the rename, or any other durability change beyond today's.
