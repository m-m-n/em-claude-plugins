## Goal

The two documents that describe the `batch` block and the `failed_kind`
vocabulary agree again: the batch-mode snippet carries the same key set as
the schema's, every persisted key has a defined writer, the cap's ownership
is cited to whoever actually owns each part of it, and the external-cause
value's gloss states a meaning without implying a detection guarantee no
write path provides.

## Design

### The drift

| Statement in place today | Why it is false |
|---|---|
| the batch-mode snippet shows the `batch` block's keys, declaring itself to show "the same keys only" | the snippet lacks the auto-resume record the schema defines, so the key-equivalence claim is false |
| the batch-mode bullet saying the block persists rework counters only | the auto-resume record is not a rework counter |
| the batch-mode sentence attributing both the branch and the cap to the develop skill | the schema owns the cap key, its member names and the unset-read default value; the develop skill owns only the judgment that consumes them |
| the schema's auto-resume record, including a `cap` member | no document defines the write path that materialises the record, so a persisted key exists with no writer |
| the schema's external-cause value gloss, which names an orphaned implementer *or a harness failure* | the only write path that produces that value keys off an orphan-origin journal event; a harness failure with no such signal falls to the decision-required value |

### The rule this task pins

1. **Key-set equivalence is real, and checked as equivalence.** The
   batch-mode snippet carries the auto-resume record with both member keys.
   The check is a comparison of the two documents' snippet key sets, not a
   hard-coded list in the test — a list would drift the same way the prose
   did.
2. **What the block persists.** The sentence describing the block's content
   covers the auto-resume record alongside the rework counters, and keeps
   its existing point unchanged: the block never activates batch mode.
3. **Cap ownership, stated once per part.** The schema owns the key path,
   the member names, and the unset-read defaults including the cap's default
   value. The develop skill owns the consuming judgment: when the count is
   incremented, how the cap is compared, and what happens at the cap. The
   batch-mode citation names each owner for the part it owns, instead of
   attributing the whole cap to the develop skill.
4. **A writer for every persisted key.** The schema's `batch` block section
   names the write path that materialises the auto-resume record — the same
   orchestrator write that creates the `batch` block, cited to the
   batch-mode document — and states the record's initial member values as
   the unset-read defaults it already defines, so the record is never
   materialised with values the read rule would not have produced.
5. **Meaning versus detection.** The external-cause value's meaning is
   unchanged and stays the closed two-value vocabulary's. The gloss gains a
   separation: it states what the value MEANS, and points at the write-path
   owner for which concrete failures are attributed to it today. The
   fail-closed direction is stated explicitly — a failure that carries no
   external-cause signal reads as the decision-required value and stops the
   run — so a reader cannot infer that a harness failure resumes
   automatically.

Nothing here changes the vocabulary, its required-ness, the missing-value
read rule, or the classification any write path performs. This task edits
descriptions and citations, not behaviour.

## Test Notes

- AC-1 is the criterion whose past failure mode was a stale hard-coded
  expectation: extract the fenced `batch` snippet from each document, reduce
  each to its set of key names, and compare the two sets. That assertion
  keeps holding the next time a member key is added, and fails the moment
  one document is updated without the other.
- AC-3 and AC-5 are wording assertions over prose that must NOT restate what
  it cites: assert the citation's presence together with the absence of a
  definition-shaped restatement, with a negative proof against synthetic
  text that does restate it — the same shape the existing modules already
  use for this feature's citation discipline.
- AC-5's "textually unchanged" clause is best asserted as presence of the
  existing vocabulary, required-ness and missing-value sentences, so an edit
  that rewrites them fails the criterion rather than passing silently.
