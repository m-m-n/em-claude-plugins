# Task Plan: task0001 — Stop the was_open conditional reading at the valid closer

## Goal

In `_args_json_conditional_step()` of destructive-guard, the branch for a
statement entered while a `[[ ]]` conditional opened in an earlier statement is
still open reads the statement's words in order and stops at the valid closer
`]]`. Words after the closer (redirection targets such as `=~` or `-eq`) no
longer drop the exclusion of the following notion call, detection of uncertain
words before the closer is kept, and regression tests pin both.

## Requirements

## Design

### The defect

In the `was_open` branch, every non-operator word of the statement goes
through the uncertain checks before the branch looks for the closer. Bash
accepts only redirections (and a closing `)` of an enclosing group) after `]]`
in the same statement, so the words after the closer are redirection targets,
yet the branch reads them as words of the conditional: in
`[[ true && true ]] >=~` the redirection target `=~` is read as the regex
operator, and in `[[ true && true ]] >-eq` the target `-eq` is read as an
arithmetic operator word. The chunk becomes uncertain and the notion call with
`--session "$SID"` after it turns from KIND_NOTHING to KIND_INSPECTED.

### Contract of the changed branch

- Precondition: `was_open` is true. The inputs (the marked chunk, the
  statement's words, its simple commands, its separator, `was_open`) and the
  result shape (UNCERTAIN, OPEN) are unchanged.
- Processing flow:
  1. Take the statement's non-operator words in their order of appearance
     (the same word list the branch reads today).
  2. For each word, in order:
     1. When the word is the closer, the conditional is closed there and the
        reading stops: no later word of the statement is read by this
        function. The closer is a word whose text as written
        (`_args_json_word_source()`) is exactly `]]` and from which no trailing
        carriage return was stripped.
     2. Otherwise, when `_unsettled()` holds for the word, or the word's
        restored text (`_args_json_declaration_word()`) is in
        `_ARGS_JSON_DOUBLE_BRACKET_WORDS`, the result is (true, true) at once,
        as today.
     3. Otherwise the reading continues with the next word. A word whose
        restored text is `]]` but which is written with a backslash, a quote or
        a line continuation, and a `]]` with a stripped trailing carriage
        return, are not closers: the reading continues past them, as today.
  3. OPEN after the statement is false when a closer was met, true otherwise.
     The existing tail of the function then applies unchanged: an open
     conditional whose statement ends at a `;` or a lone `&` is (true, true);
     otherwise the result is (false, OPEN).
- Postconditions and invariants:
  - The opener-statement branch (`was_open` false) is not changed.
  - The only caller stays `_args_json_nameref_scan()`. Its other readings
    (redirection-variable subscript, deferred evaluation, the command-level
    reading of each simple command) are unchanged; the command-level reading
    still reads the whole statement, words after the closer included.
  - The function stays static analysis of the command string: it launches
    nothing, reads no file, builds no decision and names no
    `destructive-guard/` reason ID (NFR2, NFR3).

### Docstring (FR4)

The docstring of `_args_json_conditional_step()` keeps its existing statement
for the opener statement ("Words before the opener and words after the closer
are not read here.") and gains, next to it, this sentence, which AC-5 pins
verbatim after whitespace normalization:

"In a later statement that holds the closer, the words up to just before the
closer are read and the words after the closer are not read here."

### Regression tests (FR5)

- A new test class in `tests/test_destructive_guard_args_json.py` (for example
  TestDbracketWasOpenCloseScan) with the label prefix
  `dbracket-was-open-close-scan` as a class constant. It reuses the module's
  existing helpers (the loaded hook, Spy, judge, KIND_NOTHING, KIND_INSPECTED,
  the case-table path) and reads shared tables from their classes instead of
  copying them (TestSourceTextReadings.CLOSER_OPERANDS).
- To see the report of `_args_json_conditional_step()` per statement, wrap it
  with a spy during one scan, the way
  TestDbracketOpenerArithScan.conditional_reports does.
- The array assignment is `A=(json --mcp desktop-commander --tool start_process); `.
  The notion call is
  `mcp-bridge run --mcp notion --tool notion-create-comment --session "$SID" --args-json '{"command":"git branch -D example"}'`.
  A judgment command is: the optional array assignment, the form, `; `, the
  notion call.
- Case-table rows (six; labels start with `dbracket-was-open-close-scan: `
  followed by a description in the style of the neighbouring dbracket rows):

  | Decision | Command | Fourth element |
  |---|---|---|
  | allow | `[[ true && true ]] >=~`, `; `, the notion call | none |
  | allow | the array assignment, `[[ true && true ]] >=~`, `; `, the notion call | none |
  | allow | `[[ true && true ]] >-eq`, `; `, the notion call | none |
  | allow | the array assignment, `[[ true && true ]] >-eq`, `; `, the notion call | none |
  | deny | the array assignment, `[[ true && true =~ true ]]`, `; `, the notion call | `{"rule": "git-branch-force-delete"}` |
  | deny | the array assignment, `[[ true && true -eq 0 ]]`, `; `, the notion call | `{"rule": "git-branch-force-delete"}` |

- Order of work (hook-test rule): add the case rows and the new test class
  first and confirm that the allow rows and the tests of AC-1, AC-2, AC-4 (the
  read-past forms) and AC-5 fail against the unchanged branch; then change the
  branch and the docstring.

## Test Notes

- Unit: AC-1, AC-4 and AC-5 (the per-chunk scan, the spy on
  `_args_json_conditional_step()`, the docstring). Integration: AC-2 and AC-3
  (Spy kinds in-process, judge through the hook as a subprocess). AC-6 runs the
  case runner and reads the case table. AC-7 is the existing suite.
- Pitfall: the command-level reading makes a continuation statement uncertain
  when its first word is not an allowlisted name (for example `a`, or an
  escaped `]]`). A scan-level "reads false" assertion therefore needs a
  continuation statement led by `true`, as in AC-1 and AC-4 (a). The SPEC
  example of AC-4 (e) begins its continuation statement with an escaped `]]`,
  so the scan of that chunk stays true from the command-level reading whatever
  this task does; only the conditional reading's report is asserted for it.
- AC-4 (d): the carriage return sits directly after `]]` inside the
  continuation statement; the lexer strips it and records it as a trailing
  carriage return, so that `]]` is not a closer and the `=~` after it is read.
- AC-3 forms and AC-4 (b), (c), (d) already read true before the change; they
  are regression guards, not red tests.
- Several other test modules iterate every case-table row (for example the
  stage-agreement test of `tests/test_destructive_guard_lexer_agreement.py`),
  so run the whole `unittest discover`, not only the new class.
- Write no machine-specific path or home-directory path into a case row.
