# Task Plan: task0001 — Judge the body of a bare zsh anonymous function in codex-hook-interactive-guard

## Goal

Both copies of codex-hook-interactive-guard judge the body of a zsh anonymous
function `function () { ... }` — after a leading reserved word or with no
prefix — and deny when that body launches an interactive program, while a
quoted or escaped `function` and `function function ()` keep their
function-definition reading. Regression cases in the guard's test table pin
both sides of the rule.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/scripts/codex-hook-interactive-guard.py` — word quoting carried onto each word, the lone-bare-function rule in name detection, docstring additions
- `em-review/scripts/codex-hook-interactive-guard.py` — the identical change, keeping this file byte-identical to the em-workflow copy
- `tests/test_codex_hook_interactive_guard.py` — five regression entries appended to the CASES table

## Design

### Components touched (identical in both copies)

| Component | Change |
|-----------|--------|
| `_Word` | Gains one attribute stating whether the word is bare: it contains no quoting, no escaping and no expansion. Attribute name is the implementer's choice; it must read as "bare / unquoted". |
| `_Parser._finish_word` | When it produces a `_Word`, it carries over the parser's existing per-word `bare` flag into the new attribute (FR2). Every other place that constructs a `_Word`, if any, also supplies the attribute with the value matching that word's actual quoting. |
| `_Parser._names_function` | Gains the lone-bare-function rule below (FR1, FR4). |
| Module docstring (step 4 of the function-definition description), the `_Group` `head` description, the `_names_function` docstring | Each gains a sentence stating the new rule (FR5). |

### Name-detection contract (`_Parser._names_function`)

Processing flow, in order:

1. Existing, unchanged: drop the leading run of reserved words (RESERVED_WORDS) and a `-p` directly after `time`.
2. New: if exactly one word remains, its text is `function`, and that word is bare, the answer is "not a function name". This also covers the case where step 1 dropped nothing (the command starts with the bare `function` itself).
3. Existing, unchanged: the two-word case whose first word is `function` (the `function NAME` form). Because step 2 applies only to a one-word remainder, `function function ()` still reaches this step and stays a definition of a function named `function` (FR4).
4. Existing, unchanged: every remaining rule (one non-`function` word is a name; three or more words left is not a name).

Postconditions:

- Lone bare `function`: the `()` that follows does not start a function definition, so the groups after it — `( ... )` or `{ ...; }` — are judged as executed groups through the existing group-judgment path. An interactive launch in the body yields deny.
- Lone `function` that is quoted or escaped (for example single-quoted, double-quoted, or preceded by a backslash): not bare, so step 2 does not fire and the existing reading holds — a function named `function` is defined and its body is not judged (FR3).
- Judgment does not depend on which shell runs the command: the same reading applies on the outer command line, inside `zsh -c`, and inside `bash -c` (SPEC A5).

Constraints (NFR2): standard library only; no self-call and no call cycle is introduced; `_names_function` keeps its name and stays a single forward pass that reads the words without modifying them.

### Docstrings (FR5)

Each of the three locations states that when the single word left after the reserved-word removal is a `function` containing neither quoting nor escaping, it is not a function name and the group after it is judged. The new sentences are additions: the phrases the existing tests pin stay verbatim — ``only `name()` and `function name()` start a function definition``, `three words or more left after the removal`, and every GROUP_HEAD_MARKERS and NAMES_FUNCTION_MARKERS phrase.

### Two copies (FR6)

Make the change in one copy and reproduce it byte-for-byte in the other. The existing byte-identity test in the guard's suite is the check.

### Regression entries (FR7, NFR1)
