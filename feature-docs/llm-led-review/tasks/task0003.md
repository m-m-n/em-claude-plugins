# Task Plan: task0003 — Turn the reviewer registry into a primary-reviewer registry

## Goal

Make `references/reviewers.yaml` state, for every selected perspective, which
non-Claude reviewer runs the MAIN review, so no perspective is left without a
primary reviewer chain and no registry text still presumes the Claude +
cross-model parallel comparison.

## Requirements

FR2, FR3, FR10

## Scope

### Files to Create
- `tests/test_reviewers_primary_chains.py` — structural assertions over the two
  registry files.

### Files to Modify
- `em-workflow/references/reviewers.yaml` — per-perspective key rename, chains
  for the two currently-empty perspectives, header rewrite.
- `em-workflow/references/review-rules.yaml` — header prose only.

## Design

### `reviewers.yaml`

- The per-perspective ordered chain key becomes `primary_chain`
  (IMPLEMENTATION.md Shared Components, "Registry chain key"). `claude_skill`
  and `requires_spec` keep their names, values and meaning, and the six
  perspective names stay exactly as they are. `version` may stay or be bumped —
  nothing reads it mechanically.
- Every perspective gets a non-empty chain; an empty chain is no longer a legal
  registry state, because a perspective without a chain has no primary reviewer
  at all. The two perspectives that are empty today get these chains:

  | perspective | chain (in order) |
  |---|---|
  | comprehensive | codex → litellm `vertex-glm-5` → litellm `muse-spark` |
  | license | codex → litellm `vertex-deepseek-v3.2` → litellm `muse-spark` |

  Both lead with the codex harness: these two perspectives have no track record
  as a non-Claude main review (SPEC A-3), so the harness with the longest track
  record goes first and the Vertex/Muse entries act as the budget /
  rate-limit fallbacks. The four existing chains keep their current order and
  models.
- Header rewrite. Keep: the responsibility split (the harness plugin owns WHICH
  MODELS EXIST and how to reach them; this registry owns WHICH MODEL EACH
  PERSPECTIVE GETS), the statement that `model` is handed to the reviewer
  verbatim, and the list of valid litellm model names. Replace: every sentence
  that describes launching a Claude reviewer for each perspective, adding a
  cross-model reviewer beside it, or scoring agreement between the two. The new
  text says the phase dispatches ONE reviewer per selected perspective from the
  front of `primary_chain`, and cites `references/review-phase.md` for the
  no-available-entry Claude fallback and for the retryable chain walk — it must
  not restate either rule (each is owned by the phase document).
- Keep the per-perspective rationale comments (why security leads with codex,
  why the others lead with the cheap Vertex model), updating only the wording
  that framed them as second-opinion choices.

### `review-rules.yaml`

Prose-only change, in the header comment block: the paragraph describing what
firing `cross_validation` causes ("each selected perspective … is double-run
(claude + that entry's model) for agreement scoring") is replaced by the
meaning fixed in IMPLEMENTATION.md D2 — the flag stays computed exactly as
before and is recorded in the plan and passed to the round evaluator as a
high-intensity marker, but it no longer adds a second dispatch, because every
selected perspective already runs a non-Claude primary reviewer. Data content
is untouched: `baseline`, `rules`, `spec_review` and the `cross_validation`
block keep their values, and the `domains vocabulary` comment block must stay
intact (an invariants check compares it against the plan-writing skill).

## Test Notes

- Test code in this repository uses the Python standard library only (no
  PyYAML): read the registry text and assert over it with line/regex parsing,
  the way `tests/test_batch_policies.py` reads its YAML registry. Structural
  data facts (perspective set, chain contents, rule values) are asserted
  against concrete expected values, not by diffing a copy of the file.
- Use raw-text assertions for the header prose (AC-4, AC-5, AC-6's prose half)
  so a stale sentence inside a comment is still caught.
- Do not assert anything about `references/review-phase.md` or the reviewer
  agents — they are not this task's files and will not carry this feature's
  changes in this worktree.
- Write the test module first; both registry files already exist, so the module
  starts red on the new expectations and goes green as the registries are
  edited.

- The domains vocabulary comment block, and any change to
  `skills/plan-writing/SKILL.md`.
