# Task Plan: task0005 — User-facing description of the new review composition and the version bump

## Goal

Make everything a user reads — the plugin README, the standalone review entry
point and both plugin registries — describe the review step as "one non-Claude
primary reviewer per perspective plus one Opus evaluator, orchestrator
decides", and ship that change under a bumped plugin version.

## Requirements

FR11, FR14

## Scope

### Files to Create
- `tests/test_llm_led_review_user_docs.py` — structural assertions over this
  task's four files.

### Files to Modify
- `em-workflow/README.md` — flow diagram note, agent table, review section,
  chain table, prerequisites.
- `em-workflow/skills/review/SKILL.md` — description and standalone bullets.
- `em-workflow/.claude-plugin/plugin.json` — version and description fields.
- `.claude-plugin/marketplace.json` — the em-workflow entry's version and
  description fields.

## Design

### `README.md`

- The flow-diagram annotation and the review section describe: for each
  selected perspective the phase dispatches ONE non-Claude reviewer taken from
  the front of that perspective's `primary_chain`; when no harness entry of the
  chain is available the Claude generic reviewer runs as the fallback for that
  perspective; after every perspective's result is final, one Opus evaluator
  subagent evaluates the whole round and returns an evaluation, and the
  orchestrator decides the next action (auto-fix / another round / rework /
  completion). Nothing may still say the Claude reviewer runs per perspective
  in parallel with a cross-model reviewer, or that agreement between the two is
  scored.
- The agent table gains a row for the evaluator agent (name and one-line role),
  changes the `reviewer` row to "fallback only", and changes the
  `codex-reviewer` row to the primary reviewer for its perspective. The skill
  column semantics stay as they are.
- The chain table lists all six perspectives with the chains pinned in
  IMPLEMENTATION.md Shared Components ("Primary chains") — quoted from there,
  not from the registry file, which does not carry this feature's edit in this
  worktree — and is retitled as the primary-reviewer chain table. Keep the
  sentence assigning harness ownership to the vertex-review side and
  per-perspective model choice to em-workflow.
- The prerequisites section: a missing codex CLI or a missing `vertex-review`
  plugin no longer means "cross-validation is skipped" — it means those chain
  entries are unavailable, and a perspective whose whole chain is unavailable
  falls back to the Claude reviewer, so em-workflow still runs end to end.
- The review-records section stays as it is (the round record keeps its path
  and its downstream-read fields).

### `skills/review/SKILL.md`

`name`, `argument-hint`, `disable-model-invocation`, `model` and
`allowed-tools` frontmatter stay unchanged. The `description` and the
standalone bullets describe the same composition as the README, so a standalone
`/em-workflow:review` reads the same as a develop-driven review. The bullet
that today describes cross-model validation subject to per-perspective provider
availability becomes the primary-chain + Claude-fallback statement, with the
evaluator step named. The skill keeps delegating to
`references/review-phase.md` in standalone mode and grows no reviewer-selection
logic of its own; its never-commit statement, its `--report-only` behaviour,
its round-record path and its auto-apply caution stay unchanged.

### The two registries

`version` becomes the value pinned in IMPLEMENTATION.md Shared Components
("Plugin version"), identically in both files. Each `description` is edited
only where it describes the review step's composition — the same replacement as
the README's review section, compressed to the description's register. Every
other clause of both descriptions (spec/plan/implement/verify/retrospect,
worktrees, batch mode, licensing, the other slash commands) stays untouched,
and the marketplace entry is located by its `name`, never by array position.
The em-review entry in the marketplace file must not be modified.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: both registries carry the pinned version for em-workflow, the two
      values are equal, and the value compares strictly greater than 0.1.58
      under dot-separated numeric comparison; the em-review entry is byte-identical
      to before.
- [ ] AC-2: both em-workflow descriptions state the new review composition (a
      non-Claude primary reviewer per perspective, a Claude fallback when no
      harness is available, one Opus evaluator, the orchestrator deciding the
      next action) and no longer describe the review step as a Claude reviewer
      with conditional cross-model validation.
- [ ] AC-3: `README.md`'s agent table lists the evaluator agent with its role,

      reviewer.
- [ ] AC-4: `README.md`'s review section describes the one-reviewer-per-
      perspective dispatch, the Claude fallback, the evaluator step and the
      orchestrator's decision, and its chain table lists all six perspectives
      with exactly the chains pinned in IMPLEMENTATION.md.
- [ ] AC-5: `README.md`'s prerequisites state that a missing codex CLI or
