# Task Plan: task0002 — LLM-led review phase protocol and the evaluator agent

## Goal

Rewire the review phase so each selected perspective gets exactly one
non-Claude primary reviewer (Claude only as a no-harness fallback) and a single
Opus evaluator judges the round's output, with every write, gate, mechanical
check and next-action decision staying with the orchestrator.

## Requirements

FR1, FR3, FR4, FR6, FR8, FR9, FR10, FR12, FR13, FR15, NFR1, NFR3, NFR5, NFR6

## Scope

### Files to Create
- `em-workflow/agents/review-evaluator.md` — the Opus evaluator subagent
  definition (thin prompt; defers to the evaluation contract).
- `tests/test_review_phase_llm_led.py` — structural assertions over the phase
  protocol and the new agent definition.

### Files to Modify
- `em-workflow/references/review-phase.md` — Phase R1 note, Phase R2 dispatch,
  Phase R2b chain walk, Phase R3 replaced by R3a/R3b, Phase R5 round record.

## Design

### Phase R2 — primary reviewer dispatch (FR1, FR3, FR9, FR10)

For each selected perspective, walk that perspective's `primary_chain` in
`references/reviewers.yaml` (the registry key pinned in IMPLEMENTATION.md
Shared Components) from the front and take the FIRST entry whose harness is
available, using the Phase R0 availability probes unchanged. A codex entry
dispatches the codex reviewer; a litellm entry dispatches the vertex-review
reviewer with the registry's `model` passed through verbatim. Exactly one
primary reviewer per perspective. When no entry of the chain is available,
dispatch the Claude generic reviewer for that perspective instead — the two are
mutually exclusive, and the Claude reviewer is never launched alongside a
harness reviewer. All Task calls of the round still go in ONE message, and the
orchestrator still passes only paths and the file list, never diff content.
Record per perspective: the chain index picked, the run role
(`primary` / `fallback`) and the orchestrator-known source identity
(IMPLEMENTATION.md Shared Components, source identity vocabulary).
Every statement describing the old "Claude reviewer + one cross-model reviewer,
scored for agreement" shape must be gone from this phase document. Phase R1
keeps its two layers and its `cross_validation` computation unchanged
(IMPLEMENTATION.md D2); only the sentence describing what firing it CAUSES is
rewritten — it now marks the round as high-intensity for the evaluator instead
of adding a second dispatch.

### Phase R2b — chain walk (FR9)

Unchanged in substance, retargeted at the primary reviewers: same three
retryable `skip_reason` values, same harness-vs-model advance semantics, same
cap of two fallback dispatches per perspective, same one-message-per-hop rule,
same non-retryable handling and same harness-level-failure carve-out. Add that
the evaluator is dispatched only after every perspective's walk has finished,
and that a perspective whose chain is exhausted keeps its last skip result
(that perspective contributes a skip, not a Claude re-run — the Claude fallback
branch is decided in R2 from availability, never from a skip).

### Phase R3a — evaluation (FR4, FR5, FR7)

New section, heading pinned by IMPLEMENTATION.md. One dispatch of
`Task(subagent_type="em-workflow:review-evaluator")` per round, carrying the
input block whose field names are pinned in IMPLEMENTATION.md Shared
Components; `evaluation_contract_path` points at the evaluation contract
document, resolved in Phase R0 alongside the other SSOT paths under the same
fail-closed rule. `changed_files` and `spec_path` are normalized to
project_root-based absolute paths exactly as for reviewers. The evaluator
receives every run's verbatim output tagged with the `run_id` the orchestrator
assigned, plus `round_context`, and returns one object.

### Phase R3b — mechanical gates (FR6, FR13, NFR1)

New section, heading pinned by IMPLEMENTATION.md. Apply IMPLEMENTATION.md
decision D3 in order: `file` lexical check, existence under project_root,
`severity` vocabulary, `category` ∈ this round's dispatched perspectives else
unconditional drop (never relabel), 4096-byte caps, `stable_id` recomputed from
the existing normalization formula (which stays verbatim, including
`same_site` and `coupling_id`), `sources` rebuilt from `source_run_ids`. Then
the mechanical dedupe, the round-context suppression of `declined` findings,
and the two confidence corrections — and only those two: the old
claude/cross-model agreement table (95 / 60 / 50 / 70 / 65) is removed, and so
is the forced relabel of out-of-`changed_files` findings to `comprehensive`
(only the confidence cap remains for them). State the evaluator-failure
degradation (D4) and the advisory status of `recommended_action` (D5) here.

### Phase R5 — round record (FR12)

`perspective_runs` entries gain `role`; one entry records the evaluator run (no
`perspective`, `source: claude`, `role: evaluator`, `status`), and
`source: claude` on a perspective entry now means the fallback run. Everything
else about the record — path, file name, `findings` fields, `resolution`,
`resolution_reason`, plan structure, the batch auto-rework/defer behaviour and
the rework ordering — stays byte-compatible; records written before this change
stay readable with no translation.

### Evaluator agent definition (FR4, FR15, NFR5)

A thin prompt shaped like the existing reviewer agents: pinned frontmatter
(IMPLEMENTATION.md Shared Components), Step 0 fail-closed resolution of
`evaluation_contract_path`, a statement that the contract owns the inputs, the
output object, the ownership boundary and untrusted-input handling, and the
read-only constraint. It must NOT contain a `# Task assignment` heading (the
plugin invariants checker forbids that heading in agent definitions), and must
not restate the contract's field lists.

### Protected literals (NFR6, D7)

Leave untouched: the fix-commit block's shared lock file name, `flock 9`, the
stage-before-commit ordering and the `fix({feature}): review round ` message
prefix; the Phase R5/R6 batch statements about the withheld report body and the
unchanged round-record writes; the Phase R5 rework ordering and its citations
of the rework synthesis SSOT. Introduce no new AskUserQuestion and no new
`gate_id` anywhere in the new path.
