# Task Plan: task0004 — Reviewer-side role framing: primary reviewers and the Claude fallback

## Goal

Re-frame the reviewer I/O SSOT and the two reviewer agent definitions so the
harness reviewers read as the MAIN review for their perspective and the Claude
generic reviewer as the no-harness fallback, without changing a single input
name, skip string or existing schema member the external `vertex-review`
plugin depends on.

## Requirements

FR1, FR2, FR3, NFR2, NFR4

## Scope

### Files to Create
- `tests/test_reviewer_roles_protocol.py` — structural assertions over this
  task's four files.

### Files to Modify
- `em-workflow/references/review-protocol.md` — reviewer enumeration and role
  framing only.
- `em-workflow/references/review-output-schema.json` — category enum
  widening.
- `em-workflow/agents/reviewer.md` — fallback-only role statement.
- `em-workflow/agents/codex-reviewer.md` — primary-reviewer role statement.

## Design

### `review-protocol.md` (NFR4 — treat as a published contract)

The document is read directly by the separately-installed `vertex-review`
plugin, which cannot be edited or tested from this repository. The change is
therefore confined to WHO RUNS WHEN:

- The opening enumeration of the three reviewers keeps all three entries and
  their harness descriptions, but states that for a selected perspective the
  phase dispatches exactly one reviewer — a harness reviewer (codex or litellm)
  as the main review, and the Claude generic reviewer only when that
  perspective's registry chain has no available harness entry.
- Sentences that frame a harness reviewer as a second opinion, a cross-model
  check, or an agreement partner are rewritten in those terms. Where the skip
  section says "Any cross-model reviewer …", the wording becomes a harness
  reviewer (codex / litellm) — the CONDITION and the `skip_reason` string it
  emits are unchanged.

Everything else is frozen: input field names and their meanings (including
`model` being litellm-only and always present for it), the target-resolution
priority, path-list validation ownership, the investigation budget, the three
severity levels, the output schema block and its rules, the `suggestion`
format guidance, round continuity, every `skip_reason` string with the
three-value retryable set marked as such, the read-only constraint, and the
untrusted-input section. No new input field, no new skip reason, no removed
schema member.

### `review-output-schema.json` (FR2)

Widen the finding `category` enum so it contains every registry perspective
that can now be dispatched to a harness reviewer — `license` is the missing
one; the other five are already present. Additive only: `required` lists,
`additionalProperties`, the `severity` enum and the root `source` enum stay
exactly as they are. This is what keeps a license finding from a harness
reviewer from being emitted with a category the phase must then drop.

### `agents/reviewer.md` (FR3)

Frontmatter `name` / `model` / `effort` / `tools` unchanged. The description
and a short role sentence in the body state that this agent is dispatched as a
perspective's reviewer only when that perspective's chain has no available
harness entry, and that it never runs beside a harness reviewer for the same
perspective. Its Step 0 / Step 1 / Step 2 / Step 3 behaviour, its
protocol-following statement and its absolute-path rules are unchanged — a
fallback run must produce exactly the same output as before.

### `agents/codex-reviewer.md` (FR1, NFR2)

Frontmatter `name` / `model` / `effort` / `tools` / `skills` unchanged. The
description and the body's opening role sentence state that this agent performs
the main review for its perspective through the Codex CLI, instead of an
independent second-model review for cross-validation. The codex availability
probe, the wrapper-script delegation, the skip objects and — critically — the
scratchpad temp-file discipline section stay verbatim: an existing test module
asserts that section's elements (temp file, scratchpad, schema copy,
intermediate output, the parallel-instance hazard), and the parallel-instance
hazard it describes only gets more likely now that this agent runs for every
perspective in one message.

## Test Notes

- Raw-text assertions over the two Markdown files (a stale sentence inside a
  code fence still counts); JSON parsing with the standard library for the
  schema file. No external test dependency.
- AC-2 is a freeze test: enumerate the input field names and the skip strings
  as explicit literals in the module, so a later edit that "tidies" one of them
  fails loudly. This is the guard for NFR4, whose blast radius is a plugin this
  repository cannot test.
- Do not assert anything about `references/review-phase.md`,
  `references/reviewers.yaml`, or the evaluator files — they are not this
  task's files and carry no changes in this worktree.
- Edge case: the em-review plugin ships its own copy of a codex reviewer
  definition. It is out of scope and must not be touched or asserted on; only
  the `em-workflow/` copy is this task's file.
