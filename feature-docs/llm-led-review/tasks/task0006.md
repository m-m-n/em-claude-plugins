## Goal

Replace the all-or-nothing Evaluator coverage gate with a per-site
accountability floor that the evaluation contract itself declares, so a
normal triage outcome never discards a whole evaluation and a single
critical finding can never disappear without a trace; and bring the
evaluator's finding object back into literal conformance with SPEC FR6/FR7.

## Design

### D-A: the coverage gate becomes a per-site floor, not an evaluation-wide verdict

Today's gate compares the reviewers' critical/high sites against the
evaluator's post-gate critical/high findings and, on zero overlap, throws
the ENTIRE evaluation away. Two defects follow from the same shape: a
legitimate triage that dismisses every reviewer critical/high (false
positives, demotions, round-context suppression) is indistinguishable from
an omission and is punished as a failure; and because the gate fires only on
total loss, suppressing exactly one critical finding always passes.

Replace it with a floor applied **per site**: for each critical/high site a
reviewer run reported, that site must appear either in the evaluation's
`findings` or in the evaluation's `dismissed_sites` (D-B). A site present in
neither is lifted into `findings` on its own, carrying that reviewer run's
own text, that run's orchestrator-assigned source identity, the dispatching
perspective as `category`, and confidence `60` — the same values the
degradation path already assigns. Nothing else about the evaluation is
discarded. The all-lost case is covered by this floor as the limiting case,
so no separate zero-coverage rule remains.

### D-B: the obligation lives in the evaluation contract, not only in the orchestrator

The evaluator is today measured against a criterion its own contract never
states. Add a root field `dismissed_sites` to the output object: one entry
per reviewer-reported critical/high site the evaluator deliberately did not
carry into `findings`, naming the site (`file`, `line`), the run it came
from, and the reason it was dropped (false positive / demoted / already
resolved per `round_context` / duplicate of another finding). With this
field in place the floor of D-A enforces a contract-declared completeness
property of the evaluator's own output — a structural check — rather than
re-judging the evaluation's content, which is what SPEC FR6's closed
enumeration of orchestrator-side gates excludes.

### D-C: one same-site predicate

`same_site` (defined in Phase R3b step 5) is the only site-equality
predicate used anywhere in R3b, including the floor. The reduction of
reviewer findings to `(file, line_bucket)` sites is removed — the two
disagree at bucket boundaries (lines 9 and 11 are the same site under
`same_site` and different sites under the bucket reduction), and R3b already
declares `same_site` authoritative and `line_bucket` a pre-filter only.

### D-D: degradation is for structural failure only

Evaluator-failure degradation keeps exactly the two triggers SPEC FR6's
enumeration supports: the evaluator's Task failed, or the returned object is
missing a required root field. Coverage is not a trigger. When the Task
itself succeeded but the floor of D-A had to lift one or more sites, the
evaluator run is recorded in `perspective_runs` with `status: completed` and
a `degraded: true` marker — never `status: failed`, which would misreport a
successful Task and corrupt the retrospect signal.

### D-E: a schema-valid empty result is not, by itself, evidence of review

Phase R2b's rule that schema validity is the only test for a reviewer result
stays (it is a reviewer-side rule and outside this task's file set). What
changes is that the evaluator no longer treats an empty reviewer output as a
finished perspective: the evaluator independently inspects the round's
`changed_files` for every dispatched perspective and records, per
perspective, whether it corroborated an empty result or produced findings of
its own. This keeps SPEC FR3 intact (no second reviewer is dispatched) while
removing "one model returned well-formed emptiness" as a sufficient
condition for a perspective being reviewed. The contract's existing bounded
read allowance for the evaluator (Read-Only Constraint) is the budget for
this; if the bound is raised, the new bound is stated in the same section
and stays a fixed number, and NFR5's no-write constraint is untouched.

### D-F: the finding's source field is `sources` (FR7 conformance)

SPEC FR7 fixes the evaluator's finding shape to the round-record finding
shape, whose field is `sources`. The evaluator's output object is renamed to
`sources` accordingly, and `source_run_ids` disappears from the contract,
the phase document and the agent prompt. The values the evaluator puts there
are run ids and are ALWAYS overwritten by the orchestrator with its own run
identities (Phase R3b step 6, SPEC FR6) — the rename changes the field name
only, never the ownership. No SPEC.md change is required: the implementation
side is what diverged from the specification, and conforming the
implementation restores FR7 without weakening FR6 or NFR1.

### D-G: the category gate is per-run equality

SPEC FR6 states the category check as equality with the perspective that was
dispatched. Phase R3b step 3 relaxed it to membership in the round's
dispatched-perspective set, which lets an injected finding move between
perspectives that both ran. Restore per-run equality: a finding's `category`
must equal the dispatched perspective of the run(s) its `sources` name;
a finding left with no valid run (attributed to `claude:evaluator`) must
carry a category that was dispatched this round. Mismatch drops the finding
unconditionally — relabelling stays forbidden (NFR1).

### Specification-change judgement

No SPEC.md change is proposed by this task. Every item above conforms the
implementation documents to SPEC FR6 / FR7 / NFR1 as written; the additions
(`dismissed_sites`, the per-site floor, the coverage statement) sit inside
the plan-owned evaluation contract and the plan-owned degradation path, both
of which IMPLEMENTATION.md owns rather than SPEC.md.
