## Findings to resolve (verbatim from round 1)

### F-1 (severity: high, category: security, `em-workflow/hooks/queue_taskstop_net.py`)

**agents.jsonl 由来の worktree_path に封じ込め検査がなく、任意ディレクトリへの
journal.jsonl 追記が起きる**

index 由来の `worktree_path` は絶対パス・`..` 無しの検査しか通らず、worktrees_root
配下であることを確認していない。既存 2 フックの `worktree_path` はその場の prompt 由来
だが、本フックだけはディスク上の JSONL を書き込み先の権威にしている。round 1 loop 3 の
候補集合照合で 1 エントリが複数値と一致しうるようになり、到達容易性が上がった。
agents.jsonl に 1 行追記できる者は、ワークフロー領域外の任意の既存ディレクトリに
`journal.jsonl` を新規作成・追記させられる。

Suggested approach: エントリから導出した journal ディレクトリが、そのエントリを
読み出した feature ディレクトリと一致することを要求する。`agents.jsonl` と
`journal.jsonl` は同一ディレクトリという既存契約なので、等値検査で正常系は一切
壊れない。あわせて候補リストの要素数に上限を設ける（正規の writer が生成しうる
最大候補数は構造化フィールド数 + 埋め込み 1）。

### F-2 (severity: medium, category: architecture, same file)

**候補リスト join に曖昧性検出が無く、診断レイヤが権威ログの別タスクに failed を
書きうる**

候補フィールドが launch ごとに一意である保証は無い。停止側ハンドルが親タスク/
セッション側の ID だった場合、同一セッションの全 launch エントリが同じ候補値を持ち、
last-wins で無関係なタスクに `failed` が書かれうる。`failed` は launch guard が
再起動を許可する状態でもあるため、実行中タスクの二重起動まで連鎖しうる。

Suggested approach: 走査中に identifier が 2 つ以上の異なる (index ファイル, task) に
跨ってマッチしたら、last-wins で選ばず解決失敗として no-op にする。既存の stale
ガードと同じ「分からないなら書かない」方針の延長。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: An index entry whose recorded worktree path does not resolve to a child of
      the feature directory that entry was read from is ignored: no journal write
      happens, no file or directory is created anywhere, and the hook exits 0.
- [ ] AC-2: A normal entry (worktree directly inside its own feature directory) still
      resolves and still appends exactly one failure event — the containment check does
      not regress the happy path.
- [ ] AC-3: When the stop identifier matches entries belonging to two or more distinct
      (feature index, task) pairs, the hook writes nothing and exits 0.
- [ ] AC-4: An index entry carrying an implausibly long candidate list (beyond what the
      writer can produce) is ignored, and the hook exits 0.
- [ ] AC-5: Staleness regression coverage: with two entries for the SAME task in one
      feature index, stopping via the EARLIER identifier appends nothing, and stopping
      via the LATER identifier appends exactly one failure event.
- [ ] AC-6: Feature-scope regression coverage: two feature directories each hold an
      entry for the same task id; stopping the agent recorded in the alphabetically
      earlier feature appends exactly one failure event to THAT feature's journal and
      leaves the other feature's journal untouched. This test must fail if the
      staleness key stops being scoped per feature index.
- [ ] AC-7: Candidate-list join coverage: an entry whose candidate list contains a
      non-representative identifier resolves when the stop uses that non-representative
      value; an identifier absent from the list resolves to nothing. Entries with no
      candidate list still resolve through the legacy representative key.
- [ ] AC-8: Both-writers integration coverage: driving the `SubagentStop` failure net
      and this recorder in sequence over the same task — in BOTH orders — leaves exactly
      one failure line for that task, with both hooks exiting 0.
- [ ] AC-9: Symlink coverage: with the journal path replaced by a symlink to a file
      outside the feature directory, the hook exits 0 and the link target stays
      unwritten.
- [ ] AC-10: The full suite (`python3 -m unittest discover -s tests`) passes.
