# Task Plan: task0001 — Agent index writer hook

## Goal

Deliver a new fail-open hook that records, at implementer launch time, the mapping from
the harness's agent identifier to the em-workflow task identity, so that a later stop
can be resolved back to a task and its journal.

## Requirements

FR3, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

- `em-workflow/hooks/queue_agent_index.py` — the hook: fires after a subagent-launch
  tool call, appends one agent-index entry for em-workflow implementer launches.
- `tests/test_queue_agent_index.py` — subprocess-driven unit tests for the hook.

### Files to Modify

- `em-workflow/hooks/hooks.json` — add this hook's registration entry only.

## Design

### Responsibility

One job: turn an observed implementer launch into one line in that feature's agent
index. It never writes `journal.jsonl`, never decides anything about task state, and
never blocks the tool call.

### Trigger

The post-invocation hook event for the subagent-launch tool. The launch tool is named
`Agent` in current Claude Code versions and `Task` in older ones; **both names must be
matched**, exactly as `queue_launch_guard.py` documents — matching only one silently
disables the hook on the other.

### Processing flow

1. Parse the hook input. Non-object input, or a tool name outside the two launch tool
   names, ends the run with no action.
2. Determine whether this is an em-workflow implementer launch, using the same
   acceptance rule the launch guard uses: the launch tool input's subagent-type field
   when present and non-empty is authoritative; otherwise the presence of a valid task
   assignment block in the prompt decides. Anything else ends the run with no action.
3. Extract the task identifier and worktree path from the prompt's task assignment
   block. Validate both per the Conventions in IMPLEMENTATION.md. Invalid values end
   the run with no action.
4. Extract the harness agent identifier from the tool result. Accept a structured
   identifier field if the result is an object; otherwise accept an identifier embedded
   in the result's text. Failing to find one ends the run with no action
   (IMPLEMENTATION.md D3).
5. Derive the journal directory from the worktree path (Shared Components:
   Journal-directory derivation). If that directory does not exist, end the run with no
   action — never create it.
6. Append one index entry to the agent index in that directory, per the Agent index
   contract in IMPLEMENTATION.md (append-only JSONL, exclusive whole-file lock,
   symlink-refusing open, `0o644`, created if absent).

### Failure policy

Every abnormal condition ends the run with exit status 0 and no output. `main()` carries
a top-level catch-all so that no exception can escape, mirroring
`queue_failure_net.py`'s stated rationale.

### Registration

Add one entry to `em-workflow/hooks/hooks.json` under the post-invocation tool event,
with the matcher covering both launch tool names, the plugin-root-relative `python3`
command form, and `timeout: 15`. Do not modify, reorder, or remove the three existing
registrations (IMPLEMENTATION.md D5).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Given a launch event whose tool input identifies an em-workflow implementer
      and whose tool result carries an agent identifier, exactly one index entry is
      appended to the agent index in the journal directory derived from the worktree
      path, containing the agent identifier, the task identifier, the worktree path,
      and an RFC 3339 timestamp with offset. Exit status is 0.
- [ ] AC-2: The hook appends an entry for BOTH launch tool names (`Agent` and `Task`),
      verified by two separate cases.
- [ ] AC-3: A launch whose subagent-type field names a non-implementer agent produces
      no index entry and exit status 0, even when the prompt contains a task assignment
      block.
- [ ] AC-4: An invalid task identifier (not matching `^task[0-9]+$`), a relative
      worktree path, or a worktree path containing a `..` segment each produce no index
      entry and exit status 0.
- [ ] AC-5: When the derived journal directory does not exist, no file and no directory
      are created, and exit status is 0.
- [ ] AC-6: A tool result carrying no recoverable agent identifier produces no index
      entry and exit status 0.
- [ ] AC-7: Malformed JSON on standard input produces exit status 0, no output, and no
      file writes.
- [ ] AC-8: Two concurrent invocations for different tasks in the same feature both
      append their entry, and every line in the resulting index file parses as JSON
      (no interleaved or truncated writes).
- [ ] AC-9: `em-workflow/hooks/hooks.json` remains valid JSON, still contains the three
      pre-existing registrations unchanged, and additionally registers this hook with
      `timeout: 15` and the plugin-root-relative command form.
- [ ] AC-10: The agent identifier is recovered both from a structured result field and
      from an identifier embedded in result text, verified by two separate cases.

## Test Notes

- Follow `test/README.md`: invoke the hook as a subprocess with JSON on standard input
  and assert on exit status plus file side-effects. Use a temporary directory per test;
  never touch real `~/.claude` state or any real feature's worktree directory.
- AC-1 through AC-7 and AC-10 are unit-level. AC-8 is a small integration test using
  threads or concurrent subprocesses, mirroring the concurrency test already present in
  `tests/test_queue_launch_guard.py`.
- AC-9 is a structural assertion over the parsed `hooks.json`; keep it in this task's
  test file scoped to this hook's own entry, since task0003 owns the whole-file
  registration check.
- Because the live payload layout is unverified (IMPLEMENTATION.md D3), the tests
  define the accepted layouts. Write at least one negative test per rejected layout so
  the tolerance is bounded rather than open-ended.

## Out of Scope

- Writing, reading, or interpreting `journal.jsonl`.
- Any change to `queue_launch_guard.py`, `queue_failure_net.py`, or
  `queue_stop_guard.py`.
- Pruning, rotating, or garbage-collecting the agent index.
- Documentation updates under `em-workflow/references/` (task0003 owns those).
