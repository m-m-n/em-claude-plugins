# Task Plan: task0003 — Documentation and registration consistency

## Goal

Bring the em-workflow reference documents in line with the expanded set of journal
writers, record the stop-path investigation finding where future agents will read it,
and assert that every hook registration in the plugin manifest is present and
well-formed.

## Requirements

FR1, FR6, FR7, NFR3, NFR5

## Scope

### Files to Modify

- `em-workflow/references/implement-phase.md` — the Supporting cast section's hook
  inventory and the Stale-`launched` caveat.
- `em-workflow/references/workflow-schema.md` — the journal writer list.
- `em-workflow/.claude-plugin/plugin.json` — patch version bump.
- `tests/test_hooks_registration.py` — extend to cover the newly registered hooks.

## Design

### What changes in `implement-phase.md`

The "Supporting cast: journal, hooks, resume" section currently describes three hooks
under the heading "The three hooks". It must describe the full set after this feature,
including:

- the agent index writer: what fires it, that it writes only the agent index (never the
  journal), and that it is fail-open;
- the stop-tool recorder: what fires it, that it appends `failed`, and that it is
  idempotent with the existing failure net;
- the fact that a stop through the stop tool does NOT reach the `SubagentStop` failure
  net, which is the reason the recorder exists. State this as an observed property of
  the harness, with the evidence summarized (see IMPLEMENTATION.md's investigation
  result table) — a future maintainer must not have to re-run the probe to know why
  there are two `failed` writers.

The Stale-`launched` caveat currently lists the mitigations for a `launched` line with
no live implementer. Add the recorder to that list as the mitigation that covers the
deliberate-stop case, and keep the existing mitigations intact.

The section's framing sentence ("The three hooks") and any other count-bearing phrasing
must be updated so no stale count survives.

### What changes in `workflow-schema.md`

The journal paragraph states that the journal is "written only by `merge-task.sh` and
the queue hooks". Confirm that phrasing still reads correctly with the added hooks and
make the writer set unambiguous. The invariants that must remain stated: the journal is
append-only, is never rewritten or deleted, and is never written by the orchestrator.

The agent index is NOT part of the journal contract and must be described, if at all,
as separate diagnostic plumbing — it must not be presented as a second authoritative
state file.

### Version bump

Bump the patch component of the `version` field in
`em-workflow/.claude-plugin/plugin.json`, per the repository convention documented in
the root `CLAUDE.md`. Do not touch any other field.

### Registration test

Extend `tests/test_hooks_registration.py` so that the manifest assertions cover the
hooks added by this feature as well as the existing three: each registered hook's
referenced script file exists on disk, each entry uses the plugin-root-relative
`python3` command form, and each carries the standard timeout. Keep the existing
assertions passing unchanged.

Because the two hook tasks each add their own registration entry in parallel, this
task's test must assert on the merged result — the full expected set — rather than on
any single entry.

## Test Notes

- AC-1 through AC-5 are documentation criteria. Verify them by reading the edited
  sections; do not add brittle text-matching tests over prose.
- AC-6 through AC-8 are covered by the extended `tests/test_hooks_registration.py`.
  Drive the assertions from the manifest's actual contents rather than from a
  hardcoded list of hook file names, so the test does not need editing when a further
  hook is added.
- This task does not create hook scripts. Its registration test must therefore tolerate
  running before the hook tasks have merged: assert the invariants over whatever the
  manifest declares, so the suite is meaningful at any merge order.
