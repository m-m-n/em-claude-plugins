# Task Plan: task0001 — Limit the scenario-ID form check's exclusion to line-start fenced blocks

## Goal

`find_hyphenless_scenario_ids` excludes exactly the line-start fenced blocks (backtick or tilde) and HTML comments, so its range matches the "fenced code blocks" wording of the documents. The read side and the documents stay as they are.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/scripts/validate-worker-output.py` — the exclusion range of the scenario-ID form check and the docstring that describes it
- `tests/test_validate_worker_output.py` — regression tests for the new range
- `tests/test_gate_option_vocabulary.py` — refreshed sha256 pins with their comments

## Design

### Contract of find_hyphenless_scenario_ids(text)

- Precondition: `text` is any string.
- Postcondition: returns the set of hyphen-less scenario IDs in what remains of `text` after line-start fenced blocks and HTML comments are excluded. It accesses no file and raises no exception for any string (NFR1).
- It no longer calls `_strip_noise`. Its callers in `_validate_scenario_id_form` do not change.
- The docstring states the new range and no longer says the text passes through `_strip_noise`.
- The line scan is a private helper in the scenario-ID form check section. The Markdown structural parsing section is not edited.

### Line classification

- **Opening line** (FR2): optional leading spaces and tabs, with no upper limit, then a run of three or more of the same character, backtick or tilde. The opening length is the full length of that run. After a backtick run the rest of the line holds no backtick. After a tilde run the rest of the line has no restriction.
- **Closing line** (FR3): optional leading spaces and tabs, then a run of the opening character at least as long as the opening run, then only spaces and tabs to the end of the line.
- **Line end**: a trailing carriage return counts as part of the line end when judging opening and closing lines.
- **Unclosed block** (FR4): an opening line with no closing line excludes everything from the opening line to the end of the document.

### Flow

1. Split the text into lines on the line feed character only. `str.splitlines` is not used.
2. Exclude each block as whole lines, from its opening line through its closing line, including the rest of the opening line. The remaining lines stay separated by line feeds, so the character before a kept line is a line feed, not the end of an earlier kept line.
3. Remove HTML comments from the remaining text with the existing `_HTML_COMMENT_RE`. Blocks go first, as in `_strip_noise`, so an opening-shaped line inside a comment still opens a block, and a comment opener inside a block has no effect.
4. Scan the rest with `_TS_ID_RE`. The hyphen test and the preceding-character test are unchanged.

### Behavior to keep as specified

- The read side and the check differ on purpose (SPEC A7): an ID in a tilde block is read by `extract_verification_scenario_ids` but not reported, and an ID between inline triple backticks is not read but is reported.
- A line that starts with triple backticks and holds more backticks later is not an opening line (FR5), so the ID on it is reported.
- A line that starts with three tildes, followed by an ID and more tildes, is an opening line (SPEC A4).
- A backtick fence after a list marker or a quote marker is not an opening line (SPEC A10), so IDs inside it are checked.

### sha256 pins (FR8)

`VALIDATE_WORKER_OUTPUT_SHA256` and `TEST_VALIDATE_WORKER_OUTPUT_SHA256` in `tests/test_gate_option_vocabulary.py` hold the digests of the final bytes of `em-workflow/scripts/validate-worker-output.py` and `tests/test_validate_worker_output.py`. Any later edit to either file needs a new refresh. Each constant's comment block gains a last paragraph in the existing form, "Refreshed again by scenario-id-fence-scope/task0001", stating what changed and ending with the existing statement that `PINNED_VALIDATOR_TEST_LINE` is unaffected and the existing "Same rationale: refresh, don't remove." The other pins in that file stay.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (TS-1, TS-2, TS-5) A hyphen-less ID is not reported when it sits inside a line-start block fenced by backticks or tildes, or after the fence characters on the opening line of such a block, including when the opening and closing lines start with spaces or tabs.
- [ ] AC-2: (TS-3, TS-4) A hyphen-less ID between inline triple backticks is reported, both in the middle of a sentence and on a line that starts with the triple backticks and continues with text after the closing backticks.
- [ ] AC-3: (TS-6, TS-7, TS-8) An ID on the line after a longer closing run, or after a closing run followed by spaces and tabs, is reported. An ID on the line after a shorter run, a run of the other character, or a run followed by other characters is not reported. With an unclosed backtick or tilde opening line, only IDs before that line are reported.
- [ ] AC-4: (TS-9, TS-10, TS-11, NFR1) An ID in an HTML comment is not reported, and an ID outside a block after a comment opener inside that block is reported. IDs on the lines right before and right after a block, and right after a block at the start of the document, are reported. In a CRLF document an ID inside a block is not reported and an ID on the line right after it is. For the empty string, a lone line feed, a lone carriage return and an opening line with no line end, the function returns a set without raising.
- [ ] AC-5: (TS-12) Given a tilde block and inline triple backticks, `_strip_noise` keeps the tilde block and removes the inline triple backticks, and `extract_verification_scenario_ids` reads an ID in the tilde block and does not read an ID between inline triple backticks. The patterns of `_FENCE_RE` and `_TS_ID_RE` are unchanged.
- [ ] AC-6: (TS-13) `validate_worker_result` on a completed planner result gives no error when VERIFICATION.md and the task plan hold a hyphen-less ID in a tilde block, and gives a `scenario-id-form` error when they hold it between inline triple backticks.
- [ ] AC-7: (TS-14) `VALIDATE_WORKER_OUTPUT_SHA256` and `TEST_VALIDATE_WORKER_OUTPUT_SHA256` match the final files, each constant has its new refresh comment, and `python3 -m unittest discover -s tests` passes.
