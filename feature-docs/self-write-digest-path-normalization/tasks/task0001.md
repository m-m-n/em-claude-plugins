# Task Plan: task0001 — Align self-write-digest root containment with scope validation

## Goal

`self-write-digest.py`'s `allowed_write_roots` containment check returns,
for every (path, root) pair, the same truth value as
`validate-worker-output.py`'s `path_is_contained_in_root`. As a result, a
worker's own `created` write that scope validation admits under a
`./`-prefixed root (or any other root that normalizes the same way) enters
`self_write_set` and is not judged stale. The Rule R1 contract text and the
script's docstrings state the same rule, and tests pin the agreement.

This feature has a single task, so no IMPLEMENTATION.md exists; this plan is
self-contained.

## Design

### Reference behavior (unchanged, owned by `validate-worker-output.py`)

`path_is_contained_in_root(path, root)`, together with
`is_safe_relative_path` and `path_segments`, is the reference. This task
does not change it. Its behavior, which is the FR1 rule, is the following
containment decision for a (path, root) pair:

1. **Unsafe side → not contained.** If either string is empty, starts with
   `/`, contains NUL, or has a `..` segment (splitting with `\` treated as
   a separator equivalent to `/`), the path is not contained.
2. **Normalize both sides.** Treat `\` as `/`, split into segments, and drop
   empty segments and `.` segments.
3. **Root with no segments left → contained.** A safe root that keeps no
   segment (`.`, `./`, `\`, …) contains every safe relative path.
4. **Otherwise strict prefix.** The path is contained only when the root's
   segments are a strict prefix of the path's segments. A path equal to the
   root is therefore not contained, and neither is a sibling whose name
   extends the root's last segment.

### Script-side responsibilities (existing function names are kept)

| Function | Contract after this task |
|---|---|
| `_segments(path)` | Pre: a string. Post: its segments with `\` treated as `/`, and empty and `.` segments dropped. |
| `_check_allowed_roots(value)` | The input-shape check is unchanged: a non-list, or a non-string entry, is still invalid input. Post: the normalized form of every safe root (rule 1). An unsafe root is kept out and admits nothing. A safe root with no segments left is KEPT and admits every safe path (rule 3). |
| `_inside_a_root(path, roots)` | Post: false when the path is unsafe (rule 1). Otherwise true when some kept root has no segments (rule 3), or when some kept root's segments are a strict prefix of the path's segments (rule 4). |

`_check_allowed_roots` currently drops any root whose segment list is
empty. Under FR1 it must tell two cases apart. The empty string (unsafe:
empty) and `/` (unsafe: absolute) are still dropped. `.`, `./` and `\` are
safe and keep zero segments, so they are kept and contain everything.

The script implements this normalization inside itself. It does not load,
import or open `validate-worker-output.py` (NFR1); it uses only the standard
library, and it opens no file other than its input document, in binary
read mode.

### Identification flow for one observed change (unchanged except step 4)

1. The `_is_relative_and_clean` pre-check (absolute path, or `..` split on
   `/`) is unchanged. It runs before the target lookup.
2. Matching against `write_policy.targets` stays exact string equality. A
   path that is a target is judged by its target as before.
3. A path that is not a target is considered only when its kind is
   `created` (`ROOT_ADMITTED_KINDS` is unchanged).
4. The FR1 containment decision runs against each kept root. Any true
   result makes the path a member.

Paths the retained pre-check excludes are also excluded by rule 1, so the
pre-check never makes the result diverge from the reference for a path that
is not a target.
