## Design

### The defect being fixed

`TestPerTargetCaseTable.test_the_cases_come_after_every_other_case` collects the
positions of the case-table cases whose label starts with
`mixed-rm-self-config-deny TS-` and asserts that they run from the first such
position to the last case of the table. That held only until the next feature
appended its own cases. This feature appends its cases at the end of the table,
as SPEC.md FR5 and `.claude/rules/hook-tests.md` require, so the assertion
fails. It already fails on main and at this feature's base commit, for the same
reason.

### The check after the change

The check on mixed-rm-self-config-deny's cases becomes:

- At least one case carries the label prefix (unchanged).
- The labelled positions form one contiguous run: every position from the first
  labelled position to the last labelled position is labelled, so no case
  without the label sits between two labelled cases.
- Nothing is required about the cases after the run. Cases of later features may
  follow it.

What the rest of the class already checks stays as it is. In particular
`test_none_of_the_cases_joins_the_earlier_features_run` still requires the run
to begin after the earlier feature's run.

### Testability of the run check

The run check takes the case table and the label prefix as inputs, instead of
reading only the class's table loaded from the case-table file, so that the
tests below can run it on small tables built in the test module. Whether it is a
module-level helper or a method is left to the implementer. Its result on the
real case table is still asserted, as before.

### Wording

The class docstring says the feature's cases "are the last of the table". The
method name and its failure message say "after every other case" and "one run
at the end of the table". All three are reworded to describe the contiguous-run
property. Renaming the method is allowed.
