# Task Plan: task0001 — Audit changed poetry.lock / Pipfile.lock pins in the pip SCA job

## Goal

When a change touches poetry.lock or Pipfile.lock, the pip axis of
`scan-dependencies.py scan` audits that lockfile's own pins and reports a
vulnerable pin as a finding. A lockfile that cannot be converted, or whose
direct-dependency declaration file cannot be resolved, yields a fixed
machine-readable skip reason instead of a silent fallback.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR9, FR10, FR11, FR12, NFR1, NFR2,
NFR3, NFR4, NFR5, NFR6, NFR7

## Scope

### Files to Create
- `tests/test_sca_pip_lockfile_audit.py` — tests for the Acceptance Criteria below (stub pip-audit on a restricted PATH)

### Files to Modify
- `em-workflow/scripts/scan-dependencies.py` — pip target selection, lockfile conversion, declaration check, prepared-file scope, lockfile job form, canonical-name comparison, aggregation in the scan flow
- `tests/test_sca_scan_invocation.py` — lockfile job-form assertions replacing the lockfile directory-form test (TS3)

## Design

This task implements IMPLEMENTATION.md Shared Components C1-C6 under
decisions D2-D6. This section adds only task-local detail.

### Conversion rules (C3)

poetry.lock:
- Structure: the top-level `package` key must hold an array. Otherwise the
  lockfile is unconvertible.
- Every element of that array is considered, whatever its group or category
  (A3). An element is excluded (and counted) when its `source` table has type
  git, directory, file or url; when its name or version is missing or not a
  string; or when the name or version fails the FR11 rules.

Pipfile.lock:
- Structure: the top-level value must be an object in which at least one of
  `default` / `develop` is an object. Otherwise the lockfile is
  unconvertible. Other top-level keys (such as `_meta`) are ignored.
- Every entry of both `default` and `develop` is considered (A3). The entry
  key is the name. An entry is excluded (and counted) when its value is not
  an object; when it carries any of the keys git, path, file or editable; when
  its version is missing, not a string, or not "==" followed by a non-empty
  remainder; or when the name or the remainder fails the FR11 rules. The
  version written is the remainder after "==".

FR11 rules:
- The name fully matches `^[A-Za-z0-9][A-Za-z0-9._-]*$`.
- The version is non-empty, contains no whitespace of any kind (spaces, tabs,
  line breaks), no `;` and no `#`, and does not begin with `-`.

Output:
- Each excluded entry adds one to the excluded count.
- Each kept pin becomes one line: the C1 canonical name, `==`, the version.
  The same canonical name with the same version collapses to one line. Hashes
  and markers are never written.
- Grouping (A5, D4): for each canonical name, sort its distinct versions by
  plain string order. The k-th version goes to group k, and groups are
  ordered 1..K. Lines inside a group are sorted.

Unconvertible:
- The file is absent on disk (for example, deleted by the change),
  unreadable, not valid UTF-8, or not valid TOML / JSON.
- Parsing fails in any other way (TM-4).
- The file resolves outside the project root (TM-3, through the existing
  project-root confinement helper).
- The structure check fails.
- Zero lines remain.

### Declaration check (C4) and direct names

- `_pip_manifest_candidate` maps Pipfile.lock to the sibling Pipfile and
  poetry.lock to the sibling pyproject.toml (unchanged). Every other name maps
  as before. It never returns a lockfile path, and it returns nothing for a
  path outside the project root.
- The check reports `not found` when the candidate is unresolvable or outside
  the project root, missing, unreadable, not valid UTF-8, or not valid TOML.
  The parseability test applies to both pyproject.toml and Pipfile. The
  pyproject.toml name extraction itself stays the existing parser (A7).
- Pipfile direct names are the keys of its `[packages]` and `[dev-packages]`
  tables (each only when it is a table). The existing direct-name resolution
  uses them whenever the resolved declaration file is a Pipfile.

### Canonical comparison (C1, FR9)

`normalize_pip` treats an advisory as direct when the canonical form of the
reported name equals the canonical form of any declared name. This applies to
every pip job, including requirements.txt and pyproject.toml.

### Scan flow for pip

1. Validate the registry entry and resolve the executable as today. The
   tool-absent and validation reasons are unchanged and come first.
2. Select the pip target (C2). A target that is not a lockfile follows the
   existing path unchanged.
3. Convert the lockfile (C3). If it is unconvertible, add
   `pip_lockfile_unconvertible`, launch nothing, and continue with the next
   ecosystem.
4. Run the declaration check (C4). If the result is `not found`, add
   `pip_direct_manifest_not_found`, launch nothing, and continue.
5. Inside the prepared-file scope (C5), for each group in order: build the job
   (C6) with the lockfile path and that group's file, execute it, and judge
   the outcome with the existing judgement.
6. Normalize each completed run with the lockfile path as manifest (FR10) and
   append its findings in run order. Collect the reasons of runs that did not
   complete, de-duplicate them, and add them to the skip reasons (D5). Sum the
   undetermined-severity counts over all runs.
7. Leaving the scope removes every prepared file, on normal and exceptional
   exit alike.
8. pip is listed as scanned when at least one run completed. Then append the
   unpinnable note (D3), worded as FR6 states it: one entry gives
   ` 1 pip lockfile entry not auditable (pip_lockfile_entries_unpinnable).`
   and N > 1 entries give
   ` N pip lockfile entries not auditable (pip_lockfile_entries_unpinnable).`

### Other existing functions

- `_pip_target`, `build_scan_job` and their docstrings: the lockfile
  directory form is removed in favour of C6.
- `build_scan_jobs`: performs no run-time preparation. Its docstring states
  that a pip lockfile target is outside its contract, because the C6
  rejection applies.
- Module loading: the script still loads without the standard-library TOML
  parser (D6).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1): target selection
  - When the changed-file list holds at least one pip lockfile (basename poetry.lock or Pipfile.lock), the pip target is the first such lockfile in list order. This holds even when pyproject.toml or requirements.txt appears earlier.
  - pip-audit is then launched only in the lockfile form. For [pyproject.toml, poetry.lock] the stub records exactly one invocation, and it carries `-r`, `--no-deps` and `--disable-pip`.
  - For a list without a pip lockfile, the pip target is the same file as before this change.
  - The targets for npm, cargo and go are unchanged for any list.
  - A list holding only uv.lock, pdm.lock or pylock.toml selects no ecosystem.
- [ ] AC-2 (FR3, NFR2, NFR6, TM-5): lockfile job form
  - A pip job built for a lockfile and a prepared requirements file has the argument vector [absolute pip-audit path, `-r`, prepared file path, `--no-deps`, `--disable-pip`, `--format`, `json`]. Its manifest is the lockfile's project-relative path.
  - The job is built even when the prepared path does not exist, without reading or writing any file and without launching a process.
  - A pip lockfile manifest given without a prepared file is rejected; it never yields the directory form.
  - Jobs for requirements.txt and pyproject.toml keep their previous argument vectors and contain neither `--no-deps` nor `--disable-pip`.
  - The pip registry entry, `ALLOWED_EXECUTABLES`, `ECOSYSTEM_LOCKFILES` and the pip child-environment pins hold their previous values.
- [ ] AC-3 (FR2, FR7, FR10): end-to-end findings
  - Setup: poetry.lock is the only changed file and pins a vulnerable version. The sibling pyproject.toml declares the package with a range that admits the fixed version.
  - The result has at least one finding for that package, `skipped` is false and `skip_reason` is null.
  - The finding's `file` is the lockfile's project-relative path, also when the lockfile sits in a subdirectory.
  - The finding's description carries the pinned version as the affected range.
  - The same holds for Pipfile.lock with a Pipfile that declares the package under `[packages]`, and for a package declared only under `[dev-packages]`.
  - The prepared file holds one `name==version` line for every pin of every group (all poetry.lock packages; Pipfile.lock default and develop). It holds no hash, and a repeated `name==version` appears once.
- [ ] AC-4 (FR4, NFR3): split runs
  - Setup: a lockfile pins one canonical name at two versions.
  - pip-audit is launched twice. Each prepared file contains that name exactly once, and the first launch receives the version that sorts first.
  - The single result holds the findings for both versions, in launch order.
  - Scanning the same input twice gives byte-identical result JSON, and no prepared-file path appears anywhere in the result.
  - When one of the two launches does not complete, the result is skipped with that launch's reason listed once (also when both fail with the same reason), and the other launch's findings are kept.
- [ ] AC-5 (FR5, FR12, TM-2, TM-3, TM-4): unconvertible lockfiles
  - Each of these selected lockfiles yields `skipped` true with skip_reason `pip_lockfile_unconvertible`: an invalid-TOML poetry.lock; an invalid-JSON Pipfile.lock; a poetry.lock without a top-level package array; a Pipfile.lock in which neither default nor develop is a mapping; a lockfile whose every entry is excluded (for example, all git); non-UTF-8 content; sections or entries of the wrong value type; JSON nested beyond the parser's limit; a lockfile that is a symlink resolving outside the project root; a lockfile listed as changed but absent on disk.
  - In every one of those cases the stub records no invocation, no exception leaves the scan, and neither the manifest form nor the directory form is used.
  - With cargo's tool absent and npm completing in the same scan, skip_reason is `cargo_tool_not_found+pip_lockfile_unconvertible` and npm's findings are kept.
- [ ] AC-6 (FR6, FR11, TM-1, TM-2): excluded entries
  - An entry is excluded from conversion and counted when any of these holds:
    - poetry.lock source type is git, directory, file or url
    - a Pipfile.lock entry carries git, path, file or editable
    - the version is missing, or (Pipfile.lock) not of the form ==X
    - the name does not fully match `^[A-Za-z0-9][A-Za-z0-9._-]*$` (for example `-r evil`)
    - the version contains whitespace, a line break, `;` or `#`, or begins with `-`
  - While at least one pin remains, the remaining pins are audited and `skipped` is false.
  - The summary ends with ` 1 pip lockfile entry not auditable (pip_lockfile_entries_unpinnable).` for one excluded entry, or ` N pip lockfile entries not auditable (pip_lockfile_entries_unpinnable).` for N > 1.
  - Every line of every prepared file passes the FR11 checks, and no excluded name or version text appears in any prepared file.
- [ ] AC-7 (FR7, FR8, TM-3, TM-4): declaration file
  - `_pip_manifest_candidate` returns the sibling Pipfile for Pipfile.lock and the sibling pyproject.toml for poetry.lock, never a lockfile path.
  - A selected lockfile yields `skipped` true with skip_reason `pip_direct_manifest_not_found` when its declaration file is missing, unreadable, not valid TOML, or a symlink resolving outside the project root. The stub records no invocation and no exception leaves the scan.
  - With a valid Pipfile, the direct names are exactly the keys of its `[packages]` and `[dev-packages]` tables.
- [ ] AC-8 (FR9): canonical names
  - Directness is decided on PEP 503 canonical names on both sides (lower-cased, each run of `-`, `_` and `.` replaced by one `-`).
  - With `Django` declared and `django` in the lockfile and in pip-audit's output, the advisory counts as direct and reaches the findings.
  - A declared `Foo_Bar.baz` matches a reported `foo-bar-baz`.
  - The existing requirements.txt and pyproject.toml normalization tests pass unchanged.
- [ ] AC-9 (NFR1, TM-6): temporary files
  - While pip-audit runs, each prepared file lies outside the project root and is accessible by its owner only (the stub records the permission bits).
  - After the scan returns, no prepared file remains: a test-owned temporary directory is empty again.
  - When the execution step raises, the exception propagates and no prepared file remains.
  - For a git-initialized project, `git status --porcelain` is identical before and after a lockfile scan.
- [ ] AC-10 (NFR4, NFR5, NFR7): dependencies, suites and scope
  - The script gains no import outside the standard library; lockfile and Pipfile parsing use only the standard-library TOML and JSON parsers.
  - The script still loads when the standard-library TOML parser is unavailable, and a poetry.lock target then yields `pip_lockfile_unconvertible`.
  - New and changed test modules import only the standard library and use neither a real pip-audit nor the network.
  - `python3 -m unittest discover -s tests` and `python3 em-workflow/scripts/check-plugin-invariants.py .` both succeed.
  - This task edits no file under a `.claude-plugin/` directory.

## Test Notes

- **Placement**: AC-1, AC-3 to AC-9 and the module-loading part of AC-10 go
  in the new module. AC-2 goes in `tests/test_sca_scan_invocation.py` (TS3)
  together with that module's existing job-form tests.
- **Module loading**: load the script by file path, as the sibling SCA test
  modules do. Write a small stub writer locally; do not import from a sibling
  test module.
- **Stub pip-audit**: a Python script with an absolute-interpreter shebang,
  with PATH restricted to its directory. On each invocation it records the
  argument vector, the content of the `-r` file and that file's permission
  bits to a record file in a test-owned directory outside the project root.
  It prints pip-audit-shaped JSON built from the `-r` lines. Configured
  vulnerable pins get an advisory whose description embeds a critical CVSS
  v3.1 vector, so the existing severity rule can determine the severity.
- **"Not launched"**: the record file is absent or empty.
- **Cleanup (AC-9)**: point the system temporary location at a test-owned
  empty directory for the test's duration, and assert it is empty after the
  scan. For the exception path, replace the execution step with one that
  raises, then assert both that the exception propagates and that the
  directory is empty.
- **Symlinks (AC-5, AC-7)**: place the symlink target in the test's own
  temporary directory, outside the project root.
- **Missing TOML parser (AC-10)**: load a fresh copy of the script while the
  standard-library TOML module cannot be imported.
- **Existing assertions in `tests/test_sca_scan_invocation.py`**:
  - Replace the test asserting the directory form for poetry.lock
    (lines 243-248).
  - The loops over manifests (lines 250-264) supply a prepared file path for
    lockfile manifests.
  - Check `install`, `--fix`, `-o`, `--output` and `--require-hashes` for
    every pip job, and `--no-deps` only for non-lockfile jobs.
  - Assert that lockfile jobs carry `--no-deps` and `--disable-pip`.
- **Unchanged files**: `tests/test_sca_scan_normalization.py` must pass
  unmodified (TS10).
- **Invariants (AC-2)**: assert the literal expected values of the registry
  pip entry, `ALLOWED_EXECUTABLES`, `ECOSYSTEM_LOCKFILES` and the pip
  child-environment pins.
