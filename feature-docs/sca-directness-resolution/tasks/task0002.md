# Task Plan: task0002 — pyproject.toml direct names from tomllib with explicit skip

## Goal

pip scan units whose direct names come from pyproject.toml read them with tomllib regardless of quoting and extras, include the Poetry dependency tables, mark the set incomplete wherever a declaration cannot be resolved, and skip explicitly when tomllib is unavailable.

## Requirements

FR3, FR5, FR6, FR7, NFR1, NFR3, NFR4, NFR6

## Scope

### Files to Create
- `tests/test_scan_dependencies_pyproject_directness.py` — regression tests for this task's acceptance criteria

### Files to Modify
- `em-workflow/scripts/scan-dependencies.py` — pyproject resolver over tomllib, pip FR6 skip, shared components when absent

## Design

Cross-task contracts (DirectNames, `_requirement_name`) and decisions D1, D4 and D5 are in IMPLEMENTATION.md; they are referenced here, not restated.

### pyproject resolver (`_pip_pyproject_direct_names`)

- Pre: the pyproject.toml location.
- Post: a `DirectNames`; never raises.

1. Read and parse the manifest with tomllib. Not resolvable, not readable, or not valid TOML → empty and incomplete.
2. `[project].dependencies` present as a list: each item goes through `_requirement_name`; its name is direct. A non-string item, or an item with "no name", makes the set incomplete; the remaining items are still read.
3. `[project].dependencies` absent while `[project].dynamic` lists `dependencies` → incomplete.
4. `[tool.poetry.dependencies]` and `[tool.poetry.dev-dependencies]`: every key whose canonical form is not `python` is a direct name.
5. Neither a static `[project].dependencies` list nor either Poetry table present → incomplete. A static empty list is a complete declaration of zero names.
6. `project.optional-dependencies`, `dependency-groups`, `tool.poetry.group.<g>.dependencies` and every other table are never read as declarations and never affect completeness.
7. Unexpected shapes (`dependencies` not a list, a Poetry dependency table not a table, `dynamic` not a list) → incomplete.

### Explicit skip (FR6)

Per IMPLEMENTATION.md D4: a pip unit whose direct names would come from pyproject.toml — the pyproject unit itself, or a lockfile unit that passes the existing lockfile checks and whose direct manifest is pyproject.toml — is reported skipped with skip reason `pip_toml_parser_unavailable` when tomllib is unavailable at call time, and pip-audit is not invoked for it. The checks that yield `pip_direct_manifest_not_found` and `pip_lockfile_unconvertible` keep their conditions and run first. Requirements-file units never take this skip.

### Classification boundary

This task does not change `normalize_pip`, the pip undetermined count or the summary notes; per the IMPLEMENTATION.md function ownership table those belong to another task. The resolver's result reaches the pip classifier through the existing call path, and D1 keeps the current classifier working with a `DirectNames`.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR3): For `dependencies = ['requests[socks]>=2', 'django==3.2.0']` (single-quoted), the resolver returns exactly requests and django, marked complete; double-quoted strings, entries with environment markers, and `name @ url` direct references yield their names the same way. Through the scan, a severity-high advisory reported for requests and one for django each produce a finding. (TS-7)
- [ ] AC-2 (FR3): Keys of `[tool.poetry.dependencies]` and `[tool.poetry.dev-dependencies]` are direct names except `python`. Names that appear only in `project.optional-dependencies`, `dependency-groups` or `tool.poetry.group.<g>.dependencies` are not direct, and a manifest declaring only those tables is incomplete. (TS-19)
- [ ] AC-3 (FR5, TM-5): The resolver marks the set incomplete — while still returning every name it did resolve — when `[project].dynamic` lists dependencies without a static list, when neither `[project].dependencies` nor a Poetry dependency table exists, when the manifest is invalid TOML, and when it cannot be read; in each case the scan unit is not skipped. (TS-8, TS-20)
- [ ] AC-4 (NFR3, TM-4): For unexpected shapes — `dependencies` given as a string, a non-string list item, a Poetry dependency table given as a string, `dynamic` given as a string — the scan returns normally without an exception and the set is incomplete. (TS-25)
- [ ] AC-5 (FR6, NFR4, TM-6): With the module's guarded tomllib binding replaced by None, a pyproject.toml scan unit reports skip reason exactly `pip_toml_parser_unavailable` and the pip-audit stand-in is never invoked for it, while a requirements.txt unit in the same scan completes. (TS-15)
- [ ] AC-6 (FR6): With tomllib replaced by None, the situations that produce `pip_direct_manifest_not_found` and `pip_lockfile_unconvertible` today produce the same tokens, and no unit whose direct names come from a requirements file reports `pip_toml_parser_unavailable`. (TS-24)
- [ ] AC-7 (NFR1): `python3 -m unittest discover -s tests` passes and the script imports nothing outside the standard library (tomllib only through the existing guarded import). (TS-26, TS-28)

## Test Notes

- AC-1 to AC-4 test the resolver directly (names plus `complete`); AC-1 additionally drives the pip scan path with a stand-in pip-audit payload, relying on the current classifier.
- Counting undetermined advisories for the AC-3 cases is covered on the classifier side through a stand-in for this resolver (IMPLEMENTATION.md D5); do not add pip counting here.
- tomllib absence (AC-5, AC-6): replace the module's guarded binding with None for the duration of the test and assert the scanner stand-in recorded no invocation.
- Unreadable manifest (AC-3): remove read permission; skip only that sub-case when the test runs with privileges that ignore file permissions.
