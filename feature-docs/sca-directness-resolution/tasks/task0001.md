# Task Plan: task0001 — Cargo directness from a tomllib-parsed Cargo.toml with undetermined reporting

## Goal

Cargo scan units decide directness by canonical-name matching against direct names read from a tomllib-parsed Cargo.toml, count the advisories they cannot classify into the cargo undetermined note, and skip explicitly when tomllib is unavailable.

## Requirements

FR1, FR2, FR5, FR6, FR7, NFR1, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `tests/test_scan_dependencies_cargo_directness.py` — regression tests for this task's acceptance criteria

### Files to Modify
- `em-workflow/scripts/scan-dependencies.py` — Cargo resolver over tomllib, canonical matching and undetermined counting in normalize_cargo, cargo FR6 skip, undetermined aggregation and notes call in run_scan, shared components when absent

## Design

Cross-task contracts (DirectNames, the legacy-value rule, canonical_pip_name, the per-unit `directness_undetermined` count, `_undetermined_directness_notes`) and decisions D1–D4 are in IMPLEMENTATION.md; they are referenced here, not restated.

### Cargo resolver (`_cargo_direct_dependency_names`)

- Pre: the scan unit's Cargo.toml location.
- Post: a `DirectNames`; never raises.

1. Read and parse the manifest with tomllib. Not resolvable, not readable, or not valid TOML → empty and incomplete.
2. Dependency tables: `dependencies`, `dev-dependencies` and `build-dependencies` at the top level, and the same three under every `target.<cfg>` table. The sub-table form (`[dependencies.serde]`) is an ordinary entry of the parsed dependencies table and is read like the inline forms.
3. Name of each entry (key K, value V):
   - V is a table with a string `package` → that string.
   - V is a table with `workspace = true` → when the same manifest's `[workspace.dependencies]` entry K is a table with a string `package`, that string; otherwise K.
   - Otherwise → K.
4. A `[workspace]` table with a non-empty `members` list → incomplete. Member manifests are not read; the root's own entries stay in the set.
5. Any unexpected shape (a dependency table that is not a table, `package` that is not a string, `target` that is not a table, `members` that is not a list) → incomplete.

Entries of `[workspace.dependencies]` are not direct names by themselves.

### Classification (`normalize_cargo`)

Apply IMPLEMENTATION.md D2, comparing canonical forms of both the reported and the declared names (FR1). A payload entry carrying `is_direct` keeps precedence. Report the unit's `directness_undetermined` and forward it to `run_scan` through the cargo scan unit.

### Explicit skip (FR6)

Per IMPLEMENTATION.md D4: when a cargo unit's direct names would come from a Cargo.toml and tomllib is unavailable at call time, the unit is reported skipped with skip reason `cargo_toml_parser_unavailable`, and cargo-audit is not invoked.

### Summary

Write the D3 aggregation in `run_scan` (both ecosystem sums, one `_undetermined_directness_notes` call appended after every pre-existing note).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1): Given a Cargo.toml declaring `Foo_Bar` and a cargo-audit payload without `is_direct` reporting `foo-bar` with severity high, the scan produces exactly one finding for that advisory. Given a payload entry that carries `is_direct`, its directness follows `is_direct` regardless of the manifest — also when the set is incomplete — and it is never counted as undetermined. (TS-1, TS-17)
- [ ] AC-2 (FR2): Crates declared in `[dependencies]`, `[dev-dependencies]` and `[build-dependencies]`, in the sub-table form `[dependencies.serde]` with `version = '1'`, and in `[target.'cfg(unix)'.dependencies]` as `foo = '1'` are direct: a severity-high advisory for serde and one for foo each produce a finding. (TS-2, TS-4)
- [ ] AC-3 (FR2): With `alias = { package = 'real-name', version = '1' }`, an advisory for real-name produces a finding and an advisory for alias is not matched as direct. With `x = { workspace = true }` and a `[workspace.dependencies]` entry x carrying `package = 'y'`, an advisory for y produces a finding. (TS-3, TS-18)
- [ ] AC-4 (FR5, TM-5): Given a Cargo.toml whose `[workspace]` lists members and a severity-high advisory for a crate it does not declare, the scan produces no finding for that advisory, `skipped` stays false, and the summary ends with ` 1 cargo advisory with undetermined directness (cargo_directness_undetermined).`; crates declared in the root's own tables remain direct. Given a complete manifest, an advisory for an undeclared crate stays transitive and no undetermined note appears. (TS-5, TS-14)
- [ ] AC-5 (FR5, NFR3, TM-4): For a Cargo.toml that is invalid TOML, one that cannot be read, and ones with unexpected shapes (a dependencies table given as a string, `package` given as a number), the scan returns normally without an exception and a severity-high advisory for an undeclared crate is counted as cargo undetermined. (TS-6, TS-25)
- [ ] AC-6 (FR5, NFR4, TM-6): Under an incomplete set, an undeclared advisory whose severity is known and below the threshold is dropped without being counted, and one whose severity is unknown is counted exactly once. Two undetermined advisories produce the plural text (`advisories`). The cargo undetermined note follows every pre-existing summary note and contains no crate name, manifest path or advisory text. (TS-16, TS-23)
- [ ] AC-7 (FR6, NFR4, TM-6): With the module's guarded tomllib binding replaced by None, a cargo scan unit with a Cargo.toml reports skip reason exactly `cargo_toml_parser_unavailable` and the cargo-audit stand-in is never invoked. (TS-15)
- [ ] AC-8 (NFR1, NFR5): `python3 -m unittest discover -s tests` passes, the pre-existing npm and go tests pass without modification, and the script imports nothing outside the standard library (tomllib only through the existing guarded import). (TS-26, TS-28)

## Test Notes

- AC-1 to AC-7 are tests in the new module that drive the cargo scan path end to end with a temporary project directory and a stand-in cargo-audit payload; AC-8 is the full suite run.
- Canonical matching (AC-1): cover case and separator variants (underscore, hyphen, dot).
- tomllib absence (AC-7): replace the module's guarded binding with None for the duration of the test and assert the scanner stand-in recorded no invocation.
- Unreadable manifest (AC-5): use a manifest whose read permission is removed; skip only that sub-case when the test runs with privileges that ignore file permissions.
- AC-6 ordering: include at least one pre-existing note in the scenario (for example a go note via its stand-in) and assert the cargo note comes after it.
