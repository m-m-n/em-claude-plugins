### Requirements resolver (`_pip_requirements_direct_names`)

- Pre: the scan unit's requirements file, located inside the project root, and the project root.
- Post: a `DirectNames`; never raises; never opens a file outside the project root; never fetches a URL.

The walk starts at the unit's file. A visited set, shared by the whole walk and keyed by each file's resolved location, records every file opened. For each file:

1. Read it. Missing or unreadable → incomplete; this branch ends.
2. Join every physical line ending in a backslash with the following line; drop comments and blank lines.
3. For each logical line:
   - **Include** (`-r X`, `-rX`, `--requirement X`, `--requirement=X`):
     1. X is a URL → not fetched; incomplete.
     2. Otherwise X is taken relative to the including file's directory, expressed relative to the project root, and accepted only when `_resolve_project_relative` confines it to the root (this rejects `..` escapes, absolute paths outside the root, and symlinks resolving outside it). Rejected → never opened; incomplete.
     3. Already visited → nothing happens; the set is not made incomplete.
     4. Otherwise → walk into it; the names it declares are direct.
   - **Constraint** (`-c X`, `-cX`, `--constraint X`, `--constraint=X`) → ignored: not opened, and the set is not made incomplete.
   - **Editable** (`-e`, `--editable`) → a path or URL requirement without a resolvable name → incomplete.
   - **Any other option line** → ignored, as today.
   - **Requirement line** → `_requirement_name`; a name is direct; "no name" → incomplete.

### Classification (`normalize_pip`)

Apply IMPLEMENTATION.md D2, comparing canonical forms of both the reported and the declared names. Report the unit's `directness_undetermined` and forward it to `run_scan` through the pip scan unit. An advisory counted as undetermined is not also counted in the existing unknown-severity counter.

### Summary

Write the D3 aggregation in `run_scan` (both ecosystem sums, one `_undetermined_directness_notes` call appended after every pre-existing note).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR4): A requirements.txt containing only `-r requirements/base.txt` yields the names declared in requirements/base.txt as direct, marked complete, and a severity-high advisory for one of them produces a finding. Nested includes (each relative to its including file's directory), the forms `-rX`, `--requirement X` and `--requirement=X`, and lines continued with a trailing backslash resolve the same way. (TS-9, TS-21)
- [ ] AC-2 (FR4, NFR2, TM-1): Includes that leave the project root — through `..`, through an absolute path, or through a symlink whose target lies outside the root — are never opened (a fixture file outside the root is not read and its names never appear), the set is incomplete, and a severity-high advisory for an undeclared package is counted as pip undetermined. (TS-10)
- [ ] AC-3 (FR4, FR5, NFR2, NFR3, TM-2, TM-4): A URL include is never fetched (no network access is attempted). A missing include target, an unreadable include target, a line holding only a URL or a local path, and an editable line each mark the set incomplete; the scan returns normally without an exception and a severity-high advisory for an undeclared package is counted as pip undetermined. (TS-13, TS-22, TS-25)
- [ ] AC-4 (FR4, TM-3): For two requirements files that include each other, the resolver terminates, names from both files are direct, and the set stays complete. A `-c constraints.txt` line is not opened, names only in constraints.txt are not direct, and the set stays complete with no undetermined note. (TS-11, TS-12)
- [ ] AC-5 (FR5, TM-5): The pip classifier compares canonical names on both sides (a pyproject.toml declaring `Django==3.2.0` with pip-audit reporting `django` produces a finding). With a complete set, an advisory for an undeclared package stays transitive and no undetermined note appears. With an incomplete set, an undeclared advisory whose severity is known and below the threshold is dropped uncounted, and one whose severity is unknown is counted once as undetermined and not in the existing unknown-severity note. An incomplete `DirectNames` supplied by a stand-in for the pyproject resolver is counted the same way. (TS-8, TS-14, TS-20, TS-23)
- [ ] AC-6 (FR5, NFR4, TM-6): The pip note reads exactly ` 1 pip advisory with undetermined directness (pip_directness_undetermined).` for one advisory and uses `advisories` for two or more; it comes after the pre-existing pip severity, unpinnable and go notes; when a cargo count is also supplied through `directness_undetermined` by a stand-in cargo unit, the pip note precedes the cargo note; the notes contain no package name or path; `skipped` and `skip_reason` are unchanged. (TS-16)
- [ ] AC-7 (NFR1, NFR5): `python3 -m unittest discover -s tests` passes, the pre-existing npm and go tests pass without modification, and the script imports nothing outside the standard library. (TS-26, TS-28)
