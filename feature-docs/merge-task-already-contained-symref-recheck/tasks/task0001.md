# Task Plan: task0001 — Re-check the integration ref on merge-task.sh's already-contained path

## Goal

On merge-task.sh's already-contained path, `merged` and exit 0 are produced only when one condition holds right before the journal append: the integration ref is still a direct ref whose value equals the parent value read under the lock. Otherwise the run ends with exit 2 and has no side effects. Tests inject the check-to-read gap and prove the fix.

## Design

### Re-check on the already-contained path (merge-task.sh)

Position: inside the branch named by the "Parent already contains us" comment. It runs after the ancestor check succeeds and before the merged-event append and the `MERGED:` line.

Flow:

1. The ancestor check of the task tip against PARENT succeeds (existing).
2. Ask git quietly whether the exact integration ref (`refs/heads/` + PARENT_BRANCH) is a symbolic ref. Use the same query form as the existing post-lock check (SPEC.md FR1 (1)). Decide on the exit status alone:
   - 0 (a symbolic ref, dangling included): reject. The ERROR line names the integration ref and contains "symbolic ref".
   - 1: continue to step 3.
   - any other status: reject. The ERROR line names the integration ref and the exit status.
3. Run the same-value compare-and-swap on the exact integration ref with the no-deref option. The new value and the expected old value are both PARENT, the value read under the lock (SPEC.md FR1 (2); the glossary's 同値 CAS). On failure, reject. The ERROR line names the integration ref and contains "update-ref".
4. On success, the existing merged-event append (with PARENT), the `MERGED:` line and exit 0 follow unchanged.

Contract:

- **Precondition**: the merge lock is held. PARENT is the commit read from the exact integration ref after the existing post-lock symbolic-ref check. The ancestor check of the task tip against PARENT succeeded.
- **Postcondition, accepted**: at the moment of the CAS, the integration ref is a direct ref whose value equals PARENT. The CAS is the last git invocation before the journal append.
- **Postcondition, rejected**: exit 2. Stderr carries exactly one line beginning with `ERROR`, and the line contains PARENT_BRANCH. The two re-check calls do not pass git's own diagnostic output through to stderr. No dirty-worktree wording appears. No journal.jsonl is created or extended. No `MERGED:` line appears on stdout. A step-2 rejection writes no ref at all. A step-3 rejection leaves the integration ref's value and the task ref's value unchanged.
- **Kept as is**: the existing post-lock symbolic-ref check before the parent-value read, the fast-forward path, the merge-commit path and the meaning of exit codes 0 / 1 / 2 (IMPLEMENTATION.md D2).

### Comments (FR4)

Four locations gain this statement: on the already-contained path, right before `merged` is recorded, the script confirms that the integration ref is still a direct ref. It then confirms by a same-value CAS that the ref's value is still PARENT. If either check fails, the run ends with exit 2. The four locations:

- the header paragraph stating that the integration ref must be a direct ref
- the exit 2 examples in the "Exit codes" block
- the "Merge source and parent" section comment
- the already-contained branch itself

Header and section wording that counts the integration ref's no-deref update-ref calls is adjusted to stay accurate once the CAS adds one more such call. The comment for the already-contained branch must not go between the "Parent already contains us" line and the ancestor-check line that follows it, and it must not repeat the case name.

### Content pin (FR5)

The pin equals the sha256 of the final merge-task.sh bytes. Any commit that changes merge-task.sh also updates the pin in that commit. The provenance list in the comment right above the pin gains an entry for this feature (feature name, task0001 and a short clause on what changed), in the same form as the existing entries.

### Test harness: new git-shim modes (tests/test_merge_task_journal.py)

Extend the existing `_build_git_shim` helper. The existing "repoint" and "status" modes keep their behavior, and the helper's documentation describes every mode. In each new mode, every invocation not described below goes to the real git unchanged. Each mode records its interceptions so that a test can assert how many times the shim acted. Invocation counts ("first", "second") are kept per shim instance. The values the shim needs (the ref to point at and the original integration value) are supplied when the shim is built.

| Mode (name is the implementer's choice) | Behavior | Used by |
|---|---|---|
| swap | On the first invocation whose subcommand is show-ref and whose arguments include the integration ref, the shim first uses the real git to make the integration ref a symbolic ref targeting the task ref. It records the interception, then hands the original invocation to the real git. Later show-ref invocations pass through. | TS-1 |
| swap then restore | Swap as above. Then, on the second invocation whose subcommand is symbolic-ref and whose arguments include the integration ref, the shim first uses a no-deref update through the real git to set the integration ref back to its original value as a direct ref. It records the interception, then passes the call through. | TS-2 |
| delete before re-check | On the second symbolic-ref invocation naming the integration ref, the shim first deletes the integration ref through the real git. It records the interception, then passes the call through. | TS-5 |
| second status | The first symbolic-ref invocation naming the integration ref passes through. The second is recorded and exits 128 without calling git. | TS-3 |

## Test Notes

- **TDD order**: add the shim modes and the AC-1 to AC-3 tests first, and run them against the unmodified script. The expected red results: TS-1 and TS-2 end with exit 0 and a `merged` event. TS-3 and TS-5 end with exit 0 and a journal of two lines, because the pre-change script makes no second symbolic-ref call and the shim never acts. Record these red reasons, then change the script.
- **Determinism**: the shim injects every race synchronously inside the script's own git invocation. Use `_run_merge` with the shim env. No sleep, lock-wait harness or process signalling is needed.
- **Side effects on symbolic-ref cases**: assert ref values through the exact-ref helpers (`_exact_ref_value`, `_parent_symbolic_target`). The name-resolving helpers follow symbolic refs.
- **Assertions when the journal must not exist**: AC-1 and AC-2 (a) can reuse `_assert_symref_case_rejected`. The other runs start after a first merge, so the journal already exists; AC-2 (b) and AC-3 assert an unchanged journal line count instead of an absent journal.
- **Reflog**: not asserted, per SPEC.md Assumptions.
- **AC-5 comment wording and AC-7**: checked by review of the diff against the implement base commit. The structural parts of AC-5 are covered by the existing doc-contract pins.
