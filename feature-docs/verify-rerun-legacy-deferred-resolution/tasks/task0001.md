## Design

### Legacy re-run statement (FR1)

Added to the same subsection, following IMPLEMENTATION.md Shared Components "Legacy re-run procedure" and decisions D1, D2 and D4. It states, in Japanese and in the subsection's existing style:

1. When verify is re-run on a workflow.yaml whose verify step has no round or no passed_ids, the same procedure is followed.
2. In that case round becomes 1 (the absent round is read as 0, per the workflow-schema.md rule the subsection cites, not restates).
3. passed_ids is written in the same workflow.yaml write that records result.
4. When result is pass, the mapping and the run of resolve-verified-findings.py are performed, followed by the existing commit step. When result is not pass, neither is performed (the existing behavior).

The statement does not describe how verify is returned to pending (D4).

### Mapping rule (FR3)

The subsection's mapping rule follows IMPLEMENTATION.md D3:

- Mapped: a finding whose claim is that criterion ID's miss, even when cause analysis, a fix suggestion or a scope judgment is written alongside it.
- Not mapped: a finding whose correspondence is ambiguous; a finding that also claims the miss of another criterion that has not passed, or another defect; a finding in whose body the ID merely appears.
- The phrase 「未達そのもの以外の内容を含む指摘は対応づけない」 is removed from the subsection.

### Text that must stay (NFR2, NFR3)

The rewrite keeps every existing fixed phrase of the subsection, including: interactive でも batch でも同じ; ゲートも質問も batch の non-packet ゲートも追加しない; 未達そのものであるときだけ; 本文に ID が現れているだけでは足りない; 対応が曖昧な指摘; the reference to Untrusted-Input Handling. The kept phrase 未達そのものであるときだけ and the new add-on tolerance must read as one consistent rule: the claim is the miss itself, and add-ons are not a second claim.

The rewrite adds no text naming gate_id, AskUserQuestion or batch-policies.yaml, no wording that gives deferred to the rest of verify, and no backtick around category vocabulary anywhere in the verify phase (write category spec, not a backticked spec).

### Test changes (FR4)

tests/test_verify_pass_resolution_procedure.py reads the subsection text, as the existing tests in the file do, and gains assertions for each statement of the two parts above. The test TestAC2MappingRule.test_ac2_ambiguous_and_mixed_content_findings_are_left_out is updated to pin the new not-mapped wording and to assert the old exclusion phrase is absent. The other existing assertions stay as they are; when the Untrusted-Input Handling reference and 本文に ID が現れているだけでは足りない are not already pinned, assertions are added for them.
