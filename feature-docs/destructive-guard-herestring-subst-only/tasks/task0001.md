# Task Plan: task0001 — Bound the here-string branch's payload index so later destructive statements are judged

## Goal

destructive-guard no longer crashes on a command line that aims a here-string
at a shell word whose only remaining token is a substitution. Instead the
hook completes and denies the later `rm -rf /var/b` in the same command line.
Before the fix, regression cases for both substitution spellings are added
to the expectation suite.

## Requirements

FR1, FR2, FR3, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/hooks/destructive-guard.py` — here-string branch of the shell-payload extraction function (extract_shell_payload_anchored). Only the condition right after the payload-index helper call changes.
- `em-workflow/hooks/tests/destructive-guard-cases.json` — two deny cases are added.

## Design

### Defect

In the here-string branch of extract_shell_payload_anchored, the here-string
target token can be an unquoted whole-word substitution placeholder. In that
case the branch asks the payload-index helper (_payload_index) for the first
non-placeholder word at or after position 1 of the statement's word list.
When the start position is already out of range, the helper returns the
start position unchanged. That is its documented contract, and this task
keeps it (NFR1).

Take a statement whose only word is the shell word itself, such as
`bash <<< $(echo hi)` or ``sh <<< `x` ``. Its word list has one element,
so the returned index equals the list length. The branch then reads the word
at that index. The out-of-range error is uncaught, and the hook exits with a
non-zero status. That outcome does not block the command, so the later
statements of the same command line are never judged.

### Change (FR1)

The branch promotes the word at the returned index to the payload only when
all three conditions hold. They are evaluated in this order:

1. the index is greater than zero;
2. the index lies inside the word list (it is less than the list length);
3. the word at that index is not itself a whole-word substitution
   placeholder.

The word itself is read only after condition 2 holds. When any condition
fails, the branch takes its existing fallback, which is unchanged: it returns
the here-string target token (the marked placeholder) as both payload and
anchor.

The helper's contract and body stay unchanged. The range check lives at the
call site.

### Resulting behaviour (FR2)

The two command lines are `bash <<< $(echo hi); rm -rf /var/b` and
``sh <<< `x`; rm -rf /var/b``. For each, the first statement takes the
placeholder fallback above and the hook keeps running. The second statement
is judged as a separate statement and receives deny. The hook exits 0 with a
deny decision.

### Work order (FR3, `.claude/rules/hook-tests.md`)

1. Add the two deny cases to the case file.
2. Run the suite against the unfixed code. Confirm both new cases fail with
   got `(exit 1)`.
3. Apply the condition change.
4. Run the full suite and confirm every case passes.

### Behaviour that stays unchanged (NFR1)

These stay as they are:

- the payload-index helper;
- the `-c` branch;
- the `eval` branch;
- the other paths of the here-string branch: a target that is not a
  placeholder is still returned directly, and a quoted whole-word
  substitution target still yields no payload.

## Test Notes

- The test harness is the existing expectation suite. Each AC-1 case is one
  test. The runner launches the hook as a subprocess with a PreToolUse Bash
  JSON input, so one check covers both the exit status and the decision. A
  non-zero exit shows up as got `(exit N)`, and a deny on exit 0 shows up as
  `deny`.
- How each criterion is checked:

  | Criterion | Check |
  |---|---|
  | AC-1 | the case file itself |
  | AC-2 | the red run |
  | AC-3, AC-4 | the two new cases on the fixed code |
  | AC-5 | the full suite run |
  | AC-6, AC-7 | diff inspection |

- AC-2 is the TDD red step. Record that run in the task's test record. The
  runner accepts a path argument, so the same check can be reproduced later
  against the base revision's copy of the hook.
- Edge case covered by the change: a statement whose word list is the single
  shell word, so the index is out of range.
- Edge case already handled, needing no new case: a statement that has words
  after position 1, all of them placeholders. The helper returns position 1,
  which is in range, and condition 3 sends it to the fallback.
- Run the suite in the same change as the code fix
  (`.claude/rules/hook-tests.md`).

## Out of Scope

- Changing the payload-index helper's contract or body, or the `-c` or
  `eval` branches.
- Pinning a verdict for `bash <<< $(echo hi)` alone, without a later
  destructive statement.
- Hardening crash paths outside the here-string branch, or adding a
  catch-all error handler to the hook.
- Any change to plugin versions.
