# Task Plan: task0001 — Zero-count rules in artifact-digest.md with documentation tests

## Goal

The Pre-dispatch verification and Layer 5 recording sections of `em-workflow/references/artifact-digest.md` state what happens when there is nothing to verify or record. In that case Calculation is not run: the verification succeeds, or nothing is recorded. `tests/test_artifact_digest_docs.py` pins both zero cases, so the repeated stale judgement and the false layer-5 failure cannot return unnoticed.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/references/artifact-digest.md` — add the zero-target rule to the Pre-dispatch verification section and the zero-artifact rule to the Layer 5 recording section
- `tests/test_artifact_digest_docs.py` — add tests that pin both zero cases; existing test methods stay unchanged

## Design

The contracts of both edited sections, and of the unchanged Calculation command, are pinned in IMPLEMENTATION.md, Shared Components. This section covers placement within each section and the test design.

### Pre-dispatch verification (FR1)
1. Add a zero-target rule as the first decision of the section's procedure, ahead of the step that runs Calculation over the targets. A reader who follows the section in order must meet this rule before any Calculation step.
2. The rule counts the write-policy targets that require an `expect_digest`. Cite the write-policy model for which actions carry that requirement; do not list the actions again.
3. When the count is zero, Calculation is not run, the verification is treated as successful (not a mismatch), and the dispatch proceeds.
4. State that the zero case covers both an empty targets list and a targets list in which no target requires an `expect_digest`, for example one whose targets are all `create` (SPEC.md Edge Cases).
5. When the count is one or more, the existing procedure and every existing mismatch condition stay as they are: a sha256 difference, an error element, a path that the quoting rule keeps out of the command, and exit code 2.

### Layer 5 recording (FR2)
1. Add a zero-artifact rule ahead of the existing one-Calculation step: when the result's `written_artifacts` has zero entries, Calculation is not run and nothing is recorded.
2. In the same place, state that whether an empty `completed` result is acceptable is not decided here. It is left to the rules of the layer that handles that result. Do not name or restate those rules.
3. For one or more entries, keep the existing procedure: one Calculation call over every `written_artifacts` path, and an artifact-validation failure on an error element, on exit code 2, or on a path that the quoting rule excludes.

### Constraints on the document edit (NFR1, NFR2)
- Add text only. Do not reword or remove any sentence that existing tests pin. This covers the "one Calculation call" and "every written_artifacts path" phrases, the exit-code-2 item of the Calculation section ("no argument was given", "standard output carries no array"), and the error-element mismatch and failure wording.
- Add no heading of any level. Write each rule as prose or list items inside its existing section, so the six level-2 headings and any heading-based slicing in the existing tests stay intact.
- Leave the Calculation, Digest definition, Legacy records and Dispatch sites sections unchanged.
- Edit no file outside Scope. The citing dispatch sites and the write-policy model's "Who verifies expect_digest" passage already cite this document.

### Documentation tests (FR4, NFR3)
- Add new test methods; a new test class in the same file is acceptable. Reuse the file's existing section-slicing and whitespace-normalization helpers where they exist instead of adding parallel ones.
- Pre-dispatch test: in the heading-sliced, whitespace-normalized Pre-dispatch verification section, assert the presence of (a) a zero-count phrase tied to the `expect_digest` requirement, (b) a statement that Calculation is not run, and (c) a statement that the verification succeeds rather than mismatches.
- Layer 5 test: in the heading-sliced, whitespace-normalized Layer 5 recording section, assert the presence of (a) a zero-count phrase tied to `written_artifacts`, (b) a statement that Calculation is not run, (c) a statement that nothing is recorded, and (d) the statement that leaves the acceptability of an empty `completed` result to another layer's rules.
- Choose the document wording and the asserted phrases together, so the tests pin the key phrases of the rule, not a whole sentence or its line layout.
- If a new matcher is used to assert absence, add a paired case showing that the matcher fires on crafted text containing the phrase.
