# Task Plan: task0002 — Resolve heredoc destinations from one structural analysis shared with statement splitting

## Goal

Every heredoc's destination is decided from the same lexical and statement
structure that `statements()` itself uses. That structure covers:

- case state
- compound groups, including groups opened in earlier statements
- pipelines continued over blank lines
- command-substitution nesting
- comments and quotes

The destination is never decided from a separate re-lex of the chunk.
Sink-bound bodies that the current code lets through are denied again, and
the cost of deciding destinations stays proportional to input size.

## Design

Cross-task context lives in IMPLEMENTATION.md:
- D2 is the FR5 interpretation. Its three outcomes (sink-bound,
  undeterminable, data) and the undeterminable conditions stay as they are.
- D3 is the rework decomposition and the version rule.
- Shared Components SC1 (statement classification) and SC2 (fallback sink
  match) are contracts this task calls. It never changes what they decide.

The terms (heredoc operator, host statement, enclosing statement, pipeline,
command word, sink word, data command) keep the meanings fixed by the first
pass. Everything below is local to this task.

### Component 1: lexical structure scan (one scanner, two outer modes)

- **Input**: a text and an outer mode, `shell` or `heredoc-body`.
- **Output**:
  - the comment spans
  - the quoted spans
  - the command-substitution spans, in both spellings, each with its parent
    span and whether it is closed
- **Postconditions**:
  1. Inside a substitution body, shell rules apply in both modes:
     - A `)` inside quotes, inside a comment or ending a case pattern never
       closes the span.
     - Nested substitutions are reported at every level.
  2. In `shell` mode, a `#` at the start of a word outside quotes starts a
     comment that runs to the end of the line. Text inside a comment or
     inside single quotes opens no substitution.
  3. In `heredoc-body` mode, quote characters and `#` outside any
     substitution are literal text. A backslash-escaped `$` or backtick
     opens no span.
  4. An unterminated span is reported as unterminated and extends to the
     end of the text. It is never truncated silently.
  5. This is the only routine in the file that finds substitution
     boundaries. Every caller uses it: chunk processing, heredoc operator
     collection and body-substitution extraction.

### Component 2: heredoc operator collection (refines the first-pass extraction)

- Operators inside a comment (Component 1, `shell` mode) are never
  collected, at any position on the line.
- An operator that is not the first operator on its line is collected only
  when it is outside quotes.
- The first operator on a line keeps its current recognition, including
  inside quotes. SPEC.md Assumptions keep that behaviour.
- Body consumption is otherwise unchanged from the first pass. Operators
  consume body lines in order, and text after the last consumed delimiter
  line stays in the chunk and is checked as commands (FR3, FR4).

### Component 3: chunk statement analysis (built once per chunk)

It is built from the same lexing result `statements()` uses:
- substitutions are marked
- case state carries across statements

For each statement it records:
- **Source span**: its position in the heredoc-stripped chunk. Heredoc
  operators are mapped to host statements by position only.
  - No marker characters are inserted into the text.
  - A control character in the input has no special meaning.
- **Shaped words**: identical to what `statements()` yields for it.
- **Case state at its start**: only `case` and `esac` in command-word
  position change it.
  - A quoted `esac`, or an `esac` that is an argument or a pattern, never
    closes it.
  - Pattern words before the pattern's closing `)` are never command words.
- **Pipeline membership**:
  - A pipe separator continues the pipeline to the next statement that has
    words.
  - Segments that hold only whitespace or newlines are skipped. They never
    end the downstream search.
  - `||`, `&&`, `;`, `&` and a bare newline end the pipeline.
- **Open compound groups**: every `{ … }` or `( … )` open at the statement,
  including groups opened in an earlier statement or on an earlier line.
  Each group records the downstream pipeline that follows its closer.
- **Substitution nesting**: which substitution span holds the statement,
  and that span's enclosing statement.

Statements inside a substitution body are analysed by the same procedure,
within the existing ten-level depth cap. Each substitution body is analysed
at most once per chunk, and every heredoc record in the chunk is resolved
against this one analysis.

### Component 4: destination decision (keeps D2's outcomes, changes the evaluation order)

For one heredoc, the **levels** are:
- the host statement
- its pipeline downstream
- the downstream pipeline after the closer of each compound group open at
  the host
- each enclosing statement, with its own pipeline and its own open groups,
  outward to the outermost

Each level's statements are classified with SC1.

1. **sink-bound** when any level has a sink. This holds even when another
   level is unlexable or undeterminable.
2. Otherwise **undeterminable** when any level meets a D2 condition, or any
   of these holds:
   - A group closer's downstream pipeline cannot be found.
   - A substitution body the heredoc sits in fails to lex.
3. Otherwise **data**.

The rescan rule is unchanged from the first pass:
- A sink-bound body is queued.
- An undeterminable body is queued only when SC2 matches the stripped chunk.
- A data body is never queued.

### Component 5: substitutions in an unquoted-delimiter heredoc body

This applies to a body that is not queued by Component 4 and whose delimiter
is unquoted.
- Component 1 in `heredoc-body` mode finds the substitution spans.
- Each outermost span's body is queued as a chunk of its own and processed
  like any chunk. Nested levels are therefore found and checked at every
  depth, within the depth cap.
- An unterminated span queues the rest of the body from its opening.
- A quoted-delimiter body is literal. Nothing is extracted from it.

## Test Notes

- **Where the tests run**: AC-1 to AC-6 and AC-8 run through the cases file
  and the unchanged runner. NFR4 allows no new test file.
- **TDD order**:
  1. Add every listed case.
  2. Run the suite against the unmodified guard and record the failures.
  3. Change the guard until the whole suite passes.
  4. Commit the two files together.
- **Size**: the task has eight acceptance criteria, one above the usual
  split threshold. This is accepted because all eight rest on one shared
  analysis in one file (IMPLEMENTATION.md D3). Splitting them would put
  parallel rewrites of the same routines into separate worktrees.
- **Recommended extra cases**: add these only if they hold under the rules
  above. They never replace a listed case.
  - `cat <<'EOF' |` followed by several blank lines, then `bash` after the
    delimiter line: deny.
  - `{ cat <<'EOF'` / RESET / `EOF` / `} | grep x`: allow.
  - Backtick spellings of TS-42 and TS-44: deny.
  - `cat <<EOF` / `\$(git reset --hard HEAD)` / `EOF`: allow. The escaped
    `$` opens no substitution.
- **Stress measurement (AC-7)**: generate the inputs outside the
  repository, and do not commit the generator (NFR4).
  - Family A: N repetitions of `x="$(cat <<'EOF'` / `hello` / `EOF` / `)"`.
  - Family B: N repetitions of `case x in x) cat <<'EOF'` / `hello` / `EOF`
    / `;; esac`.
  - Use N = 800 and N = 1,600 for each family.
  - Feed each input to the guard as a hook payload and time it.
- **Inspection**: the change-set, import and version clauses of AC-8 are
  checked by inspecting the diff against the task's base.
