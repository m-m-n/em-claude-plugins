# Task Plan: task0003 — Keep git data only for built-in subcommands, and match quote-split sink names in the fallback

## Goal

A `git` invocation counts as a data command only when the subcommand it runs
is a built-in on a closed list. Built-ins cannot be shadowed by an alias
defined in any configuration source, so the case where git runs an alias as a
program becomes undeterminable instead of data. The undeterminable fallback
also catches a sink name that is split by quoting characters. Every fallback
rescan it performs today is kept.

### Change 1: the git condition in statement classification (SC1)

A statement whose command word is `git` is classified as follows.

1. Skip git's global options, left to right.
   - Options that take a value, either as the next word or after `=`:
     `-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace`, `--config-env`.
   - Options without a value: `-p`, `-P`, `--paginate`, `--no-pager`,
     `--bare`, `--no-replace-objects`, `--literal-pathspecs`,
     `--glob-pathspecs`, `--noglob-pathspecs`, `--icase-pathspecs`,
     `--no-optional-locks`.
2. The statement is **undeterminable** when any of these holds:
   - Another word starting with `-` appears before the subcommand. This
     includes `--exec-path`.
   - No subcommand word remains.
   - The subcommand word is statically unknown.
3. The statement is **data** when the subcommand is on this closed list of
   built-ins:
   - `add` `am` `apply` `blame` `branch` `cat-file` `check-attr`
     `check-ignore` `check-mailmap` `commit` `commit-tree` `diff`
     `diff-tree` `fast-import` `hash-object` `interpret-trailers` `log`
     `ls-files` `ls-tree` `mailinfo` `mailsplit` `mktag` `mktree` `notes`
     `rev-list` `rev-parse` `show` `status` `tag` `update-index` `update-ref`
   - `credential` and `hook` are deliberately absent, because each hands its
     standard input to a configured program. `bisect`, `filter-branch`,
     `submodule`, `difftool`, `mergetool` and `rebase` are absent too,
     because each runs programs named in its options or in configuration.
4. Any other subcommand is **undeterminable**. That covers aliases from any
   configuration source, external `git-*` programs and unlisted built-ins.

Constraints on the change:
- The condition reads only the statement's own words, as SC1 requires.
- Assignments in front of the statement need no special handling. Any
  alias they define can only be reached through a subcommand that is not
  a built-in, and step 4 covers that.
- This condition replaces the existing same-statement handling of
  `GIT_CONFIG_*`, `-c` and `--config-env` for git. A statement whose
  subcommand is a listed built-in is data whatever configuration it sets,
  because no alias can shadow a built-in. A statement whose subcommand is
  not listed is undeterminable whatever configuration it sets.
- The data-command list itself is unchanged. `git` stays on it, and this
  condition is applied on top of it.

### Change 2: the fallback sink match (SC2)

- The fallback matches when the current chunk-wide sink test matches the
  stripped chunk as written. That is today's behaviour, and it is kept
  exactly.
- The fallback also matches when the same test matches the stripped chunk
  with every `'`, `"` and `\` character removed.
- The fallback is still applied only to undeterminable heredocs, one heredoc
  at a time. A data heredoc is never queued because of it (TS-25).

This keeps every rescan FR5 performs today and adds rescans only in the
detecting direction, as FR5 requires ("検知漏れの方向には倒さない").

### Behaviour that must not change

- The sink-word vocabulary.
- Every data command other than `git`.
- How host, pipeline, group and enclosing statements are found.
- The evaluation order of sink-bound, undeterminable and data.
- `head()`, `WRAPPERS` and `WRAPPER_VALUE_FLAGS`.
- `check_pipe_to_shell()` and every check function called from `main()`.
- `hooks.json` and the runner script.

### Expectation cases (added first, FR6)

Add each case in the existing `[expected verdict, label, command]` shape,
with Japanese labels in the existing style. In the list below, ` / `
separates the lines of one command, and each ` / ` is a newline in the JSON
string. The body line `git reset --hard HEAD` is written as RESET. IDs refer
to VERIFICATION.md.

- TS-47 (deny): `export GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=alias.x GIT_CONFIG_VALUE_0='!bash'; git x <<'EOF'` / RESET / `EOF`
- TS-48 (deny): `VAL='!b"a"s"h"' git --config-env=alias.x=VAL x <<'EOF'` / RESET / `EOF`
- TS-49 (deny): `bash scripts/check.sh; git x <<'EOF'` / RESET / `EOF`
- TS-50 (deny): `timeout 10 b"a"s"h" <<'EOF'` / RESET / `EOF`
- TS-51 (allow), two cases:
  - `bash scripts/check.sh && git -c user.name=x commit -F - <<'EOF'` / RESET / `EOF`
  - `bash scripts/check.sh && git -C /tmp/r commit -m "$(cat <<'EOF'` / RESET / `EOF` / `)"`

## Test Notes

- **Where the tests run**: every criterion runs through the cases file and
  the unchanged runner. NFR4 allows no new test file.
- **TDD order**:
  1. Add every listed case.
  2. Run the suite against the unmodified guard and record the failures.
  3. Change the guard until the whole suite passes.
  4. Commit the two files together.
- **Existing allow cases**: if a pre-existing allow case has a git host
  whose subcommand is a built-in missing from the list, the list may be
  extended by that built-in. The built-in must not hand standard input to a
  configured program, and must not run a program named in its options.
  Record every extension in the task's test record. Never change an
  existing case to make the suite pass.
- **Recommended extra cases**: add these only if they hold under the rules
  above. They never replace a listed case.
  - `bash x.sh; git --exec-path=/tmp commit -F - <<'EOF'` / RESET / `EOF`:
    deny.
  - `bash x.sh; git "$sub" <<'EOF'` / RESET / `EOF`: deny.
- **Inspection**: the change-set, import and version clauses of AC-5 are
  checked by inspecting the diff against the task's base.

## Out of Scope

- A listed built-in that runs a program named in an option or in
  configuration, for example an editor set through `-c core.editor` for
  `commit -e`. This stays the recorded risk in IMPLEMENTATION.md.
- Sink names that only appear after expansion, such as `$'\x62ash'` or a
  variable. The fallback removes quoting characters only and evaluates
  nothing (NFR1).
- How host, pipeline, group, case and enclosing statements are found, and
  the evaluation order of the destination outcomes.
- Any version change, `hooks.json` or the runner script.
