# Task Plan: task0002 — State the /proc and /dev/fd rule in the hook docstring and the protocol

## Goal

The `path:` item of the `cd prefix:` paragraph in the module docstring of `bash_guard.py` and the path item of the Verbatim execution rule in `command-execution-protocol.md` both state the FR1 rule, every existing wording matcher keeps passing, and a new wording test pins the added statement in both places.

## Requirements

FR5, NFR6

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/hooks/bash_guard.py` — the path item of the cd prefix paragraph in the module docstring only
- `em-workflow/references/command-execution-protocol.md` — the path item of the Verbatim execution rule
- `tests/test_bash_guard_cd_prefix.py` — wording tests for the added statement, placed inside or directly after the existing path-condition wording test class

## Design

The rule to state is IMPLEMENTATION.md D1; the meaning of "under /proc or /dev/fd" is the predicate pinned in IMPLEMENTATION.md Shared Components; D2 forbids describing the /proc/self/root/.. prefix as allowed.

### What both texts add

One added statement in each place, in the existing English register, saying that:

- a path under /proc or /dev/fd fails the path check;
- "under" means the first component is `proc`, or the first two are `dev` and `fd`, ignoring empty and `.` components (the texts may phrase this compactly);
- this is judged on the path as written, on each stage reached while resolving the logical path and the physical path component by component, and on the target of each link followed, not on the final realpath alone.

### Constraints the edit must respect (FR5)

- The strings `logical path`, `physical path`, `strictly below`, `existing directory`, `otherwise` and `both` stay; so do the parenthetical definitions of the logical path (containing `..`) and of the physical path (containing `as written`).
- The protocol keeps `realpath` and `.claude/worktrees/em-workflow/`, and the sentence that reaches `.claude/worktrees/em-workflow/` after "strictly below" keeps having no period between the two. Put the new statement after the existing physical-path sentence, not inside it.
- Neither text contains `realpath of <path> is an existing directory` or `path's realpath is an existing directory`.
- The docstring's `cd prefix:` paragraph stays a single paragraph: the added lines contain no blank line, keep the item's indentation, and leave every statement matched by `STATEMENT_PATTERNS` untouched. The sentences "A resolution error counts as not below" and "<path> is only resolved, never used as the directory or argument of a child process" stay in the item.

### Wording test

A matcher in the style of the existing `_states_new_path_condition`: it flattens whitespace and checks for the needles that carry the added statement (at least `/proc`, `/dev/fd`, a reference to the path as written, a reference to the stages of both resolutions, and a reference to link targets; the implementer picks the exact needles to match the chosen wording). Tests apply it to the module docstring and to the Verbatim execution rule section, read through the existing `_load_guard_module` and `_verbatim_execution_rule` helpers, and check that it fires on forged text with one needle removed.
