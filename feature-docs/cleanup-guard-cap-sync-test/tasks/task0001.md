# Task Plan: task0001 — Cap-consistency test between develop SKILL.md and the cleanup guard constants

## Goal

`tests/test_failed_run_cleanup_guard.py` gains a test that fails whenever the
batch automatic-rework cap values written in develop SKILL.md disagree with
the hook's `LINEAGE_CAP_COUNT` / `HARD_CAP_ROUNDS`, together with in-memory
mutation and malformed-text cases showing that the check detects every
disagreement and every unreadable layout.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify
- `tests/test_failed_run_cleanup_guard.py` — add one module-level extraction-and-comparison function and the new test classes for TS1-TS8; the existing tests, helpers and imports stay as they are

## Design

### Inputs (read-only)

- **SKILL.md text**: the file at the module's repository root joined with
  em-workflow / skills / develop / SKILL.md, read as UTF-8 text. An absent
  file makes the real-file test fail; it is never a skip.
- **Hook constants**: the attributes `LINEAGE_CAP_COUNT` and
  `HARD_CAP_ROUNDS` of the module object returned by the existing
  `load_hook_module()` helper. The new test code never writes either value as
  a literal (FR2).

### Extraction-and-comparison function (FR5)

One module-level function in the test module (not a test method).

| Aspect | Contract |
|---|---|
| Input | the full SKILL.md text, the lineage cap count, the hard cap rounds |
| Output | a list of mismatch descriptions (human-readable strings); an empty list means consistent |
| Side effects | none: no file access, no output, the text is never modified |
| Postcondition | the list is empty only when each of the four values below was found exactly once and all four rules hold; missing or ambiguous content is reported as entries, never raised |

Processing flow:

1. Locate the paragraph marker — the bold text
   `**batch 自動 rework の系譜 cap**`, asterisks included — in the raw text.
   Zero or several occurrences yield one mismatch naming the item
   "lineage cap paragraph" (missing / ambiguous), and no value is read.
2. Take the bullet list that follows the marker: it starts at the first
   bullet line after the marker and before the next heading, and each item is
   that bullet line plus its indented continuation lines. The list ends at
   the first line that is neither (a blank line, or an unindented non-bullet
   line).
3. Normalize each item: every line break together with the indentation that
   follows it becomes one space (FR4; the hard cap reach phrase spans a line
   break in the real file).
4. Match the four patterns against each normalized item and sum the matches
   over the items. Patterns use the full-width parentheses （ and ）; N is a
   run of ASCII digits.

   | Item name | Pattern |
   |---|---|
   | lineage cap label | `系譜 cap（値 N）` |
   | lineage cap reach condition | `累積出現回数が N に達した` |
   | hard cap label | `hard cap（値 N）` |
   | hard cap reach condition | `` `batch.verify_rework.rounds`（…）が N に達した `` — the backtick-quoted field name, then a full-width parenthetical whose content contains no closing full-width parenthesis |

   No other number is read: the "2 回目" in the lineage cap bullet matches
   none of the patterns, and the number-less cap mentions elsewhere in
   SKILL.md lie outside the list.
5. Each item name whose match count is not exactly 1 yields one mismatch
   that names the item and says "missing" (0 matches) or "ambiguous" (2 or
   more, with the count).
6. Each FR3 rule whose operands were all found exactly once is checked; a
   violated rule yields one mismatch containing the SKILL.md value(s), the
   compared constant's name and the constant's value.
   - lineage cap reach condition = `LINEAGE_CAP_COUNT`
   - lineage cap label + 1 = `LINEAGE_CAP_COUNT`
   - hard cap reach condition = `HARD_CAP_ROUNDS`
   - hard cap label = `HARD_CAP_ROUNDS`

### Real-file test (TS1)

Reads the SKILL.md text and the two constants as above, calls the function,
and asserts an empty list; the failure message shows the returned list.

### Mutation tests (TS2-TS5, TS8)

- Each case copies the real text in memory and changes exactly one number;
  the real file is never edited (FR6, NFR2).
- The replacement target is a fixed-text phrase carrying the number the hook
  constants imply for it (lineage cap label = `LINEAGE_CAP_COUNT` minus 1;
  the other three values and the "ID が N 回目" phrase = the constant
  itself), not a hard-coded number, so a coordinated change of both sides
  keeps these tests valid. The hard cap reach target is a phrase on one
  physical line ending in "が N に達した", long enough to occur once.
- Each case first asserts that its target occurs exactly once in the raw
  text, then replaces it with the same phrase carrying a different integer,
  chosen so that the value is recognizable in a mismatch message.
- TS2-TS5 are one test method per value (SPEC AC2); each asserts at least
  one mismatch.
- TS8 changes only the number of the lineage cap bullet's "ID が N 回目"
  phrase and asserts an empty list.

### Malformed-text tests (TS6, TS7)

- TS6: three copies — lineage cap bullet removed, hard cap bullet removed,
  one label reworded so its pattern no longer matches. Each yields at least
  one mismatch naming the missing item.
- TS7: a copy with one cap bullet duplicated inside the list yields at least
  one mismatch naming the ambiguous item.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS1; FR1, FR2, FR3, FR5): a test reads the real SKILL.md and takes `LINEAGE_CAP_COUNT` / `HARD_CAP_ROUNDS` from the module returned by `load_hook_module()`, passes them to the extraction-and-comparison function and asserts an empty list; it passes on the current tree (including the hard cap reach phrase that spans a line break). No new test code writes either constant's value as a literal, and an absent SKILL.md fails the test instead of skipping it.
- [ ] AC-2 (TS2-TS5; FR3, FR6): four test methods, one per value (lineage cap label, lineage cap reach condition, hard cap label, hard cap reach condition), each copy the real text in memory, assert their replacement target occurs exactly once, replace only that number with a different integer, and assert at least one mismatch whose text contains the replaced value and the name of the compared constant (`LINEAGE_CAP_COUNT` for the lineage cap values, `HARD_CAP_ROUNDS` for the hard cap values).
- [ ] AC-3 (TS6; FR4): for each of the three copies — lineage cap bullet removed, hard cap bullet removed, a label reworded so its pattern no longer matches — the function returns at least one mismatch naming the missing item; none returns an empty list and none is skipped.
- [ ] AC-4 (TS7; FR4): for a copy in which a cap bullet is duplicated inside the list, the function returns at least one mismatch naming the ambiguous item.
- [ ] AC-5 (TS8; FR4): for a copy in which only the number of the lineage cap bullet's "ID が N 回目" phrase is changed (exactly-once replacement asserted), the function returns an empty list.
- [ ] AC-6 (TS10, TS13; FR6, NFR2, NFR5): the task's diff from its base changes only `tests/test_failed_run_cleanup_guard.py`; the hook and SKILL.md are byte-identical to the base; running the module creates or modifies no repository file (git status output is the same before and after the run).
- [ ] AC-7 (TS9, TS11, TS12; NFR1, NFR3, NFR4): both `python3 -m unittest tests.test_failed_run_cleanup_guard` and `python3 -m unittest discover -s tests` collect and pass the new tests, and the module's existing tests still pass; every added import is a standard-library module; every new class is named `Test<Behavior>` and every new test method `test_<condition>_<expected_result>` (test/README.md).

## Test Notes

- Every criterion is an in-process unit test: no subprocess and no fixture
  tree are needed. Calling `load_hook_module()` executes only the hook's
  module level, as the existing in-process tests already do.
- Red phase: before the function exists, every new test fails because the
  function is undefined. TS1 is green against the current tree by design
  (SPEC AC1), so that missing-function failure is its red.
- AC-6 and the command half of AC-7 are checked by running the commands, not
  by test code.
- A future re-wrap of SKILL.md that breaks a Japanese phrase across lines
  (for example inside "累積出現回数") inserts a space and makes that value
  "missing". This fail-closed result follows FR4 as written; do not widen
  the normalization to hide it.
