# Task Plan: task0003 — Policy header and terminal-line coverage follow the split

## Goal

`references/batch-policies.yaml`'s header stops asserting that the three arms
keep aborting at unchanged strength and states the batch relaxation plus the
interactive retention instead, and
`references/batch-terminal-line.md` keeps `gate_fail_closed` in its closed
reason-code set while narrowing only its coverage wording.

## Requirements

FR3, FR17, FR21, FR22, NFR1, NFR5, NFR8, NFR9

## Scope

### Files to Create

None — this task modifies existing files only.

### Files to Modify

- `em-workflow/references/batch-policies.yaml` — the header comment; the
  decision table itself is untouched
- `em-workflow/references/batch-terminal-line.md` — the coverage wording for
  one reason code; the code set and the stop-point table are untouched
- `tests/test_batch_policies.py` — the header pins
- `tests/test_batch_stop_contract.py` — the reason-code and stop-point pins,
  plus the coverage-wording pin

## Design

Both files are layer-L2 citers. Neither may state a condition of the relaxation
rule; both refer to `references/question-resolution.md` by path
(IMPLEMENTATION.md C1).

**batch-policies.yaml header.** The paragraph that currently ends by saying
every other fail-closed arm — `category: security`, `category: license` and
`reversible: false` — keeps aborting immediately "at unchanged strength" is
rewritten to state the two-mode split instead: in batch those three arms are
relaxed into the consultation route, in interactive they keep aborting
immediately, per `references/question-resolution.md`. The rest of the
paragraph's job is unchanged: `rework.spec-change` stays documented as
intentionally unlisted and still carries no entry, and the header still
restates no gate internals — no step ordering, no abort precedence, no
classification mechanics. The `gate_policies` mapping gains no key and loses
none (IMPLEMENTATION.md C8).

**batch-terminal-line.md.** The closed eleven-code reason set is unchanged as a
set, and so is the eleven-row stop-point table, including the
`fail-closed-abort` row that maps to `gate_fail_closed` and names
`references/question-resolution.md` as its source. Only the code's coverage
wording narrows: it now describes the aborts that survive in both modes plus
interactive's own aborts. Per the Shared Components contract, that narrowed
wording refers to the surviving aborts by a collective phrase plus the path
citation, and does NOT re-enumerate the set — the enumeration lives in the
resolution SSOT alone (NFR1).

The terminal line's prefix, field grammar and value sets are untouched, so
quiet-output discipline is unaffected (NFR5).
