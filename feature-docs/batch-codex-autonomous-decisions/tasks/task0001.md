## Design

This task owns layer L1 of IMPLEMENTATION.md. Everything below is stated in
that one document; nothing here is duplicated into another file.

**Mode condition.** The relaxation is conditioned on the `--batch` invocation
flag alone (IMPLEMENTATION.md convention C7). The document must say so
explicitly wherever the split is stated, so no reader can reach the
`workflow.yaml` `batch` block as an activation source.

**Fail-closed classification.** Its arms become two groups:

1. *Relaxed in batch* — the question's `category` is `security`; the question's
   `category` is `license`; an `assumptions[]` entry whose
   `related_question_ids` names this question carries `reversible: false`. In
   interactive, each aborts the phase immediately, before any policy-table
   lookup, before the consultation, before `on_unanswered` is read and before
   any option is selected — the current wording, retained verbatim as the
   interactive branch. In batch, each is instead routed into the Codex
   consultation route (the Unlisted-gate fallback's consultation procedure) and
   resolved there.
2. *Surviving in both modes* — the surviving-abort set exactly as
   IMPLEMENTATION.md Shared Components enumerates it. This is the one place the
   set is enumerated.

The paragraph that currently declares the three relaxed arms unavailable to the
policy lookup and to the consultation "at unchanged force and outside this
revision's scope" is the sentence the rewrite supersedes; the negative proof in
the pins is against it.

**Precedence reservation.** Rewritten so that its "abort arm evaluated first,
abort final and non-overridable" rule is scoped to interactive for the three
relaxed arms. In both modes the routed arm still never converts a SURVIVING
abort into a classification. In batch, a question satisfying both the routed
arm's condition and one of the three relaxed arms takes the relaxed route
rather than aborting.

**Classification gate.** Direction 2 (the category / irreversibility check over
the whole bound set) is relaxed on exactly the same terms as the Fail-closed
classification: in batch it routes to consultation instead of aborting, for a
bound-set member category of `security` or `license`, for the sentinel value,
for a missing / unreadable / out-of-vocabulary category, and for the
`reversible: false` arm. Direction 1 (origin membership) and both malformed
`gate_id` / `category` pairings stay fail-closed in both modes, and the
document states that split explicitly and says why: direction 1 is an integrity
check over orchestrator-held data, not a judgement call. Direction 1's existing
"final and non-overridable" sentence is retained verbatim — the phrase-count
assertion in the pin module changes because direction 2's copy of it goes away,
not because direction 1's does.

**Consultation.** Batching and the ceiling are unchanged: a relaxed question
joins the packet's single batched consultation, the turn-3 trajectory judgement
stands, and the five-turn ceiling still counts wrapper launches per packet.

**Opus escalation.** Stated per the Shared Components contract: one dispatch
per packet, carrying every question still unmapped when the consultation ends;
per question it returns either an `option_id` present in that question's own
options or an explicit no-decision, with the reasoning in both cases; the
mapping judgement and the untrusted-output rule extend to its output unchanged;
it is counted outside the five-turn ceiling, at most one per packet. No agent
definition file is created (IMPLEMENTATION.md D2).

**Codex-absent route.** When the availability probe reports `unavailable`, the
same Opus escalation runs in the consultation's place, instead of the current
"skip straight to `on_unanswered`".

**No abort when nothing maps.** When neither the consultation nor the
escalation produces a mapping, the run falls through to `on_unanswered`, and
`block` takes the option with the smallest side effect on the success path.
The block branch's prose is rewritten: it no longer claims that security /
licensing / irreversible-operation questions never reach it. It states the
two-mode split — in interactive they were aborted upstream, in batch they
arrive here through the relaxed route — and keeps the specification-change
carve-out (removed by the routed arm at step 2) as a separate, explicitly
distinct mechanism.

**Batch resolution sequence step 2.** Its "a question it aborts never reaches
step 3" becomes mode-conditional, without restating the Classification gate's
Outcome step (NFR1's non-duplication guard).

**Audit obligation.** The document states that every resolution taken through
the relaxed route appends one batch audit record, and cites
`references/phase-state.md` for the record's shape and its writer entry. It
does not restate the record's fields.

**Wrapper.** One sentence only: the wrapper may answer from a fallback
provider. No provider name, no detection mechanism, no marker token
(IMPLEMENTATION.md C3).

## Test Notes

path to exercise. Write the pins first: for each sentence this rewrite
supersedes, add the negative proof before writing the replacement prose, so the
pin is observed failing against the pre-change document.

Edge cases worth an explicit pin: a question that satisfies both the routed
arm's condition and one of the three relaxed arms (batch → relaxed route,
interactive → abort); the availability-probe `unavailable` branch (escalation,
not `on_unanswered`); and the block branch's two distinct reasons for the
categories it does and does not see.

counts occurrences of the "final and non-overridable" sentence. Determine the
post-change count from the intended prose first, set the assertion to it, and
watch it fail against the current document before editing the prose.
