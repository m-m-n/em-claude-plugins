# Task Plan: task0004 — Fail closed on an unreadable here-document delimiter word

## Goal

A here-document operator whose delimiter word the lexer cannot read no longer
leaves its body lines to be re-read as commands: the judgment of such a
command is never allow, so a later `<<WORD` or unclosed quote inside the body
bash skips can no longer hide a destructive line bash executes (findings
267e8e9657658f40, 643305535d3c874d, 1f64cb294e6ffe41, d9c0ee86072979fe). The
reproduction inputs of the round 1 here-document fixes are pinned in the case

## Design

Notation (IMPLEMENTATION.md): `{BS-NL}` is a backslash immediately followed by
a newline; `{NL}` is a newline.

### Current gap
When the lexer meets a real here-document operator whose delimiter word it
cannot read (`$(`, `${`, `$'`, `$[`, a quote or a backquote never closed, an
extglob group, and the other forms `_heredoc_operator()` reports with no
delimiter), it registers no operator and takes no body; it only ignores later
operators on the same line. bash does take a body for that operator and skips
its lines up to the delimiter line. The hook instead lexes those body lines as
commands, so a `<<WORD` or an unclosed quote on one of them can open a region
that swallows a line bash executes after the real body ends, and the hook
returns allow. Confirmed forms include delimiter words `$(x)`, a backquoted
span, `$[1]`, `${x}`, `$'x'`, `'a'$'b'`, an unclosed quote, and a word
containing `{BS-NL}`; the backquote and `$[` forms were deny before the
review round 1 auto-fix loop 3 and are allow now.

### Target behavior
1. **Fail closed.** At a position where the lexer would register a
   here-document operator, a delimiter word it cannot read makes the
   judgment of the whole command ask — never allow — whatever the following
   lines contain. The ask has its own rule identifier and message (the
   here-document delimiter cannot be read, so the body lines bash skips
   cannot be placed). Under unattended execution the existing downgrade in
   `decide()` turns it into deny; `decide()` itself is not changed.
2. **Route.** The outcome reaches the decision the way the lexer's other
   unsettled outcomes do (the unmatched-subscript and work-bound asks reached
   through `ask_lex_unsettled()`), so every stage that lexes the chunk —
   including a cached reading — produces the same outcome (IMPLEMENTATION.md
   Shared Components, "Lexer facts and the extglob parse-unit record").
3. **Same-line suppression.** The rule that ignored later operators on the
   same line exists only to cope with the missing body; with fail-closed it
   no longer decides any verdict and may be removed.
4. **Readable delimiters.** A delimiter word the lexer can read keeps its
   current handling. When a form listed under Current gap turns out to be
   readable to the lexer yet misread (its body placed differently from
   bash), the fix for that form is to read it as bash does, so the
   destructive line is denied; either way the AC-1 outcome holds.
5. **Work bound.** The check is made where the operator is already read,
   inside the existing scan, with no second pass over the input (NFR2).

### Assumption
All four findings accept a fail-closed verdict (two suggest it directly, one
offers it as an alternative to reproducing bash's body exclusion, one asks
for a conservative verdict). This plan takes fail-closed for unreadable
words. Reversible.
