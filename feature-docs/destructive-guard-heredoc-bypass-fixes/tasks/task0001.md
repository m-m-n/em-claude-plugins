# Task Plan: task0001 — Judge assignment words and builtin names on the logical word

## Goal

`word_transition()` judges assignment words and builtin names on the logical
word, so that a backslash-newline inside a word no longer hides an array
assignment or a declaration / re-parsing builtin from the hook (finding
b0734a006de6f4d7).

## Requirements

FR1, FR5, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create
None.

### Files to Modify
- `em-workflow/hooks/destructive-guard.py` — word_transition(): accumulate
  the logical word during the existing scan and use it for the assignment-word
  judgment (NAME= / NAME+= / NAME[) and as the input of the
  command-name classification; keep ARR_END and SUB_AT as original-input
  offsets.
- `em-workflow/hooks/tests/destructive-guard-cases.json` — append the

## Design

Notation (IMPLEMENTATION.md): `{BS-NL}` is a backslash immediately followed by
a newline; `{NL}` is a newline.

### Current gap
The assignment-word judgment and the builtin-name judgment examine only the
first plain fragment of a word, and a `{BS-NL}` ends that fragment. So
`x{BS-NL}=(` is not seen as an array assignment and `decl{BS-NL}are` is not
seen as `declare`. bash removes the `{BS-NL}` before it splits words and reads
both as the unsplit forms. The hook then reads the destructive line after the
here-document operator differently from bash and allows it.

### Logical word (contract: IMPLEMENTATION.md Shared Components)
- The judgment input is the word's leading plain text — the same text the
  current judgment examines — except that a `{BS-NL}` which bash removes as a
  line continuation is skipped instead of ending that text. Consecutive
  `{BS-NL}` pairs are each skipped.
- Every other boundary that ends the plain text today (a quote, an expansion,
  an operator, an unquoted blank, and so on) still ends it. This task changes
  nothing else about which words qualify.
- The logical text is accumulated character by character during the existing
  scan of the word; nothing is re-read (NFR2, TM-5).
- For each logical character the judgment needs to locate (the `=`, the `+`
  of `+=`, the `[`, the `(`), its original-input offset is kept with it, so
  ARR_END and SUB_AT are recorded as original-input offsets.

### Judgments that switch to the logical word
1. Assignment word: `NAME=`, `NAME+=`, `NAME[` (subscript start), and the
   array start that follows `=` / `+=`.
2. Command-name classification: membership in the declaration group (declare,
   typeset, local, export, readonly) and in the re-parsing group (eval, let,
   alias). This task changes only the input of the classification. It does
   not change group membership, and it does not change what the hook does
   with an argument `NAME[` of either group.

### Flow
1. While scanning a word, append each plain character and its original offset
   to the logical text. On a `{BS-NL}` that bash removes, advance past it
   without appending and without ending the plain text.
2. Where the current code judges the word, run that judgment on the logical
   text.
3. When the judgment yields an array start or a subscript start, record
   ARR_END / SUB_AT from the kept original offsets.
4. For a word containing no in-word `{BS-NL}`, steps 1–3 give exactly the
   current judgment and offsets.
