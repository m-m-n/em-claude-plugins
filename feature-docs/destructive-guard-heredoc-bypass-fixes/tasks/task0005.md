# Task Plan: task0005 — One owner for extglob parse-unit recording, independent of call path and lexer cache

## Goal

The extglob parse-unit count that guards against switching extglob in the
middle of a command has a single owner again: the lexer hands its facts to
consumers only through the map it returns, units are recorded at one point,
and the count and verdict no longer depend on which stage lexed a chunk first
or on whether a map came from the lexer cache (finding 730712dde1bd3462).

## Design

### Current gap
The line starts of extended-glob parentheses travel from the lexer pass to
`lex_shell()` through a module-level set that the pass overwrites, and are
copied onto the map only when the lexing met such a parenthesis. The flag
saying a parenthesis was met is raised only on a fresh lexing, never on a
cache hit. Units are recorded only where `statements()` lexes a chunk, while
other stages call the same lexer. The count therefore depends on which stage
lexed a chunk first and on the cache's state, and no single place states what
a unit is and who records it.

### Target behavior
The contract is IMPLEMENTATION.md Shared Components, "Lexer facts and the
extglob parse-unit record". For this task:

1. **Facts on the map.** The extended-glob line starts and whether such a
   parenthesis was met are part of the map `lex_shell()` returns, set on
   every map (empty / false when none was met). No module-level state carries
   them from the pass to `lex_shell()`. A cached map and a freshly lexed one
   for the same key are indistinguishable.
2. **Met flag from maps.** "The lexing met an extended-glob parenthesis",
   which decides whether the command is judged under extglob on as well, is
   raised for every map a judgment reads that carries the fact, cache hits
   included.
3. **One recording point.** Units are recorded at exactly one point: where a
   chunk is lexed with its origin known. Unit identity stays the pair
   (origin, line start in the chunk's text) as established for FR4; texts
   derived from a recorded chunk (stripped, marked, a fragment) are not new
   units. The unit record is reset only at the start of a judgment.
4. **Readers.** Every reader of the line starts, the met flag or the unit
   record reads them through the map or the one recording point; the
   docstrings of the recording and counting functions name the readers.
5. **Work bound.** No second pass over the input and no uncounted loop
   (NFR2).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: for any text, the extended-glob line starts and the met fact on
  the map `lex_shell()` returns are identical whether the map is produced
  fresh or returned from the cache, and whether or not other texts were
  lexed in between; a text with no extended-glob parenthesis gets empty line
  starts and a false met fact. Tested in the new test module over TS5's
  input, its differing-prefix variant and T2 AC-4.7.
- [ ] AC-2 (TM-7): judging the same payload a second time in one process,
  and judging it after every chunk of it was lexed beforehand, each give the
  same verdict, the same met determination and the same unit count as a
  first judgment with an empty cache — over TS5's input, its differing-prefix
  variant, T2 AC-4.7, and every case-table entry containing `@(`, `!(`, `+(`,
  `*(` or `?(`.

  yields its expected verdict, the same as with the cache enabled.
- [ ] AC-4 (FR4, NFR1): TS5's input yields ask, its differing-prefix variant
  yields ask, T2 AC-4.7 yields allow, the unattended downgrade cases at the
  end of `em-workflow/hooks/tests/run-destructive-guard.py` pass, and every
  case-table entry passes with its expected verdict; the case table is not
  modified by this task.
