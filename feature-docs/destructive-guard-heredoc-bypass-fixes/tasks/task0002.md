# Task Plan: task0002 — Stop deferring here-document bodies at NAME[ in declaration-builtin arguments; separate eval / let / alias

## Goal

In the arguments of declare / typeset / local / export / readonly, `NAME[` no
longer defers the start of a pending here-document body (finding
a7c0d90ac3e44e5b), and eval / let / alias are handled as a separate group so
that T2 E-1 stays deny while the eval / let / alias forms that bash 5.3.9
executes are denied.

## Design

Notation (IMPLEMENTATION.md): `{BS-NL}` is a backslash immediately followed by
a newline; `{NL}` is a newline.

### Current gap
A here-document operator earlier on a line stays pending until that line ends,
and its body starts on the next line. When a declaration builtin's argument
begins `NAME[`, the hook reads an open subscript and defers the start of the
pending body past the end of the line. bash does not defer it in the measured
forms, so the hook's idea of which lines are here-document body no longer
matches bash's, and a line bash executes falls outside what the hook inspects
as a command. The hook before the round 2 change (the baseline) denied these
inputs; the current hook allows them. An earlier fix that stopped the deferral
for every builtin at once broke T2 E-1, because eval re-parses its arguments
and needs its own handling.

### Target behavior
1. **Group split.** The command-name classification (IMPLEMENTATION.md Shared
   Components) distinguishes the declaration group (declare, typeset, local,
   export, readonly) from the re-parsing group (eval, let, alias). The
   argument branch takes the group from that classification, never from a
   separate reading of the raw command word, so that a command name the
   classification recognizes through a line continuation gets the same
   handling as the unsplit name.
2. **Declaration group.** When an argument begins `NAME[` (as judged by the
   assignment-word judgment, SUB_AT in original-input offsets) while a
   here-document operator is pending, the start of that pending body is not
   deferred: at the end of the line the body starts exactly where it would if
   the argument had no `[`. Inputs denied by the baseline return to deny.
   T2 E-9 (`declare -a x[0]=( <<EOF` followed by `git reset --hard`), where the
   here-document operator comes after a subscript closed on the same line,
   keeps deny.
3. **Re-parsing group.** The reading that makes T2 E-1
   (`eval x[a b]=( <<EOF` followed by `git reset --hard`) deny is kept. Each
   form obtained by changing the command name of a target-behavior-2 input to
   eval, let or alias is measured on bash 5.3.9: a form in which bash executes
   the destructive line is made deny; a form in which it does not is left as
   the hook reads it today and is not added as deny.
4. **`SUBSCRIPT_ARRAY_FORMS`.** For every form in that list, no here-document
   operator is registered — unchanged.
5. **Unchanged neighbors.** Quoted arguments of eval / let / alias do not open
   an array (T2 E-15, allow). A declare reached through `builtin` or `command`
   stays outside this handling (T2 E-16 / E-17, allow).

### Flow
1. The command word is classified into a group (shared classification).
2. On an argument that begins `NAME[`:
   - declaration group: read the subscript without deferring any pending
     here-document body;
   - re-parsing group: keep the current subscript reading, changed only as far
     as target behavior 3 requires;
   - neither group: unchanged.
3. `close_subscript()` is changed only as far as needed to keep step 2: any
   pending-body deferral it releases is never set up for a declaration-group
   argument.
