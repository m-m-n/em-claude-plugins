# Task Plan: task0003 — Identify extglob parse units by origin and position

## Goal

`_count_extglob_units()` tells parse units apart by where they come from (the
top level or a specific eval / -c expansion) and where they sit, instead of by
the text before the parenthesis, so that an outer and an inner eval sharing
the prefix `x=(@` with an extglob switch between them yield ask (finding
f34ee27bc8c323b1).

## Requirements

FR4, FR5, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create
None.

### Files to Modify
- `em-workflow/hooks/destructive-guard.py` — _count_extglob_units() and the
  points where the eval / -c expansions hand parse units to it: carry each
  unit's origin and position, and count distinct units by that identity.
- `em-workflow/hooks/tests/destructive-guard-cases.json` — append the
  f34ee27bc8c323b1 reproduction input and its differing-prefix variant.

## Design

Notation (IMPLEMENTATION.md): `{NL}` is a newline.

### Current gap
The defense against switching extglob in the middle of a command decides ask
from the number of distinct parse units. Units are deduplicated by the text
before the parenthesis alone, so an outer eval and an inner eval that both
begin `x=(@` collapse into one unit, the count drops to one, and the switch
between them goes undetected: the hook allows the command.

### Expected verdict
The reproduction input is fixed to ask, not deny. Deny under unattended
execution comes from the existing downgrade of ask in `decide()`, already
covered by the downgrade cases at the end of
`em-workflow/hooks/tests/run-destructive-guard.py`; this task changes neither.

### Unit identity
- A parse unit's identity is the pair (origin, position).
  - Origin: the text the unit was parsed from — the top-level command string,
    or one particular eval / -c expansion. Nested expansions are distinct
    origins: an inner eval inside an outer eval is a different origin from the
    outer eval, and an expansion is told apart from its siblings by where its
    argument sits in its parent.
  - Position: the offset at which the unit starts in its origin's text.
    Together with the origin this locates the unit in the original input.
- Two units are the same unit only when both origin and position coincide. The
  text before the parenthesis plays no part in identity.
- Re-reading the same original text in another lexer stage is not a new
  origin: the same parenthesis examined again at the same origin and position
  stays one unit, so single-unit inputs such as T2 AC-4.7 do not gain an ask.
  Excess ask that today comes from counting re-parses as separate units
  (8633a419fec4b21c) is not addressed.
- The origin and position are known where the unit is produced (the current
  scan position and the expansion being scanned); identity is taken from there
  without re-reading any input, and the set of identities grows at most
  linearly with the input (NFR2, TM-5).

### Flow
1. When a top-level scan or an eval / -c expansion produces a parse unit with
   an extended-pattern parenthesis, attach the current origin and the unit's
   position.
2. `_count_extglob_units()` counts distinct (origin, position) pairs.
3. The ask decision that consumes the count is unchanged; only the count
   changes.
