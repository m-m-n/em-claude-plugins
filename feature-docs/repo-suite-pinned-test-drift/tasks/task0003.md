# Task Plan: task0003 — em-workflow version リテラル固定の撤去（abort-terminal-commit-precedence / stop-reason-coverage）

## Goal

Replace the 0.2.2 string-equality pins in two test modules with form and lower-bound checks, plus a registry-agreement check for FR6, so that the checks stay green at any later em-workflow version.

## Requirements

FR6, FR7, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_abort_terminal_commit_precedence.py` — TestVersionBump checks form, a 0.2.2 floor and manifest/entry agreement; EXPECTED_VERSION, method names and docstrings renamed; negative proofs
- `tests/test_stop_reason_coverage_version_bump.py` — the two literal-target tests check form and a 0.2.1 floor; method names, docstrings and module docstring renamed; negative proofs

## Design

This task implements the Version form rule, Lower-bound comparison and Registry agreement contracts from IMPLEMENTATION.md Shared Components, locally in each module (D2). task0001 bumps em-workflow to 0.2.4 in parallel, and the manifest artifact contract guarantees that only the version value changes. Every live check here must pass at 0.2.3, which is the value in this worktree, and at 0.2.4.

**FR6 (`tests/test_abort_terminal_commit_precedence.py`)**

- The two TestVersionBump tests stop comparing strings with 0.2.2. Together they verify three things:
  - the em-workflow version in `em-workflow/.claude-plugin/plugin.json` and the one in the em-workflow entry of `.claude-plugin/marketplace.json` both pass the form rule
  - each is at least 0.2.2 by the lower-bound comparison
  - the two are identical
- EXPECTED_VERSION becomes a floor constant with a name that says it is a minimum. It still holds 0.2.2.
- The method names and docstrings say "at least 0.2.2, well-formed, and in agreement" instead of "is 0.2.2".

**FR7 (`tests/test_stop_reason_coverage_version_bump.py`)**

- test_version_is_the_literal_bump_target reads `plugin.json`. test_entry_version_is_the_literal_bump_target reads the marketplace em-workflow entry. Each changes from string equality with 0.2.2 to: the value passes the form rule and is at least 0.2.1.
- Both methods get names that no longer say "literal bump target". Their docstrings and the relevant part of the module docstring now describe the floor check.
- FR7 has no agreement column in D2. Each registry is checked on its own.

**Negative proofs (NFR3, hermetic, D2 applicable columns)**

The matchers take version values as input. The negative-proof tests give them forged values:

- FR6 matcher:
  - 99.0.0 in both registries is accepted
  - 0.2.10 in both is accepted, which proves the comparison is numeric and not lexicographic
  - 0.2.1 in both, which is below the floor, is rejected
  - a malformed value in one registry is rejected; examples: "0.2", "0.2.x", "v0.2.4", "0.2.4-rc1", an empty string, a non-string
  - disagreeing registries, such as 0.2.4 against 0.2.5, are rejected
- FR7 matcher:
  - 99.0.0 is accepted
  - 0.2.0 is rejected
  - a malformed value from the same kinds as above is rejected
