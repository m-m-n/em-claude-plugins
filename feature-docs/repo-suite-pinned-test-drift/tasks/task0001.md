# Task Plan: task0001 — develop SKILL.md の AskUserQuestion 言い換えと em-workflow version bump

## Goal

Bring the AskUserQuestion count in the develop skill back within its pinned budget by rewording one phrase, and bump em-workflow from 0.2.3 to 0.2.4 in the same commit.

## Requirements

FR4, FR11, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/skills/develop/SKILL.md` — reword the phrase "AskUserQuestion を出さない" on the --pr item of 引数処理 (line 106)
- `em-workflow/.claude-plugin/plugin.json` — version 0.2.3 to 0.2.4
- `.claude-plugin/marketplace.json` — em-workflow entry version 0.2.3 to 0.2.4

## Design

This task writes two shared artifacts. The postconditions for both are pinned in IMPLEMENTATION.md Shared Components ("develop SKILL.md (artifact)" and "em-workflow / marketplace manifests (artifact)"). Parallel tasks rely on them.

**SKILL.md rewording (FR4)**

- The question budget is met by rewording, not by raising the baseline. `BASELINE_COUNTS` in `tests/test_muse_consent_no_new_questions.py` stays as it is, and that file is not modified.
- Target: the `--pr` item in the 引数処理 section (line 106). Replace "AskUserQuestion を出さない" with a wording that does not contain the tool name and says the same thing: no user question is raised. The SPEC's example wording is 「質問を出さない」.
- The meaning of the `--pr` item does not change. Only that phrase changes. The rest of line 106 and every other line of the file stay byte-identical. This includes line 4 (argument-hint), Step C's AskUserQuestion at line 910, and the Non-packet gates reference at lines 918-919.
- Postcondition: the file contains at most 7 occurrences of `AskUserQuestion`, which is the budget pinned for it by `BASELINE_COUNTS`.

**Version bump (FR11, NFR4, D3)**

- In `em-workflow/.claude-plugin/plugin.json`, the `version` value goes from 0.2.3 to 0.2.4.
- In `.claude-plugin/marketplace.json`, the em-workflow entry's `version` goes from 0.2.3 to 0.2.4. The em-review entry stays 0.5.13.
- Only these two version string values change. Keys, key order, whitespace, description and every other field stay byte-identical, so the non-version digests pinned by the suite stay valid.
- The SKILL.md change and both version edits go into a single commit.

**Regression check flow**

1. Before editing, run the full repository suite. Record the set of failing test ids as the baseline. It is expected to contain the 16 failures listed in SPEC AC2.
2. Apply the edits.
3. Run the full suite again. The failing set must equal the baseline minus the budget test (test_muse_consent_no_new_questions's test_no_develop_or_review_document_exceeds_its_pinned_budget). The other baseline failures belong to parallel tasks and stay failing in this worktree.
4. A test that fails after the change but not before may pin the literal 0.2.3 or the replaced phrase. Do not edit it here. Report it as a plan deviation with its test id and the pinned value (IMPLEMENTATION.md Conventions, "Scope discipline").
