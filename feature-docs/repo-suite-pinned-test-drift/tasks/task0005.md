# Task Plan: task0005 — review-rules.yaml ピン留めテストの追随

## Goal

Make the four `review-rules.yaml` checks in the primary-chains test module expect the current definitions, without changing `review-rules.yaml`. Each changed check gets a negative proof on forged text.

## Requirements

FR10, NFR1, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_reviewers_primary_chains.py` — the four review-rules.yaml checks expect the current definitions; module and class docstrings updated; negative proofs

## Design

The source of truth is `em-workflow/references/review-rules.yaml`. This task only reads it (D1), and its current definitions are the expected values.

**Expected values**

| Test | Expected after this change |
|---|---|
| test_baseline_unchanged | baseline is exactly [comprehensive, security] |
| test_rules_block_unchanged | exactly four rules, in file order: (1) if_domains [data-persistence] requires [performance]; (2) if_domains [concurrency, external-io] requires [performance]; (3) if_domains [api-contract] requires [architecture]; (4) if_complexity high requires [architecture, comprehensive] |
| test_cross_validation_data_block_unchanged | cross_validation.when_any holds exactly one condition: complexity high |
| test_computation_semantics_preserved_in_prose | the header prose contains "Layer 1 settles the value and Layer 2 cannot change it"; "re-evaluates it after Layer 2" is no longer required |

**Wrapped prose (D4)**

In the file's header comment, the phrase "Layer 1 settles the value and Layer 2 cannot change it" breaks after "cannot". The next line starts with a comment marker followed by "change it." The prose check normalizes both sides the same way before the substring test: it removes line-leading comment markers and collapses whitespace. If the module already has a normalization for this check, that one is used instead.

**Docstrings**

The module docstring and class docstrings drop every statement of a retired definition, such as a baseline without security, the former rules, the former when_any, or re-evaluation after Layer 2. They describe the current definitions.

**Matcher / loader separation and negative proofs (NFR3)**

Following IMPLEMENTATION.md Conventions, each of the four checks becomes a matcher over given text or over a given parsed block. The live tests call it with the content of `em-workflow/references/review-rules.yaml`. The negative-proof tests call it with forged in-memory text:

- A baseline that holds the value the test expected before this change, or that lacks security, is rejected.
- A rules block that holds the rule set the test expected before this change, has a rule missing, or has an extra rule, is rejected.
- A when_any that holds the conditions the test expected before this change, or any condition besides complexity high, is rejected.
- Prose that contains only the retired phrase is rejected.
- Prose where the current phrase wraps at a different word, with a comment marker on the new line, is accepted.
- Prose where one word of the current phrase is altered is rejected.
