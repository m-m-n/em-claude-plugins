# Task Plan: task0001 — wake cleanup script and its behavior tests

## Goal

`em-workflow/scripts/cleanup-task.py` removes one merged task's worktree and
branch without force, from any working directory, and reports each target's
outcome as the result JSON of IMPLEMENTATION.md C2.

## Requirements

FR1, FR2, FR3, FR5, FR6, FR7, FR8, NFR1, NFR3, NFR4

## Scope

### Files to Create
- `em-workflow/scripts/cleanup-task.py` — the cleanup script (IMPLEMENTATION.md C1, C2, C3)
- `tests/test_cleanup_task.py` — behavior and static tests of the script (TS-1 to TS-7)

### Files to Modify

None.

## Design

The CLI, the result JSON and the exit status are IMPLEMENTATION.md C1, C2 and
C3. They are not restated here; this section covers only what happens inside
the script.

### Input validation (FR5, TM-1)

Runs before any git command. Any failure exits 2 with empty standard output.

| Input | Accepted only when |
|-------|--------------------|
| Options | Exactly the three long options of C1, each once; nothing else on the command line |
| `--feature` | The whole value matches `^[a-z0-9][a-z0-9-]*$`; a trailing newline is not accepted |
| `--task` | The whole value matches `^task[0-9]+$`; a trailing newline is not accepted. This rejects `integration`, so the script can never address the integration worktree or branch |
| `--integration-worktree` | Absolute; holds no NUL or other control character; has no empty, `.` or `..` segment (so no trailing separator); its last five segments are `.claude`, `worktrees`, `em-workflow`, the `--feature` value, `integration`; and it names an existing directory |

A value starting with `-` is rejected whether it is passed as a separate word
or attached with `=`.

### Derived values

- Task worktree path: the integration worktree's parent directory joined with
  the task ID.
- Task branch: `em-workflow/{feature}/{T}`; its exact ref is
  `refs/heads/em-workflow/{feature}/{T}`.

### How git is run (NFR1)

- Every git child process uses the integration worktree as its repository
  location, so neither the caller's working directory nor its branch affects
  the outcome.
- git gets an argument list, never a shell command string.
- The environment passed to git drops the variables that would redirect git
  to another repository (the same set `em-workflow/scripts/merge-git.py`
  drops), disables terminal prompts and uses the C locale, so messages are
  stable.
- `git` is looked up by name on `PATH` (the tests put a logging shim there).
- The set of git operations is closed: the worktree registration list, a
  non-forced worktree removal, exact ref resolution, and a non-forced
  `branch -d`. The script never passes a forcing flag, never runs a worktree
  prune, and runs nothing else that writes (TM-2).

### Flow

1. Validate the inputs (above). On failure, exit 2.
2. Read the worktree registration list. If reading it fails, exit 1.
3. Decide whether the task worktree path is registered. Paths are compared
   after resolving symbolic links on both sides; an entry whose directory no
   longer exists still matches by its registered path, so a missing directory
   with a live registration is not `absent`.
   - Not registered: worktree `absent`.
   - Registered: run the non-forced worktree removal. Success: `removed`.
     Failure: `kept`, with git's message as `reason`; the branch becomes
     `skipped` with fixed text as `reason`; go to step 6.
4. Resolve the exact ref of the task branch. Does not resolve: branch
   `absent`, go to step 6. Resolution fails for any other reason: exit 1.
5. Run `branch -d` on the task branch with the integration worktree as the
   repository location. Success: `removed`. Failure: `kept`, with git's
   message as `reason`.
6. Print the C2 object on one line and exit 0.

`reason` texts taken from git are its standard error with surrounding
whitespace trimmed; when git printed nothing, the text names the failed
operation and its exit status. Either way the text is non-empty.

## Acceptance Criteria (MANDATORY)

Every criterion below is checked through child-process runs of the script, and
every exit-0 run's standard output is exactly one line holding one JSON
object that conforms to IMPLEMENTATION.md C2.

- [ ] AC-1 (FR1, FR5, TM-1, TS-6): Each of the following exits 2 with empty
      standard output and zero git invocations in the `PATH` shim's log, and
      leaves the integration branch tip, the worktree registration list and
      the task branch unchanged: a `--feature` of `a/b`, `../x`, the empty
      string, `-x` (as a separate word and attached with `=`), `Feature` or a
      valid name plus a trailing newline; a `--task` of `integration`, `task`,
      `task1/x`, the empty string, `-task1` or `task0001` plus a trailing
      newline; an `--integration-worktree` that is relative, contains a `..`
      segment, ends with a separator, ends in segments other than
      `.claude/worktrees/em-workflow/{feature}/integration` for the given
      feature, or does not exist; a missing option, a repeated option and an
      unknown extra option. A shape-valid existing directory that is not a
      git worktree exits 1 with empty standard output.
- [ ] AC-2 (FR2, FR7, FR8, NFR1, TS-1): With the task branch merged into the
      integration branch but not into `main`, a run whose working directory
      is the main tree (on `main`) and a run whose working directory is
      outside any repository each exit 0 with `worktree.result` and
      `branch.result` both `removed` and both reasons null. Afterwards the
      task worktree is absent from the registration list and from disk, and
      the exact task ref no longer resolves.
- [ ] AC-3 (FR2, FR3, FR8, TS-2): With the task branch not merged into the
      integration branch, the run exits 0 with `worktree.result` `removed`,
      `branch.result` `kept`, `branch.name` equal to
      `em-workflow/{feature}/{T}` and a non-empty `branch.reason`. The task
      ref still resolves to the same commit.
- [ ] AC-4 (FR6, FR8, TM-2, TS-3): With an uncommitted change in the task
      worktree, the run exits 0 with `worktree.result` `kept`, a non-empty
      `worktree.reason`, `branch.result` `skipped` and a non-empty
      `branch.reason`. The worktree stays registered with the change intact,
      the task ref is unchanged, and the shim's log holds no `branch`
      invocation.
- [ ] AC-5 (FR7, TS-4): Each case exits 0. Branch already gone (the task
      worktree registered on a detached HEAD, no task branch): worktree
      `removed`, branch `absent`. Worktree already gone (not registered,
      branch merged): worktree `absent`, branch `removed`. Both gone: both
      `absent`.
- [ ] AC-6 (FR6, FR7, TS-5): With the task worktree's directory deleted but
      its registration left in place, the run exits 0 and `worktree.result`
      is not `absent`. When it is `kept`, `worktree.reason` is non-empty and
      `branch.result` is `skipped`. The shim's log holds no `prune`
      invocation.
- [ ] AC-7 (FR2, TM-2, TS-7): The text of `em-workflow/scripts/cleanup-task.py`
      contains none of `-D`, `--force` and `-f` as a standalone token (not
      preceded or followed by a letter, digit, `_` or `-`), anywhere in the
      file, comments and docstrings included. Across every run of AC-1 to
      AC-6, no git invocation in the shim's log carries `-D`, `--force`, `-f`
      or `prune`, and every branch deletion invocation names the integration
      worktree as its repository location, the subcommand `branch -d`, and
      the task branch as its only target.

## Test Notes

- AC-1 to AC-6 are integration tests on disposable git repositories (NFR3).
  The fixture: a repository on `main`; the integration branch
  `em-workflow/{feature}/integration` checked out as a worktree at
  `.claude/worktrees/em-workflow/{feature}/integration`; a task branch made
  from it, holding one commit, checked out as a worktree at
  `.claude/worktrees/em-workflow/{feature}/{T}`; for the merged case, the
  task branch merged into the integration branch inside the integration
  worktree, with `main` left without it.
- Resolve the temporary directory's real path before building paths, so
  registered paths and expected paths agree on systems whose temporary
  directory is a symbolic link.
- The fixture's own git commands run with an environment that does not put
  the shim on `PATH`; only the script's run does. The shim records each
  argument list and then runs the real git (`tests/test_merge_preflight.py`
  has the same kind of shim).
- AC-6: git versions differ in whether removing a registered worktree with a
  missing directory succeeds. Assert only what AC-6 states.
- AC-7's static part is a text scan of the script file; its dynamic part
  reads the shim logs collected by the other tests' runs (or repeats those
  runs).
- Run the script with the current interpreter and bytecode writing off; never
  import it into the test process (IMPLEMENTATION.md Conventions).

## Out of Scope

- Reading `workflow.yaml`, the journal or any other file.
- Editing `em-workflow/.claude-plugin/plugin.json` or
  `.claude-plugin/marketplace.json` (NFR4).
