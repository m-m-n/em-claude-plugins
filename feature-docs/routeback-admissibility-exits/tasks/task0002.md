## Design

Read IMPLEMENTATION.md first. Its Conventions (wording bans, test-module
discipline), its pinned-literal registry, and the "Rework Round 1 — revised
shared contracts" section govern every edit below and are not restated here.
Where that section revises a postcondition of D1/D3/D4, the revised
postcondition is what this task implements against.

### Site A — I.2.b step 1: give the in-flight check a trigger that can fire

The check's current failure condition is the conjunction "the journal last
event is `launched` while neither the task worktree nor the task branch
exists". In the state the recovery exists for — I.2.a creates the worktree and
the branch BEFORE the launch call, and the launch guard records `launched` at
allow time — both artifacts are present, so the conjunction is false and the
recovery never runs.

Required outcome: the failure condition is satisfiable in a state where the
task worktree and the task branch both exist while the journal's last event
for that task is `launched`. The document names the evidence the check reads
to reach that determination, and states the determination at exactly one site.
The existing conjunctive wording is rewritten, so its matcher moves with it
(Site E).

Unchanged by this site: the check still does not reclassify the task by
itself; I.2.a's last-event rule stays authoritative and is cited, not
restated; the task is still named in the phase report.

### Site B — I.2.b step 1 + Supporting cast: make the recovery executable

The recovery instructs the wake phase to stop "that task's recorded agent",
but the protocol defines no task → agent-identifier lookup: Resume names three
state sources (workflow.yaml, journal, git actual state) and the agent index
is declared diagnostic plumbing existing solely so the stop-tool recorder can
resolve a stop back to a task, one direction only, with more than one
identifier candidate recordable per entry.

Required outcome — exactly one of these two branches, stated in full:

1. **Defined lookup.** The orchestrator-side read of the agent index becomes
   part of the protocol: its owning site states which entry is selected for a
   task, which candidate is passed to the stop tool when an entry carries more
   than one, and that an unresolvable or ambiguous lookup stops nothing. The
   wake/resume state-source enumeration names that source alongside the three
   it already lists, so the recovery no longer depends on a source the
   protocol excludes. I.2.b step 1 cites the owning site instead of restating
   it.
2. **No lookup.** The recovery is restated so it consumes no agent-identifier
   lookup at all, and its primary outcome is produced by a writer the document
   already owns.

Under either branch: the residual is confined to explicitly enumerated
conditions, and "the launch never started" is not one of them — that state is
what the recovery exists for, so it must reach the primary outcome. The
residual keeps naming the task in the report.

Also under either branch: no file under `em-workflow/hooks/` is modified
(NFR1). Branch 1 changes what the protocol says the orchestrator may read; it
does not change what any hook does.

### Site C — I.2.c: an exit for a journal `merged` the ancestor check refutes

The third conjunct blocks route-back whenever the last-event replay alone
reports a task's journal last event as `merged`. For the trust-but-verify
state (journal `merged`, `git merge-base --is-ancestor` fails) that closes the
last non-terminal exit: retry is denied permanently by the launch guard,
route-back is now inadmissible, so the gate-rejected terminal is all that is
left — the same terminal as abort.

Required outcome, both parts:

1. That state reaches an outcome other than the gate-rejected/abort terminal,
   reached without the user selecting abort. Admissible shapes include
   resolving the state upstream so the ancestor check no longer fails before
   the gate is evaluated, and an explicit recovery on the gate-rejected branch
   (which requires rewriting that branch's "no retry loop, no alternative
   recovery route" sentence — permitted, since only
   `tests/test_implement_routeback_gate.py` pins it, with Site E's paired
   proof). Any narrowing of the third conjunct is admissible ONLY together
   with a stated exit for the state it protects: a recycled id inheriting a
   journal `merged` must never become launch-guard-denied with no way out.
2. The gate-rejected branch's cause enumeration names every condition that can
   send a task to that terminal, the third conjunct's condition included, so
   the branch a state lands on is readable from the text.

Constraints: both banned tokens stay absent from the whole I.2.c section;
journal mechanics stay in I.2.b / Supporting cast with I.2.c citing them; every
immutable I.2.c literal in the registry still occurs; the terminal
journal-last-event literal keeps its position before the `create-plan`
write-set instruction; the write set still leaves every task `pending`.

### Site D — I.2.a: correct the premise's citation

The premise sentence added by task0001 cites the gate conjunct as "the third
route-back gate conjunct above" — I.2.c is below I.2.a, the owning section is
not named, and the sentence carries a doubled causal construction
("Because … , so … , no retired task id …").

Required outcome: the premise names the owning section explicitly, states its
position correctly relative to I.2.a, and reads as one premise with a single
causal construction. It must stay true under whatever Site C adopts.

Retained: the inheritance-invariant conclusion, the failed-only carve-out
sentence, the always-in-flight sentence and the unreachability slice's opening
and closing anchors — all pinned by a module outside the declared change set.

## Test Notes

All criteria except AC-8 and AC-10's suite run map to unit-level
document-contract assertions in the two named modules.

- Work test-first: write or update each matcher so it FAILS against the
  document as it currently reads (task0001's delivered text), capture the
  pre-change sample it will be proven against at that same moment, then write
  the prose until it passes. A matcher green before the edit proves nothing —
  and several matchers here assert the negation of text task0001 just added,
  so the pre-change sample must come from this task's branch point.
- Slice before asserting, on the narrowest slice that carries the claim
  (I.2.a / I.2.b step 1 / I.2.c gate / the gate-rejected slice / Supporting
  cast bullets). A phrase surviving elsewhere in the document must not be able
  to satisfy a claim about one branch.
- AC-2 is a two-branch criterion: assert exactly the branch adopted, and
  record in the test record which branch that was and why. Do not write
  assertions for both.
- Edge cases worth an explicit assertion: the allowed-but-never-started state
  (worktree and branch present, journal `launched`) reaches the recovery's
  primary outcome; a journal `merged` refuted by the ancestor check reaches a
  non-terminal outcome; a task with no journal event at all still never blocks
  route-back; the residual enumeration is closed and does not swallow the
  never-started case.
- TDD-awkward: AC-8's "no hook file modified" is a property of the diff, not
  of the document — verify it by inspecting the change set rather than adding
  a committed checker, and record that in the test record file.
- Run the FULL suite from the repository root after each edit site, not only
  the two named modules: the modules outside the declared change set are the
  pins that catch an accidental rewrite of an immutable literal.
