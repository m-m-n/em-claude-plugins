# Task Plan: task0003 — Re-ground I.2.a's inheritance-invariant matchers on the surviving wording

## Goal

Make this feature's own I.2.a matchers agree with the I.2.a text the
integration branch actually carries, so the three failing assertions rest on an
invariant the live document states instead of on a literal a test module
outside the declared change set now asserts is absent — and the suite goes
green without touching the protocol document.

FR2, FR6, NFR2, NFR3, NFR4

## Design

Read IMPLEMENTATION.md first. Its Conventions (test-module discipline), its
pinned-literal registry, and the section "Rework Round 2 — revised shared
contracts (task0003)" govern every edit below and are not restated here. Where
that section supersedes a pinned-literal registry entry, the superseding text
is what this task implements against.

### Root cause

Three assertions in `tests/test_recycled_task_id_consistency.py` require the
sentence fragment naming a retired task id leaving a merged last event behind
for a renumbered task to inherit to be PRESENT in the whitespace-normalized
I.2.a section:

- the positive survival assertion of the I.2.a premise class (VF-1)
- the retained-anchor guard on this feature's task0001 pre-change sample (VF-2)
- the retained-anchor guard on this feature's task0002 pre-change sample (VF-3)

The integration branch's I.2.a no longer contains that fragment. The same
module outside this feature's declared change set that once pinned its
presence — `tests/test_routeback_reset_scope_consistency.py` — now asserts its
ABSENCE from I.2.a and pins a superseding recursion invariant in its place:
that no retired task id is ever re-issued, so a task whose workflow.yaml status
is pending can never carry an inherited merged journal last event, placed after
the unreachability terminal.

Restoring the fragment into the document is therefore INADMISSIBLE: it would
turn three failures into a failure of a module this feature may not edit, and
the feature's own SPEC records that no acceptance criterion requires any
particular new string in the protocol document. The repair belongs entirely on
the matcher side.

### Site A — the survival assertion

The positive assertion is re-grounded on a conclusion the live I.2.a actually
states and that no module outside the declared change set forbids: that a task
whose workflow.yaml status is pending can never carry an inherited merged
journal last event, and that the recycled-task-id carve-out therefore stays
scoped to failed only. The assertion keeps its class and keeps asserting
against the whitespace-normalized I.2.a slice; only the literal it looks for
changes. Conventions 1 applies unchanged: one module-level constant per
asserted literal, read by every assertion that uses it.

### Site B — the two retained-anchor guards

Each guard picks an anchor satisfying all three of:

1. it occurs in that guard's own pre-change sample;
2. it occurs in the live I.2.a section;
3. it is not a literal that any test module outside the declared change set
   asserts is absent from I.2.a.

Condition 3 is what makes this repair durable rather than a second guess at the
same wording; conditions 1 and 2 are Conventions 3's existing non-vacuity rule,
unchanged.

The two pre-change sample constants are verbatim historical captures of the
document at task0001's and task0002's branch points. They are NOT edited: an
edit to a sample invalidates every negative proof taken against it. Only the
anchor each guard selects out of the sample changes.

### Constraints that apply to both sites

- Never edit a test module other than `tests/test_recycled_task_id_consistency.py`;
  the others are the mechanical check that the pins outside the declared change
  set survive.
- Never edit the protocol document. This task changes no prose; if the suite
  cannot be made green without a document edit, that is a reportable plan
  deviation, not a license to edit it.
- No file under the hooks directory changes.
- No version bump: no file under the plugin directory changes in this task, so
  FR7's precondition is not met and both manifests keep their current value.
- No test is removed or skipped, no class of an existing name is re-introduced,
  and the module's test-method count does not decrease.

## Test Notes

- All criteria except AC-5's aggregate run are unit-level assertions inside the
  single named module; AC-6 is a property of the diff, verified by inspecting
  the change set and recorded in the test record file rather than by a
  committed checker.
- Work from the failing state: run the three named tests first and confirm they
  fail for the stated reason (the literal absent from the live I.2.a), then
  re-ground them and confirm they pass. A matcher that was already green proves
  nothing here.
- Before choosing each anchor, read the absence assertions of
  `tests/test_routeback_reset_scope_consistency.py` over the I.2.a slice; an
  anchor that module forbids reproduces this failure in the opposite direction.
- Prefer an anchor the outside module already pins as surviving text over one
  it says nothing about: an anchor nobody else guards can be rewritten by a
  later change without either module noticing.
- Avoid making the re-grounded assertion a verbatim second copy of the exact
  literal the outside module owns where an equivalent claim in this module's
  own slice will do; two modules pinning one byte string is what made the
  previous rewrite break three tests at once.
- Run the FULL suite from the repository root, not only the named module: the
  modules outside the declared change set are the only mechanical check that
  the repair did not simply move the contradiction.
