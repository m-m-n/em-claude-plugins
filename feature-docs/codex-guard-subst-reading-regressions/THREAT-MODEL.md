# Threat Model: codex-guard-subst-reading-regressions

## Verdict
threats-identified

## Rationale
Inspected: SPEC.md and REQUIREMENTS.md (FR1 to FR9, NFR1 to NFR5), and the reading path of codex-hook-interactive-guard in both copies. The hook takes the `tool_input.command` of a Codex PreToolUse(Bash) call from standard input, splits it into simple commands with its reader, walks every nested literal shell `-c` string, and prints one deny object for an interactive interpreter launch or prints nothing. Tier: full. No DESIGN.md (the design step was skipped). All three tasks declare `input-handling`, so the one trust boundary is analysed at deep depth; no task declares `auth`, `external-io` or `data-persistence`.

The feature changes only how a command substitution inside double quotes is read: a context of its own for the zsh `for` word list, continuation pairs in the empty `()` check, coproc and repeat by the kind of the holding shell, and one re-read of an unknown-kind string that stops undecidable. The command string stays the only input; the guard writes no file, opens no connection and starts no process (NFR3, unchanged). Spoofing, Repudiation, Information disclosure and Elevation of privilege do not realistically apply: the guard authenticates no party, keeps no record, its deny reason does not echo the command text (unchanged here), and it grants nothing — it can only deny. The category that applies is Denial of service, in two forms: a reading cost that grows faster than the input, so the hook does not answer the Bash call in time; and a misreading that lets an interactive launch through, so the REPL keeps waiting for input after the pseudo terminal is gone and the unattended run stalls.

Residual risk, accepted as FR6 specifies it and recorded in IMPLEMENTATION.md Risk Assessment for review: when the re-read of an unknown-kind string reads to the end, its commands replace the first read's. A string whose earlier substitution holds `coproc WORD` or `repeat`, reads to the end under both readings but ends at different places, and is followed by a part that only the first reading finds undecidable, can lose a launch that the first read settled before its last checkpoint. Such a string has to be shaped for it; the guard's documented posture is that a misreading costs a missed detection. No mitigation is recorded for it here.

## Trust Boundaries

### TB-1: The Codex Bash command string entering the guard's reader
Crossing: the command text of a Codex PreToolUse(Bash) call, generated by the agent and possibly shaped by untrusted content the agent has read, crosses from the Codex process into the guard process through standard input; every literal shell `-c` string nested in it is read again by the guard.
Boundary files: em-workflow/scripts/codex-hook-interactive-guard.py, em-review/scripts/codex-hook-interactive-guard.py
Depth: deep (input-handling)
