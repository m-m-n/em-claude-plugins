# Task Plan: task0001 — zsh for word list read in a context of its own

## Goal

Inside a double-quoted command substitution, the word list of a zsh `for name (words)` is read in a context of its own instead of the arithmetic context `a`: a `#` comment and a newline are read as in a command list, and no word of the list is at a command position. The defect 1 reproduction (TS1) and its derived forms are denied again on both copies.

## Design

Cross-task rules (both copies, CASES format and anchors, docstring ownership, the shape of the context stack, no version change) are in IMPLEMENTATION.md and are not restated here.

### Where the word-list context opens and closes

1. The `(` that today opens context `a` for the word list (the `(` read while the list is in the head state after the `for` name, blanks allowed before it) opens the new word-list context instead. Its stacked state records, as today, that its close gives the enclosing command list a command position.
2. The `)` that closes this outermost word-list entry restores the enclosing list and puts it at a command position (unchanged: `for x (a) {` keeps working).
3. A `(` read while the word-list context is on top opens a nested word-list entry (a zsh glob qualifier such as `*(N)`). Its close is a closing inside a word: reading goes on in the enclosing word list, and no command position is given to anything.
4. `$((` keeps opening the arithmetic context `a`, and `a` keeps its present reading. The arithmetic `for ((` is untouched.

### Reading inside the word-list context

Each character is decided in this order:

1. A backslash pair, a single-quoted unit, a `$'` unit, a double quote, a backtick, `$(`, `$((` and `${` are followed exactly as in every other context; nothing changes for them.
2. A `#` whose previous character is a space, a tab, a newline, `;`, `&`, `|` or `(` starts a comment: the same start condition as in a command list. The comment runs to the next newline; quotes, a `)` and substitutions inside it open nothing and close nothing. A comment with no newline before the end of the input makes the chunk undecidable, as a comment in a command list does.
3. `(` and `)` behave as in the section above.
4. Every other character, the newline included, is part of a word or separates words. No word in the list is at a command position, so nothing in it opens a case statement, acts as a closing word or starts a head; a newline separates words but gives the next word no command position.

### Constraints

- The context needs no new per-entry value; its state is the stack character itself (NFR1: constant-size state).
- The comment is skipped with one forward scan to its newline, so a long run of commented lines is read in linear time (TS26).
- No method reachable from the substitution skip may become `parse`, the shared quoted-unit reader, the range quote removal or the skip itself (NFR2).

### Documentation (FR8, owned region per IMPLEMENTATION.md)

The Contexts on the stack passage of the `_skip_substitution` docstring describes `a` as the arithmetic context only, and adds the word-list context with the reading above (comment start condition, comment contents, newline, nested parenthesis, the close of the outermost entry). The rule 6 sentence on `for name (words)` stays as written: it remains accurate.
