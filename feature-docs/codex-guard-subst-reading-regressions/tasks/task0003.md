### 1. Shell kind (FR3)

- Three kinds: bash, zsh, unknown.
- The kind of a literal `-c` string is decided from the basename of the shell command word that directly holds it, the word the judgment already resolves after assignments, option-less wrappers (`env` and the others) and a path. The match is the one `_family_of` uses: the name itself, or the name followed only by digits and dots. `bash`, `bash5`, `bash5.2` and `/usr/bin/bash` are bash; `zsh`, `zsh5.9` and `/usr/bin/zsh` are zsh; `sh`, `dash`, `ksh` and their suffixed forms are unknown.
- Contract of `_judge` (internal): given the words of one simple command and its connection, it returns the verdict as today and, when it hands back a literal shell `-c` string, also the kind of the shell that holds that string. Its only caller is `_scan`.
- `_scan` passes that kind when it parses the string. A string's kind comes from its direct holder alone: a `zsh -c` string inside a `bash -c` string is zsh (TS24). The work-list entry needs no new value.
- The hook command itself is parsed with the unknown kind. `find_deny(command)` keeps exactly one parameter (NFR5).

### 2. Rule switches of the parser (FR4, FR5)

- The parser is built with two switches, fixed for its lifetime and parser-wide (never part of a stacked entry, per IMPLEMENTATION.md): the coproc NAME rule and the zsh repeat rule.

| Reading | coproc NAME rule | zsh repeat rule |
|---|---|---|
| bash | on | off |
| zsh | off | on |
| unknown, first read | on | on |
| unknown, re-read | off | off |

- `coproc` read as a standalone, bare word at a command position: the next word is at a command position in every reading (`coproc {`, `coproc while`). When that next word is an ordinary word:
  - NAME rule on: the word after it is at a command position as well (today's reading; `coproc c {`).
  - NAME rule off: it is read as the first word of a simple command (the head state after a first word, so a `name()` may follow it), and the words after it are arguments (`coproc echo case x in x` opens no case statement).
- `repeat` read as a standalone, bare word at a command position:
  - repeat rule on: a head word, as today: the count is an ordinary word never read as a keyword, and the word after it is at a command position (`repeat 1 {`).
  - repeat rule off: no head word. It is an ordinary command word, the first word of a simple command, and the words after it are arguments (`repeat x case y in y` opens no case statement).
- The word decision (`_read_command_word`) reports `repeat` as a head word only when the repeat rule is on; `select`, `for` and `function` are read the same way in every reading (A2).
- Substitutions nested in the string and the quote removal of a delimiter range use the same parser, so they read with the same switches.

### 3. The re-read (FR6), inside the module-level parse

Contract: the module-level `parse` takes the string and its kind (unknown when not given) and returns the simple commands, or raises `_Undecidable` carrying the checkpoint commands, exactly as today.

1. Build a parser with the switches of the kind (the first read) and read the string.
2. Read to the end: return its commands.
3. An exception other than `_Undecidable` on the first read leaves `parse` unchanged, as today (no re-read).
4. `_Undecidable` on the first read of a bash or zsh string: raised unchanged (no re-read).
5. `_Undecidable` on the first read of an unknown-kind string: keep that exception as it is, with its checkpoint commands. Build a fresh parser with both switches off and read the same string once more.
6. The re-read reads to the end: return its commands.
7. The re-read raises anything, `_Undecidable` or any other exception class: discard it and raise the kept first `_Undecidable`, with the checkpoint commands the first read settled.

- At most two reads per string (NFR1). The re-read builds a new parser object; neither the module-level `parse` nor the parser's own parse method calls itself, and nothing reachable from `_skip_substitution` reaches `parse` (NFR2).
- `_scan` keeps exactly one try around its `parse` call, with handlers for `_Undecidable` and `Exception`, and the `Exception` handler neither returns nor raises (NFR5). The character count toward NESTED_READ_LIMIT stays in `_scan`, before `parse`, so a string that is re-read counts once at its length (A3).

### 4. Documentation (FR8, owned regions per IMPLEMENTATION.md)

- The comments on the `HEAD_*` constants and `HEAD_AFTER_WORD`: which head words depend on the coproc NAME rule and the zsh repeat rule.
- `_skip_substitution` docstring: the coproc and repeat sentences of rule 6 per reading, and the head-state list of rule 7 where it names `repeat` or `coproc`.
- `_read_command_word` docstring: `repeat` is a head word only under the zsh repeat rule.
- `_Parser` docstring: the two switches and what each reading uses.
- The module-level `parse`, `_judge` and `_scan` docstrings: the kind, where it comes from, the re-read and its fallback, the single count toward NESTED_READ_LIMIT.
- Module docstring step 7 (the kind of a `-c` string decides how its substitutions are read) and step 9 (the one re-read of an unknown-kind string and its fallback to the first read's checkpoint commands).
- Every pinned marker sentence and passage anchor stays verbatim, including the step 7 sentence about judging a literal `-c` string at every level with the same rules and the checkpoint sentences in step 9, `_Parser` and `_scan`; new sentences are added beside them. Only the loop and coproc head rule entries of RULE_MARKERS may be rewritten, in the same change as the docstring, and only where their sentence's meaning changes.
