# Task Plan: task0001 — State the --once re-launch contract, pin it with tests, bump version

## Goal

The batch reference documents state that a run which ended at a `--once`
phase boundary is continued by re-launching with the structured result's
`feature` value as the path argument and without passing the task description
again; that wording and the existing Step A rules are pinned by regression
tests; the em-workflow plugin version is raised by one patch step.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_batch_once_relaunch_contract.py` — regression tests for the
  re-launch contract wording (both documents), the existing Step A rules in
  batch-mode.md, and SKILL.md's 「パス引数なし」 item; each check with
  negative proofs.
- `test-docs/batch-once-refire-dedup/task0001.tests.yaml` — the per-task test
  record the implement protocol requires.

### Files to Modify
- `em-workflow/references/batch-mode.md` — the "Step A feature resolution"
  row of the `## Non-packet gates` table: append the re-launch contract to
  the batch-behavior cell.
- `em-workflow/references/batch-terminal-line.md` — the state bullet under
  ## Field values: extend the existing consumer re-launch sentence with the
  re-launch contract.
- `em-workflow/.claude-plugin/plugin.json` — version 0.2.12 → 0.2.13.
- `.claude-plugin/marketplace.json` — the em-workflow entry's version
  0.2.12 → 0.2.13.

## Design

Cross-task rules referenced here (not restated): IMPLEMENTATION.md Shared
Components (anchors A1 / A2 and the existing Step A rule phrases) and
Conventions (pointer-document literal constraint, table-cell constraint,
bullet-shape constraint, matcher conventions, standard library only, version
bump).

### 1. batch-mode.md — Step A feature resolution row

- Keep the row's existing text byte-identical; append one sentence to the end
  of the batch-behavior cell.
- The appended sentence says: a re-launch that continues a run which ended at
  a `--once` phase boundary passes the structured result's `feature` value as
  the path argument and does not pass the task description again, and names
  `references/batch-terminal-line.md` as the owner of that value.
- It contains anchors A1 and A2. It describes only how the value is used — no
  key list, no value domain, no escaping (NFR4).
- Illustrative wording (anchors are the only binding part): "A re-launch that
  continues a run which ended at a `--once` phase boundary passes the
  structured result's `feature` value as the path argument (value owned by
  `references/batch-terminal-line.md`) and does not pass the task description
  again."

### 2. batch-terminal-line.md — `state` bullet

- Extend the existing sentence about a consumer that sees the phase-boundary
  state and re-launches the same feature so that it also states: the consumer
  passes the result's `feature` value as the path argument and does not pass
  the task description again.
- Keep the substrings "`state` as `phase_done`" and "re-launches the same
  feature" intact; add anchors A1 and A2 inside the same bullet.
- No other bullet, section, key, order, escaping rule or value domain
  changes.

### 3. tests/test_batch_once_relaunch_contract.py

Scope extractors (pure functions over document text):

| Extractor | Input | Output | Failure |
|-----------|-------|--------|---------|
| Step A row extractor | batch-mode.md text | The single table row inside `## Non-packet gates` whose first cell begins with "Step A feature resolution" | Section or row absent, or more than one matching row → assertion failure |
| `state` bullet extractor | batch-terminal-line.md text | The top-level bullet of `## Field values` that opens with the backticked `state` key, up to the next top-level bullet | Section or bullet absent → assertion failure |
| 「パス引数なし」 item extractor | SKILL.md text | The list item opening with 「パス引数なし」 inside the argument-processing part (before `## Step 0`), including its indented continuation line | Item absent → assertion failure |

Matchers (each takes the extracted scope, normalizes whitespace, asserts
substrings):

| Check | Scope | Required phrases | Requirement |
|-------|-------|------------------|-------------|
| C1 re-launch contract in batch-mode.md | Step A row | A1, A2, `references/batch-terminal-line.md` | FR1, FR4(1), NFR4 |
| C2 re-launch contract in batch-terminal-line.md | `state` bullet | "re-launches the same feature", A1, A2 | FR3, FR4(2) |
| C3 existing Step A rules in batch-mode.md | Step A row | The four existing rule phrases (IMPLEMENTATION.md Shared Components) | FR1, FR2, FR4(3) |
| C4 SKILL.md 「パス引数なし」 item | 「パス引数なし」 item | 「常に新規 feature として Step A の create-spec ルートへ」 and 「既存ブランチの列挙・推測はしない」 | FR2 |

Negative proofs (forged text, no file I/O):

- For every required phrase of C1–C4: the real scope with only that phrase
  removed makes the matcher fail.
- Scope proofs: a forged batch-mode.md whose anchors appear only in a
  different row fails C1; a forged batch-terminal-line.md whose anchors appear
  only in the `feature` bullet fails C2.
- Extraction proofs: forged documents with the row / bullet / item missing
  make the corresponding extractor fail rather than yield an empty scope.

Plus a self-check that the module imports only standard library modules
(NFR2).
