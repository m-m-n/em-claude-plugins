# Task Plan: task0002 — spec-writer numbers SPEC.md test scenarios in the TS-n form

## Goal

The spec-writer prompt, the SPEC.md template and the spec-writer contract all
require every test scenario in a new SPEC.md, and every
`payload.spec_index.test_scenarios[].id`, to use the TS-n form (`TS-1`,
`TS-2`, …).

## Requirements

FR1, NFR3

## Scope

### Files to Create

- `tests/test_scenario_id_spec_writer_docs.py` — document-content tests for the three files below

### Files to Modify

- `em-workflow/agents/spec-writer.md` — add the scenario numbering rule and state the ID form in the Output section
- `em-workflow/references/templates/spec-document.md` — give the Test Scenarios placeholder items TS-n IDs
- `em-workflow/references/contracts/spec-writer-contract.md` — state the ID form of the spec_index test scenario entries

## Design

Scenario ID forms are defined in IMPLEMENTATION.md Shared Components. This
task owns the SPEC.md numbering statement (IMPLEMENTATION.md D4).

### spec-writer.md

- Section `## Rendering REQUIREMENTS.md and SPEC.md`: inside the SPEC.md
  bullet, next to the existing FR/NFR numbering sentence and written the same
  way, add a rule. Number every test scenario in SPEC.md's Test Scenarios
  section `TS-1`, `TS-2`, … (hyphenated, matching `^TS-[1-9][0-9]*$`), as one
  sequence starting at `TS-1`. These IDs must agree exactly, as literal
  strings, with `payload.spec_index.test_scenarios[].id`.
- Section `## Output`: the `payload.spec_index.test_scenarios[]` bullet states
  that `id` is the TS-n string used in SPEC.md.

### spec-document.md

Inside `## Test Scenarios`:

- The placeholder items under `### Unit Tests`, `### Integration Tests`,
  `### E2E Tests` (the scenario lines only), `### Edge Cases` and
  `### Performance Tests` each begin with a TS-n ID. Number them as one
  sequence from `TS-1` through the section, in document order, with no gap
  and no repeat.
- In `### E2E Tests`, the two detection-result lines and the "Existing E2E
  tests pass without regression" line stay unchanged.
- No heading is added, removed or renamed anywhere in the template.

### spec-writer-contract.md

In the `completed` payload's `spec_index` list, the `test_scenarios[]` entry
states that `id` uses the TS-n form, with `TS-1`, `TS-2` as examples, and
that it agrees exactly with the IDs in SPEC.md.
