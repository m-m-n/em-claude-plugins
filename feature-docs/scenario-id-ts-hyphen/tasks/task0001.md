# Task Plan: task0001 — Validator check rejecting hyphen-less scenario IDs in planner output

## Goal

`em-workflow/scripts/validate-worker-output.py` rejects a completed
implementation-planner result whose feature-directory VERIFICATION.md or newly
planned task plans contain a hyphen-less (TSn) scenario ID. Every read-side
scenario ID behavior and every other worker's validation stay as they are, and
the two sha256 pins on the validator and its test module are refreshed.

## Requirements

FR3, FR4, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/scripts/validate-worker-output.py` — add the scenario-ID form check and run it on implementation-planner results
- `tests/test_validate_worker_output.py` — add test classes for the check
- `tests/test_gate_option_vocabulary.py` — refresh the two sha256 pins on the files above and add the refresh comments

## Design

Implement the "Hyphen-less ID detection rule" and the "Scenario-ID form check
contract" exactly as pinned in IMPLEMENTATION.md Shared Components. Follow
IMPLEMENTATION.md D1 (completed results only) and D2 (reuse the read grammar,
add a left boundary). This section adds only what is specific to this task.

### Components

| Component | Responsibility | Contract |
|-----------|----------------|----------|
| Hyphen-less ID finder | Return the hyphen-less IDs in one document's text | Pre: any string. Post: the set defined by the detection rule. Pure; no file access. |
| Scenario-ID form check | Produce the `scenario-id-form` errors for one implementation-planner result | Pre: the result is a mapping; the feature directory is given. Post: a list of validation errors, possibly empty; never raises. |

### Processing flow

1. The worker-result validation finishes its existing workflow-patch and
   task-plan checks.
2. If the worker is `implementation-planner`, the result's status is
   `completed` and a feature directory was given, run the scenario-ID form
   check. Otherwise do nothing.
3. Target (a), VERIFICATION.md under the feature directory:
   - absent: no error;
   - a symlink, not a regular file, larger than the existing plan-read byte
     limit, or not decodable as UTF-8: one `scenario-id-form` error naming
     the file and the reason; the content is not scanned;
   - otherwise: run the finder; one error if it returns anything.
4. Target (b), for each `tasks_patch.entries` item that has a `plan`:
   - skip the item when its plan fails any precondition the existing
     task-plan validation applies (those failures are already reported
     there), or when its final path segment is `TASK.md`;
   - otherwise read the plan, run the finder, and report one error if it
     returns anything.
5. Add the errors to the result's error list.

Reuse the validator's existing plan-path resolution helper, its `TASK.md`
exemption predicate, its plan-read byte limit and its noise-stripping step.
Do not restate their logic. Do not change the read grammar, the Test Scenarios
ID extraction function or the noise-stripping step.

### Error message

- Code: `scenario-id-form`.
- VERIFICATION.md: the message contains `VERIFICATION.md` and every
  hyphen-less ID found, de-duplicated and sorted.
- Task plan: the message contains the task id, the `plan` value as given in
  the patch (for example `tasks/task0001.md`), and every hyphen-less ID found,
  de-duplicated and sorted.
- An unreadable VERIFICATION.md: the message contains `VERIFICATION.md` and
  the reason (symlink, not a regular file, too large, or not UTF-8).

### Pin refresh

After the validator and its test module reach their final content, set
`VALIDATE_WORKER_OUTPUT_SHA256` and `TEST_VALIDATE_WORKER_OUTPUT_SHA256` in
`tests/test_gate_option_vocabulary.py` to the new digests. Add a comment block
beginning "Refreshed again by scenario-id-ts-hyphen/task0001" after the
existing comment blocks above each of the two constants, following that file's
existing convention: what changed, and that `PINNED_VALIDATOR_TEST_LINE` is
unaffected and still asserted. Keep every existing comment, including the
"Refreshed again by worker-digest-ownership/task0003" block that
`tests/test_digest_contract_alignment.py` reads. Do not change
`WORKFLOW_PATCH_SHA256`, `FIXTURE_SHA256` or `PINNED_VALIDATOR_TEST_LINE`.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR3; TS-1, TS-4): a completed implementation-planner result
  validated with a feature directory whose VERIFICATION.md Test Scenarios
  section carries a hyphen-less ID yields exactly one `scenario-id-form`
  error. Its message contains `VERIFICATION.md` and that ID. When the same
  VERIFICATION.md also carries the hyphenated spelling of the same number, the
  error is still produced and lists only the hyphen-less spelling.
- [ ] AC-2 (FR3; TS-2, TS-7): an entry whose plan `tasks/task0001.md`
  contains a hyphen-less ID yields one `scenario-id-form` error whose message
  contains `task0001`, `tasks/task0001.md` and that ID. An entry whose plan's
  final path segment is `TASK.md`, with the same content, yields no
  `scenario-id-form` error.
- [ ] AC-3 (FR3; TS-3, TS-5, TS-6; SPEC A1, A2): no `scenario-id-form` error
  is produced when every ID in VERIFICATION.md and the plans is in the TS-n
  form, when hyphen-less IDs appear only inside fenced code blocks or HTML
  comments, or when an ASCII letter or digit directly precedes `TS` (the
  SPEC's X- and U-prefixed examples). An error is produced when a hyphen-less
  ID sits inside an inline code span, at the very start of the document, or
  directly after a non-ASCII character such as Japanese text.
- [ ] AC-4 (FR3, FR4; TS-8; IMPLEMENTATION.md D1): no `scenario-id-form`
  error is produced for (i) a rework-planner result whose feature-directory
  VERIFICATION.md carries hyphen-less IDs, (ii) an implementation-planner
  result with a status other than `completed` and a hyphen-less
  VERIFICATION.md in the feature directory, (iii) any validation run without
  a feature directory, (iv) a completed implementation-planner result whose
  feature directory has no VERIFICATION.md, or (v) a hyphen-less plan file in
  `tasks/` that no `tasks_patch.entries` item names.
- [ ] AC-5 (TM-1): a `plan` value that is absolute, has a `..` segment or
  passes through a symlink is not read by the new check. Only the existing
  task-plan errors appear for it, even when the file it points to contains a
  hyphen-less ID. A VERIFICATION.md that is a symlink yields one
  `scenario-id-form` error naming the symlink reason, and a hyphen-less ID in
  the symlink's target is not listed in any message.
- [ ] AC-6 (TM-2): a VERIFICATION.md that is larger than the plan-read byte
  limit, is a directory, or does not decode as UTF-8 yields one
  `scenario-id-form` error. The validation returns normally: the function
  returns its error list without raising, and the command line exits 1, not
  2.
- [ ] AC-7 (FR4, NFR1, NFR2, NFR3; TS-9, TS-12):
  `TestScenarioIdExtractionAcceptsBothForms`,
  `TestReworkIndexNoveltyWithBothScenarioIdForms` and
  `tests/test_requirements_tests_replace.py` pass with their expectations
  unchanged. The two pins in `tests/test_gate_option_vocabulary.py` equal the
  final digests and carry a refresh comment naming
  scenario-id-ts-hyphen/task0001. `PINNED_VALIDATOR_TEST_LINE`,
  `WORKFLOW_PATCH_SHA256` and `em-workflow/references/workflow-patch.md` are
  unchanged. `python3 -m unittest discover -s tests` passes.

## Test Notes

- AC-1 to AC-6 are unit tests in new classes in
  `tests/test_validate_worker_output.py`. They call the worker-result
  validation function directly with a temporary feature directory, following
  the existing `TestPlanPathContainment` pattern (a completed
  implementation-planner result with a `replace_planning` patch and a valid
  plan body that satisfies the existing Files and Acceptance Criteria checks).
  Assert on the presence or absence of the `scenario-id-form` code and on the
  message substrings.
- Add one command-line test through the module's existing CLI runner: a
  hyphen-less VERIFICATION.md gives exit code 1 and the JSON output contains
  `scenario-id-form`.
- Hyphen-less IDs are test data built inside the test module.
- Symlink cases: skip with a reason when the platform cannot create symlinks.
  Do not create FIFOs or device files; a read on them can block.
- Oversized VERIFICATION.md: write a file just above the existing byte limit,
  reading the limit from the validator module instead of repeating the
  number.
- The existing fixture corpus run (`TestFixtureCorpusDataDriven`) must keep
  every exit code. The rework-planner fixtures whose baseline VERIFICATION.md
  uses the hyphen-less form are the corpus-level evidence for AC-4 (i).
- AC-7: run the three named tests unchanged, then refresh the pins last,
  after every other edit to the two pinned files is final.

## Out of Scope

- Changing the read grammar, the Test Scenarios ID extraction or the
  noise-stripping step.
- Rewriting existing documents that use the hyphen-less form.
- New fixtures under `em-workflow/references/fixtures/`.
- Every documentation change (owned by other tasks).
