# Task Plan: task0004 — Planner-side documents describe the TS-n requirement and its check

## Goal

The create-plan phase document lists the new scenario-ID form check among the
invariants the validator implements. The implementation-planner prompt and the
planner contract state that a new VERIFICATION.md and new task plans use the
TS-n form only, and that the hyphen-less form is rejected by that check.

## Design

Describe the "Scenario-ID form check contract" from IMPLEMENTATION.md Shared

### create-plan-phase.md, section 9

- Add one bullet to the list of invariants the validator implements. It says:
  for an implementation-planner result with status `completed`, when the
  feature directory is supplied, the feature directory's VERIFICATION.md and
  every task plan named by `tasks_patch.entries[].plan` (except a plan whose
  final path segment is `TASK.md`) contain no hyphen-less scenario ID outside
  fenced code blocks and HTML comments. Name the error code
  `scenario-id-form`, and say that rework-planner output is not checked.
- In the paragraph about dropping `--feature-dir`, add the scenario-ID form
  check to the checks that are skipped together. The sentence's count of
  checks must match the list.
- The "not implemented by the script" list, the section heading and the
  canonical invocation block stay unchanged.

### implementation-planner.md, step 5

Add a short statement under `### 5. VERIFICATION.md (feature-wide, this agent
OWNS it)`. A new VERIFICATION.md and every task plan this agent writes use the
TS-n scenario ID form only, following the plan-writing skill's scenario ID
rule (including its rule for a SPEC.md that uses the hyphen-less form). A
hyphen-less ID in either is rejected by the validator's scenario-ID form
check. Keep every `###` step heading as it is. Do not touch the
`## Gate option vocabulary` section; it is byte-pinned from its heading to the
end of the file.

### planner-contract.md

Add a `##` section placed before `## Gate option vocabulary`. It states:

- new VERIFICATION.md files and task plans use the TS-n form only;
- `scripts/validate-worker-output.py` rejects a `completed` result validated
  with `--feature-dir` when either contains a hyphen-less ID outside fenced
  code blocks and HTML comments (code `scenario-id-form`);
- rework-planner output is outside this check;
- the rule text is owned by the plan-writing skill, which this contract cites
  and does not restate.

The gate_id set and the Gate option vocabulary table stay unchanged.
