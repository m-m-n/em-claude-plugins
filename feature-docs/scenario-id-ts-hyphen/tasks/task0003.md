# Task Plan: task0003 — plan-writing limits the hyphen-less form to reading existing documents

## Goal

The plan-writing skill's scenario ID rule requires the TS-n form in every new
VERIFICATION.md and task plan, and accepts the hyphen-less (TSn) form only when
an existing document is read.

## Requirements

FR2, NFR3

## Scope

### Files to Create

- `tests/test_scenario_id_plan_writing_rule.py` — document-content tests for the rule

### Files to Modify

- `em-workflow/skills/plan-writing/SKILL.md` — rewrite the scenario ID rule after the VERIFICATION.md template and add a checklist item

## Design

Scenario ID forms, the Hyphen-less ID detection rule and the Scenario-ID form
check are defined in IMPLEMENTATION.md Shared Components. This task owns the
authoring rule text (IMPLEMENTATION.md D3, D4).

### The scenario ID rule (the block after the VERIFICATION.md template)

The block stays outside the template's fenced block, in the same place. It
states, in this order:

1. New VERIFICATION.md files and new task plans (`tasks/*.md`) use the TS-n
   form only: `TS`, a hyphen, one or more digits.
2. The TSn form (`TS` immediately followed by digits, no hyphen) is a valid
   scenario ID only when an existing document is read. The validator's
   extraction recognizes both forms.
3. A new VERIFICATION.md or task plan contains no hyphen-less ID anywhere
   outside fenced code blocks and HTML comments — not only in the scenario
   table. An implementation-planner result that breaks this is rejected by
   the scenario-ID form check of `em-workflow/scripts/validate-worker-output.py`.
4. When SPEC.md uses the hyphen-less form (a feature created before this
   rule), the new VERIFICATION.md uses the same numbers in the TS-n form, and
   SPEC.md is not rewritten.
5. These two are the only scenario ID forms.
6. Scenario IDs are compared as literal strings. Keep the existing example
   that the hyphen-less and hyphenated spellings of 13 are distinct IDs.

The current sentence saying the hyphen-less form "is also a valid scenario
ID" without qualification is removed. Item 2 replaces it.

### Pre-Save Self-Verification Checklist

Add one item: new VERIFICATION.md and every task plan use only TS-n scenario
IDs, with no hyphen-less ID outside fenced code blocks and HTML comments.
Every existing checklist item stays as it is.
