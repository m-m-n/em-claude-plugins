## Design

### Single-quoted `$(` matching (FR4)

- Scope: only the search, in the honor_single_quotes=False scan, for the
  closing parenthesis of a `$(` that sits inside a single-quoted span.
- Result contract (C5): for every input the spans found are identical to the
  current implementation's. A `$(` inside a single-quoted span is matched
  only when it balances before that span ends; otherwise it stays unmatched,
  as now. Whatever the current search counts as opening and closing,
  including any nested-quote handling it applies, is kept.
- Cost contract: the total work for all `$(` in one single-quoted span is
  linear in the span length. Each character of the span is examined a
  bounded number of times, however many `$(` the span holds.
- Flow:
  1. On reaching a single-quoted span, resolve every `$(` inside it in one
     forward pass over the span. Do not run a separate search from each `$(`.
  2. A `$(` that balances before the span ends gets its span, exactly as
     the current search would report it.
  3. A `$(` still open when the span ends is unmatched.
  4. Hand the results to the rest of the scan in the same form as today.

### Runner time limit (FR10)

- Every evaluation the runner performs is bounded by 10 seconds. This
  includes each case's evaluation under the unattended-run demotion. The
  value equals the timeout hooks.json sets for destructive-guard.py. Keep it
  as one named value in the runner, with a note that it mirrors hooks.json.
- When an evaluation runs past the limit:
  - the evaluation stops and leaves no process behind;
  - the case counts as FAIL, and its FAIL line shows the label and says it
    timed out;
  - the runner moves on to the remaining cases;
  - the final summary and exit status treat it like any other FAIL.
- Invocation and the output for cases that finish within the limit are
  unchanged (C7).

### Cases (FR8, FR10, FR9)

- Three deny cases hold the SPEC TS-9 forms. Their labels carry

- Labels, placement and the target placeholder follow IMPLEMENTATION.md
