# Task Plan: task0004 — Skipped-word sinks and command-name overrides make data judgments undetermined

## Goal

Two cases stop being judged data:

- a heredoc whose host statement names a shell sink in a word skipped
  before the command word, or uses `env` split-string;
- every heredoc in a command that redefines a command name.

Both become undetermined and go to the existing fallback. This closes
511cd470522973d8 and b8fd289ca7750a04.

## Design

### Skipped-word sink check (FR6)

- Skipped words are the words that the existing command-word resolution
  passes over before the command word:
  - `VAR=value` assignments;
  - wrapper options and their values;
  - git / gh global option values.
- A skipped word matches when SHELL_SINK, applied exactly as it is applied
  today, matches any of these forms of the word:
  - the word as written;
  - the part after its first `=`;
  - the leading word of that value;
  - each of the above with quotes removed.

  Examples: `GIT_EDITOR=bash`, `core.editor=sh`, a quoted sink value.
- A match makes the destination undetermined (IMPLEMENTATION.md C1).
- `env` with `-S` or `--split-string` makes the destination undetermined in
  every spelling:
  - as a separate argument;
  - attached to the option, quoted or not;
  - joined with `=`;
  - `-S` inside a cluster of short options.
- Non-sink values do not match. For example `user.name=x` in existing cases
  468 and 469 stays allow.
- The check runs once over the skipped words of the statement it receives
  (C4).

### Command-name override detection (FR7)

- If the command string passed to the hook contains any override construct,
  every heredoc in that command that would be data becomes undetermined
  (C1). Shell-sink results are not affected.
- Override constructs:
  - function definitions:
    - `NAME()`, with or without a space before the parentheses;
    - `function NAME`, with or without `()`;
    - any body form, including a `( … )` body;
  - `alias`, `hash` or `enable` at command position, as the existing
    command-word resolution determines command position;
  - assignment to PATH:
    - as a prefix assignment of a command;
    - as a standalone assignment statement;
    - as an argument of `export`.
- Where constructs are detected:
  - Counted: text the guard parses as commands, including nested command
    text it already scans as commands.
  - Not counted: the bodies of data heredocs and comments. Inside a quoted
    string a word is not at command position.
- Not in scope (REQUIREMENTS.md A7): PATH assignments through declare,
  typeset or readonly, and definitions inside files read by source or `.`.
- Cost (NFR3): the presence flag is computed once per hook invocation in
  one forward pass.
- Residual risk A6 stays as accepted. If the override target path contains
  no sink name, the undetermined body is not rescanned.

### Precedence

- A heredoc that is shell-sink stays shell-sink.
- Otherwise, if FR6 or FR7 applies, the heredoc is undetermined.
- Otherwise the existing classification applies.
