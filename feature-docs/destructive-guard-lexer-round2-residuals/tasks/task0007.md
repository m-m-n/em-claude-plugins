# Task Plan: task0007 — One named snapshot for the non-adjacent-close resume

## Goal

The state the lexer saves and restores when it resumes after a
non-adjacent `))` close is captured and restored through one named
snapshot type defined in one place, and the set of openers to read as two
parentheses is returned by the pass instead of being mutated in place, so
adding pass state can no longer silently corrupt a resume; the lexical map,
work and verdicts stay exactly as they are (review round 1 finding
956849b341a5150b).

## Design

Cross-task rules that apply here (IMPLEMENTATION.md): the two-parentheses
re-reading row and the rework round 1 pass-state snapshot row of Shared
Components (this task owns the snapshot type), the `lex_shell()` contract
row, the test layout rows.

### Pass-state snapshot

- Every piece of pass state that the resume restores — each collection that
  grows during a pass (regions, single-quote candidates, encountered
  openers, here-document operators, pending here-document entries and their
  sequence records, and any other such collection present at the time) and
  each scalar it resets — is a named field of the pass state, which is held
  in one record whose fields can be enumerated.
- One snapshot type captures and restores that state. Capture and restore
  are defined next to each other on that type; no other site truncates,
  re-slices or reassigns these fields for a resume.
- Each collection is restored from its own recorded extent. In particular
  pending here-document entries and their sequence records are restored
  independently, never on the assumption that their lengths move together.
- Pass-state fields that a resume deliberately does not restore are named
  in one explicit list kept next to the snapshot type.

### Openers read as two parentheses

- A pass does not modify the opener set it receives. The openers it newly
  decides to read as two parentheses are part of the pass's returned
  result, and the caller combines them for any further pass.

### Whole-text-restart reference path

The reference reading the map-equivalence test compares against stays
available and uses the same snapshot type and the same returned-value
form; it gains no restore logic of its own.

### Behaviour to preserve

Final lexical maps (regions, here-document operators with bodies,
candidates, unopened openers, tail start), the work counted, the budget
rule and every hook decision are unchanged for every input.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR5): A test captures a snapshot from a pass state, appends to every collection field and changes every restored scalar field, restores, and asserts every field equals its captured value; the test iterates over the snapshot type's declared fields, so a field added to the type is covered without editing the test.
- [ ] AC-2 (FR5): A test asserts that the pass state's enumerable fields equal the union of the snapshot's restored fields and the explicit not-restored list, and that the two sets are disjoint, so a pass-state field added without classification fails it.
- [ ] AC-3 (FR5, NFR4): A test restores a snapshot captured while pending here-document entries and their sequence records have different lengths, and asserts both are restored to their own captured contents.
- [ ] AC-4 (FR5): A test runs a pass over a text with one non-adjacent close (e.g. `x=$((echo a) | wc -c)`) with an opener set given as input, and asserts the input set is unchanged afterwards and the pass result names that opener.
- [ ] AC-5 (FR5, NFR1, NFR3, NFR4, TM-4): The map-equivalence test over the case table and fixed forms, the linearity tests, the budget-exceeded test and the determinism test all pass with their expectations unchanged.
- [ ] AC-6 (NFR5): The case table is not modified by this task, and `python3 em-workflow/hooks/tests/run-destructive-guard.py`, `python3 -m unittest tests.test_destructive_guard_lexer_agreement` and `python3 -m unittest discover -s tests` all pass, including `TestStageAgreement` and `TestModuleContract`.
