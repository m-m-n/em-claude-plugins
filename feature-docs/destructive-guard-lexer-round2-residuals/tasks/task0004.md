# Task Plan: task0004 — Linear re-reading for `((` / `$((` without an adjacent `))`

## Goal

When a `((` or `$((` closes without an adjacent `))`, the lexer reaches the
two-parentheses reading without re-reading the whole text once per such
opener, so the work stays linear in the input length and short benign
commands no longer exceed the work bound, while the lexical map stays
exactly what today's reading gives (finding 29bbf9032dd762a0).

## Requirements

FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/hooks/destructive-guard.py` — handling of a non-adjacent close in the arithmetic frame and the re-reading loop of the lexer entry point.
- `em-workflow/hooks/tests/destructive-guard-cases.json` — append this task's allow cases after the last entry.
- `tests/test_destructive_guard_lexer_agreement.py` — linearity, time-bound, budget and map-equivalence tests.

## Design

Cross-task rules that apply here (IMPLEMENTATION.md): this task owns the
two-parentheses re-reading row of Shared Components; it must keep the
settle channel row and the here-document pending-body semantics unchanged;
the `lex_shell()` contract row, case table append protocol and test layout
row also apply.

### Meaning to preserve

- An opener `((` or `$((` whose first close at its own depth is a lone `)`
  (not followed by `)`) is read as two parentheses: `((` as two nested
  groups / subshells, `$((` as a command substitution whose body starts
  with a subshell. Reading one opener this way can change how later text
  is read, including whether a later opener closes adjacently.
- The final map — regions, here-document operators (with bodies),
  single-quote candidates, unopened openers, tail start — is the reading in
  which exactly the openers that close without an adjacent `))` are read as
  two parentheses: the same map today's whole-text restart produces.

### What changes

- Today each such opener ends the pass and restarts the whole text with
  one more opener marked, so k openers cost about k whole-text passes
  (destructive-guard.py :1332 and the loop at :1451-1461).
- The new reading must reach the same final map with total counted work at
  most `LEX_WORK_FACTOR` × text length + 1024 for any number of such
  openers, including openers nested inside another's re-read span, inside
  double quotes, and openers whose span crosses a line start with a
  here-document operator pending.
- The approach is the implementer's choice within the lexer's
  architecture (for example: resuming locally from the opener with the
  grammar state it had there, or settling every such opener found in one
  pass before a single restart, provided dependencies between openers are
  still resolved to the same final map in a bounded number of passes).
- The work counter keeps its meaning (every loop iteration counted against
  the budget, across all passes and re-reads); the rounds counter keeps
  counting passes or re-reads and is not pinned by any test.
- The budget rule is unchanged: past the bound the lexer raises its
  budget-exceeded condition and the hook answers ask (deny under
  `CLAUDE_BATCH`), never allow.

### Not touched

The end-of-pass collection of unclosed openers and their settle-all-at-once
behaviour (other tasks rely on it), command-position transitions,
here-document operator reading and subscript reading.

## Acceptance Criteria (MANDATORY)

Commands below use the case table's JSON string notation (`\n` is a
newline). The FR5 inputs, as measured in the review record, are: L28 and
L100 = the lines `x=$((echo N) | wc -c)` for N = 0..27 (633 characters) and
N = 0..99 (2289 characters), joined by `\n` with no trailing newline; S40 =
the statements `((cd /tmp/aN && ls) || echo no)` for N = 0..39, joined by
`\n`.

- [ ] AC-1 (FR6): Before any commit that changes `em-workflow/hooks/destructive-guard.py`, a commit appends to the case table, after its last pre-existing entry, L28, L100 and S40 as allow cases with labels beginning with 29bbf9032dd762a0; the task branch history shows that order.
- [ ] AC-2 (FR5, TM-4): L28, L100 and S40 each get the decision allow both without `CLAUDE_BATCH` and with `CLAUDE_BATCH=1`.
- [ ] AC-3 (FR5, FR7, NFR1, TM-4): A test in `TestUnclosedOpeners` or `TestReworkLinearity` builds k = 200 and k = 400 lines of each unit `x=$((echo N) | wc -c)` and `((cd /tmp/aN && ls) || echo no)` (N numbered per line) and asserts that the 400-line work is at most 2.5 × the 200-line work + 100 and at most `LEX_WORK_FACTOR` × its length + 1024; the existing linearity tests keep passing.
- [ ] AC-4 (FR5, NFR4): A test asserts, for every command in the case table and every fixed form of the agreement test, that the regions, here-document operators, candidates, unopened openers and tail start of `lex_shell()` equal those of the whole-text-restart reading; fixed expectations additionally pin these maps for a nested non-adjacent close (`$(( $((echo a) ) )` style), a non-adjacent close inside double quotes, and one whose span crosses a line start while a here-document operator is pending; the same text gives an identical map after the lexer cache is cleared.

- [ ] AC-6 (NFR3, TM-4): When the work bound is exceeded on an input that contains non-adjacent closes, `lex_shell()` raises its budget-exceeded condition and the hook's run entry point answers ask (deny with `CLAUDE_BATCH=1`), never allow — checked in-process with the work factor lowered for the duration of the test; the existing budget test keeps passing.
- [ ] AC-7 (FR8, NFR5): No pre-existing case-table entry is removed, edited or reordered, this task's cases sit at index 627 or later (located by label and command text), and `python3 em-workflow/hooks/tests/run-destructive-guard.py` and `python3 -m unittest tests.test_destructive_guard_lexer_agreement` both pass, including `TestStageAgreement` and `TestModuleContract`.

## Test Notes

- AC-1 is a history check: the three allow cases currently get ask (the
  budget is exceeded), so the runner is red until the fix.
- AC-4's reference: one way is a test-side driver that reproduces today's
  whole-text restart over the pass function with no budget limit, if the
  pass function still accepts the set of openers to read as two
  parentheses; otherwise capture the base implementation's maps for the
  corpus before the change and pin them. Write the equivalence test first:
  it passes on the base and must keep passing after the change.
- AC-4's corpus includes every case-table command, so after merge it also
  covers the cases the sibling tasks add.
- AC-5 runs through the hook's stdin / stdout contract and is timed, like
  the existing 60 KB tests.
- AC-6 cannot use the subprocess helper (a separate process does not see an
  in-process change to the work factor); drive the hook's run entry point
  in-process with stdin / stdout and the batch environment variable
  substituted, and restore the work factor afterwards.
