# Task Plan: task0005 — Here-document fallback and close lines that keep the following lines inspected

## Goal

A `<<` whose delimiter word cannot be read no longer leaves the rest of the
text to ordinary shell lexing (where a body's `#` or `'` can hide a line
bash executes), and a close line ends a body only where bash 5.3 ends it,
so a destructive line after either form is inspected and denied
(review round 1 findings 1baa909f9b288847 and 19edf404b5cbeb2b).

### Unreadable delimiter word: tail reading (FR4, NFR6, SPEC A3)

- Which words are unreadable does not change: no word before a
  metacharacter or the end of the text; a quoted segment that does not
  close on the operator's line; a word holding a command substitution, a
  backtick, or a `${` / `$((` / `$[` construct.
- Today such a `<<` registers no operator and the text after it is lexed as
  ordinary shell, so a later `#` opens a comment and a later `'` opens a
  quote over lines bash executes.
- New reading: from the position of such a `<<` on, the text is read the
  way the settle channel reads its tail — no comment, no single- or
  double-quote region and no further here-document operator is opened, and
  every following line stays subject to inspection. The tail start of the
  map is the earliest of this position and any tail start the settle
  channel reports.
- Reading such a word literally as a delimiter (bash 5.3 uses `E${x}` as
  written) is not done in this task; every unreadable word takes the tail
  reading.

### Close-line matching (FR4, NFR6)

- `<<`: a line closes the body only when the line, with its line end
  removed, equals the delimiter value exactly. Leading or trailing spaces
  and tabs prevent the close.
- `<<-`: leading tabs are removed from the line first, then the remainder
  must equal the delimiter value exactly. Leading spaces and any trailing
  blank prevent the close.
- The close-line word function and the per-text line index follow the same
  rule per operator, and the index can look up a delimiter value that holds
  blanks (a quoted delimiter such as `E' X'`, value `E X`). The index stays
  one pass over the lines.
- A delimiter value that no line matches still takes no body (unchanged).

### Existing expectations that change

- The agreement test that pins the old blank allowance for close lines is
  rewritten to the per-operator rule above.
- The fixed expectation that pins "lexed as today" for a quote not closed
  on the operator's line is rewritten to the tail reading.
- Case-table entries are fixed points (IMPLEMENTATION.md Conventions): if
  either change flips the verdict of a pre-existing case, the case is not
  edited, the behaviour change is withheld for that form, and the conflict
  is reported as a plan deviation.

### Not touched

Delimiter extent, delimiter value and quoted flag for readable words;
command-position reading and `time` options; subscript reading; the
non-adjacent re-reading and its resume state (any new pass state this
task adds is registered per the pass-state snapshot row of IMPLEMENTATION.md).
