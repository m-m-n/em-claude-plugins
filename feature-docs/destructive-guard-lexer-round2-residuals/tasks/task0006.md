# Task Plan: task0006 — `time` options read as bash 5.3 reads them

## Goal

After `time -p`, only `--` is a `time` option; a second `-p` is the command
word and ends the command position, so a following `name[...]=...` word is
an argument whose `<<` is a real here-document operator and the lines after
its body are inspected (review round 1 finding 48e1f462b0dd164f).

### `time` option transitions (FR2, NFR6)

- Directly after `time`: `-p` is an option (the command position is kept
  and the marker records that `-p` was seen); `--` ends the options (the
  command position is kept and no further option is accepted).
- Directly after `time -p`: only `--` is an option (handled as today). Any
  other word, a second `-p` included, is the command word: it ends the
  command position exactly as any other command word does.
- After `--`: no option is accepted (unchanged).
- Nothing else in the grammar state changes: reserved words, the
  after-closer state and assignment-acceptable positions are decided as
  before for every input that does not repeat `-p` after `time -p`.

### Existing expectations that change

If an agreement test pins a repeated `-p` after `time -p` as an option, it
is rewritten to the rule above. Case-table entries are fixed points
(IMPLEMENTATION.md Conventions): if the change flips a pre-existing case,
the case is not edited and the conflict is reported as a plan deviation.

### Not touched

Here-document operator reading and close lines, subscript reading itself,
the non-adjacent re-reading.
