# Task Plan: task0001 — Regression tests for multi-substitution rm reason designations

## Goal

Regression tests pin that destructive-guard's reason text names each substitution-only
rm target by a distinct positional designation, in order, when a command carries two or
more such targets. The hook stays unchanged when those tests pass on the current hook.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR9, FR10, FR11, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_destructive_guard_multi_substitution_reason.py` — the regression tests for TS-1, TS-2, TS-3 and TS-5 to TS-9

### Files to Modify
- `em-workflow/hooks/destructive-guard.py` — modified only when a new test fails on the unmodified hook (FR6); otherwise left identical to the base commit

## Design

### Cases

D(n, m) below stands for the designation text "n番目のrmのm番目の対象" followed by the
bracketed stand-in, for example `` 1番目のrmの2番目の対象[`$(...)`] ``. The Acceptance
Criteria spell every expected designation out in full.

| TS | Command | CLAUDE_BATCH | Decision | Reason ID | Designations, exactly and in order | Must not appear in the reason text |
|----|---------|--------------|----------|-----------|------------------------------------|------------------------------------|
| TS-1 | `rm -rf $(cat a) $(cat b)` | absent | ask | rm-unresolvable | D(1, 1), D(1, 2) | `cat a`, `cat b` |
| TS-2 | `rm -rf $(cat a); rm -rf $(cat b)` | absent | not pinned (FR2 pins none) | not pinned | D(1, 1), D(2, 1) | — |
| TS-3 | `rm -rf $(cat a) $(cat b)` | present | deny | rm-unresolvable | D(1, 1), D(1, 2) | — |
| TS-5 | `` rm -rf `cat a` `cat b` `` | absent | ask | rm-unresolvable | D(1, 1), D(1, 2) | — |
| TS-6 | `` rm -rf $(cat a) `cat b` `` | absent | ask | rm-unresolvable | D(1, 1), D(1, 2) | — |
| TS-7 | `rm -rf <(cat a) <(cat b)` | absent | ask | rm-unresolvable | D(1, 1), D(1, 2) | — |
| TS-8 | `rm -rf $(cat a) /tmp/scratch $(cat b)` | absent | ask | rm-unresolvable | D(1, 1), D(1, 3) | 1番目のrmの2番目の対象 |
| TS-9 | `rm -rf $(printf MULTISUBBODYALPHA) $(printf MULTISUBBODYBETA)` | absent | ask | rm-unresolvable | D(1, 1), D(1, 2) | MULTISUBBODYALPHA, MULTISUBBODYBETA |

Behaviour these expectations rest on (SPEC.md A6): a backtick substitution becomes the
same stand-in as a dollar-paren substitution; in a process substitution the opening and
closing operators are not counted as targets; the static target `/tmp/scratch` is safe,
produces no record, and still occupies target position 2.

### Flow for one case

1. Build a PreToolUse payload for the Bash tool whose command is the case's command.
2. Run `em-workflow/hooks/destructive-guard.py` as a child process, locating it the
   same way `tests/test_destructive_guard_rm_reason_positions.py` does, with the
   payload on standard input.
3. Build the child environment explicitly: the HOME and PATH the test chooses, plus
   CLAUDE_BATCH only for TS-3. Nothing is inherited from the runner's environment that
   could change the decision, so the result is the same when the runner itself has
   CLAUDE_BATCH set (NFR1).
4. Read the permission decision and the reason text from the hook's JSON output. The
   reason ID is the rule name in the reason text's leading destructive-guard prefix,
   read the same way the existing reason tests read it.
5. Extract every designation from the reason text, in order of appearance, with a
   pattern of the same form as DESIGNATION_PATTERN in
   `tests/test_destructive_guard_rm_reason_positions.py` (NFR4). Reusing that constant
   by import or defining an identical local one is the implementer's choice; the
   existing file is not modified.
6. Compare the extracted list with the expected list as whole ordered lists. One
   equality check covers order, distinctness and "each exactly once" (NFR4).
7. Check that every "must not appear" string is absent from the reason text.

### Conditional hook change (FR6)

1. Write the tests and run them against the unmodified hook.
2. When every new test passes, the hook is not touched.
3. When a new test fails, change the hook so that every case above passes, under these
   constraints:
   - the SUBSTITUTION_STANDIN value and the four inert conditions in its comment stay
     unchanged (FR5)
   - the single-target reason text stays unchanged (FR4)
   - the decision and the reason ID stay as above (THREAT-MODEL.md TM-2)
   - no substitution body text reaches the reason text (THREAT-MODEL.md TM-1)
   - the same command still yields the same reason text (NFR2)
4. After a hook change, run both suites named in AC-7 (the project's hook test rule),
   and name the test that failed before the change in the implementation report.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `tests/test_destructive_guard_multi_substitution_reason.py` is collected by `python3 -m unittest discover -s tests`, uses only the standard library, runs the hook as a child process with a PreToolUse JSON on standard input, and passes both when the runner's own environment has CLAUDE_BATCH set and when it does not, because the child environment carries the HOME and PATH the test sets and carries CLAUDE_BATCH only in the batch case (NFR1).
- [ ] AC-2: For `rm -rf $(cat a) $(cat b)`, the decision is ask without CLAUDE_BATCH and deny with CLAUDE_BATCH, the reason ID is rm-unresolvable in both, the designations extracted from the reason text equal exactly [`` 1番目のrmの1番目の対象[`$(...)`] ``, `` 1番目のrmの2番目の対象[`$(...)`] ``] in both, and neither `cat a` nor `cat b` appears in the reason text. This pins TM-1 (no substitution body is rendered) and TM-2 (the decision stays ask, or deny under CLAUDE_BATCH) (TS-1, TS-3; FR1, FR3).
- [ ] AC-3: For `rm -rf $(cat a); rm -rf $(cat b)`, the extracted designations equal exactly [`` 1番目のrmの1番目の対象[`$(...)`] ``, `` 2番目のrmの1番目の対象[`$(...)`] ``] (TS-2; FR2).
- [ ] AC-4: For each of `` rm -rf `cat a` `cat b` ``, `` rm -rf $(cat a) `cat b` `` and `rm -rf <(cat a) <(cat b)`, the decision is ask, the reason ID is rm-unresolvable, and the extracted designations equal exactly [`` 1番目のrmの1番目の対象[`$(...)`] ``, `` 1番目のrmの2番目の対象[`$(...)`] ``]. This pins TM-2 (the decision stays ask) (TS-5, TS-6, TS-7; FR7, FR8, FR9).
- [ ] AC-5: For `rm -rf $(cat a) /tmp/scratch $(cat b)`, the decision is ask, the reason ID is rm-unresolvable, the extracted designations equal exactly [`` 1番目のrmの1番目の対象[`$(...)`] ``, `` 1番目のrmの3番目の対象[`$(...)`] ``], and the text 1番目のrmの2番目の対象 does not appear in the reason text. This pins TM-2 (the decision stays ask) (TS-8; FR10).
- [ ] AC-6: For `rm -rf $(printf MULTISUBBODYALPHA) $(printf MULTISUBBODYBETA)`, the decision is ask, the reason ID is rm-unresolvable, the extracted designations equal exactly [`` 1番目のrmの1番目の対象[`$(...)`] ``, `` 1番目のrmの2番目の対象[`$(...)`] ``], and neither MULTISUBBODYALPHA nor MULTISUBBODYBETA appears in the reason text. This pins TM-1 (no substitution body is rendered) and TM-2 (the decision stays ask) (TS-9; FR11).
- [ ] AC-7: `python3 em-workflow/hooks/tests/run-destructive-guard.py` and `python3 -m unittest discover -s tests` both exit 0 with no pre-existing test file modified (FR4, NFR2). `em-workflow/hooks/destructive-guard.py` is identical to the base commit unless a new test failed on the unmodified hook; in that case the implementation report names the failing test, and the SUBSTITUTION_STANDIN value `$(...)` and the four inert conditions in its comment are unchanged. This pins TM-2 (a hook change keeps both existing suites passing) (TS-4, TS-10, TS-11; FR5, FR6).

## Test Notes

- Every case is an integration test through the hook child process; there is no unit
  test (SPEC.md Test Scenarios). One test method per TS, or a table-driven test with
  one sub-test per TS, is the implementer's choice; a failure message names the TS.
- These tests pin existing behaviour, so they are expected to pass on their first run
  against the unmodified hook (SPEC.md A1, A6). To show they are not vacuous, confirm
  once that a collapsed expectation (a single designation, or the body text being
  present) fails the assertions; that probe is not committed.
- Compare designations as ordered lists, never as sets or counts (NFR4).
- TS-2 pins designations only, because FR2 pins no decision.

## Out of Scope

- Adding cases to `em-workflow/hooks/tests/destructive-guard-cases.json`; that runner
  compares no reason text (SPEC.md A4).
- New notations, such as an occurrence suffix on the stand-in or part of a
  substitution body in the reason text (SPEC.md A2).
- Modifying any existing test file, including
  `tests/test_destructive_guard_rm_reason_positions.py` (FR4).
- Changing SUBSTITUTION_STANDIN or its comment (FR5).
- Changing the hook when every new test passes (FR6).
- Editing `em-workflow/.claude-plugin/plugin.json` or `.claude-plugin/marketplace.json`
  (NFR3).
