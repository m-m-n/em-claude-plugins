# Task Plan: task0005 — Realign README gates and guarantee, and pin them in the doc-contract test

## Goal

`test/README.md` states the Syntax gate as two or more dot-separated
segments, adds the dunder rejection and the new Loader confirmation failure
conditions, and states the non-execution guarantee at the IMPLEMENTATION.md
D1 range; the doc-contract test pins the two-or-more-segment wording and the
guarantee range.

## Requirements

- `tests/test_tests_yaml_id_rules_docs.py` — wording checks for the two-or-more-segment rule and the guarantee range

## Design

README changes (FR6):

- Syntax gate: "one or more dot-separated segments" becomes "two or more
  dot-separated segments", consistent with the existing statement that IDs
  start with `tests.`.
- Structural resolution: adds that a method ID whose last segment is a dunder
  name (for example `__init__`) is rejected as `not a test method`, even when
  the TestCase subclass defines it.
- Loader confirmation: adds two failure conditions for an ID — the loader
  returns something that is not a suite, and an exception is raised while
  walking the returned suite.
- Non-execution guarantee: replaced with the IMPLEMENTATION.md D1 canonical
  statement, verbatim. Any claim that resolved objects are never called or
  instantiated is removed.
- The Test Docs Records section is not touched (SPEC A4).

Doc-contract test (FR7):

- Adds checks that the README contains the two-or-more-segment wording and
  both halves of the D1 statement: test method bodies are never executed;
  Loader confirmation, like ordinary collection, instantiates the test
  classes (including a custom `__init__`) and runs `load_tests` hooks.
- Each check is a predicate over README text, so the same predicate can be
  applied to an in-memory copy with the phrase removed to show that it fails.
- Any existing check that asserts superseded wording is updated here.
