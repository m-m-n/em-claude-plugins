# Task Plan: task0003 — Resolve readable IDs in ACs that have extraction errors

## Goal

check_record resolves every ID read as a single-line scalar from an AC's
tests, even when that AC also has extraction errors (including a duplicated
tests key and a duplicated AC key), and reports extraction and resolution
errors together; elements that are themselves extraction errors are never
resolved. The test that pinned the old behavior is renamed with the inverted
expectation, and the record that names it follows.

## Requirements

FR2, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_tests_yaml_id_resolution.py` — extraction (extract_text and the per-AC loop of check_record), their docstrings and the Extraction section comment, and TestExtractionErrors fixture tests including the FR8 rename
- `test-docs/tests-yaml-test-id-resolution/task0001.tests.yaml` — the AC-2 entry follows the renamed test

## Design

Extraction result per AC:

- Extraction yields two disjoint results per AC: readable IDs (scalars
  complete on one line) and extraction errors (per element).
- An element that produced an extraction error contributes no ID. None of
  the following yields an ID: a mapping element, a nested element, an empty
  element, a multi-line value continuing onto a deeper line (the first-line
  fragment that the base path adds to the IDs is excluded), an unclosed
  quote, a flow-style list that failed to parse (no ID at all is taken from
  it).

check_record (this task owns its loop, IMPLEMENTATION.md Shared Components):

- Resolves every readable ID of every AC, whether or not that AC also has
  extraction errors.
- A duplicated tests key within an AC and a duplicated AC key count as
  extraction errors of that AC (SPEC A2); readable IDs under them are still
  resolved and reported under the AC key's name.
- Returns, per record, one list holding both the extraction errors and the
  resolution errors. Ordering follows the base's existing convention; no new
  sorting rule is introduced.
- Relies on resolve_id never raising (IMPLEMENTATION.md D2), so the loop adds
  no exception handling.

FR8 (the rename and the record change travel together in this task, so the
real-repository per-record test never points at a missing test name):

- TestExtractionErrors.test_an_ac_with_an_extraction_error_gets_no_resolution_errors
  is renamed to a name stating that readable IDs in an AC with extraction
  errors still get resolution errors, and its expectation is inverted.
- In `test-docs/tests-yaml-test-id-resolution/task0001.tests.yaml`, the AC-2
  ID naming the old test is changed to the new name; nothing else in that
  record changes.

Documentation, FR6: the docstrings of extract_text and check_record and the
Extraction section comment next to the extraction code describe the new
behavior. The module docstring is not edited here (IMPLEMENTATION.md D3).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: For a block-form record whose AC tests lists `tests.nope.A.b` and the mapping element `{name: x}`, check_record returns both the mapping element's extraction error and the resolution error for `tests.nope.A.b` (FR2, SPEC AC-2).
- [ ] AC-2: For an AC with a duplicated tests key, and for a record with a duplicated AC key, readable nonexistent IDs used as probes produce resolution errors reported under that AC key's name, alongside the duplicate-key extraction error (FR2).
- [ ] AC-3: For each extraction-error element kind — mapping, nested, empty element, multi-line value continuing onto a deeper line, unclosed quote, failed flow-style list — check_record returns the element's extraction error and no resolution error for any text taken from that element, with probes chosen so that resolving them would produce a resolution error (FR2).
- [ ] AC-4: The old test name no longer exists, and a test under the new name asserts the inverted expectation and passes (FR8).
- [ ] AC-5: The AC-2 entry of `test-docs/tests-yaml-test-id-resolution/task0001.tests.yaml` names the new test instead of the old one, and that record's real-repository per-record test passes (FR8, NFR3).
- [ ] AC-6: The docstrings of extract_text and check_record and the Extraction section comment describe resolution of readable IDs despite extraction errors and the exclusion of error elements (FR6).
- [ ] AC-7: `python3 -m unittest discover -s tests` passes and the checker module imports only standard-library modules (NFR1, NFR2, NFR3).
