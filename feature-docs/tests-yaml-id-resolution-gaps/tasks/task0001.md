# Task Plan: task0001 — Syntax gate rejects IDs with fewer than two segments

## Goal

The Syntax gate rejects every ID with fewer than two dot-separated segments —
in practice the bare `tests` — before any import, and the existing tests that
treated the bare `tests` as a passing ID are corrected.

## Requirements

FR1, FR6, FR7, FR8, NFR1, NFR2, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_tests_yaml_id_resolution.py` — Syntax gate (canonical_id_failure) and its docstring, Syntax-gate fixture tests, and the three existing tests that accept the bare tests ID

## Design

Syntax gate (canonical_id_failure), FR1:

- Adds a segment-count rule: an ID with fewer than two dot-separated segments
  fails with a reason that starts with `not a canonical ID`.
- The rule belongs to the Syntax gate, which runs before Structural
  resolution, so it inherits the gate's existing guarantee: no import happens,
  and the module search path and the module cache are unchanged.
- The rule only removes the single-segment case from the accepted set; every
  ID of two or more segments that passed at base still passes.
- Its docstring states the accepted form as two or more dot-separated
  segments starting with `tests` (FR6). The module docstring is not edited
  here (IMPLEMENTATION.md D3).

Existing tests that encode the old behavior (FR8):

- TestSyntaxGate.test_canonical_ids_pass_the_gate: the bare `tests` leaves
  the passing set; its rejection is asserted in the same class.
- TestResolutionWithoutExecution.PASSING: the bare `tests` is removed; the
  class keeps its purpose with the remaining IDs.
- TestSearchPathAndModuleCache.test_root_is_at_the_front_of_the_search_path_only_for_the_duration_of_the_call:
  switches to an ID of two or more segments that still reaches an import, so
  the "root at the front only during the call" observation is still made. The
  test keeps its name and the property it checks.

Shared contracts used: the Shared Components entries for the checker entry
points, resolve_id and check_record in IMPLEMENTATION.md (signatures and
return shapes unchanged).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: canonical_id_failure returns a reason starting with `not a canonical ID` for the bare `tests` (FR1).
- [ ] AC-2: Every ID of two or more segments that the base Syntax-gate tests accept (module, class and method forms) is still accepted by canonical_id_failure (FR1).
- [ ] AC-3: check_record on a record whose AC-1 lists only the bare `tests` returns an error line naming `tests` with a reason starting with `not a canonical ID`, and the module search path and the module cache are identical before and after the call (FR1, SPEC AC-1).
- [ ] AC-4: TestSyntaxGate.test_canonical_ids_pass_the_gate and TestResolutionWithoutExecution.PASSING no longer treat the bare `tests` as passing, and the TestSearchPathAndModuleCache root-at-front test still observes the root at the front of the search path during an import and its absence after the call (FR8).
- [ ] AC-5: canonical_id_failure's docstring states the two-or-more-segment requirement (FR6).
- [ ] AC-6: `python3 -m unittest discover -s tests` passes and the checker module imports only standard-library modules (NFR1, NFR2).
