### Postconditions this task must make true in every path

The findings show that statement shaping breaks the "Shaped statement" postconditions in the paths listed below. Each path must satisfy all five postconditions.

1. **Payload re-scan (finding `df32e3552c3ee176`).** Deciding whether a statement is a `-c` / eval / here-string invocation, and extracting its payload, uses the shaped statement. That means the command word after grouping, case-pattern, reserved-word and wrapper syntax, not the raw first token. The substitution-marked and quoted-marked parallel token lists that payload extraction also reads must be shaped the same way, so that all three stay aligned token for token. Fused-closer splitting changes token counts. An index computed on one list must not be applied to another list that was split differently. After the change, the `head()` docstring statement that its callers receive tokens with the grouping vocabulary already stripped is true for every caller, or it is reworded to match what is true.
2. **Case item terminators (finding `25f07de01edba472`, lexed part).** A case item ends on `;;`, `;&`, `;;&` and `;|`. This holds whether the terminator shares a line with the body or stands on its own line. A statement with no tokens of its own still has its separator evaluated for case state. After an item ends, the next pattern's text is pattern data, never a command word.
3. **Case recognition is fail-closed (finding `c757b2e569edf076`).** `case` opens a case construct only when it sits at command position with no command wrapper (`command`, `sudo`, `env` and the rest of `WRAPPERS` except `time`) and no VAR=value prefix before it. `time` and `!` are shell keywords and may precede a real `case`. A statement cannot validly end with the pattern state still open when the separator is `;`, `&&`, `||` or `&`. Only `|` (between pattern alternatives) and a newline keep the pattern state open. If any other separator arrives while the pattern is open, the open case frame is discarded, and the statements after it are judged as ordinary commands.
4. **esac inside a pattern (finding `751c5ab440d50b42`).** `esac` ends the case only when it is the first word of a pattern position (right after `in` or after an item terminator) and is not followed by the pattern closer `)`. An `esac` that is a later alternative after `|`, or that is directly followed by `)`, is pattern text. Quoting cannot be told apart at this layer. Reading such a word as pattern text is the stricter direction (IMPLEMENTATION.md Conventions).
5. **Runs of fused closers (finding `b6b2b64d62e8983b`).** An unquoted operator token that starts with a run of `)` is split into one closer per `)`. The remainder after the run is then classified: a real redirect operator stays a redirect, and `(` becomes a subshell opener. Each closer is recognized as a closer in the same way a single `)` already is. That covers the case-pattern closer when the case state expects one, and otherwise a closer that is never an argument or a target.
6. **Redirects around wrappers (finding `b4d16b6b22951280`).** A redirect that sits between a wrapper and that wrapper's options or command word does not stop the wrapper or option skip. The redirect operator and its target are removed from the word sequence before the command word is located, and are still delivered to write-target extraction as redirects. This also covers fd-numbered redirects, which lex as a separate digit token plus the operator (`sudo 2>/dev/null -u root …`, `env 2>/dev/null -u X …`). A redirect target never becomes the command word, an option value, an rm target or a command's destination.
7. **Parse-failure fallback (finding `25f07de01edba472`, merged part).** When a chunk fails to lex and falls back to the regex split, grouping and compound syntax at command position is still removed before the command word is located. That syntax includes an opener fused to the first word (`(rm`) and a closer fused to the last argument (`/home/sakura/x)`). A closer is never an argument there either. Two approaches are acceptable: lex each newline-separated line of the chunk separately and use the lexed path for the lines that parse, or strip the syntax as text on the fallback tokens. Either is fine as long as every row below holds.

### Processing flow (per statement, lexed path)

1. Split fused closer runs and fused closer-redirects into closers, openers and real redirect operators.
2. Separate redirect operators, fd digits and their targets from the words, and keep the redirects for write-target extraction.
3. On the remaining words, run the leading-construct scan, interleaved with the wrapper and assignment skip, updating the chunk's case state under postconditions 2 to 4.
4. Drop closers from the arguments. Hand the shaped words and the kept redirects to every per-statement check.
5. Run payload extraction on the shaped statement, with the marked and quoted-marked parallels shaped identically.
6. Evaluate the statement's separator for case state, even when the statement has no tokens.
