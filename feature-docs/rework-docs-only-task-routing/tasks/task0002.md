# Task Plan: task0002 — rework-planner documents: docs-only scope, write_policy, files rule, doc_corrections

## Goal

The rework-planner agent definition and its contract describe the docs-only correction route from the worker's side: which documents it rewrites directly, how those writes are authorized through `write_policy`, the feature-docs files rule for synthesized tasks, the docs-only patch shape, and the `payload.doc_corrections` declaration.

## Design

Read IMPLEMENTATION.md first: Shared Components "Docs-only correction route", "Route decision order", "Docs-only round", "Mixed round", "`requirements_patch` tests replacement", "`payload.doc_corrections`", "Rename-aware coverage rule" and "Feature-docs files rule". This task owns the prose of `payload.doc_corrections` and of the rename-aware coverage check in the contract; the route itself is owned by `references/rework-task-synthesis.md` (`### Docs-only correction route` in Section 9) and is cited, never restated (NFR4).

### `agents/rework-planner.md`

- Opening paragraph: keep the phrase "you never rewrite the feature's existing plan" (pinned by an existing test) and add one sentence making the docs-only correction route the single exception, citing the route by heading and file.
- Process: before synthesizing, check the route decision order (cite). On the docs-only route, create no task, correct `VERIFICATION.md`, `IMPLEMENTATION.md` and existing `tasks/*.md` directly, change requirement test references through the tests replacement of `references/workflow-patch.md`, and declare each correction in `payload.doc_corrections`. In a mixed round, split within the same dispatch: docs-only items corrected directly, code items synthesized under the existing grouping rule.
- Files rule (FR3): one sentence stating that a synthesized task's `files` never include a path whose first path segment is `feature-docs`, citing `references/rework-task-synthesis.md` Section 7 as the owner.
- Document update scope table: add a row for existing `tasks/*.md` (only through the docs-only correction route); extend the `VERIFICATION.md` and `IMPLEMENTATION.md` conditions with the docs-only route.
- The "Workflow patch, never a direct write" section: add the docs-only round shape (Shared Components "Docs-only round"): still `append` with `expected_next_task_id`, empty entries, only the origin step returned to `pending`, `implement` untouched, `workflow.implement.base_commit` preserved; `rework_index` present as an empty mapping. The existing sentence for rounds with tasks stays.
- Output: name `payload.doc_corrections` and point to the contract for its shape.

### `references/contracts/rework-planner-contract.md`

- Responsibility: add the docs-only correction route as the one case where existing plan documents are rewritten (cite the route).
- Document update scope table section: add the existing `tasks/*.md` row and the docs-only conditions; keep the string `Always created` and the specification-change transition row (both pinned).
- The `write_policy` section: state that each existing `tasks/*.md` a round rewrites is listed in `write_policy.targets` with `action: replace_own`, and none is listed on a round that does not rewrite it — the same treatment the section already gives `VERIFICATION.md` and `IMPLEMENTATION.md`. Then state the alignment with `references/contracts/spec-writer-contract.md`'s `replace_own` ("overwrites the same-phase output the worker itself produced earlier"): the planning documents under `feature-docs/{feature}/` are output of the planning workers (implementation-planner at create-plan, rework-planner at rework), and this contract reads "same-phase output the worker itself produced" as that planning lineage's output — the reading the existing `VERIFICATION.md` / `IMPLEMENTATION.md` precedent already relies on; `expect_digest` handling and the orchestrator's pre-dispatch verification are unchanged (cite `references/artifact-digest.md`). SPEC.md and REQUIREMENTS.md never become targets (TM-6).
- Coverage check 2 of "The validation script (5.11.1) performs these four checks:": amend its wording to the rename-aware coverage rule (an ID outside `verification_index` passes only through a declared `scenario_renames` pair whose `from` is in `verification_index`). Constraints from existing pins: the region from that sentence to the `payload.shared_contract_rationale` heading keeps exactly four numbered items `1.` to `4.`, gains no other numbered list, and the word "baseline" must not appear before item 4.
- New section headed with `payload.doc_corrections`, placed after the `payload.shared_contract_rationale` section and before `## Specification-change transition`: the shape and obligation from Shared Components "`payload.doc_corrections`", including that the origin pair is Invariant 6's (cited). State that the declaration is the traceability record of each docs-only correction (TM-4).
- Do not add anything to `## Gate identifiers` (the validator parses backticked tokens there into its gate registry). Do not introduce the strings `Phase R5` or `reviews/round` anywhere in the contract (pinned absent).
