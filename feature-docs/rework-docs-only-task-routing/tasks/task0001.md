## Design

### New subsection `### Docs-only correction route` (Section 9)

Placed after the whole `### Wording-correction route` subsection and before `## 10. Workflow state transition`. Its content, each item once:

1. **Scope**: a needed change that fails the Wording-correction route's eligibility and is resolved by changing only `VERIFICATION.md`, `IMPLEMENTATION.md`, existing `tasks/*.md` under `feature-docs/{feature}/`, and requirement test references in `workflow.yaml`. A change that needs SPEC.md or REQUIREMENTS.md stays with the SPEC-change transition (Section 10).
2. **Decision order**: Wording-correction route, then this route, then rework-task synthesis / SPEC-change transition.
3. **Result of a docs-only round**: no task is synthesized; the rework-planner corrects the documents itself, as `references/contracts/rework-planner-contract.md` states (cited); requirement test references change through the tests replacement of `references/workflow-patch.md` (cited); the patch returns only the origin step to `pending` (verify for verify-sourced, review for review-sourced). One sentence states in plain words that this route does not return `implement` to `pending`. Invariant 1 is not reworded.
4. **Mixed round**: docs-only items are corrected directly; code items become tasks under Section 4; a round with at least one task returns `implement` and the origin step to `pending` as before; the origin-step-only rule is limited to docs-only rounds.
5. **Declaration**: every correction made through this route is declared in `payload.doc_corrections`, defined in `references/contracts/rework-planner-contract.md` (cited, shape not restated).
6. **Consistency with the specification (TM-7)**: every change this route makes keeps the changed document consistent with SPEC.md and REQUIREMENTS.md, which this route never changes; a correction that would make a scenario or acceptance criterion check less than SPEC.md / REQUIREMENTS.md require is not a docs-only correction and continues to rework-task synthesis or the SPEC-change transition.

Label constraint: the bold labels of the new subsection must differ from the Wording-correction route's labels (`**Eligibility`, `**Outcome when eligible**`, `**Guard**`, `**Ordering**`). The existing test module for that route extracts its blocks from the first occurrence of each label between `### Wording-correction route` and `## 10.`, a range that now also contains the new subsection. The new subsection must also not contain the classification-gate verdict literals, which that same range is checked against.
