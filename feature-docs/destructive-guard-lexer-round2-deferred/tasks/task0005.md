# Task Plan: task0005 — Inspect the content of bash 5.3 `${ cmd; }` / `${| cmd; }` as commands

## Goal

A `${` directly followed by a space, a tab, a newline or `|` opens a
command-form substitution whose content is read and inspected as commands,
as bash 5.3 runs it, instead of a parameter expansion whose content is
never inspected (finding 1fcae1f76f2a20f0). This holds at the top level,
inside double quotes, inside other expansions and at the literal top level
of an unquoted here-document body.

## Requirements

FR7, FR9, FR10, FR11, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6, NFR7

## Scope

None.

- `em-workflow/hooks/tests/destructive-guard-cases.json` — append this task's cases after the last entry.
- `tests/test_destructive_guard_lexer_agreement.py` — a new class and a stage-agreement subclass after the unclosed-openers class, the in-place rewrites named under Design, and the kind constants at the top of the file if they list region kinds.

## Design

Cross-task rules that apply here (IMPLEMENTATION.md): the `${` dispatch
row, the word-level grammar state row (the `}` part), the substitution
regions downstream row (all three owned by this task), the tail gate row
(the command form is never gated), the lexical map row, the pass state row,
the case table append protocol, the test layout row, lexical pin ownership,
the fail-safe direction, the bash confirmation convention, the
existing-cases convention and D4.

### Recognition and region

- `${` directly followed by a space, a tab, a newline or `|` is the command
  form; every other `${` is the parameter form, read exactly as today
  (settle channel included). The decision is made before any settle or
  tail decision, wherever the dollar handling runs: shell-rule frames,
  double quotes, parameter expansions, arithmetic, subscripts and the
  literal top level of a here-document body.
- The command form opens a shell-rule frame whose content starts at a
  command position, as a command substitution's does, and records a region
  of the new kind `brace-command-substitution`. The new kind is a member of
  the substitution kinds (and therefore of the opaque kinds), and is not
  masked.
- It is never settled and never refused: an unclosed one is not listed in
  UNOPENED, sets no tail start, and stays open to the end of the text (or
  of the discarded line, below), like an unclosed command substitution.
  It opens after a tail source as well (D4).

### Close

- A `}` that is a whole word at a reserved-word position (a command
  position: after `;`, `&`, a newline, or at the start of the content)
  closes the innermost command-form frame, unless it closes a `{` brace
  group opened inside that frame. A `}` anywhere else (an argument, inside
  a word, quoted) does not close it.
- A command form opened on a discarded line (an array-direct `<<`) closes
  at that line's newline together with every other open context, as the
  discarded-line rule already does.
- Any field this adds to a frame or to the pass state is classified in the
  resume snapshot (restored or deliberately not restored).

### Downstream (substitution regions row)

- The structure scan treats a closed command-form region as a span; its
  inner text is exactly the characters between the opener (`${`, or `${|`
  for that form) and the closing `}`; it is marked at its level and queued
  as its own chunk, like a command substitution.
- An unclosed command-form region is reported as unmatched, as an unclosed
  command substitution is, and its inner text, from after the opener to the
  end of its extent, is also queued as its own chunk, so `echo ${ rm ...`
  is inspected (SPEC F7). Here-document body extraction does the same for a
  body, reading a `${|` form from after the `|`.
- Deeply nested unclosed forms make each level queue the rest of the text;
  the statement layer's existing relative scan budget turns that into the
  scan-budget ask (deny under `CLAUDE_BATCH`), never into allow and never
  past the hook timeout (NFR2, NFR3).

### Cases (FR9)

Commands in the case table's JSON string notation (`\n` newline). Labels
begin `1fcae1f76f2a20f0 round2-deferred`, then the tag `FR7.1` to `FR7.7`:

1. deny: `echo ${ rm -rf /home/sakura/valuable; }`
2. deny: `echo ${|rm -rf /home/sakura/valuable; }`
3. deny: `echo ${\nrm -rf /home/sakura/valuable\n}`
4. deny: `cat <<E\n${ rm -rf /home/sakura/valuable; }\nE`
5. deny: `echo ${ rm -rf /home/sakura/valuable` (unclosed: bash reports a syntax error; the content is still inspected, SPEC F7)
6. allow: `echo ${x} ${x:-y} ${#x}`
7. allow: `cat <<'E'\n${ rm -rf /home/sakura/valuable; }\nE`

Forms beyond SPEC.md's deny list (double quotes, nested in a parameter
expansion, an inner brace group) are pinned in the agreement test; each is
added to the case table (tags `FR7.8` onward) only when confirmed on bash
5.3 (bash confirmation convention).

### Existing expectations that change (SPEC A8)

In the unclosed-openers class of the agreement test:

- The test that `${ ` repeated 20000 times is settled without a rescan per
  opener (20000 UNOPENED offsets, tail start 0): the input becomes a
  parameter-form opener repeated 20000 times (`${x ` each), so the settle
  path keeps the same assertions; a companion assertion for `${ ` repeated
  20000 times checks linear work, no UNOPENED offset and no tail start.
- The opener list keeps `${` (now nested command forms) and gains the
  parameter-form opener `${x`, so the 60 KB bulk test covers both readings.
- The mixed-unit test and the here-document bodies list are rewritten only
  if a test there fails; their assertions (never allow, within the hook
  timeout, deterministic) are kept.

### Not touched

The tail gate (task0001), subscript reading (task0002), the line index and
close-line rule (task0003), blanks (task0004), the non-adjacent-close
re-reading, and every parameter-form reading.

## Acceptance Criteria (MANDATORY)

Commands use the case table's JSON string notation. "Both modes" means
without `CLAUDE_BATCH` and with `CLAUDE_BATCH=1`. Case numbers refer to the
Cases list under Design.

- [ ] AC-2 (FR7, NFR4, NFR6, TM-7): For cases 1 to 3, `lex_shell()` reports one closed `brace-command-substitution` region from the `${` to the final `}`, no parameter-expansion region, no UNOPENED offset and no tail start; the structure scan reports it as a span whose inner text is exactly the characters between the opener (`${`, or `${|` in case 2) and the final `}`; the map is identical after clearing the lexer cache; each is deny in both modes. For case 4, the here-document body extraction reports one substitution whose inner text is exactly the characters between `${` and `}` on the body line, and the case is deny in both modes.
- [ ] AC-3 (FR7, NFR6, TM-7): `echo "${ rm -rf /home/sakura/valuable; }"` reports the command-form region inside the double-quote region; `echo ${x:-${ rm -rf /home/sakura/valuable; }}` reports it inside the parameter-expansion region; `echo ${ { rm -rf /home/sakura/valuable; }; }` reports one command-form region that closes at the last `}`; all three are deny in both modes.
- [ ] AC-4 (FR7, NFR6, TM-7): For case 5, the command-form region runs to the end of the text, is not closed, is not in UNOPENED, sets no tail start, its inner text is inspected, and the case is deny in both modes. - [ ] AC-5 (FR7, NFR7, FR10): The pre-existing case-table entries labelled `heredoc-syntax-error E-12`, `heredoc-syntax-error T2 AC-5.5` and `heredoc-syntax-error T2 AC-5.7` stay deny; for each, a command form opened on the discarded line closes at that line's newline.
