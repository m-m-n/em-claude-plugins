# Task Plan: task0008 — Judge the safe-delete exception on the target bash receives, trailing `\r` included

## Goal

A `\r` at the end of a delete target is part of the name bash passes to
`rm`, so the safe-delete exception never matches a different name than the
one deleted: `rm -rf build\r` is judged like any other non-safe target, in
whatever way the `\r` was written (unquoted, backslash-escaped or quoted)
and on every tokenizing path (review round 1; finding under Provenance).

## Requirements

FR6, FR9, FR10, FR11, NFR4, NFR5, NFR6, NFR7

## Provenance

- source: review
- review_round: 1
- source_ids: b0f7592cd79e75ea

The trailing-`\r` rule disregards a `\r` at the end of an unquoted word for
all matching, including the safe-delete exception. A backslash-escaped
`\r` (`build\\\r`), an unquoted one (`build\r`) and a quoted one on the
fallback path that loses the quoted attribute all reach the exception as
`build`.

## Design

Cross-task rules that apply here (IMPLEMENTATION.md): the trailing-`\r`

### Rule

- A trailing `\r` is still disregarded when the decision layer matches
  command names, options, reserved words, separators, redirect targets and
  destructive targets, so every verdict that only moves toward ask or deny
  is unchanged.
- The safe-delete exception — the containment predicate over build
  artifacts and scratch roots — and any other decision that turns a delete
  target into an allow, reads the target exactly as bash receives it,
  trailing `\r` included, whether the `\r` was unquoted, escaped with a
  backslash or quoted, and whether the words came from the tokenizer or
  from the fallback word split. A target is therefore safe only if it is
  safe with its `\r`: `build\r` is not the build artifact `build`, while
  `/tmp/x\r` is still a proper descendant of `/tmp`.
- The words the lexer and the tokenizer read, and their offsets, do not
  change.

### Existing expectation that changes

In `TestCarriageReturnIsNotABlank`, the matching-forms entry
`rm -rf ./build\r` changes from allow / allow to deny / deny: bash deletes
`build\r`, not the safe target `build`, and the entry was this feature's
own pin, not a case-table entry (NFR7 holds). Every other matching-forms
entry keeps its expectation.

### Cases (FR9)

Commands in the case table's JSON string notation. Labels begin
`b0f7592cd79e75ea round2-deferred`, then the tag `R1.CR1` to `R1.CR5` in
this order:

1. deny: `rm -rf build\\\r`
2. deny: `rm -rf build\r`
3. deny: `rm -rf \"build\r\"\n'`
4. deny: `rm -rf ./node_modules\r\n`
5. allow: `rm -rf /tmp/x\r`

Cases 1 to 3 are the finding's reproductions; their verdict is the verdict
of the same command with the `\r` replaced by a letter (`rm -rf buildx` is
deny), so they move a decision only toward deny and need no bash
confirmation.

### Not touched

The lexer, the tokenizer, the fallback word split's own reading, and every
matching that only leads to ask or deny.
