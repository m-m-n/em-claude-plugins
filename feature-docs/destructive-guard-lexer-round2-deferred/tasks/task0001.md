# Task Plan: task0001 — One tail gate, and no `${` / `$((` / `$[` / `((` / case pattern state after an unreadable delimiter word

## Goal

After a `<<` whose delimiter word cannot be read (a tail source), no
parameter expansion, arithmetic expansion, bracket arithmetic, arithmetic
command or case pattern state opens, in the lexer or in statement shaping,
so a destructive line bash 5.3 runs is inspected and denied (finding
52bfa0f59d1ea852). Every tail decision of the lexer pass is made by one gate
(the part of finding c8c16caba82d6238 this feature takes).

## Requirements

FR2, FR8, FR9, FR10, FR11, NFR1, NFR4, NFR5, NFR6, NFR7

## Scope

### The tail gate (FR8)

- One function of the lexer pass answers, for an opener kind and its offset,
  whether the opener may open. The kinds and their two classes are those of
  IMPLEMENTATION.md's tail gate row.
- It is the only place in the pass where an opener decision compares an
  offset with the tail start or tests whether a tail source has been met.
  The tail start's own bookkeeping stays as it is: its initial value from the
  settled openers, its update when a tail source is met, and its update at
  the end of a discarded line.
- Every site SPEC.md FR8 lists (quote, `$'`, `$"`, comment, here-document
  operator, discarded-line triggers in an array, the declaration `=(`
  error, the array-element subscript, quote characters inside a parameter
  expansion, arithmetic, bracket arithmetic, subscript and extended-glob
  frame) and the assignment-word subscript start obtain their decision from
  the gate.
- For every kind that exists today, the decision is exactly today's: the
  refactor changes no reading of a pre-existing form.

### New tail-source kinds (FR2, NFR6, SPEC A4)

- Once a tail source has been met, the parameter form of `${`, `$((`, `$[`
  and a `((` at a command position are refused: their characters stay
  literal text, their offset is listed in UNOPENED (D5), and reading goes on
  after them as it does after a settled opener of the same kind (a refused
  `((` leaves the word in progress and ends the command position, as a
  settled `((` does).
- Once a tail source has been met, a `case` word opens no case construct; it
  is read as an ordinary command word.
- Not refused: `$(`, backticks, process substitutions and the command form
  `${ ` / `${|` (D4). The command form is built by task0005; on this branch
  every `${` is the parameter form and is refused after a tail source.
- A tail that comes from settled openers alone (no tail source) keeps
  today's reading of these kinds: they open, and an unclosed one is settled
  as today.

### Statement-level case shaping (FR2)

- `statements()` and the here-document destination table builder obtain the
  chunk's tail start from the lexer's map of that chunk. A statement that
  begins at or after it opens no case construct with `case`: the word is the
  statement's command word. The group-closer mirror of the case state
  follows the same rule. A case construct whose `case` word precedes the
  tail start is opened, read and closed as today.

### Cases (FR9)

Commands in the case table's JSON string notation (`\n` is a newline). Five
deny cases, labels beginning `52bfa0f59d1ea852 round2-deferred FR2.1` to
`FR2.5`:

1. `cat <<E${x}\n${\nE${x}\nrm -rf /home/sakura/valuable\n}`
2. `cat <<E${x}\n$((\nE${x}\nrm -rf /home/sakura/valuable\n))`
3. `cat <<E${x}\n$[\nE${x}\nrm -rf /home/sakura/valuable\n]`
4. `cat <<E${x}\n((\nE${x}\nrm -rf /home/sakura/valuable\n))`
5. `cat <<E${x}\ncase x in\nE${x}\nrm -rf /home/sakura/valuable\nesac`

### Existing expectations that change

- `TestHeredocFallbackAndCloseLines` pins, for
  `cat <<E${x}\n"a\n$'b\n$"c\nrm -rf /home/sakura/valuable\n"`, one
  parameter-expansion region and an UNOPENED list of the quote characters.
  The `${` of `E${x}` lies after the tail source, so the expected regions
  become none and UNOPENED also lists that `${`. Rewritten in place; the
  deny verdict and the masking of the quote characters are unchanged.
- No other existing expectation is expected to change; one that does follows
  IMPLEMENTATION.md's existing-expectations convention.
