# Task Plan: task0002 — Env-route tail rule: locale quotes, split openers, answer kept when the chunk build fails

## Goal

Two gaps between the merged env route and the current FR1 are closed.
Condition (b) of the tail rule is matched on the tail with its line
continuations removed, and it matches `$"` as well as `$'`. And when the
payload's lexer map was obtained but a later step of the chunk build fails, the
rule's answer on that map is kept in the otherwise empty reading. Such commands
get the `args-json-unrestorable` ask, which is a deny in batch, instead of an
allow. Every other verdict stays as it is.

## Design

IMPLEMENTATION.md decisions D1 to D5 apply, and its Shared Components section
holds the full contracts. This section states what changes.

### Tail rule (`_args_json_env_tail_unrestorable()`)

The signature, the `unreadable` precondition, the tail and the purity of the
rule stay as they are. The flow becomes:

1. When `LEX_MAP.unreadable` is not set, the answer is false.
2. TAIL is the raw text of PAYLOAD from the tail start to the end, as today.
3. JOINED is TAIL with every backslash-newline pair removed.
4. (b) When JOINED contains the two characters `$'` or the two characters `$"`,
   the answer is true. Nothing but the line continuations has been removed at
   this point, so a backslash between `$` and a quote character still
   separates them.
5. (a) Otherwise the answer is whether JOINED, with every `'`, `"` and `\`
   character removed, contains `mcp-bridge`. This condition is unchanged.

Postconditions: every tail the rule answered true for before this task is
still answered true, and the cost stays linear in the length of TAIL.

### Env body reading (`_args_json_env_body_reading()`)

The flow becomes:

1. Obtain the payload's map through the lexer call the chunk build makes (the
   payload text, shell mode, the setting in force). When that call raises
   LexBudgetExceeded, LexUnmatchedSubscript included, the reading is the empty
   reading, as today: the rule is not asked and nothing propagates.
2. Evaluate the tail rule on the map. Its answer is the reading's starting
   value of Unrestorable.
3. Build the payload chunk as today (`_args_json_payload_chunk()`, two
   arguments). The lexer's cache returns the map of step 1 inside it. When the
   chunk is None, return a reading with no entries, no Overrun, and Unrestorable
   set to the answer of step 2.
4. Read the lifted notion statements as today, their Unrestorable ORed in. An
   exception of the statement loop propagates unchanged, as today.

Postconditions: the only new result is the one of step 3 with a true answer.
The lexer call of step 1 reports the same facts the chunk build's call reports,
so it changes neither the flags left after the readings nor whether the second
reading runs. A payload that cannot be lexed is lexed once per reading, not
twice.

## Test Notes

- **The one existing test to update**:
  `test_the_rule_is_not_asked_when_the_chunk_cannot_be_built` in
  `TestEnvBodyReading` makes the chunk builder answer None for a payload whose
  map is available, and expects the rule not to be asked. Its setup changes to
  the map-unavailable case (the lexer raises for the payload's text, so the
  chunk cannot be built either); its two assertions (the empty reading, the
  rule not asked) stay. It keeps its name, because the merged test record under
  `test-docs/` names it. The opposite case (chunk builder answers None, map
  available) becomes a new test of TS-19.
- **Other existing assertions**: none contradicts the two changes, so none is
  updated. Every payload an existing test expects to be restorable either has a
  map whose `unreadable` is not set, or has a tail that holds neither `$'` nor
  `$"` once the line continuations are removed. If one is found to fail, that
  is a plan deviation to report, not a reason to edit the assertion.
- **Order (TDD, `.claude/rules/hook-tests.md`)**: add the cases and unit tests
  first and run them on the unmodified hook. The three TS-4 cases must fail
  there (allow); one that already passes is not reaching the env route, or its
  tail holds another trigger, and is rewritten until it fails. TS-21 may pass
  there, because array subscripts do not open in the unread tail, so it is
  recorded and need not be red. The red state of the kept answer comes from the
  TS-19 unit tests.
- **Payload quoting**: the env route reads a payload only when the payload
  word is statically restorable. A double-quoted payload makes `${tag}` an
  expansion, so the route never reads it. TS-4 (d), (e) and TS-21 hold no
  single quote and fit in a single-quoted payload as they are. TS-4 (f) holds
  single quotes: join single-quoted runs with backslash-escaped `'` outside
  quotes, as the existing ANSI-C TS-4 case does. The payload text of (e) and
  (f) must not hold `$"` or `$'` without the continuation, and no other quote
  character may directly follow a `$` anywhere in the tail.
- **TS-17** extends the class that tests the predicate (`TestTailRule`), with
  maps made by the lexer for hand-written payloads, as the existing tests do.
- **TS-18** extends the env body reading tests. Adding the three bodies to the
  module's list of unreadable bodies makes the existing loops over that list
  cover them.
- **TS-19** makes a step of the chunk build after the map fail (for example the
  structural scan of the payload's stripped text), limited to the payload, with
  the statement and its enclosing chunk built beforehand, so the failure never
  reaches the outer command. One test instead makes the chunk builder answer
  None. The flag tests go through the route, where the save and restore is.
- **TS-20** makes the lexer raise for the payload's text only, and raise the
  flags before it does, like the early-return test of
  `tests/test_destructive_guard_env_route.py`.
- **Module docstring**: the sentence that says the rule looks for the
  `mcp-bridge` word or `$'` is brought in line, and TS-17 to TS-20 and this
  task are named.
- No test creates CPU load; every test is a single static analysis call.
