# Task Plan: task0001 — Env-route tail rule for unreadable heredoc delimiters

## Goal

On the env route of destructive-guard, a `bash -c` payload is reported as
unrestorable when its here-document delimiter word cannot be read and its
unread tail holds the `mcp-bridge` word (also when split by quotes or a line
continuation) or `$'`. Such a command then gets the `args-json-unrestorable`
ask, which is a deny in batch, instead of an allow. Benign env-route bodies
keep their current verdicts.

## Design

IMPLEMENTATION.md decisions D1 to D4 apply. This section states the task's
own contracts.

### Tail rule (new module-level predicate)

Signature: `_args_json_env_tail_unrestorable(payload, lex_map) -> bool`.

- **Inputs**: PAYLOAD is the text of the `bash -c` payload the env route
  reads. LEX_MAP is the map `lex_shell()` returns for PAYLOAD in shell mode
  under the extglob setting in force, which is the map the reading's chunk was
  built from.
- **Result**: true exactly when `LEX_MAP.unreadable` is set and TAIL meets
  condition (a) or condition (b).
  - TAIL is the raw text of PAYLOAD from `LEX_MAP.tail_start` to its end. An
    absent tail start, which A4 says does not occur when `unreadable` is set,
    reads as the start of PAYLOAD.
  - (a) Remove every backslash-newline pair (line continuation) from TAIL,
    then remove every `'`, `"` and `\` character from what is left. The result
    contains `mcp-bridge` as a substring. The order is fixed: continuations
    first, then the quote and backslash characters.
  - (b) TAIL contains the two characters `$'`.
- **No other reading**: no expansion is evaluated, so a name that becomes
  `mcp-bridge` only after expansion (`${a}cp-bridge`, `$(printf ...)`) does
  not match (A3). Text before the tail start is never examined.
- **Purity**: it lexes nothing, reads no module state, raises no flag and has
  no side effect. Its cost is linear in the length of TAIL.

### Env body reading (`_args_json_env_body_reading()`)

1. Build the payload chunk as today (`_args_json_payload_chunk()`). When the
   chunk is None, return the empty reading as today; the tail rule is not
   evaluated.
2. Obtain the payload's map through the same lexer call the chunk build makes
   (the payload text, shell mode, the setting in force). The lexer's cache
   returns the map the chunk build made, so the payload is not lexed again.
   Evaluate the tail rule on it. Its answer is the reading's starting value of
   Unrestorable.
3. Read the lifted notion statements as today. Their Unrestorable is ORed
   into the reading's Unrestorable.
4. Return the reading. The tail rule does not change its entries or its
   Overrun.

The tail rule runs before the statement loop, so a LexBudgetExceeded raised
by the loop propagates unchanged, as today. `_args_json_payload_chunk()`
keeps its signature and its result, because existing tests call it directly.

### Left as it is

- `_args_json_env_body_readings()`: the save and restore of the three lexer
  flags and the decision to make a second reading (FR3, A5). The lexer call in
  step 2 returns a map whose facts the chunk build already reported, so it
  changes neither the flags left after the readings nor whether the second
  reading runs.
- `_args_json_env_combine()`: it already ORs Unrestorable over the readings
  (FR2).
- `_queue_args_json_chunks()` and `_DeferredAsks`: an unrestorable result is
  held as the `args-json-unrestorable` ask. A deny outranks it, and the
  scan-budget ask outranks it (NFR2). The reason id and the reason text stay
  as they are.
- Every path outside the env route (NFR1).

## Test Notes

- **Order (TDD, `.claude/rules/hook-tests.md`)**: add the cases first and run
  the runner on the unmodified hook. The TS-1 to TS-4, TS-7 and TS-15 cases
  must fail there (allow); a case that already passes is not reaching the env
  route and is rewritten until it fails. Record the verdicts of the TS-6 and
  TS-14 commands on the unmodified hook before writing those two cases.
- **Payload quoting**: the env route reads a payload only when the payload
  word is statically restorable. A double-quoted payload makes `${tag}` an
  expansion, so the route never reads it. For TS-4 (c), whose body holds
  single quotes, join single-quoted runs with backslash-escaped `'` and `$`
  outside quotes, or write the payload in ANSI-C quoting. TS-4 (b) holds a
  backslash followed by a newline inside the single-quoted payload.
- **Unit tests (TS-9 to TS-12)** load the hook as IMPLEMENTATION.md
  Conventions states, with a module of their own, and restore every state a
  test sets. TS-9 calls the predicate with maps made by `lex_shell()` for
  hand-written payloads. TS-10 drives the env body reading through
  `_args_json_env_payload_values()` or `_args_json_env_body_reading()`.
  TS-11 uses a body with an extended-pattern parenthesis inside an array (so
  that two readings run) and patches the predicate to answer true under one
  setting only; the reading looks the predicate up at call time, so the patch
  takes effect. TS-12 repeats the eight-entry-state pattern of
  `tests/test_destructive_guard_env_route.py` on a body that fires the rule.
- No test creates CPU load; every test is a single static analysis call.
