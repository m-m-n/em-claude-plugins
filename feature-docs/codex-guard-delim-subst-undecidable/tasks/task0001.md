# Task Plan: task0001 — Shared substitution skip: same-line heredoc, command-position arithmetic, word parentheses

## Goal

The guard's shared substitution skip reads a `$( ... )` that contains a
same-line `<<`, a command-position `((`, or a parenthesis inside an argument
word to the same closing position zsh uses, so a heredoc delimiter `${ ... }`
holding such a substitution no longer makes the guard silent and the
`python3 -i` after the terminator line is denied in both copies.

## Requirements

## Design

All changes live in the shared substitution skip (`_skip_substitution`) and
helper methods reachable from it. The call-structure invariant in
IMPLEMENTATION.md (Conventions, Call structure) holds for every new helper.
The readings below are the ones SPEC.md fixes (A4, A5, A6); the zsh 5.9
measurements in SPEC.md are the reference behavior.

### 1. Same-line heredoc operator inside a substitution (FR1)

Flow, inside the skip, outside any case statement:

1. An unquoted `<<` that is not `<<<` marks the substitution frame it appears
   in as having a pending heredoc, instead of returning undecidable at once.
   The operand word after the operator (including the `<<-` form) is read as
   an ordinary word.
2. While any open substitution frame has a pending heredoc, an unquoted
   newline (in any context, word-parenthesis context included) makes the
   reading undecidable, as today.
3. When that frame's closing `)` is reached with the mark still pending, the
   mark is dropped and the frame closes at the same position it would close
   without the operator. No heredoc body is read.

Unchanged: a `<<` in a case statement's subject, pattern or item body stays
undecidable; `<<<` is not a heredoc. The decision is made inside the single
forward pass (a mark plus a newline check), never by re-scanning ahead from
each `<<`. Because double-quoted `$( ... )` and the unquoted `$( ... )` inside
a delimiter `${ ... }` both go through this skip, the reading applies to both.

### 2. Command-position `((` (FR2)

1. At command position (including the word position right after `for`), two
   adjacent opening parentheses with nothing between them open an arithmetic
   frame. Parentheses separated by whitespace are not this form and keep the
   current reading.
2. Inside the arithmetic frame, `<<` is a shift operator, not a heredoc;
   nested parentheses are counted; quotes and nested expansions are tracked as
   in other contexts.
3. If the frame ends with `))`, it closes; the enclosing list is then at
   command position, keeping the current close_command meaning.
4. If the matching close is not `))`, everything read since that `((` is
   discarded and the reader restarts at that `((`, reading it as two nested
   subshells (the current reading), so the result equals today's result.
5. Each `((` gets at most one such fallback re-read. The total number of
   characters re-read within one call is bounded by a named limit; once the
   limit would be exceeded, the reading is undecidable. The limit's value is
   the implementer's choice, stated in the docstring, and keeps total work
   linear in input length.
6. The arithmetic frame and the fallback use the reader's existing explicit
   stack; nothing recurses.

### 3. Parenthesis inside an argument word (FR3)

1. A `(` that is not at command position — in the middle of a word, or at the
   start of a word in argument position — opens a new word-parenthesis frame.
   This is a new context kind; the existing w context is not reused (it reads
   `#` as a comment).
2. Inside the frame: words never reach command position, so case, the closing
   keywords and function heads are not recognized; `#` is a word character;
   `;`, `&`, `|` and newline are word characters and are neither separators
   nor undecidable; quotes, backslash pairs, `$( )`, `$(( ))`, `${ }` and
   backquotes are tracked as in other contexts.
3. A nested `(` opens a nested frame of the same kind; `)` closes the
   innermost one. When the outermost frame closes, the enclosing list resumes
   in the state it had before the `(`, still inside the same word.
4. Unchanged readings: `(` at command position (subshell), `<(`, `>(`, `=(`,
   a function head `name()` in command position, and the word list of
   `for name (words)` (w context).

### 4. Docstring (FR6)

The skip's docstring (and the module docstring where it states the same rule)
describes readings 1-3. The phrase "a heredoc anywhere in the chunk (item
bodies included)" stays, scoped to heredocs inside a case statement. Wording
that says a heredoc is always undecidable is removed. When a phrase pinned by
the documentation test (its undecidable and rule marker lists) changes, the
test's marker text changes in the same edit.

### 5. Two copies (FR4) and version (NFR4)

The em-workflow copy is edited and the em-review copy is made byte-identical
to it in the same change. Neither plugin's `plugin.json` nor the root
marketplace file is touched.
