# Task Plan: task0001 — `reproduction` in the review output schemas, protocols and SCA scanner

## Goal

Both plugins' reviewer output schema requires a nullable `reproduction` field on
every finding, both review protocols state its value rules, and the
dependency-vulnerability scanner emits it, with the existing pinned tests kept
in line.

## Requirements

FR1, FR3, FR10, FR12, NFR5

## Scope

### Files to Create
- `tests/test_reproduction_output_contract.py` — tests for AC-1 to AC-4 across both plugins.

### Files to Modify
- `em-workflow/references/review-output-schema.json` — add the `reproduction` property and its `required` entry.
- `em-review/references/review-output-schema.json` — the same addition.
- `em-workflow/references/review-protocol.md` — Output Schema section: example and rules.
- `em-review/references/review-protocol.md` — Output Schema section: example and rules.
- `em-workflow/scripts/scan-dependencies.py` — the finding builder `_build_finding` emits `reproduction` as null.
- `tests/test_reviewer_roles_protocol.py` — `FROZEN_FINDING_REQUIRED` and the Output Schema section digest.
- `tests/test_sca_axis_schema_enums.py` — `EXPECTED_FINDING_REQUIRED`.

## Design

Contract source: IMPLEMENTATION.md Shared Components rows
"`finding.reproduction` field" and "Reproduction value rules". This task
defines the field; it implements no aggregation and no verification.

### Schemas (both files)

- The finding object gains a property `reproduction` placed after
  `suggestion`. It accepts a string or null, written in the same any-of form
  the file already uses for `line` and `skip_reason`.
- Finding `required` becomes the existing eight names in their existing order
  followed by `reproduction`.
- Everything else stays byte-for-byte: root `required`, both
  `additionalProperties: false` flags, the severity enum, the category enum and
  the root source enum. The two files keep their existing differences (em-review
  has narrower category and source enums); the added property line and required
  entry are identical in both.

### Review protocols (both files, Output Schema section only)

- The example finding object shows `reproduction` after `suggestion`.
- The Rules list states:
  1. `reproduction` is one of the finding fields that must always be present.
  2. For the security perspective: steps that reproduce the finding, or an
     equivalent confirmation method, naming the input, the path by which it
     reaches the code, and the observable result; null only when neither can be
     given. What exactly to write is detailed by the perspective skill.
  3. For every other perspective: always null.
  4. An empty or whitespace-only string is treated as null (no steps).
- No other section changes: Inputs, Step 0, Review Target Resolution,
  Path-List Validation, Investigation Budget, Severity, the `suggestion` format
  subsection's content, Round Continuity, Skip Semantics, Read-only Constraint
  and Untrusted-Input Handling stay as they are.

### Scanner

`_build_finding` returns every finding with `reproduction` set to null; nothing
else in its output changes. The vulnerability axis is a non-security
perspective, so the value is always null. The `file-tasks` path reads only a
finding's title and needs no change; findings without `reproduction` (older
inputs) remain accepted there.

### Pinned tests

- `FROZEN_FINDING_REQUIRED` and `EXPECTED_FINDING_REQUIRED` become the
  nine-name list.
- The em-workflow Output Schema section digest in
  `tests/test_reviewer_roles_protocol.py` is recomputed from the edited file and
  replaced in place, with a refresh comment naming this feature (IMPLEMENTATION.md
  Conventions: the count of 64-digit hex constants stays the same).

## Test Notes

- AC-1 / AC-2: compare lists by full equality, not membership, so a
  replacement is caught. Pre-change baselines are the values in the current
  files: em-workflow category enum has seven values (including `license` and
  `vulnerability`) and source has four (including `tool`); em-review category
  has five and source has three.
- AC-3: scope phrase checks to the text between the `## Output Schema` heading
  and the next `## ` heading, whitespace-normalized. The em-workflow protocol is
  scanned by `tests/test_reviewer_roles_protocol.py` for forbidden framing
  phrases ("second opinion", "cross-model check", "agreement partner",
  "cross-validation partner", "agreement source", "cross-model reviewer"); new
  text contains none of them.
- AC-4: load the script from its path the way the existing SCA tests do and call
  the finding builder directly with representative arguments. The schema-driven
  SCA tests (`test_sca_scan_execution.py`, `test_sca_scan_normalization.py`,
  `test_sca_per_project_scan_binding.py`, `test_sca_go_govulncheck_real_output.py`)
  read the schema dynamically and are the regression check that schema and
  scanner change together.
- Self-check: a forged schema lacking `reproduction` in `required` fails the
  AC-1 assertion.
