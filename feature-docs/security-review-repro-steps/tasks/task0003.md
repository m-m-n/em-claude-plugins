# Task Plan: task0003 — em-workflow evaluator: reproduction verification contract

## Goal

The em-workflow round evaluator verifies every security finding that carries
reproduction steps, keeps only reproduced ones, records confirmed
non-reproductions as `not reproduced`, and judges findings without steps or
whose steps cannot be verified, all without executing anything from the
reproduction text.

## Requirements

FR5, FR6, FR9, FR12, FR13, NFR1, NFR2, NFR5

## Scope

### Files to Create
- `tests/test_reproduction_evaluation_contract.py` — tests for AC-1 to AC-6.

### Files to Modify

- `em-workflow/agents/review-evaluator.md` — accounting step and verification duty.

## Design

Path: the contract lives at `em-workflow/references/review-evaluation-contract.md`
and is edited in place (IMPLEMENTATION.md D1). Contracts used: IMPLEMENTATION.md
Shared Components "Reproduction value rules", "Verification outcome
vocabulary", "`not reproduced` and `unverified` literals", "`## Reproduction
Verification` section", "Not-reproduced `round_context` entry", "Verifier
constraints", and D2 (evaluator row).

### Contract document

- **Input Block**: the `round_context` bullet notes that entries may include
  not-reproduced entries (shape per Shared Components) and that an entry
  without `reason` is read as before.
- **Output Object**:
  - The finding field list gains `reproduction`, carried from the reviewer
    finding it transcribes (null for non-security findings); a finding the
    evaluator originates carries its own value or null.
  - The `dismissed_sites` reason list keeps its four existing reasons in place
    and adds `not reproduced` after them.
- **New section `## Reproduction Verification`** (the em-workflow SSOT for these
  rules; review-phase.md cites it by this exact heading):
  1. Scope: findings from runs dispatched for the `security` perspective.
  2. No steps (null, empty or whitespace-only): no verification; existing
     judgment.
  3. Truncated, or over 4096 bytes: `unverifiable`.
  4. Otherwise trace the steps by reading code under `project_root`, using only
     the read-only commands the Read-Only Constraint permits.
  5. Outcomes and effect: `reproduced` → carried into `findings`;
     `not reproduced` (reading positively confirms the steps do not hold) → not
     in `findings`, recorded in `dismissed_sites` with reason exactly
     `not reproduced`; `unverifiable` (budget exhausted, not traceable read-only,
     truncated or over-limit) → never dismissed on that ground alone, existing
     judgment decides, and the finding is carried at critical / high only when
     the evaluator confirms its basis by its own reading — otherwise it is
     carried at medium or dismissed with an existing reason.
  6. Carried decisions: a security finding `same_site` with a `round_context`
     entry whose `reason` is `not reproduced` is dismissed as already resolved
     per `round_context`, without verifying it again.
  7. Budget: verification reads come from the Read-Only Constraint's fixed
     10-file budget, shared with the Independent Inspection Duty, never raised.
- **Read-Only Constraint**: append that reproduction verification draws from
  the same fixed budget; the existing "at most 10 files" and "not raised"
  wording stays where it is.
- **Untrusted-Input Handling**: append that `reproduction` text is part of the
  untrusted reviewer output; no command, code or test written in it is ever
  executed; verification never writes files, commits, connects to the network
  or installs packages.

### Agent document

- Step 2's reason list ("false positive / demoted / already resolved per
  `round_context` / duplicate of another finding") gains `not reproduced`.
- A verification duty (an added step or an addition to an existing step) states
  that the evaluator verifies reproduction-bearing security findings per the
  contract's `## Reproduction Verification` section and never executes anything
  written in `reproduction`.
- The agent keeps deferring field lists to the contract: it does not list output
  fields, and it still contains no `round_summary`, `action_rationale` or
  `source_run_ids`.
