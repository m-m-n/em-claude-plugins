# Task Plan: task0002 — Reproduction instructions in the review-security skills and codex-reviewer briefs

## Goal

Security-perspective reviewers in both plugins, Claude and Codex alike, are told
to write reproduction steps or an equivalent confirmation method into each
finding's `reproduction`, and the codex-reviewer carries that instruction into
the prompt it sends to Codex.

## Requirements

FR2, FR4, FR12, NFR5

## Scope

### Files to Create
- `tests/test_reproduction_reviewer_instructions.py` — tests for AC-1 to AC-5.

### Files to Modify
- `em-workflow/skills/review-security/SKILL.md` — new "## reproduction" section after the "## category" section.
- `em-review/skills/review-security/SKILL.md` — the same section, identical text.
- `em-workflow/agents/codex-reviewer.md` — Step 2 brief range and the Step 4 task-block description.
- `em-review/agents/codex-reviewer.md` — the same two changes.
- `tests/test_reviewer_roles_protocol.py` — refresh the em-workflow codex-reviewer step digest.

## Design

Value rules come from IMPLEMENTATION.md Shared Components "Reproduction value
rules"; this task only instructs reviewers.

### review-security skills (both)

- A new section whose heading line is exactly `## reproduction`, placed after
  the `## category` section, as the last section of the file.
- It instructs, for every security finding, writing into `reproduction` the
  steps that reproduce it or an equivalent confirmation method, naming
  concretely the input, the path by which that input reaches the vulnerable
  code, and the observable result.
- It states that `reproduction` is null only when neither steps nor a
  confirmation method can be given.
- Everything before the new heading (frontmatter, title, the "What to flag",
  "What NOT to flag" and `## category` sections) stays byte-identical. The new
  section text is identical in the two plugins.

### codex-reviewer agents (both)

- Step 2: the perspective brief extracted from the loaded skill is the "What to
  flag" / "What NOT to flag" content plus the skill's `## reproduction` section
  when the skill has one (only the security skill does).
- Step 4: the `<task>` bullet states that the brief's reproduction instructions,
  when present, are part of the `<task>` block.
- Unchanged: frontmatter, description, the opening body sentence, Steps 0, 1,
  3, 5 and 6, the temp-file discipline section, and every existing sentence of
  Step 4 (new words are added, nothing is reworded).
- `tests/test_reviewer_roles_protocol.py`: the em-workflow codex-reviewer digest
  (from the Step 0 heading to end of file) is recomputed and replaced in place
  with a refresh comment naming this feature; the count of 64-digit hex
  constants stays the same.

(TS3)

- [ ] AC-3: In each skill, all text before the `## reproduction` line is byte-identical to its pre-change content, and the `## reproduction` section text is identical between the two plugins; `tests/test_threat_model_review_security.py` passes unchanged. (TS3)
- [ ] AC-4: In both `codex-reviewer.md` files, Step 2 includes the skill's `## reproduction` section in the perspective brief when present, and Step 4's `<task>` bullet states that the reproduction instructions are part of the prompt. (TS5)
- [ ] AC-5: In both `codex-reviewer.md` files, the frontmatter, the description, the opening body sentence and every step other than Steps 2 and 4 are byte-identical to their pre-change content; the em-workflow codex-reviewer step digest in `tests/test_reviewer_roles_protocol.py` is replaced in place; the existing codex-reviewer tests (`test_codex_reviewer_temp_file_isolation.py`, `test_codex_reviewer_interactive_guidance.py`, `test_threat_model_reviewer_inputs.py`) pass unchanged.
- [ ] AC-6: `tests/test_reproduction_reviewer_instructions.py` imports only standard-library modules, and `python3 -m unittest discover -s tests` passes. (NFR5)

## Test Notes

- AC-1 / AC-2: locate the section from the `## reproduction` line to end of
  file; whitespace-normalize before phrase checks.
- AC-3 / AC-5: the byte-identity checks compare against digests computed once
  from the pre-edit files (the existing suite's convention), scoped to the
  unchanged ranges (for the skill: start of file up to the new heading; for the
  agents: frontmatter, opening prose, and each unchanged step).
- AC-4: scope checks to the Step 2 section and to Step 4's `<task>` bullet
  respectively, so the same words elsewhere cannot satisfy them.
- Self-check: a forged skill text that places the new section before
  `## category` fails AC-1.

## Out of Scope

- The schema, protocol and scanner changes (`reproduction` field definition).
- Any verification of `reproduction`, round records, review-phase documents.
- The non-security perspective skills (they produce null per the protocol and
  need no section).
- The Claude reviewer agent (it loads the whole skill already).
