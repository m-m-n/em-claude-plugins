# Task Plan: task0006 — Keep and verify every distinct reproduction on same-site merge (both review phases)

## Goal

When same-site findings are merged, a correct short `reproduction` is no longer
lost behind a longer wrong one: both review phases keep a bounded set of
distinct non-null values, verify every kept value, and decline a finding as
`not reproduced` only when all kept values fail and nothing was dropped.

### Dedupe merge (em-workflow Phase R3b, em-review Phase R3 and the R4 re-aggregation)

The existing merge text stays as it is. New sentences next to it state the
"Merged reproduction set" rule:

- `reproduction` keeps the longest non-null value (unchanged).
- `reproduction_alternates` holds the other distinct non-null values. Distinct
  means not byte-identical after the per-finding cap and normalization step
  (em-workflow R3b step 4, em-review R3 step 6). Order: byte length descending,
  ties in merge order. At most 2 entries.
- `reproduction_overflow` is true exactly when the merged findings carried more
  than 3 distinct non-null values; values beyond the 3 kept are dropped.
- A finding that merged with nothing has `reproduction_alternates` empty and
  `reproduction_overflow` false.

### Reproduction verification (both documents)

The existing verification paragraph gains the finding-level rule over the kept
values (`reproduction` plus every `reproduction_alternates` value):

- `reproduced` when at least one kept value is reproduced; verification may stop
  at the first value that is reproduced.
- `not reproduced` only when every kept value is positively confirmed not to
  hold and `reproduction_overflow` is false.
- Otherwise `unverifiable`. Overflow is never grounds for `declined` as
  `not reproduced`.
- The effects of each outcome stay as D2 states them.
- Each document states the worked case in one sentence: a short value that
  holds, merged with a longer value that does not, makes the finding
  `reproduced` and it stays a target.
- The verifier constraints already stated for `reproduction` explicitly cover
  `reproduction_alternates` (untrusted, nothing executed, read-only).
