# Task Plan: task0001 — Per-shell reading of delimiter `${ ... }` ranges in nested -c strings

## Goal

After this task, three readings hold in both copies of codex-hook-interactive-guard:

- A nested `-c` string held by bash registers its heredoc delimiter's `${ ... }` ranges in the bash form.
- A string held by sh or ksh is read under both forms, and the guard denies when either reading denies.
- Every other reading stays as it is today.

Regression rows and tests pin all three.

### Processing flow: the parse driver

1. Look up the parser switches for the kind, as today, and the delimiter rule for the reading.
2. If the reading is the bash form or quote removal, run the single-reading procedure with that rule. It returns or raises exactly as today.
3. If the reading is "both", run the procedure with the bash form (reading A). Keep its outcome, whether any of its parsers recorded "differs", and whether any of its parsers ended in an exception other than `_Undecidable`.
4. Apply the skip condition of D3. If reading B is not skipped, run the procedure with quote removal and keep its outcome.
5. Combine the outcomes by D3 and return or raise the result.

The single-reading procedure builds its parsers through the module's `_Parser` name, looked up at call time, so a test that swaps that name in the module namespace still sees every parser the driver builds (TestRereadFallback).
