# Task Plan: task0001 — Anchor start-time identity check in the TTY reaper

## Goal

The reaper stops nothing when the anchor seen during the ancestor-chain read
and the anchor PID's entry in the snapshot cannot be confirmed as the same
process, and keeps stopping its targets as before when they are the same
process. Both script copies stay byte-identical, and regression tests pin
the behaviour.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/scripts/codex-hook-tty-reaper.py` — add the anchor identity check and describe it in the module docstring Flow
- `em-review/scripts/codex-hook-tty-reaper.py` — made byte-identical to the em-workflow copy in the same commit
- `tests/test_codex_hook_tty_reaper.py` — add the regression tests for the anchor identity check

## Design

### Where the check sits (flow of the reap routine)

1. Ancestor-chain read: confirms the anchor is an ancestor of the hook
   (unchanged), and also yields the anchor's start time as read during that
   same walk.
2. Snapshot: taken as today (unchanged).
3. Anchor identity check (new): look up the anchor PID in the snapshot.
   - The entry exists and its start time equals the recorded start time
     exactly → continue to step 4.
   - Otherwise (the start times differ by any amount, one tick included; or
     the snapshot has no entry for the anchor PID) → stop nothing: open no
     pidfd, send no SIGTERM and no SIGKILL, and return to the normal
     exit-0, no-output path.
4. Existing target selection and stopping (unchanged).

### Contract of the start-time carrier

- Precondition: the ancestor-chain read succeeded (when it does not, the run
  already stops nothing, as today).
- Postcondition: the reap routine holds the anchor start time from the same
  read that established the ancestor chain. A second, later read of the
  anchor is never used as the recorded value (FR1).
- How the value leaves the ancestor-chain read is the implementer's choice,
  constrained by NFR3: existing tests that call or inspect the
  ancestor-chain read (TestAncestorChainRule and any other) pass unchanged.

### Identity rule

- Identity means: same PID and equal start time. The parent PID is not part
  of identity — an anchor whose ppid alone changed is the same process.
- The check looks at the anchor only. A process between the anchor and the
  hook that exited during the run (absent from the snapshot) does not affect
  the check; the hook's own reachability from the anchor in the snapshot is
  not required.

### Module docstring

- The Flow describes the anchor identity check at the point where it runs,
  within the existing 10 steps (no step added or removed).
- The step 4 and step 6 wording that TestModuleDocstring pins is kept
  verbatim.

### Copies

- The em-workflow copy is edited; the em-review copy is made byte-identical
  to it in the same commit (FR2).

### Constraints

- Standard library only (NFR1).
- Exit code 0 and nothing on stdout / stderr on every path, the mismatch
  and anchor-absent paths included (NFR2).
- No PID-addressed signal delivery is added; every signal keeps going
  through the existing pidfd path (NFR4, THREAT-MODEL.md TM-2).
- THREAT-MODEL.md TM-1 is the mitigation this task implements through
  AC-1, AC-2 and AC-3.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-1; FR1, FR4): In an in-process regression test, after the
  ancestor-chain read and before the snapshot, the anchor PID's entry is
  replaced by a process X whose start time is later than the anchor's, and
  a descendant of X that started after X has stdin on `/dev/pts/*`. No
  SIGTERM and no SIGKILL is recorded and no pidfd is opened (`world.sent`
  and `world.open_calls` are empty). This test fails when run against the
  pre-fix script.
- [ ] AC-2 (TM-1; FR1, FR4): With the same layout as AC-1 and X's start
  time exactly one tick after the anchor's, no signal is recorded and no
  pidfd is opened.
- [ ] AC-3 (TM-1; FR1, NFR2): When the snapshot has no entry for the anchor
  PID, no signal is recorded and no pidfd is opened. On this path and on the
  AC-1 path, the hook's entry point ends with exit code 0 and writes nothing
  to stdout or stderr.
- [ ] AC-4 (FR1, NFR3): When only the anchor's ppid changes between the
  ancestor-chain read and the snapshot (start time unchanged), the anchor's
  descendant whose stdin is on `/dev/pts/*` is stopped as before.
- [ ] AC-5 (FR1): When a process between the anchor and the hook is absent
  from the snapshot (it exited during the run) and the anchor's start time
  matches, the anchor's descendant whose stdin is on `/dev/pts/*` is still
  stopped.
- [ ] AC-6 (FR2, FR3): The module docstring's Flow describes the anchor
  identity check, still has 10 steps and keeps the pinned step 4 / step 6
  wording (TestModuleDocstring passes), and the two copies are
  byte-identical (TestCopies passes).
- [ ] AC-7 (TM-2; NFR1, NFR3, NFR4): The diff of both copies against the
  base adds no PID-addressed signal delivery and no import outside the
  standard library; no existing test case is changed; and both
  `python3 -m unittest tests.test_codex_hook_tty_reaper` and
  `python3 -m unittest discover -s tests` pass.

## Test Notes

- AC-1 to AC-5 are unit tests in `tests/test_codex_hook_tty_reaper.py`,
  run in-process through the existing World seam (`world.sent`,
  `world.open_calls`, `on_stat`) or by substituting the snapshot routine, as
  SPEC.md TS1 allows. The substitution takes effect after the ancestor-chain
  read and before the snapshot, so the ancestor-chain read still sees the
  original anchor.
- AC-1 is the TDD red step: run it before the fix and confirm it fails (a
  signal is recorded or a pidfd is opened), then implement the check.
- AC-2 is the boundary case of AC-1 (one tick); AC-4 and AC-5 guard against
  a check that is too strict (false mismatch).
- AC-3's output check follows whatever capture approach the existing tests
  use for exit code and output; if none exists, capture stdout / stderr
  around the entry point within the test.
- AC-6 and AC-7's suite runs reuse existing tests; the diff part of AC-7 is
  checked by reading the diff, not by a unit test.

- `.claude/rules/hook-tests.md`: not changed.
- `plugin.json` / `marketplace.json`: not touched.
