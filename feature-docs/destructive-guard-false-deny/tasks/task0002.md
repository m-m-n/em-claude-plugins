# Task Plan: task0002 — Narrow the FR2 re-scan skip to one static mcp-bridge or printf command

## Goal

destructive-guard skips re-scanning a single-quoted substitution candidate
only when the whole command is one static `mcp-bridge run` or
`printf '%s\n'` command and the candidate fills a data argument of it. Every
other single-quoted candidate is re-scanned as the hook at the implement
base commit did. This closes the two residual high findings and removes
the false deny of TS-6. The skip decision becomes one independent function
built on lexer information, and the FR2-specific word lists and raw-text
patterns are removed.

Provenance: review round 1, findings `9db27104415c584f` and
`767398d2b9499db6`.

## Design

### Background
The current hook decides the FR2 skip with an execution-word list, an
allowlist of words whose arguments are not executed (including
`_ARGS_NOT_EXECUTED_WORDS`), patterns over the raw command text for
re-evaluation constructs, and special handling of `printf -v`. Each review
auto-fix loop found a new bypass of that approach:

- `9db27104415c584f`: with a variable holding a single-quoted substitution
  of a forced deletion, `eval "$X"` inside a nested command substitution or
  `bash -c "$X"` inside a process substitution comes out allow. The hook at
  the implement base commit denied it.
- `767398d2b9499db6`: `sort` is on the allowlist, but
  `sort --compress-program=sh` runs its temporary data as a program. Data
  holding a single-quoted substitution piped into it comes out allow. The
  hook at the implement base commit denied it.

The raw-text patterns also re-introduced false denies: TS-6 comes out deny,
and words such as set, let or function inside a quoted JSON body or a
trailing comment cause a deny.

This task replaces that approach with a positive, narrow shape. It is a
strict subset of SPEC FR2's (a)-(d): every command it skips is a top-level
chunk that lexed cleanly, whose only command word is not an execution word
and is static, with no override construct.

### Terms
- **Implement base commit**: `workflow.implement.base_commit` in
  `workflow.yaml`, `03343519bf77a6d38bb717aec1fc701f7f0a72b2`. "The base
  hook" is the hook at that commit, before this feature.
- **Top-level chunk**: the chunk `statements()` takes off its pending stack
  first, that is the original command string. Every chunk derived from it is
  not top-level.
- **Single-quote candidate**: a span reported only by the quote-agnostic
  scan (the scan with single quotes not honoured). It lies inside a
  single-quote or ANSI-C-quote region. A span of a real substitution region,
  which the quote-aware scan also reports, is not a single-quote candidate.
- **Word**: a word of the top-level command as the lexer delimits it, with
  its start and end positions and the quote regions it is made of.

### Skip decision function
One function decides which single-quote candidates of the top-level chunk
are not queued. It is separate from the chunk loop's queueing code.

- **Input**: the lexing result the chunk loop already has for the top-level
  chunk (words with positions, the quote kind of each region, and which
  region contains which), and the chunk's single-quote candidate spans.
- **Output**: the set of candidate spans whose bodies are not queued. An
  empty set means every candidate body is queued.
- **Call**: evaluated for the top-level chunk before any of its candidate
  bodies is queued. For every other chunk the set is empty.
- **Purity**: it changes no run-global state (the command-name override
  flag, deferred data-heredoc bodies, marker positions, the substitution
  list, token flags).
- **Fail-closed**: any condition that is false, or that the lexing result
  cannot decide, makes the output empty.
- **Means**: it reads token positions, quote kinds and region nesting. It
  matches no regular expression over the raw command text, and it consults
  no list of execution words or not-executed words.

A candidate is in the output only when every condition below holds.

**Whole-input conditions** (any failure empties the output):
- **W1**: the top-level chunk lexed without the parse-failure fallback, and
  every quote and substitution in it is closed.
- **W2**: the whole input is exactly one simple command. Whitespace, one
  trailing comment and trailing newlines after it are permitted. Nothing
  else is: no second command (after `;`, `&`, `&&`, `||`, a pipe or a
  newline), no redirect of any kind (here-strings and descriptor
  duplications included), no heredoc, no assignment word before the command
  word, no control structure or compound command (`for`, `while`, `if`,
  `case`, subshell, group), no function definition, no negation, and no
  wrapper (for example env, builtin, command, exec, nohup, time, sudo,
  xargs).
- **W3**: the command word is the first word, unquoted, with no backslash,
  and equal to exactly `mcp-bridge` or exactly `printf`. A path-qualified
  name (for example `/tmp/mcp-bridge`) does not qualify.
- **W4**: every word of the command is static.
  - Outside quotes: no `$` that starts an expansion, no backtick, no
    backslash (line continuations included), no glob character (`*`, `?`,
    `[`), no brace (`{`, `}`), no leading tilde.
  - Inside double quotes: no `$`, no backtick, no backslash.
  - Single-quote and ANSI-C-quote regions are static whatever they contain.
  - A word with a real substitution, such as a double-quoted command
    substitution argument, is therefore not static. Its substitution is
    re-scanned as before.

**Shape conditions**:
- **S1 (mcp-bridge)**: the second word is exactly `run`. A candidate
  qualifies only inside the word that immediately follows a word that is
  exactly `--args-json`. The `--args-json=` joined form does not qualify.
- **S2 (printf)**: the second word consists of exactly one single-quote
  region whose content is `%s\n` (percent, s, backslash, n). No option comes
  before it. A candidate qualifies only inside a word after it.

**Candidate condition**:
- **C1**: the candidate lies inside a closed single-quote or ANSI-C-quote
  region that is not nested in any other region and that makes up the whole
  word. A word that joins the quote region with any other text does not
  qualify.

Candidates of the same command that fail S1, S2 or C1 are queued as before.

### Queueing rule and invariants
- **Q1**: compared with the base hook, every chunk sends the same entries
  to the pending stack in the same order, except that the bodies the skip
  decision function returns are not sent. The decision is consulted when a
  candidate body would be pushed. No entry is removed from, or reordered in,
  the pending stack after it has been pushed.
- **Q2 (FR3, TM-2)**: compared with the base hook, these stay unchanged:
  the top-level span list, both marking passes, the extension of the
  run-global substitution list (so every marker index still names the right
  entry, including the index of an omitted body), the registered marker
  positions, and the per-token unresolved and substitution-only flags.
- **Q3 (NFR2)**: `scan_budget` and `MAX_SHELL_PAYLOAD_EXPANSIONS` are
  unchanged.

### Removal
Remove the code this feature added for the previous FR2 decision and no
longer needs: the FR2 execution-word set, `_ARGS_NOT_EXECUTED_WORDS`, the
raw-text patterns for re-evaluation constructs, the `printf -v` special
handling, and the post-push removal of pending entries. `SINK_WORD_RE` and
every other name present at the implement base commit stay as they are.

### Case conventions
- Format follows `.claude/rules/hook-tests.md`: three elements per case.
- `git branch -D example` is the only destructive text in each added case.
  In every added deny case it sits only in a single-quoted or ANSI-C-quoted
  substitution or in a substitution, so the deny comes from re-scanning.
- Labels are in Japanese, like the existing ones. Each starts with the
  feature name, then the TS-n ID or the condition it pins (for example W2
  redirect, S2 option).
- The new cases are appended as one contiguous block at the end of the
  array. No case carries a home directory or other machine-specific path.
