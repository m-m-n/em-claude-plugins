# Task Plan: task0001 — Scratchpad rule for saved Codex wrapper output, cited from the tier pre-survey

## Goal

When the orchestrator saves the output of a `run_codex_exec.sh` call to a
file, the procedure it follows puts that file in the session scratchpad and
never under the project root. The rule is stated once, in step 2 of the
Codex consultation procedure. The develop tier pre-survey cites it, and
structural doc tests pin both documents so that a regression is detected.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `test-docs/codex-consult-output-scratchpad/task0001.tests.yaml` — the per-task acceptance-test record (format and ownership as defined by the implement phase)

### Files to Modify
- `em-workflow/references/question-resolution.md` — add the saved-output placement rule to step 2 ("Wrapper invocation") of the Codex consultation procedure
- `em-workflow/skills/develop/SKILL.md` — add a citation of that rule to step 3 ("Codex 事前調査") of the "### tier 決定" section
- `tests/test_question_resolution_doc.py` — region-scoped assertions for the new rule, plus negative twins
- `tests/test_develop_tier_staged_procedure.py` — a new test class for the step 3 citation, plus negative twins

## Design

This feature has a single task, so there is no IMPLEMENTATION.md. The
version-bump Action manages plugin versions in this repository, so this task
gives no instruction about version fields.

### Rule text in question-resolution.md (FR1, FR2, FR3, NFR1, NFR6)

- **Region**: the text between the markers "2. **Wrapper invocation.**" and
  "3. **One turn per call.**" inside "### Codex consultation procedure".
- **Placement**: add the rule as one or more new, self-contained English
  sentences, starting on their own line or lines inside that region. Do not
  splice them into an existing sentence. Do not re-wrap, reword or move any
  existing line of step 2. The invocation line, both `--litellm` variants,
  the 600000 ms timeout sentence and the exit-code chain-advance paragraph
  stay byte-for-byte unchanged. Keep the new sentences outside the
  `litellm`-only sentence, so the rule reads as governing every turn on
  either harness entry, including the turns after a mid-consultation move
  from `codex` to `litellm`.
- **Content the new sentences must carry**:
  1. A condition: the rule applies only when the output of a
     `run_codex_exec.sh` call is saved to a file, and it names both streams
     (stdout, stderr). Saving stays optional. When nothing is saved, the rule
     imposes nothing.
  2. Placement: such a file goes into the session scratchpad directory. Name
     this in prose as the per-session scratchpad directory that the harness
     provides (SPEC A-2). Do not name it through a shell variable.
  3. Prohibition: the file is never written under `{project_root}`, and the
     redirect target is never a path relative to the current directory.
- **Ownership**: this is the only place the rule is defined. No other
  document restates it.
- **Variables (NFR1)**: introduce no shell variable. Do not add a path
  example. If one turns out to be unavoidable, every variable in it uses the
  guarded default form `${VAR:-default}`. An orchestrator-local name such as
  `$S` never appears.
- **Forbidden tokens (NFR2)**: the added text contains none of 'rate limit',
  'rate-limit', '429', any provider name listed in the existing
  provider-name test, a `taskNNNN` identifier, or a backticked gate_id
  literal.

### Citation in SKILL.md (FR4, NFR3, NFR6)

- **Region**: within the "### tier 決定" section, the text between the
  markers "3. **Codex 事前調査**" and "4. **no-work 停止**".
- **Placement**: add one Japanese sentence (or a short sentence pair) as new
  line(s) after the last existing sentence of step 3, before the "4." marker,
  using the step's existing indentation. Existing sentences and both markers
  stay unchanged.
- **Content**: the sentence says that where a saved pre-survey output (the
  JSON the pre-survey returns, when it is saved to a file) is placed follows
  `references/question-resolution.md`, the Codex consultation procedure,
  step 2 (Wrapper invocation). It does not restate the rule. It carries no
  scratchpad wording and no project-root wording, in English or Japanese.
  The English names "Codex consultation procedure" and "Wrapper invocation"
  are used as-is, as identifiers of the cited target.
- **Forbidden tokens (NFR3)**: the tier section must never contain a decimal
  literal (digit, period, digit), 'P(0)', 'expectation_clear', a
  `gate_id: <value>` form, or 'AskUserQuestion'. Never follow the step number
  with a period. Write the reference so that no digit-period-digit sequence
  can appear even after all whitespace is removed. For example, do not end a
  sentence with "2." right before the "4." marker. Refer to the step by
  number together with its name "Wrapper invocation".
- **Variables (NFR1)**: introduce no shell variable.

### Tests in tests/test_question_resolution_doc.py (FR5)

- A region extractor returns the step 2 region, whitespace-collapsed, from
  the existing `self.text`. It fails the test (an assertion, never a silent
  empty string) when either marker is missing or the markers are out of
  order.
- **Placement matcher (AC-1)** asserts that the region contains the
  scratchpad-placement phrase, including both stream names.
  **Prohibition matcher (AC-2)** asserts that the region contains the
  `{project_root}` prohibition phrase and the current-directory-relative
  prohibition phrase. The matchers pin the exact phrases the implementer
  wrote, compared on the whitespace-collapsed rendering.
- **Negative twin (AC-3)**: a synthetic copy of the pre-fix step 2 text,
  taken from the base revision, is passed through the same matchers, and
  each matcher is asserted not to match. The matchers are written as reusable
  predicates over a text argument, so that the twin and the real assertion
  run the identical check.
- **Retention pin (AC-7)**: the region still contains, verbatim, the
  invocation line, both `--litellm` values, and the 600000-millisecond
  timeout sentence.

### Tests in tests/test_develop_tier_staged_procedure.py (FR6)

- A new test class. It reuses the module's existing tier-section locator
  (`TIER_SECTION`) and its `_contains` / `_strip_ws` helpers. It defines no
  second locator and no duplicate helper.
- It slices the region from "3. **Codex 事前調査**" to "4. **no-work 停止**"
  within `TIER_SECTION`, and fails loudly when either marker is missing or
  the markers are out of order.
- **Citation matcher (AC-4)**: the region names
  `references/question-resolution.md`, "Codex consultation procedure" and
  "Wrapper invocation".
- **Non-restatement (AC-5)**: the region contains neither the English rule
  sentence(s) added to question-resolution.md (verbatim) nor the rule's
  placement terms ("scratchpad", "スクラッチパッド", "project root",
  "プロジェクトルート", matched case-insensitively on the whitespace-stripped
  text). A verbatim English match alone could not catch a Japanese
  restatement, which is why the placement terms are checked too.
- **Negative twin (AC-5)**: the citation matcher, run against a synthetic
  copy of the pre-fix step 3 text from the base revision, does not match.

### Unguarded-variable check (NFR1)

- For each of the two regions, collect every shell-variable token, in both
  the bare `$NAME` form and the braced form. Each token found in the fixed
  document must be either already present in that region's pre-fix text (in
  step 2: `${CLAUDE_PLUGIN_ROOT}` and `$PROMPT`; in step 3:
  `${CLAUDE_PLUGIN_ROOT}`) or in the guarded default form `${VAR:-default}`.
- Negative twin: a synthetic region containing a bare redirect through an
  undefined variable (the incident's `$S` form) fails the check.
- Each region's check lives in the test module that owns that document.

## Test Notes

- Every criterion is a unit-level structural doc test, except AC-7 (a) and
  (d), which are diff checks performed at the verify phase.
- TDD order: write the region extractors and matchers first. Confirm they
  fail on the current documents (red), and confirm the negative twins
  already pass. Then edit the documents until the positive assertions pass
  (green).
- The negative twins embed the pre-fix region text as a literal. Copy it from
  the base revision, not from the edited file, so that the twin keeps
  representing the bug after the fix.
- Collapse whitespace before every phrase match in question-resolution.md,
  since Markdown line-wrapping must not affect the result. For SKILL.md, use
  the module's `_strip_ws` helper, because Japanese text wraps without
  spaces.
- Before adding a test, check that the module does not already define a
  test method with the same name. A silently shadowed method would drop an
  existing test.
- Record each AC's test IDs in the `tests.yaml` record, in the format
  `test/README.md` describes.
