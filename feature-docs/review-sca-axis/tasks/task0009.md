# Task Plan: task0009 — Scan execution outcomes and the partial-coverage result contract

## Goal

Axis 2's result can no longer read as a completed clean scan unless every
selected ecosystem actually completed: each scanner run is judged on its exit
status and its payload shape together, and an ecosystem that did not complete
is visible to a mechanical consumer rather than demoted to prose.

## Design

### One outcome per scan job, with no third state

Executing a scan job (the object IMPLEMENTATION.md D8 pins, constructed by the
sibling rework task) yields exactly one outcome:

- **completed** — a payload the ecosystem's normalizer can read; or
- **not_completed** — a machine-stable reason.

There is no "completed with an empty payload because nothing came back". Empty
stdout is not an empty successful scan: a front end that resolves but has no
audit capability, and a scanner that dies before writing anything, both produce
it, and both are `not_completed`.

### Exit status and payload shape are judged together

Neither alone is sufficient. An audit tool legitimately exits non-zero
precisely when it found something, so exit status alone would discard real
findings; and a tool can exit non-zero while printing a well-formed JSON ERROR
envelope, so a parseable payload alone would accept a failure as data. The
rule is per tool:

- a documented advisory-found exit status is accepted ONLY when the payload
  also has that tool's success structure;
- an exit status outside the tool's documented set is `not_completed`;
- a payload whose top level is that tool's error envelope (npm's missing-
  lockfile error object is the concrete case) is `not_completed` regardless of
  exit status;
- empty stdout is `not_completed`.

Each arm has its own machine-stable reason, distinguishable from the others
and from the tool-absent reason FR3 already defines.

### Partial coverage is machine-readable, not prose

The emitted object stays ONE object: the result schema carries exactly one
`skipped` / `skip_reason` pair and forbids properties outside its fixed set,
so per-ecosystem structure cannot be added to it. Partial coverage is
expressed within that shape:

- `skipped` is `true` whenever ANY selected ecosystem did not complete, with
  `skip_reason` carrying the combined stable reasons in a deterministic order;
- `findings` still carries everything the completed ecosystems produced — a
  skip about ecosystem B never suppresses ecosystem A's advisories;
- `skipped: false` with `skip_reason: null` therefore means, and only means,
  that every selected ecosystem completed;
- `summary` names which ecosystems completed and which did not, in prose that
  contains no tool-sourced text.

The protocol statement follows the same shape: the Phase R2 paragraph that
records axis 2's run currently reads a skip as "the scan tool absent on PATH".
One additive sentence states that a skipped axis-2 run also covers partial
coverage, that the run's row carries the combined reason, and that the result's
findings still enter the evaluator's inputs. The edit is additive — several
test modules pin this document's text, so no already-pinned sentence is
reflowed or reworded.

is raised once for the round, in both places, at the same value. This task owns
that bump; the two sibling rework tasks do not touch either file, so the bump
