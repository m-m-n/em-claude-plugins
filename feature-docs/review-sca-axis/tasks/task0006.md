# Task Plan: task0006 — Security-skill delegation note and plugin version bump

## Goal

The security reviewer stops re-reporting what axis 2 now decides
mechanically, and the plugin version is raised in both registries so the
change actually reaches an installed cache.

## Requirements

FR19, FR20, FR22, NFR6

## Scope

### Files to Create
- `tests/test_sca_axis_skill_and_version.py` — pins for both edits and the
  stdlib-only convention for this feature's new test modules.

### Files to Modify
- `em-workflow/skills/review-security/SKILL.md` — one addition to the
  "What NOT to flag" section.
- `em-workflow/.claude-plugin/plugin.json` — version 0.1.65 → 0.1.66.
- `.claude-plugin/marketplace.json` — the em-workflow entry's version, same
  value.

## Design

### Delegation sentence (FR19)

"What NOT to flag" gains a statement that the judgement of KNOWN CVEs in
dependency packages is made mechanically by axis 2, so the security
perspective should not spend findings on it. The existing two sentences of
that section stay; the addition is one more item in the same voice. Nothing
elsewhere in the skill changes — in particular the `category` section still
requires every finding to carry the security category.

The sentence is scoped to known-CVE dependency advisories only. Reasoning
about whether a vulnerable path is actually reachable in this codebase stays
in scope for the security reviewer: axis 2 reports the advisory, the
evaluator judges reachability, and neither replaces a human-facing security
review of the code itself.

### Version bump (FR20)

Both registries move to the same new value, one patch above the current one,
per the repository's version-bump rule (behaviour corrections and ordinary
feature work are patch-granular here, and every prior bump in this repository
is patch). The two files must agree exactly — an installed cache keys off
this value, so a mismatch or a missed bump leaves users running the old code.

## Test Notes

- AC-3's comparison must be tuple-based; a string comparison would call
  "0.1.9" greater than "0.1.65". The repository's existing version-bump test
  modules already establish that pattern.
- AC-4's scan reads each module's own import statements only; a module that
  loads a script by file path (task0001's and task0005's modules do) is not a
  third-party import and must not be flagged — that distinction deserves an
  explicit case so the check is not accidentally over-strict.
- AC-2's "unchanged" is asserted against the specific surviving sentences and
  headings rather than a whole-file hash, so this task's own addition does
  not fail its own assertion.
