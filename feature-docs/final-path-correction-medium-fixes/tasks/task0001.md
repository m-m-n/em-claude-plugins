# Task Plan: task0001 — correction rules of the validator

## Goal

A final-path correction passes the validator only when it changes paths and
nothing else, and the correction completes on documents shared by several tasks
and on re-planning.

## Requirements

FR1, FR2, FR3, FR5, FR6, FR7, FR8, FR9, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/scripts/validate-worker-output.py` — the correction rules, their docstrings and the two worker-result checks
- `tests/test_final_path_correction.py` — recurrence tests and the pinning tests of SPEC.md Reference Impact
- `tests/test_gate_option_vocabulary.py` — refresh of the validator byte pin only

## Design

Decisions D2 to D7 of IMPLEMENTATION.md are binding here and are not restated.
The components below can be built and tested in this order.

### 1. Path state

Compute the D2 state before the `replace_all` branch of `_validate_dry_run_apply`,
so the corrections block can read it whatever `tasks_patch.mode` holds. The
`replace_all` branch keeps its behavior.

### 2. Form check

A pure predicate on one string, true when all of FR2's three clauses hold. The
whole string must match, so a trailing line break fails. Condition 4 applies it
after the safe-path check and before the base lookup, and reports under
`path-correction-new-path`.

### 3. Reference scanner

A pure function of a text and the corrections. Post: the ordered, non-overlapping
occurrences of D3, each with its span, its token and whether it is a path or a
bare name. The scanner is the only definition of an occurrence: comparison,
left-behind check and FR1 all use it, and none of them searches for substrings.

### 4. Positional comparison

Input: the base text, the current text, the base occurrences, and for each
occurrence the old text plus its D4 replacements.

Post: true when the current text can be read as the literal runs of the base in
order, with each occurrence holding one member of its permitted set, consuming
the whole current text. Permitted texts may be prefixes of each other, so this is
a search over the pair (occurrence index, current position). Visited pairs are
remembered, so the cost is bounded by that pair count and never grows
exponentially. Replacements are literal and the current text is never rescanned.

### 5. Condition 5

`_path_correction_content_errors` takes the path state and the journal's last
events, and builds its document set keyed by normalized path (D5). A document
used by several tasks is checked once. Errors keep the wording `old path` for a
path token, and name a bare token as a bare old file name. A left-behind check and
a comparison failure on one document are separate errors, as today.

`_correction_normalizer` and `_normalize_path_strings` are removed.

### 6. Correction entry limits

These run on the correction entry only, after condition 5, reading the entries
and `requirements_patch` of the patch.

- **Requirements limit**: FR1 (a). A malformed item is a rejection, not a pass.
- **Entries limit**: FR1 (b) and (c), one error per rejected reason, naming the
  task and the file. A file is read with `_read_base_document`, and any reason it
  gives is a rejection.
- **Canonical render**: one function, D6. Pre: every rendered string passed the
  form check. Post: the exact text of D6.
- **Plan check**: FR1 (d). The plan is read with the checks condition 5 uses for a
  current document, and a plan that cannot be read is a rejection.

### 7. Worker-result checks

- `_validate_scenario_id_form` gains an optional third parameter for the workflow.
  VERIFICATION.md is skipped only when the workflow is given and the patch is on
  the correction entry; a null workflow scans. Two-argument calls keep working,
  because `tests/test_validate_worker_output.py` is itself byte-pinned and does
  not change. The call site in `validate_worker_result` passes the workflow.
- `_validate_corrected_task_plans` groups the target tasks by normalized plan and
  checks each plan once, against the union of those tasks' files after correction.
  A plan used by one target behaves as today.

### 8. Docstrings and pin

Update the section comment and the docstrings of every function changed here so
that they state FR1 to FR3, FR5 to FR7 and FR9.

Refresh the validator byte pin under D7, as the last edit.
