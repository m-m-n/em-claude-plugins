# Task Plan: task0001 — Fix anonymous-function stdin connection in codex-hook-interactive-guard

## Goal

codex-hook-interactive-guard (both copies) treats a zsh anonymous function's
body as connected when a stdin redirect is read in the head, and when a stdin
redirect follows an argument word that contains `(`, so the reproduction
commands become silent while the denied range outside the targeted forms stays
as it is today.

## Requirements

## Design

Cross-task conventions (byte-identical copies, CASES entry format, pinned
docstring markers, hook constraints) are in IMPLEMENTATION.md "Conventions"
and are not restated here.

### Current defect (from the feature goal)

- Opening the anonymous body group goes through `_open_group`, which flushes
  the head simple command (`_flush`). The stdin state read so far in the head
  is discarded; the body group receives only the pipe state, so a `python3`
  in the body is treated as unconnected.
- While the arguments after the body's `}` are read, a `(` opens a group
  through `_open_group`, which flushes and leaves `after_group` empty. A
  later `<` attaches to the group made from the argument, and the body stays
  unconnected.

### Contract A: head stdin redirect reaches the anonymous body (FR1, FR2)

- Trigger: the parser opens the body group of an anonymous function in any of
  the three forms already recognized — bare `function { ...; }`,
  `function () { ...; }`, `() { ...; }`.
- Input state: the stdin redirects (`<` `<<` `<<<` `<&` `0<`) read in the
  head simple command before the body — before `function`, between
  `function` and `{` (bare form only), or before `(` of `()`. A newline
  between `()` and `{` does not drop this state.
- Postcondition: the body group is connected when the head carried a stdin
  redirect, in addition to the existing sources (pipe connection from the
  head, stdin redirect among or after the arguments). Groups nested inside
  the body receive the connection through the existing propagation rules.
- Scope limits (FR2):
  - the state is attached to the anonymous body only, never to the `(` group
    of the head's `()` itself;
  - it does not reach commands after the separator that ends the arguments
    (`;` `&&` `||` `|` `|&` `&` newline);
  - it is not applied to groups that are not anonymous functions;
  - redirects other than stdin (`>`, `2>`, and so on) do not count as a
    connection;
  - an explicit `-i` inside the body is still denied.
- Unchanged (SPEC Out of Scope): a stdin redirect between `()` and `{`, and a
  redirect before a plain `{ ...; }` or a subshell `( ... )`, keep the
  verdict the base revision gives.

### Contract B: `(` inside anonymous-function arguments (FR3)

Flow while `after_group` points at the anonymous body (arguments after `}`):

1. A `(` appears, mid-word (`foo(x)`) or word-initial (`(x)`).
2. Locate its matching `)` with the existing paren-skipping semantics
   (`_skip_parens`: quotes handled as today; backquotes and comments not
   treated specially).
3. Branch on the range from `(` to the matching `)`:
   - matched, and the range holds no unquoted `;`, `&`, or newline: the whole
     range becomes part of the current argument word (whitespace and `|`
     inside it are part of the word); `after_group` keeps pointing at the
     body; reading continues after `)`;
   - matched, and the range holds an unquoted `;`, `&`, or newline: the
     pre-change reading applies (a group is opened), giving the same verdict
     as the base revision;
   - no matching `)`: undecidable (silent), as before.
4. A stdin redirect among or after the arguments connects the body
   (existing rule, now also reached after such a word).
5. A separator outside any such range ends the arguments (existing rule).

- A `)` with no matching `(` among the arguments keeps the current
  `_close_paren` handling (a separator that closes an enclosing subshell when
  there is one).

### Contract C: linear parsing (NFR2, TM-1)

- Over one whole parse, the work spent locating `(`…`)` ranges and checking
  them for separators is bounded by a constant times the input length.
- This holds for the TS20 shape: a range that contains `;` falls back to
  opening a group, and a nested anonymous function's arguments then meet a
  `(` inside that group, repeatedly. Restarting a scan toward the end of
  input from every nested `(` does not meet this contract.
- No recursion is introduced; the module stays standard-library only and
  touches no file, network, or subprocess (NFR3).

### Contract D: docstrings (FR4, NFR4)

- Module docstring step 4, and the `_Group` / `_Parser` docstrings where they
  describe the changed behavior, state: the head stdin redirect inheritance
  and its scope; how `(` inside arguments is read; the exception for an
  unquoted `;`, `&`, or newline in the range.
- The description of where arguments end does not contradict a `|` inside a
  `(`…`)` range not ending the argument.
- The paren search is not described as a fully quote-aware search.
- Every marker pinned by `TestGuardDocumentation` stays verbatim.
