# Task Plan: task0002 — Re-derive the findings record's auxiliary Codex facts under temporary Codex homes

## Goal

Every fact the findings record relies on comes from a Codex invocation run
with HOME and CODEX_HOME in temporary directories. The auxiliary commands in
section 2 of the record (`codex --version`, `codex --help` and any
subcommand help, `codex features list`) ran without them. On 0.160.0,
`codex features list` reads `$CODEX_HOME/config.toml`, so those runs read
the user's real Codex home (NFR1).

## Requirements

FR1, FR2, NFR1, NFR5

## Provenance

- source: verify
- source_ids: TS-8
- review_round: not applicable (verify-sourced)

## Scope

### Files to Create
None.

### Files to Modify
- `feature-docs/codex-repo-hook-trust/HOOK-TRUST-FINDINGS.md` — section 2's auxiliary Codex invocations are replaced by isolated re-runs. Every other Codex command line in the record states its HOME and CODEX_HOME.

## Design

The vocabulary (route, repository hook, executing route, Branch E / Branch N,
findings record) and the conventions (Codex home isolation, credentials,
evidence over absence, bounded launches) are defined in IMPLEMENTATION.md.
The findings record is the Shared Component there. This task writes to it
under the same contract.

### 1. Isolated re-run of the auxiliary invocations

- Re-run every Codex invocation that section 2 of the record cites
  (`codex --version`, `codex --help`, any subcommand help, `codex features
  list`, and any other Codex subcommand the record cites outside the
  probes). Each re-run has HOME and CODEX_HOME pointed at freshly created
  temporary directories.
- The temporary CODEX_HOME used for `codex features list` holds the same
  configuration the probes used (feature settings, trust entry, litellm
  profile, as the record describes them). It is rebuilt from the record's
  own description. Nothing is copied from the user's real HOME or Codex
  home, and nothing there is read, listed or written.
- Credentials are not needed for these commands. Set no credential variable
  for them.
- Every launch is bounded in wall-clock time and leaves no process behind.

### 2. Record update

- Section 2 shows, for each re-run, the command line with HOME and
  CODEX_HOME given as temporary-directory placeholders, together with the
  output the record relies on.
- Facts that section 2 derived before (the reported version, the hook
  location and event list and its source, the feature state) are re-derived
  only from the re-runs. The record states for each one whether it is
  unchanged.
- The earlier non-isolated invocations may be mentioned only with a
  "superseded" label. None of their output is cited.
- The verify failure names only section 2's auxiliary invocations. Every
  other Codex command line in the record (probes, positive controls,
  post-change probes) gets an explicit statement of its HOME and
  CODEX_HOME, so the whole record can be inspected for isolation line by
  line. If one of those invocations turns out to have run without
  temporary homes, that is a plan deviation under section 3.

### 3. Deviation rule

- The result matrix, the per-route verdicts and the branch are not changed
  by this task.
- Stop and report a plan deviation in either of these cases. A re-run gives
  a different reported version, a different location or event list, or a
  feature state that would change a probe's result, a per-route verdict or
  the branch. Or a probe, positive control or post-change probe turns out
  to have run without temporary homes. Do not
  edit the record's conclusions, the wrappers, the tests or TB-3. Those
  files are outside this task.
