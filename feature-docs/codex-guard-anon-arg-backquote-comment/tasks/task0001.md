# Task Plan: task0001 — Read a word-start `#` as a word character in backquote-triggered argument groups

## Goal

In both copies of `codex-hook-interactive-guard.py`, a provisional argument
group that returned to group reading through a backquote (and every group
nested in it) reads an unquoted `#` at word start as a word character until a
direct separator clears that reading, so the anonymous function body's
explicit `python3 -i` is denied again. The regression rows and the docstring
markers land in the same change.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/scripts/codex-hook-interactive-guard.py` — per-group comment-exception state set when a group opens, consulted when a word-start hash is read, cleared on the parser's own direct separators; docstring updates (FR2, FR3, FR4, FR8)
- `em-review/scripts/codex-hook-interactive-guard.py` — the same change, byte-identical to the em-workflow copy (FR6)
- `tests/test_codex_hook_interactive_guard.py` — four new deny rows in the CASES table and the new docstring markers (FR7, FR8)

## Design

Notation used below: W(SHAPE) is the command
``zsh -c 'setopt nonomatch nobareglobqual; function { python3 -i; } SHAPE'``.
`<newline>` stands for one literal LF character inside the command string.
Every command here is hook input only — fed as `tool_input.command` on the
hook's standard input, never executed.

### Where the exception state lives (SPEC A6, decided here)

The state is one new attribute on the group record (`_Group`). Its meaning:
"while this group is the innermost open group, an unquoted `#` at word start
is a word character, not the start of a comment". No existing symbol is
removed or renamed.

Lifecycle of the attribute:

1. **Set by the opening condition (FR2)** — a provisional group opened by
   `_read_argument_parens` because `_scan_parens` returned `end`,
   `separated` is false and `backquoted` is true starts with the attribute
   set.
2. **Inherited at open (FR3)** — any `(` group, `{` group or provisional
   group opened while the current innermost group has the attribute set
   starts with it set, whatever its own opening condition. The value is
   copied once, at open time, from the parent's value at that moment.
3. **Otherwise unset (FR3, FR5)** — every other group starts with the
   attribute unset and reads `#` exactly as today.
4. **Cleared by a direct separator (FR4, SPEC A1, A2)** — when the parser
   itself reads `;`, a lone `&`, `&&`, `|&` or a newline while a group with
   the attribute set is the innermost open group, that group's attribute is
   cleared. It is never set again for that group. Only the innermost group
   is touched: a separator read inside a nested group never changes an outer
   group.
5. **Discarded on close (FR3)** — when a group closes, its attribute goes
   with it and the parent's own value (possibly already cleared) applies
   again.

What counts as a direct separator is exactly what reaches the parser's own
separator handling (`_separator`, SPEC A1). `|`, `||`, the redirections `&>`
and `>&`, quoted separators and backslash-escaped separators never clear the
attribute.

### Reading `#`

At the comment handling in `parse`:

- innermost open group has the attribute set, unquoted `#` at word start →
  the `#` is a word character (it starts a word; the following characters
  join the word under the existing word rules, so a following `)` still
  closes the group);
- any other case → unchanged: comment outside every group, comment in a
  provisional group opened by `;` / `&` / newline, comment in a provisional
  group opened because no `)` was found, mid-word `#` stays a word character,
  `#` inside `$(` follows `_skip_substitution` as today (SPEC A5).

### What does not change (FR5)

`_scan_parens` (end detection and return values), the `paren_budget` charge
in `_read_argument_parens`, `_skip_parens`, `_skip_substitution` (including
its comment reading inside `$(`), the end-of-input handling, the rescue
conditions (`_rescue_separator`, `_rescue_argument_groups`,
`_closes_after_rescue`), the connection rules and the `first_sep` record.
An unclosed backquote stays undecidable (no output). How backquote and `$(`
contents are read stays as it is.

### Performance (NFR1)

The attribute is decided once per group open from the parent (constant
time). Reading a separator and reading `#` consult only the innermost group
(constant time). No recursion is introduced and nothing is rescanned, so
the parse stays linear in the command length.

### Docstrings (FR8)

The rule — the opening condition, the word-character reading of a
word-start unquoted `#` while the group is innermost, inheritance at open,
clearing on the five direct separators, and that this is the single
exception added to the previous SPEC's assumption A2 — is written in four
places in both copies: the module docstring's step 4, the `_Parser`
docstring, the `_read_argument_parens` docstring, and the description of the
new `_Group` attribute.

The existing marker sentence "a backquote and a comment get no special
reading" stays verbatim; the exception is stated next to it so the two read
consistently. The other existing markers (`BACKQUOTE_MODULE_MARKER`,
`BACKQUOTE_PARSER_MARKER`, `BACKQUOTE_SCAN_MARKER`,
`BACKQUOTE_READER_MARKER`, `ANONYMOUS_ARGUMENT_MARKERS`,
`RESCUE_PROVISIONAL_MARKER`) stay. No sentence listed in
`STALE_DOCSTRING_SENTENCES` or `STALE_GROUP_SENTENCES` returns.

The docstring tests gain markers for the new rule, named and checked in the
same style as the existing marker constants, and checked against both
copies.

### CASES rows (FR7)

Four rows, each with expected decision `deny`, labelled in the style of the
neighbouring rows, appended without touching any existing row. The command
strings are the hook input verbatim — the `'"'"'` sequence in the fourth row
is part of the string.

1. Reproduction: ``zsh -c 'setopt nonomatch nobareglobqual; function { python3 -i; } foo(`echo x` #)'``
2. Reproduction followed by a newline and `python3 -i`: ``zsh -c 'setopt nonomatch nobareglobqual; function { python3 -i; } foo(`echo x` #)<newline>python3 -i'``
3. Nested group in the range: ``zsh -c 'setopt nonomatch nobareglobqual; function { python3 -i; } foo(`echo x` (a #))'``
4. Scan stopping early at a `)` inside the backquote, then a direct `;`: ``zsh -c 'setopt nonomatch nobareglobqual nobadpattern; function { python3 -i; } foo(`case x in x) echo x;; esac`; # '"'"' ignored<newline>python3 -i'``

Row 4 is the guard against an over-broad exception: the `;` clears the
exception, so the `#` starts a comment, the provisional group is rescued by
the `;`, and the `python3 -i` after the newline is judged. Without the
clearing rule, the `'` after `#` becomes an unclosed quote and the result
turns silent.
