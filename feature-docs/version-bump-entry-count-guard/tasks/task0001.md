# Task Plan: task0001 — Scope the marketplace AC-3 check to the em-workflow entry

## Goal

Adding a plugin entry to `.claude-plugin/marketplace.json` no longer fails
`tests/test_recycled_task_id_contract_version_bump.py`. task0002's AC-3
("fields this task does not touch are unchanged") is verified only through
the em-workflow entry's name and source. Values built inside the test show
that this check tolerates extra plugins and still fails on em-workflow
name/source drift. The task0002 test record matches the module.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4

- `test-docs/recycled-task-id-contract/task0002.tests.yaml` — AC-3 tests list and red_reason match the module after the removal

## Design

### em-workflow entry check (module-local)

| Item | Contract |
|------|----------|
| Input | A marketplace mapping in its JSON-parsed shape: a top-level mapping whose plugins array holds entry mappings |
| Lookup | The entry whose name is exactly em-workflow, located the same way the retained test locates it today |
| Fails (the test framework's assertion failure) when | No entry is named em-workflow; or that entry's source is not exactly ./em-workflow |
| Never inspects | The array length, the entry order, or any entry other than em-workflow |
| Side effects | None; it reads no file and writes no file |
| Postcondition | Returns without failure exactly when an entry named em-workflow exists and its source is ./em-workflow |

**Non-weakening rule (FR2)**: before refactoring, list every assertion the
retained test makes today. Every assertion about the em-workflow entry
keeps holding through the check. If the retained test turns out to contain
an assertion that depends on the array length or on another entry, do not
drop it silently: stop and report it as a plan deviation.

### Retained test flow

1. Read the repository's marketplace.json and parse it as JSON, as today.
2. Apply the em-workflow entry check to the parsed mapping.

### In-test data cases (FR5)

Each case builds its marketplace mapping inside the test. The mapping is
independent of the repository file's contents, and nothing is written to
disk.

| Case | Data | Expected |
|------|------|----------|
| Extra plugin tolerated | em-review, em-workflow (source ./em-workflow), plus a third plugin entry whose name is not em-workflow | Check passes |
| Source drift | em-workflow entry present with a source other than ./em-workflow | Check raises an assertion failure |
| Name drift | The em-workflow entry renamed to another name, so no entry is named em-workflow | Check raises an assertion failure |

  both observations in the per-task test record.
