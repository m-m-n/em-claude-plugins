# Task Plan: task0007 — Resolve the current session's start from the transcript's first timestamped entry

## Goal

Marker-based current-session resolution (IMPLEMENTATION.md D2 form 2) succeeds
against transcripts as they are actually written — whose leading record carries
no `timestamp` — so the I.2.b orphan recovery can reach a decision instead of
degrading to `current-session-unknown` on every real invocation.

## Provenance

- source: `verify`
- source_ids: MANUAL-D2
- review_round: null

The verify phase reproduced the failure directly: `_first_entry_timestamp` in
`em-workflow/scripts/recover-orphaned-task.py` inspects only the transcript's
FIRST non-blank JSONL line and returns None when that line carries no
`timestamp` field. Real transcripts under `~/.claude/projects/{encoded-cwd}/`
open with a record such as `{"type":"last-prompt",...}` that has no
`timestamp` — 40 of 40 sampled files in this repository's transcripts
directory. `_resolve_current_session_via_marker` finds the right transcript and
then discards it, so `resolve_current_session(None, None, marker, dir)` returns
None and D2 form 2 degrades to `current-session-unknown` in practice. The whole
FR2 proof path therefore never fires. The existing 3029 automated tests pass
because every fixture writes a timestamped first line, so the defect is
observable only through the manual D2 check.

## Design

### What is wrong today

D2 form 2 says the resolved transcript's "first entry's timestamp" is the
current session's start. That was implemented as *the first non-blank line, and
nothing else*: a leading record without a `timestamp` field, an unparsable
leading line, or a leading line that is not a JSON object each abandon
resolution outright. Transcripts in the harness's real layout always open with
such a record, so the strict reading makes form 2 unreachable — the marker scan
identifies the correct file and then throws it away.

### The revised rule

IMPLEMENTATION.md D2 (updated in this same rework round) now pins the rule this
task implements; the task does not restate it. In flow terms:

- The marker scan is unchanged: newest modification time first, and the FIRST
  transcript containing the token is committed to. No fall-through to an older
  transcript on any later failure.
- The committed transcript's start instant is the EARLIEST parseable
  `timestamp` among its entries. Blank lines, lines that are not valid JSON,
  lines that are not JSON objects, and entries whose `timestamp` is absent or
  unparsable are skipped — the same line-level tolerance the transcript's
  newest-activity reader already applies.
- Resolution fails only when NO entry in the committed transcript yields a
  parseable timestamp; that stays `current-session-unknown` (Residual).
- Taking the earliest rather than the positionally-first instant is the
  fail-safe direction (IMPLEMENTATION.md Conventions, NFR1): the current
  session's start is the threshold a recorded session's newest activity must be
  strictly older than, so an earlier threshold can only make recovery harder to
  prove, never easier.
- Form 1 (explicit `--current-session-id` with `--current-session-start`) keeps
  precedence and keeps its own failure behaviour unchanged.

The helper's docstring currently cites D2 as authority for failing outright on a
timestamp-less first entry. It is rewritten to cite the revised D2, so no
in-repo text still presents the old behaviour as intended.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With an injected transcripts directory holding one marker-bearing
      transcript whose first non-blank line is a JSON object with no
      `timestamp` field (the real layout's leading record shape) and whose
      later entries carry parseable `timestamp` values, marker-based resolution
      returns a pair: the transcript file name's stem, and the earliest
      parseable timestamp in that file. It does not return None.
- [ ] AC-2: With the same fixture changed only so that the leading line is
      blank, is not valid JSON, or is valid JSON that is not an object,
      resolution returns the same pair as AC-1 — malformed leading lines are
      skipped, never a resolution failure.
- [ ] AC-3: With a marker-bearing transcript in which NO entry carries a
      parseable timestamp (entries with the field absent, null, non-string and
      unparsable are all present), resolution returns None, and a full
      invocation of the script over that fixture reports `residual` with reason
      `current-session-unknown`, leaves the journal byte-identical to its
      pre-call content, and records zero invocations of the journal-helper stub.
- [ ] AC-4: With a marker-bearing transcript whose parseable timestamps are not
      in ascending order (a later instant appearing on an earlier line), the
      resolved start equals the earliest parseable timestamp in the file, not
      the one on the earliest line.
- [ ] AC-5: With two transcripts that both contain the marker, the one with the
      newer modification time is committed to; when that committed transcript
      yields no parseable timestamp the outcome is `current-session-unknown`,
      and the older marker-bearing transcript is never adopted as the current
      session — asserted by a fixture whose older transcript would resolve
      successfully.
- [ ] AC-6: Form 1 precedence is unchanged: with both `--current-session-id`
      and `--current-session-start` supplied, the marker is not consulted even
      when it would resolve, and an unparsable explicit start still yields
      `current-session-unknown`.
- [ ] AC-7: End to end with both real helper scripts and a marker-bearing
      transcript whose leading record carries no `timestamp`, a fixture that is
      otherwise a proven orphan (journal final event `launched`, a bound agent
      index entry whose session identity differs from the resolved current
      session, that session's transcript quiet strictly before the resolved
      start) reports `recovered` and appends exactly one `failed` line carrying
      reason `orphaned`.
- [ ] AC-8: `em-workflow/.claude-plugin/plugin.json` and the em-workflow entry
      of `.claude-plugin/marketplace.json` declare the same version, strictly
      greater than the value each carried before this task.
- [ ] AC-9: `python3 -m unittest discover -s tests`, run from the repository
      root, exits 0 with zero failures and zero errors, importing only the
      standard library, with every new test living in repository-root `tests/`
      as `test_*.py` and reading or writing no real `~/.claude` state.

## Test Notes

- AC-1 through AC-6 are unit-level and build on the fixtures
  `tests/test_recover_orphaned_task.py` already uses: a temporary directory
  holding the journal, the agent index and an injected `--transcripts-dir`,
  plus the stub helper implementing SC2's outcome contract.
- The AC-1 fixture is the regression that the current suite lacks. Write the
  leading record with the shape observed in the real layout — a JSON object
  carrying a `type` and no `timestamp` — so a future reader can see why the
  case exists. Do not replace the existing timestamped-first-line fixtures;
  a transcript whose first entry *does* carry a timestamp must keep resolving
  to that same instant.
- AC-5 needs deterministic modification times; set them explicitly on the two
  files rather than relying on write order.
- AC-3's "journal byte-identical" assertion reads the file's bytes before and
  after the invocation; comparing parsed events would hide a partial line.
- AC-7 is the only criterion that runs the real journal helper; it is the
  in-task counterpart of the integrated scenario and belongs in the existing
  end-to-end test group rather than in a new module.
- AC-8 needs no new test module — `tests/test_plugin_version_parity.py`
  already asserts parity and baseline advancement over both manifests.

## Out of Scope

- Changing the marker scan's ordering or its commit-to-first-match rule. The
  scan already finds the right transcript; only the start-time derivation is
  defective.
- Introducing any new source of the current session's identity (a harness API,
  an environment variable, the hook input). SPEC.md leaves that source open and
  D2 form 1 already accepts an explicit value; adding a source would be a
  specification change.
- Changing D3's proof condition, the newest-activity reader, or any SC6 reason
  code — `current-session-unknown` keeps its exact meaning and remains the
  outcome when resolution genuinely fails.
- Changing `em-workflow/references/implement-phase.md`: its I.2.b block cites
  D2 for the resolution rule instead of restating it, so the revised rule needs
  no edit there (NFR7).
- Relaxing the fail-safe direction anywhere: no path added by this task may
  make a recovery provable that was not provable before, other than by
  resolving a current session that previously could not be resolved at all.
