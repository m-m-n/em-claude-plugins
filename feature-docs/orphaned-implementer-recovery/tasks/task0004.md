# Task Plan: task0004 — SSOT document updates and plugin version bump

## Goal

The SSOT documents state the new, narrowly-scoped exception under which the
orchestrator records a terminal journal event for a proven orphaned
`launched`, with one owning section and citations everywhere else, and the
plugin version is raised in both required places.

## Requirements

FR4, FR7, FR8, NFR6, NFR7

## Scope

None.

- `em-workflow/references/workflow-schema.md` — the journal event definition

## Design

**Owning section (NFR7).** `implement-phase.md`'s I.2.b Recovery / Residual
block owns the orphan-recovery rule in full: the candidate conditions, the
evidence order and its residual reason codes (IMPLEMENTATION.md SC6), the
invocation protocol for the two helpers including the marker emission that
precedes it (D2), and the statement that this is the only case in which the
orchestrator appends a journal event. Every other location cites that
section by repository-relative path and restates none of it.

**The journal-write rule (FR7).** The "Supporting cast" journal bullet and
the Stale-`launched` caveat currently assert that the orchestrator never
writes the journal. Both are rewritten to name the exception and cite the
owning section. `workflow-schema.md`'s writer-set paragraph — currently "No
other hook, and never the orchestrator, appends to journal.jsonl" — names
the new writer script and records `orphaned` as an additive value of the
existing `failed` reason field, again by citation. `em-workflow/README.md`'s
journal description is brought into agreement the same way.

**Agent index authority (FR8).** `workflow-schema.md`'s `agents.jsonl`
paragraph keeps the existing invariant that the index carries no
task-status semantics, and states that the session identity read by I.2.b
orphan recovery is the sole exception. `implement-phase.md`'s Agent index
writer bullet records the added field (SC1) and that it is never a match
candidate. Both cite the owning section.

**Downstream convergence (FR4).** The I.2.c text states that a `failed`
carrying reason `orphaned` is an ordinary failed: in batch, the failed-task
policy fires its single retry with a kept worktree and the I.2.a resume
guard; in interactive, retry / route back to planning / abort are offered.
Existing wording is reused — no new policy, threshold or branch is
introduced by this task.

**Version bump (NFR6).** Raise the patch component of the em-workflow
version, writing the same value into both files.

## Test Notes

- The constants held by `tests/test_implement_routeback_gate.py` are
  verbatim citation phrases from the rewritten blocks. Update prose and
  constants in this same change; a constant that still matches the old text
  means the rewrite did not land where the test looks.
- Prefer asserting the citation phrase plus the distinguishing new clause
  over asserting whole paragraphs, so ordinary editorial edits do not break
  the suite while a lost rule still does.
- No new test file is introduced. Version-bump consistency is a verify-phase
  check (TS-11) rather than a unittest, so it cannot collide with any check
  the repository may already have.
