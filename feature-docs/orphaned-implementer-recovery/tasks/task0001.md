# Task Plan: task0001 — Record the launching session identity in the agent index

## Goal

The agent index records which session launched each implementer, so that
I.2.b reconcile can compare that identity against the current session —
without changing any behaviour the existing readers depend on.

## Requirements

FR1, FR9, NFR3, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/hooks/queue_agent_index.py` — the appended entry gains the
  session identity field described by SC1.
- `tests/test_queue_agent_index.py` — the per-field entry assertions and the
  entry fixture helper move with the entry shape.
- `tests/test_queue_taskstop_net.py` — the compatibility assertions
  (including the test that reproduces the real writer's output) confirm the
  added field changes nothing on the reader side.

## Design

**Entry shape.** The hook appends one entry per launch. That entry gains one
independent top-level field carrying the launching session's identity
(IMPLEMENTATION.md SC1), alongside the fields it already writes. The
candidate list of harness agent identifiers is untouched: the session
identity is never appended to it and never becomes a match candidate.

**Value source and validation.** The value comes from the session-identity
field of the hook's input JSON. Before being recorded it passes SC5's
validation rule. A value that is absent, not a string, or fails SC5 is
omitted from the entry; the entry is still appended and the hook still exits
0 (NFR3 — the fail-open discipline is unchanged, and the added field never
becomes a new way for the hook to fail).

**Reader-side compatibility (FR9).** Entries written before this change have
no such field, and fail-open entries will not have one either. The stop-side
resolution path — candidate-list matching, the identifier-key fallback, the
candidate-list cap, and the containment check — reads only the fields it
already read. The added field is inert for it: it neither widens the
candidate set nor changes ambiguity, staleness or containment outcomes.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A launch whose hook input carries a valid session identity
      produces exactly one agent index entry containing that identity as an
      independent top-level field, with every previously existing field
      unchanged in name and value.
- [ ] AC-2: The session identity never appears inside the agent-identifier
      candidate list, and is never usable as a match candidate on the stop
      side.
- [ ] AC-3: When the hook input carries no session identity, or a value that
      fails SC5's validation rule, the entry is appended without the field
      and the hook exits 0.
- [ ] AC-4: Stop-side resolution behaviour — match, ambiguity refusal,
      staleness, containment — is unchanged both for an entry that carries
      the new field and for one that does not (TS-6).
- [ ] AC-5: `python3 -m unittest discover -s tests` passes; the changed and
      added tests import only the standard library and never read or write
      real `~/.claude` state.

## Test Notes

- Hook behaviour is exercised by subprocess launch with stdin JSON, per the
  repository's existing hook-test convention; extend the existing entry
  fixture helper rather than duplicating it, so every assertion moves with
  the shape in one place.
- AC-3 needs three inputs: identity absent, identity of the wrong type, and
  identity present but failing SC5 (for example containing a path
  separator). All three must still produce an appended entry and exit 0
  (TS-8).
- AC-4 is a regression guard: keep the existing resolution assertions and
  add the paired case (same fixture with and without the new field) so the
  suite proves the field is inert rather than merely untested.
- The test that reproduces the real writer's output must be updated in this
  same change, or it will assert the old shape.

## Out of Scope

- Any journal read or write (task0002 and task0003 own those).
- Anything under `em-workflow/scripts/`.
- Documentation updates and the plugin version bump (task0004 owns both).
- Changing the candidate-list format, the identifier-key fallback, the
  candidate-list cap, or the containment check.
