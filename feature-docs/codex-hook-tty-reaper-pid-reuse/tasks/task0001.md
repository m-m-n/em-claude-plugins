# Task Plan: task0001 — Start-time link rule and pidfd signalling in codex-hook-tty-reaper.py

## Goal

`codex-hook-tty-reaper.py` (both copies) never sends SIGTERM or SIGKILL to a
process that does not descend from the anchor, even when a PID is recycled
during the snapshot or between the identity check and a signal. Regression
tests pin both reproductions from the workflow goal.

## Design

Cross-task conventions (fail closed, error policy, silent operation, two
copies) are in IMPLEMENTATION.md and are not restated here. Code locations
below are the ones the workflow goal names (`_depths_below`, `_stop`,
`_same_process`, `_snapshot`, `main()`).

### Link rule (one rule, two walks)
A link from a process X to its recorded parent Y is valid when Y's recorded
start time is not later than X's recorded start time. Equal start times are
valid. Start times are the values recorded in the snapshot.

### Descendant computation (FR1) — the depth computation (`_depths_below`)
- Precondition: one snapshot (PID, PPID, start time, state per process) and
  the anchor PID.
- Postcondition: the target set holds exactly the processes reachable from the
  anchor through valid links; each target's depth is its link count from the
  anchor.
- The anchor's start time is taken from the snapshot. When the anchor is not in
  the snapshot, the target set is empty and nothing is stopped (A3).
- A process whose link to its parent is invalid is not a target, and neither is
  any process reachable only through it.
- Existing exclusions (the hook itself, its ancestor chain) and every other
  selection rule are unchanged (NFR3).

### Ancestor-chain check (FR6) — the walk from the hook to PID 1
- Every link on the chain is checked with the link rule. One invalid link
  anywhere on the chain means the run sends no signal at all.
- Equal start times on the chain do not prevent stopping.
- The chain still serves both the anchor validation and the exclusion set.
  Behaviour when a chain member is missing from the snapshot is unchanged
  (NFR3).

### Stopping through pidfd (FR2-FR5) — the stop routine (`_stop`)
1. **Availability (FR4)**: when the pidfd-open seam or the pidfd signal-send
   seam is unavailable, nothing is stopped. The PID-addressed signal function
   the current code uses is never a fallback, on any path.
2. **SIGTERM phase**, in the existing target order (deepest first, same depth
   by ascending PID; NFR3), per target:
   1. open a pidfd for the target's PID;
   2. while holding it, read the target's stat and confirm that the start time
      equals the recorded one and the state is not dead (`Z`, `X`, `x`);
   3. confirmed: send SIGTERM through that pidfd and keep the pidfd for the
      SIGKILL phase;
   4. not confirmed: close the pidfd; the target receives no signal for the
      rest of the run.
3. **Grace**: the existing 0.5 s wait, unchanged (NFR3).
4. **SIGKILL phase**, same order, only for targets that received SIGTERM: repeat
   the confirmation of step 2.2 while holding the same pidfd; confirmed: send
   SIGKILL through that pidfd. A target never gets a second pidfd (FR3).
5. **Closing**: every pidfd the run opened is closed before `main()` returns, on
   every path.

Error handling (FR5):
- ProcessLookupError from the pidfd open or the pidfd signal-send for a target:
  not an error. That target receives no further signal (its pidfd, if open, is
  closed); the other targets continue.
- Any other error from either function (including EMFILE and ENOSYS at open,
  and PermissionError): no further signal to any target, the SIGKILL phase
  included; all open pidfds are closed; exit 0 with no output.
- A stat read that fails during a confirmation keeps its existing handling
  (NFR3).

### Test seams and fakes (FR8)
- `main()`'s signalling seams become: pidfd open, pidfd signal-send and pidfd
  close. Their defaults are the real standard-library functions. When the
  running interpreter lacks a pidfd function, the corresponding default is the
  "unavailable" value that triggers FR4. The PID-addressed signal function is
  no longer a seam.
- The defaults test asserts the real pidfd functions as defaults, not the
  PID-addressed signal function.
- Fake pidfd: on open it binds to the process instance (PID plus start time)
  that holds the PID in the fake process table at that moment; an open for a
  PID nobody holds raises ProcessLookupError. A signal through a fake pidfd is
  recorded against the bound instance and the pidfd used, or raises
  ProcessLookupError when that instance no longer exists; it never reaches a
  different instance now holding the PID. Close marks the fake closed.
- The fake stat reader can swap the instance holding a PID right after
  returning a value (reproduction 2).
- The fakes can be set to raise ProcessLookupError, OSError(EMFILE),
  OSError(ENOSYS) or PermissionError at open or at signal-send for a chosen
  PID.
- In-process tests replace the PID-addressed signal function with a recorder
  and assert it is never called.
- Existing tests that observed signals through the old seam are migrated to the
  pidfd fakes with their assertions (selection, order, timing) kept.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, TM-1): In the descendant computation a link is adopted only
  when the parent's recorded start time is not later than the child's, so a
  rejected child and every process reachable only through it receive neither
  SIGTERM nor SIGKILL. With anchor A, unrelated process C (start 100) whose
  recorded parent P was recreated under A with start 200, C receives no signal
  (TS-1). A parent and child with equal start times under the anchor: the
  child receives SIGTERM (TS-3). The anchor missing from the snapshot: no
  signal is sent.
- [ ] AC-2 (FR6, TM-2): When the hook's ancestor chain contains a link whose
  parent started later than its child, no signal is sent in the run; when the
  chain's start times are equal across a link, the targets are still stopped
  (TS-4).
- [ ] AC-3 (FR2, TM-3): Each target's pidfd is opened before its identity
  check, the check runs while the pidfd is held, and SIGTERM is sent only
  through that pidfd and only when the check passes; a target that fails the
  check receives no signal then or later and its pidfd is closed. With a stat
  read that returns start 100 after which the PID's instance becomes start 200,
  the start-200 instance receives neither SIGTERM nor SIGKILL; this test fails
  against the current code (TS-2).
- [ ] AC-4 (FR3, TM-4): For every target that received SIGTERM, SIGKILL goes
  through the same pidfd that carried its SIGTERM, after the same start-time and
  dead-state check; no target gets a second pidfd; after `main()` returns — on
  success and on every error path — no pidfd the run opened remains open
  (TS-7).
- [ ] AC-5 (FR4, TM-5): With the pidfd-open seam absent or set to the
  unavailable value, with the pidfd signal-send seam absent or set to the
  unavailable value, and with pidfd open raising OSError(ENOSYS), no signal is
  sent and the PID-addressed signal function is never called (TS-5).
- [ ] AC-6 (FR5): ProcessLookupError from pidfd open or pidfd signal-send for one
  target skips that target while the other targets still receive their
  signals; OSError(EMFILE) at open or PermissionError at signal-send stops every
  later signal, the SIGKILL phase included; every path exits 0 with no output
  (TS-6).
- [ ] AC-7 (FR7, FR8, NFR2, NFR3): The defaults test pins the real pidfd
  functions as `main()`'s defaults; the fake pidfd binds to the instance holding
  the PID at open time; the existing tests for selection, order (deepest first,
  same depth by ascending PID), timing (SIGTERM, 0.5 s, SIGKILL), silent
  operation, import without side effects and no `__pycache__`, the byte-identity
  test of the two copies, and the Linux real-process tests all pass;
  `python3 -m unittest tests.test_codex_hook_tty_reaper` and
  `python3 -m unittest discover -s tests` pass (TS-8, TS-11, TS-12).
- [ ] AC-8 (FR9, NFR1): The module docstring's Flow steps 4, 6, 8 and 10 and its
  errors paragraph state the start-time link rule for descendants and for the
  ancestor chain, signalling through a pidfd held until SIGKILL, and that
  nothing is stopped when pidfd is unavailable; both copies import
  standard-library modules only (TS-9, TS-10).
