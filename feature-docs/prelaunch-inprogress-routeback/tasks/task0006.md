# Task Plan: task0006 — Define the record, carry it on re-planning, and reject it in worker patches

## Goal

- `tasks.{T}.routeback_failed_journal_line` has a single normative
  definition in `workflow-schema.md`.
- A re-planning `replace_all` carries it verbatim for carried task ids.
- `validate-worker-output.py` rejects any worker `tasks_patch` entry that
  tries to set it.

## Requirements

FR6, FR11, FR12, FR13, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_routeback_record_schema_patch.py` — tests for the schema definition, the carry-over list and apply_patch preservation, and the worker-entry rejection

### Files to Modify
- `em-workflow/references/workflow-schema.md` — an optional field line in the Full structure tasks block, plus a new section defining the record
- `em-workflow/references/workflow-patch.md` — the record added to the verbatim carry-over field list of the Re-planning task-id allocation section
- `em-workflow/scripts/validate-worker-output.py` — task-entry validation rejects an entry carrying the record key
- `tests/test_replanning_carry_over.py` — the carried-field constant and the full-record fixture follow the new list

## Design

The record's contract is pinned in IMPLEMENTATION.md Shared Components
("Record" and "Schema anchor"). This task makes `workflow-schema.md` its
normative home.

**`workflow-schema.md` — Full structure.** In the `tasks` block of the
Full structure, add an optional `routeback_failed_journal_line` line after
`branch`. Its comment marks it optional, orchestrator-written and absent
by default.

**`workflow-schema.md` — new section.**

- The heading line is exactly ``## `routeback_failed_journal_line` ``.
- Contents:
  - meaning: the route-back reset confirmation record;
  - target file: `{project_root}/.claude/worktrees/em-workflow/{feature}/journal.jsonl`;
  - value: the 1-based physical line of the task's last `failed` event at
    reset time;
  - the LF-only counting rule, with blank and malformed lines counted, and
    a final non-empty segment without LF counted;
  - the canonical form: an unquoted decimal integer whose first digit is
    1–9;
  - every reader treats a non-canonical value, an absent key or `null` as
    no record;
  - the sole writer: the orchestrator, in I.2.c's route-back write set. It
    is not written for a task with no journal event. Scripts, hooks and
    worker patches never write it;
  - it is not rewritten at the I.2.a launch-state commit, I.2.b step 3, a
    retry or a terminal-status write. It is overwritten only by a later
    route-back of the same task. Nothing clears it;
  - the readers: I.2.a, I.2.b step 1, `queue_stop_guard.py`. Cite
    `references/implement-phase.md` for how they use it; do not restate
    the classification.
- Placement:
  - Recommended: after the ``## `completed_at_commit` (rule R2)`` section,
    before `## Sibling artifacts`.
  - Never between ``## `failed_kind` `` and ``## `completed_at_commit` ``.
    That span is compared byte for byte.
  - Never inside the `agents.jsonl` paragraph up to `## Status semantics`.
  - Never inside the journal writer-set span.
  - Do not edit the `tasks.*.status` transitions bullet. It must stay free
    of "except", "unless", "not met" and "exception".

**`workflow-patch.md`.**

- Add `routeback_failed_journal_line` to the verbatim carry-over list in
  "Re-planning task-id allocation".
- Add it as one more comma-separated, backtick-quoted item in the same run
  as `title` … `notes`, so the existing list parser reads 11 fields.
- The Permitted preserve vocabulary and the mandatory preserve table are
  unchanged.

**`validate-worker-output.py` — FR13.**

- Task-entry validation rejects any entry that has the
  `routeback_failed_journal_line` key, whatever its value, null included.
- It applies under both `replace_all` and `append`.
- It uses the existing machine-readable error shape, with its own stable
  error code naming the field.
- Carried ids never reach entry validation and are unaffected.
- `apply_patch` already deep-copies carried records. Do not change that
  behavior.
- The comment block containing the "replace-all-task-id-reused" anchor,
  directly before the `replace_all` branch, stays contiguous.

**`tests/test_replanning_carry_over.py`.**

- The carried-field constant grows from 10 to 11 entries.
- The full-record fixture gains the record with an integer value.
- Its "document list = fields apply_patch preserves" check passes against
  the updated `workflow-patch.md`.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR11, TM-3): `workflow-schema.md` lists
  `routeback_failed_journal_line` as an optional field in the Full
  structure tasks block. It has a section whose heading is exactly
  ``## `routeback_failed_journal_line` ``. That section states:
  - the meaning and the journal path;
  - the 1-based physical-line value, counted on LF only, with blank and
    malformed lines counted;
  - the canonical form (an unquoted integer of digits with first digit
    1–9);
  - that a value that is absent, `null` or non-canonical means no record.
- [ ] AC-2 (FR11, TM-1): The section names the orchestrator's I.2.c
  route-back write set as the sole writer, and states that scripts, hooks

  not rewritten by the launch-state commit, I.2.b step 3, a retry or a
  terminal-status write, and is overwritten only by a later route-back. It
