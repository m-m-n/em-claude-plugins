# Task Plan: task0002 — Rewrite the I.2.a "pending + launched can never arise" sentence and the tests pinned to it

## Goal

Step I.2.a no longer claims that workflow.yaml `status: pending` combined with
journal last event `launched` can never arise. It states when that combination
arises and that the existing in-flight rule governs it. The existing tests
pinned to the old sentence follow the new wording, and a new test module fails
on the old sentence.

## Design

Region boundaries, the shared term "launch-state commit", the protected
sections and the test conventions are fixed in IMPLEMENTATION.md (Shared
Components, Conventions, D1–D3) and are not restated here.

### The sentence

Target: the Region P sentence that opens "Given I.2.c's route-back
precondition below" and ends "workflow.yaml `status: pending` combined with
journal last event `launched` can never arise."

After the edit:

- The claim that the combination can never arise is gone.
- The premise may stay: route-back admits only tasks with a terminal journal
  last event, ids are never re-issued, and so a task carries only its own
  terminal events. This premise still grounds the sentences that follow.
  Keeping the opening "Given I.2.c's route-back precondition below" and the
  citation of the re-planning task-id allocation rule (`replace_all`) keeps
  the existing slice anchors and their content checks valid.
- New content:
  - the combination arises between a task's launch and Step I.2.a's
    launch-state commit below;
  - it also arises when that commit is not reached: an interruption, or a
    second exit 4;
  - when it arises, the in-flight rule stated just above governs it ("A task
    whose journal last event is `launched` is always in-flight, regardless of
    workflow.yaml `status`"), cited and not restated. The recycled-task-id
    carve-out does not apply to it.
- Placement: the same position as the old sentence — after the in-flight
  sentence and before the sentence that opens "Because Step I.2.c's
  route-back gate below". The recursion invariant therefore still follows the
  rewritten text.

### Text that stays byte-identical

Everything in `implement-phase.md` outside this one sentence. Existing tests
pin these Region P items in particular:

- "This carve-out is deliberately scoped to `failed` only";
- the in-flight sentence quoted above;
- the premise "Because Step I.2.c's route-back gate below blocks route-back
  whenever any task's journal last event is `merged`" and "independent of the
  ancestor check". From that premise through "correctly scoped to `failed`
  only." there is exactly one "Because " and one " so ". The rewritten text
  sits before this span and adds neither word inside it;
- the recursion invariant "No retired task id is ever re-issued, so a task
  whose workflow.yaml `status` is `pending` can never carry an inherited
  `merged` journal last event";
- the raw line-wrap literal "`tasks.*.status`. Select" + line break +
  "unlaunched tasks (no journal event yet and `status != merged`, ascending".
