### 3. Regression test module (`tests/test_exit4_ac2_test_id_drift.py`)

| Component | Responsibility | Contract (pre/postcondition) |
|---|---|---|
| Target list | Name the tests.yaml records under check | Explicit enumeration with exactly one entry: the target record. Its path is derived from this module's own location. No glob or directory scan of `test-docs/` (FR6). |
| ID extractor | Read one tests.yaml and return its acceptance test IDs, grouped by AC key, in file order | Pre: the file exists. Post: for each AC key under `acceptance_tests`, returns the IDs listed under that AC's `tests` key. An inline empty list yields an empty group. Any other shape of `tests` fails the test with a message naming the file and the AC key, and never silently yields zero IDs. Examples: a flow list with entries, a nested mapping, a missing `tests` key. Uses the standard library only, with no YAML library (NFR1). |
| Resolution judge | Decide whether one dotted ID resolves | Resolved only when the longest importable dotted prefix is a module and any remaining segments name either a test-case class in that module, or that class plus a method defined on it. Everything else is unresolved: an import failure, a missing attribute, or an attribute that is neither a test-case class nor a method of one. If the standard test loader is used, an error the loader records, or a failure placeholder in its result, also counts as unresolved, because the loader can report a missing attribute that way without raising. The judge never runs a test and never calls a resolved object. |
| Aggregate check | Apply the judge to every ID in a list | Post: passes exactly when every ID resolves. Otherwise it fails, and the failure message lists every unresolved ID, not only the first. Resolvable IDs are not listed. |
| Import-path setup | Make `tests.`-prefixed IDs resolvable whatever directory the run starts from | The repository root, derived from this module's location, is importable while the resolution tests run. If the root was not on the import path beforehand, it is removed again afterwards. |

Processing flow of the main resolution test:

1. For each entry of the target list, extract the IDs grouped by AC.
2. Flatten them in file order.
3. Run the aggregate check over the flattened list.

Guards that make the main test meaningful (FR7):

- **Negative proof**: the judge reports the stale ID as unresolved.
- **Guard on the negative proof**: the stale ID's module part and its
  module-plus-class part both resolve. This shows the rejection comes from the
  missing method and not from a broken import.
- **Non-vacuity guard**:
  - The flattened list is not empty and contains the replacement ID.
  - The per-AC counts are AC-1: 2, AC-2: 4, AC-3: 1, AC-4: 4, AC-5: 0, for 11
    in total. A parser that drops entries is therefore caught.

Wording checks, kept in the same module because NFR2 forbids adding tests to
the version_bump module:

- **Docstring check (FR3, FR4)**:
  - Reads the version_bump module's docstring from its source file without
    importing or executing the module.
  - Asserts that neither old string is present.
  - Non-vacuity guard: the text read is not empty and mentions both "AC-2" and
    "AC-4".
- **red_reason check (FR2)**: reads the value of AC-2's red_reason from the
  target record. Precondition: the AC-2 block has exactly one red_reason line
  in single-line double-quoted form. Anything else fails the check with a
  message naming the file, and never passes vacuously. It asserts:
  - The value is not empty.
  - The value begins with the observed-red clause.
  - "AssertionError" occurs exactly once in the value.
  - The value names all four AC-2 test methods.
  - The value contains neither "that entry is untouched" nor
    `has_no_version_key`.
  - The AC-2 block keeps `red_confirmed: true`.

## Test Notes

- **TDD order**: write the new module first and run it against the unfixed
  tree.
  - Expected red: the main resolution test (the stale ID does not resolve),
    the non-vacuity guard (the replacement ID is absent), the docstring check
    and the red_reason check (the old value contains "that entry is
    untouched" and names none of the four AC-2 test methods).
  - Expected green from the start: the negative proof, its module/class guard
    and the aggregate-message test (AC-5). They drive the judge with fixed
    inputs, which is normal for negative-proof tests. Record that in this
    task's tests.yaml red_reason instead of treating it as vacuity.
  - Then fix the record and the docstring until everything is green.
- **AC-5 input**: build the list inside the test. Use two method names that do
  not exist on `TestMarketplaceEntryVersion` plus one that does, and call the
  aggregate check directly.
- **Resolving `tests.`-prefixed IDs**: this imports the version_bump module a
  second time under a package-qualified name. `discover -s tests` loads it as a
  top-level module. The second copy only has to be resolved: its tests must not
  run and must not join the running suite.
- **Shadowing `tests` name**: if `tests` resolves to something other than the
  repository's `tests/` directory in some environment, for example an
  installed package with the same name, the positive assertions (AC-4, the
  guards in AC-6) fail. They do not pass vacuously, and that is intended.
- **Commands**:
  - TS-1: `python3 -m unittest tests.test_exit4_tip_argument_version_bump.TestMarketplaceEntryVersion.test_em_review_entry_version_not_bumped_with_em_workflow`
  - Full suite: `python3 -m unittest discover -s tests`

  Both run from the repository root.
