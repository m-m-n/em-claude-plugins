# Task Plan: task0004 — Linear anchor lookup in the `--args-json` collaborator

## Goal

`_queue_args_json_chunks()` finds the token position of each value's anchor
word in time linear in the number of values plus the number of tokens, so a
statement with many `--args-json` values no longer costs a token search per
value (findings 0379cf2eb7ad4e92 / 9981fd673b28e7e4). What it queues, and every
origin position, stays identical.

## Design

### Lookup rule (FR5)

Per call of `_queue_args_json_chunks()`, after the existing early returns and
budget handling:

1. A value with neither candidate bodies nor `command` strings queues nothing,
   so no token position is computed for it.
2. For a value that queues something, the anchor word's token index comes
   from a map from token span to token index over the statement's tokens. The
   map is built at most once per call, and only when the first value that
   needs it is reached. For each span it holds the index of the first token
   with that span, which is the index the current per-value search returns.
3. An anchor word without a span (or whose span is not in the map) is located
   by `_token_index()`, as today.

The entries queued, their order, and their origin positions (anchor prefix,
statement index, token index, ordinal) are the same as at base for every
input. `_args_json_word_index()` may be kept as the single-word fallback or
folded into the new lookup; no other code calls it.

### Docstring (NFR1)

Step 3 of the `_queue_args_json_chunks()` docstring states the lookup rule:
positions only for values that queue something, through a span map built at
most once per call, with `_token_index()` for a word without a span.
