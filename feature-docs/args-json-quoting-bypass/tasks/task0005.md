# Task Plan: task0005 — Nameref declarations: enclosing-shell chain and Bash word boundaries

## Goal

The nameref (`declare -n`) declarations the single-word-certain judgment
consults are the ones Bash actually has in effect for the statement: a derived
chunk sees the declarations of its own text and of every enclosing chunk whose
shell environment it inherits, and a declaration command is recognised with
Bash's word and redirection boundaries and through `command --`. A quoted
expansion that Bash turns into several arguments through such a declaration can
no longer keep the notion-pair exclusion (TM-1, SPEC FR1).

## Design

The single-word-certain judgment stays in its one helper, referenced only from
`_args_json_notion_pair()` (IMPLEMENTATION.md, Shared Components; NFR6). This
task changes only what that judgment learns about the nameref declarations and
the shell-state-unknown result that the review auto-fix added; it does not
change which word forms FR1 treats as certain.

### Declarations in effect for a derived chunk (1d971862e2458376, a3fdb05c00db3c03, 21b0ef3d5aaa59ae)

- Today every derived chunk consults the top chunk's text only. Instead, each
  derived chunk records its immediate enclosing chunk.
- A chunk that runs in a copy of the enclosing shell's environment (a command
  substitution, and every other derived kind the hook already treats as
  inheriting the shell environment) sees the declarations of its own text and
  those of each enclosing chunk, walking the chain up to the top chunk. A
  declaration in any chunk of the chain therefore counts, whatever the depth.
- A `bash -c` payload chunk (a new process) sees at least the declarations of
  its own payload text. Whether it also keeps consulting the enclosing chunks
  is left to the implementer; consulting them is the safe side, and no case
  pins either choice.
- Whatever else the scan derives from a chunk's text (the shell-state-unknown
  result of a `source` or `.` command) follows the same chain.
- Counting a declaration in an enclosing chunk regardless of its position
  relative to the derived chunk is allowed (safe side).

### Command recognition in the declaration scan (6083a3b46956a2f0, 4d1573a9f53b167f, 7bb299da67faace7)

- The scan takes a simple command's words and its redirection operators from
  the boundaries the existing lexer records, the same boundaries the rest of
  the hook works from. It never joins a redirection operator or its target to
  an adjacent word.
- A redirection (operator plus target) placed before the command name, glued
  to the command name, or after it, with or without spaces, is skipped when
  the scan determines the command name and the declaration options. A glued
  form and its spaced form always give the same result.
- `command` prefix: the scan skips `command`, then `command`'s own options,
  then a `--` terminator, and judges the word after them as the invoked
  builtin. A `-v` or `-V` option is treated as running that word (safe side).
  Any other prefix the scan already skips has its `--` terminator skipped the
  same way.

### Runner cases (FR8)

label starts with `args-json-quoting-bypass`, holding the cases below in this
order. Each label is Japanese, starts with `args-json-quoting-bypass TS-n`

on the unchanged hook; record every case's pre-fix verdict in the task's test

`mcp-bridge run --mcp notion --tool notion-create-comment --format "$r" --args-json '{"command":"git branch -D example"}'`;
