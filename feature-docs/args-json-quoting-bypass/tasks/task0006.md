## Design

### What `statements()` looks like afterwards

- From its `def` line to its last line, `statements()` is byte-identical to
  `statements()` at the implement base commit `996e1443a63b46e552a97d2ad7e2d2f96ae8f778`.
  Its docstring is part of that.
- It still calls `_queue_args_json_chunks()` once per statement it yields, with
  the same arguments as at base (TestStructure, NFR6).

### Where the derivation link is set instead

- The link stays the one the nameref chain walk reads today: a derived
  chunk's `_MarkedText` carries `_is_derived` true and `_outer_marked` naming
  the marked text of the chunk it was derived from;
  `_args_json_nameref_declared()` keeps walking that chain. The existing unit
  tests that build such chains by hand keep passing unchanged.
- The link is set by code that `statements()` already calls with the chunk's
  marked text, and before the notion-pair predicate is first asked about any
  statement of that chunk. `_queue_args_json_chunks()` is such a place: it
  receives the chunk's marked text, its anchor (origin-position prefix) and
  the run's own `_ScanState` and `_DeferredAsks` objects, and it asks for the
  decision only after it has been called.
- The parent of a chunk is found from the anchors: every derived chunk's
  anchor extends the anchor of the chunk it was derived from, and the top
  chunk's anchor is empty. A run-scoped record of the chunks seen so far (kept
  on an object that `statements()` creates per run and already passes to the
  collaborator) maps an anchor to its chunk; a chunk's parent is the
  registered chunk with the longest anchor that is a proper prefix of its own.
  - When several registered chunks qualify (equal anchors), or the refined
    anchor of a substitution body points into a payload derived from the
    true parent, the result may name a chunk below the true parent; the chain
    still reaches the true parent and the top chunk. Counting more chunks
    than the true chain is the safe side and is allowed.
  - A derived chunk (non-empty anchor) for which no registered chunk
    qualifies keeps `_is_derived` true and no link, which the chain walk
    already reads as "declared" (the safe side).
  - A chunk is registered whether or not its statements were lexed, and
    before the collaborator's existing early return, so the chain does not
    skip a chunk that holds statements.
- The collaborator's queued entries and their origin positions stay identical
  (IMPLEMENTATION.md, task0004's contract for `_queue_args_json_chunks()`).

### The unquoted-heredoc result

- Today `statements()` marks a chunk as "may hold a nameref" when the body of
  one of its heredocs with an unquoted delimiter holds a current-shell
  substitution opener (`${` followed by whitespace or `|`, line continuations
  removed); a quoted delimiter's body is left out. The same result is now
  reached outside `statements()`.
- The heredoc bodies are stripped from the chunk before its marked text is
  built, so the information has to be taken where the unstripped chunk or its
  heredoc records are still at hand: a helper `statements()` already calls
  with them (for example `_strip_heredocs_mapped()`, which receives the
  unstripped chunk and returns the stripped text that becomes the marked
  text's source). The implementer chooses the seam and how the result reaches
  the chunk's nameref answer.
- Any state this task keeps outside the objects of one `statements()` run is
  either cleared where `main()` clears its other per-judgment state, or is a
  pure function of the text it is keyed by, so the verdict and the kinds of a
  command never depend on what was judged before it in the same process.

### Docstrings and comments

- The `_MarkedText` comment on the link fields and the
  `_args_json_nameref_declared()` docstring name the code that now sets the
  link, instead of `statements()`.
- The docstring of `_queue_args_json_chunks()` states the added registration
  step, and that it changes nothing the collaborator queues.
