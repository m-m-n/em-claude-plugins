# Task Plan: task0001 — Read VERIFICATION.md only as a bounded regular file

## Goal

The validator's scenario-ID loader never blocks on a VERIFICATION.md that
is not a regular file, and never reads one without a bound. It returns the
unreadable state instead. Validation of rework-planner output then ends with
exit 1 and the existing rework-index error rather than hanging or exhausting
memory, and regression tests pin this for both the feature-dir side and the
baseline-dir side.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — the scenario-ID loader for VERIFICATION.md reads only a regular file, without blocking and with a byte limit
- `tests/test_rework_docs_only_validator_rules.py` — loader and CLI cases for a FIFO, a symlink to /dev/zero, a symlink to a regular file, a dangling symlink and an over-limit file, plus a CLI runner with a timeout

## Design

### Loader contract

`_load_scenario_ids(path)` returns `(state, value)` and never raises,
whatever the path, the file kind or the content. That includes a
`ValueError` from the path itself, which the current loader already absorbs.

- **Precondition**: `path` names `VERIFICATION.md` directly under the
  feature directory or the baseline directory.
- **absent** — `("absent", None)` only when the path has no directory
  entry: it is not found, or a parent component is not a directory. This is
  the same as today.
- **ok** — `("ok", ids)` only when the entry is a regular file and not a
  symlink, holds at most the byte limit, and decodes as UTF-8. `ids` is what
  `extract_verification_scenario_ids` derives from the text; that derivation
  does not change.
- **unreadable** — `("unreadable", reason)` in every other case:
  - a symlink, whether it points to a regular file, to a device or nowhere
    (SPEC A1)
  - a directory, a FIFO or a device file
  - a file over the byte limit, or bytes that are not UTF-8
  - any failure to stat, open or read the file

  `reason` is a short human-readable string. Its wording may change
  (SPEC A3).
- **No blocking**: a non-regular entry is never read, and opening the file
  never waits for a FIFO writer.

### Reading sequence

1. Classify the directory entry without following a symlink. A missing entry
   is absent. A symlink or a non-regular entry is unreadable.
2. Open the file without following a symlink and without blocking. If the
   open fails, the file is unreadable.
3. Confirm that the opened descriptor is a regular file. This catches an
   entry swapped between step 1 and step 2. If it is not, the file is
   unreadable.
4. Read at most the byte limit plus one byte. More than the limit means
   unreadable, and the rest of the file is never read.
5. Decode the bytes as UTF-8. If decoding fails, the file is unreadable.

The byte limit is the existing `MAX_PLAN_READ_BYTES` (SPEC A2).

### Reuse decision

The same script already has a reader that implements this sequence for the
scenario-ID form check: `_read_document_for_scenario_scan`, whose reasons
are rendered by `_scenario_scan_reason_text`. `_load_scenario_ids`
delegates to it instead of adding a second copy of the sequence:

- the reader's absent outcome becomes the absent state;
- every other outcome without text becomes the unreadable state, with the
  rendered reason;
- the loader keeps its own guard, so that anything the reader might still
  raise, such as a `ValueError`, also becomes unreadable.

The form check's behavior does not change. The loader's docstring is updated
to list the new unreadable cases.

### Callers unchanged

`_VerificationDiff`, `_RenameAwareCoverage` and the CLI are not modified.
The unreadable state still flows into one rework-index error per needed
unreadable file, and that error still contains "cannot be read as text" and
the file's path. The CLI still ends with exit 1 and JSON error details
(FR3).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-1): The loader returns the unreadable state with a non-empty reason, returns promptly and never raises for each of these: a FIFO with no writer, a symlink to /dev/zero, a symlink to a regular file holding valid scenario IDs, and a dangling symlink (TS-4).
- [ ] AC-2 (TM-2): A regular file one byte over `MAX_PLAN_READ_BYTES` gives the unreadable state. A regular file of exactly the limit that holds valid scenario IDs gives ok with those IDs. For a sparse regular file many times the limit, the call gives unreadable, and the memory it allocates stays under twice the limit: the file is never loaded in full (TS-5).
- [ ] AC-3: Existing behavior is kept. A missing file gives `("absent", None)`. A directory, and bytes that are not UTF-8, give unreadable. A regular file gives ok with the IDs `extract_verification_scenario_ids` derives. Every existing test in `TestRenameCoverageDiff` and `TestRenameDiffFixtures` passes without modification (TS-6).
- [ ] AC-4 (TM-1): The feature-dir VERIFICATION.md is replaced by a FIFO, and the CLI validates a rework-planner result whose coverage judgement needs the post-change set (as in the existing directory case). The run happens in a subprocess with a timeout. It ends before the timeout with exit 1 and exactly one rework-index error, whose message contains "cannot be read as text" and the FIFO's path (TS-1).
- [ ] AC-5 (TM-1): The same as AC-4, with the feature-dir VERIFICATION.md replaced by a symlink to /dev/zero: exit 1 before the timeout, and exactly one rework-index error naming that path (TS-2).
- [ ] AC-6 (TM-1): The baseline-dir VERIFICATION.md is replaced by a FIFO in one case and by a symlink to /dev/zero in another, and the result declares a scenario rename whose judgement needs the baseline set. The CLI run ends before the timeout with exit 1 and exactly one rework-index error naming the baseline-side path (TS-3).
- [ ] AC-7: Every case that gives the loader or the CLI a FIFO or a /dev/zero link runs in a child process with a timeout of seconds, not minutes, and with a memory cap where the platform supports one. So with the fix reverted, each such case fails at the timeout or the cap and does not hang or exhaust memory (NFR2). FIFO cases are skipped where a FIFO cannot be created, and /dev/zero cases are skipped where /dev/zero does not exist (SPEC A4). The test module imports only standard-library modules, and `python3 -m unittest tests.test_rework_docs_only_validator_rules` passes, `TestStandardLibraryOnly` included (FR4, NFR1).

## Test Notes

- **AC-1**: unit-level (TS-4).
  - The FIFO and /dev/zero cases call the loader inside a child process
    that loads the validator module, calls the loader once and reports the
    returned state. These cases never call the loader inside the test runner
    itself: with the fix reverted, that would hang or exhaust the runner.
  - The regular-file symlink and dangling symlink cases cannot block, so
    they may call the loader in the runner.
- **AC-2**: unit-level and in the runner (TS-5).
  - The exact-limit file and the limit-plus-one file are ordinary files of
    about 1 MB.
  - The many-times-the-limit file is created sparse, by setting its length
    without writing data, so creating it costs no disk space and no CPU.
  - Measure the memory the call allocates with the standard library's
    allocation tracing.
- **AC-3**: the existing suites (TS-6) plus an explicit missing-file
  assertion.
- **AC-4 to AC-6**: integration through the CLI (TS-1 to TS-3).
  - Reuse the existing CLI fixture builder of `TestRenameCoverageDiff`.
    Replace VERIFICATION.md after the directory is built, the same way the
    existing directory case does.
  - The existing CLI runner takes no timeout. Add a runner variant that
    takes one, and treat a timeout as a test failure.
  - Keep the variant's timeout short and fixed. Apply the memory cap to the
    child process before it starts executing, through the standard library's
    resource limits, large enough for a normal validator run. On a platform
    without resource limits, rely on the timeout alone.
- **TDD red phase**: run the new cases once before the fix. The FIFO cases
  fail at the timeout and the /dev/zero cases at the timeout or the cap.
  This is the evidence for AC-7's "with the fix reverted" clause.
- Do not repeat the cases in loops, and do not run them in parallel to
  provoke a failure. Each case runs once per test run.
