# Task Plan: task0001 — Regression tests for D2 form 2 over timestamp-less leading records

## Goal

Two regression tests pin D2 form 2 (marker-based current-session resolution)
against transcripts whose leading records carry no `timestamp`: one drives
the full orphan recovery through the command-line entry point with the real
journal helper, one checks the resolution function's returned pair directly.

## Requirements

FR1, FR2, FR3, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_recover_orphaned_task.py` — add one command-line entry point
  test (FR1) and one current-session resolution test (FR2); list both in the
  module's header docstring under this feature's name.

## Design

### Placement

Per IMPLEMENTATION.md D1: the FR1 test sits with the existing command-line
entry point tests, the FR2 test with the existing current-session resolution
tests. Reuse the module's existing fixture writers, child-process runner and
loaded script module; add a helper only when no existing one can express a
fixture.

### FR1 — command-line entry point, form 2, real journal helper

Fixture, entirely under one per-test temporary directory:

1. **Journal**: an existing regular file whose only entry for the task is a
   `launched` event carrying an `at` value.
2. **Agent index**: one entry for the task, bound to that launch per D7
   (its `at` equal to the `launched` event's `at`), carrying a session
   identity that passes SC5 and names the recorded session.
3. **Transcripts directory** holding exactly two transcripts:
   - the recorded session's, named after its session identity, whose newest
     timestamp is strictly earlier than the current session's resolved
     start, and which does not contain the marker;
   - the current session's, whose first record is a JSON object with no
     `timestamp` field, followed by at least one line that contains the
     marker and carries a parseable timestamp. The earliest parseable
     timestamp in this file is the resolved start.

Invocation: the script's command-line entry point as a child process, with
exactly `--journal`, `--agents-index`, `--task`, `--transcripts-dir` (the
temporary transcripts directory) and `--marker`. None of
`--current-session-id`, `--current-session-start` or `--journal-helper` is
passed, so form 2 alone resolves the current session and the default
sibling helper (the real `journal-append-failed.py`) performs the append.

Expected: exit status 0; stdout is a single JSON object whose `outcome` is
`recovered`, whose `task` is the task id, whose `reason` is the empty
string, and which has no other key; the journal holds the original
`launched` entry unchanged followed by exactly one new entry whose `event`
is `failed`, whose `task` is the task id and whose `reason` is `orphaned`.

### FR2 — function level, earliest parseable timestamp

Fixture: a temporary transcripts directory holding one transcript with a
known file name stem that contains the marker. Its lines, in order:

1. at least three JSON-object records with no `timestamp` field, whose
   `type` values are pairwise distinct;
2. a record with a parseable timestamp at 15:00;
3. a record with a parseable timestamp at 10:00, on the same date and with
   the same explicit UTC offset as the 15:00 record.

The marker appears on at least one line; its placement does not change the
expected result.

Invocation: `resolve_current_session` with no explicit session id, no
explicit start, the marker, and the temporary directory.

Expected: the pair (the transcript's file name stem, the 10:00 instant),
the instant compared as a parsed timezone-aware value, not as a string.

A derivation that read only the first line would return no result; one that
took the positionally-first timestamp would return 15:00. The fixture shape
above is what lets the test tell both apart from the correct result
(IMPLEMENTATION.md D2).

## Test Notes

- FR1 is an integration test (child process plus the real journal helper);
  FR2 is a unit test of the resolution function.
- Both tests are expected to pass on their first run against the unchanged
  script (IMPLEMENTATION.md D2). Do not modify the script to obtain a
  failing run; the fixture shapes pinned by AC-3 and AC-4 carry the
  discriminating power, and review checks them against those criteria.
- The real journal helper refuses a journal that does not already exist or
  that is a symbolic link: write the journal as a regular file before
  starting the child process.
- The appended `failed` entry's `at` is the helper's current local time;
  assert its presence at most, never its value.
- Give every fixture timestamp an explicit UTC offset so that instants
  compare as timezone-aware values; mixing offset-bearing and offset-less
  values makes the comparison ill-defined.
- In FR1, keep the recorded session's newest activity well before (for
  example a day before) the current session's resolved start, so the proof
  does not rest on a boundary case.
- Run the module alone first, then the full discovery command from the
  repository root.
