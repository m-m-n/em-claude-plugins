# Task Plan: task0001 — review-phase.md Phase R5: gate-abort status rule, resume path, legacy recovery

## Goal

Phase R5 of `em-workflow/references/review-phase.md` becomes the single
definition site for what the orchestrator writes when a `rework.spec-change`
question stops a review-sourced rework run, how that run resumes, and how a
review step already left `failed` by such a stop is recovered; the existing
`status: failed` reservation sentence gains a statement of its scope. A new
document-structure test module pins every element, each matcher with a
negative twin.

### 2. SC1 block — gate-abort status rule and resume path

Content elements, each pinned by its own matcher (element ids are local to
this plan and need not appear in the document):

- **E1 trigger**: in review-sourced rework, after step 1 of
  `references/rework-task-synthesis.md` Section 10 has written
  `review.needs_rework = true` and `review.status = pending`, the
  `rework.spec-change` question ends the run.
- **E2 enumerated stops**: exactly these four, each cited to
  `references/question-resolution.md` without restating its definition —
  the Classification gate's verdict stop (stated to include the stop that
  verdict (a), goal not met, produces), the gate's inapplicable case, the
  gate's origin-membership failure, and the malformed `rework.spec-change`
  pairing abort.
- **E3 field outcomes**: `workflow[review].status` is written `pending`
  (it was `in_progress` from Step B); `review.status` stays `pending`;
  `review.needs_rework` stays `true`.
- **E4 prohibition**: `failed` is written to neither `workflow[review].status`
  nor `review.status`.
- **E5 commit**: the write is committed with `commit-docs.sh` before the run
  stops; an exit 4 follows the exit-4 recovery of `skills/develop/SKILL.md`
  Step B (cited, not restated).
- **E6 non-effects**: none of the five steps of the Section 10
  specification-change transition runs, so the create-spec, create-plan and
  implement statuses are unchanged; `batch.review_rework_count` is not
  incremented (its increment belongs to the applied-patch path of the
  batch-mode paragraph).
- **E7 exclusion**: a spec-change gate stop in verify-sourced rework is
  outside this block.
- **E8 resume path (FR3)**: on `/em-workflow:develop <feature>`, Step B
  selects `review` (`pending`) as the next step and stop condition 3 does
  not fire; the review phase runs a new round; the Completion gate leads into
  the ordinary rework path above; in interactive mode the spec-change
  question rework-planner returns is asked to the user directly; the packet
  the Classification gate's stop or inapplicable outcome closed as obsolete
  is not re-presented (cite the gate's Outcome step in
  `references/question-resolution.md`). Do not claim obsolescence for the
  fail-closed aborts (IMPLEMENTATION.md Open Questions).
- **E9 stop-report guidance**: the stop's report — in batch, the
  `resume_conditions` value included — conveys that running
  `/em-workflow:develop <feature>` in interactive mode re-runs a review
  round and then reaches the spec-change decision (D3). No reason code is
  named (D2).
- **E10 no new control flow**: the block adds no Step B branch, no
  stop-condition-3 exception and no interactive question (D4).

Mode: the block carries no mode condition of its own (FR1 states none);
which of the four stops can occur in which mode stays
`references/question-resolution.md`'s.

### 3. SC2 block — legacy recovery procedure (FR4)

- **R1 applicability**: both hold — `workflow[review].status` is `failed`,
  and the last entry of `classification` in `phase-state/rework.yaml` has
  `decision: stop` (record shape cited to `references/phase-state.md`).
- **R2 restored values**: `workflow[review].status` and `review.status`
  become `pending`; `review.needs_rework` becomes `true`.
- **R3 commit**: the write is committed with `commit-docs.sh`.
- **R4 non-application**: when the record does not confirm R1 (file absent,
  list empty, or last entry not `decision: stop`), the procedure is not
  applied and stop condition 3's ordinary stop stands.
- **R5 continuation**: after the procedure, the run resumes through the SC1
  block's resume path (cited by label).
- **R6 no new control flow**: the procedure adds no Step B branch and no
  stop-condition-3 exception.
