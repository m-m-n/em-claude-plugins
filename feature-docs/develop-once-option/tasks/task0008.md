# Task Plan: task0008 — `batch-mode.md` の終端行の出力条件を到達状態で定義し直す

## Goal

`em-workflow/references/batch-mode.md` の `## Terminal line` が、終端行の
出力条件を「ランの終わり」を主語に述べたまま、ランを終わらせないターン
（`--once` のフェーズ境界）を第 3 項に並べている自己矛盾を解消する。
出力条件は「そのターンで契約 SSOT の定める終端状態に達したこと」とし、
3 つの機会はその条件が成り立つ場合の列挙として述べる。ラウンド 1 で
`SKILL.md` 側だけに適用された同型の修正（task0006）を、ポインタ層の
もう一方の文書にも揃える。

## Requirements

FR9, NFR1, NFR2, NFR3, NFR4, NFR5

## Provenance

- `source`: verify
- `source_ids`: `SC4`
- `origin_kind`: verify / `origin_id`: `SC4`

verify フェーズの Success Criteria SC4 のうち、**出力機会側**の未達が

## 事実（修正対象）

`em-workflow/references/batch-mode.md` の `## Terminal line` 冒頭は現在
次の形になっている。

> At the end of every batch run — on normal completion, on every terminating
> stop, and on a turn that ends at a `--once` phase boundary — the final
> assistant message carries a machine-readable terminal line as its last
> line.

主語は「ランの終わり」のまま、ランを終わらせないターンが第 3 項として
並んでいる。`SKILL.md` の 引数処理 は `--batch` 指定時に最初に
`batch-mode.md` を Read すると規定しているため、この文を根拠に
「`--once` 境界では終端行を出さない」と読む経路が残る（NFR5 に対する
実害）。同型の矛盾はラウンド 1 で `SKILL.md` 側だけが直され
（task0006、現行の定義文は「そのターンでランが同 SSOT の定める終端状態に
達した場合」）、`batch-mode.md` 側が取り残された。

## Scope

- `tests/test_batch_stop_contract_skill_wiring.py` — `batch-mode.md` 側の
  出力条件を固定する matcher・その負の証明・非空虚性ガード

## Design

### R-D: 出力条件の主語

定義文の主語を「ランの終わり」から「そのターンが到達した状態」に変える。
`SKILL.md` 側（task0006）と同じ形:

- 条件: そのターンで契約 SSOT の定める終端状態のいずれかに達したこと。
- 通常完了・すべての終端停止・`--once` のフェーズ境界で終わるターンは、
  いずれもその条件が成り立つ場合の列挙であって、条件に対する追加の制限
  ではない。この位置づけを文が明示する。

「ランを終わらせるターンであること」という限定表現は残さない。

### 保持しなければならないもの

- `references/batch-terminal-line.md` を唯一の SSOT として名指しし、出力の
  直前に Read する指示（既存テスト
  `test_section_instructs_reading_the_contract_doc_before_emitting` /
  `test_section_names_the_contract_document`）。
- 機会としての「a `--once` phase boundary」という文字列（既存テスト
  `test_section_covers_once_boundary_occasion` がこの部分文字列を見ている）。
- 「ここでは書式を再掲しない」という位置づけ（FR9 / NFR1）。

### contract-literal guard の制約（触れてはならない語彙）

`tests/test_batch_stop_contract_skill_wiring.py` の
`_find_contract_literal_violations` と
`tests/test_batch_stop_contract.py` の `TestBatchModePointer` により、
`batch-mode.md` 全体で次が禁止されている。書き換えはこの内側に収める。

- prefix リテラル
- 4 つのフィールド名トークンが**揃って**出現すること
- 11 個の停止理由コード
- センチネル `no-step`
- `state={値}` の形、および `--once` 境界の値のベアリテラル
- `state=` / `step=` / `reason=` / `detail=` のいずれかの部分文字列

現行の「prefix, field grammar and value sets」という言い回しはこの制約を
満たしており、同等の抽象度を保つ。

### 非退行（NFR4）

`## Non-packet gates` 表のデータ行 10 行と、catch-all（"ten rows above"）/
diff-size gate / per-command approval の各文言は触れない。`## Reporting`
以降も変更しない。

## Test Notes

  `_section` / `_strip_ws` / `_find_contract_literal_violations` を使う。
