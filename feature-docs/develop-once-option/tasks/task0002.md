# Task Plan: task0002 — ポインタ層（SKILL.md バッチ終端行 / batch-mode.md）の `--once` 対応と literal guard 拡張

## Goal

`--once` のフェーズ境界でも終端行を出すことを、値リテラルを一切書かずに 2 つの
ポインタ文書へ記述し、SSOT 分割が崩れていないことを `state` 値まで拡張した
literal guard で機械的に強制する。

## Requirements

FR9, FR10, FR11, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Modify
- `em-workflow/skills/develop/SKILL.md` — 「## バッチ終端行」 節の本文のみ
- `em-workflow/references/batch-mode.md` — `## Terminal line` 節のみ
- `tests/test_batch_stop_contract_skill_wiring.py` — contract-literal guard を
  `state` 値まで拡張し、新しい記述と誤検知不在を固定する

## Design

### ポインタ層が述べること／述べないこと

| 文書 | 追加する内容 | 触れてはならないもの |
|---|---|---|
| SKILL.md 「## バッチ終端行」 | 終端行の出力対象に `--once` のフェーズ境界で終わるターンが含まれること（「いつ出すか」のみ） | `state` の値・prefix・4 フィールドの文法・理由コード・sentinel |
| `batch-mode.md` `## Terminal line` | 同じ出力機会の拡張（IMPLEMENTATION.md D8） | 同上 |

`--once` の境界そのものの定義は SKILL.md の別の節が持つ（IMPLEMENTATION.md
D5、task0001 が記述する）。この節は「その境界で終わるターンも出力対象」と
参照するだけで、境界の定義を再掲しない。

### 維持しなければならない既存の保証

「## バッチ終端行」 節について、次はすべて現状のまま残る（NFR4、AC8）:

1. 「## 停止時の報告」 の直後にあり、その間に level-2 見出しが無い。
2. 出力の直前に `${CLAUDE_PLUGIN_ROOT}/references/batch-terminal-line.md` を
   Read し、そこに定義された prefix・フィールド文法・値の集合をそのまま使う、
   という指示。
3. 最後の assistant メッセージの末尾に 1 行だけ出力する、という規則（NFR5）。
4. 一般化された no-line 規則 — 停止条件 5、implement の launch ターンと wake
   ターンを非終端の例として名指しする形。
5. 既存の停止点の列挙（停止条件 2 / 3 / 4 / 6、フェーズ内のゲート中断、
   Step C 内の中断、Step A の feature 解決失敗、commit-docs.sh の 2 回目の
   exit 4、implement / verify フェーズが定める終端停止）。

`batch-mode.md` については、Non-packet gates 表の 10 データ行と catch-all /
diff-size / per-command の文言が不変（NFR4）。

### 終端状態の個数（FR11）

SKILL.md の 「同 SSOT が定める 2 つの終端状態のいずれか」 は、個数を固定せず、
どの `state` 値も名指ししない表現へ置き換える（IMPLEMENTATION.md D4）。
契約文書側の同種の文言は task0003 が扱う。

### literal guard の拡張（FR10）

拡張の規則は IMPLEMENTATION.md D2 が唯一の定義元。このタスクは
`tests/test_batch_stop_contract_skill_wiring.py` 側の実装を担う:

- 既存の検査（prefix リテラル、4 フィールド名の同時出現、理由コード、sentinel）
  は現状のスコープ・意味のまま。
- `state` 値の検査を D2 の形（契約固有の `state={値}` 形、および `--once`
  境界値の裸のリテラル）で追加し、両ポインタ文書に対してファイル全体で適用する。
- `completed` / `stopped` / `skipped` の裸の語は決して違反にしない。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR9): SKILL.md の 「## バッチ終端行」 節が、`--once` のフェーズ境界で

      「維持しなければならない既存の保証」 1-5 がすべて成立している。
- [ ] AC-2 (FR11): SKILL.md から 「2 つの終端状態」 のように個数を固定した表現が
      無くなり、置き換え後の表現がどの `state` 値も名指ししていない。
- [ ] AC-3 (FR9, NFR1, IMPLEMENTATION.md D8): `batch-mode.md` の
      `## Terminal line` 節が `--once` のフェーズ境界を含む出力機会を述べ、
      値リテラルを再掲せず、契約文書を名指しして出力直前に Read する指示を保つ。
      Non-packet gates 表は 10 データ行のままで、catch-all / diff-size /
      per-command の文言が不変。
- [ ] AC-4 (FR10): 拡張後の guard を実ファイル 2 つ（SKILL.md、batch-mode.md）に

- [ ] AC-5 (FR10, NFR3): 新しい `state` 値を再掲した偽造 SKILL.md 抜粋と偽造

      非空虚性ガードを付け、偽造テキストがスライサで見つかり実際に値を含むことを

      誤検知検証として明示的に検証する。
- [ ] AC-7 (NFR2, NFR3): `python3 -m unittest discover -s tests` が exit 0。
      `tests/test_batch_stop_contract_skill_wiring.py` は標準ライブラリのみを

## Test Notes

- 変更対象モジュールは既存の
  `tests/test_batch_stop_contract_skill_wiring.py` 1 つだけ（IMPLEMENTATION.md
  D6）。既存クラス・既存アサーションは削らず、拡張として足す。
- `state` 値集合の定数はこのモジュール内に自前で持ち、不在チェックにのみ使う。
  契約文書がその値を定義していることは**主張しない** — その文書は task0003 が
  所有し、このワークツリーにまだマージされていない可能性があるため（既存
  モジュールが理由コードで採っているのと同じ cross-task safety）。
- AC-5 の偽造テキストは、既存の negative proof（4 フィールド名の再掲、理由コード
  の再掲）と同じ組み立て方に揃える: スライサが見つけられる最小の節を作り、
  そこに新しい `state` 値を契約固有の形で書く。
- AC-6 は「実ファイルに対して違反 0 件」という形の検証になるため、AC-4 と
  アサーションが重なる。誤検知の意図を明示するために、`completed` /
  `skipped` / `stopped` が実ファイル中に実際に出現していること（非空虚性）も
  併せて確認する — 出現していなければ誤検知検証が空回りする。
- 端: `state=` の形は `batch-mode.md` の既存アサーションが別モジュールでも
  検査している。拡張が既存の意味を弱めない（`state=` 単独の不在検査を消さない）
  ことを確認する。
- 端: SKILL.md 側の guard スライスは 「## バッチ終端行」 からファイル末尾の
  `$ARGUMENTS` までに及ぶ。task0001 が別の節を足しても、それがこのスライスに
  入らない配置であること（IMPLEMENTATION.md D3-3）が前提。
