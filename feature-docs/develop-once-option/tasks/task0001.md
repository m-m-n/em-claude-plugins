# Task Plan: task0001 — develop SKILL.md に `--once` の引数処理・フェーズ境界・停止条件 7・対話モード終了行を追加する

## Goal

`em-workflow/skills/develop/SKILL.md` が `--once` を起動ごとのフラグとして定義し、
1 フェーズの境界（4 種）・停止条件 7・implement 途中で終わらない制約・対話モードの
終了行を述べる状態にする。新しいテストモジュールがその記述を構造的に固定する。

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR12, FR14, NFR2, NFR3, NFR4

  フェーズ境界 / 停止条件 7 / 非境界 / 対話モード終了行）を固定する構造アサーション

### Files to Modify
- `em-workflow/skills/develop/SKILL.md` — frontmatter の `argument-hint`、

## Design

### 追加する記述の責務

| 記述 | 置き場所 | 述べること |
|---|---|---|
| `--once` の引数 | 「引数処理」 の箇条書き 1 項目 | 指定時は 1 フェーズ実行してターンを終える / `--batch` と併用できる / `workflow.yaml` にも `phase-state/` にも記録しない（起動ごとの設定） |
| `argument-hint` | frontmatter | 既存の列挙に `--once` を加える |
| 停止条件 7 | 「ターンを終わらせていい唯一の条件」 のリスト末尾 | `--once` 指定時、1 フェーズが完了したとき |
| フェーズ境界の定義 | 新しい節（IMPLEMENTATION.md D3 の配置規則に従う） | IMPLEMENTATION.md D5 の 4 種の境界と、それぞれ「コミット済みになった時点で終わる」こと。次の起動が再開する位置 |
| 非境界 | 同じ節 | implement フェーズの途中では終わらない（in-flight の実装者がプロセス終了で失われるため）。停止条件 5 の待機ターン、implement の launch / wake ターンは非終端 |
| 対話モードの終了行 | 同じ節 | 終了報告に加える 1 行。`{step}` と `{feature}` をそのまま含む形で本文に書く |

### 事前条件・事後条件

- 事前条件: 既存の 6 つの停止条件とその文言、既存の節見出し、既存の
  「これらに該当しない限り」 で始まるアンカー文が現状のまま存在する。
- 事後条件: 上表の記述がすべて存在し、既存の 3 つのテストモジュール
  （`tests/test_develop_skill_rewiring.py`、
  `tests/test_batch_stop_contract_skill_wiring.py`、
  `tests/test_batch_stop_contract.py`）が変更なしで緑のまま。

### 配置の制約

IMPLEMENTATION.md D3 が唯一の定義元。とくにこのタスクに効くのは次の 3 点で、
いずれも既存モジュールのスライサが依存している:

1. 新しい節は 「## 停止時の報告（停止条件 2-4 のみ）」 より前に置く。
   「## バッチ終端行」 以降には何も追加しない。
2. 「## 停止時の報告」 と 「## バッチ終端行」 の間に level-2 見出しを作らない。
3. 停止条件リストは 1-6 をそのままにして 7 を足し、リスト直後のアンカー文を残す。

加えて、SKILL.md には終端行の `state` 値リテラルを一切書かない（D3-5）。
`--once` で終わったターンの状態は役割で表現し、値は SSOT に委ねる。新しい記述に
`gate_id` / 「gate ID」 の語を持ち込まない（D3-6）。

### 対話モードの終了行

SPEC.md FR12 が定める 1 行を、プレースホルダを含む形のまま本文に書く。
テストは空白除去後の完全一致で照合する（この文書は日本語を空白なしで
折り返すため）。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1): 「引数処理」 に `--once` の項目があり、(a) 1 フェーズ実行して
      ターンを終える、(b) `--batch` と併用できる、(c) `workflow.yaml` にも
      `phase-state/` にも記録しない（起動ごとの設定）、の 3 点をすべて述べている。
      frontmatter の `argument-hint` に `--once` が含まれる。
- [ ] AC-2 (FR2, FR3, FR4, FR5): SKILL.md が 4 種すべてのフェーズ境界を述べて
      いる — 通常 step の `completed`（`design` のみ `skipped`）+ コミット、
      `retrospect` の `completed`（Step C は次の起動）、verify 失敗時の rework
      パッチ適用・`implement` と `verify` の `pending` 復帰・コミット、
      2 つの自動再入 routing コミット（implement I.2.c の `create-plan` →
      `needs_update`、rework の spec-change による `create-spec` →
      `needs_update`）。各境界で「コミット済みになった時点で終わる」ことが
      読み取れる。
- [ ] AC-3 (FR6, NFR4): 「ターンを終わらせていい唯一の条件」 に項目 7 が加わり、
      項目 1-6 の文言は 1 文字も変わらず、リスト直後のアンカー文が残っている。
      既存モジュールの bullet-3 スライス（`3. ` から `4. ` まで）が従来どおり
      機能する。
- [ ] AC-4 (FR14): `--once` が implement フェーズの途中でターンを終えないこと、
      および停止条件 5 の待機ターンと implement の launch / wake ターンが
      非終端であることが述べられている。
- [ ] AC-5 (FR12): 対話モードの `--once` 終了行が、SPEC.md FR12 の文言と
      （`{step}` / `{feature}` のプレースホルダを含めて）空白除去後に完全一致
      する形で存在する。
- [ ] AC-6 (NFR4, IMPLEMENTATION.md D3): 追加内容が D3 の配置不変条件をすべて
      満たし、SKILL.md のどこにも終端行の `state` 値リテラルが現れず、新しい
      記述に `gate_id` / 「gate ID」 が現れない。既存の 3 モジュールを 1 行も
      変更せずに全体スイートが緑。
- [ ] AC-7 (NFR2, NFR3): `tests/test_develop_once_option.py` が
      `python3 -m unittest discover -s tests` で発見され、標準ライブラリのみを
      import し、このタスクが追加した matcher にはそれぞれ negative proof と
      非空虚性ガードが付いている。全体スイートが exit 0。

## Test Notes

- 単体レベルの構造アサーションのみ。ランタイムの挙動変更が無いため統合テストは
  無い（NFR2）。既存の `tests/test_develop_skill_rewiring.py` と同じ流儀
  （自前のヘルパー、モジュール間 import なし）に従う。
- AC-2 の「4 種の境界が揃っている」判定はヘルパー関数（matcher）になるため、
  negative proof（3 種しか述べていない偽造テキストを拒否する）と非空虚性ガード
  （偽造テキストがスライサで見つかり、実際に 3 種を含む）を付ける。
- AC-1 / AC-3 / AC-4 / AC-5 は素の存在・不在アサーションで足りる（純粋な
  regression / presence ガードは negative proof 免除の慣習に該当する）。ただし
  AC-5 は完全一致なので、空白除去した文字列同士で比較する。
- AC-3 の回帰: 「ターンを終わらせていい唯一の条件」 見出しからアンカー文までを
  切り出し、`3. ` と `4. ` の索引が取れること、`7. ` が存在すること、1-6 の
  各行が現状の文言のままであることを確認する。
- AC-6 のうち `state` 値リテラルの不在は、このモジュールでは値の綴りを
  ハードコードせず「IMPLEMENTATION.md D1 が定める値」を自モジュールの定数として
  1 箇所に置き、不在チェックにのみ使う（他モジュールから import しない）。
- 端: 停止条件リストへの追加が 「これらに該当しない限り」 のアンカーより後ろに
  はみ出すと既存スライスが壊れる。この配置自体をアサーションで固定する。
- 端: frontmatter の `argument-hint` は 1 行の文字列なので、`--batch` など既存の
  値が消えていないことも併せて確認する。
