# Task Plan: task0004 — プラグイン version を 0.1.51 に上げ、2 つのマニフェストの一致を機械的に固定する

## Goal

`em-workflow` の `version` を 2 つのマニフェストで同時に 0.1.50 から 0.1.51 へ
上げ、以後この 2 箇所が食い違ったらテストが落ちる状態にする。

## Requirements

FR13, NFR2, NFR3

## Scope

### Files to Create
- `tests/test_plugin_version_parity.py` — 2 つのマニフェストの `version` 一致と
  bump 済みであることを固定する

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — `version` を 0.1.51 へ
- `.claude-plugin/marketplace.json` — em-workflow エントリの `version` を
  0.1.51 へ

## Design

### 変更の内容

`.claude/rules/core-plugin-version-bump.md` が定める 2 箇所を同じ値にする。
現行値は両方 0.1.50（SPEC.md A5 で確認済み）、目標は 0.1.51。それ以外の
フィールド（`name` / `description` / `source` / `category` / `author` など）は
触らない。

### マニフェストの形の違い

`.claude-plugin/marketplace.json` は `plugins` 配列を持ち、そのうち
`name` が `em-workflow` のエントリだけが `version` キーを持つ。もう一方の
エントリ（em-review）には `version` キーが無い。したがって照合は配列の
インデックスではなく `name` で引く（IMPLEMENTATION.md D7）。

### 検証の責務

- 一致: 2 つのマニフェストの em-workflow の `version` が同一であること。
- 前進: 変更前の値（0.1.50）より大きいこと。将来の bump でも落ちないよう、
  文字列比較ではなくドット区切りの数値列としての比較で「より大きい」を判定する。
- 既存チェッカとの関係: `em-workflow/scripts/check-plugin-invariants.py` は
  version の一致を検査しない。このタスクが足すテストがその欠けを埋める。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR13): `em-workflow/.claude-plugin/plugin.json` の `version` と
      `.claude-plugin/marketplace.json` の em-workflow エントリの `version` が
      ともに `0.1.51` になっている。他のフィールドと em-review エントリは
      変更されていない。
- [ ] AC-2 (FR13, NFR3): `tests/test_plugin_version_parity.py` が、(a) 2 箇所の
      `version` が同一であること、(b) その値がドット区切りの数値列として
      0.1.50 より大きいこと、を検証する。marketplace 側のエントリは `name` で
      選択する。
- [ ] AC-3 (NFR2, NFR3): `python3 em-workflow/scripts/check-plugin-invariants.py`
      をリポジトリルートに対して実行して exit 0。
      `python3 -m unittest discover -s tests` が exit 0。新しいモジュールは
      標準ライブラリのみを import する。

## Test Notes

- JSON の読み取りは標準ライブラリだけで済む。ファイルパスはリポジトリルート
  からの相対で解決する（`tests/` の既存モジュールと同じ流儀）。
- 素の一致・比較アサーションのみなので、matcher の negative proof は不要
  （NFR3 の免除規定に該当する純粋なガード）。ただし「エントリが見つからない」
  ケースで暗黙に成功しないよう、em-workflow エントリが実際に取得できたことを
  先に確認する（非空虚性）。
- 端: marketplace.json の em-review エントリには `version` キーが無い。全
  エントリを一律に走査する書き方だと KeyError になるか、逆に何も検査しない形に
  なりうる。
- 端: 「0.1.50 より大きい」は将来の bump で自動的に満たされ続ける形にする。
  0.1.51 と完全一致で固定すると、次の bump のたびにこのテストが落ちる。
