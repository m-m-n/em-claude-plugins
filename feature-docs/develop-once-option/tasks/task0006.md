| 箇所 | 現状 | 問題 |
|---|---|---|
| SKILL.md 「## バッチ終端行」冒頭の定義文 | 出力主体を「ランを終わらせるターン（Step C の完了処理、または下記に列挙する終端の停止条件で終わるターン）」と二重に限定している | 直後の対象列挙には `--once` のフェーズ境界が加わっているが、`--once` 境界ターンはランを終わらせない。定義文だけを読むと終端行を出さない判断になり、FR7 / NFR5 が要求する出力が落ちうる |

### R-C: 出力条件の定義

定義文は「そのターンで、ランが同 SSOT の定める終端状態に達したか」を条件と
して述べる。Step C の完了処理・`--once` のフェーズ境界・列挙された終端の
停止条件は、その条件が成り立つ場合の列挙であって、条件に対する追加の制限
ではない。この形にすると、末尾の「終端状態に達していない場合は出力しない」
という規則と定義文が同一の判断基準を指し、二重定義が消える。

保持する既存の記述（いずれも既存アサーションが固定している）:

- 「最後の assistant メッセージの末尾に終端行を 1 行出力する」という文言
  （空白除去比較で照合されている）。
- 行の書式・フィールドの意味・値の集合の唯一の SSOT が
  `references/batch-terminal-line.md` であること、ここでは「いつ出すか」だけを
  定めること。
- 出力の直前に `${CLAUDE_PLUGIN_ROOT}/references/batch-terminal-line.md` を
  Read し、そこに定義された prefix・フィールド文法・値の集合をそのまま使う、
  という指示。
- 対象の列挙（Step C の完了処理、`--once` のフェーズ境界、停止条件 2 / 3 /
  4 / 6、フェーズ内のゲート中断、Step C 内の中断、Step A の feature 解決失敗、
  commit-docs.sh の 2 回目の exit 4、implement / verify が定める終端停止）。
- 一般化された no-line 規則（停止条件 5 がその 1 インスタンスであり、
  implement の launch ターンと wake ターンも同様）。FR14 の非境界がここで
  担保されている。
- 「同 SSOT が定める終端状態のいずれか」— 個数を言わず、値も名指ししない
  （FR11 / IMPLEMENTATION.md D4）。

### 変更が守る制約（FR9 / NFR1 / IMPLEMENTATION.md D3）

- `state` の値 literal、prefix、4 つのフィールド名の同時出現、停止理由コード、
  sentinel をいずれも導入しない。ガードはファイル全体に適用される。
- `gate_id` / "gate ID" の言及を新たに導入しない（D3 項目 6）。
- 「## 停止時の報告」と「## バッチ終端行」の間に level-2 見出しを作らない。
  subsection の後ろに何も追記しない（D3 項目 2・3）。

### R-D: 偽陽性証明の形

ガードが whitelist 語を flag しないことの証明は、合成サンプルに対して行う。
モジュールは、実ファイルに `stopped` 等の語が現れるか否かについて何も
主張しない。実ファイルに対する保証は、既存の 2 本の全文 0 違反チェック
（SKILL.md / batch-mode.md）が引き続き担う。`completed` / `skipped` が実
ファイルに実在することを見る非空虚性チェックは、それらが実際に通常語彙として
使われているため有効であり、そのまま残す。

  されるため、複数トークンにまたがる照合は既存の `_strip_ws` 慣行に従って

  回帰ガードで、同モジュールの慣行どおり免除。
