# Task Plan: task0006 — Pin the inspection of a static --args-json value beside an equals-form flag word with a non-static destination

## Provenance

- source: verify
- source_ids: AC-17

## Goal

The flag-reading unit tests pin the current judgment of IMPLEMENTATION.md D2
step 1: an `=`-form flag word of a known value-taking name whose value part is
not static (for example `--mcp="$S"`) does not stop the inspection, so the
static `--args-json` value of the statement is inspected. With that,
`python3 -m unittest tests.test_destructive_guard_args_json` and
`python3 -m unittest discover -s tests` pass (SPEC.md AC-17).

## Requirements

FR3, FR6, FR13

## Scope

### Files to Create

None.

### Files to Modify
- `tests/test_destructive_guard_args_json.py` — the TestFlagReading entries for the equals form of a flag word whose value part is not static

## Design

The flag reading is pinned in IMPLEMENTATION.md D2 (step 1 revised in this
round) and D5. This section gives the task-level detail. The hook already
reads these forms as D2 step 1 states; this task changes no hook code.

### Starting point

The verify run of round 2 found one failing subtest:
TestFlagReading's test of flag-position words that are not static holds the
entry labelled "equals form with a destination", the command
`mcp-bridge run --mcp="$S" --args-json '{"command":"ls"}'`, and expects
"nothing to do". The hook inspects that statement (one inspected result),
which is what SPEC.md FR3 (c), FR3 (g) and FR6 require: a non-static
destination and the `=` form are not FR6 forms. The test is wrong; the hook is
right.

### The change (FR13)

- The entry labelled "equals form with a destination" leaves the test of
  flag-position words that are not static. The same command becomes an entry
  of the test of a destination that is not static, which expects exactly one
  inspected result.
- That test also gains these inspected forms, each a non-static value part
  after the first `=` of a known value-taking name, followed by the static
  `--args-json` value of the class (the command whose top-level command
  string is ls):
  - the tool name with an unquoted variable as its value part
    (`mcp-bridge run --tool=$T --args-json` and the value);
  - the session name with a double-quoted variable as its value part
    (`mcp-bridge run --session="$SID" --args-json` and the value).
- A test pins that, for the statement with `--mcp="$S"` before the value, the
  one inspected value holds exactly the command string ls, and that the
  Unrestorable flag of the result is not set.
- The test of flag-position words that are not static gains these entries,
  each expecting "nothing to do" with the Unrestorable flag not set:
  - a name part that is not static before the `=`
    (`mcp-bridge run --$N=x --args-json` and the value);
  - an unknown name with a non-static value part
    (`mcp-bridge run --unknown="$S" --args-json` and the value).
- The test of a non-static value word keeps its entry "equals form with a
  substitution" (`--args-json="$(cat a.json)"`): that inline value is
  skipped and there is no other value, so the statement stays "nothing to do".
- Every other test and every other entry keeps its assertions.

### Red step

The moved entry and the new inspected entries pass against the current hook;
the new not-inspected entries pass as well. The red evidence for this task is
the failing subtest of the verify run: before the change, running the unit
test module reports the "equals form with a destination" subtest as failed
(expected "nothing to do", obtained one inspected result); the implementer
report records that run. If any new entry fails against the current hook, that
is a plan deviation to report, and the hook is not changed.
