# Task Plan: task0003 — Read mcp-bridge run flags as mcp-bridge does, and ask instead of skipping silently

## Goal

destructive-guard reads the words after `run` of an `mcp-bridge run` statement
the way mcp-bridge reads them and inspects every static `--args-json` value,
whatever its destination. A decoded top-level `command` no longer takes from
the payload counter. A bound that leaves a `command`, a body or a payload
unscanned, and a static word whose quoting cannot be restored, give an ask
settled after the queue is drained, so a deny found still wins. The step's
bookkeeping leaves statements(). New cases and revised unit tests pin it.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR9, FR10, FR11, FR12, FR13, NFR1, NFR2, NFR3, NFR4, NFR5

## Design

The component names and contracts, decisions D1 to D7 and the out-of-scope
list O1 / O2 are pinned in IMPLEMENTATION.md. This section gives the
task-level detail.

### Starting point

The merged code (task0001, task0002) reads the words after `run` only in the
canonical flag sequence: every other form, a repeated `--args-json` and a
`--mcp` / `--tool` value that is not static make the statement not inspected.
It reads value words through a quote-residue mode of
`_read_word_as_written()`, which cannot tell a word that is not static from
one whose quoting cannot be restored. statements() calls the decision inline,
adds its charge before checking the budget, queues each decoded `command`
string against the payload counter (none at zero), tracks the step's overrun
with two flags of its own, and extracts `-c` / `eval` / here-string payloads
only while the counter is above zero.

### Decision per statement (`_mcp_bridge_args_json_chunks()`)

1. **Target (FR1)**: unchanged.
2. **Notion pair (FR2)**: the canonical reading of IMPLEMENTATION.md D2,
   unchanged and not widened. A statement it determines as the pair gives
   "nothing to do", with no Unrestorable flag.
3. **Flag reading (FR3, FR6, FR11)**: every other target statement is read as
   IMPLEMENTATION.md D2 states, steps 1 to 4. The first stop decides: a
   flag-position word that is not static, an unknown name or a value-taking
   flag without a value gives "nothing to do"; an unrestorable flag-position
   word sets Unrestorable and ends the reading with no value inspected; `--`
   and a positional word end the reading normally.
4. **Values (FR3 (e), (f), (g), FR6, FR11)**: no `--args-json` gives "nothing
   to do". Each `--args-json` value is handled on its own, in order: a value
   word of its own is classified (D5) and skipped when not static, or skipped
   with Unrestorable set when unrestorable; an inline value is the text after
   the first `=` of the restored flag word, anchored at that flag word.
5. **Per static value (FR4, D3)**: the nesting pass, the decode keeping every
   pair, and the walk, as task0001 built them. A syntax error or a top level
   that is not an object skips that value; nesting above `MAX_ARGS_JSON_DEPTH`
   or any other decoder failure sets Overrun.
6. **Result**: per inspected value its anchor word, bodies and `command`
   strings in document order; the total charge (at least, for each decoded
   value, its rebuilt length plus one per JSON value visited plus the length
   of each string searched); the Overrun and Unrestorable flags.

### Word reader (D5)

The three outcomes and what leads to each are in IMPLEMENTATION.md D5. Two
details for this task:

- A locale quote whose content holds an unescaped `$` or backtick holds a
  parameter expansion or a substitution: not static. Without one: unrestorable.
- `_read_word_as_written()` loses its quote-residue mode and its docstring
  paragraph on it; its result for the masking-stop caller stays exactly as it
  is.

### Collaborator `_queue_args_json_chunks()` (NFR5, FR5, FR7, FR11)

Its contract is IMPLEMENTATION.md's. Two details:

- **Anchors**: each queued entry is anchored like a payload: the statement
  index, the token index of its value's anchor word in the statement's tokens
  as written, and an ordinal that keeps the entries of one word in document
  order, bodies first, then `command` strings (as task0001 did).
- **Marks**: each entry carries the chunk's derived Python-body mark, and no
  substitution index.

### statements() side (NFR5, FR12, D6, D7)

- One `_DeferredAsks` record and the scan state are created per run. Every
  statement statements() yields gets exactly one call of the collaborator,
  after its payload extraction; the loop holds no other `--args-json` logic
  (the per-chunk and per-run overrun flags and the inline queueing go away).
  A short comment at the call site names the collaborator; the FR10
  explanation sites are task0004's.
- The payload extraction runs for every lexed statement whatever the counter
  holds (D7): a payload that is not blank is queued and takes one while the
  counter is above zero; with the counter at zero it is not queued and the
  scan-budget ask is held in the record.
- After the queue is drained the record is settled (D6). The two existing
  early returns on an ordinary overrun stay as they are.

### Writing the cases file

The cases file is JSON, so each backslash of a shell text above is written
escaped and each `"` is written as an escaped quote. The command the runner
sends must equal the shell text exactly: in TS-29 the six characters
backslash, `u`, `0024` reach the hook, not a `$` (an editing tool can decode
such an escape on the way into the file, IMPLEMENTATION.md D4); in TS-21 the
two characters backslash and `0` sit inside the ANSI-C quote. After writing,
each new case's command is read back from the file, compared with the shell
text of its row, and the repetitions of TS-18, TS-19 and TS-22 are counted.

### Existing cases and FR12

Before the hook changes, the existing cases are searched for an allow case
that holds 26 or more `-c` / `eval` / here-string payloads in any chunk. If
one exists, or if the run after the change turns an existing allow case into
an ask through FR12, the task stops without editing that case and reports it
(FR9).

### Unit tests (`tests/test_destructive_guard_args_json.py`, FR13)

The module keeps loading the hook from its path, uses the standard library
only, and adapts its spy and helpers to the revised result. Revised:

- **TestPayloadCounter**: decoded `command` strings take no count: with the
  counter used up by 25 payloads ahead, every `command` string of the value is
  still queued; with 25 `command` strings ahead, a `-c` payload after them is
  still queued; with the counter used up, one more payload that is not blank
  is not queued and the run's early-stop list ends as the scan-budget ask.
- **TestFlagReading**: inspected — the canonical forms of task0001 that are
  not the pair, a quoted, double-quoted or backslashed flag name, the `=`
  form, single-dash flags, a value before `--` or a positional word, each
  value of a repeated `--args-json`, a `--mcp` or `--tool` value that is not
  static, the notion pair written with a quoted flag name; not inspected — the
  notion pair in the canonical reading (in any flag order), an unknown flag, a
  value-taking flag with no value word, no `--args-json`, a second word other
  than `run`, no subcommand, a flag-position word that is not static, and the
  value word forms that are not static.
- **TestDocstring**: the O1 and O2 wording of IMPLEMENTATION.md, and the
  absence of every form IMPLEMENTATION.md says is not out of scope.

Added:

- **Unrestorable (FR11)**: an ANSI-C NUL, a character outside ASCII, an escape
  `_decode_ansi_c()` does not handle, and a locale quote, in a value word and
  in a flag-position word, each set Unrestorable; a flag-position one leaves
  no value inspected; a word that also holds an FR6 (1) element sets nothing;
  the notion pair sets nothing; the settled early-stop list is the
  `args-json-unrestorable` ask alone, or the scan-budget ask alone when both
  are held; with no early-stop list the ask is emitted.
- **Deferral (FR7)**: on Overrun, and on a charge that does not fit, the
  scanned total is unchanged, nothing of the statement is queued, a `-c`
  payload queued before the statement still has its statements yielded, the
  step does nothing for later statements, and the settled early-stop list is
  the scan-budget ask.
- **Deny wins**: the hook's judgment of a command that holds an
  unconditional `git branch -D` statement beside the TS-21 form, and beside
  the TS-22 form, is deny.
- **Structure (NFR5)**: statements() calls `_queue_args_json_chunks()` exactly
  once per statement it yields, and `_mcp_bridge_args_json_chunks()` is called
  only from it.

The decoder-failure, charge and walk tests of task0001 keep their assertions,
adapted to the revised result.

## Test Notes

- AC-1 to AC-7 run through the case runner and the unit test module; each new
  case is one test. The runner is the hook's test harness
  (`.claude/rules/hook-tests.md`).

  under the unchanged hook is a plan deviation to report: its scenario does not
  reproduce the gap.

  hold an ask of its own; if one does, that is a plan deviation to report.

  alone; how the unit tests drive it is the implementer's choice.

  commit; `_read_word_as_written()`'s masking-stop result is covered by the
  existing case suite and unit tests.

  report; the case is not edited.
