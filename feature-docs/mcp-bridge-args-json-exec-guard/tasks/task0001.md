# Task Plan: task0001 — Decode and inspect the --args-json value of mcp-bridge run statements

## Goal

For every `mcp-bridge run` statement other than the notion pair, destructive-guard
rebuilds the `--args-json` value under Bash quoting rules, decodes it as JSON,
and queues the substitution candidates of every decoded string and every
top-level `command` string for the ordinary re-scan. A destructive command
written with JSON or shell escapes, or as plain text in the top-level
`command`, is denied. The case suite and unit tests pin the behaviour.

### Terms

- **Value word**: the word right after the `--args-json` flag word.
- **Static word**: a word the value rebuild below returns a value for.
- **Unquoted run**: a word whose source text equals its value and holds no
  quote character, backslash, `$` or backtick.
- **Candidate rule**: the rule the lexer applies to single-quote content
  (P8, `_lex_quote_candidates()`): a `$(` closes at the `)` that balances its
  own `(` when every `(` and `)` counts alike, failing that at the first `)`
  after it, and with none it is no candidate; a backtick closes at the next
  backtick, and with none it is no candidate; the search resumes after a
  candidate's end. A candidate's body is the text between its opener and its
  closer.

### Per-statement flow of `_mcp_bridge_args_json_chunks()`

1. **Target (FR1)**: the command word that `head()` returns over the
   statement's shaped words is exactly `mcp-bridge` and carries no
   substitution flag, and the first word after it is exactly `run`.
   Otherwise the result is Not inspected. A statement in which
   `mcp-bridge run` is only text inside another command's argument (TS-11)
   has another command word.
2. **Flag reading (D2)**: the words after `run` are read left to right; the
   first is in flag position. A word in flag position is one of `--mcp`,
   `--tool`, `--args-json`, `--format`, `--session` or `--dry-run`, written as
   one unquoted run. `--dry-run` takes no value; each other flag takes the
   next word as its value whatever it holds, and the word after a value is in
   flag position. Any other word in flag position (`--`, a positional word, a
   single-dash or `=` form, a quoted flag word, an unknown name), or a
   value-taking flag with no value word, gives Not inspected (FR6).
3. **Notion pair (FR2)**: when `--mcp`, `--tool` and `--args-json` each
   appear exactly once, the `--mcp` value is `notion` and the `--tool` value
   is `notion-create-comment`, each written as one unquoted run, the result is
   Not inspected.
4. **Shape (FR6)**: `--args-json` appearing other than exactly once, or any
   `--mcp` or `--tool` value word that is not static, gives Not inspected. A
   missing or repeated `--mcp` / `--tool` does not, on its own.
5. **Rebuild (FR3)**: the value word is rebuilt as described below. A value
   word that is not static gives Not inspected.
6. **Nesting bound (D3)**: one pass over the rebuilt value, outside JSON
   strings (a `"` opens and closes a string; inside one, a backslash escapes
   the next character), counts `[` and `{` up and `]` and `}` down. A depth
   above `MAX_ARGS_JSON_DEPTH` gives Overrun.
7. **Decode (FR4, D3)**: the rebuilt value is decoded as standard JSON with
   the standard library's decoder, keeping every key/value pair of each object
   in source order, duplicates included, instead of only the last value of a
   repeated key. The decoder's own acceptance is not narrowed. A JSON syntax
   error gives Not inspected (FR6). Any other decoder failure gives Overrun. A
   decoded top level that is not an object gives Not inspected (FR6).
8. **Walk (FR4, FR5)**: an iterative walk visits the member values and array
   elements at every depth, in document order. Each string value is searched
   with the candidate rule, and each body that is not blank is collected.
   Object keys are not searched. Each member of the top-level object whose key
   is exactly `command` and whose value is a string, duplicates included, is
   collected as a command string when it is not blank. A `command` below the
   top level, and a value that is not a string, get only the candidate search.
9. **Result**: Inspected, with the charge, the bodies, the command strings and
   the value word.

### Value rebuild (FR3)

The value word is read from the chunk's source text and the lexer's top-level
regions, by the rules of `_read_word_as_written()`:

- a single-quote region is its content;
- a double-quote region is its content with `\$`, `` \` ``, `\"`, `\\` and
  backslash-newline resolved, and is not static when it holds an unescaped
  `$` or backtick;
- an ANSI-C-quote region is decoded by `_decode_ansi_c()`, and is not static
  when that decoder gives no result;
- outside quotes, a backslash keeps the next character, and with a newline
  after it both vanish;
- regions and unquoted text joined in one word are concatenated.

Not static: any other region kind (a substitution, a parameter or arithmetic
expansion, a locale quote, an array subscript), an unquoted `$` or backtick,
the unquoted glob, brace and tilde forms `_read_word_as_written()` rejects, and
a word that is a substitution as a whole.

One difference from `_read_word_as_written()`: the marker residue that the
marking left for a single-quote candidate (a `$(` or backtick inside a
single-quote or ANSI-C-quote region of the word) does not make the word not
static. The candidate's characters are taken from the source as the literal
text Bash passes on. Residue of a real substitution still makes the word not
static. `_read_word_as_written()`'s result for its existing caller (the
masking-stop check) does not change; whether the rebuild extends it behind an
option or uses a sibling reader is the implementer's choice.

The same reading decides whether a `--mcp` or `--tool` value word is static.

### Caller side in `statements()` (FR4, FR5, FR7, A4)

- **Where**: in the statement loop, after a statement from a lexed segment is
  yielded, next to the payload extraction and independent of the payload
  counter for the bodies. A short comment at the call site names the
  component and FR3 to FR5. The FR10 explanation sites are not edited.
- **Charge**: the Inspected result's charge is added to the running scanned
  total. When the total passes `scan_budget`, and on an Overrun result, the
  loop takes the same early stop it takes for its own overrun: with no
  early-stop list the scan-budget ask is emitted, otherwise
  `SCAN_BUDGET_ASK` is appended and the scan ends.
- **Bodies (FR4)**: each body becomes a pending entry like a substitution
  body: no substitution index, the chunk's derived Python-body mark, and an
  anchor at the value word in the payload anchor form (statement index, the
  value word's token index, and an ordinal that keeps the entries of one word
  in document order).
- **Command strings (FR5)**: each command string becomes a pending entry like
  a `-c` payload, anchored the same way. One is taken from the payload counter
  that `MAX_SHELL_PAYLOAD_EXPANSIONS` sets for the whole input per queued
  command string. While the counter is zero, no command string is queued
  (A4); bodies are still queued.
- A queued entry is charged again when it is popped, as every chunk is.

### Charge (FR7)

The charge of one Inspected value is at least the rebuilt value's length (the
nesting pass and the decode) plus, for the walk, one per JSON value visited
and the length of each string searched. The payload counter is a separate
count and is not touched by the charge.

### Writing the cases file

The cases file is JSON, so each backslash of a shell text above is written
escaped and each `"` is written as an escaped quote. The command the runner
sends must equal the shell text exactly: the six characters of `$` must
reach the hook, not a `$`. After writing, each new case's command is read back
from the file and compared with the shell text of its row.

### Unit tests (`tests/test_destructive_guard_args_json.py`)

The module loads the hook from its path, as the existing unit tests that load
it do, and uses the standard library only.

- **Decoder failure (TM-3)**: with the decoder made to fail with a failure
  that is not a JSON syntax error, the component gives Overrun; with a value
  that is a JSON syntax error, it gives Not inspected.
- **Charge (TM-4, FR7)**: the charge of an Inspected value is at least the
  rebuilt value's length plus the number of JSON values visited.
- **Payload counter (FR5, A4)**: through `statements()`, a command whose
  `mcp-bridge run` statement follows enough `bash -c` payloads to use up the
  counter yields the candidate body of its decoded `command` but not the
  command string itself; with one count left, both are yielded.

### Order (NFR3)

The new cases are added before the hook changes. A runner run against the
unchanged hook reports every new deny and ask case as failed with obtained
decision allow, and every new allow case as passed. The implementer report
records that run. Then the hook changes.
