## Design

- **What fails, and why.** `TestSpecificVersionValues.test_em_workflow_manifest_and_entry_agree_on_the_current_version`
  requires `em-workflow/.claude-plugin/plugin.json` and the em-workflow entry of
  `.claude-plugin/marketplace.json` to exactly equal `PLUGIN_SPECS["em-workflow"]["expected"]`.
  task0001 moved both manifests to 0.2.1 (FR7). The literal still reads "0.2.0", so this
  one test fails. The module's own comments say a later em-workflow bump updates this
  literal.
- **Change.** Replace only the em-workflow `expected` literal with "0.2.1". The comment
  block stays as it is, plus one appended line that names routeback-residual-connections
  and 0.2.1. The line follows the style of the existing comment lines.
- **Keep the exact-match form.** Do not change the comparison to `>=` or to a
  baseline-plus-equality check, even though IMPLEMENTATION.md D5 describes that form for
  new version modules. D5 governs the module task0001 created. This task changes only a
  pre-existing module's pin value.
- **Leave everything else unchanged.** Other `PLUGIN_SPECS` entries (for example
  em-review), other constants, test methods and classes, and existing comment lines stay
  byte-identical.
- **No other modules.** Other version-bump modules that pin em-workflow may still fail on
  0.2.1 after this change. Report each one as a deviation, and do not edit it. This task
  covers only the module named in review finding aef23290e7d97475.
