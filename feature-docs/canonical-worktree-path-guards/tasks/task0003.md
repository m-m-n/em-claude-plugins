# Task Plan: task0003 — Invocation contract: link-resolving --task-worktree comparison

## Goal

The Same-session extension invocation contract in implement-phase.md states
that `--task-worktree` (`$WT_ROOT/{T}`, supplied whether or not that path
exists) is compared with the Agent index entry's recorded worktree after
links are resolved on both sides. The doc-contract test pins the new clause
and proves that the old "plain string" wording is gone.

## Requirements

FR5, NFR1

## Scope

### Files to Modify
- `em-workflow/references/implement-phase.md` — the --task-worktree clause in the I.2.b Same-session extension invocation contract
- `tests/test_stale_launched_missing_artifacts_doc_contract.py` — updated R4_NEW_STATEMENT, a negative-proof test for the removed comparison wording, and a standard-library import check

## Design

### The clause in implement-phase.md

The clause sits inside the seven-evidence-input list of the I.2.b
Same-session extension invocation contract.

- **Kept**: the flag name, the value as the task's expected worktree path
  (`$WT_ROOT/{T}`), "supplied whether or not that path exists", the
  reference to the Agent index entry's recorded worktree, and the trailing
  `(SC-2)` provenance marker.
- **Replaced**: "compared by the identity-binding step as a plain string
  against". The new text says the identity-binding step compares the value
  with the recorded worktree after resolving links on both sides. This is
  the rule of SC-2 in IMPLEMENTATION.md, stated at the level of detail
  FR5 requires.
- **Untouched**: every other sentence of implement-phase.md.

The exact wording is this task's choice (IMPLEMENTATION.md D3).
`R4_NEW_STATEMENT` equals the new clause after whitespace normalization.

### Test changes

- `R4_NEW_STATEMENT` is updated to the new clause. The existing tests that
  iterate over the R2/R3/R4 new statements then cover presence and
  forged-removal detection unchanged.
- A new test class adds three pieces: a verbatim pre-change excerpt of the
  clause as it reads at the base revision, a forbidden phrase (the "as a
  plain string" comparison wording) and a retained anchor (a part of the
  clause that survives the change). Its tests assert that the forbidden
  phrase is absent from the normalized I.2.b section, that the phrase and
  the anchor are both present in the pre-change excerpt (negative proof),
  and that the anchor is present in the live section.
- Existing constants other than `R4_NEW_STATEMENT`, and every existing test
  name and body, stay as they are.
