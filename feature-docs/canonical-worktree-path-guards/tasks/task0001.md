# Task Plan: task0001 — Launch guard: git-common-dir project-root fallback

## Goal

In linked layouts, the launch guard derives the project root for the
canonical `worktree_path` from git's common dir. A launch from the main
worktree is allowed, a launch from inside another worktree is denied before
the journal is touched, and states that cannot be decided still fail open.

## Requirements

FR1, FR2, FR3, FR6, NFR1, NFR2, NFR4, NFR5

## Scope

### Files to Create
- `tests/test_queue_launch_guard_linked_layout.py` — linked-layout subprocess tests (FR6), segment-absent fail-open tests, fallback call-shape and failure tests, hook docstring document test, standard-library import check for the hook and this module

### Files to Modify
- `em-workflow/hooks/queue_launch_guard.py` — project-root derivation gains the git-common-dir fallback; module docstring updated

## Design

### Project-root derivation

Contract: given a `worktree_path` that has already passed the hook's
existing validation, return the project root or "undetermined".

1. The normalized path contains `/.claude/worktrees/em-workflow/` →
   the root is the prefix before its last occurrence. This is today's
   behaviour, unchanged, including today's outcome for a segment at the
   very start of the path (undetermined, no fallback).
2. The segment does not occur at all → run
   `git rev-parse --path-format=absolute --git-common-dir` once, with
   `worktree_path` as its working directory, bounded by the existing
   `GIT_TIMEOUT_SECONDS`. Exit 0 with non-empty trimmed output → the root
   is the parent directory of the normalized output.
3. Anything else in step 2 — the process cannot start (including a missing
   working directory), times out, exits non-zero or prints nothing →
   undetermined.

Undetermined → the cwd check is skipped (fail-open, TM-1 in
THREAT-MODEL.md). A missing or non-string `cwd` still skips the check
before any git call is made, as today.

### cwd check (unchanged around the new derivation)

The derived root and the cwd's git toplevel are compared by realpath, as
today. When they differ, the launch is denied before the journal is opened,
and the deny names the derived root both in the reason and as the cd target.
When the cwd's toplevel cannot be resolved, the check is skipped.

### Unchanged

In-flight and merged denials, the deny-before-journal order, the journal
location (the parent directory of `worktree_path`; see SC-1 in
IMPLEMENTATION.md), `worktree_path` validation, the task-assignment parsing
and its patterns (byte-identical copies live in sibling hooks), and exit 0
for every input.

### Module docstring

The fail-open list no longer names "a worktree path outside the
`.claude/worktrees/em-workflow/` layout". The docstring states: the project
root comes from the segment; when the segment is absent, it is the parent
of the git common dir resolved from `worktree_path`; when neither resolves,
the cwd check is skipped (fail-open). The exact wording is this task's
choice and is pinned by this task's own document test.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR2, FR6, TS1–TS3): For each of the three link placements (`.claude`, `.claude/worktrees`, `.claude/worktrees/em-workflow`, each a symlink to a directory inside a temporary git project), with an integration worktree and a task worktree created by `git worktree add` under the feature's worktree root reached through the link, and `worktree_path` set to the strict realpath of the task worktree (asserted to lack the segment), a launch with cwd at the main worktree exits 0 with empty stdout and appends a `launched` event for the task.
- [ ] AC-2 (FR2, FR6, NFR2, TS1–TS3): With the same three fixtures and cwd in the integration worktree, the hook exits 0 with a `deny` decision. Both the reason and the cd instruction name the main worktree's path (the project root), and the journal holds no `launched` event for the task afterwards.
- [ ] AC-3 (FR2, NFR2, TS4): With the segment absent and git unable to resolve a common dir — (a) an existing directory inside a temporary non-repository directory, (b) a nonexistent absolute path — the hook exits 0 and emits no deny output. `tests/test_queue_launch_guard.py` passes unmodified, including `test_worktree_path_outside_layout_fails_open`.
- [ ] AC-4 (NFR4, TS12): At function level, with the hook's process runner replaced by a recording stand-in: a path with the segment triggers no git-common-dir call. A path without it triggers exactly one call, `git rev-parse --path-format=absolute --git-common-dir`, with `worktree_path` as working directory and `GIT_TIMEOUT_SECONDS` as the timeout.
- [ ] AC-5 (TM-1, NFR2, TS12): At function level, when the fallback call fails to start, times out, exits non-zero or prints only whitespace, the project root is undetermined and the cwd check produces no denial. No real timeout is waited for.
- [ ] AC-6 (FR3, TS5): The module docstring states the segment derivation, the git-common-dir fallback when the segment is absent, and fail-open when neither resolves. It does not contain the pre-change outside-layout skip statement. Each presence and absence assertion is paired with a forged-text negative proof, and a verbatim pre-change excerpt shows that the absence search finds the old statement.
- [ ] AC-7 (NFR1, NFR5, TS14): The hook and the new test module import only standard-library modules, checked by parsing their import statements. The fixtures build linked layouts from symlinks in temporary directories, and no test sleeps or depends on timing.

## Test Notes

- **Fixture per placement** (subTest per placement): make a temporary
  directory and use its realpath as the project root. Run `git init` and
  make an initial commit with a committer identity supplied inside the
  fixture, so the test does not depend on the user's git config. Create
  the link target directory inside the project and the link at the
  placement. Then create the integration and task worktrees with
  `git worktree add` from the project root, at
  `.claude/worktrees/em-workflow/{feature}/integration` and
  `.../{feature}/{T}` through the link, each on its own branch.
- **Link target names** must not recreate the
  `/.claude/worktrees/em-workflow/` segment. Each fixture asserts that the
  canonical `worktree_path` lacks the segment, so a test cannot pass
  vacuously through the segment path.
- **Git environment**: run every git call in the fixtures, and the hook
  subprocess itself, with repository-selecting git environment variables
  (for example `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`) removed. A
  suite started from inside a git hook then cannot act on the real
  repository. Give fixture git calls a timeout.
- **Non-repository directory (AC-3)**: if the system temp directory could
  itself sit inside a git repository, bound git's repository discovery for
  the hook subprocess with the ceiling-directories environment variable.
- **Journal**: read it at the parent directory of the canonical
  `worktree_path` (SC-1 in IMPLEMENTATION.md).
- **Function-level tests (AC-4, AC-5)**: load the hook file as a module and
  replace its process runner with a stand-in that records arguments and
  returns or raises the scripted outcome. Restore it after each test.
- **Docstring test (AC-6)**: read the module docstring by parsing the hook
  file, not by importing it under a different name.
- The new module is self-contained. It builds its own launch payload and
  its own hook subprocess helper, and imports no other test module
  (IMPLEMENTATION.md D2).

## Out of Scope

- Link targets that recreate the segment, links resolving outside the main
  worktree, and a git common dir that is not the main worktree's `.git`.
- Any change to the in-flight and merged denials, the journal location,
  `worktree_path` validation or the task-assignment parsing.
- Modifying `tests/test_queue_launch_guard.py`.
- The stale-launched identity binding and the implement-phase.md wording,
  which are handled elsewhere in this feature.
- The plugin version (`em-workflow/.claude-plugin/plugin.json`,
  `.claude-plugin/marketplace.json`).
