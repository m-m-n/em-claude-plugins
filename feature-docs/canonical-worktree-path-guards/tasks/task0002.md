# Task Plan: task0002 — Stale-launched: link-tolerant worktree binding

## Goal

`resolve_bound_stop_target` compares the Agent index entry's recorded
worktree with `--task-worktree` after resolving links on both sides. A
canonical recorded path then binds to `$WT_ROOT/{T}` given through a link,
even when that worktree no longer exists. Malformed values and resolution
errors are binding failures, never exceptions.

## Requirements

FR1, FR4, FR5, FR7, NFR1, NFR3, NFR5

## Scope

### Files to Modify
- `em-workflow/scripts/recover-orphaned-task.py` — the worktree condition of the identity-binding function follows SC-2, and that function's docstring states it
- `tests/test_stale_launched_recovery_chain.py` — new linked-layout binding test classes (FR7), docstring document tests, standard-library import check, the updated docstring of TestChainTaskWorktreeExistenceIrrelevant, and this feature's entries in the module docstring's AC index

## Design

### Binding step (new chain step 4)

`resolve_bound_stop_target(entry, task_worktree, stop_target)` keeps its
signature and its return contract: the bound identity on success, nothing
on failure. The caller already maps failure to `agent-identity-unproven`.
Its three conditions, all of which must hold:

1. **Candidates (unchanged)**: `agent_ids` is a non-empty list naming
   exactly one distinct value.
2. **Worktree (changed, SC-2 in IMPLEMENTATION.md)**: the entry's
   `worktree_path` and `task_worktree` are each a non-empty string that is
   an absolute path. Each is resolved through non-strict link resolution:
   every existing link is resolved and the path need not exist. The
   resolved values must be equal. Any OS-level or invalid-value error
   (embedded NUL) raised while resolving either side is caught inside the
   binding step and means failure. The step never raises.
3. **Stop target (unchanged)**: `stop_target` is a string equal to the one
   candidate.

The source-level pin reads the function's whole source text, docstring
included. That text must never contain the token `session_id` (TM-4). A
helper extracted for condition 2, if any, reads only the two worktree
values and is equally free of that token.

### Docstrings (FR5)

- `resolve_bound_stop_target`: the old statement that the recorded
  `worktree_path` "equals `task_worktree`" is replaced by the SC-2 rule.
  Both values must be non-empty absolute strings, both are resolved through
  links without requiring existence, and the resolved values must be equal.
  A resolution error is a binding failure.
- `TestChainTaskWorktreeExistenceIrrelevant`: "compared as a plain string"
  is replaced by "compared after resolving links on both sides"; a path
  that does not exist still binds when it names the recorded worktree.

### Unchanged

The module docstring's chain description (it says "matches"), the CLI flags
and their help text, every other chain step and reason code, the legacy
chain, and the journal-helper invocation.

## Test Notes

- **Reuse** the module's proving fixture, stub journal helper and residual
  assertion helper. Each case mutates exactly one value of the proving
  fixture: the recorded `worktree_path` in the Agent index entry, or the
  `task_worktree` argument.
- **Linked fixture**: inside the temporary directory, create a project
  directory holding a real target directory and the
  `.claude/worktrees/em-workflow` symlink to it. Create `$WT_ROOT/{T}`
  through the link. Record its strict realpath in the entry and pass the
  link spelling as `task_worktree`. The link target name must not recreate
  the `/.claude/worktrees/em-workflow/` segment.
- **Forced resolution error (AC-4)**: replace the link resolution the
  binding step uses with a stand-in that raises an OS-level error, and
  restore it after the test.
- **NUL (AC-4)**: Python versions differ on whether non-strict resolution
  raises for an embedded NUL or returns a value. Assert only the outcome,
  which SC-2 fixes as a binding failure either way. On the entry side, NUL
  arrives through a JSON escape in `agents.jsonl`.
- **Non-string argument (AC-4)**: `decide()` treats any non-None evidence
  value as opting into the chain, so a non-string `task_worktree` reaches
  the binding step.
- **CLI case (AC-1)**: run the script as a subprocess with the same flags
  the existing command-line tests use, pointing the journal helper at the
  stub.
- **Pre-existing coverage**: the mismatch test and the nonexistent-path
  test (`/x/...` values with no links) keep passing unchanged, because
  non-strict resolution of a path without links returns it as written.
