# Task Plan: task0001 — Universalize the implement-phase exit-4 recovery scope, pin it, and bump the plugin version

## Goal

The implement phase's exit-4 bounded-recovery contract binds every
`commit-docs.sh` call site in that phase with exactly one named carve-out, the
new wording is pinned by tests, and the plugin version is bumped in both
manifests in the same change.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create

None. Every file in scope already exists; this task modifies four of them.

### Files to Modify

- `em-workflow/references/implement-phase.md` — the exit-4 recovery bullet inside the "Branch & Worktree Model (READ FIRST)" section is rewritten to a universal scope with one named carve-out
- `tests/test_implement_routeback_gate.py` — assertions are added for the universal scope, the two newly named bound sites, and the absence of the closed-enumeration phrasing, each absence assertion paired with a regression proof
- `em-workflow/.claude-plugin/plugin.json` — the version value is bumped from 0.1.42 to 0.1.43
- `.claude-plugin/marketplace.json` — the em-workflow entry's version value is bumped from 0.1.42 to 0.1.43

## Design

Cross-task conventions — the wording presence/absence constraints, the
test-module conventions, edit containment, and the citation-not-restatement
rule — are stated in IMPLEMENTATION.md and are not repeated here. This section
states only what this task must produce.

### 1. Definition-layer rewrite (FR1, FR2, FR3)

The `**exit-4 recovery**` bullet in `## Branch & Worktree Model (READ FIRST)` of
`em-workflow/references/implement-phase.md` must end up with these properties.

| Property | Required end state |
|---|---|
| Scope | Universally quantified: the bounded recovery applies to every `commit-docs.sh` call site in the implement phase |
| Exclusion | Exactly one, named inside the same bullet: Step I.2.c's route-back commit |
| Enumeration status | Illustrative — a reader must be able to tell the listed sites are examples under the universal scope, not the definition of the bound set |
| Exhaustiveness claim | Removed. The current tail asserting that the listed sites are the three `commit-docs.sh` call sites in this phase where exit 4 can occur no longer appears |
| Sites named on the bound side | Step I.1's baseline commit; Step I.2.a's launch-time task status / task branch write; Step I.2.b's wake-phase commit; Step I.2.c's rejected-path terminal status commit; Step I.3's implement-completed / completed-commit write |
| Recovery procedure | Unchanged in substance: refresh, re-capture the tip, re-apply the same transition re-derived from source, one retry; a second exit 4 stops the phase with a report naming the call site |
| Carve-out sentences | The carve-out sentence and the unreachability-proof sentences that follow it survive, with the proof's reasoning left at its current breadth |

Step I.2.a and Step I.3 have no textually explicit `commit-docs.sh` invocation
line in the document; their commits exist only through the write-then-commit rule
the same section already owns. The bullet names them as the commits that rule
produces. Adding explicit invocation lines at those steps is out of scope (A3).

### 2. Decision flow the rewritten bullet must support

A reader (the orchestrator) holding an exit 4 from some implement-phase call site
must reach a defined answer by these steps alone:

1. Identify the call site that returned exit 4.
2. Ask whether that site is the single carve-out named in the bullet.
3. If it is not — which is the default for every site, including sites added to
   the phase after this edit — perform the bounded recovery, then retry once.
4. If the retry also returns exit 4, stop the phase with a report naming the call
   site and the tasks involved.
5. If it is the carve-out, that site's own unreachability proof and its
   stop-with-report terminal apply instead.

Step 3's "default for every site" must hold without the reader needing the site
to appear in the bullet's list.

### 3. Pinning-layer additions (FR5, NFR6)

Add to `tests/test_implement_routeback_gate.py`:

- A presence assertion for the universal-scope phrasing, extending the existing
  class that covers the exit-4 enumeration.
- A presence assertion that both Step I.2.a's launch-time write and Step I.3's
  completion write appear inside the bullet's bound-side enumeration — not merely
  somewhere in the file.
- An absence assertion for the removed closed-enumeration phrasing, plus its
  paired regression proof in the existing regressions class showing the same
  matcher flags the pre-change text.

Existing assertions run unchanged. Nothing is deleted, renamed away, or skipped,
and the module's test-method count does not go down.

### 4. Packaging-layer bump (FR6)

Both manifests move from 0.1.42 to 0.1.43 within this task. No other field of
either manifest changes.

## Test Notes

- Unit level, in `tests/test_implement_routeback_gate.py`: AC-1 maps to the
  universal-scope presence assertion and to the closed-enumeration absence
  assertion (TS1, TS3); AC-2 to the bound-side membership assertion (TS2); AC-3
  and AC-4 to the existing assertions running unchanged plus the three-document
  agreement class (TS4); AC-5 to the regression-proof pairing (TS3, NFR6).
- Write the assertions before the document edit. The universal-scope and
  bound-side assertions must fail against the current text, and the
  closed-enumeration absence assertion must fail against the current text as
  well — a new assertion that passes before the edit is not pinning anything.
- Scope the bound-side assertion (AC-2) to the bullet's own text, not the whole
  file: both step identifiers occur elsewhere in the document, so a file-wide
  search would pass without the bullet naming them.
- Regression-proof pairing: the proof runs the new absence matcher against a
  literal copy of the pre-change wording and asserts it matches there. Without
  it, a typo in the matcher yields a permanently green, meaningless assertion.
- Integration level: the whole-suite run is the only mechanism that catches other
  modules pinning this bullet's wording (A4) — do not substitute inspection.
- Version consistency (AC-6, TS6): assert the two manifests agree on the same
  value rather than checking each file in isolation.
- Edge cases to keep in view while wording the replacement: do not re-form the
  forbidden comma-and sequence while widening the list (EC4); do not let the
  edit spill outside the bullet, since a byte-identity test on a batch-mode
  paragraph and a bare-git-command test over the Step I.2.c section both run over
  wider scopes (EC3).
