# Task Plan: task0001 — Leave out only the protected rm targets from the pool

## Goal

When one rm lists a protected self-config operand beside a target the hook denies, the hook gives that target's deny (rm-recursive, or rm-root) instead of the self-modification ask. An rm whose other targets give no deny still gets the self-modification ask. The case table and the unit tests pin both outcomes.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/hooks/tests/destructive-guard-cases.json` — the old TS-15 case changes in place; this feature's rule-pinned cases are appended at the end

## Design

The behavior is the "Per-target exclusion" contract in IMPLEMENTATION.md Shared Components. This plan states where it is implemented and how it is pinned.

### 1. The protected operand set (FR2, FR4)

`rm_operands_name_self_config()` becomes a function that returns a set of operand numbers. It may be renamed, or replaced by a new function; no caller of the old boolean form may remain.

- **Input**: the operand basis of one rm invocation, exactly the sequence `check_rm()` received for that invocation: the rm's own arguments on the plain route, or the remainder of a substitution-headed statement.
- **Output**: the operand numbers, as `_number_rm_operands()` assigns them on that same sequence, of the operands that do not start with `-` and whose raw form or `normalize_candidate()` form matches `SELF_CONFIG`. The set is empty when no operand matches.
- **Properties**: no side effects; the same input always gives the same set (NFR3). The protected-path test itself does not change: a match on the normalized form alone is not used (FR2, SPEC.md A1).

### 2. The main loop, both routes (FR1, FR3)

1. **Plain route.** `check_rm()` returns the records of the statement's rm invocation. When the statement reached the self-modification ask, compute the protected set on the same arguments. Only records whose number is outside the set join the pool. Otherwise every record joins, as today.
2. **Substitution-headed route.** Apply the same rule to the remainder this route handed to `check_rm()`. It applies only when this route established the statement's rm invocation, as today.
3. **Ordinals.** The invocation's anchor stays in the invocation list in every case. The ordinals and the target numbers in reasons therefore still count the left-out targets: in `rm -rf ~/.claude/skills/foo /home/user/valuable` the winner is "1番目のrmの2番目の対象".
4. **Nothing else changes.** The condition (the statement's own self-modification ask), the resolution step and the CLAUDE_BATCH demotion stay as they are. Because left-out records never reach rendering, a winning reason is built from the remaining winners only. It carries no self-modification text and no demotion sentence.

### 3. Expected verdicts

| Scenario | Command | Verdict / reason id |
|----------|---------|---------------------|
| TS-1 | `rm -rf ~/.claude/skills/foo /home/user/valuable` | deny / rm-recursive |
| TS-2 | `rm -rf /home/user/valuable ~/.claude/skills/foo` | deny / rm-recursive |
| TS-3 | TS-1's command with CLAUDE_BATCH set | deny / rm-recursive |
| TS-4 | `rm -rf ~/.claude/skills/foo ~` | deny / rm-root |
| TS-5 | `rm -rf ~/.claude/skills/foo tmp/$X` | ask / self-modification |
| TS-6 | `rm -rf ~/.claude/skills/foo /tmp/x` | ask / self-modification |
| TS-7 | `rm -rf ~/.claude/skills/foo ~/.claude/hooks/bar` | ask / self-modification |
| TS-8 | `rm ~/.claude/skills/foo /home/user/valuable` | ask / self-modification |
| TS-9 | `rm -rf $HOME/.claude/skills/foo /home/user/valuable` | deny / rm-recursive |
| TS-10 | `rm -rf -- ~/.claude/skills/foo /home/user/valuable` | deny / rm-recursive |
| TS-11 | `rm -rf ~/.claude/skills/foo /home/user/valuable ; git commit --amend` | deny / rm-recursive |
| TS-13 | `$(printf rm) -rf ~/.claude/skills/foo /home/user/valuable` | pinned to the actual output |
| TS-14 | `rm -rf ~/.claude/skills/foo ~/.claude/skills/foo` | ask / self-modification (both occurrences left out) |
| TS-15 | `rm -rf /home/user/valuable > ~/.claude/settings.json` | deny / rm-recursive (a redirect target is not an operand, so nothing is left out) |

A non-recursive rm that names a protected operand and a root-shaped operand gives deny / rm-root under this rule. Add no special handling to keep it an ask; IMPLEMENTATION.md Open Questions records it.
