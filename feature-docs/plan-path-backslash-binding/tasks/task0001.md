# Task Plan: task0001 — Phase documents derive the plan path from the path_segments segments

## Goal

Step I.2.a of `implement-phase.md` hands the implementer, and Plan-path check
rules 2 and 3 judge, the plan path made from the segments that `path_segments`
returns for the stored `tasks.{T}.plan` value. Section 2a of
`phases/create-plan-phase.md` states the same resolution. The docs tests pin
the new wording and flag the pre-fix wording.

## Requirements

FR1, FR2, FR3, FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/references/implement-phase.md` — the task_plan_path line of the Step I.2.a prompt payload, and rules 2 and 3 of the Plan-path check
- `em-workflow/references/phases/create-plan-phase.md` — the resolution sentence of section 2a
- `tests/test_final_path_correction_docs.py` — the pins of those three places and their negative proofs

## Design

The derivation every changed statement expresses is IMPLEMENTATION.md, Shared
Components, "Plan path resolution". It is referenced here, not restated.

### 1. The task_plan_path line (FR1)

The line sits in the fenced prompt payload block of Step I.2.a. Today it says
the feature directory is "joined with the stored tasks.{T}.plan value". The
new line:

- names the integration worktree's feature-docs/{feature}/ as the base;
- states that what is joined onto it are the segments that path_segments of
  scripts/validate-worker-output.py returns for the stored tasks.{T}.plan
  value (plain text without backticks, like the neighbouring payload lines);
- keeps "the value the Plan-path check admitted";
- does not hold the contiguous pre-fix phrase "joined with the stored
  tasks.{T}.plan value", and names no tasks/{T}.md;
- does not describe what the normalization does (no mention of separators,
  backslashes or dropped segments);
- stays one line, directly after the worktree_path line, directly before the
  implementation_md_path line, and before the `## Untrusted data` label line.

### 2. Plan-path check rules 2 and 3 (FR2, NFR1)

- Rule 2 (no symlink) states its target as the path that `task_plan_path`
  carries: the `path_segments` segments of the stored value joined onto the
  integration worktree's `feature-docs/{feature}` directory. It keeps "no
  component of the path, intermediate ones included, is a symlink" and holds
  no "realpath".
- Rule 3 (containment) states that the realpath of that same path lies inside
  the realpath of `feature-docs/{feature}`. It holds no "symlink".
- Neither rule describes its target as the stored value joined as-is.
- Each rule stays one bullet of exactly one sentence. The existing
  one-sentence check counts a period followed by whitespace or by the end of
  the bullet, so no abbreviation with a period (such as "i.e." or "e.g.")
  appears in a bullet.
- Rule 1, rule 4, the opening sentences of the paragraph (when the check runs,
  why the path may stand among the trusted fields, the abort) and the place of
  the paragraph stay as they are.
- Wording constraints of the paragraph (NFR1): it holds none of
  `PP_FORBIDDEN_PHRASES` (among them "symbolic link", "link component",
  "strict realpath", "Unicode general category Cc"); each sentence holds at
  most two of `PP_CONDITION_MARKERS`; it uses no uppercase EVERY or ALL.

### 3. Section 2a of create-plan-phase.md (FR3)

- The sentence saying the implement phase resolves the stored value to "the
  absolute path of the integration worktree's `feature-docs/{feature}/` joined
  with that value" changes so that what is joined are the segments that
  `path_segments` of `scripts/validate-worker-output.py` returns for that
  value.
- It keeps "behind the Plan-path check of `references/implement-phase.md`" and
  the "(cited, not restated here)" marker, and does not describe what the
  normalization does.
- "joined with that value" no longer appears in the section.
- The stored-value sentence ("The stored `tasks.{T}.plan` value is relative to
  `feature-docs/{feature}` ...") is unchanged and stays a separate sentence.
- The phrases other tests pin in section 2a stay (`PP_2A_RETAINED`, and the
  single-task shape phrases of `tests/test_tier_phase_preconditions.py`).

### 4. Docs test pins (FR5)

Inside the final-path-plan-binding block of
`tests/test_final_path_correction_docs.py`:

- The needle set of the task_plan_path line requires the normalized-segment
  wording (path_segments and the script name), keeps the base, the stored
  value name and "the value the Plan-path check admitted", and the line
  matcher reports a line that holds the pre-fix phrase.
- The `PP_RULES` entries of rule 2 and rule 3 require the new target wording.
  The separation check (no "realpath" in rule 2, no "symlink" in rule 3)
  stays.
- The resolved-path needles of section 2a require the new wording.
- New verbatim pre-fix samples, captured from the base revision before the
  edit: the current task_plan_path line, the current rule 2 and rule 3

- The older samples already in the file (`PP_PRE_CHANGE_PAYLOAD_BLOCK`,

- Forged texts inside existing negative tests that quote the pre-fix wording

## Test Notes

All criteria are docs tests on whitespace-normalized text of the section they
concern. Work test first: update the pins and add the pre-fix samples, see the
pins fail on the live text, then edit the two documents until they pass. Each
new matcher gets a negative proof (the verbatim pre-fix sample, or a forged
copy of the live text with the new wording removed). The byte-identity of rule
1, rule 4 and the other sentences of the Plan-path check paragraph can be
checked against the base revision with a read-only git command during
implementation; the committed tests pin them through the existing needles.
