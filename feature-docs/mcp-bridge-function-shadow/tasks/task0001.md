# Task Plan: task0001 — Lift the notion-pair exclusion on override and shell-state constructs in the chunk chain

## Goal

The notion-pair exclusion of the `mcp-bridge run --args-json` step no longer
applies when the statement's chunk, or any chunk that encloses it, holds a
construct that may change what the name `mcp-bridge` runs or leaves the shell
state unknown. Such a statement has its decoded `--args-json` value inspected
like every other pair, so a destructive command no longer passes through the
exclusion by shadowing `mcp-bridge` with a function of the same name.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2

## Design

### Where the lift sits (FR5, FR7)

- In `_mcp_bridge_args_json_chunks()`, a statement is "nothing to do" as the
  notion pair only when `_args_json_notion_pair()` answers true AND the chain
  decision below answers "not lifted". The pair predicate is asked first, as
  now, and the chain decision is asked only when the predicate answers true,
  so the predicate keeps being called once per target statement and the chain
  is never walked for a statement that is not the notion pair.
- A lifted statement goes on to step 3 unchanged: the flag reading, the
  decoding, the candidate bodies and the top-level `command` strings, the
  Unrestorable flag and the scan charge, exactly as for any other pair.
- Nothing else changes: `_args_json_notion_pair()`, the single-word-certain
  helper, the code of `_single_quote_skip_spans()`, the nameref answer
  (`_args_json_nameref_declared()` and its scan), `override_seen` and the
  heredoc data decision, the masking stop, and the code of `statements()`.
  `statements()` references no new name: `TestStructure` keeps holding.

### Chain decision `_args_json_notion_lifted(marked)` (FR4, NFR2)

- Input: MARKED, the `_MarkedText` of the chunk the statement was lexed from.
  None reads as lifted (fail safe).
- Output: true when the chunk or any chunk of its enclosing chain, up to the
  command's own chunk, holds a construct of the per-chunk scan below.
- Walk: from the chunk up through the derivation link the chunk record already
  sets (`_outer_marked`, while the chunk is marked derived), in a loop, never
  by recursion. It stops at the first chunk that has a kept answer, at the
  first chunk whose scan is true, and at the command's own chunk (not
  derived). A derived chunk with no link reads as lifted.
- Every chunk the walk visits keeps the answer in a new slot of `_MarkedText`
  (declared and initialised next to `_nameref_declared_cache`), so each
  chunk's answer is computed once per `statements()` run and kept. The nameref
  cache is not read or written by this decision.
- A chunk whose source is a `_StrippedWithShellSubstitution` (an
  unquoted-delimiter heredoc body that holds a current-shell substitution)
  reads as lifted, the same rule the nameref answer applies to it. It may be
  set when `_ChunkLinks.register()` registers the chunk or read by the scan.
- The walk and the scan read only marked texts that are already registered:
  the chunk record registers a chunk before its first decision, and every
  enclosing chunk was registered when its own statements were handed over.

### Per-chunk scan `_args_json_shadow_scan(marked)` (FR1, FR2, FR3, FR6)

Reads only the text of one chunk, never its enclosing chunks and never the
bodies of its substitutions (those are their own chunks and stand in this
chunk's text as marker residue). True when any of the following holds:

1. FR1: some statement of the chunk is flagged by `_overrides_command_name()`.
   The statement's words are read with the same lexing of the marked chunk,
   the same token preparation (marker residue turned into the substitution
   flags) and the same statement shaping (fused closers split, redirections
   taken out, command position found by the leading-shape step with the
   chunk's own case-pattern state and its tail statements) that
   `statements()` applies, so a construct is at command position here exactly
   when `statements()` would read it there. Sharing a helper with
   `statements()` is allowed only if what `statements()` yields does not
   change and `statements()` references no name that holds `args_json`.
2. FR2, current-shell substitution: the chunk holds one as
   `_args_json_has_brace_substitution()` reads it (the reading the nameref
   scan uses: the opener anywhere in the text, quoted or not, also across a
   line continuation). A quoted opener counts because the shell can evaluate
   it later (`${var@P}`, an arithmetic subscript).
3. FR2, command words: some simple command of the chunk, split at the same
   boundaries, with the redirections removed and the same prefix words
   skipped as in `_args_json_declares_nameref()` (assignments, `builtin`,
   `command`, `exec`, `time`, `!`, the reserved words that introduce a
   command, each with its own options and `--`), has a command name that
   `_args_json_declaration_word()` cannot restore, or whose restored text is
   `eval`, `source`, `.`, `trap`, `mapfile` or `readarray`. `trap`, `mapfile`
   and `readarray` are added to the three FR2 words because each runs a string
   as code in the current shell (THREAT-MODEL.md TM-2). Code may be shared with
   the nameref reading, but the nameref answer does not change: its vocabulary
   and its `declare -n` rule stay as they are.
4. FR3: some word of some statement of the chunk, redirection targets
   included, holds `BASH_FUNC_` or `BASH_ALIASES` as a substring of its value.
   The two words are named once, in a constant only this scan reads. They are
   not added to `OVERRIDE_BUILTINS`, `OVERRIDE_VARIABLE_NAME`,
   `STOP_COMMAND_WORDS` or `STOP_VARIABLE_NAMES`.
5. Fail safe: a chunk without lexer regions, or a chunk any of whose
   statements comes from the parse-failure fallback, reads as true. This also
   covers every construct `_overrides_command_name_unlexed()` reads.

What FR6 needs follows from these readings and is not a separate check: a
quoted `NAME()` is one word with no `()` operator after it, a comment is
blanked before lexing, and a data heredoc body is taken out of the chunk text
and never queued. The `BASH_CMDS` match of item 1 and the matches of item 4
are substring matches, so they match a quoted word too.

### Descriptive text (FR8)

- `statements()` docstring, the paragraph that begins "The statement loop
  below also inspects": the sentence that the notion pair is the only pair
  whose decoded value is not inspected, and the phrase "whose options do not
  determine the notion pair", state instead that the notion pair's decoded
  value is left uninspected only while `_args_json_notion_lifted()` answers
  false, and is inspected like every other pair when an override or
  shell-state construct stands in its chunk or an enclosing chunk.
- `_single_quote_skip_spans()` docstring, closing paragraph: the clause that
  the notion pair is the one pair the decoded-value inspection leaves out gets
  the same qualification and names `_args_json_notion_lifted()`. The code of
  the function does not change.
- `_mcp_bridge_args_json_chunks()` docstring: step 2 names
  `_args_json_notion_lifted()` and the lift, keeping the phrases
  "single-word-certain" and "`--format`, `--session` and `--args-json` value
  words"; the "nothing to do" sentence before "Per statement" qualifies "its
  options determine the notion pair" the same way. The "Out of scope" part does
  not change (`TestDocstring` forbids a list of phrases there).
- The docstrings of the two new functions state their contracts, including
  that the answer is computed once per chunk and kept and that the chain is
  walked without recursion.

  function-import names built from pieces or written with ANSI-C escapes.

- Changing `_overrides_command_name()`, `_overrides_command_name_unlexed()`,
  `override_seen`, the heredoc data decision, the masking stop, the nameref
  answer, `_args_json_notion_pair()` or the code of
  `_single_quote_skip_spans()`.
- Editing SPEC.md or any document of another feature.
