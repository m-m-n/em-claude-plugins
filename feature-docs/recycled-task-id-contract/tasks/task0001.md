# Task Plan: task0001 — recycled-task-id contract wording, classification table and its pin

## Goal

Make `em-workflow/references/implement-phase.md` state the recycled-task-id
rule and the hook classification in one non-contradictory reading, back that
statement with a machine-readable classification table, and turn the
consistency tests into a contract that fails when the documentation or the
hook implementation changes alone.

## Requirements

## Design

### The contradiction to remove (FR1)

I.2.a currently scopes the recycled-task-id rule to "the orchestrator's
interpretation of the journal" and, in the same sentence, records an explicit
exception in which the Stop hook applies the very same carve-out. A reader
cannot decide from one reading whether the rule is orchestrator-only or also
hook-side; the two halves state opposite things.

Target semantics — one statement, one reading:

1. The recycled-task-id carve-out (a task whose journal last event is
   `failed` while its own workflow state reads `pending` counts as
   unlaunched, not failed) is applied by TWO parties: the orchestrator's
   journal interpretation, and the Stop hook.
2. The remaining three queue hooks derive a task's state from the journal's
   last event alone and never consult the per-task workflow status.
3. The "governs only … with one explicit exception" construction disappears.
   State the classification positively (who applies it / who does not), so
   the sentence carries no self-cancelling clause.
4. Keep the statement normative and singular: I.2.a remains the only place
   the rule is stated; other sites cite it.

### Unlaunched detection, recorded not fixed (FR4)

The hooks decide "unlaunched" from the absence of any journal event for a
task id — nothing else. The orchestrator's own selection rule in I.2.a
additionally requires that the task's workflow status is not `merged`; the
hooks carry no equivalent condition. I.2.a must say so, together with the
reason (the hooks are fail-open nets, not authorities; the orchestrator
protocol and the resume guard remain authoritative), so the document stops
implying protection the hook side does not provide. No hook changes (NFR3).

### The classification table (FR5)

Add exactly one table to the document, positioned so both I.2.a and the
Supporting cast hook bullets can cite it as the classification's source.
Contract (also in IMPLEMENTATION.md Shared Components):

| Aspect | Contract |
|---|---|
| Anchor | A stable textual anchor (caption/heading line) immediately preceding the table, unique in the document, that the parser locates it by |
| Rows | Exactly the four queue hooks I.2.a's classification names — no more, no fewer |
| Hook column | A repo-relative path reference to the hook source, resolvable from the repository root |
| Classification column | One value from a fixed two-value vocabulary: reads the per-task workflow status / does not read it |
| Consumer obligation | A malformed row, an unknown classification value, or a path that does not resolve to an existing file is a hard failure — never a silent skip |

### Parse step and observation rule (FR5, NFR4)

The new module owns three separable steps, so that the pin stays a single
test while its parts remain provable:

1. **Parse** — input: the document text (default: the document itself).
   Output: the table's rows as (hook path, classification) pairs.
   Postcondition: raises/fails on a missing anchor, a missing table, a
   malformed row, or an unrecognized classification value.
2. **Observe** — input: one hook path. Output: whether that source reads the
   per-task workflow status. The rule is defined ONCE and applied uniformly
   to every row; no per-hook special-casing. It considers only *executable*
   content: comments and docstrings are excluded before the check, because at
   least one hook mentions the workflow state file only in its module
   docstring and a raw text search would misclassify it. Precondition: the
   path resolves to an existing file (otherwise: failure, per FR5).
3. **Compare** — input: parsed rows. Output: the list of disagreements
   between a row's classification and the observation of its source.
   Postcondition: empty list ⟺ documentation and implementation agree.

The single pin test asserts the comparison over the real document yields an
empty disagreement list. Non-vacuity guards belong with it: the parsed table
must yield at least one row of each classification value, and every parsed
path must resolve. These are structural guards, not restated classifications
(NFR4).

The parse step is imported by `tests/test_recycled_task_id_consistency.py`
rather than duplicated there — the discovery run puts `tests/` on the import
path, and a second parser would recreate the second source of truth NFR4
forbids.

### Split assertions (FR3)

`TestRecycledTaskIdRuleScopedToOrchestrator` keeps its name and gains two
independent assertions, each over one group obtained from the parsed table:

- Group A — the hooks classified as NOT reading the per-task workflow
  status: assert I.2.a's wording places each of them on that side.
- Group B — the hook classified as reading it (the explicit exception):
  assert I.2.a's wording places it on that side.

The two must not collapse into one loop or one assertion: a break on either
side must fail the assertion for THAT group only, so a post-mortem can tell
which side moved. Each group assertion first asserts its group is non-empty
(a floor of three for group A and one for group B is permitted — those counts
come from FR3's own wording, not from a restated classification), so an
emptied group cannot make the loop vacuously pass.

### Collateral updates in the existing module

The document edit invalidates assertions in
`tests/test_recycled_task_id_consistency.py` that pin the pre-change I.2.a
wording (the scope sentence, the hook-name conjunction, and the pre-change
wording samples the negative proofs run against). Update them so they assert
the POST-change wording and their negative proofs run against the wording
being replaced. Every other module in `tests/` is untouchable: they encode
line-wrap literals, byte-identical paragraphs and section orderings of the
same document, and the edit must not disturb them.

## Test Notes

- Unit level: AC-1 through AC-4 are document-contract assertions over
  whitespace-normalized section slices — the established pattern in this
  suite (line-wrap choices must never make an assertion brittle; byte-identity
  assertions stay on raw text).
- Integration level: AC-6's pin crosses two artifacts (documentation and hook
  sources) and is the feature's only cross-artifact check.
- TDD order: write the new module's parse/observe/compare steps against the
  table BEFORE the table exists (red because the anchor is missing), then add
  the table, then the wording. The split assertions are red until the table
  and the wording both land.
- Edge cases worth covering: missing anchor; a row whose path does not
  resolve; an unrecognized classification value; a table with rows of only
  one classification value; an inverted classification (TS4's negative
  check).
- TDD-awkward: the document edit itself cannot be driven test-first without
  first choosing the exact post-change phrases. Handle it by fixing each
  asserted phrase as a module-level constant shared by its positive test and
  its negative proof (the pattern already used in this module), then writing
  the document to satisfy it.
- Before editing the document, enumerate every module under `tests/` that
  reads it and every literal it asserts; those are the constraints the edit
  must not disturb.
