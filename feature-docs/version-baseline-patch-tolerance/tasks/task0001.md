# Task Plan: task0001 — Lower-bound version check in the version-bump test module

## Goal

The version checks of `tests/test_review_perspective_model_effort_version_bump.py` accept every version of the baseline's major that is at or above the baseline's next minor, with the patch unchecked and no upper bound on the minor. The four current-version tests pass against the repository as it is, and keep passing across later CI patch bumps and later minor bumps.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `tests/test_review_perspective_model_effort_version_bump.py` — change the acceptance rule of the bump helper, replace the two tests that pinned the old exact rule, and update the module and helper docstrings.

## Design

### Notation

A baseline is written (M, m, p): its major, minor and patch as integers. A candidate is the version under check, parsed into an integer triple the same way.

### Acceptance rule of `_assert_minor_bump_over_baseline`

The helper keeps its name and its callers.

- Precondition: the candidate version string is turned into an integer triple by `_version_tuple`. A missing or malformed version is rejected there, exactly as today; `_version_tuple` is not changed.
- Postcondition, accept: the helper returns without raising when the candidate's major equals M and the candidate triple is greater than or equal to (M, m + 1, 0), compared element by element as integers.
- Postcondition, reject: in every other case the helper raises AssertionError.
- The patch takes no part in the decision beyond that comparison. The minor has no upper bound.
- Versions are never compared as strings (NFR2).

| Candidate against baseline (M, m, p) | Result |
|---|---|
| (M, m + 1, 0) | accept |
| (M, m + 1, a nonzero patch) | accept |
| (M, m + 2, 0), or any higher minor of major M | accept |
| (M, m, p + 1), a patch-only bump | reject |
| (M, m, p), unchanged | reject |
| (M, m − 1, any patch), a lowered minor | reject |
| (M + 1, m + 1, 0), a different major numerically above the bound | reject |
| missing or malformed version | reject, through `_version_tuple` |

### Test changes

- `test_rejects_minor_bump_with_nonzero_patch` is removed and replaced by a test that, against a fake baseline, asserts that (M, m + 1, a nonzero patch) is accepted.
- `test_rejects_minor_raised_by_two` is removed and replaced by a test that, against a fake baseline, asserts that (M, m + 2, 0) is accepted.
- The names of the two replacement tests are the implementer's choice (for example `test_accepts_minor_bump_with_nonzero_patch` and `test_accepts_minor_raised_by_two`). They do not reuse a removed name.
- Kept with their names and purposes: `test_accepts_the_correct_bump`, `test_rejects_patch_only_bump`, `test_rejects_unchanged_version`, `test_rejects_major_change`, `test_rejects_lowered_minor`, the two string-ordering-trap tests, `test_entry_without_a_version_fails_the_bump_check`, `test_only_standard_library_imports`, the four current-version tests, and every other test of this module whose name `test-docs/review-perspective-model-effort/task0006.tests.yaml` references.
- The four current-version tests are `test_version_is_a_minor_bump_over_baseline` in `TestEmWorkflowManifest` and in `TestEmReviewManifest`, `test_em_workflow_entry_version_is_a_minor_bump_over_baseline` and `test_em_review_entry_version_is_a_minor_bump_over_baseline`. They keep reading the real manifest and marketplace entries and checking them against `EM_WORKFLOW_BASELINE` and `EM_REVIEW_BASELINE` through the helper.

### Docstrings

- Module docstring: the AC-1 description states the lower-bound rule of the table above. The matcher -> negative-proof list names only tests that exist in the module after the change: it names the two replacement tests and no longer names the two removed tests.
- Helper docstring: states the same rule, including the rejection of a different major and the delegation of missing or malformed versions to `_version_tuple`.

### Unchanged parts

- `EM_WORKFLOW_BASELINE` and `EM_REVIEW_BASELINE` keep their current values.
- The module keeps importing standard-library modules only.
