# Task Plan: task0001 — Keep block-scalar and plain-continuation state across non-ASCII-whitespace-only lines

## Goal

In `em-workflow/hooks/queue_stop_guard.py`, a line made only of non-ASCII
whitespace no longer ends the multi-line value tracker's block-scalar state
or plain-scalar continuation state, so a following `- '…` line cannot open a
quoted value that hides the genuine `routeback_failed_journal_line` record
and later tasks. For the three reported forms the Stop hook exits 2.

## Design

### Line class: non-ASCII blank line

Term used below. A line is a *non-ASCII blank line* when, after its line
terminator is removed:

1. it becomes empty once all Unicode whitespace is stripped — the same
   whitespace set the reader functions outside the tracker already use for
   their blank-line check (SPEC.md A1), and
2. it is not made only of U+0020 spaces and U+0009 tabs. An empty line falls
   in that space/tab class and is not a non-ASCII blank line.

Examples: a line of only U+3000, only U+00A0, only U+000B, only U+000C, or
four spaces followed by U+3000. Not examples: an empty line, a line of only
spaces and tabs, U+3000 followed by `x`.

One classification serves both state rules below, so the two rules cannot
drift apart.

### Rule 1 — block-scalar state (FR1)

Precondition: the tracker is inside a block scalar (`_block_parent` is set).

For a non-ASCII blank line at any column (column 0, the parent's
indentation, or deeper):

- `feed` returns False for the line;
- `_block_parent` keeps its value;
- the line is not handed to `_read_line`.

Postcondition: the next line that is not a non-ASCII blank line is judged
against the unchanged block-scalar state by its own indentation, exactly as
if the non-ASCII blank line were absent. Consecutive non-ASCII blank lines
behave the same. Every block-scalar header form (`|`, `>`, `|-`, item
`- |`) reaches this branch.

### Rule 2 — plain-scalar continuation state (FR2)

Precondition: in `_read_line`, `_plain_parent` is set.

For a non-ASCII blank line at any column: the continuation does not end, and
neither `_plain_parent` nor `_pending` changes. This holds for a key's value
(`notes: hello`) and for an item's content (`- hello`).

Postcondition: as in Rule 1, the next line is judged against the unchanged
state.

### Unchanged behavior (FR3, FR6)

- Value-start (pending) position: a non-ASCII blank line there is still read
  as a plain scalar, and deeper following lines as its continuation; a
  column-0 non-ASCII blank line followed by `- '…` still opens a quoted value
  (residual A1 of routeback-record-quoted-open-residual, pinned by
  `TestColumnZeroNonAsciiBlankLine`).
- Lines of only spaces and tabs.
- Lines where non-ASCII whitespace is followed by a non-whitespace character
  (e.g. U+3000 then `x`): still judged by indentation.
- The blank-line checks of `task_ids_from_workflow`, `iter_task_block_lines`
  and `task_routeback_records_from_workflow` (outside the tracker).
- The module docstring.

### Fixture for the new tests

Journal line 1 is a `failed` event for task0001. task0001 is `pending`, has
`notes`, and after `notes` the direct key `routeback_failed_journal_line: 1`.
task0002 follows, `pending`, with no journal event. The `notes` value takes
one of three forms, each with C being U+3000 or U+00A0 (six fixtures):

- (a) `    notes: |` / `      body line` / a column-0 line of only C /
  `      - 'x`
- (b) as (a), with the C line placed after four spaces
- (c) `    notes: hello` / a column-0 line of only C / `      - 'x`
