# Task Plan: task0001 — Merge result contract and renderer

## Goal

The merge skill gets a product-level SSOT for its structured result and a renderer. Every terminal of a merge run prints a result that conforms to that contract, even when its input is invalid.

## Requirements

FR21, NFR5, NFR7, NFR8

## Scope

### Files to Create
- `em-workflow/references/merge-result.md` — SSOT for the merge result: key set and order, vocabularies, reason-code table, format rules (cited from batch-terminal-line.md), confidentiality, fallback result
- `em-workflow/scripts/merge-result.py` — renderer that turns a JSON input document into one conformant result
- `tests/test_merge_result.py` — unit tests for the renderer and the contract/renderer consistency

### Files to Modify

## Design

### Contract document (`merge-result.md`)

1. **Consumer and timing**: the loop-develop dispatcher reads the last assistant message of a `/em-workflow:merge --batch <feature>` run. Every terminal except the usage display (FR2) ends with exactly one result.
2. **Keys and order**: the eight keys in IMPLEMENTATION.md C3's order, with the meaning of each.
3. **Vocabularies**:
   - result and route values as in IMPLEMENTATION.md C2
   - reason codes as a table (code, condition, emitter) holding exactly C2's set
   - rule: `reason` is empty for `merged` / `already_merged` and mandatory for `not_merged`
4. **Format**: cite the format and escaping sections of `em-workflow/references/batch-terminal-line.md` by name instead of restating them. State only what differs: the key set and the vocabularies.
5. **Value rules**:
   - `feature` is empty or matches the feature pattern
   - `merge_commit` is empty or a 40-hex SHA
   - `pr_url` is empty or an https URL
   - `worktree_removed` is `true` / `false`
   - `detail` is a single line, redacted, and capped at a length the document states
6. **Confidentiality**: the same constraint as batch-terminal-line.md (cited), plus the replacements of `em-workflow/references/doc-redaction.md` applied to every value.
7. **Fallback**: one fixed `not_merged` / `internal_error` result that the skill prints verbatim when the renderer cannot run.
8. **No gate_id**: the document contains no gate_id (NFR8).

### Renderer (`merge-result.py`)

- **Input**: the C3 input document path (one argument).
- **Function**: an importable rendering function that takes the input mapping and returns the result text. The command-line entry point reads the document, calls the function and prints the text.
- **Validation**, applied per field:
  - result, route and reason must belong to their vocabularies
  - a `not_merged` result must carry a reason
  - the other fields follow the contract's value rules
- **Invalid input**: when any check fails, the renderer produces `not_merged` / `internal_error`. Its detail names the failing field but never echoes the value. An unreadable or non-JSON document follows the same path.
- **Normalization before escaping**:
  - collapse line breaks and control characters in `detail` into spaces
  - replace absolute paths under `project_root` (when supplied) with repository-relative paths
  - replace any other absolute path under the home directory with its `~/...` form
  - replace Notion URLs with `<notion-url>`
  - apply the length cap
- **Exit code**: 0 whenever a result was printed.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: For every reason code in C2, rendering a `not_merged` input produces exactly the eight keys in C3's order, each value double-quoted and escaped as the contract states. `merged` and `already_merged` inputs render with an empty reason. (TS12)
- [ ] AC-2: The following inputs each render a `not_merged` / `internal_error` result whose detail names the offending field and never contains the invalid value (TM-14):
  - result, route or reason outside its vocabulary
  - a `not_merged` input with an empty reason
  - a non-40-hex `merge_commit`
  - a non-https `pr_url`
  - a `feature` failing the pattern
  - a `worktree_removed` other than true / false
- [ ] AC-3: A detail containing line breaks, double quotes, backslashes or control characters renders as one escaped single-line value. The output holds each contract key exactly once, in order, and nothing else, so no extra key or second result can be injected. (TS12, TM-14)
- [ ] AC-4: Absolute paths and Notion URLs in any value are replaced before rendering (TS21, TM-15):
  - a path under the supplied `project_root` renders repository-relative
  - any other path under the home directory renders as `~/...`
  - a Notion URL renders as `<notion-url>`
- [ ] AC-5: An input document that is missing, unreadable or not a JSON object still yields a conformant `not_merged` / `internal_error` result with exit code 0.
- [ ] AC-6: `merge-result.md` defines the key order, the three vocabularies and the fallback result, and contains no gate_id. A test parses its reason-code table and asserts it equals the renderer's reason vocabulary and C2's 28 codes. (FR21, NFR8)

## Test Notes

- AC-1 and AC-3 are unit tests on the importable rendering function. Load the script by path without writing a bytecode cache into `em-workflow/`.
- AC-5 runs the script as a subprocess with a temporary input file.
- AC-4 uses a placeholder home such as a temporary directory supplied through the environment the renderer reads for the home directory. The test never relies on the real home path.
- AC-6 reads `em-workflow/references/merge-result.md` from the repository and compares sets.

## Out of Scope

- Deciding when each reason code is emitted; that is owned by the scripts and SKILL.md.
- Changing `em-workflow/references/batch-terminal-line.md` or develop's terminal line.
