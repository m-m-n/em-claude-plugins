# Task Plan: task0004 — GitHub repository and PR decisions

## Goal

`merge-pr.py` resolves the chosen remote to a GitHub repository and confirms that gh's default repository is the same one. It also finds the feature's PR and decides, right before merging, whether that PR may be merged.

## Requirements

FR6, FR7, FR8, FR9, FR22, NFR3, NFR4, NFR5

## Scope

### Files to Create
- `em-workflow/scripts/merge-pr.py` — subcommands repo, resolve, state (IMPLEMENTATION.md C6)
- `tests/test_merge_pr.py` — unit tests with a PATH-stubbed gh

### Files to Modify

## Design

Contract: IMPLEMENTATION.md C1, C2, C6; decisions D5, D6.

- **repo (FR6, D6)**:
  - Ask gh to resolve the chosen remote's URL to a GitHub repository; failure → stop `remote_not_github`.
  - Separately ask gh for its default repository for the project.
  - When that default cannot be determined or differs from the remote's repository → stop `remote_unresolved`, with both names in detail when known.
  - Otherwise outcome `github` with `repo` (owner/name).
- **resolve (FR7, FR8, A25)**: list PRs of `repo` whose head is `em-workflow/<feature>/integration` and whose base is base_branch, in every state.
  - Any merged PR → `merged` with `pr_number`, `pr_url`, `merge_commit`.
  - An open, non-draft PR → `open` with `pr_number`, `pr_url`, `head`.
  - An open draft → stop `pr_draft`.
  - Only closed, unmerged PRs → stop `pr_closed`.
  - No PR → `none` with `create_head` (the integration branch) and `create_base` (base_branch) for the skill's push and `gh pr create`.
- **state (FR9, D5)**: read the PR's state, draft flag, mergeability and head SHA.
  - Merged → `merged` with `pr_url`, `merge_commit`.
  - Not open → stop `pr_closed`.
  - Draft → stop `pr_draft`.
  - Mergeability conflicting → stop `pr_conflicting`; mergeable or unknown counts as not conflicting.
  - Head differs from `--head` → stop `pr_head_moved`.
  - Otherwise `ready`.
- **Validation**:
  - PR numbers are positive integers, SHAs are 40 lowercase hex, URLs are https.
  - gh output that is not parseable or fails validation is an internal failure (non-zero exit), never a guess.
  - Every gh call names `repo` explicitly (except the default-repository query, which by design names none) and is time-limited.
- **Operation boundary (FR22)**: the script only reads through gh. It never creates, edits or merges PRs, never calls a write API, and never changes git refs.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: repo returns `github` with the owner/name the stub reports for a GitHub remote, and stops `remote_not_github` when the stub cannot resolve the remote (a non-GitHub URL). (TS5)
- [ ] AC-2: repo stops `remote_unresolved` when gh's default repository for the project differs from the remote's repository, or cannot be determined. (TS24, TM-11)
- [ ] AC-3: resolve covers every PR situation (TS2, TS13, TS17):
  - a merged PR → `merged` with number, URL and merge commit
  - an open non-draft PR → `open` with number, URL and head
  - no PR → `none` with `create_head` equal to the integration branch and `create_base` equal to base_branch
  - closed-only → stop `pr_closed`
  - an open draft → stop `pr_draft`
- [ ] AC-4: state covers every pre-merge situation (TS17, TM-12):
  - an open, non-draft PR whose mergeability is mergeable or unknown and whose head equals `--head` → `ready`
  - closed → stop `pr_closed`
  - merged → `merged`
  - draft → stop `pr_draft`
  - conflicting → stop `pr_conflicting`
  - a head different from `--head` → stop `pr_head_moved`
- [ ] AC-5: Malformed gh output (non-JSON, a non-numeric PR number, a short SHA, a non-https URL) makes the script exit non-zero without emitting an outcome. A stub that never answers makes the call end within its time limit.
- [ ] AC-6: Across all tests, the gh stub's invocation log shows only read operations, always with the explicit repository (except the default-repository query), and no git ref changes. (TS20)

## Test Notes

- The gh stub is a small executable placed first on PATH. It answers from per-test fixture files and appends every invocation's arguments to a log the test inspects.
- Remotes are configured in a temporary repository with placeholder GitHub and non-GitHub URLs; nothing touches the network.
- The time-limit case in AC-5 uses a stub that sleeps longer than a short limit; the test passes that limit through an option or environment value the script documents for tests.

## Out of Scope

- Pushing, creating or merging PRs (the skill's direct operations).
- Waiting for checks.
- Choosing the remote (merge-git route).
