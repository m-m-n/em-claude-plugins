# Task Plan: task0009 — Plugin manifest descriptions and minor version

## Goal

The em-workflow manifests describe the new merge skill, and the em-workflow version's minor component is raised in both places that carry it.

## Requirements

FR23

## Scope

### Files to Create

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — description mentions the merge skill; version minor raised
- `.claude-plugin/marketplace.json` — em-workflow entry: description mentions the merge skill; version set to the same value as plugin.json

## Design

- **Descriptions**: add a short phrase about unattended merging of a completed feature (`/em-workflow:merge`) to both descriptions, keeping their existing wording otherwise.
- **Version**: raise the minor component of the em-workflow version in `em-workflow/.claude-plugin/plugin.json` and in the em-workflow entry of `.claude-plugin/marketplace.json` to the same value, with the patch component reset to zero (FR23, D10). Other plugins' entries are untouched.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Both files parse as JSON, and both em-workflow descriptions mention the merge skill.
- [ ] AC-2: The em-workflow version is identical in plugin.json and in the marketplace entry. Compared with the integration base commit, its minor component is one greater and its patch component is zero; its major component is unchanged. (TS26)
- [ ] AC-3: No other plugin's entry in `.claude-plugin/marketplace.json` changes, and the existing plugin-invariant tests in `tests/` still pass.

## Test Notes

- AC-1 and AC-3 are checked by parsing the files and running the existing suite.
- AC-2 depends on the base commit, so it is checked in the verify phase (TS26) by comparing against the integration base rather than by a permanent unit test.

## Out of Scope

- README changes (task0007 owns the hook row, task0008 the skill row).
- Any other plugin's version.
