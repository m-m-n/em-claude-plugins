# Task Plan: task0010 — Bind PR decisions to the current base and integration tip

## Goal

`merge-pr.py` stops judging a PR without the current state: `state` always checks the PR's base branch, and neither `resolve` nor `state` reports `merged` for a PR whose head is not the commit this run is merging. The skill passes the values those checks need.

## Design

Contract: IMPLEMENTATION.md C1, C2, C6 (as updated by this rework); decisions D5, D6.

- **state (FR9)**:
  - `--base` is mandatory. A call without it is a malformed-arguments exit (exit 2, nothing on stdout), like any other missing argument.
  - A PR whose base branch differs from `--base` stops `pr_head_moved` with both branch names in `detail`. The existing reason code is kept; no new reason code is added (C2 stays closed and unchanged).
  - `merged` is reported only when the PR's head commit equals `--head`. A merged PR with any other head stops `pr_head_moved`.
  - The check order otherwise stays as it is: closed, draft, conflicting, then head and base.
- **resolve (FR7, FR8)**:
  - New mandatory argument `--integration-tip <40-hex SHA>`: the integration branch's commit this run is about to merge, or has just merged.
  - Only a MERGED PR whose head commit equals `--integration-tip` yields `merged`. A MERGED PR with any other head is ignored, and the decision continues with the open, draft, closed and none classes in the existing precedence. A feature whose integration branch advanced after an earlier PR merged therefore gets its open PR (`open`) or a new PR (`none`), never `merged`.
  - When several MERGED PRs match, the highest PR number is used, as today.
- **SKILL.md**:
  - Step 5.2 and the re-resolve in step 5.3 pass `--integration-tip <integration_tip>`, the value preflight returned.
  - Step 13.2's `state` call passes `--base <base_branch>`.
  - Step 13.2's post-merge re-resolve passes `--integration-tip <head_sha>`, the head it merged. The text no longer says that call is "the same as step 5.2".
  - Values stay literal identifiers already validated by the scripts; no variable expansion or command substitution (NFR1).
- The operation boundary is unchanged: the script still only reads through gh.
