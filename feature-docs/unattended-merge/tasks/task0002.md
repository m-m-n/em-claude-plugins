# Task Plan: task0002 — Preflight: target resolution, precondition, review findings, command approval

## Goal

`merge-preflight.py` decides, from the integration branch tip alone, whether a feature may proceed to merging. When it may, the script hands the skill validated values (project root, worktree path, base branch, verification commands).

## Requirements

FR2, FR3, FR4, FR5, FR13, FR22, NFR4, NFR5

## Scope

### Files to Create
- `em-workflow/scripts/merge-preflight.py` — preflight decision script (IMPLEMENTATION.md C4)
- `tests/test_merge_preflight.py` — unit tests with temporary git repositories and an approval-store override

### Files to Modify

## Design

Contract: IMPLEMENTATION.md C1, C2, C4. Checks run in C4's fixed order, and the first failure decides the stop reason.

1. **Feature name**: fails `^[a-z0-9][a-z0-9-]*$` → stop `invalid_feature_name` before any git command.
2. **Integration branch**: the local branch `em-workflow/<feature>/integration` must exist, else stop `integration_branch_missing`. The project root is derived as the main working tree root from the repository's common git directory. The worktree path is that root plus `.claude/worktrees/em-workflow/<feature>/integration`.
3. **workflow.yaml**: read `feature-docs/<feature>/workflow.yaml` from the branch tip's committed content, never from a working tree. Parse it with safe YAML loading only. Each of these stops `record_unreadable`:
   - the file is absent or unparseable
   - the document is not a mapping
   - the workflow list is not a list of mappings
   - the loader is unavailable
4. **base_branch**: must be present and a valid branch name within C1's conservative character set, not starting with `-`, else stop `base_branch_invalid`. Whether it exists locally or remotely is decided later by merge-git / merge-pr.
5. **Precondition (FR4, D8)**:
   - every workflow step's status must be exactly `completed` or `skipped`
   - a verify step whose `result` is `fail` also fails
   - stop `precondition_unmet`; detail lists every failing `step:status` pair (and `verify:result=fail`)
6. **Review records (FR5)**:
   - Among `feature-docs/<feature>/reviews/round<N>.yaml` at the tip (N a positive integer), take the largest N. With none, skip the check (`review_round` null).
   - Read the findings with the round-record shape owned by `em-workflow/references/review-phase.md`.
   - A finding whose severity is critical or high (compared case-insensitively) and whose resolution is neither exactly `fixed` nor exactly `declined` blocks.
   - Stop `unresolved_findings`; detail lists every blocking stable_id. An id that is missing or outside a conservative identifier pattern is listed as a fixed placeholder and still blocks.
   - An unreadable or malformed latest record stops `record_unreadable`.
7. **Approval (FR13)**:
   - Collect the non-empty `build_command`, `test_command` and `e2e_test_command` of every component (components in name order; build → test → e2e).
   - Run the plugin's `hooks/bash_guard.py` (located relative to this script) in its list mode for the project root; compare exact strings.
   - Any non-empty command not approved, a multi-line command, or a list call that fails → stop `commands_unapproved`; detail names each `component.field`.
   - The approval store is only read.
8. **Proceed**: emit C4's proceed fields. `commands` carries each command string verbatim.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Feature names and the integration branch are checked first (TS16, TM-1):
  - a name failing the pattern (uppercase, leading `-`, containing `;` or a space) stops `invalid_feature_name` and runs no git command
  - a valid name whose integration branch does not exist stops `integration_branch_missing`
- [ ] AC-2: Each of the following stops `record_unreadable` (TS16, TM-3):
  - workflow.yaml absent at the tip
  - an unparseable document
  - a non-mapping document
  - a document carrying a YAML object-construction tag (proving safe loading)
  - a workflow list that is not a list of mappings
- [ ] AC-3: base_branch is validated (TS16, TM-2):
  - missing, starting with `-`, or containing shell metacharacters (`;`, `$`, backquote, space, quote) stops `base_branch_invalid`
  - `main`, `release/1.2` and `feature_x` are accepted
- [ ] AC-4: The precondition holds only when every step is completed / skipped and verify's result is not fail (TS3, TM-4):
  - `implement: pending` stops `precondition_unmet` with `implement:pending` in the detail
  - `verify: failed` stops with `verify:failed`
  - verify completed with `result: fail` stops
  - all completed / skipped passes
- [ ] AC-5: Review findings are judged on the latest round only (TS4, TM-4):
  - round1 holds an unresolved high finding D; round2 holds a deferred high A, a declined critical B and a fixed high C → stop `unresolved_findings` whose detail contains A and none of B, C, D
  - only declined / fixed critical-high findings → passes
  - no round records → passes with `review_round` null
  - an unreadable latest round → `record_unreadable`
- [ ] AC-6: Approval uses an empty store pointed to by `EM_WORKFLOW_APPROVALS` (TS11, TM-5):
  - any non-empty command → stop `commands_unapproved` naming each unapproved `component.field`
  - the store file is byte-identical (or still absent) afterwards
  - empty commands are skipped
  - with every command approved → proceed, listing the commands verbatim in C4's order
- [ ] AC-7: On proceed the output carries every C4 field with validated values. Instruction-shaped text in free-text fields of workflow.yaml (such as `goal`) or in finding descriptions changes no verdict. The script writes nothing to the repository or the approval store, and runs git only for read operations (no fetch, push, merge, worktree or ref update) and no gh at all. (TS16, TS20, NFR4)

## Test Notes

- Every test builds its own temporary repository with an integration branch whose commits hold the workflow.yaml / round files for that case.
- AC-7's git restriction uses a PATH-prepended logging shim that delegates to the real git. gh is absent from the test PATH, or replaced by a stub that fails the test if called.
- AC-6 needs approved strings in a temporary store. Write the store in the shape bash_guard reads; check that shape in `em-workflow/hooks/bash_guard.py` and `em-workflow/references/command-execution-protocol.md`.

## Out of Scope

- Remote selection, PR handling and worktree inspection.
- Recording approvals of any kind.
- Running the verification commands.
