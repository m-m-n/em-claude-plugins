# Task Plan: task0011 — Literal pathspecs for conflicted paths

## Goal

In SKILL.md's conflict-resolution step, a conflicted path is always passed to git as a literal path, so a file name shaped like pathspec magic (for example `:(top)` or `:(top,glob)*.md`) can never make `git add` / `git rm` / `git log` act on other files.

## Scope

### Files to Modify

- `tests/test_merge_skill_doc.py` — existing step 9 assertions that look for the plain "git add -- " form updated to the literal form

## Design

Contract: IMPLEMENTATION.md D1 (guard-sensitive operations stay in SKILL.md); TM-6 in VERIFICATION.md.

- Quoting and `--` do not disable pathspec magic. git's `--literal-pathspecs` global option does, for every pathspec of that invocation.
- Every git command in step 9 that receives `<conflicted_path>` as a pathspec carries `--literal-pathspecs` directly after `git`:
  - staging: `git --literal-pathspecs add -- "<conflicted_path>"`
  - deletion: `git --literal-pathspecs rm -- "<conflicted_path>"`
  - attribution: `git --literal-pathspecs log --format=%H <merge_base>..MERGE_HEAD -- "<conflicted_path>"`
- Commands in step 9 whose pathspec is built only from validated identifiers (`feature-docs/<name>/`) may stay as they are.
- The existing "unattributable" conditions (paths containing `"`, `$`, backquote, `\` or a newline) are unchanged.
- The commit command, its fixed message and the rule against bypassing hooks are unchanged.

## Test Notes

- Extract the command forms from SKILL.md at test time rather than copying them into the test, so the behavioral tests prove the documented form, not a duplicate.
- Build each repository in a per-test temporary directory. Create the conflict with two branches that both change the magic-named file, and leave the merge in progress before running the form.
- Run git with an argument list (no shell), substituting the placeholder only. The point is the pathspec semantics, not shell quoting.
- AC-6 runs the hook as a subprocess with a JSON payload, the same way `em-workflow/hooks/tests/run-destructive-guard.py` does. Set `PYTHONDONTWRITEBYTECODE` so no bytecode is written under `em-workflow/`.
