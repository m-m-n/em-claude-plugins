# Task Plan: task0005 — em-workflow プラグイン version の同時 bump

## Goal

em-workflow プラグインの内容変更に合わせて、プラグイン定義とマーケットプレイス
定義の version を同じ値へ上げ、インストール済みキャッシュが更新される状態に
する。

## Requirements

FR12, NFR3, NFR4, NFR5

## Scope

### Files to Create

- `tests/test_verify_rework_lineage_cap_version_bump.py` — 2 マニフェストの
  version 一致と、本フィーチャーによる bump が行われたことのアサーション
  （TS10 と負の証明）

### Files to Modify

- `em-workflow/.claude-plugin/plugin.json` — version フィールド
- `.claude-plugin/marketplace.json` — em-workflow エントリの version フィールド

## Design

### 1. bump の規則

プロジェクトのルール（`.claude/rules/core-plugin-version-bump.md`）に従う。

- 上げる場所は 2 箇所。両方を**同じ値**にする。
- 刻み方は semver。本フィーチャーは既存の挙動の修正（batch モードの rework
  上限の数え方の変更）であり、patch 単位で上げる。
- 変更前の値は `0.1.61`。これより大きい値にする。
- 他プラグインの version は動かさない。

### 2. テストの位置づけ

既存の `tests/test_*_version_bump.py` 群と同じパターンに倣う。既存の
`tests/test_plugin_version_parity.py` が「2 マニフェストの一致」を汎用的に
検査しているため、本タスクのモジュールは**このフィーチャーによる bump が
実際に行われたこと**（変更前の値より大きいこと）を固定する役割を持つ。

- 2 つのマニフェストから em-workflow の version を読み、一致することを確かめる。
- その値が変更前の値より大きいことを、semver の数値比較で確かめる（文字列の
  辞書順比較にしない — `0.1.9` と `0.1.61` の順序を誤るため）。

### 3. スコープ

本タスクはドキュメント本文を一切変更しない。プラグインの description や name
にも触れない。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR12): プラグイン定義の version とマーケットプレイス定義の
      em-workflow エントリの version が同じ値である。
- [ ] AC-2 (FR12): その値が変更前の値（`0.1.61`）より大きい。patch 部分のみが
      上がっている。
- [ ] AC-3 (FR12): 他プラグインのエントリの version が変更されていない。
- [ ] AC-4 (回帰): 既存の `tests/test_plugin_version_parity.py` が通る。
- [ ] AC-5 (NFR3, NFR4): 新規テストモジュールが標準ライブラリのみを import し
      （JSON の読み取りは標準ライブラリで行う）、version が据え置きのままの
      合成データに対して同じ matcher が失敗することを示す負の証明を含む。

## Test Notes

- semver の比較は「major / minor / patch を整数に分解して比較する」方式で行う。
  プレリリース識別子は本プロジェクトの version 体系に存在しないため考慮しない。
- 変更前の値は本タスクのテスト内に定数として持つ。将来この定数が実際の値を
  追い越さないよう、比較は「変更前の値より大きい」という一方向の不等式に
  とどめ、特定の値との一致を要求しない。
- 負の証明: 変更前の値のままの合成データと、2 マニフェストの値が食い違う合成
  データの 2 種類を用意する。
- 本タスクは他タスクの成果物にアサートしない（version の値はドキュメント本文
  と独立）。

## Out of Scope

- ドキュメント本文の変更（他の全タスク）
- 他プラグイン（em-review など）の version
- `LICENSE` ファイルの生成・更新
- インストール済みキャッシュの手動更新（利用者側の Claude Code 再起動で反映
  される）
