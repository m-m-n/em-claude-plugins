# Task Plan: task0004 — interactive の Step C デフォルト条件付き変更と非変更ガード

## Goal

interactive の Step C 三択を維持したまま、`verify.status` が `failed` のときだけ
推奨デフォルトを「ブランチを残す」に切り替え、質問文に failed の事実と
`failed_items` 件数を提示する。あわせて review 側の cap 挙動と
`rework-task-synthesis.md` が変更されていないことを機械的に固定する。

## Design

### 1. 推奨デフォルトの条件付き切り替え（FR9）

Step C 手順 1 の AskUserQuestion は三択（`{base_branch}` にマージ / ブランチを
残す / PR を作成）を維持する。変えるのは推奨表示（デフォルト）の選び方だけ。

| 条件 | 推奨デフォルト |
|---|---|
| `verify.status` が `failed` 以外 | `{base_branch}` にマージ（現行どおり） |
| `verify.status` が `failed` | ブランチを残す |

さらに、`verify.status` が `failed` のときは質問文に次の 2 つを提示する。

1. verify が `failed` である事実
2. `failed_items` の件数

選択肢そのものは奪わない（interactive の本質は人が決めること）。塞ぐのは
「テストが落ちた状態でも Enter 一発でマージが選ばれる」という 1 点。

batch 側の挙動（質問せず「ブランチを残す」を自動選択）は現行のまま変えない。
三択それぞれの本文（マージ時のクリーン確認、ブランチを残す場合の扱い、PR
作成の手順）も変えない。

### 2. review 側の非変更ガード（FR10）

review の cap 到達時挙動は本フィーチャーで変更しない。意図的な非対称であること
を回帰テストで固定する。

固定する対象:

- `em-workflow/references/review-phase.md` の Phase R5 batch 節 —
  `batch.review_rework_count` によるカウント、残 finding を
  `resolution: deferred` にすること、その理由文字列
  `"batch mode: rework cap reached"` の 3 点が残っていること。
- `em-workflow/references/batch-mode.md` の Non-packet gates 表の
  `review.residual-critical-high` 行が現行の内容であること。
- `em-workflow/references/review-phase.md` が verify 側のカウンタを参照して
  いないこと。

これらのファイルは本タスクの `files` に含まれない（変更しないため）。他の
どのタスクもこの 3 点を変更しないことが本計画上明らかであるため、非変更の
アサーションを書いてよい（IMPLEMENTATION.md D2 の例外）。

注意: `batch-mode.md` は task0001 が別の行（`verify.failed` 行と `batch`
ブロック節）を変更する。本タスクのアサーションは `review.residual-critical-high`
行に限定し、ファイル全体のハッシュや全文一致では固定しない。

### 3. `rework-task-synthesis.md` の非変更（NFR2）

`em-workflow/references/rework-task-synthesis.md` は変更しない。同ドキュメントの
Invariant 7（interactive と batch は retry/round cap だけが違う）の記述が残って
いることを内容 pin として固定する。統合ブランチの差分に同ファイルが現れない
ことの確認（TS9）は verify フェーズの手動確認で行う。

## Test Notes

- 検査対象のセクションは Step C の手順 1。Step C の見出し行は task0002 が
  書き換えるため、**セクションの切り出しに Step C の見出し全文を使わない**。
  手順 1 のラベル（完了方式の決定）など、本タスクと task0002 のどちらも変更
  しない文字列を境界に使う（worktree 独立性のために必要な配慮）。
- TS11 は条件分岐の記述と提示要件の存在、および旧記述の不在を検査する。
  「デフォルト（推奨表示）は `{base_branch}` にマージ」という無条件形が残って
  いないことを非存在アサーションで確かめる。
- TS8（FR10 の回帰ガード）は本タスクが変更しない 2 ファイルを読む。行単位で
  切り出し、その中の 3 要素の存在だけを検査する。ファイル全体を対象にすると
  task0001 の変更で落ちる。
- NFR2 の pin は `rework-task-synthesis.md` の Invariant 7 の記述に限定する。
  同ファイルは他のフィーチャーでも参照されるため、広すぎる pin は将来の変更を
  過剰に縛る。
- 負の証明: 無条件デフォルトの旧文と、review 側の cap 記述が消えた合成テキスト
  の 2 種類を用意する。
