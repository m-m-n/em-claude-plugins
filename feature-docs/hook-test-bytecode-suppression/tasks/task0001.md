# Task Plan: task0001 — Load the destructive-guard hook without writing bytecode in two test modules

## Goal

`load_hook()` in `tests/test_destructive_guard_extglob_units.py` and
`_load_hook()` in `tests/test_destructive_guard_lexer_agreement.py` stop
writing bytecode for `em-workflow/hooks/destructive-guard.py`. Each turns
bytecode writing off only while the hook module body executes, and restores
the caller's value afterwards. New tests pin this. A single run of either
module, and a whole-suite run, then leave no `__pycache__` under
`em-workflow/hooks/`.

## Requirements

FR1, FR2, FR3, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_destructive_guard_extglob_units.py` — the load_hook() helper follows the loader contract below; a new test class pins the contract; the module docstring is updated.
- `tests/test_destructive_guard_lexer_agreement.py` — the _load_hook() helper (whose import-time call binds the module-level hook H) follows the same contract; a new test class pins it; the module docstring is updated.

## Design

Cross-task conventions (flag discipline, nothing written under
`em-workflow/`) and the whole-run ordering finding (D2) are in
IMPLEMENTATION.md. They are not restated here.

### Loader contract (both helpers)

This applies to `load_hook()` (extglob_units) and `_load_hook()`
(lexer_agreement).

- **Call form and result (unchanged)**:
    - Called with no arguments, each helper returns a newly created module.
      The module is executed from `em-workflow/hooks/destructive-guard.py`
      under the module name the helper uses today.
    - Every call yields a fresh module. extglob_units relies on this: each
      load starts with an empty lexer cache.
    - The tests may need to aim a helper at another file. An optional
      parameter that defaults to today's target is allowed for that. The
      no-argument call keeps today's behavior.
- **Precondition**: none on the flag. The helper works whether
  `sys.dont_write_bytecode` is False or True on entry.
- **While the module body executes**: `sys.dont_write_bytecode` is True,
  from just before execution starts until it ends, normally or by raising.
  The window does not extend past the helper call.
- **Postcondition, normal return**: the flag holds exactly the value it
  held just before the call.
- **Postcondition, raise**: the flag holds exactly the value it held just
  before the call. The exception reaches the caller as raised: not
  swallowed, not replaced.
- **Precedents in the repository**: two helpers already follow this
  contract with the standard library only. One is `load_hook_module()` in
  `tests/test_queue_launch_guard_linked_layout.py`. The other is
  `load_merge_module()` in `tests/test_destructive_guard_merge_allow.py`.

### Flow (per helper)

1. Remember the flag's current value.
2. Turn bytecode writing off (flag True).
3. Execute the hook module body.
4. On every exit from step 3, normal or by exception, put back the value
   from step 1.
5. Return the module on a normal exit. Otherwise let the exception
   propagate.

The module-level binding in lexer_agreement still calls `_load_hook()` once
at import, and its value stays what the existing tests use.

### New tests (one test class per module)

Each module gets its own class, because each covers its own helper. A name
stating the behavior works, e.g. "the hook load writes no bytecode". The
class checks:

- **Flag during execution**: while the loaded module's body runs, the flag
  is True. Checked with the starting value False and with True.
- **Flag after return**: after a normal return, the flag equals the
  starting value. Checked for False and True.
- **Flag after raise**: the loaded module's body raises an exception
  specific to the test. The flag equals the starting value afterwards, for
  False and True, and the caller receives that exception.

How the tests run:

- **Probe module**: these tests do not load the real hook. They aim the
  helper at a probe module that the test writes into a test-owned temporary
  directory. The probe either records the flag value its body sees, or
  raises.
    - Aiming the helper can work in two ways. One temporarily replaces the
      module's hook-path constant for the test's duration. The other uses
      the optional parameter (see the contract above).
    - With a probe, a broken helper can never write under
      `em-workflow/hooks/`.
- **Starting value**: every test sets the starting value itself and does
  not inherit it. In a whole run the inherited value is already True (D2).
- **Restoring the flag**: before it ends, every test puts back the value it
  found. This holds on every exit path: pass, fail and error.
- **Coverage of the real hook**: existing tests in both modules still load
  the real hook through the helpers. The command-level checks (AC-6) cover
  the real hook's bytecode.

### Docstrings

- In each module docstring, the Layout list gains one line for the new
  class. Following the existing lines, it names this feature
  (hook-test-bytecode-suppression task0001) and the requirement IDs it
  covers.
- In each module docstring, the sentence saying the hook is loaded from its
  file path also says that the load writes no bytecode.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1): While the module body loaded by `load_hook()` in
  `tests/test_destructive_guard_extglob_units.py` executes,
  `sys.dont_write_bytecode` is True. This holds whether the value before
  the call is False or True.
- [ ] AC-2 (FR2): While the module body loaded by `_load_hook()` in
  `tests/test_destructive_guard_lexer_agreement.py` executes,
  `sys.dont_write_bytecode` is True. This holds whether the value before
  the call is False or True. The module-level hook binding is still made
  by an import-time call to `_load_hook()`.
- [ ] AC-3 (NFR3): After either helper returns normally,
  `sys.dont_write_bytecode` equals the value it held just before the call.
  Tested with starting values set explicitly to False and to True.
- [ ] AC-4 (FR1, FR2, NFR3; SPEC Edge Cases): When the loaded module body
  raises, after the call `sys.dont_write_bytecode` equals the value it held
  just before the call. Tested for both helpers with starting values False
  and True. The caller receives the raised exception itself.
- [ ] AC-5 (NFR3): Every test added by this task leaves
  `sys.dont_write_bytecode` at the value it held when the test started,
  whether the test passes, fails or errors. None of these tests creates,
  deletes or renames a file under `em-workflow/`.
- [ ] AC-6 (FR1, FR2, FR3): Each command below starts with no `__pycache__`
  directory anywhere under `em-workflow/hooks/`, in an environment that
  neither disables nor redirects bytecode writing. Each is run from the
  repository root. Afterwards there is still no `__pycache__` directory
  under `em-workflow/hooks/`, `em-workflow/hooks/tests/` included:
  (a) `python3 -m unittest tests.test_destructive_guard_extglob_units`,
  (b) `python3 -m unittest tests.test_destructive_guard_lexer_agreement`,
  (c) `python3 -m unittest discover -s tests`.
- [ ] AC-7 (NFR1, NFR2): `python3 -m unittest discover -s tests` and
  `python3 em-workflow/hooks/tests/run-destructive-guard.py` both exit 0.
  This includes the `TestModuleContract` class of both modules, which
  checks standard-library-only imports. Every pre-existing test in the two
  modules passes without changes to its assertions. The task's change set
  modifies only the two files listed in Scope.

## Test Notes

- **Unit tests (AC-1 to AC-5)**: they go in each module's new class (see
  Design). Write them first.
    - Against the unchanged helpers, the "flag True during execution from
      False" checks of AC-1 and AC-2 fail. That is the red step.
    - AC-3 and AC-4 already pass before the change, because nothing changes
      the flag yet. They pin the restore behavior the change must keep.
- **Command-level checks (AC-6)**:
    - Before running them, confirm that `PYTHONDONTWRITEBYTECODE` and
      `PYTHONPYCACHEPREFIX` are unset. Do not pass the interpreter's `-B`
      option. Otherwise the checks pass without proving anything.
    - List any `__pycache__` directory under `em-workflow/hooks/`, for
      example with a `find` limited to that directory.
    - The red step and any earlier run in this worktree can leave
      `em-workflow/hooks/__pycache__/` behind. It is git-ignored, so it does
      not show in `git status`. Remove it with `gio trash`, never with `rm`
      (IMPLEMENTATION.md D3).
    - Run (a), (b) and (c) in that order and check after each one. A
      passing run leaves the starting state for the next one.
- **Change-set check (AC-7)**: compare against the implement step's
  `base_commit` in workflow.yaml.
- **Edge case**: in a whole run, `sys.dont_write_bytecode` is already True
  when these modules' tests run. `tests/test_merge_ci_wait.py` sets it at
  import (IMPLEMENTATION.md D2). Tests that inherit the value instead of
  setting it would pass even against a helper that never restores the flag.
- **Placement in lexer_agreement**: the module is large (over 6000 lines).
  Add the new class next to `TestModuleContract` or at the end of the
  module. Do not reorder existing classes.
- **NFR2**: the temporary directory and the temporary replacement of a
  value both come from the standard library. Each module's import check
  accepts them.
