# Task Plan: task0001 — R1 Order: return-time recheck and Known limit

## Goal

Rule R1's "Order" states the return-time recheck as the orchestrator's step
after the comparison and before the recording write, and "Known limit" says
which window the recheck covers and which window rests on the exclusivity
assumption. Document tests pin both.

## Requirements

FR1, FR2, FR5, FR8, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6, NFR7

## Scope

### Files to Create
- `tests/test_return_time_recheck_docs.py` — document tests for the recheck in R1 "Order" and for "Known limit" (FR8 (b)), with forged-text controls

### Files to Modify
- `em-workflow/references/contracts/worker-envelope.md` — Rule R1: the "Order" block gains the return-time recheck after step 4; the "Known limit" block gains the post-scope-verification and remaining-window statements

## Design

Shared terms ("return-time recheck", "recording write", the interval end
point) and decisions D1–D3 are in IMPLEMENTATION.md; they are not restated
here.

**Order block (FR1, FR2).** Keep the intro sentence ("only after the scope
verification has produced the observed change set") and steps 1–4 with
their wording. Add, after step 4 and still inside the Order block (before the
`**Means.**` label), the return-time recheck. It must state, with the
orchestrator as actor:

1. When it runs: after step 4's comparison has not made the result stale and
   after Layer 5's `Calculation` (`references/artifact-digest.md`) when
   `written_artifacts` is non-empty; before the recording write (the
   phase-state write that records the run's `artifacts` and
   `self_write_set`; for an empty `written_artifacts`, the write recording
   the returned `status` and `self_write_set`).
2. What it compares: for each path of the self-write set, the current git
   blob id (`git hash-object --`), mode and kind (file / symlink / absent),
   against the values the same run's scope verification observed for that
   path after the dispatch (`references/phases/create-spec-phase.md`, "Scope
   verification").
3. What it never compares: a raw-byte sha256 (the artifact digest of
   `references/artifact-digest.md`, `digest_inputs` values) — stated as a
   negated sentence.
4. Outcome: any mismatch, or a recheck that cannot run (a read failure
   included), makes the result stale, handled as the scope verification's
   stale handling states; a stale result reaches no recording write. An
   empty self-write set passes with nothing to do.
5. The recording write follows only a passing recheck.

The text uses the literal term `return-time recheck` at least once in the
Order block. It places the recheck's elements after the four existing step
anchors and before the phrase that names the recording write, so the order
reads in one pass.

**Known limit block (FR5).** Keep the existing sentence verbatim (worker and
another actor changing the same permitted path; cannot be told apart; rests
on the exclusivity assumption stated below). Append sentences, before the
`(Provenance:` paragraph, stating: a change made after the scope
verification is detected by the return-time recheck; the remaining window
from the recheck to the recording write rests on the exclusivity
assumption, whose interval the section below states. Point at that section
instead of restating the interval's variants here.

**Constraints from existing tests (must keep passing unchanged):**
`tests/test_self_write_digest_docs.py` — every R1 label appears exactly
once; Order keeps its four anchors in sequence and "mismatch, or a script
exit other than `0`, makes the result stale"; Known limit keeps "worker and
another actor change the same permitted path", "cannot be told apart",
"exclusivity assumption" and precedes the Exclusivity heading; every
sentence of the R1 labelled region that mentions a digest / hash / sha256
names the orchestrator or is negated; no worker-directed digest
instruction; no `expect_digest` token anywhere in the document; the
normalization paragraph, the seven `digest_source` keys and the timing
paragraph's existing sentences are unchanged; `worker_digest_stance` passes.

## Test Notes

- All criteria are unit-level document tests over `worker-envelope.md`.
- Slice the Order block from `**Order.**` to `**Means.**` and the Known
  limit block from `**Known limit.**` to the `(Provenance:` paragraph;
  normalize whitespace before matching.
- Order probe: first positions of the four existing anchors, then the recheck
  term, then the recording-write phrase, strictly increasing.
- Element probes (AC-2, AC-3) are presence probes on the recheck text only
  (the text after step 4's anchor), so that step 4's own "stale" wording
  cannot satisfy them.
- Forged controls: the pre-change Order block and Known limit block (as they
  read at this feature's base) and single-element deletions of the new text.
- A sentence naming `git hash-object` must carry "orchestrator" or a negation
  — check it with the same convention the existing test applies.
