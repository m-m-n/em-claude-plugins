# Task Plan: task0002 — Exclusivity interval through the recording write

## Goal

The exclusivity assumption's interval ends at the completion of the
recording write (or at the stale judgment) in both documents that state it,
with the same end point in both. Document tests pin the end point.

## Requirements

FR3, FR4, FR8, NFR1, NFR2, NFR3, NFR5, NFR7

## Scope

### Files to Create
- `tests/test_exclusivity_interval_docs.py` — document tests for the interval end point in both documents (FR8 (a)), with forged-text controls

### Files to Modify
- `em-workflow/references/contracts/worker-envelope.md` — section "Exclusivity assumption during dispatch": the interval sentence
- `em-workflow/references/phases/create-spec-phase.md` — section "Exclusivity assumption (normative)": the "Scope of applicability" paragraph

## Design

The end-point contract ("Exclusivity interval end point" and "Recording
write") and decision D4 are in IMPLEMENTATION.md; they are not restated
here.

**worker-envelope.md (FR3).** In the paragraph after the quoted assumption,
replace only the interval's end ("through the end of that dispatch's scope
verification") with the IMPLEMENTATION.md end point: through the completion
of the phase-state write that records the run's `artifacts` and
`self_write_set`; for a run whose `written_artifacts` is empty, through the
write that records its returned `status` and `self_write_set`; when the
result is judged stale, through that judgment. Keep, in the same
paragraph: "only to the five workers in the 2.3 applicability table", the
start ("from the start of the dispatch's scope snapshot capture"), "it is
not a standing constraint on the plugin as a whole", and the review
wave-parallel auto-fix loop exception with `references/review-phase.md`.
Keep the heading and the quoted assumption unchanged.

**create-spec-phase.md (FR4).** In `**Scope of applicability**`, replace only
the end ("through the end of verification") with the same end point and the
same two variants. Keep "only to the five workers in design-input.md 2.3",
the start ("from taking the scope snapshot"), and "it is not a standing
constraint on the plugin as a whole". Keep the heading, the quoted
assumption, the review-phase exception paragraph, "Why the assumption
holds", and the not-enforced table unchanged.

The two documents may differ in surrounding sentence shape, but each names
the same end-point elements: the phase-state write, `artifacts`,
`self_write_set`, the empty-`written_artifacts` variant naming `status`, and
the stale judgment.

**Constraints from existing tests (must keep passing unchanged):** the
heading `## Exclusivity assumption during dispatch` stays and stays after
R1's `**Known limit.**` label (`tests/test_self_write_digest_docs.py`);
`worker_digest_stance` passes (no worker-directed digest instruction is
added; no `expect_digest` token enters `worker-envelope.md`);
`tests/test_check_plugin_invariants.py` and
`tests/test_worker_contracts_create_spec.py` pass.
