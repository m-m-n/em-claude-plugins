## Design

### The new bullet (identical meaning in both files)

- A top-level bullet of the Skip Semantics list, for a reviewer whose call of
  the contributor tier (`muse-spark-contributor`) muse_guard denied.
- Carries the skip object exactly as IMPLEMENTATION.md Shared Components
  "Skip object" pins it (SPEC.md FR1), on one line.
- States the role split pinned in IMPLEMENTATION.md Shared Components ("Role
  split after the deny"): the reviewer returns the object and ends; it does
  not retry the same entry as plain `muse-spark`; it does not record or
  re-judge consent; it does not choose another model or chain entry; the
  orchestrator selects the next entry.

### Placement and statements

| | em-workflow | em-review |
|---|---|---|
| Position of the new bullet | after the `harness_unavailable` bullet and before the bullet holding the retryable-set statement | inside the retryable group, before the bullet holding the retryable-set statement |
| Retryable-set statement | SPEC.md FR1 sentence with `five`; the chain-walk sentence (`walks the perspective's fallback chain on exactly these strings`) is kept | SPEC.md FR2 sentence with `four`; the chain-walk sentence is kept |
| Non-retryable statement | SPEC.md FR1 sentence (`... outside the five above, is NOT retryable`) | SPEC.md FR2 sentence (`These last two are NOT retryable, like every value outside the four above`) |
| After the statement | `review_data_too_large` does not appear | the `scratchpad_unavailable` and `review_data_too_large` bullets stay after it |

Only the Skip Semantics section changes; every other section of both files
keeps its bytes (several are hash-frozen by `tests/test_reviewer_roles_protocol.py`).
