# Task Plan: task0001 — Rewrite the muse_guard DENY_CONTEXT to the reviewer-conditional recovery route

## Goal

Both `muse_guard.py` copies tell a denied agent the route the review protocol
defines: a reviewer returns the `contributor_consent_missing` skip object and
ends; any other agent continues without the contributor tier. Nothing else in
the hook changes.

## Design

### DENY_CONTEXT contract

- A module-level string constant that renders as exactly one line (no line
  break character in the value).
- The only value embedded in it is `PLUGIN_SLUG`. Nothing from the hook input
  (command text, working directory) and nothing derived from it (project key,
  store path) is ever embedded.
- Three clauses, in this order:
  1. What to do instead, in two branches. When the agent is acting as a
     reviewer: return the skip object whose `skip_reason` is
     `contributor_consent_missing` and end. Otherwise: do not look for a
     workaround, and continue the work without the contributor tier.
  2. Consent is recorded only when the user runs the
     `/{PLUGIN_SLUG}:contributor-consent` skill in an interactive session.
  3. The agent must not run `muse_guard.py --record` to consent on its own.
- Keeps the string `muse-spark` (for example inside the tier name).
- Drops the current instruction to continue with a non-contributor
  `muse-spark` entry of `reviewers.yaml` or with another chain entry. No
  sentence tells the agent to switch to any chain entry or model.
- The comment above the constant is updated to describe the two-branch first
  clause; the comment above DENY_REASON is not changed.

The skip object and the role split it relies on are pinned in
IMPLEMENTATION.md Shared Components ("Skip object", "Role split after the
deny"); this task names only the `skip_reason` value, never the full object.

### What stays unchanged (NFR1)

Classification, the store read, fail-open behavior, the deny-only decision
(no `ask`, no `allow`), the four-field payload, DENY_REASON, the CLI path and
every other line except DENY_CONTEXT and its comment.

### Twin constraint (FR7)

The same edit is made to both copies, so they keep the same line count and
differ only on the `PLUGIN_SLUG` line.
