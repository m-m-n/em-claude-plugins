### Pin update

- The module-level constant that holds the preconditions phrase (currently
  `R2_PRECONDITIONS_PHRASE`, "This exit is reached once three preconditions all hold:
  the ancestor check just failed; ...") is replaced by the reviewed preconditions
  sentence, copied verbatim from I.2.b step 1's ancestor-check bullet of the live
  document at this task's base commit (whitespace-normalized matching, Convention 6).
  The existing positive test `test_all_new_phrases_present` keeps its name and keeps
  reading this constant.
- The old phrase "the ancestor check just failed" becomes an absence assertion with a
  negative proof against a verbatim sample of the same bullet taken from the parent of
  commit `4ad3d3b3` (the only revision that still carries it), plus a retained-anchor
  guard (a phrase present in both that sample and the live bullet).

### New clause pins

Three new module-level constants, each copied verbatim from the live ancestor-check
bullet at this task's base commit, each matched only inside that bullet's slice:

1. Exit-1 restriction — the clause stating that the precondition holds only when the
   task branch ref resolves and the ancestor check on it exits 1 (not an ancestor),
   rather than any other exit code.
2. Exit-128 non-invocation — the sentence stating that an exit code of 128 does not
   lead to the `merge-unverified` helper invocation.
3. Already-`merged` exclusion — the sentence excluding a task whose `workflow.yaml`
   status already reads `merged` from the invocation.

Each new pin has a positive test (constant present in the live bullet) and a negative
proof: a derived copy of the verbatim live bullet sample with exactly that clause
removed, on which the same matcher returns no match, guarded by a retained anchor
that is still present in the derived copy (so the proof cannot pass vacuously).
