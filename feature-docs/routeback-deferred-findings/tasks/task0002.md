# Task Plan: task0002 — evidence chain accepts observed artifact absence

## Goal

`evaluate_stale_launched_chain` in `em-workflow/scripts/recover-orphaned-task.py`
treats `--worktree-present` / `--branch-present` values `yes` and `no` as observed
evidence and continues through its unchanged remaining steps, reserving
`task-artifacts-missing` for an absent or unrecognized artifact observation — so a
stale `launched` task with one or both artifacts missing can reach `recovered` under
full termination and stop-result proof.

## Requirements

FR2, FR10, NFR5, NFR8

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/scripts/recover-orphaned-task.py` — step 1 of the opt-in evidence chain, the module docstring (caller preconditions, step 1 description, meaning of the narrowed residual code) and the argparse help of the three artifact-related flags
- `tests/test_stale_launched_recovery_chain.py` — convert the existing artifact-absence and direct step-order tests to unrecognized tokens, and add missing-artifact recovery and residual cases at function level and command-line level

## Design

Normative contract: IMPLEMENTATION.md SC-2 and D1 / D2.

### Step 1 of the evidence chain (new behaviour)

1. Artifact observations: each of the worktree and branch observations must be
   exactly the string `yes` or exactly the string `no` (case-sensitive). If either is
   absent or is any other token, end with residual `task-artifacts-missing`. This
   decision still happens before any agent-index read, any path assembly and any file
   open (the existing step-order property).
2. Both observations recognized (any of the four yes/no combinations): keep them as
   evidence and continue. No later step branches on them; `no` never ends the chain.
3. The journal-state pre-check that follows (terminal event → `noop_terminal`; any
   non-`launched` event → `journal-not-launched`) is unchanged.

Steps 2 through 7 (launch-bound agent entry, session identity, agent-identity binding,
termination, stop result, one helper invocation with reason `stale-launched` and the
last `launched` event's raw `at`) are unchanged. The identity-binding step keeps
comparing `--task-worktree` as a plain string with the entry's recorded worktree; the
caller now supplies the expected path `$WT_ROOT/{T}` whether or not it exists, so no
existence check may be introduced there.

### Unchanged

- The chain-entry rule in the decision entry point: any supplied evidence input
  (including `no`) opts in from the same-session branch only; supplying none keeps the
  legacy `same-session` outcome.
- The legacy chain: it consults no artifact input and its steps, codes and helper
  invocation (`orphaned`, no launch identity) do not change.
- The closed set of sixteen residual reason codes (names, membership, order);
  `task-artifacts-missing` stays defined, with the narrowed meaning.
- Outcome shape and exit codes of the script.

### Docstring and help updates

- Remove the caller precondition that the task worktree and task branch exist. State
  the caller's candidate conditions as: journal last event `launched`, the task's
  `Task()` call not outstanding in the reconcile step, and the Agent index lookup
  resolving no live agent; artifact state is evidence, never a precondition.
- New-chain step 1 description: `yes` / `no` observations are accepted as evidence;
  `task-artifacts-missing` only for an absent or unrecognized observation.
- Help for the two presence flags: an observation, exactly `yes` or `no`. Help for
  `--task-worktree`: the task's expected worktree path, supplied whether or not it
  exists.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR2): Starting from the shared proving fixture, each of the observation
  pairs (worktree `no`, branch `yes`), (worktree `yes`, branch `no`) and (worktree
  `no`, branch `no`) yields outcome `recovered`, both through the decision entry point
  and through a direct call of `evaluate_stale_launched_chain`; the stub helper is
  invoked exactly once with the task id, reason `stale-launched`, the journal path,
  and the last `launched` event's raw `at` as launch identity.
- [ ] AC-2 (FR2): An absent observation, or an observation that is not exactly `yes`
  or `no` (for example `Yes`, `absent`, the empty string), on either flag yields
  residual `task-artifacts-missing`, the stub helper is not invoked and the journal is
  byte-identical; a direct call with nonexistent agent-index and journal paths plus an
  unrecognized token still yields `task-artifacts-missing`, proving the decision
  precedes any read or open.
- [ ] AC-3 (FR2, NFR5): For each of the three missing-artifact pairs, a termination
  observation of absent, `launch-accepted`, `error` or `output-idle` yields
  `agent-termination-unproven`, `running` yields `agent-still-live`, and a non-proving
  stop result yields `stop-result-unproven`; in every case the journal is
  byte-identical and the helper is not invoked.
- [ ] AC-4 (FR2): A `--task-worktree` value naming a path that does not exist on disk
  but equals the entry's recorded worktree still binds (the run reaches `recovered`
  with the other proofs); a value differing from the recorded worktree yields
  `agent-identity-unproven`.
- [ ] AC-5 (FR2): The module's sixteen residual reason constants are exactly the
  pre-change sixteen values; every pre-existing test in
  `tests/test_recover_orphaned_task.py` passes unmodified (legacy chain unchanged).
- [ ] AC-6 (FR2): Through the command-line entry point, `--worktree-present no
  --branch-present no` together with every other proving flag exits 0 and prints
  outcome `recovered`; `--worktree-present maybe` with the same flags prints residual
  `task-artifacts-missing`.
- [ ] AC-7 (FR2, FR10): The module docstring no longer contains "the task worktree and
  task branch exist" nor "both `--worktree-present` and `--branch-present` read
  `yes`", and states that `yes` / `no` observations are accepted as evidence and that
  `task-artifacts-missing` means an absent or unrecognized observation; each absence
  assertion has a negative proof against a verbatim pre-change docstring excerpt.
