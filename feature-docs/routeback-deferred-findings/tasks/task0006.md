# Task Plan: task0006 — em-workflow version bump 0.2.10 → 0.2.11

## Goal

The em-workflow plugin version reads 0.2.11 in both registries, so installed copies
pick up this feature's plugin changes, and a new test pins that both registries agree
and are past the pre-feature baseline 0.2.10.

## Requirements

FR9, FR10, NFR8

## Scope

### Files to Create

- `tests/test_routeback_deferred_findings_version_bump.py` — version-lockstep test against the pre-feature baseline 0.2.10

### Files to Modify

- `em-workflow/.claude-plugin/plugin.json` — version from 0.2.10 to 0.2.11, nothing else
- `.claude-plugin/marketplace.json` — the em-workflow entry's version from 0.2.10 to 0.2.11, nothing else

## Design

Normative reference: IMPLEMENTATION.md D9. This task is the only one touching either
registry.

- The em-workflow entry in the marketplace registry is located by its `name`, never by
  position; the em-review entry and every other field in both files stay unchanged.
- The new test follows the existing `*_version_bump.py` pattern: parse each version as
  three integer components, assert both are strictly greater than the baseline 0.2.10
  by per-component integer comparison, and assert they are equal. It never pins the
  literal 0.2.11, so it keeps holding after later bumps.
- Negative proofs in the same module: the raw-string comparison trap (a two-digit
  patch component sorting below a one-digit one as text), a version equal to the
  baseline is rejected, two differing versions are rejected, a malformed version shape
  is rejected.
