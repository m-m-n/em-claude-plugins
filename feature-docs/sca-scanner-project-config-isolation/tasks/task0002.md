# Task Plan: task0002 — Document isolation-directory execution and guard the unchanged scan surfaces

## Goal

Two outcomes:

- The axis 2 description in `review-phase.md` states the new npm / cargo execution location, the isolation failure tokens and the trusted configuration scope.
- New guard tests pin the pip / go jobs, the `ECOSYSTEM_ENV_PINS` values and HOME pass-through, so the isolation change cannot silently alter them.

## Requirements

FR10, FR11, FR13, NFR4

## Scope

### Files to Create

- `tests/test_sca_scan_unchanged_surfaces.py` — guard tests for the pip / go jobs, the ECOSYSTEM_ENV_PINS values and HOME pass-through, driven by offline recording stubs

### Files to Modify

- `em-workflow/references/review-phase.md` — axis 2 description of where and how npm / cargo scans run, the isolation failure tokens and the trusted configuration scope
- `tests/test_sca_review_phase_multi_project_coverage.py` — align its assertions on the axis 2 text with the updated description

## Design

The contracts this task documents and guards are pinned in IMPLEMENTATION.md Shared Components: the isolation failure reason tokens, the npm / cargo execution-location contract, the unchanged scan surfaces and the trusted configuration scope. This task states them. It does not extend them.

### review-phase.md, axis 2

- Replace every statement that npm / cargo run with the reviewed project root as cwd with the execution-location contract. That means:
    - a per-group isolation directory outside the reviewed tree;
    - npm gets copies of `package.json` and the selected anchor;
    - cargo gets a copy of `Cargo.lock`;
    - cargo-audit gets the copy through `--file`, with no `--url` / `--db`.
- State the failure handling:
    - the unit becomes `not_completed` with `npm_isolation_failed` / `cargo_isolation_failed`;
    - there is no fallback to the reviewed tree;
    - the other groups continue and their findings are kept.
- State the trusted configuration scope (FR11).
- Leave the rest of axis 2 as it is: grouping, the binding check, processing order and pip / go behavior.

### Guard tests (new file)

- Expected values are literal, pinned from the pre-change behavior that the implementer observes in the base code.
- They must hold both before and after the isolation change merges (IMPLEMENTATION.md D2). Therefore no assertion depends on the npm / cargo cwd or on the cargo argv, which that change alters.
- pip / go: drive run_scan with offline stubs that record argv, cwd and environment.
- ECOSYSTEM_ENV_PINS: compare it with a literal snapshot of every ecosystem key and value.
- HOME: for each of the npm, cargo, pip and go child processes, the stub records HOME.
- This file owns its own stub harness (IMPLEMENTATION.md Conventions).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR10): For pip and go invocations made through run_scan and recorded by offline stubs, argv and cwd equal literal expected values pinned from the pre-change behavior. The recorded environment equals the runner's environment with that ecosystem's existing pins applied, with no variable added or missing.
- [ ] AC-2 (FR10, FR11): ECOSYSTEM_ENV_PINS equals a literal snapshot of its pre-change content for every ecosystem key. No key is added, removed or changed.
- [ ] AC-3 (FR11): For the npm, cargo, pip and go child processes, the recorded HOME equals the runner's HOME. None of the assertions in AC-1 to AC-3 depends on the npm / cargo cwd or on the cargo argv.
- [ ] AC-4 (FR11, FR13): The axis 2 section of `review-phase.md` states each of the following:
    - (a) the per-group isolation directory outside the reviewed tree, holding the copied inputs, is the npm / cargo cwd;
    - (b) cargo-audit receives the copy via `--file`, with no `--url` / `--db`;
    - (c) on isolation failure, the unit becomes `not_completed` with `npm_isolation_failed` / `cargo_isolation_failed`, there is no in-tree fallback, and the other groups continue;
    - (d) the trusted configuration scope.

  It contains no statement that npm / cargo run with the reviewed project root as cwd. A test in this task asserts that both tokens and `--file` appear in the axis 2 section.
- [ ] AC-5 (NFR4): All of the following hold:
    - The new and updated tests use the standard-library unittest only, run offline, and require no real scanner.
    - `python3 -m unittest discover -s tests` passes.
    - `python3 em-workflow/scripts/check-plugin-invariants.py .` passes.

## Test Notes

- Base the pinned literals on the code as it is in this task's worktree. These are characterization tests and pass there before any other change.
- Stubs are test-owned executables placed first on PATH. Each writes its record to a file named by a test-set environment variable and prints a well-formed clean result for its ecosystem.
- Point the temp parent at a test-owned directory that is a sibling of the test project tree, so the assertions stay valid once npm / cargo run from an isolation directory.
- Restore every environment variable the tests change.
- The `review-phase.md` assertion (AC-4) checks for the presence of the tokens and `--file` within the axis 2 section. The wording itself is reviewed by inspection.
