# Task Plan: task0001 — Consume the values of value-taking pip options on requirements option lines

## Goal

The requirements-file option-line reader in the dependency scanner consumes and
discards the value of every value-taking pip option, so a value token is never
mistaken for `-r` / `-c` / `-e`, and it treats every abbreviation of a
value-taking long option as undetermined. Both the silent under-reporting path
(an include swallowed while the name set stays complete) and the
over-reporting path (a value read as an editable or an include) disappear.

## Design

### Option groups

The reader distinguishes two groups of value-taking options. Short forms are
case-sensitive: `-C` (config settings) is a different option from `-c`
(constraint).

| Group | Options | Value handling |
|-------|---------|----------------|
| Interpreted (unchanged) | include `-r` / `--requirement`; constraint `-c` / `--constraint`; editable `-e` / `--editable` | As today: include and editable produce items, constraint values are consumed and never opened |
| Value-only (new) | `-i` / `--index-url` / `--pypi-url`; `--extra-index-url`; `-f` / `--find-links`; `--trusted-host`; `--no-binary`; `--only-binary`; `--use-feature`; `--hash`; `--global-option`; `-C` / `--config-settings` | The value is consumed and discarded; it never produces an item and never affects completeness |

`--install-option` belongs to neither group (it stays an ignored unknown
option). The set of value-taking long names used by the abbreviation check is
the three interpreted long names plus every value-only long name above.

### Token reading flow (per option line)

The line is split exactly as today (shell-style splitting; an unsplittable line
still yields no items and makes the set incomplete). Tokens are then read left
to right; for each token the first matching rule applies:

1. Separated form of an interpreted option (token equals its short or long
   name): unchanged — the next token is its value, or an empty value at line end.
2. Separated form of a value-only option (token equals one of its names): the
   next token is consumed as the value whatever it looks like — a leading `-`,
   a lone `--`, `-r…`, `-e…`, `-c…` — and discarded. At line end nothing is
   consumed and the set stays complete.
3. Self-contained forms — `long=value` (the value may be empty) of any
   value-taking long name, or a short name with the value attached (`-iURL`,
   `-f./wheels`, `-Ckey=val`, and the existing `-rX` / `-cX` / `-eX`): the
   token alone carries the option; no following token is consumed. Interpreted
   options keep today's meaning; value-only values are discarded.
4. Abbreviation: the token starts with `--`, the part before its first `=` is
   longer than `--`, and that part is a proper prefix (not an exact match) of at
   least one value-taking long name — unique or ambiguous alike. One
   undetermined item is produced; the following token is not consumed; the text
   after `=` is never used as a name or a file.
5. Anything else is ignored: unknown options, stray words, and a lone `--`
   that was not consumed as a value.

Rules 1–3 run before rule 4, so an exact long name (for example `--hash`) is
never classified as its own abbreviation, and a name longer than a long option
(for example `--constraint-extra`) is not a prefix of it and stays ignored.

### Contracts

| Element | Precondition | Postcondition |
|---------|--------------|---------------|
| `_requirements_option_items(text)` | `text` is a logical line starting with `-` | Returns the ordered (kind, value) items — include, editable or undetermined — or None when the line cannot be split (unchanged). No item is ever derived from a consumed value-only value. |
| abbreviation check (the existing helper, extended) | a single token | True exactly under rule 4 above |
| `_pip_requirements_direct_names(path, project_root)` | unchanged | Unchanged contract: never raises, never opens a file outside the root, never fetches a URL; an undetermined item makes the set incomplete as today |

### Reporting

No new note token, no change of note wording or position (FR6). Incompleteness
is visible only through the existing pip directness note; no token text, path,
host or credential from a requirements line reaches the summary or a finding
(NFR3, TM-4).

### In-code descriptions (FR8)

- The docstring of `_requirements_option_items` describes both option groups,
  rule 2 (including a leading `-` and a lone `--` as values), rule 3, rule 4
  over every value-taking long name, and that consumed values are never
  interpreted.
- The docstring of `_pip_requirements_direct_names` names abbreviations of any
  value-taking long option as a cause of incompleteness and states that values
  of value-only options are never opened, fetched or added as names.
- The comment of the abbreviation option table (today naming only
  `--requirement` / `--editable`), and any helper docstring that still names
  only those two, describe the full set of value-taking long names.

### Constraints

Standard library only; no new import outside it (NFR1). The resolver's
never-raise behaviour is kept (NFR1).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR2, FR4; TM-1): For the separated form of every value-only option (`-i`, `--index-url`, `--pypi-url`, `--extra-index-url`, `-f`, `--find-links`, `--trusted-host`, `--no-binary`, `--only-binary`, `--use-feature`, `--hash`, `--global-option`, `-C`, `--config-settings`), a requirements.txt holding only `<option> -c -r deps.txt`, with deps.txt declaring `vuln-pkg==1.0`, resolves to exactly {vuln-pkg} with complete=True, opens deps.txt and makes no network attempt; scanning the `--trusted-host` form with an advisory for vuln-pkg yields exactly one finding and no undetermined note. The same holds for `--trusted-host -c -r deeper.txt` inside an included file (requirements.txt: `-r inc.txt`) and for the same line split by a backslash continuation (`--trusted-host \` then `-c -r deeper.txt`): deeper.txt is opened, its names are included, complete=True.
- [ ] AC-2 (FR2, FR4, NFR2; TM-3): A consumed value is never interpreted. `-f "-enamed-pkg" -r actual.txt` resolves without named-pkg and with actual.txt's name, opens actual.txt, complete=True. `--find-links "-rdeps.txt" -r actual.txt` (deps.txt and actual.txt both inside the root) does not open deps.txt, contains none of its names, opens actual.txt, complete=True. `-f -- -r deps.txt` consumes `--` as the value, opens deps.txt, complete=True.
- [ ] AC-3 (FR3): `--trusted-host=x -r deps.txt`, `--index-url= -r deps.txt`, `-ihttps://example.invalid/simple -r deps.txt` and `-f./wheels -r deps.txt` each open deps.txt and resolve with complete=True.
- [ ] AC-4 (FR5, NFR2; TM-2, TM-3): `--trusted -c -r deps.txt`, `--index -c -r deps.txt` and `--find -c -r deps.txt` each resolve with complete=False and do not open deps.txt; scanning each (requirements.txt also declaring own-pkg, advisory for undeclared-pkg) reports no finding and counts that advisory once in the existing undetermined note. `--trusted -r deps.txt` opens deps.txt with complete=False; `--trusted=-rdeps.txt` does not open deps.txt, complete=False.
- [ ] AC-5 (FR5, FR7; TM-2): With own-pkg as the only other line, `--constraint-extra x --con y`, `--con y` and the ambiguous `--no x` each resolve to {own-pkg} with complete=False, and `--constraint-extra x` alone resolves to {own-pkg} with complete=True. The existing test `test_ac6_a_constraint_abbreviation_is_not_flagged` is rewritten to expect complete=False for its line.
- [ ] AC-6 (FR6): Lines where a value-taking option ends the line without a value (`-i`, `-f`, `--trusted-host`), and the existing lines holding a lone `--` that is not consumed as a value (`--`, `-f ./wheels --`, `--index-url https://example.invalid/simple -- --no-index`), each resolve to {own-pkg} with complete=True.
- [ ] AC-7 (NFR3, FR6; TM-4): For an abbreviation of a value-only long option whose `=` value carries a secret-looking host (for example `--trusted=secret-host.invalid`, with an advisory for an undeclared package) and for consumed values carrying credentials (an index URL with an embedded `user:secret-token` before `-c -r deps.txt`), the scan summary and findings contain no text, path, host or credential from the line; the summary's only note token is the existing pip directness note, and it appears at most once.
- [ ] AC-8 (FR6, FR7, FR8, NFR1, NFR4, NFR5): `python3 -m unittest discover -s tests` and `python3 em-workflow/scripts/check-plugin-invariants.py .` both exit 0; among the pre-existing tests only `test_ac6_a_constraint_abbreviation_is_not_flagged` changes its expectation; the new tests live in `tests/test_scan_dependencies_pip_directness.py` and use unittest and other standard-library modules only; the docstrings and the comment listed under "In-code descriptions (FR8)" describe the behaviour of the Design section.
