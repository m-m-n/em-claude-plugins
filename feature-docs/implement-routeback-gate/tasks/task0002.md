# Task Plan: task0002 — em-workflow plugin patch version bump

## Goal

Patch-bump the em-workflow plugin's declared version from 0.1.35 to 0.1.36 so
the protocol change of this feature ships with a version the plugin cache can
distinguish, without touching any other file.

## Requirements

FR7, FR9, NFR1, NFR3

## Scope

### Files to Create
- (none)

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — the `version` field only:
  0.1.35 → 0.1.36. Every other field, and the file's formatting, stay as they
  are.

## Design

- The plugin manifest is the single place this repository records a plugin's
  version (repository convention). The root `.claude-plugin/marketplace.json`
  entries carry no `version` field, so there is nothing to keep in sync there
  and that file is not touched (IMPLEMENTATION.md D5).
- The bump is a patch-level step: the feature changes protocol documentation
  only, with no added capability and no compatibility break.
- The task must remain independently green: `python3 -m unittest discover -s
  tests` passes inside this task's own worktree, which does not contain the
  document edits of the other task (IMPLEMENTATION.md Shared Components,
  "Independent green suite").
- Should an existing invariant test fail because of the bump, that is a
  finding to report, not something to resolve by editing the invariant test
  (IMPLEMENTATION.md D4).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `em-workflow/.claude-plugin/plugin.json` declares version
      `0.1.36`, and the file remains valid JSON with every other field
      unchanged. (FR9, TS-10)
- [ ] AC-2: The task's name-only changed-file list is exactly
      `em-workflow/.claude-plugin/plugin.json`; the root
      `.claude-plugin/marketplace.json` and every file under `em-workflow/`
      other than the manifest are untouched. (FR7, NFR3, TS-12)
- [ ] AC-3: `python3 -m unittest discover -s tests` passes in this task's
      worktree with no test file added or modified. (NFR1, TS-7, TS-8)

## Test Notes

- There is no automated assertion for AC-1: pinning a literal version inside
  the suite would fail in the sibling task's worktree and would have to be
  rewritten on every future bump (IMPLEMENTATION.md D3). AC-1 is verified by
  inspecting the manifest and the diff (VERIFICATION.md TS-10).
- AC-2 is verified from the task's own change set (name-only listing) —
  VERIFICATION.md TS-12 repeats the same audit feature-wide.
- AC-3 is the existing suite run unchanged; it is the regression guard that
  the manifest edit did not break a plugin-invariant check.

## Out of Scope

- `em-workflow/references/implement-phase.md` and any other protocol
  document — owned by another task.
- Adding, modifying or deleting any file under `tests/`.
- The root `.claude-plugin/marketplace.json`.
- Any change to the manifest beyond the `version` field (description, author,
  name, formatting).
