# Task Plan: task0001 — hook_main six-character end-strip declared match and regression tests

## Goal

The hook denies the YAML-parsed form of a declared, unapproved command as unapproved even when the quoted declaration mixes or repeats U+0085, U+2028 and U+2029 at its ends, without widening what the hook allows. The module docstring and comments describe the new match, and regression tests pin it.

## Design

Terms (IMPLEMENTATION.md, Conventions): the "six characters" are U+0020, U+0009, LF (U+000A), U+0085, U+2028 and U+2029. The "end-stripped form" of a command is the command with every leading and trailing occurrence of the six characters removed, in any number and any mix, from both ends. No other character is removed: U+00A0, CR, U+000B, U+000C, U+2000 to U+200A, U+3000 and the rest stay. An argument-less whitespace strip is not used.

### Constant

- One new module-level constant holds the six characters, written with escape notation (no raw U+0085, U+2028 or U+2029 in the source).
- It is separate from `DECLARED_END_STRIP`, which keeps its current five characters.
- Its name does not contain the substring "status".
- It is not placed between the definitions of strip_yaml_quotes, trim_blanks, is_matchable and declared_commands, which stay consecutive in that order and are each defined once. No new top-level function is added; any helper needed for FR1 lives inside hook_main.

### Declared predicate in hook_main

- hook_main derives two forms from the received command, without rewriting the command itself:
  - (a) the space/tab-trimmed command, as today;
  - (b) the end-stripped form.
- A command counts as declared when (a) is in the declared set, or when (b) is non-empty and is in the declared set.
- This one predicate replaces the current "(a) is in the declared set" test at all three places that consult the declared set:
  1. the early return taken when the command is not declared and the approval store file does not exist;
  2. the workflow-relevance check;
  3. the unapproved deny.
- Nothing else uses (b). The forbidden-pattern check (refusal_reason), the exact allow and the cd-prefix allow keep judging (a), so no allow ever comes from (b).

### Decision order (unchanged)

1. forbidden pattern -> deny
2. exact match of (a) against the approval store -> allow
3. cd-prefix form -> allow
4. declared (predicate above) and not approved -> deny, with the existing reason text and additionalContext
5. otherwise -> no decision

The task adds no new message text: the deny for a command matched through (b) comes from the existing unapproved-deny path.

### Docstring and comments

- The module docstring's Matching paragraph and the declared row of its decision table state that the declared check also matches the end-stripped form, name the six characters by code point, state that an empty end-stripped form is not declared, and state that no allow comes from that form.
- The comments at the three declared checks in hook_main say the same briefly.
- The docstring keeps its pinned phrases unchanged: 'after removing surrounding spaces and tabs only', 'any other whitespace at either end is never allowed', and the cd-prefix approval items.
- No docstring or comment text contains the substring "status" or a raw U+0085, U+2028 or U+2029.

### Regression test file

- Fixture:
  - One temporary git repository per case. Each holds exactly one `*_command` declaration in a feature-docs workflow.yaml, laid out as in the existing declared-command tests.
  - One temporary git repository with no declaration.
  - The approval store is isolated through EM_WORKFLOW_APPROVALS and holds only /usr/bin/true.
  - The hook runs as a subprocess with CLAUDE_PROJECT_DIR removed from its environment.
- Declarations are written into workflow.yaml as raw characters, in both double and single quotes. The test source produces those characters from escape notation.
- YAML-parsed forms are written in the test source as literals. PyYAML is not imported.
- Outcomes are read from the hook's output as allow, deny or no decision (silent), in the way the existing declared-command tests read them.
- declared_commands is called directly after loading the module without writing bytecode, the same way as the existing _load_guard_module.

YAML-parsed forms used by the criteria. Notation: `<U+xxxx>` is that character and `<LF>` is U+000A.

| Declaration (inside the quotes) | YAML-parsed form |
|---|---|
| `<U+0085>./unapproved<U+2028>` | ` ./unapproved<U+2028>` |
| `<U+0085>./unapproved<U+2029>` | ` ./unapproved<U+2029>` |
| `<U+2028>./unapproved<U+0085>` | `<U+2028>./unapproved ` |
| `<U+2029>./unapproved<U+0085>` | `<U+2029>./unapproved ` |
| `<U+0085><U+0085>./unapproved` | `<LF>./unapproved` |
| `./unapproved<U+0085><U+0085>` | `./unapproved<LF>` |
| `<U+0085><U+2028>./unapproved` | `<U+2028>./unapproved` |
| `./unapproved<U+0085><U+2028>` | `./unapproved<U+2028>` |
| `<U+2028><U+0085>./unapproved` | `<U+2028><LF>./unapproved` |
| `./unapproved<U+2028><U+0085>` | `./unapproved<U+2028><LF>` |
| `<U+0085><U+2028><U+2029>` | `<U+2028><U+2029>` |
