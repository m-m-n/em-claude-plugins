# Task Plan: task0001 — Original-position rm numbering and per-target alternatives in the combined rm reason

## Goal

Every `N番目のrmのM番目の対象` designation in destructive-guard's rm deny/ask reasons names the rm and the operand at the position they occupy when the original command string is read left to right, and every plain rm-recursive target listed in a combined reason carries its own deletion-alternative template — with no verdict and no rule id changed.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_destructive_guard_rm_reason_positions.py` — regression tests for designations and combined-reason templates (FR6)

### Files to Modify
- `em-workflow/hooks/destructive-guard.py` — origin positions in statement enumeration, one rm invocation per statement, operand numbering, deferred numbering and rendering, combined-reason templates, docstrings and comments

## Design

Feature-wide rules (reason-text hygiene, determinism, test conventions) are in IMPLEMENTATION.md "Conventions"; they are referenced here, not restated.

### Vocabulary

- **rm invocation** — one statement that reaches rm judgment: either its command word is `rm` (plain route), or it is substitution-headed and route_substitution_headed_statement() reads its command name as `rm` (substitution route). A statement yields at most one rm invocation.
- **Anchor token** — the token whose position is the invocation's position: the written rm command word on the plain route; on the substitution route, the substitution token whose body was read as command-name evidence.
- **Operand basis** — the token list the invocation's targets are numbered over: on the substitution route, the route's REMAINDER (tokens from the skip point onward — the written `rm` word, when present, is its first operand, assumption A1); on the plain route, the command's ARGS.
- **Record** — one judged target's decision before rendering: tier, rule, the invocation's anchor position, the target number, and what the single-target message needs (which message form applies, the rm-root raw token, whether the target is substitution-only, and the deletion template for a plain rm-recursive target). Records hold no ordinal and no rendered text.

### Processing flow after this task

1. Statement enumeration yields every statement together with its origin information (Part 1).
2. Per statement: establish at most one rm invocation (Part 2), judge its operand basis (Part 3) and collect records. Nothing is numbered or rendered yet.
3. After every statement has been examined: assign invocation ordinals, deduplicate records, render designations and single-target messages (Part 4).
4. Select the strongest decision, build the single or combined reason (Part 5), emit once.

Every other check (git, file destruction, external, permissions, self-modification, deferral to the sibling guards) and every early exit they make stay exactly as they are. The scan budget, the chunk processing order and the set of chunks queued for scanning do not change. No chunk is added and none is dropped.

### Part 1 — Origin positions (FR1)

**Contract.** Statement enumeration additionally reports, per statement, origin information from which the original-string position of any of its tokens can be compared with the position of any token of any other statement.

**Postcondition.** For any two rm invocations, comparing their anchor tokens' origin positions gives the same order as comparing the starting character positions of those tokens in the original command string.

**Shape (descriptive, not prescriptive of data layout).** A hierarchical position works. Every chunk carries the anchor path inherited from where it was derived. A position is that path followed by the position inside the chunk: statement order first, then token order as written (before shaping, wrappers and assignments included), then character order inside a token when two anchors fall into the same token. A derived chunk's anchor in its parent chunk is:

| Derived chunk | Anchored at, in the parent chunk |
|---|---|
| Command-substitution body (dollar-paren or backtick), including one inside a `-c` / eval / here-string payload | The substitution's own opening position |
| `-c` / eval / here-string payload | The payload word's position |
| Heredoc body queued whole (shell destination, or the undeterminable fallback) | The start of the body: after everything on its operator's line and before anything that follows its delimiter line. It is not the operator's own position |
| Substitution extracted from an unquoted-delimiter heredoc body | The heredoc body's start, then the substitution's position inside the body |

Consequences the postcondition requires:

- A substitution-headed invocation (anchor = the substitution token) sorts before every rm inside that substitution's body, because the opening of the substitution precedes its body.
- A statement that follows a heredoc operator on the same line sorts before every rm in that heredoc's body.
- Chunks lexed through the parse-failure fallback still receive origin positions: statement order and token order of the fallback's own split.

### Part 2 — One invocation per statement (FR2)

| Statement shape | Anchor token | Operand basis |
|---|---|---|
| Substitution-headed, evidence reads rm | The substitution token read as evidence | REMAINDER |
| Command word is rm, no rm evidence from a skipped substitution | The rm command word | ARGS |
| Anything else | None (no invocation) | — |

When a statement reaches both routes (substitution-headed with rm evidence, and the plain command word is also rm), the two routes are one invocation. The plain route's operand basis is REMAINDER without its first token. The tokens are the same and the flags are the same, so the plain route's judgments are a subset of the substitution route's. Either do not run the plain rm judgment for such a statement, or merge its records into the substitution route's by token position. The observable outcome must be identical: one invocation, and the same target number for the same token on either route.

route_substitution_headed_statement() keeps its entry rule (command-name evidence only), its git route and its empty result for any other evidence or unreadable evidence. It no longer consumes an ordinal, because no ordinal is assigned during the statement loop.

### Part 3 — Operand numbering (FR3)

Over the operand basis, left to right:

1. Before the first `--`, a word starting with `-` is an option and is not counted. A lone `-` therefore stays uncounted when no `--` precedes it (A3).
2. The first `--` itself is not counted.
3. After the first `--`, every word is counted: words starting with `-` and any further `--` included.
4. A word marked as operator syntax (the token's is-operator flag) is never counted.

The target number of a judged target is its count under these rules. **The judged set does not change**: a target is judged exactly when it is judged today (not starting with `-`, not operator syntax). A dash-leading operand after `--` is numbered and never judged (A2).

### Part 4 — Deferred numbering and rendering (FR1, FR2, NFR1)

- **Collection.** check_rm() judges one operand basis and returns records. It never emits, never exits and never assigns an ordinal. Per-target judgment (root shape, unresolved forms, normalization, safe roots, glob, lost evidence) and its order are unchanged. The deletion template for a plain rm-recursive deny is selected by deletion_alternative() exactly as today: the gio / HOME / control-character selection is unchanged.
- **Ordinals.** After the loop, every rm invocation gets an ordinal, including one that produced no record. Ordinals run 1..n in ascending anchor-position order.
- **Deduplication.** Records with the same (invocation, target number) collapse into one. Such records are the same token judged the same way, so they carry identical tier and rule.
- **Rendering.** The designation format is unchanged (A4): rm_target_designation() with the same text shape and the same fixed stand-in suffix for a substitution-only target. Each single-target message is byte-identical to today's text for the same designation (A5).

### Part 5 — Combined reason (FR4)

Tier and rule selection are unchanged. The winning tier is the highest rank. The rule is rm-root when any winner is rm-root; otherwise it is the winners' common rule. Selection runs after deduplication.

- **One winner.** Its single-target message is the reason, unchanged.
- **Two or more winners.** The combined reason contains:
  - A lead statement that several targets reached the same decision strength.
  - One entry per winner, in ascending (ordinal, target number) order. An entry starts with the winner's name: its designation, or for rm-root its raw token as today. An rm-root name equal to an earlier entry's name is not repeated, as today.
  - For a plain rm-recursive winner (one whose single-target message carries a deletion template), the same template text immediately after its name, before the next entry's name.
  - No template for rm-root, rm-unresolvable, or rm-recursive with lost substitution evidence.
  - A closing instruction to rewrite each target into a safe form and retry.
- **Each designation appears exactly once** in the reason.
- No character derived from any target's text appears, apart from the exceptions IMPLEMENTATION.md "Conventions" allows.

### Part 6 — Docstrings and comments (FR7)

Rewrite these to describe the behaviour after this task:

- the docstrings of rm_target_designation(), check_rm() and route_substitution_headed_statement();
- the comment at main()'s invocation-numbering site (the counter, or whatever replaces it);
- every docstring whose described contract this task changes: statements() (its yielded values) and strongest_rm_decision() (the combined reason).

## Test Notes

- Every AC except AC-7 is a test in the new module. Follow the conventions of the existing rm-reason test module (IMPLEMENTATION.md "Conventions"): a gio stub directory on PATH for the gio-present case, and an empty PATH for gio-absent.
- **Pin before editing (AC-6, TM-2).** Run every AC-1 to AC-5 command against the unmodified hook first and record the verdict and rule id. The tests assert those recorded values. The expected values are deny / rm-recursive for all, except `rm -rf -- -x` (allow) and `rm -rf / /var/a` (deny / rm-root). A recorded value that differs from this list is a finding to report, not something to adjust silently.
- **Attributing a designation to a target** without the target's text: keep exactly one target unsafe and make the others scratch-root targets (`/tmp/...`, which are safe), so the only designation in the reason belongs to the unsafe one.
- **"Between designation and next designation"**: split the reason at the occurrences of the designation pattern the existing module uses. The template text to look for is the fixed placeholder form (`gio trash -- <対象>`, `mv -- <対象> /tmp/`, or the control-character sentence).
- AC-1's heredoc and here-string cases are what distinguish the body-start anchor from an operator-position anchor, and original-string order from processing order. Keep them as separate subtests so a failure names the form.
- AC-7 can be pinned by a test that reads the hook's source text and checks the listed docstrings for the stale statements. Review covers the positive wording.
- The parse-failure fallback (an unbalanced quote around an rm statement) must not raise and must give a stable result across two runs. Add one case.
