# Task Plan: task0001 — Continue the stalled stage walk under the lenient realpath rule

## Goal

When `_stage_walk_refuses` reaches an absent or non-directory stage, the walk
continues under the lenient (non-strict) realpath rule and refuses at any
/proc or /dev/fd stage. As a result, `is_below` never probes or reads anything
under /proc or /dev/fd for a stalled path, on the logical-path side or the
physical-path side. The four rule statements and the tests change to match.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4

## Design

### Stage walk: two phases (FR1, FR2, FR4)

The walk keeps its current state: the pending components, the location
reached, and the count of links followed. It gains one fact: whether it has
stalled.

- **Phase 1** runs from the start of the walk up to the first stall. It
  behaves exactly as today.
- **The stall** is the first stage that is absent (the probe reports not
  found or not a directory), or that exists and is neither a directory nor a
  link.
- **Phase 2** starts at the stall and runs to the end of the path. There is
  no return to phase 1.

Phase 2 applies the lenient realpath's per-component rules. The walk
therefore visits, in the same order, every location the lenient realpath
would probe or read for the same text. Because the walk runs before both
realpath calls, a walk that does not refuse leaves realpath no /proc or
/dev/fd stage to reach.

| Component | Phase 1 (unchanged) | Phase 2 (continuation) |
|---|---|---|
| empty or `.` | skipped | skipped |
| `..` | drops the last reached component (the root stays the root); refuses if the remaining location is under /proc or /dev/fd | same |
| a name whose stage is lexically under /proc or /dev/fd | refuses before probing | same |
| a name the probe reports absent or not a directory | the stall: the name joins the reached location as an ordinary name, and phase 2 starts | the name joins the reached location as an ordinary name |
| a name that exists and is neither a directory nor a link | the stall, handled as in the row above | the name joins as an ordinary name |
| a directory | joins the reached location | same |
| a link | counted; above FOLLOWED_LINK_LIMIT refuses; the target is read; an absolute target is refused if its text is under /proc or /dev/fd, and otherwise resets the reached location to the root; the target's components go ahead of the pending ones (a relative target starts from the directory that holds the link) | same, and the count carries over from phase 1 |
| an operating-system failure while probing a stage or reading a link target, other than absent / not a directory | refuses (existing rule) | the name joins as an ordinary name and the walk continues with no refusal (the way the lenient realpath treats it, SPEC A4) |
| any other exception (for example an embedded NUL) | refuses | refuses |

When the walk reaches the end of the path, phase 1 or phase 2 alike, it does
not refuse (FR3). The existing post-walk rule in `is_below` decides.

Invariants to keep:
- **Only refusals are added**: before the stall nothing changes, and the old
  walk never refused after a stall. The only possible outcome change is from
  no refusal to refusal (NFR1).
- **Loops and long chains**: the walk counts every followed link and refuses
  above the limit. The lenient realpath instead treats a repeated unresolved
  link as an ordinary name. The walk is the stricter of the two, so it cannot
  miss a location realpath reaches.
- **The comment on the reached location** must stay accurate. During phase 2
  that location may hold ordinary names that do not exist, regular files, or
  a link whose target could not be read.
- **No new identifier or string literal containing `status`**: the hook's
  executable text must keep passing `test_ac7_hook_executable_text_has_no_status_substring`.

### `is_below` (FR2, FR6)

No change to its code path. The checks run in the same order: the
written-path predicate, then the logical-path walk, then the physical-path
walk, then both realpath calls, then the post-walk rule. A refusal from
either walk returns False before any realpath call. No pre-check calls
`resolves_to_directory` before the realpath calls (SPEC A6).

Unchanged: the signatures of `is_below` and `_stage_walk_refuses`, the
caller, `_under_proc_or_dev_fd`, the value of FOLLOWED_LINK_LIMIT, and the
cd prefix decision table.

### Rule statements (FR5)

- **Stage-walk docstring**:
  - Remove the sentence 'A stage that does not exist, or a non-directory,
    ends the walk without refusal ...'.
  - State the phase 2 rule instead:
    - the stage joins as an ordinary name, and a later `..` removes it
    - stages are probed and links followed again once the walk is back at
      an existing location
    - a relative target resolves from the link's directory, and an
      absolute target resets to the root
    - the /proc and /dev/fd checks apply unchanged, before probing
    - links after the stall count toward the same limit

  stage check continues past an absent or non-directory stage the way the

### Tests (FR7, FR8)

**Fixtures.** Place every new link and directory under names no other test
uses, created idempotently (with the module's existing link helper), so the
layout other tests see is unchanged. A climbing target needs enough `..` to
reach the root. Count them as `Layout.climb_target` does, from the depth of
the link's directory, and add the components the target itself places before
the climb (for example, two for `proc/missing/`). Surplus `..` at the root
stay at the root.

**Forms (FR7).**
- (a) A relative target `proc/missing/`, then the climbing `..`, then
  `proc/self/cwd`.
- (b) The same with `x/missing/` in place of `proc/missing/`.
- (c) An absolute target `<area>/task0001/missing/`, then `..`, then
  `proc/self/cwd`.
- (d) A target that stalls at a regular file in the link's directory instead
  of an absent stage.
- (e) A target like (b) that ends in `dev/fd/<n>`, where `<n>` is a
  descriptor the test opens on an in-area directory.
- **Physical-only variant**: written as `<link directory>/<link>/../<existing
  directory>`. Only the as-written resolution goes through the link of form
  (b); the logical path collapses past it.

**Logical-path corner (SPEC A1, AC2).** Written as `<hop>/../<name>`:
- `<hop>` is a dedicated link to an in-area directory, so the physical
  resolution lands on an existing directory `<name>` below the area.
- The logical collapse lands on a stalling link `<name>` beside `<hop>`. Its
  target climbs to `proc/self/cwd/shared`.
- With the process cwd in `procdep/work`, the old rule judged this form True.

**Recording.** Only the `is_below` call runs inside `_recorded_probes`. Any
fixture guard that resolves through /proc runs outside it. Recorded paths are
judged with `_is_proc_or_dev_fd_location`.

- **Test types**: all criteria are unit tests at module level, except the
  hook-level silent check in AC-2. That check runs the hook as a subprocess
  (`Fixture.run_hook` with `process_cwd`).
- **Red phase (TS2)**: write the AC-1, AC-2 and AC-5 tests first and run them
  against the unchanged walk. Expected failures:
  - AC-1 records a probe or read under /proc or /dev/fd
  - AC-2 judges the corner form True, and the hook allows it
  - AC-5 does not refuse after the stall

  Record that run in the task's test record.
- **Example for AC-5**: one link before the stall comes from the existing
  dangling link (its target is absent), then `..`, then an existing chain
  under `procdep`. With a 40-link chain the total is 41 and the walk refuses.
  With 39 it is 40 and the walk does not. The logical path never stalls, so
  the physical-path walk alone decides.
- **Error injection (AC-5)**: wrap the real probe or link read, and raise only
  for the one chosen path. Every other call goes through, the same way
  `test_ac6_an_error_while_a_stage_is_probed_makes_the_check_false` does.
- **Reuse helpers**: `_recorded_probes`, `_is_proc_or_dev_fd_location`,
  `_working_directory`, `_link`, `_link_chain`, `Layout`, `needs_proc`,
  `needs_dev_fd`, `_no_child_process`, `decide`, and `FIX.run_hook`.
- **Module conventions**: add this feature's paragraph to the test module's

  did.
