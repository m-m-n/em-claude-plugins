# Task Plan: task0007 — develop entry from failed

## Goal

A develop re-run naming the feature enters the FR5 correction from `implement: failed`
before stop condition 3, and restores the target task in one write.

## Requirements

FR6, FR9, NFR6

## Scope

### Files to Create
- `tests/test_failed_entry_develop_docs.py` — document contract tests

### Files to Modify
- `em-workflow/skills/develop/SKILL.md` — Step A.6

## Design

Add `## Step A.6: failed からの入口` between Step A.5 and Step B, in Japanese like the
rest of the document:

1. It runs once per invocation, only on Step A's existing-feature branch, after Step A.5.
   Step B never enters it, so it is not taken inside the run that failed.
2. When `implement` is not `failed`, go to Step B.
3. Capture the integration tip as a full commit ID, and run
   `${CLAUDE_PLUGIN_ROOT}/scripts/report-name-entry.py` with the four arguments of
   Shared Components.
4. Outcome `none`, `blocked`, or an exit other than 0: go to Step B with workflow.yaml
   unchanged. Stop condition 3 fires, and on `blocked` the stop report names the failed
   condition.
5. Outcome `dispatch`: run `references/phases/create-plan-phase.md` section 13, in
   interactive and batch alike, regardless of `failed_kind`, and with no new gate.
6. When that section ends without a validated patch, go to Step B with workflow.yaml
   unchanged, and stop condition 3 fires.
7. On a validated patch, make the artifact commit, then apply the patch and the
   restoration in one Write and one commit (IMPLEMENTATION.md D4), then go to Step B.

**Restoration**, for each corrected task that the script's `violations` listed:
`implement` to `pending`, `failed_kind` to null, `tasks.{T}.status` to `pending`,
`tasks.{T}.routeback_failed_journal_line` to the violation's `failed_journal_line` when
it is not null. `notes` is cleared by the patch's application, which removes the
retry-consumption record. The target's worktree and branch and merged tasks are not
touched, and a worktree with uncommitted changes is not discarded.

Add a short pointer to Step A.6 in Step B's `failed_kind` block, without rewording that
block.
