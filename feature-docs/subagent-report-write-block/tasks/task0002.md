## Design

The FR2, FR3 and FR4 components in IMPLEMENTATION.md Shared Components may be absent
when this worktree branches; follow the note under that table.

**Shape.** Structural, with and without `--dry-run-apply`, code
`path-correction-shape`: `path_corrections` per the Shared Components contract, each
`(task_id, old_path)` once, `new_path` different from `old_path`, not on
`append_rework`.

**Permission.** Under `--dry-run-apply`, per IMPLEMENTATION.md D2.

**Required inputs.** Under `--dry-run-apply` a non-empty `path_corrections` needs
`--workflow`, `--journal`, `--feature-dir`, `--target-repo` and `--base-commit`. A
missing one, or a base that does not resolve, exits 2. `--journal` naming a missing
file reads as no events.

**Conditions**, one error code each, in FR5's order:

| Condition | Rejected when |
|---|---|
| 1, `path-correction-in-flight` | Any task is `in_progress`, or any task's journal last event is `launched` |
| 2, `path-correction-merged` | The target's status or journal last event is `merged` |
| 3, `path-correction-old-path` | `old_path` is not in the target's `files`, does not match FR2, or `base_tree_entry` is not `absent` |
| 4, `path-correction-new-path` | `new_path` matches FR2, fails `is_safe_relative_path`, or `base_tree_entry` is not `absent` |
| 5, `path-correction-content` | The comparison of IMPLEMENTATION.md D3 fails |

Read documents at the base commit without a shell, and current documents through
`_resolve_contained_relative_path` under `--feature-dir`. The repository-relative
location of the feature directory is its path relative to `--target-repo`; a feature
directory outside the repository exits 2.

**Application.** In the in-memory application, a corrected carried record has
`old_path` replaced by `new_path` at the same list position and `notes` set to null.
Every other field stays verbatim.

**Carried check.** Under `--dry-run-apply`, the FR3 judgment also runs on the files
of every id in `carried_task_ids` whose status is not `merged`, on the files after
corrections, with the same error code and the same exit 2 rule.

**Plan agreement.** For each corrected task, compare its plan's Files sections with
the corrected files and report `task-plan-files-mismatch` as for an entry. Requires
`--feature-dir`, as the existing check does.

**Scenario-ID scan.** Per IMPLEMENTATION.md D8.

**Entry script.** Per the Shared Components contract. A failed task has status
`failed`, or journal last event `failed` with a status other than `merged`. The base
inputs are read only when a failed task's files hold a matching name. On `dispatch`
and `blocked`, each violation carries the task's last `failed` line, or null. The
script locates the validator as its sibling file.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `path_corrections` is accepted in the first two states of IMPLEMENTATION.md
      D2 and rejected on the Initial-planning path with
      `path-correction-not-permitted`. On the correction entry a `failed` task is
      permitted, an `in_progress` task is `replace-all-not-permitted`, non-empty
      `step_patches` is `path-correction-step-patches`, and the same patch without
      `path_corrections` is rejected as before (TS-22, TM-6).
- [ ] AC-2: With `--dry-run-apply`, a carried non-merged task's new matching name is
      `report-name-new-file`, a merged task's is not, and a corrected path is judged
      after correction (TS-9).
- [ ] AC-3: A correction meeting every condition passes, and one breaking condition
      1, 2, 3 or 4 is rejected with that condition's code (TS-10, TM-4).
- [ ] AC-4: A correction that changes anything beyond the normalization, or leaves an
      old path in a compared document, is `path-correction-content`. Replacing a bare
      old file name passes, and a new name containing the old name is not re-replaced
      (TS-10, TM-5).
- [ ] AC-5: The applied record has the path replaced in position, `notes` null and
      every other field unchanged. A corrected task's Files section that disagrees
      with files is `task-plan-files-mismatch` (TS-10, TS-11).
- [ ] AC-6: `report-name-entry.py` returns `none`, `dispatch` and `blocked` as
      contracted, carries `failed_journal_line`, and exits 2 on a missing argument or
      a base that does not resolve when one is needed (TS-21).
- [ ] AC-7: `old_path` and `new_path` get the literal treatment of `base_tree_entry`,
      a correction patch skips the VERIFICATION.md scenario-ID target only, the two
      fixtures match their declared outcome, and
      `python3 -m unittest discover -s tests` passes (TS-19, TM-1, NFR2, NFR4).
