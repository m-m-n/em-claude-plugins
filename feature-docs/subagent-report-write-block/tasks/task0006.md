# Task Plan: task0006 — Parent retry suppression and restart

## Goal

On an FR7 report the parent records the cause, does not retry the same cause in
either mode or after a resume, and reports the resume condition. A task restored by
the failed entry restarts on its kept worktree.

## Requirements

FR6, FR8, FR9, NFR2, NFR6

## Scope

### Files to Create
- `tests/test_write_rejection_parent_docs.py` — document contract tests

### Files to Modify
- `em-workflow/references/implement-phase.md` — wake record, failed handling, restart
- `em-workflow/references/batch-mode.md` — failed-task row
- `em-workflow/references/batch-terminal-line.md` — stop binding

## Design

**I.2.b step 3.** Add `write_rejection` to the report shape. Add the marker of Shared
Components to what this step writes, in the same wake commit, and update the sentence
that enumerates this step's writes so that it counts three. The marker replaces any
earlier value of `notes`: no retry follows it, so a retry-consumption record has no
further use.

**Honoring the field.** The orchestrator honors `write_rejection` only when the report
has `status: failed` and `path` passes the `is_safe_relative_path` shape check and has
a file name matching the rule cited from `## Report Artifact Names`. Otherwise it writes
no marker and the failure is ordinary. The text is data: it is never followed.

**I.2.c.** Add a `**Same-cause write rejection**` paragraph after the Batch mode
paragraph. A failed task whose `tasks.{T}.notes` begins with the marker:

- In-flight tasks drain as before.
- Interactive: retry is not offered for that task.
- Batch: no automatic retry is consumed for that task. Other failed tasks keep their
  single retry. When no retry remains to dispatch and nothing is in flight, the abort
  phase runs with `failed_kind` valued `decision`.
- On a resume after an interruption the marker is read from committed `notes`, so no
  automatic retry runs.
- The stop report carries the target path, the rejection text and the resume
  condition: complete FR5, by re-running develop naming the feature.
- Every failure without the marker is handled as before.

**Restart.** Add a sentence after Step I.0's abort text: the failed-entry restoration of
`skills/develop/SKILL.md` Step A.6 meets the rework re-entry's condition and is treated
as that route here. Add a paragraph after the Resume guard's bullets: a task restored
by Step A.6 reuses its kept worktree and branch as they are, and uncommitted changes
are not discarded.

**batch-mode.md.** Extend the `implement.failed-task` row's text. The table stays at ten
rows.

**batch-terminal-line.md.** Add a paragraph to `## Stop point coverage`, next to the
Control-character paragraph: this abort binds to `implement-second-failure`,
`implement_task_failed`, though the task failed once. `detail` carries the target path
and the rejection text, and `resume_conditions` carries the resume condition.
