# Task Plan: task0004 — Correction contract and validator call sites

## Goal

`references/workflow-patch.md` defines the final-path correction, the schema records
what it writes, and every validation call passes the two base values.

## Requirements

## Design

**workflow-patch.md.** Add `path_corrections` to the `tasks_patch` description. Add
`## Final-path correction` before `## Ownership boundary`, unnumbered, so the eighteen
rules stay eighteen. It states:

- It is the exception to copying a carried record verbatim, and it applies on the
  states of IMPLEMENTATION.md D2.
- FR5's five conditions, all required, and that a correction failing any is not
  applied.
- Condition 5's comparison, per IMPLEMENTATION.md D3.
- Ownership: implementation-planner corrects the documents and proposes `files`, the
  orchestrator applies it, and the implementer and rework-planner do not correct the
  plan.
- References in tests: unmerged by that task's implementer, merged by a new task in
  the same correction.
- Application: `files` replaced in place, `notes` cleared to null, all else verbatim.

Reword `exactly two paths; a patch matching neither is rejected` to admit this
section. Add one sentence after the `Neither this protocol-error rule` sentence naming
the correction entry as the state where a `failed` task is not a protocol error. Add
one sentence after the carried-verbatim text pointing to the section.

**workflow-schema.md.** Add a `**Failed-entry restoration.**` paragraph to the
`routeback_failed_journal_line` section: develop's Step A.6 restoration is the one
other write site, the orchestrator's as well, writing the same record under the same
value rule. The pinned sentences of that section stay as they are, so the paragraph
names itself as their exception. Define the `tasks.{T}.notes` marker of Shared
Components in a short section, and point the `notes` line of the structure at it.

**create-plan-phase.md.** Add `--target-repo {integration worktree}` and
`--base-commit {integration tip}` to the canonical invocation, and state that the
orchestrator resolves the tip just before validating. Add two bullets to section 9's
list for the FR3 check and the FR5 checks. Add `## 13. Final-path correction dispatch`:

- Pre-dispatch: the same clean-worktree precondition and scope verification.
- Dispatch: `implementation-planner`, with `planning_inputs.path_correction`, the
  `write_policy` of the planner contract, and `tasks/` in `allowed_write_roots`.
- Record the run and patch in `phase-state/create-plan.yaml` under a new `request_id`
  and the next unused `patch_id`. The `create-plan` step stays `completed`, so the
  Resume decision table does not re-enter this run; an interrupted correction restarts
  from Step A.6.
- Validate with the canonical invocation plus `--journal`.
- Any result other than `completed`, any validator exit other than 0, and any stale
  result end the dispatch: the worker's writes are discarded and workflow.yaml is not
  changed.
- Apply per IMPLEMENTATION.md D4.

**rework-task-synthesis.md.** State in Section 10 step 3 that the validation passes
the same two values as create-plan's canonical invocation, and add a bullet for the
FR3 check to Section 12's list.
