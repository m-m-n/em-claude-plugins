# Task Plan: task0001 — Report name judgment and new-file rejection

## Goal

The validator rejects a new FR2-matching name in `tasks_patch.entries`, passes an
update of a regular file at the base commit, and fails closed on a missing or
unresolvable base. plan-writing holds the rule text and the regex.

## Design

Implement the first five Shared Components of IMPLEMENTATION.md as contracted.

**FR3 check.** Runs in the workflow-patch validation, after the entries are
validated, for both operations, with and without `--dry-run-apply`, and so on both
`--kind worker-result` and `--kind workflow-patch`. There is no tier branch: a task
whose `plan` is TASK.md is an entry like any other. Each violation is one
`report-name-new-file` error with `task_id` and `path`.

**FR4.** `--target-repo` and `--base-commit` are read only after a matching name
is found. A patch without one ignores them, even when they are malformed. A failure
raises `ExecutionError`, which reaches exit 2.

**Fixture runner.** `base-tree.json` is a mapping from repository-relative path to
file content. When a case directory holds it, the runner builds a disposable
repository with those files, commits, and adds `--target-repo` and `--base-commit`
to the case's arguments. The base tree is JSON because a file with an FR2 name
cannot be written into this repository by an implementer.

**plan-writing.** Add `## Report Artifact Names`, stating:

- FR2: only the final path segment is judged, the regex
  `/^(REPORT|SUMMARY|FINDINGS|ANALYSIS).*\.md$/i` decides, case is ignored, and
  directory names are not judged.
- FR1: a file with a matching name that does not exist at the base commit is not an
  artifact of tasks' files, a task body, an acceptance criterion or VERIFICATION.md.
- A report artifact takes a name that does not match.
- A plan holds no step that writes under another name and then renames.
- A task updating a matching-name file that exists at the base commit states in its
  body that the update is made with Edit.

Add one line to the Pre-Save Self-Verification Checklist citing that section.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `REPORT_ARTIFACT_NAME_RE` and `is_report_artifact_name` meet their
      contract, and a test compares the regex in `## Report Artifact Names` with the
      constant's pattern and case-insensitive flag (TS-15).
- [ ] AC-2: `## Report Artifact Names` states each FR1 rule, including the ban on
      writing under another name and renaming (TS-17, TM-9).
- [ ] AC-3: A replace_planning or append_rework patch with a new matching name exits
      1 with `report-name-new-file`, the task id and the path, including a task whose
      plan is TASK.md and the names `report.md`, `Analysis-notes.md`, `SUMMARY_x.MD`
      and `findings.md`; `report.txt`, `reports/foo.md`, `audit-report.md` and
      `README.md` pass (TS-1, TS-2, TS-3, TS-8).
- [ ] AC-4: A matching name that is a regular file at the base commit passes; one
      that is a directory or a symlink is rejected as new (TS-4, TS-5).
- [ ] AC-5: A patch with a matching name exits 2 with either value missing, with a
      base commit that is not a full hexadecimal ID (a revision expression included),
      or with a base that does not resolve. A patch without a matching name passes
      with neither value given (TS-6, TS-7, TM-2, TM-3).
- [ ] AC-6: A path with a leading `-`, or leading pathspec magic such as `:(top)`,
      is judged as literal text and rejected as new even when the path it would
      otherwise name exists at the base commit (TS-19, TM-1).
- [ ] AC-7: The three fixtures match their declared outcome through the corpus test,
      a patch equivalent to the reproduction steps' plan is rejected, and
      `python3 -m unittest discover -s tests` passes (FR9, NFR2, NFR4).
