## Goal

implementation-planner and rework-planner cite the naming rule, and
implementation-planner has a defined final-path correction dispatch.

## Requirements

FR1, FR5, FR9, NFR3, NFR6

## Scope

### Files to Create

### Files to Modify
- `em-workflow/agents/implementation-planner.md` — citation and correction section
- `em-workflow/agents/rework-planner.md` — citation and non-correction statement
- `em-workflow/references/contracts/planner-contract.md` — correction input and output
- `em-workflow/references/contracts/rework-planner-contract.md` — citation

## Design

Both agent documents cite `em-workflow/skills/plan-writing/SKILL.md`, section `## Report
Artifact Names`, for tasks' files, task bodies, acceptance criteria and
VERIFICATION.md, in the place that already handles Plugin Version Handling. Neither
contains the regex.

**implementation-planner.md** gains one line at the top of `## Process` routing a
dispatch with non-null `planning_inputs.path_correction` to a new `## Final-path
correction` section. The text of `### 2a.` stays as it is: a test pins its
`every dispatch` wording and its lack of a skip condition. The new section states:

- This dispatch runs only this section. It is the one dispatch the `### 2a.` pass does
  not run on: it changes path strings only, and THREAT-MODEL.md is not written.
- For each target, choose a new path that does not match FR2 and does not exist in
  the worktree. When the plan documents already name a non-matching replacement,
  propose that path.
- Replace the old path, and the bare old file name, in the target's task plan,
  IMPLEMENTATION.md and VERIFICATION.md. Change nothing else.
- Return `replace_planning` with every registered id in `carried_task_ids`, the
  corrections in `path_corrections`, and `step_patches` empty. `entries` holds only
  new tasks that correct references in merged test files.
- An unmerged reference in a test is corrected by that task's implementer from the
  corrected plan, so it gets no new task.
- A re-planning pass that carries a non-merged task with a violation also corrects
  it, through the same field.

**rework-planner.md** states that it does not run this correction.

**planner-contract.md** gains a `### path_correction (dispatch-resolved value)`
subsection with the Shared Components shape, states `value_inputs` gains it as a
member when present, and states that on this dispatch `write_policy.targets` has
action `replace_own` for IMPLEMENTATION.md, VERIFICATION.md and each target's task
plan. `payload.task_index` lists only `entries`, and may be empty.
