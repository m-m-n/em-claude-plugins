# Task Plan: task0005 — Implementer immediate failure on the Write rejection

## Goal

An implementer whose Write is rejected for an FR2 name stops at once, reports the
target path and the rejection text, and never works around the rejection.

## Requirements

FR7, FR9, NFR1, NFR6

## Scope

### Files to Create
- `tests/test_write_rejection_implementer_docs.py` — document contract tests

### Files to Modify
- `em-workflow/agents/implementer.md` — rule and report field
- `em-workflow/skills/worktree-task-workflow/SKILL.md` — discipline rule
- `tests/test_implementer_untrusted_data_rule.py` — expected report keys

## Design

**implementer.md.** Add a `## Write rejection` section before `## Hard constraints`:

- Trigger: Write returns the rejection text `Subagents should return findings as text,
  not write report files.`. The name definition is cited from
  `em-workflow/skills/plan-writing/SKILL.md`, section `## Report Artifact Names`. The
  implementer needs only the trigger, so this document has no regex.
- Stop work, return `status: failed` immediately, and do not run `merge_script`.
- Do not work around it by renaming, writing under another name, creating the file
  with Edit, writing through Bash, or asking the parent to write it.
- The rule also applies to a Write rejection on a file that exists at the base commit.
  A matching-name file that exists there is updated with Edit from the start, not by
  switching to Edit after a rejection.

**Report.** Add `"write_rejection"` to the Step 7 JSON block as a top-level key with
two-space indentation, keeping any mapping on one line. Describe it after the block:
null, or `path` (repository-relative, never absolute) and `rejection_text`.

**worktree-task-workflow.** Add a `## Write rejection` section stating the immediate
failure, the report and the ban on workarounds in short form, citing implementer.md's
section for detail.

**tests/test_implementer_untrusted_data_rule.py.** Add the key to
`EXPECTED_REPORT_KEYS`. This reflects the contract change and weakens nothing.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: implementer.md states the trigger, the immediate `status: failed`, and that
      `merge_script` is not run (TS-12).
- [ ] AC-2: The Step 7 report has `write_rejection`, described with a repository-relative
      `path` and `rejection_text`, and null otherwise (TS-12, TM-8).
- [ ] AC-3: implementer.md names each banned route: renaming, another name, Edit
      creating the file, Bash, and the parent writing it (TS-12, TM-9, NFR1).
- [ ] AC-4: implementer.md states the rule's scope for a file at the base commit and
      the use of Edit from the start (TS-12).
- [ ] AC-5: worktree-task-workflow states the immediate failure, the report of target
      path and rejection text, and the ban on workarounds (TS-12).
- [ ] AC-6: `EXPECTED_REPORT_KEYS` holds `write_rejection` and
      `python3 -m unittest tests.test_implementer_untrusted_data_rule` passes.

Document contract tests, section-scoped to the new sections. Include a negative check

## Out of Scope

The parent's handling of the report, and any hook or setting.
