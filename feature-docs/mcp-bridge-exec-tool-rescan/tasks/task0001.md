# Task Plan: task0001 — Limit the mcp-bridge skip (S1) to the notion / notion-create-comment pair

## Goal

destructive-guard skips the re-scan of the single-quoted `--args-json` value
of a static `mcp-bridge run` command only when the command's options
determine the `--mcp notion` / `--tool notion-create-comment` pair. Every
other `mcp-bridge run` command has its candidates re-scanned. The case suite
pins the new behaviour, and the in-code explanations state the pair
condition.

## Requirements

## Scope

- `em-workflow/hooks/tests/destructive-guard-cases.json` — fourteen new cases: TS-1 to TS-9 and five TM-2 cases

## Design

### Terms

- **S1**: the `mcp-bridge` arm of `_single_quote_skip_spans()`.
- **S2**: the `printf '%s\n'` arm of the same function.
- **Data word**: in S1, the word right after the word that equals
  `--args-json` exactly.
- **Statement words**: the words of the one `mcp-bridge run` statement that
  S1 already accepts. W1 to W4 hold before S1 is reached, so every statement
  word is static and reaches mcp-bridge as exactly one argument.
- **Known `run` flags**: `--mcp`, `--tool`, `--args-json`, `--format` and
  `--session`, which take a value, and `--dry-run`, which takes none.
- **Canonical flag word**: a statement word that is one of the known `run`
  flag names written as one unquoted run, exactly as listed: double dash, no
  `=`, no quote or escape character.
- **Re-scan**: queueing a candidate that is not skipped to `pending`, so it is
  judged.

### Why a flag walk (IMPLEMENTATION.md D1)

mcp-bridge `run` reads single-dash and `=` forms, lets the last occurrence of
a flag win, and stops reading options at `--` or at the first positional
word. Counting `--mcp` / `--tool` words alone therefore misjudges some forms.
The walk below accepts only the canonical form, which mcp-bridge reads in
one way, and treats every other form as undeterminable.

### S1 decision flow

1. The existing part of S1 stays: the second word is exactly `run`, and the
   data word is the word right after the word that equals `--args-json`
   exactly.
2. The flag walk below reads the statement words after `run`. When it does
   not end with a determined pair, S1 returns the empty set.
3. With a determined pair, side (a) holds when the value word of `--mcp` is
   `notion` written as one unquoted run, and side (b) holds when the value
   word of `--tool` is `notion-create-comment` written as one unquoted run.
   So `--mcp 'notion'` does not satisfy side (a).
4. Both sides hold: S1 returns the data word, as today.
5. Either side is false: S1 returns the empty set, and every candidate of the
   statement is re-scanned.

### Flag walk

The words after `run` are read from left to right. The first word is in flag
position.

- A word in flag position must be a canonical flag word. Any other word there
  makes the pair undeterminable. This covers `--`, a positional word (one
  that does not begin with `-`), a single-dash form such as `-mcp`, an `=`
  form such as `--mcp=notion` or `--dry-run=true`, a quoted or partly quoted
  flag word such as `'--mcp'`, and an unknown or abbreviated name.
- After `--dry-run`, the next word is in flag position.
- After any other known flag, the next word is that flag's value word,
  whatever it holds; a value word is never read as a flag, as mcp-bridge does
  not read it as one. A value-taking flag that is the last word makes the
  pair undeterminable. The word after a value word is in flag position.
- When the words end, `--mcp`, `--tool` and `--args-json` must each have
  been read in flag position exactly once. One of them read twice or more
  makes the pair undeterminable; one of them missing means there is no pair.
  Either way S1 returns the empty set.
- The number of times `--format`, `--session` and `--dry-run` appear is not
  restricted.
- The order of the flags is not restricted (FR1), so the pair matches in any
  order (TS-2).

is re-scanned. None states that the skip applies to any static
