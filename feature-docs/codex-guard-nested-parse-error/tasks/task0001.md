## Design

### 1. Fd classification in `_Parser._redirection` (FR1, FR5)

Target: an unquoted, digit-only word immediately before a redirect operator.

Contract:
- Precondition: the word is non-empty and made of digits only.
- Postcondition: the result is either "fd N" or "not an fd". The decision
  uses only the length of the word with leading zeros removed and a string
  comparison against the ten-character limit "2147483647". The word is never
  converted to a number. No length raises an error.

| Word after removing leading zeros | Result |
|---|---|
| empty (all zeros: `0`, `00`, 5000 zeros, ...) | fd 0 (standard input) |
| 1 to 9 digits | fd of that value |
| 10 digits, not greater than "2147483647" as a string | fd of that value |
| 10 digits, greater than "2147483647" as a string | not an fd |
| 11 digits or more | not an fd |

- "Not an fd": the word stays an ordinary word of the command (an operand),
  and the redirect binds to the operator's default fd (`>` standard output,
  `<` standard input).
- Words whose value is at most 2147483647 keep their pre-change verdicts.
- If downstream logic needs to know whether the fd is standard input, it
  gets that from the zero-stripped string (empty means fd 0), not from a
  number.

### 2. Nested-parse error containment in `_scan` (FR2, NFR5)

Flow for each nested string taken from the explicit work list:

1. Add the string's length to the cumulative re-read count, before parsing
   (unchanged).
2. Parse the nested string.
3. If parsing signals `_Undecidable`: skip the string and continue from the
   command after the one holding it (unchanged).
4. If parsing raises any other error (the general exception class): handle
   it exactly as step 3. The error produces no deny and no output by itself.

Unchanged: the depth-0 parse handling (no output, docstring step 9), the
exception handling in `_judge`, docstring step 6, and the explicit work list
(no recursive call is added, NFR2).
