# Task Plan: task0010 — conditional auto-addition of implement deviations

## Goal

`em-workflow/references/implement-phase.md` auto-adds an implement deviation
to the declared change set only when it is presented with the evidence that
an existing acceptance criterion would otherwise be dropped, leaves an audit
record either way, and keeps the containment check stopping unjustified
scope expansion.

## Requirements

FR19, NFR1, NFR3, NFR5, NFR7, NFR8

## Scope

### Files to Create
- `tests/test_deviation_auto_addition.py` — pins for the conditional rule,
  the audit trail, and the retained containment check.

### Files to Modify
- `em-workflow/references/implement-phase.md` — state the conditional
  auto-addition rule and its audit trail where implementer deviations are
  already collected.

## Design

Implementers already report `deviations` in their completion report and the
phase already collects them. This task adds the decision rule for what a
reported deviation does to the declared change set (IMPLEMENTATION.md,
Shared Components row 4, and decision D7):

1. **Condition**: a deviation is auto-added to the declaration **only** when
   it is presented with the evidence that an existing acceptance criterion
   would otherwise be dropped. State the evidence requirement as a named,
   checkable condition rather than as a judgement call.
2. **Otherwise**: a deviation lacking that evidence — implementer
   convenience, a nicer structure, an unrelated cleanup (EC-5) — is **not**
   auto-added. It surfaces as an ordinary deviation and the containment check
   deals with it.
3. **Containment check retained**: the observed change set must still be
   contained in the declared set, and unjustified scope expansion is still
   stopped exactly as before. Say this explicitly, because the auto-addition
   is otherwise readable as a hole in the check.
4. **No exclusion rule**: nothing in this document may state that
   workflow-generated artefacts are excluded, ignored or subtracted from the
   observed change set at verification time (C6d) — a repository-wide guard
   scans this document for exactly that shape.
5. **Audit record**: an auto-addition leaves a record through the existing
   completion-report deviation channel — what was added, and the evidence
   that justified it. No new phase-state field is introduced (D7). A
   rejected auto-addition also leaves its reason (NFR3).
6. **Derivation reference**: the declared set this rule adds to is the
   create-plan derivation defined in
   `references/phases/create-plan-phase.md`; cite it by path and restate
   neither the derivation nor the default-entry enumeration (C2, C6c).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR19): the document states that an implement deviation is
      auto-added to the declaration only when accompanied by the evidence
      that an existing acceptance criterion would otherwise be dropped.
- [ ] AC-2 (FR19): the document states that a deviation without that evidence
      is not auto-added, naming implementer convenience as an example that
      does not qualify.
- [ ] AC-3 (FR19): the document states that the containment check remains and
      that unjustified scope expansion is still stopped.
- [ ] AC-4 (FR19, NFR3): the document states that an auto-addition leaves an
      audit record carrying what was added and the evidence, and that a
      rejected one leaves its reason.
- [ ] AC-5 (D7): no new phase-state field is introduced; the audit trail uses
      the completion-report deviation channel the document already defines.
- [ ] AC-6 (NFR1, C6c/C6d): the declared set is referenced by path to the
      create-plan derivation, the two workflow-artifact root globs are not
      enumerated together, and no exclusion of workflow-generated artefacts
      from the observed change set is stated.
- [ ] AC-7 (NFR8): the repository-wide exclusion-rule guard still reports no
      offender for this document, and the full suite passes.
