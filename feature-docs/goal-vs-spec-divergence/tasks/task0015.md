# Task Plan: task0015 — implement-derived members in the declared change set derivation

## Goal

`em-workflow/references/phases/create-plan-phase.md` §12 names the
implement-derived additions as an input to the declared change set
derivation, names the single location where an admitted addition is
retained, and lists the implement wake that admitted one as a re-derivation
trigger — so an auto-added deviation actually changes the derived set
instead of evaporating at the next re-derivation.

## Design

FR19's conditional auto-addition has a decision rule (`implement-phase.md`)
but no effect: §12 closes the derivation's Inputs to what planning
registered, and limits re-derivation to re-planning and rework append.
An admitted deviation therefore never enters the union, and re-derivation
would drop it even if it did. §12 is the derivation's SSOT, so all three
repairs belong here and `implement-phase.md` keeps citing this section as it
already does (NFR1, C2).

1. **Inputs.** State the derivation's inputs as three sources rather than
   two: the `tasks.*.files` entries planning registered; the default entries
   (whose enumeration and semantics stay in the two document templates,
   cited and never restated — C6c); and the implement-derived additions
   admitted by the deviation auto-addition rule in
   `references/implement-phase.md`, cited by path with its evidence
   condition NOT restated here.

2. **Retention.** Name exactly ONE location where an admitted addition is
   retained: the `files` list of the task whose deviation was admitted, in
   `workflow.yaml` — the same list the union is read from, so a later
   re-derivation reads the admitted paths without needing a second source of
   truth. State that re-derivation reads that location, which is what makes
   an admitted addition survive every later re-derivation. Retention is about
   the derived set's membership; the audit trail of the admission decision
   stays where `implement-phase.md` puts it today (decision D7 is not
   reopened by this task).

3. **Timing.** Add the third re-derivation trigger — an implement wake that
   admitted a deviation — to the existing two (re-planning, rework append),
   so the trigger list and the input list agree.

4. **Unchanged halves.** The derivation's guard status (a guard, not a
   statement of the goal), the containment semantics carried by the
   templates, and the absence of any exclusion of workflow-generated
   artefacts from the observed change set (C6d) are unchanged, and stay
   stated exactly as they are.
