# Task Plan: task0005 — classification audit record in the phase-state schema

## Goal

`em-workflow/references/phase-state.md` defines where a classification-gate
pass is recorded and which fields that record carries, so every gate pass —
proceeding, stopping, or inapplicable — leaves an auditable trail.

## Requirements

FR14, NFR1, NFR3, NFR5, NFR7, NFR8

## Scope

### Files to Create
_None._

### Files to Modify
- `em-workflow/references/phase-state.md` — define the classification audit
  record: location, fields, value vocabulary, and its idempotency behaviour.
- `tests/test_phase_state_doc.py` — pin the new record.

## Design

The record is the phase-state schema's only addition in this feature
(IMPLEMENTATION.md, Shared Components row 2). Define it exactly as follows,
because a sibling task writes the rule that produces it and cannot see this
file:

1. **Location**: `feature-docs/{feature}/phase-state/rework.yaml` — present
   only when `phase: rework`, as a sibling of the existing `spec_change`
   record. No new phase-state file and no new top-level file layout entry.
2. **Fields**:
   - `classifier` — `codex` | `claude`
   - `verdict` — `goal_not_met` | `spec_gap` | `not_applicable`
   - `evidence_ids` — list of existing requirement / acceptance-criterion
     IDs; non-empty is required when `verdict` is `spec_gap`
   - `decision` — `proceed` | `stop`
   - `reason` — short text; mandatory whenever `decision` is `stop`,
     carrying (for example) the goal-block-absent inapplicability
3. **Production rule**: one record per gate pass, including passes that end
   in a stop and passes where the gate was inapplicable. The behavioural
   rule that decides the verdict lives in
   `references/question-resolution.md` and is cited, never restated (C2).
4. **Idempotency**: state how the record behaves under the document's
   existing ID-uniqueness and content-invariance rules — either it follows
   the append-record discipline like `artifacts` / `patches`, or it follows
   `spec_change`'s explicit replace-wholesale exemption. Pick one and say
   which; leaving it unstated is what makes a resumed run ambiguous.
5. **Field table**: add the record to the document's every-top-level-field
   table with a one-line meaning, matching the style the `spec_change` row
   already uses.

Place the additions inside the existing Schema section and its field table
(C3) — no new numbered or top-level section beyond what the schema listing
itself needs.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR14): the schema listing shows the classification audit record
      under `phase: rework`, as a sibling of `spec_change`, in the same
      style as the existing entries.
- [ ] AC-2 (FR14): all five fields are defined with their value vocabularies
      — `classifier`, `verdict`, `evidence_ids`, `decision`, `reason`.
- [ ] AC-3 (FR14): the document states that `evidence_ids` must be non-empty
      for a `spec_gap` verdict, and that `reason` is mandatory whenever
      `decision` is `stop`.
- [ ] AC-4 (FR14, NFR3): the document states that a record is written for
      every gate pass, explicitly including passes that stop and passes where
      the gate was inapplicable.
- [ ] AC-5 (FR14): the record appears in the every-top-level-field table with
      a one-line meaning.
- [ ] AC-6 (NFR1): the document does not restate the classification rule
      itself; it cites `references/question-resolution.md` for what produces
      the record, and the record's idempotency behaviour is stated in terms
      of the document's existing rules rather than a new invention.
- [ ] AC-7 (NFR8): the module's existing phase-state pins still pass and the
      full suite passes.

## Test Notes

- Assertions are string / structure scans over
  `em-workflow/references/phase-state.md` only (C4).
- Pin each field name together with its permitted values, scoped to the
  record's own block rather than to the whole document — several of these
  tokens (`stop`, `proceed`, `reason`) occur elsewhere in the file.
- Non-vacuity: assert the schema fenced block and the field table were both
  located before asserting membership inside them.
- Negative proof for each new matcher against a synthetic sample lacking the
  record.
- Edge case: the matcher for "one record per gate pass including stops" must
  not be satisfied by the general statement about recording answers.

## Out of Scope

- The classification gate's behaviour, verdict rules and evidence criterion
  (task0004).
- The implement-phase deviation audit trail, which reuses the existing
  completion-report channel and adds no phase-state field (D7, task0010).
