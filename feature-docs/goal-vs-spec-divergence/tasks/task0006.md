# Task Plan: task0006 — batch policy header aligned with the revised fail-closed rule

## Goal

`em-workflow/references/batch-policies.yaml`'s statement about why
`rework.spec-change` is intentionally unlisted matches the revised rule: it
falls through to the classification gate rather than to an unconditional
abort — with the gate still absent from the policy table.

## Requirements

FR11, NFR1, NFR2, NFR5, NFR7, NFR8

## Scope

### Files to Create
_None._

### Files to Modify
- `em-workflow/references/batch-policies.yaml` — rewrite the header comment
  paragraph about the intentionally unlisted spec-change gate.
- `tests/test_batch_policies.py` — pin the revised wording while keeping
  every structural guard.

## Design

The policy table itself does not change: no entry is added, removed or
edited, and `rework.spec-change` stays absent from `gate_policies` (D1).
Only the header comment changes.

Today the paragraph says the gate is unlisted so that the unlisted-gate
fallback's fail-closed classification aborts it rather than guessing an
answer. The replacement states, in the same place and at the same length:

1. `rework.spec-change` carries a `gate_id` but is deliberately not listed —
   unchanged as a fact.
2. What an unlisted gate reaches has changed for this one gate: the
   fail-closed classification in `references/question-resolution.md` now
   routes it into the classification gate instead of aborting outright. Cite
   that document by path for the rule; state no verdict, asymmetry or
   evidence criterion here (C2, NFR1).
3. The reason the gate is still not a policy entry: the decision is made by
   the classification gate at resolution time, not by an `option_id` chosen
   from this table.
4. Nothing about `category: security`, `category: license` or
   `reversible: false` is implied — the header must not suggest the
   fail-closed rule as a whole was relaxed (NFR2, D2).

Constraint: the phrase "decision table" / 「決定表」 must not appear in this
file (C6a), and the existing header claims the structural checks assert —
scope stated as gate-identifier presence, the `preserve_and_reuse` meaning,
the `on_unavailable: abort` meaning — must survive unchanged.
