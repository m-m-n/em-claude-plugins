# Task Plan: task0008 — referenced-side impact scan in the analyst contract and prompt

## Goal

requirements-analyst investigates the referencing side of symbols and strings
scheduled for deletion or renaming — test files included — and reports the
affected files as create-spec output, with every scanned path resolved by the
orchestrator before dispatch.

## Requirements

FR17, NFR1, NFR5, NFR7, NFR8

## Scope

### Files to Create
- `tests/test_reference_impact_scan.py` — pins for the contract's new
  request/result fields, the envelope category, and the agent's investigation
  procedure.

### Files to Modify
- `em-workflow/references/contracts/analyst-contract.md` — the request flag,
  the result field, and the resolution-point statement.
- `em-workflow/references/contracts/worker-envelope.md` — add the
  reference-scan category row to the resolved-input-paths table.
- `em-workflow/agents/requirements-analyst.md` — the investigation procedure
  and what it reports.

## Design

Names are fixed in IMPLEMENTATION.md, Shared Components row 3, because the
orchestrator side of this contract is a sibling task's file.

### A. Envelope category

Add one row to the `resolved_input_paths` field table:
`reference_scan_targets` — the resolved paths the referenced-side scan reads.
Required, may be empty, same shape as the categories already listed. Nothing
else in that document changes; the read-restriction and untrusted-input rules
already cover the new category by construction (C2).

### B. Analyst contract

1. **Request**: `analysis_scope.inspect_reference_impact` (boolean),
   alongside the existing inspection categories. Meaningful only in
   `analysis_mode: full`; the design-system-detection mode ignores it exactly
   as it ignores the rest of `analysis_scope`.
2. **Result**: `reference_impact`, a list whose entries pair the symbol or
   string scheduled for deletion or renaming with the affected file paths.
   It appears in the `analysis_snapshot` (interim, with
   `status: needs_user_input`) and in the `analysis_mode: full` completed
   payload. State that test files are in scope of the affected paths — that
   is the point of the requirement, and a reader must not have to infer it.
3. **Resolution point**: extend the existing statement that the orchestrator
   resolves glob-derived categories before dispatch so it covers the new
   category, keeping the rule that the analyst performs no filesystem
   discovery of its own (assumption A-4).
4. **`digest_inputs`**: the full-mode row gains the resolved reference-scan
   paths, since they can influence the analyst's output. The
   design-system-detection row is unchanged.
5. The design-system-detection mode's payload exclusivity is unchanged:
   `reference_impact` is a full-mode field and must not be introduced as a
   third mode or as a detection-mode payload key.

### C. Agent prompt

State the investigation step in the analyst's own procedure: when the request
flag is set, examine the supplied scan-target paths for references to the
symbols and strings the feature intends to delete or rename, and report the
affected files in the result field above. Reinforce, in the prompt's own
terms, that the analyst reads only what the envelope supplies. Keep the
prompt's existing structure; add the step where the other inspection
categories are described.

## Test Notes

- Assertions cover only this task's three documents (C4).
- Pin field names as exact tokens (backtick-delimited), not as substrings —
  a name embedded in a longer identifier must not satisfy the assertion.
- Non-vacuity: assert the envelope's field table and the contract's mode
  table were located before asserting rows inside them.
- Negative proof per new matcher against a synthetic sample.
- Edge case: assert that `reference_impact` is NOT stated as a
  design-system-detection payload key — the exclusivity rule is easy to break
  by describing the field too generally.
- Existing modules over these documents assert supersets (every design-listed
  field must appear); adding fields is expected to leave them green — confirm
  by running the full suite rather than by editing them.
