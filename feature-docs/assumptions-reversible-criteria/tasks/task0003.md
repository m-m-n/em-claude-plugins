# Task Plan: task0003 — Bump the em-workflow plugin version in both registries and pin it with a version-bump test

## Goal

Both registries that record the `em-workflow` plugin version move from the
0.1.64 baseline to the same, strictly greater patch version, and a test module
pins that property so a later change under `em-workflow/` cannot silently ship
without a bump.

## Requirements

FR7, NFR4

## Scope

### Files to Create
- `tests/test_assumptions_reversible_criteria_version_bump.py` — pins the
  two-registry version property with per-matcher negative proofs.

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — the plugin's own version field.
- `.claude-plugin/marketplace.json` — the version field of the em-workflow entry.

## Design

### Version value

Both registries move to `0.1.65` (IMPLEMENTATION.md C5 pins the value so no
other task and no second edit can diverge). The bump is patch-level because the
feature corrects documented behaviour rather than adding a capability. The
`em-review` entry of the marketplace manifest is not touched and stays at its
current value; each plugin's version is independent.

Only the version field of each manifest changes. No other field, ordering or
formatting detail of either JSON document is altered.

### Test module responsibilities

1. Both registries report the same version string for `em-workflow`.
2. That version is strictly greater than the 0.1.64 baseline at the patch
   component, with the major and minor components unchanged.
3. The `em-review` entry of the marketplace manifest still reads its current
   pinned value, so the bump did not spill into the neighbouring plugin.
4. Per-matcher negative proofs: each of the three properties above is proved
   non-vacuous by applying its check to forged in-memory manifest data that
   violates it and asserting rejection, and to forged data that satisfies it and
   asserting acceptance. No file is written during these proofs.

The module reads only the two manifests, both of which exist on the base branch
and are edited by this task alone, so it is green in a worktree containing only
this task's changes (IMPLEMENTATION.md C4).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `em-workflow/.claude-plugin/plugin.json` reports version `0.1.65`.
- [ ] AC-2: The `em-workflow` entry of `.claude-plugin/marketplace.json` reports
      the same version as AC-1.
- [ ] AC-3: That version is strictly greater than 0.1.64 at the patch component,
      with major and minor unchanged.
- [ ] AC-4: The `em-review` entry of the marketplace manifest is unchanged at
      0.5.7.
- [ ] AC-5: `tests/test_assumptions_reversible_criteria_version_bump.py` asserts
      AC-2 through AC-4, and each of those three checks has a negative proof
      against forged data plus a non-vacuity companion.
- [ ] AC-6: The new module imports only standard-library names and passes in a
      worktree containing only this task's changes.

## Test Notes

- The version comparison is over parsed numeric components, not string
  comparison, so `0.1.100` would compare correctly against `0.1.64`.
- Edge case worth covering: equal versions across registries must not be
  accepted when they are equal to the baseline — the check is strictly greater.
- Edge case worth covering: a minor or major bump must be rejected by the
  matcher, since AC-3 requires major.minor unchanged.
- The existing version-bump test module in the repository is the style reference
  for the negative-proof pairs; do not modify it.
- Run `python3 -m unittest discover -s tests` from the repository root before
  declaring done.

## Out of Scope

- Editing the `em-review` entry, or any manifest field other than the
  `em-workflow` version.
- Regenerating or reformatting either JSON manifest beyond the single field.
- Any documentation, fixture or criterion work — other tasks own those files.
