# Task Plan: task0001 — Close the enclosing brace group at a lone closing brace after a rescued provisional chain

## Goal

In both copies of codex-hook-interactive-guard, a lone bare `}` that follows
a rescuable chain of provisional argument groups directly inside a `{` group
rescues the chain and closes that group, so the two reproduction forms are
denied. Forms that do not qualify keep their current verdicts, and the
decision stays linear-time.

## Design

Terms follow REQUIREMENTS.md section 13: provisional group, rescue, direct
separator (`_Group.first_sep`), in_anon, skipped. IMPLEMENTATION.md
Conventions apply (two copies, CASES format, undecidable stays silent).

### D1. When the rule is consulted
The rule is consulted when the body reader finishes a word that is a lone
bare `}`: unquoted, not part of an expansion, not joined to other characters,
and not a redirect target. This is the same recognition the existing `}`
handling in `_finish_word` applies; this task does not widen it. The rule
applies only when the innermost open group is a provisional group. When the
innermost open group is a `{` group, the existing close behavior is
unchanged (this is what lets a nested `{ ...; }` inside a provisional group
close normally, TS9).

### D2. Chain, base and qualification
- **Chain**: the maximal run of open provisional groups, starting at the
  innermost open group and continuing outward while the next group is also
  provisional.
- **Base**: the first open group outside the chain, or the top level when
  there is none.
- The `}` **qualifies** when all of these hold:
  1. The chain meets the same separator condition `_rescue_argument_groups`
     applies at end of input: the first direct separator is `;` or a lone
     `&`, with an inner group's separator inherited by the outer groups.
     The condition is judged on the separators the body reader actually read
     (`_Group.first_sep`), never on the `_scan_parens` lookahead.
  2. The base is a `{` group: a plain brace group, an anonymous-function
     body or a function-definition body. A `(` base or the top level does not
     qualify (FR3, FR7).
  3. Either no words are pending in the current command, or words are
     pending and the base is in_anon (the same in_anon condition the
     existing pending-word `}` rule uses).
- The separator condition is defined once and used both here and by the
  end-of-input rescue, so the two cannot drift apart.

### D3. Outcome when the `}` qualifies
1. Every group of the chain is rescued, innermost first, each removed once:
   its `(` becomes a character of the anonymous function's argument word,
   exactly as the end-of-input rescue treats it.
2. Commands the reader recorded inside the rescued groups become commands of
   the base group, so a redirect or pipe attached to the base group reaches
   them as if the provisional groups had never opened (FR2; TS6, TS7).
3. When words are pending (the in_anon case), they are finalized as a
   command of the base group before the close (TS10).
4. The base group is closed through the same path as a `; }` close. After
   it: an anonymous-function body takes the following words as arguments
   (TS12); a following word after a plain brace group makes the reading
   undecidable (TS13); a function-definition body's commands are skipped and
   a launch after a following separator is judged (TS14, TS15); a following
   `)` is read as a separator and closes an enclosing subshell, as anywhere
   else.

### D4. Outcome when the `}` does not qualify
The `}` stays an ordinary word. No open group, separator record, provisional
flag or recorded command changes. End-of-input handling is unchanged: the
existing rescue runs, and any group still open raises the undecidable
group outcome (no output). This covers the separators listed in FR3, the
missing-separator case, a non-`{` base, a pending-word `}` with a base that is
not in_anon (TS11), and the existing case 601 with no closing `}`.

### D5. Amortized constant-time decision (NFR1)
- The check at `}` never walks the open groups. Each group carries values
  fixed when it opens, derived from its parent's values only:
  - the base its chain would have (the parent itself when the parent is not
    provisional; otherwise the parent's recorded base);
  - whether the part of the chain outside it is already disqualified (the
    parent is provisional and either is itself recorded as disqualified, or
    its own first direct separator, read before this group opened, fails the
    separator condition).
- Why the values can be fixed at open time: while a child group is open, its
  parent reads no direct separator, so the parent's contribution to the chain
  cannot change until the child closes.
- The check at `}` then reads only the innermost group's own values and its
  own first direct separator.
- The implementer confirms this formulation gives the same verdict as
  `_rescue_argument_groups` for the same chain, including its outward
  inheritance rule. When the existing rule differs, the open-time values are
  adapted to match it while keeping the check constant-time per `}`.
- Rescue cost is paid once per provisional group. A failing `}` touches
  nothing, so a long run of failing `}` stays linear.
- No recursion; standard library only; no file, network or subprocess access
  (existing constraints, NFR3).
