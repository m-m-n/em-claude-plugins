# Task Plan: task0001 — 配列代入の後のグループを関数本体とみなさないようにする

## Goal

`codex-hook-interactive-guard.py` の両コピーが、配列代入（`a=()` / `a+=()` / `export a=()`）の後に改行を挟んで続くグループの中の対話起動を deny し、bash の関数定義の本体はこれまでどおり判定しない状態にする。回帰を検出するケースを `CASES` に固定する。

## Design

### 現在の流れ

1. `(` を読むと、その直前までの単純コマンドを閉じてグループを開く。このとき直前の単純コマンドに語が 1 つでもあれば、語の中身を問わずグループに関数名あり（`head`）を立てている。
2. `head` の立ったグループが中身の無いまま `)` で閉じると、次のグループを関数本体とする待ち状態（`fn_head`）を立てる。
3. `fn_head` は改行では消えず（A3）、`;` `&&` `||` `|` `&` と、語の出現で消える。
4. `fn_head` が立っている間に開いたグループは、`(` でも `{` でも関数本体として判定から外れる。

代入語 `a=` も手順 1 の「語がある」に当たるため、`a=()` + 改行 + `( ... )` の 2 つ目のグループが関数本体として外れている。

### 変更: `head` を立てる条件（FR1）

`(` を開くときに `head` を立てるのは、`(` で終わった単純コマンドの語の並びが次のどちらかのときだけとする。

| 形 | 条件 | 例 |
|---|---|---|
| (a) | 語がちょうど 1 つ。その語は動的でなく、`=` を含まない | `foo()` / `f()` / `my-func()` |
| (b) | 語がちょうど 2 つ。1 つ目が `function`、2 つ目は動的でなく `=` を含まない | `function f()` |

それ以外のときは `head` を立てない。

| `(` の直前の語の並び | `head` |
|---|---|
| `a=` / `a+=`（`=` を含む 1 語） | 立てない |
| `export a=`（2 語で、1 つ目が `function` でない） | 立てない |
| 動的な語を含む | 立てない |
| 3 語以上、または語が無い | 立てない |

現在の流れの手順 2〜4 は変えない。

### 前提と結果

- 前提: `(` を読んだ時点で、直前の単純コマンドの語の並びと、各語が動的かどうかが確定している。
- 結果:
  - 配列代入（`a=()` / `a+=()` / `export a=()`）の後に改行・空行・コメント行を挟んで続く `( ... )` と `{ ...; }` は関数本体として扱われず、中のコマンドが判定される（FR2）。
  - `foo()` + 改行 + `( ... )`、`f() ( ... )`、`f() { ...; }`、`function f() { ...; }` の本体は判定されない（FR3）。
  - `a=() ; ( ... )` は `;` で `fn_head` が消えるため、これまでどおり判定される（FR4）。

### docstring（NFR2）

- モジュール docstring の手順 4 にある関数定義の記述を、(a) (b) の形のときだけ関数定義とみなすこと、`name()` の後に改行を挟んでも続くグループを本体として扱うことを述べる形にする。
- `_Group` の docstring の `head` の説明を (a) (b) の条件に合わせる。
- `TestGuardDocumentation.DOCSTRING_MARKERS` の既存マーカーはすべて残す。

### 両コピー（FR5）

em-workflow 側を直し、em-review 側をバイト単位で同じ内容にする。2 つのコピーは同じコミットで変える。

## Test Notes

- AC-1〜AC-4 は `CASES` に足したケースで確かめる。`TestCasesTable.test_cases_run_against_both_copies` が両コピーを別プロセスとして起動し、標準入力に PreToolUse の JSON を渡して判定を見る。
- 先にケースを足すと、AC-1 の 6 件は修正前は何も出力しないため失敗する。AC-2 と AC-3 は修正前から期待どおりで、修正で壊れていないことを固定するケースになる。
- AC-1 の 6 件目（`a=()` + 改行 + `{ python3 -i; }`）は基準版でも何も出力しなかった既存の見落としで、同じ修正で deny になる（A2）。
- `CASES` にケースを足すと、`SAMPLE_CASES`（`CASES` から 12 件おきに抜いたもの）の中身がずれる。抜かれたケースは作業ディレクトリと環境変数を変えて再実行されるが、判定はコマンド文字列だけで決まるため、期待する判定は変わらない。
- `test_cases_are_unique` があるため、足すコマンドは既存のコマンドと重ならないようにする。
- `my-func()` のような識別子でない関数名は (a) に当たり、これまでどおり関数名として扱う（A1）。
- hook を変えたら `.claude/rules/hook-tests.md` のとおり `python3 -m unittest tests.test_codex_hook_interactive_guard` を走らせる。
