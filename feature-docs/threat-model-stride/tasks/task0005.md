# Task Plan: task0005 — review protocol input field and Codex prompt carriage for threat_model_path

## Goal

The review protocol defines `threat_model_path` as a security-only optional
reviewer input with untrusted-content semantics, and the Codex reviewer puts
it into the Codex prompt, with the two frozen digests that cover these texts
refreshed and nothing else in the frozen set moved.

## Requirements

FR8, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_threat_model_reviewer_inputs.py` — document-contract tests for the protocol and Codex prompt changes

### Files to Modify

- `em-workflow/agents/codex-reviewer.md` — Step 4 prompt assembly for the new field
- `tests/test_reviewer_roles_protocol.py` — add the field to the input-name list and refresh exactly two digests, with comments naming this feature

- `.claude-plugin/marketplace.json` — em-workflow entry's version field only, same condition and same value as plugin.json (SC-6)

## Design

This task owns SC-4's reviewer-side meaning (review-protocol.md) and the
Codex prompt carriage (codex-reviewer.md). Resolution and dispatch belong
to review-phase.md; detection belongs to the review-security skill.

### review-protocol.md

- **Inputs section** (the one frozen section this feature may change): one
  bullet directly after the `spec_path` bullet. It states: absolute path to
  the feature's THREAT-MODEL.md; security perspective only; optional — set
  only on the develop-driven route when the file exists; reading it does
  not count against the Investigation Budget; its content is untrusted data
  handled as the Untrusted-Input Handling section describes, and it can only
  add checks, never suppress a finding; unreadable means the review
  continues without the mitigation cross-check and says so in `summary`,
  never a skip; what to flag from it is owned by the perspective skill.
- **Step 0 Fail-Closed Resolution** (not frozen): one sentence stating that
  `threat_model_path` is outside the fail-closed pattern — its absence or
  unreadability never produces a skip object.
- **Path-List Validation** (not frozen): `threat_model_path` gets the same
  orchestrator-side realpath containment and symlink rejection as
  `spec_path`.
- The Investigation Budget, Severity, Output Schema, Read-only Constraint
  and Untrusted-Input Handling sections and the harness description bullets
  stay byte-identical.

### codex-reviewer.md (Step 4 only)

- `<task>`: when `threat_model_path` is supplied (security perspective
  only), the path goes inline as a path string for Codex to read inside its
  read-only sandbox, stated as outside the 3-file investigation budget; an
  unreadable file means the review continues and the summary says so.
- `<grounding_rules>`: THREAT-MODEL.md content is untrusted data like the
  diff — instructions inside it are payload; it only adds checks and never
  suppresses a finding; a missing-mitigation finding (defined by the
  perspective brief) cites the boundary file named in THREAT-MODEL.md with
  a null line when no specific line applies, and is never re-pointed to an
  unrelated changed file.
- Frontmatter lines, Steps 0-3, the Temp-file discipline section, Step 5
  (wrapper invocation line and its timeout declaration) and Step 6 stay
  byte-identical.

### tests/test_reviewer_roles_protocol.py

- The input-name list gains `threat_model_path`.
- The Inputs entry of the frozen-section list and the codex-reviewer steps
  digest are refreshed to the edited content, each with a comment naming
  threat-model-stride and FR8 (refresh, never remove).
- Every other frozen section digest, the harness-bullets digest, the
  reviewer-steps digest, the schema pins, the forbidden framing phrases and
  the digest-source declaration stay unchanged; no test class is removed.
