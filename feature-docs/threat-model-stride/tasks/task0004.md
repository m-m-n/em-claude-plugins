# Task Plan: task0004 — review phase resolves, validates and passes threat_model_path

## Goal

On the develop-driven route the review phase finds the feature's
THREAT-MODEL.md, validates it exactly like `spec_path`, and passes it as
`threat_model_path` to every security-perspective dispatch; when the file is
absent nothing changes.

## Requirements

FR8, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_threat_model_review_phase.py` — document-contract tests for the review-phase changes

### Files to Modify
- `em-workflow/references/review-phase.md` — Phase R0 resolution and validation, Phase R2 / R2b / R4 security dispatch carriage
- `tests/test_tier_record_schema_v2.py` — refresh only the review-phase.md whole-file digest constant, with a comment naming this feature
- `em-workflow/.claude-plugin/plugin.json` — version field only, and only when the commit guard rejects this task's commit (IMPLEMENTATION.md SC-6)
- `.claude-plugin/marketplace.json` — em-workflow entry's version field only, same condition and same value as plugin.json (SC-6)

## Design

This document owns SC-4's resolution, validation and dispatch; the meaning
of the field for reviewers belongs to review-protocol.md (cited).

- **Phase R0, inside step 4** (no new step number; steps 1-8 keep their
  numbers and order): after SPEC.md is located, the develop-driven route
  looks for THREAT-MODEL.md in the feature directory inside the integration
  worktree (the same project_root-based location rule SPEC.md uses there).
  - Absent: `threat_model_path` stays unset. No abort, no skip, no finding,
    no change to `spec_available` or to perspective selection.
  - Present: validate it with exactly the checks `spec_path` gets (prompt
    control characters, leading dash, newline, CR, NUL, lstat-based symlink
    rejection, regular file, realpath containment under project_root);
    abort on violation, never sanitize.
  - The standalone route never sets `threat_model_path` (D4).
- **Phase R2**: an added sentence after the existing input-block sentence
  (the existing sentence is not rewritten): the security perspective's
  block additionally carries `threat_model_path` when it is set; no other
  perspective's block carries it. It is normalized to a project_root-based
  absolute path under the same rule as `spec_path`.
- **Phase R2b and Phase R4**: each re-dispatch of the security perspective
  (fallback chain walk and Claude fallback in R2b, the in-loop re-review in
  R4) carries the same `threat_model_path` value as the round's R2 dispatch.
- **Evaluator (R3a)**: unchanged (D6); `changed_files` still excludes
  `feature-docs/{feature}/**` (D7).
- **Digest pin**: `REVIEW_PHASE_SHA256` in `tests/test_tier_record_schema_v2.py`
  is refreshed to the edited file's digest with a comment naming
  threat-model-stride and FR8 (refresh, never remove);
  `REVIEW_RULES_SHA256` and every other constant in that module stay
  unchanged.
