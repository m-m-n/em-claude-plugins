# Task Plan: task0003 — Enumerated-path ownership and ambiguity refusal in the Stop guard's active set

## Provenance

- Source: `review`, round 1
- Source finding ids: `51eb6a3a09783d9d` (comprehensive), `04fa12c3a465eb0b`
  (architecture)
- Both findings describe the same root cause — the second wildcard of the
  layout pattern is unconstrained, so a `workflow.yaml` belonging to another
  feature, sitting inside this feature's integration worktree, is enumerated
  and then evaluated under this feature's identity, journal directory and
  sidecar. They are therefore one task.

## Goal

Make the active set contain only `workflow.yaml` paths that the identity
derived from them actually owns, so that no other feature's `feature-docs/`
directory inside an integration worktree can be evaluated under this
feature's identity, journal or sidecar.

## Requirements

FR1, FR2, NFR2, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/hooks/queue_stop_guard.py` — insert an ownership + uniqueness
  selection step between the layout-pattern expansion and the
  `in_progress` / freshness filters of the active-set stage.
- `tests/test_queue_stop_guard.py` — add the foreign-`feature-docs` tests and
  the ambiguity-refusal unit test, and repurpose the existing
  divergent-segment probe.

## Design

Cross-task decisions live in IMPLEMENTATION.md (D1–D4 unchanged; D6 added by
this task's shared-contract extension) and are not restated here.

### Which prescription is implemented, and why

The two findings carry two different prescriptions. Both are implemented, in
a fixed priority:

1. **Primary — ownership by segment equality.** SPEC.md's Path Contract
   already states the enumerated location as
   `{worktrees_root}/{feature}/integration/feature-docs/{feature}/workflow.yaml`,
   with the *same* `{feature}` in both positions. A matched path whose two
   segments differ is therefore already outside the specified layout;
   rejecting it enforces the existing specification and is not a
   specification change. This is the mechanism that removes the defect.
2. **Secondary — ambiguity refusal.** Once ownership holds, at most one
   surviving match can carry a given identity, so ambiguity is no longer
   reachable through the pattern. It is still made an explicit, checked
   invariant rather than an unstated consequence, because the implicit
   first-wins selection is exactly what the architecture finding objects to
   and the sister hook `queue_taskstop_net.py` already contracts the refusal
   direction. It is a guard on an invariant, not the fix.

Neither prescription requires a SPEC.md change and the two are not mutually
exclusive.

### Ownership + uniqueness selection step

- **Precondition**: the ordered list of paths produced by expanding the
  layout pattern under one enumeration root.
- **Postcondition**: an ordered list of the same triples the active-set stage
  already carries (feature identity, journal directory, matched path),
  restricted to matches that satisfy all of:
  1. the identity derived by the existing single decomposition passes the
     existing feature-name shape check;
  2. the match's own `feature-docs/<segment>` segment is equal to that
     identity (**ownership**);
  3. no other surviving match derives the same identity — an identity carried
     by two or more surviving matches is dropped **in full**, contributing no
     candidate at all (**ambiguity refusal**, the fail-open direction).
- **Purity**: the step decides all three conditions from the matched path
  strings alone. It opens nothing, stats nothing, and spawns nothing, so it
  is directly unit-testable against paths that do not exist on disk.
- **Single derivation (NFR4)**: condition 2 compares two segments *of the
  path that was matched*. No path is reconstructed from an enumeration root
  plus a name, and the `feature-docs` segment is still never read as
  identity — it is only compared against the identity. The decomposition
  contract in IMPLEMENTATION.md is unchanged.

### Placement and downstream effects

- The step runs after pattern expansion and before the `in_progress` and
  freshness filters, so a rejected match costs zero file reads. Per-Stop cost
  is unchanged in shape and strictly non-increasing (NFR3): string
  comparisons over an already-materialised match list.
- Surviving candidates keep their existing stable ascending-by-identity
  ordering, so "first in-progress feature with refillable work wins" (FR2)
  keeps its current meaning across *distinct* identities. Nothing about the
  decision stage, slot arithmetic, failed-task pass-through, recycled-task-id
  carve-out, fingerprint or block cap changes (NFR5, assumption a3).
- Every exclusion this task introduces moves toward exit 0. No condition that
  previously exited 0 can exit 2 as a result (NFR2).

### Consequence for the NFR4 probe

The existing single-derivation probe asserts that a divergent-segment fixture
*blocks* and names the worktree-side segment. That assertion is precisely the
behaviour being removed, so the probe stops being a discriminator in its
current form and is repurposed to assert non-enumeration. The replacement
discriminator for "reads what it enumerated" is stronger and closer to the
real defect: two `feature-docs` directories inside **one** integration
worktree, where only the owned one may be read, so a rebuilt path or a
foreign match is observable in the BLOCK line's task ids.

## Test Notes

- `StopGuardFixture` already accepts a `docs_segment` parameter and derives
  its journal directory from `feature`, so two instances with the same
  `feature` and different `docs_segment` under one temp directory produce
  exactly the mixed-worktree layout AC-2 and AC-3 need, sharing one journal
  directory. No fixture redesign is required; the only extension worth making
  is whatever is needed to write two `workflow.yaml` files with different
  declared task id sets.
- Write the tests first. AC-1 through AC-3 fail against the current hook for
  the reason the findings describe (the foreign match is enumerated and
  evaluated under `alpha`), which is the honest red.
- AC-2 is the load-bearing assertion: the negative half (no `beta`, no
  `task0007`-`task0009` in stderr) is what distinguishes "read the owned
  match" from "read the first match".
- AC-5 is the only test in the file that imports the hook rather than driving
  it as a subprocess. Keep it in its own class, and keep the imported symbol
  surface to the single selection step so the rest of the suite stays
  behavioural.
- AC-5(d) is what pins the step's purity: if the step ever grows a filesystem
  read, the test's non-existent paths make it fail or raise.
- Journals written by a fresh temp directory are fresh by construction, so no
  explicit mtime pinning is needed for any criterion here; do not add
  assertions near the 24-hour freshness boundary.
