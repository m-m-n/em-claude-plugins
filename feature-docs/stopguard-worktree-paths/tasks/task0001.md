# Task Plan: task0001 — Worktree-layout enumeration and pair-based resolution in the Stop guard

## Goal

Make the Stop-hook queue guard resolve real features: enumerate the
integration-worktree layout from a working-directory ancestor walk, hand the
decision stage an already-resolved pair, filter out abandoned worktrees by
freshness, and migrate the test fixture to the real layout — with the
fail-open contract and every downstream decision semantic unchanged.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/hooks/queue_stop_guard.py` — replace the project-root probe
  with an ancestor walk, replace the flat-layout enumeration with the
  integration-worktree layout, add the freshness filter, and make the decision
  stage consume a resolved pair instead of constructing a path.
- `tests/test_queue_stop_guard.py` — migrate the fixture to the real layout and
  add the new real-layout, freshness, ancestor-walk and single-derivation
  tests.

## Design

Cross-task decisions D1–D4, the path contract, the fail-open convention and
the component contracts live in IMPLEMENTATION.md and are not restated here.

### Indivisibility

Enumeration, resolution and the fixture migration are one change. Splitting
enumeration from resolution is precisely the shape that caused the earlier
revert, and the migrated fixture only passes against the migrated hook. This
task therefore owns all three defective sites (`:258` path construction,
`:266` journal directory, `:311` enumeration) and the fixture together.

### Stage 1 — Enumeration root

1. Take the hook's current working directory.
2. Walk upward, the starting directory included, looking for a directory that
   contains the em-workflow worktrees path as a directory.
3. On the first hit, the enumeration root is that worktrees directory itself.
4. On reaching the filesystem root without a hit, there is no enumeration root:
   the hook has no active feature and ends silently with exit 0.
5. This stage performs no process invocation. The previous project-root probe
   — the one that shelled out for a repository top level — is removed
   entirely, together with its import of the process-spawning facility if
   nothing else needs it.

### Stage 2 — Active set

1. Expand the layout pattern under the enumeration root (IMPLEMENTATION.md,
   Path Contract) and order the matches deterministically.
2. Decompose each match once into (feature identity, journal directory) per
   the decomposition contract. The identity is the worktree-side segment; the
   `feature-docs` wildcard segment is never read as identity.
3. Reject a candidate whose derived identity does not satisfy the existing
   feature-name shape check. The check is applied to the derived identity
   only; it is not a second derivation.
4. Keep only candidates whose implement step reads `in_progress`, using the
   existing reader against the matched path.
5. Apply the freshness condition (IMPLEMENTATION.md D3) to each surviving
   candidate; a stale or undecidable candidate leaves the set.
6. Yield the survivors as (feature identity, matched `workflow.yaml` path)
   pairs, stable and ascending by identity, so that "first in-progress feature
   with refillable work wins" keeps its current meaning.
7. The flat-layout enumeration is deleted; no second enumeration path remains.

### Stage 3 — Decision (semantics unchanged)

1. Read the pair's `workflow.yaml` path verbatim. Nothing is joined from a
   root and a name.
2. Reach the journal file and the sidecar through the journal directory the
   decomposition produced.
3. Slot arithmetic, the failed-task pass-through, the recycled-task-id
   carve-out, the fingerprint, the three-consecutive-block cap and the stderr
   line format are untouched.

### Fail-open surface after the change

| Condition | Behaviour |
|---|---|
| Malformed stdin / non-dict payload | exit 0, silent |
| No enumeration root found by the walk | exit 0, silent |
| Unreadable or malformed `workflow.yaml` / journal | exit 0, silent |
| Journal directory absent | exit 0, silent |
| Neither freshness time obtainable | candidate excluded; exit 0 |
| Any unhandled exception | exit 0, silent |

### Fixture migration

The fixture writes `workflow.yaml` into the integration-worktree layout and
keeps the journal and sidecar at the worktree-side directory. Creating the
layout directories is also what makes the ancestor walk resolvable from a
fixture root, so a fixture built for a "no enumeration root" case must not
create them (IMPLEMENTATION.md D4b). Fixtures that write a journal get a
current modification time for free from a fresh temporary directory; a
fixture that relies on the fallback must be explicit about which file carries
the time being tested.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With the real-layout fixture (`workflow.yaml` in the integration
      worktree, journal at the worktree-side directory, implement step
      `in_progress`, two declared tasks, no launched events), the hook exits 2
      and its stderr BLOCK line names the feature, the free-slot count and both
      task ids in ascending order — and produces byte-identical stderr and the
      same exit code whether the working directory is the fixture root or the
      integration-worktree directory inside it. (SPEC AC1, AC2; TS1, TS2)
- [ ] AC-2: Freshness behaves in all four cases: journal time 25 hours in the
      past → exit 0 with no block despite an `in_progress` step and unlaunched
      tasks; journal time now → exit 2; no journal file with `workflow.yaml`
      time 25 hours in the past → exit 0; no journal file with `workflow.yaml`
      time now → exit 2. The threshold is a single named constant. (SPEC AC3,
      AC4; TS4)
- [ ] AC-3: Nothing outside the integration-worktree layout is ever
      enumerated: a `workflow.yaml` written only at the main-tree flat path
      with `in_progress` produces exit 0, and a working directory with no
      em-workflow worktrees directory anywhere above it produces exit 0 with
      empty stderr and no traceback. (SPEC AC5; TS5, TS6)
- [ ] AC-4: Journal variants keep their current fail-open behaviour under the
      migrated layout: journal file deleted but its directory present → every
      declared task counts as unlaunched and the hook still blocks; the whole
      worktree-side feature directory absent → exit 0 with no crash. (TS3)
- [ ] AC-5: With two features enumerated at once, both `in_progress` and both
      refillable, the hook reports the first by stable ascending feature-name
      ordering. (TS8)
- [ ] AC-6: The migrated fixture carries every pre-existing test class —
      blocking, failed-task, non-blocking states, consecutive-block cap,
      fail-open, retry-after-failure, recycled task id, round-1 regressions —
      with its intent unchanged and passing, and no test depends on the flat
      layout being enumerated. (SPEC AC6; TS7)
- [ ] AC-7: The Stop path spawns no process and imports only standard-library
      modules: the standard-library-only assertion still passes, and the hook
      source no longer references the repository-top-level probe, the external
      command name it used, or any process-spawning facility. (SPEC AC7; TS9)
- [ ] AC-8: Feature identity is derived exactly once. A probe fixture whose
      worktree-side segment name differs from its `feature-docs` segment name
      blocks, names the worktree-side segment as the feature in the BLOCK line,
      and reads the enumerated file — which fails if any read path is rebuilt
      from an enumeration root plus a feature name. (NFR4)
- [ ] AC-9: `python3 -m unittest discover -s tests` passes with no failures and
      no errors. (SPEC AC8)

## Test Notes

- Every criterion above is covered by subprocess-driven tests in the existing
  style: the hook is invoked as a child process with Stop-hook JSON on stdin,
  and assertions are on exit code and stderr text.
- Write the tests first. The migration order that keeps the red honest: add
  the new real-layout tests against the current hook (they fail because
  nothing is enumerated), migrate the fixture (existing classes go red for the
  same reason), then change the hook until the whole file is green.
- AC-1's second half is an equality assertion between two invocations, not two
  independently written expectations — that is what makes it a statement about
  the ancestor walk rather than about the message format.
- AC-2's times are set explicitly on the fixture files; use "now" and "now
  minus 25 hours" so no assertion sits near the 24-hour boundary. Do not assert
  on the boundary itself.
- AC-3's second case needs a temporary directory with no em-workflow worktrees
  directory above it; be aware that a shared temporary parent from another test
  could accidentally supply one.
- AC-8's probe is a test-only layout. It is not a supported real-world shape;
  it exists because it is the cheapest objective discriminator between "reads
  what it enumerated" and "rebuilds a path".
- Nothing here is TDD-awkward: every criterion is observable through exit code
  and stderr.
