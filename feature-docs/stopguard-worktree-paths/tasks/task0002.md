# Task Plan: task0002 — Matching plugin version bump in both manifests

## Goal

Ship the hook change: raise the em-workflow plugin version by one patch step
in the plugin manifest and in the marketplace entry, to the identical value,
so the installed plugin cache serves the fixed hook instead of the old one.

## Requirements

NFR6

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/.claude-plugin/plugin.json` — version raised one patch step.
- `.claude-plugin/marketplace.json` — the em-workflow entry's version raised to
  the identical value.

## Design

See IMPLEMENTATION.md D5 (why this is a separate task) and the "Release
version parity" row of Shared Components (the contract).

1. Read the version currently held in the plugin manifest.
2. Compute the new version as a patch increment of that value — the major and
   minor parts are unchanged. This change is a bug fix with no interface
   change, so patch is the correct step.
3. Write the new value into the plugin manifest.
4. Write the identical string into the version field of the marketplace entry
   whose source points at the em-workflow plugin directory. There is more than
   one plugin entry in that file; only the em-workflow one changes.
5. Change nothing else in either file — no reformatting, no key reordering, no
   description edit. The resulting diff is two lines.

Both files are JSON and are consumed by the plugin loader, so they must remain
parseable and keep their existing shape exactly.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The plugin manifest's version is the pre-change value with its
      patch component incremented by one, and its major and minor components
      unchanged.
- [ ] AC-2: The marketplace entry for the em-workflow plugin carries a version
      string identical to the plugin manifest's, character for character.
      (SPEC AC9)
- [ ] AC-3: No key other than those two version fields differs from the
      pre-change content of either file — the combined diff is exactly two
      changed lines.
- [ ] AC-4: Both files still parse as valid JSON, and the marketplace file
      still lists every plugin entry it listed before.

## Test Notes

- No automated test is added. The suite has no manifest test today, and SPEC's
  declared change set contains no test file for these manifests; adding one
  would widen the change set beyond what the feature declares.
- This is the one TDD-awkward item in the feature, and the planned handling is
  explicit: verification happens through the release check recorded in
  VERIFICATION.md (parse both files, compare the two version strings, confirm
  the patch step against the pre-change value), not through a new unit test.
- Do not run the version-bump edit through a script or a formatter; a
  formatter would reflow the files and break AC-3.

## Out of Scope

- Any change to `em-workflow/hooks/queue_stop_guard.py` or to
  `tests/test_queue_stop_guard.py` (task0001 owns both).
- Any change to other plugins' entries in the marketplace file.
- Adding a manifest-parity test to the suite.
- Publishing, tagging, or any action outside editing the two files.
