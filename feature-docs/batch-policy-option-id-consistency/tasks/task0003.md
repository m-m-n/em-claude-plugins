## Design

The repository rule is that a change to plugin content is accompanied by a
version bump in both places, to the same value, because the installed-plugin
cache decides freshness from that version. This change modifies plugin
content (reference documents, contracts and agent prompts under the plugin
directory), so the bump applies.

- Baseline: 0.1.41. The new value is the next patch increment; the semantics
  of the change (documentation and test additions, no behaviour removal) make
  patch the right step.
- The two fields must be the same string, not merely both greater than the
  baseline.
- Version comparison in the test is numeric per component, not string
  comparison, so that a two-digit patch component compares correctly.
- No other entry in the marketplace manifest is touched; entries for other
  plugins keep their current versions.

This task owns both files exclusively (IMPLEMENTATION.md D6); no sibling task
lists either of them.

## Test Notes

- Unit: both manifests load, the em-workflow entry is found by name rather
  than by position, the two versions are equal, and the version exceeds the
  baseline.
- Unit (hermetic): the comparison helper against synthetic version pairs,
  including a case where string comparison and numeric comparison disagree
  (for example a two-digit patch component), so the helper is proven rather
  than assumed.
- The existing suite already pins version equality against an older baseline;
  raising the version must keep those assertions green, which the whole-suite
  run confirms.

## Out of Scope

- Any change to plugin content, documentation, reference files or other test
  modules.
- Changing the version of any plugin other than em-workflow.
- Regenerating or editing plugin descriptions or manifest fields other than
  the two version fields.
