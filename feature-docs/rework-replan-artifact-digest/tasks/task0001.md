# Task Plan: task0001 — create-plan action decision: planning-lineage match, site citations and pin tests

## Goal

The create-plan action decision in
`em-workflow/references/contracts/spec-writer-contract.md` also accepts a match

## Design

### D1. The owner statement (spec-writer-contract.md)

The rule lives only in the section "How the orchestrator chooses each
target's action before dispatch". It is an addition for create-plan. The
existing introductory paragraph and the three existing bullets stay as they
are and keep governing create-spec and the design step.

The addition states the following, with the orchestrator as the actor:

1. **Scope.** It applies to the action decision of every
   implementation-planner dispatch of create-plan: the planner dispatch of
   `references/phases/create-plan-phase.md` section 4 (the first pass, every
   re-dispatch, and re-planning after a spec-change transition or a tier
   upgrade), and the final-path correction dispatch and the feature-docs
   correction dispatch of its section 13.
2. **Match.** A target path that exists gets `replace_own` when its current
   digest equals the last `artifacts` entry for that path in
   `phase-state/create-plan.yaml`, or the last `artifacts` entry for that path
   in `phase-state/rework.yaml`. The last entry for the path is the entry for
   that path that comes last in that file's `artifacts` list. Earlier entries
   for the same path, entries for other paths, and other phase-state files do
   not count.
3. **No match.** An existing create-plan target whose current digest matches
   neither of the two entries takes the existing digest-mismatch branch: the
   `create-plan.artifact-overwrite` gate in interactive mode, and the
   `references/batch-policies.yaml` decision in batch mode. No other condition
   gives `replace_own` (a spec-change record or a re-planning authorization
   does not).
4. **Reading rework.yaml.** A rework.yaml record counts only when the file's
   mapping has phase `rework` and a feature equal to the workflow's feature.
   An absent file, an unreadable or malformed file, a mismatched phase or
   feature, or no `artifacts` entry for the path each count as no record from
   rework.yaml. The decision then rests on the create-plan.yaml comparison
   alone.
5. **Legacy values.** A rework.yaml recorded value that differs from the
   file's current digest is compared as `references/artifact-digest.md`
   "Legacy records" states, the same way as a create-plan.yaml recorded value.
   This is a citation: the section names neither `git hash-object` nor the
   steps of that comparison.

Constraints that the surrounding documents and tests put on this section:

- The introductory paragraph keeps citing `references/artifact-digest.md`
  with the section names "Calculation" and "Legacy records" in double quotes.
- Every new sentence about a digest has the orchestrator as its subject. No
  sentence tells a worker to compute, hash, verify or compare a digest; the
  whole contract is checked for such sentences.
- The heading text, the `write_policy` action table and the gate option
  vocabulary table are unchanged, and no new gate id appears.

### D2. The site citations (create-plan-phase.md)

Each of the three places cites the owner by path and section name —
`references/contracts/spec-writer-contract.md`, "How the orchestrator chooses
each target's action before dispatch" — as the rule by which the orchestrator
chooses the action of each `write_policy.targets` entry. None restates any
part of the rule.

- **Section 4.** The citation is a sentence of its own. The existing sentence
  "Before the `Task` dispatch, the orchestrator verifies the planner's
  `write_policy.targets` per ..." and the grant paragraph stay word for word.
- **Section 13, ahead of its subsection.** The citation sits before the
  subsection heading, for example in the **Pre-dispatch.** paragraph. The six
  bold labels keep their order and their pinned phrases, and no new subsection
  is added.
- **The subsection "Feature-docs correction dispatch".** The citation sits in
  the subsection itself. It uses none of section 13's bold labels and carries
  no gate-id-shaped token.
- **All three.** None of them contains `git hash-object`, any restatement
  marker that `tests/test_artifact_digest_docs.py` checks,
  `phase-state/rework.yaml`, the last-entry rule or the gate id. From section
  12 to the end of the document, none of the words that
  `tests/test_feature_docs_entry_develop_docs.py` forbids there appears.

### D3. The pin tests (tests/test_artifact_digest_docs.py)

New test classes are appended after the existing ones, under a banner comment
that names this feature and task. Existing test methods, and the module
constants and helpers they use, keep their behavior. New constants and
helpers may be added.

Slices:

- The owner section: the level-2 heading "How the orchestrator chooses each
  target's action before dispatch" of spec-writer-contract.md.
- Section 4: its level-2 heading "4. Planner dispatch".
- Section 13's head: from the level-2 heading "13. Final-path correction
  dispatch" up to the subsection heading, so that a citation present only in
  the subsection does not satisfy it.
- The subsection: its level-3 heading "Feature-docs correction dispatch".

Assertions, on whitespace-normalized text, check key tokens and phrases,
never whole sentences or line positions:

- TS-1: the owner section names `phase-state/create-plan.yaml`,
  `phase-state/rework.yaml`, the last-entry rule and `replace_own` for
  create-plan, and its scope names re-planning and both section 13
  dispatches.
- TS-2: the owner section routes a create-plan target with no match to
  `create-plan.artifact-overwrite` and `references/batch-policies.yaml`.
- TS-3: the owner section states phase `rework`, the feature match and the
  no-record cases, and cites `references/artifact-digest.md` "Legacy records"
  for rework.yaml values. The owner section does not contain
  `git hash-object`.
- TS-4: each of the three site slices cites the owner path and section name,
  and contains neither `git hash-object`, nor an existing restatement marker,
  nor `phase-state/rework.yaml`. The rework.yaml probe is kept apart from the
  existing restatement-marker list, because that list is also applied to
  `references/rework-task-synthesis.md` section 10, which names
  `phase-state/rework.yaml` by design.

Non-vacuity: every assertion has a forged-text case. A presence matcher fails
on a forged copy that lacks the statement, for example the owner section with
`phase-state/rework.yaml` taken out, or a site slice with its citation taken
out. An absence matcher fires on a forged copy that contains the token.
