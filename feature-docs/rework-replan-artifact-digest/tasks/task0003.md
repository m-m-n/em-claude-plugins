## Design

### D1. The write check in `## Final-path correction`

Today the **Path strings only.** bullet ends with this write check:
"Before writing anything, determine every file this dispatch will actually
edit and check each one's `write_policy.targets` action; if any file it must
edit carries `preserve`, write nothing and return `status: blocked` naming
that path."

- The **Path strings only.** bullet keeps its first two sentences word for
  word ("Replace the old path, and the bare old file name, in the target's
  task plan, IMPLEMENTATION.md and VERIFICATION.md. Change nothing else.") and
  loses the write check.
- A new bullet labelled **Write check first.** is placed directly after the
  **Other plans.** bullet and directly before the **Shared bare name.**
  bullet. Its text after the label is the write-check sentence above, word for
  word. The label is the one the same check carries in
  `## Feature-docs correction`.
- After the change, no sentence and no bullet of the section placed before
  the **Other plans.** bullet contains `write_policy.targets`.
- The section's intro paragraph, the **Other plans.** bullet and every other
  bullet, with their labels and order, are unchanged. No other section of the
  file changes, `## Feature-docs correction` included.

### D2. The inherited version-bump test

`tests/test_review_perspective_model_effort_version_bump.py` is replaced, byte
for byte, by the content of the same path on the `main` branch at the time the
task is implemented (`git show main:tests/test_review_perspective_model_effort_version_bump.py`).
Nothing else is written to it. Because its content equals the `main` branch's,
merging the feature into `main` makes no conflicting change to this file.

The `main` branch's copy keeps its own standard-library-only check. If that
copy reads a file that does not exist on the integration branch, or its tests
do not pass on the integration branch, the implementer does not adapt it and
reports the deviation instead.

### D3. The pin tests (`tests/test_artifact_digest_docs.py`)

New test methods are appended after the existing ones, under a banner comment
that names this feature and task0003. Existing test methods, and the module
constants and helpers they use, keep their behavior. The slice is
`## Final-path correction` of `em-workflow/agents/implementation-planner.md`,
from its heading to the next level-2 heading. Bullets are the section's
top-level `- ` items, and matching is on whitespace-normalized text so the
document's hard line wrapping does not matter.

- Presence: the section holds a bullet labelled **Write check first.** whose
  text states "Before writing anything", "will actually edit",
  `write_policy.targets`, `preserve`, "write nothing" and `status: blocked`
  naming that path.
- Order: that bullet comes directly after the **Other plans.** bullet.
- Absence: the **Path strings only.** bullet holds neither
  `write_policy.targets` nor `preserve`, and no text of the section before the
  **Other plans.** bullet holds `write_policy.targets`.
- Forged-text cases: a section without the **Write check first.** bullet
  fails the presence matcher; a section where that bullet stands before
  **Other plans.** fails the order matcher; a **Path strings only.** bullet
  that holds `write_policy.targets` makes the absence matcher fire.
