## Design

### 1. Complete the stop enumeration in 「バッチ終端行」

The subsection lists 停止条件 2 / 3 / 4 / 6, フェーズ内のゲート中断, Step C
内の中断 and implement / verify のフェーズ固有終端停止. Two terminating stops
the contract will cover are missing:

- **Step A の feature 解決失敗** — the fail-closed feature-identifier gate, and
  a batch run started with neither a path argument nor a task description
  (both already defined in this same document's Step A).
- **`commit-docs.sh` の 2 回目の exit 4 によるフェーズ中断** — defined in
  `references/phase-state.md` and `references/implement-phase.md`.

Both are named in this document's own Japanese prose. The subsection keeps
naming stops the way it already does; it never names a reason code, a
stop-point key, the prefix, the four field names or the sentinel — the SSOT
partition (IMPLEMENTATION.md Conventions, D6) is unchanged by this task.

### 2. Generalize the no-line rule

Today the subsection excludes 停止条件 5 only, though implement's launch turn
(ends right after launching) and wake turn (ends after refill) also end while
the run continues — both specified in `references/implement-phase.md`. Restate
the exclusion as the general rule:

- Precondition: the turn is ending and the run has NOT reached a terminal
  state (the two terminal states the contract document defines — named as a
  concept, never as literals).
- Postcondition: no terminal line is emitted.
- 停止条件 5 and implement's launch / wake turns are named as instances of the
  rule, not as its definition.

The strings 「停止条件 5」 and 「終端行を出力しない」 stay present, so the
existing wait-turn guarantee remains asserted.

### 3. Read the SSOT before emitting

The prefix, the field grammar and the value sets live in exactly one file, and
no document tells the emitting orchestrator to open it. Both pointer documents
gain that instruction:

- SKILL.md 「バッチ終端行」: state that immediately before emitting the line the
  orchestrator Reads `${CLAUDE_PLUGIN_ROOT}/references/batch-terminal-line.md`
  and uses the prefix, field grammar and value sets defined there as-is. The
  `${CLAUDE_PLUGIN_ROOT}`-prefixed form is this skill's existing convention for
  every document it actually makes the orchestrator read.
- `batch-mode.md` `## Terminal line`: the same instruction in one sentence.

Neither sentence adds a literal, so both documents stay inside the SSOT
partition and inside the contract test's absence checks.

### 4. Cross-task safety (independent worktrees)

`tests/test_batch_stop_contract.py` (task0004's file) asserts that
`batch-mode.md` restates no reason code. The sentence added here contains no
code name, so it passes against the nine-code list in this task's worktree AND
against the eleven-code list after task0004 merges. Symmetrically, the
reason-code tuple in this task's own module is extended to eleven members: it
is used only for absence checks, so it is green whether or not task0004 has
merged.
