## Goal

Make the terminal-line contract document TOTAL (every terminating stop point
has a row) and DETERMINISTIC (any single stop resolves to exactly one reason
code), and specify how `detail` is normalized, so that an orchestrator
reaching any terminating stop can construct the line without inventing a value
and without choosing between two applicable codes.

## Design

### 1. Close the reason-code set over the two uncovered stops

`## Field values` already lists Step A's feature-resolution failure among the
stops the `no-step` sentinel applies to, but no reason code and no coverage row
exists for it; the phase abort taken when a `commit-docs.sh` call returns exit
4 a second time (`references/phase-state.md`, "Phase-state exit-4 recovery"
step 7, and `references/implement-phase.md`'s wake-phase reconcile) has the
same gap. Two codes and two coverage rows close it. The names are fixed by
IMPLEMENTATION.md Shared Components as amended in this rework round:

| New stop-point key | New reason code | Source document | `step` value at that stop |
|---|---|---|---|
| `step-a-abort` | `feature_resolution_aborted` | `skills/develop/SKILL.md` | the `no-step` sentinel |
| `docs-commit-conflict` | `docs_commit_conflict_aborted` | `references/phase-state.md` | the id of the step whose phase aborted |

`step-a-abort` covers both Step A abort paths that SKILL.md already defines:
the fail-closed feature-identifier gate, and the batch run started with neither
a path argument nor a task description. Consequently the closed sets become
ELEVEN codes and ELEVEN stop-point keys, and every prose count in the document
("nine") moves with them.

### 2. Precedence rule (determinism)

`implement-second-failure` and `verify-rework-cap` both leave a step's status
`failed`, so develop's stop condition 3 also matches them; `docs-commit-conflict`
can overlap the same way. A rule stated immediately after the coverage table
removes the ambiguity:

- Precondition: a stop matches more than one row of the table.
- Postcondition: the phase-specific row wins over the generic
  `stop-condition-N` rows, so exactly one code applies.
- The `stop-condition-3` row's meaning is correspondingly narrowed to
  `failed` / `needs_update` states that NO phase-specific row covers.

The rule names the overlapping keys explicitly, so a test can pin its presence
rather than search prose for a paraphrase.

### 3. `detail` normalization

`## Line format` guarantees "always exactly one physical line", but `detail`'s
suppliers (implementer notes, a gate's `blocking_reason`, a YAML parser
message) can carry newlines. The normalization rule belongs in `## Line
format`, next to the one-physical-line guarantee:

- Replace every CR, LF and TAB in the value with a single space.
- Collapse runs of spaces to one, then trim.
- If the normalized value is empty, substitute a fixed non-empty placeholder,
  so `## Field values`'s "non-empty" definition still holds.

### 4. Generalize the no-line rule

`## No line on a wait turn` currently names develop's stop condition 5 only,
though implement's launch turn and wake turn also end mid-run. Restate it as a
general rule — a turn that has NOT reached either of the contract's two
terminal states emits no line — keeping stop condition 5 as the named example
and adding the implement launch/wake turns (`references/implement-phase.md`) as
further instances. The heading text itself is unchanged: the seven level-2
headings and their order are a Shared Component pinned by the contract test.

### 5. Say only what the Source column can back

The table's third column claims the named document "owns (defines) the stop
point", but the stop-point keys exist in no document. Two ways out; this task
takes the LOW-RISK one, because writing eleven keys as anchors into four other
documents (`skills/develop/SKILL.md`, `references/question-resolution.md`,
`references/batch-policies.yaml`, `references/phase-state.md`) risks tripping
pre-existing test modules and violates NFR2's no-existing-module-change budget:

- Weaken the claim to what is true — the third column NAMES the document where
  the stop point is specified — and drop the parenthetical "(defines)".
- Make the claim machine-checked: every Source cell is a plugin-relative path
  that resolves to an existing file under `em-workflow/`, so a renamed or
  deleted owner document turns the suite red instead of leaving a dangling
  reference.
