## Design

### Current state (what is being corrected)

`## Field values` defines `resume_conditions` as NOT put through `detail`'s
normalization: the newlines, indentation and trailing spaces it carries
survive as `## Escaping`'s escapes rather than being collapsed. The first
bullet under the OWN-rules label contradicts that by rejecting a decoded
line terminator in `resume_conditions` as well as in `detail`. The block's
introductory sentence adds a third claim — that none of the rules can fire
while `## Escaping` is honoured — which the bullets themselves contradict,
since they reject an escaped control character exactly like a bare one.

### Document change — the introductory sentence (FR4)

The sentence beginning "Each of the four cannot fire while ..." is replaced.
The replacement:

1. Keeps the framing that the block states em-workflow's own hardening
   obligations, stated as defense in depth.
2. Keeps the existing statement that these are NOT carried-over consumer
   behaviour and that this repository can verify nothing about how the
   external consumer enforces them.
3. Drops the blanket "cannot fire" claim entirely (assumption A8) — each
   rule's own firing condition belongs in that rule's text.
4. Carries no count word for the number of rules, so the sentence does not
   go stale when a rule is added or split.

### Document change — the per-field rules (FR1, FR2, FR3)

The single shared bullet becomes two bullets, in this order:

- **`detail`** — rejects a line terminator or a terminal-control code point
  after decoding, in the same form as the carried-over numbered constraints
  for `branch` and `pr_url`. Unchanged in substance (assumption A2). Its
  stated reason: `## Field values` already replaces every CR, LF and TAB in
  `detail` with a space before escaping, so a surviving one means the
  normalization was skipped, which is why rejection is correct.
- **`resume_conditions`** — rejects only terminal-control code points other
  than CR (U+000D), LF (U+000A) and TAB (U+0009) after decoding, and states
  explicitly that a decoded CR, LF or TAB inside `resume_conditions` is NOT
  a violation, because `## Field values` defines those as surviving as
  `## Escaping`'s escapes rather than being collapsed.

The "`## Escaping` does not help here either" clause — an escaped control
character inside the value is rejected exactly like a bare one — is retained
and applies to whatever each bullet still rejects.

The exemption set is exactly CR, LF and TAB (assumption A1). Every other
code point the old rule covered stays rejected, including U+2028, U+2029 and
the C0/C1 terminal-control ranges; the wording must not read as a general
relaxation.

### Pinned content the document change must not disturb (FR5, FR6, NFR5)

- `## Result format` and `## Escaping` stay byte-identical. They are pinned
  by an existing regression test that compares each section against a
  captured literal; that test must pass unmodified.
- The carried-over half of `## Consumer constraints` keeps exactly five
  numbered items, unchanged. All new wording is bullets under the OWN-rules
  label — never renumbered into that list.
- The `## Field values` `resume_conditions` bullet is preferably left
  untouched. If it is touched at all, these six literals must survive
  verbatim: "NOT put through `detail`'s normalization", "survive as",
  "non-whitespace whenever `state` is `stopped`", "never empty and never
  whitespace-only", "empty for every other `state`", and "carried in full
  inside `resume_conditions`".
- After the change, no statement in `## Field values`, `## Escaping`,
  `## Result format` or `## Consumer constraints` contradicts another for
  any of the eight values.

### Test change — the existing own-hardening matcher (FR7)

The existing matcher `_assert_own_hardening_rules_stated` keeps every
guarantee it has today and gains none of the new positive assertions:

- It stays anchored on the OWN-rules label via the existing splitter, so it
  cannot be satisfied by the carried-over numbered constraints alone

- It still asserts all three shape defenses: the exact eight keys in order
  with a missing/extra/reordered key rejected; the duplicate-key rule with
  its last-wins and exactly-eight-physical-lines wording; and the closed
  documented-domain check for `state`, `step` and `reason`.
- It still asserts the "carried-over consumer behaviour" labelling.
- Its per-field expectations are updated to the new wording: both field
  names still appear, "line terminator" and "terminal-control" still appear
  (the `detail` bullet supplies them), and the "does not help here either"
  clause still appears.

### Test change — the new exemption matcher (FR9, TS1-TS3)

Its negative proof uses the pre-change bullet verbatim ("`detail` and
