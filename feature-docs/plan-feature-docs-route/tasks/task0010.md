# Task Plan: task0010 — Step A.6 restoration written once, in the last correction's Write

## Goal

When one Step A.6 evaluation runs both the feature-docs correction and the
final-path correction, every restoration item is written together in the last
correction's Write (FR9's one Write). A correction that is not last writes its
patch only, so its targets stay failed tasks and an interruption or an
unresolved final-path judgment no longer leaves the feature unresumable.

### Defect being fixed

Today the split writes each correction's task-level items (status and
`routeback_failed_journal_line`) in that correction's own Write. When
`final_path_remaining` is true, the feature-docs correction's Write sets its
targets to `pending` while `implement` stays `failed`. The failed-task
selection (`scripts/report-name-entry.py`, status `failed` or last journal
event `failed`) then drops a target that has no `failed` journal event, so an
interruption, or a final-path correction that ends without a validated patch,
leaves both judgments at `none` on the next start and Step B's stop condition
3 fires on every start.

### Revised text of Step A.6

1. List item 9 keeps its pinned sentence (the artifact commit first, then the
   patch and the restoration in one Write and one commit). It adds that the
   restoration a Write carries is the one the restoration split assigns to
   it, so the Write of a correction that is not the last carries the patch
   only.
2. The `**復元の分割**` paragraph and its list state:
   - the Write of a correction that is not the last of the evaluation writes
     that correction's patch only; the targets' tasks.{T}.status stays failed
     and no routeback_failed_journal_line is written, so the targets stay
     failed tasks for the next judgment whether or not they have a failed
     journal event;
   - the task-level items for the targets of every correction of the
     evaluation (violations of the final-path correction, targets of the
     feature-docs correction) and the step-level items (implement and
     failed_kind) are written together in the Write of the last correction of
     the evaluation, and only when no judgment is unresolved;
   - the definition of an unresolved judgment stays (blocked, a non-zero exit,
     ended without a validated patch); when one exists, no restoration item
     is written, task-level or step-level;
   - the final_path_remaining rule stays: the feature-docs correction is last
     when it is false; when it is true the final-path judgment follows on the
     re-captured tip and, on dispatch, its correction is last;
   - when the final-path judgment on the re-captured tip returns none, the
     feature-docs targets' task-level items and the step-level items are
     written alone, together, in one Write and one commit.
3. The interruption paragraph is rewritten so that every sentence holds: after
   an interruption between corrections, or after the final-path correction
   ends unresolved, every target still has status failed and implement is
   still failed; on the next start the feature-docs judgment returns none
   (no feature-docs path is left) and the evaluation proceeds to the
   final-path judgment, which still selects those tasks as failed tasks. The
   restoration of that evaluation is written for the targets of its own
   corrections. The sentence about section 13's Apply paragraph stays true
   and says why: the final-path correction is always the last correction of
   its evaluation, so its Write carries the patch and the restoration
   together.
4. Nothing else in Step A.6 changes: the order of the two scripts, the
   dispatch item, the unresolved-judgment item and the untouched-items
   paragraph keep their text.
