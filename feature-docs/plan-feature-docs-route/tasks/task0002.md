## Design

owner of D3, D4 and D8; it cites spec-writer-contract.md for the action
itself and workflow-patch.md for the patch field.

   `## Scope & concurrency assumption` and before `## Scenario ID form`. It
   states:
   - when the route applies;
   - the stage-1 request result (shape and admission);
   - the orchestrator's grant: one `amend_other_feature` target per in-scope
     path; the orchestrator sets `expect_digest` to the digest at dispatch;
     re-dispatch under a new `request_id`. How the orchestrator runs this is

     grants);
   - that validation, the `workflow.yaml` update and the commit stay with
     the orchestrator, before `create-plan` completes;
   - the scope rule (D4) as the single owner;
   - `blocked` naming the path for an out-of-scope need or an ungranted
     stage-2 need (A2);
   - the three validator codes;
   - that the fix record and the declared change set are cited (phase-state
     and create-plan-phase.md section 12), not restated;
   - untrusted content and doc redaction, citing the worker envelope's
     sections.
2. **New H3 `### feature_docs_correction (dispatch-resolved value)`** inside
   `## Additional input: planning_inputs`, after the `path_correction`
   subsection and before `## Question packet bundling rule`. It mirrors the
   `path_correction` subsection's bullets for D8:
   - the shape;

     correction`; empty `payload.task_index`);
   - process (cited from `agents/implementation-planner.md`,
     `## Feature-docs correction`).
   The yaml block of planning inputs gains one commented line for the
   value.

   targets appear only after a request, citing `## Other-feature documents`.
