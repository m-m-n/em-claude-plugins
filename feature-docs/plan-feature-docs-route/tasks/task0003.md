# Task Plan: task0003 — The amend_other_feature write_policy action

## Goal

`amend_other_feature` becomes the seventh `write_policy` action: defined in
spec-writer-contract.md, counted as a self-write only when it modifies a
file, and accepted by `self-write-digest.py`. Every "six actions" wording in
the action-model documents becomes count-free.

## Requirements

FR4, FR6, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_amend_other_feature_action.py` — document and script tests for this task's criteria, with negative proofs

### Files to Modify
- `em-workflow/references/contracts/spec-writer-contract.md` — action table heading, new row, target example comment
- `em-workflow/references/contracts/worker-envelope.md` — self-write table row, count-free wording, heading citation
- `em-workflow/references/contracts/designer-contract.md` — count-free wording
- `em-workflow/references/contracts/rework-planner-contract.md` — count-free wording
- `em-workflow/agents/spec-writer.md` — count-free wording
- `em-workflow/references/artifact-digest.md` — heading citations
- `em-workflow/scripts/self-write-digest.py` — accept the action and its admitted change kind

- `tests/test_self_write_digest_docs.py` — refresh the matrix and the citation pins
- `tests/test_self_write_digest.py` — extend the matrix cases

## Design

Work against IMPLEMENTATION.md D2.

1. **spec-writer-contract.md**
   - The heading "The six `write_policy` actions" becomes "The `write_policy`
     actions".
   - The table gains a row for `amend_other_feature`:
     - `expect_digest` is required: the digest the orchestrator recorded at
       dispatch;
     - the worker may modify the existing file's content, and must not
       create, delete or change its file kind;
     - it is valid only on implementation-planner dispatches of create-plan;
     - its scope is cited from `references/contracts/planner-contract.md`,
       `## Other-feature documents`.
   - One sentence states that the route reuses neither `replace_own`,
     `replace_authorized` nor the artifact-overwrite batch policy.
   - The target example comment lists all seven actions.
   - `### Who verifies \`expect_digest\`` is unchanged; its sentences are
     pinned by `check-plugin-invariants.py`.
2. **worker-envelope.md**
   - The self-write membership table gains the row "target
     `amend_other_feature`": `created` not a member, `modified` member,
     `deleted` not a member.
   - The heading citation is updated.
   - The two "six actions" mentions become count-free.
   - The document still never contains the string `expect_digest`.
3. **designer-contract.md, rework-planner-contract.md, agents/spec-writer.md,
   artifact-digest.md**: each "six actions" mention, and each citation of the
   old heading, becomes count-free or names the new heading. Nothing else in
   them changes.
4. **self-write-digest.py**
   - The action vocabulary gains `amend_other_feature`.
   - Its admitted change kinds are `modified` only.
   - An unknown action is still rejected as an input error.
   - The identification order is unchanged: `regenerate` is still decided
     last.
5. **Pinned tests**
   - The six-action sets, the count assertion and the heading literal in
     `tests/test_threat_model_planner_contract.py` are refreshed to the
     seven-action set and the new heading.
   - The matrix and the citation literals in
     `tests/test_self_write_digest_docs.py` are refreshed.
   - The matrix cases in `tests/test_self_write_digest.py` gain the new
     target's three change kinds.
   - Each refresh carries a comment naming this task. Every other assertion
     stays.
   - `tests/test_worker_contracts_create_spec.py` derives its six names from a
     historical design document and still passes unchanged.

planner-contract.md's own "six actions" wording is outside this task's
files, so this task's count-free check covers only the files listed above.
