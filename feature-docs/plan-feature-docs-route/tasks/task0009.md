# Task Plan: task0009 — create-plan grants, fix recording and the declared change set

## Goal

create-plan-phase.md states how the orchestrator grants other-feature
documents and how it checks and records the declared fixes. Section 12 reads
those fixes into the declared change set, and phase-state.md defines the
`other_feature_doc_fixes` record.

FR3, FR4, FR5, FR6, FR7, NFR1, NFR3, NFR4

## Design

Work against IMPLEMENTATION.md D2, D3, D4 and D5. The scope rule and the
result shapes are cited from planner-contract.md
`## Other-feature documents`; they are not restated.

1. **Section 4, grant rule.** A paragraph after the existing dispatch
   inputs:
   - when the planner returns the request result and it validates, the
     orchestrator checks each requested path against the cited scope rule
     and confirms that it exists as a regular file in the integration
     worktree;
   - for each path it adds one `amend_other_feature` target whose
     `expect_digest` is the digest the orchestrator computes for the path
     now, verified before dispatch per `references/artifact-digest.md`;
   - it re-dispatches once, under a new `request_id`, with the same planning
     inputs;
   - the stage-2 dispatch's `digest_inputs` include each granted path, and
     `dispatch_digest_inputs` records them;
   - a request result that fails validation is handled like any failed
     planner result, and nothing is granted;
   - grants live only in that dispatch's `write_policy`; an interruption
     resumes by re-running stage 1;
   - no question is asked and no gate is added (NFR1).
2. **Section 7.** The completed output also covers the stage-1 request
   result and the stage-2 `payload.other_feature_doc_fixes`, cited from
   planner-contract.md.
3. **Section 8.** A new paragraph; the existing return-time order paragraph
   and its sentences stay byte-identical.
   - In scope verification (layer 4), every observed `modified` path under
     an `amend_other_feature` target must be listed in `written_artifacts`
     and declared in `other_feature_doc_fixes`; otherwise the result fails.
   - The recording phase-state write appends one `other_feature_doc_fixes`
     entry per declared fix (`path`, `change`, `reason`, and `produced_by`
     set to the run's `request_id`). That is the same write that records
     layer 5 and `self_write_set`.
4. **Section 9.** The validator-implemented list gains three bullets:
   - `plan-task-feature-docs`, citing `skills/plan-writing/SKILL.md`,
     `## Feature-docs Files`;
   - the three other-feature document codes;
   - a patch carrying `tasks_patch.feature_docs_removals` meets
     `references/workflow-patch.md`'s `## Feature-docs correction` under
     `--dry-run-apply` with `--journal`.
   The "not implemented" block and the canonical invocation block stay
   byte-identical (pinned by digest).
5. **Section 12.**
   - Inputs become the union of four sources: the existing three, plus every
     `path` of the `other_feature_doc_fixes` record in
     `phase-state/create-plan.yaml`, cited from `references/phase-state.md`.
   - Retention gains a sentence: that record is append-only and survives
     phase restarts and re-planning, so a fix stays in the derived set.
   - Timing gains "or a fix is recorded" without dropping the three pinned
     triggers.
   - Every pinned phrase of section 12 stays, and none of the forbidden words
     appears.
6. **phase-state.md.**
   - The schema example gains `other_feature_doc_fixes` with one entry.
   - The top-level field table gains a row: create-plan only; append-only
     list; fields `path`, `change`, `reason`, `produced_by`; written by the
     orchestrator in the recording write; never rewritten or cleared,
     `generation` increments included; read by create-plan-phase.md
     section 12.
   - An entry written before the field existed is still valid.
