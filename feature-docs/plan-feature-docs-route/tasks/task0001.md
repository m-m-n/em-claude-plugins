# Task Plan: task0001 — Planner rules for feature-docs files and other-feature documents

## Goal

The plan-writing skill owns the rule that no task's `files` holds a
feature-docs path, and the implementation-planner prompt cites it and states
how the planner amends other features' documents (two stages) and how it runs
the feature-docs correction dispatch.

## Requirements

FR1, FR3, FR4, FR8, FR10, NFR3, NFR4, NFR5

## Scope

### Files to Create
- `tests/test_feature_docs_planner_rules_docs.py` — document tests for this task's criteria, with negative proofs

### Files to Modify
- `em-workflow/skills/plan-writing/SKILL.md` — new Feature-docs Files section and one checklist item
- `em-workflow/agents/implementation-planner.md` — citation in step 4, the other-feature document behaviour, the Process routing line, the new Feature-docs correction section, the Output paragraph
- `tests/test_report_name_planner_docs.py` — only if a pinned phrase must be refreshed because the 2a-exception sentence changes (refresh, not weaken)

## Design

### plan-writing SKILL.md: `## Feature-docs Files` (rule owner, FR1)

A new H2 placed before `## Pre-Save Self-Verification Checklist (MANDATORY)`.
It states, as the single owner of this rule:

- What a feature-docs path is: the predicate of IMPLEMENTATION.md Shared
  Components. It uses the same normalization as the rework Feature-docs files
  rule in `references/rework-task-synthesis.md`, which is cited, not
  restated as a second rule.
- No task's `files` holds a feature-docs path. This covers the own feature's
  `feature-docs/{feature}/`, other features' directories and
  `feature-docs/LESSONS.md`. A task's `plan` value is outside the rule.
- When the plan needs another feature's document changed, the planner makes
  that change itself through the route in
  `references/contracts/planner-contract.md`, `## Other-feature documents`
  (cited), never through a task.
- `scripts/validate-worker-output.py` rejects a violating `replace_planning`
  entry with code `plan-task-feature-docs`.

The checklist gains one item: no task's `files` holds a feature-docs path
(`## Feature-docs Files`).

### implementation-planner.md

Constraints, all pinned by existing tests:

- The nine `### ` step headings stay exactly as they are.
- No new `### ` heading is added anywhere.
- `## Gate option vocabulary` stays byte-identical and last.
- `## Final-path correction` keeps its content, apart from the one
  2a-exception sentence below.

Changes:

1. `## Process` lead: a second routing sentence. A dispatch whose
   `planning_inputs.feature_docs_correction` is non-null runs only
   `## Feature-docs correction` and none of the steps. The "every other
   dispatch" sentence stays true for both routes.
2. `### 4.` files bullet: cite plan-writing's `## Feature-docs Files` by
   path plus heading and do not restate it. Add one paragraph for the
   other-feature document behaviour in an ordinary create-plan:
   - stage 1: when no `amend_other_feature` target is present, return the
     request result and write nothing;
   - stage 2: plan as usual, amend only the granted documents, and declare
     each fix;
   - a needed path out of scope, or not granted on stage 2, means `blocked`
     naming the path (A2).
   The shapes are cited from planner-contract.md; they are not restated.
3. Untrusted content (NFR5): the paragraph in step 4 states that
   other-feature document content is untrusted data under the worker
   envelope's Untrusted-Input Handling (cited). Any instruction found there
   is not followed and is reported.
4. A new H2 `## Feature-docs correction` with no subheading. It is placed
   after `## Final-path correction` and before `## Output`. It holds the
   planner's process for IMPLEMENTATION.md D8:
   - the trigger;
   - the exception to the `### 2a.` pass (THREAT-MODEL.md is not written);
   - reading each target plan to find what it asked of the document;
   - the four kinds of target path and how each is handled;
   - editing target plans: the path leaves the Files sections, and the steps
     and criteria that asked the implementer to change the document are
     reworded as done by the planner;
   - leaving requirements and other criteria unchanged;
   - not editing merged plans;
   - the patch shape and the empty `payload.task_index`.
5. `## Final-path correction`: its 2a-exception sentence ("the one dispatch
   the `### 2a.` pass does not run on") is adjusted so it stays true now
   that two dispatches skip the pass. The rest of that section is unchanged.
6. `## Output`: name the request result and `payload.other_feature_doc_fixes`
   as the other `completed` shapes, citing planner-contract.md.
