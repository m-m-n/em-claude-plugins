# Task Plan: task0005 — Validator checks for other-feature document requests, grants and fixes

## Goal

`validate-worker-output.py` mechanically enforces the other-feature document
route:

- the scope rule on every requested, granted and declared path;
- the `amend_other_feature` action only where it is valid;
- the stage-1 request result's shape and admission;
- the equality of declared fixes with the written grants;
- the shape of the `other_feature_doc_fixes` phase-state record.

## Requirements

FR3, FR4, FR5, FR6, FR7, NFR2, NFR3

## Scope

### Files to Create
- `tests/test_other_feature_docs_validator.py` — tests for this task's criteria

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — the action vocabulary, the scope predicate, the request-result and fix checks, the phase-state record shape
- `tests/test_gate_option_vocabulary.py` — refresh the validator byte pin with a comment naming this task

## Design

Work against IMPLEMENTATION.md D2, D3, D4 and D5.

1. **Scope predicate.** One function implements D4. It takes the path and
   the own feature name, uses the existing safe-relative check and
   `path_segments`, and returns in-scope or out-of-scope. It never raises.
   The own feature name is the one the validator already has for the
   dispatch (the envelope's or the workflow's `feature`). When neither is
   available, the second-segment condition is judged against no feature, so
   only the other conditions apply.
2. **Action admission.**
   - `amend_other_feature` joins the validator's write_policy action
     vocabulary.
   - A target with this action is valid only when the worker is
     implementation-planner and the phase is create-plan, when
     `expect_digest` is non-null, and when its path is in scope. A breach is
     `other-feature-doc-scope`.
   - Other actions are checked as today.
3. **Request result (stage 1).** The current rule says a completed
   implementation-planner result needs `workflow_patch` and
   `payload.task_index`. It gains one alternative: the request result shape
   of D3. That result is admitted only when the envelope has no
   `amend_other_feature` target, and each requested path must be in scope.
   - Shape errors and admission errors are `other-feature-doc-request`.
   - Scope errors are `other-feature-doc-scope`.
   - A payload carrying both `other_feature_doc_requests` and `task_index`
     is a request error.
4. **Fix declaration (stage 2).**
   - With `amend_other_feature` targets present, the set of
     `payload.other_feature_doc_fixes` paths must equal the set of those
     target paths listed in `written_artifacts`.
   - Each fix needs non-empty `path`, `change` and `reason`.
   - A fix on a dispatch without such targets, a fix for a path that is not a
     target, a written target with no fix, and a duplicate path are each
     `other-feature-doc-fix`.
   - The coverage of `written_artifacts` by targets and allowed roots stays
     as today, so a written grant passes that check.
5. **Phase-state record.** When the phase-state validation reads a
   create-plan phase-state with `other_feature_doc_fixes`, the value must be
   a list of mappings with non-empty string `path`, `change`, `reason` and
   `produced_by`, and each `path` must pass the safe-relative check. A breach
   is `other-feature-doc-fix`. The key's absence is valid, and unknown keys
   stay tolerated as today.
6. **Malformed input.** Every check above reports and skips; none raises.
7. **Byte pin.** Refresh `VALIDATE_WORKER_OUTPUT_SHA256` per the Conventions.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-1): The scope predicate accepts `feature-docs/call-end-history/THREAT-MODEL.md` and `feature-docs/other/sub/NOTE.md` for feature `self`. It rejects each of:
  - `feature-docs/self/SPEC.md`;
  - `feature-docs/LESSONS.md`;
  - `feature-docs/other/workflow.yaml`;
  - `feature-docs/other/phase-state/x.md`;
  - `feature-docs/other/tasks/task0001.md`;
  - `feature-docs/other/design/mockups/a.md`;
  - `feature-docs/other/notes.txt`;
  - an absolute path, a path with `..`, a NUL path and a non-string.
  `./feature-docs/other/A.md` and `feature-docs\other\A.md` are judged on their normalized segments. Each rejected path in a request, a fix or a target yields one `other-feature-doc-scope` error naming it.
- [ ] AC-2 (TM-1): An `amend_other_feature` target is accepted on an implementation-planner create-plan dispatch with an in-scope path and a non-null `expect_digest`. The same target yields `other-feature-doc-scope` for another worker, another phase, or a null `expect_digest`. An unknown action is still rejected as before.
- [ ] AC-3: A request result (completed, empty `written_artifacts`, null `workflow_patch`, non-empty `other_feature_doc_requests` with `path` and `reason`) passes on a dispatch without grants. It yields `other-feature-doc-request` when grants exist, when `task_index` is also present, or when an item lacks `reason` or repeats a path.
- [ ] AC-4 (TM-2): With grants for A and B, the fix check behaves as follows:
  - a result writing A and declaring a fix for A passes;
  - writing A without a fix fails;
  - declaring B without writing it fails;
  - declaring a non-granted path fails;
  - declaring fixes on a dispatch without grants fails.
  Each failure is `other-feature-doc-fix`.
- [ ] AC-5 (TM-2): A create-plan phase-state with a well-formed `other_feature_doc_fixes` list passes, and one without the key passes. A non-list value, a non-mapping item, and an item missing `produced_by` each yield `other-feature-doc-fix`.
- [ ] AC-6 (TS-9, part): Non-list payload values, non-mapping items and non-string fields in requests, fixes, targets and the phase-state record are reported as errors, and no check raises.
- [ ] AC-7: `python3 -m unittest discover -s tests` passes, and the refreshed byte pin carries a comment naming this task.
