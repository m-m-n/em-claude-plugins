# Task Plan: task0004 — Validator rejects feature-docs paths in replace_planning entries

## Goal

`validate-worker-output.py` rejects every feature-docs path in the `files` of
a `replace_planning` patch's `tasks_patch.entries` with the new code
`plan-task-feature-docs`, while the append rule and carried tasks behave as
before.

## Requirements

FR2, NFR2, NFR3

## Scope

### Files to Create
- `tests/test_plan_task_feature_docs_validator.py` — tests for TS-1 to TS-4 and the malformed cases of this check

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — the new check in the task-entry validation for the replace_all mode
- `tests/test_rework_docs_only_validator_rules.py` — invert the expectation of the replace_planning test
- `tests/test_gate_option_vocabulary.py` — refresh the validator byte pin with a comment naming this task

## Design

Work against IMPLEMENTATION.md D1 and the feature-docs path predicate in
Shared Components.

- **Where.** The task-entry validation already receives the mode. For mode
  `replace_all`, each `files` element that is a string and a feature-docs
  path yields one `plan-task-feature-docs` error. The message contains the
  task id and the path as given (its repr), and says that a planned task's
  files must not reach `feature-docs/**`, citing
  `skills/plan-writing/SKILL.md`, `## Feature-docs Files`.
- **Unchanged.** The append branch, its code `rework-task-feature-docs` and
  its message are unchanged. The comment saying replace_planning entries are
  never checked is corrected.
- **Not checked.** Carried tasks never pass through entry validation, so
  they are not checked. This holds with and without `--dry-run-apply`.
- **Malformed values.** A non-list `files` and a non-string element are
  already reported by the existing structural codes. The new check skips
  them and never raises.
- **Tests.**
  - The replace_planning test in
    `tests/test_rework_docs_only_validator_rules.py` keeps asserting through
    the same two calls, but expects the new code once. Its name may change to
    state the new expectation.
  - The look-alike cases of that file stay as they are.
- **Byte pin.** Refresh `VALIDATE_WORKER_OUTPUT_SHA256` per the Conventions.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS-1): A replace_planning patch whose entry `files` holds `feature-docs/call-end-history/THREAT-MODEL.md` yields exactly one `plan-task-feature-docs` error, and its message contains the task id and that path.
- [ ] AC-2 (TS-2): `./feature-docs/x`, `feature-docs\x\y.md` and `feature-docs//x` each yield one `plan-task-feature-docs` error, and `feature-docs-archive/x` and `src/feature-docs/x` yield none. An entry with two feature-docs paths yields two errors.
- [ ] AC-3 (TS-3): For an append_rework patch, the codes and messages for a feature-docs path are the same as before this change (`rework-task-feature-docs` only), and `plan-task-feature-docs` never appears.
- [ ] AC-4 (TS-4): A re-planning patch whose `carried_task_ids` names a task with a feature-docs path in `files` gets no `plan-task-feature-docs` error, with and without `--dry-run-apply` against a workflow holding that task.
- [ ] AC-5: The replace_planning test in `tests/test_rework_docs_only_validator_rules.py` now expects `plan-task-feature-docs`, and every other test in that file is unchanged.
- [ ] AC-6 (TS-9, part): An entry whose `files` is not a list, or holds a non-string element next to a feature-docs path, is reported through errors and never raises. The feature-docs path is still reported once.
- [ ] AC-7: `python3 -m unittest discover -s tests` passes, and the refreshed byte pin carries a comment naming this task.

## Test Notes

- Unit tests call the validator's patch validation directly, as the
  existing rework rule tests do.
- AC-4 also runs the command-line validator with `--dry-run-apply` on a
  temporary workflow file. Use a temporary directory that is removed by the
  test framework's cleanup.
- Assert codes and message substrings, not whole messages.

## Out of Scope

- The other-feature document checks.
- The feature-docs removal field and the entry script.
- Any change to the append rule.
