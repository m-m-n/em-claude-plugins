# Task Plan: task0002 — Child PATH keeps only absolute entries

## Goal

The PATH each scanner child process receives keeps only the caller PATH's
absolute entries, unmodified and in their original order, and it is left out
when no absolute entry remains. A scanner therefore cannot resolve its own
helper programs from relative or empty entries.

## Requirements

FR4, FR5, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_sca_child_env_path_filtering.py` — unit and run_scan integration tests for this task's Acceptance Criteria

### Files to Modify
- `em-workflow/scripts/scan-dependencies.py` — child PATH filtering in build_child_env, plus the FR5 updates to the comment above CHILD_ENV_BASE_KEYS and the build_child_env docstring
- `tests/test_sca_scan_unchanged_surfaces.py` — the fixture PATH value in test_ac2_the_child_environment_is_the_pass_through_keys_plus_the_pins becomes absolute (NFR3)

## Design

### build_child_env (FR4)
Implements the `build_child_env` contract and the absolute-entry rule pinned in
IMPLEMENTATION.md Shared Components.

1. Copy every pass-through key that is present in `environ`, as today.
2. PATH: when `environ` has PATH, keep its entries per the absolute-entry
   rule. If at least one entry survives, set PATH to the survivors joined with
   the platform path-list separator; otherwise leave PATH out. When `environ`
   has no PATH, leave PATH out.
3. Apply the ecosystem's pins on top, as today.

The key list `CHILD_ENV_BASE_KEYS` stays as is: PATH remains a pass-through
key, and only its value is filtered. The decision is lexical: no file is
opened, no filesystem state is inspected and no process is started (NFR1). The
signature is unchanged.

### Existing fixture (NFR3)
In `test_ac2_the_child_environment_is_the_pass_through_keys_plus_the_pins`,
the runner fixture's PATH value (`runner-PATH`, a relative entry) becomes an
absolute value, and the expected mapping follows it. The assertion (child
environment = pass-through keys + pins) stays the same. No other existing test
changes.

### Comments (FR5; IMPLEMENTATION.md D2)
- Comment above `CHILD_ENV_BASE_KEYS`: it no longer says PATH is carried
  through unchanged. It says that PATH keeps only its absolute entries (and is
  dropped when none remain), while the other keys are carried through
  unchanged.
- `build_child_env` docstring: states the PATH rule.

Do not edit `resolve_executable`, the Scan job construction section comment or
`build_scan_jobs`. They belong to the sibling resolution change
(IMPLEMENTATION.md D2).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR4, TM-2): Given an environ whose PATH is `tools`, an empty entry, `/usr/bin`, `./node_modules/.bin` and `/opt/bin` joined with the platform path-list separator, the child PATH is `/usr/bin` and `/opt/bin` joined with that separator. Absolute entries are kept as written: a duplicated absolute entry, and an absolute entry that ends in a directory separator, both survive unchanged in their original positions.
- [ ] AC-2 (FR4, TM-2): The child environment has no PATH key in three cases: the environ's PATH consists only of relative or empty entries (`tools`, `./node_modules/.bin`, `.`, an empty entry, `~/bin`); PATH is the empty string; the environ has no PATH.
- [ ] AC-3 (FR4, NFR2): For every ecosystem, HOME, TMPDIR, TEMP, TMP, SYSTEMROOT and USERPROFILE reach the child with the environ's values, and every pin of that ecosystem overrides as before. `test_ac2_the_child_environment_is_the_pass_through_keys_plus_the_pins` passes with an absolute fixture PATH and an unchanged assertion.
- [ ] AC-4 (FR4, TM-2): Run run_scan with a runner PATH that holds relative and empty entries around the absolute recording-stub directory. Every recorded scanner launch (npm, cargo, pip, go) received a PATH equal to the runner's absolute entries joined in order, with no relative or empty entry in it.
- [ ] AC-5 (NFR1): `build_child_env` returns the same result while file opening, filesystem inspection and process launching are made to fail during the call. Its parameters remain `ecosystem` and `environ`, and `environ` still defaults to the process environment.
- [ ] AC-6 (FR5): The comment above `CHILD_ENV_BASE_KEYS` no longer states that PATH is carried through unchanged, and that comment and the `build_child_env` docstring both state the FR4 rule. Verified by inspection.
- [ ] AC-7 (NFR3): `python3 -m unittest discover -s tests` passes. The only change to an existing test file is the fixture PATH value of `test_ac2_the_child_environment_is_the_pass_through_keys_plus_the_pins` in `tests/test_sca_scan_unchanged_surfaces.py`.
