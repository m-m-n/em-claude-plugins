# Task Plan: task0002 — State the binding rejection in workflow-patch.md

## Goal

The `path-correction-entries` limit of `workflow-patch.md` states the binding
rejection of the correction entry, so the contract says what the validator
enforces, and a docs test pins that statement.

## Requirements

FR4, NFR3, NFR4, NFR5

## Scope

### Files to Modify
- `em-workflow/references/workflow-patch.md` — the binding rejection in the path-correction-entries bullet
- `tests/test_final_path_correction_docs.py` — one new docs test class and one new module-hygiene class
- `tests/test_gate_option_vocabulary.py` — in-place refresh of the workflow-patch.md byte pin

## Design

### The contract text

In `## Final-path correction`, paragraph "**Limits on entries and
requirements.**", the bullet that opens with `path-correction-entries` gains
the binding rule of IMPLEMENTATION.md, Shared Components, in contract wording:

- On the correction entry, an item is also rejected when an entry of any
  kind exists now at `tasks/{T}.md` under the feature directory (a regular
  file, a directory, or a symlink, a dangling one included) and the item's
  `plan`, compared after `path_segments` normalization, is not
  `tasks/{T}.md`.
- A state of `tasks/{T}.md` that cannot be determined counts as existing.
- The error carries the task id and the path `tasks/{T}.md`.
- The rule does not require `tasks/{T}.md` for a plan when no such entry
  exists. Like the rest of the limits, it does not run on the Re-planning
  path, which the existing sentence "The Re-planning path is not limited"
  already states.

Wording constraints, all from the existing pins of
`tests/test_final_path_correction_docs.py`:

- Every string of `LIMITS_NEEDLES` stays in the limits text.
- The limits text gains no numbered item; the text stays a bullet list.
- No sentence of the new text contains a form of "normaliz" together with
  "both" or "one text".
- The new text stays between "**Limits on entries" and "**Ownership.**", and
  the numbered conditions and their text are not touched.
- No absolute home-directory path, no external URL, and none of the strings
  "REPORT|SUMMARY" and "(REPORT".

### Docs test (TS-10)

A new class directly after `TestMediumFixesLimitsOutsideTheConditions`, per
IMPLEMENTATION.md, Shared Components. It slices the
`path-correction-entries` bullet out of the limits text, normalizes
whitespace, and asserts distinctive phrases of the new rule: the existing
entry at `tasks/{T}.md`, the `path_segments` comparison of `plan`, any entry
kind with the dangling symlink, the indeterminate state counted as existing,
and the task id plus `tasks/{T}.md` in the error. Each matcher has a negative
proof: it fails on the bullet's pre-change text, kept verbatim as a module
constant captured from the base revision, and on a forged copy with one
phrase removed.

### Module hygiene (TS-11)

A new class that parses the import statements of
`tests/test_final_path_correction.py` and
`tests/test_final_path_correction_docs.py` and asserts that every imported
top-level module is in the standard library (the stdlib module-name set of
the running interpreter), plus a negative proof on a forged source holding a
third-party import. Relative or local imports that the modules already use,
when any, are named explicitly as allowed.

### Byte pin

After the document change, `WORKFLOW_PATCH_SHA256` in
`tests/test_gate_option_vocabulary.py` is set to the new digest of
`workflow-patch.md`, with a new comment paragraph directly above the
assignment, following the refresh convention in IMPLEMENTATION.md, Shared
Components. The comment names FR4 and the binding rule in the
`path-correction-entries` limit, and says that the numbered application
rules and the five numbered conditions are unchanged.
`VALIDATE_WORKER_OUTPUT_SHA256` is not touched by this task.
