# Task Plan: task0001 — Bind the correction entry's plan to tasks/{T}.md in the validator

## Goal

On the final-path correction entry, the validator rejects an item of
`tasks_patch.entries` whose plan is not `tasks/{T}.md` while an entry exists at
`tasks/{T}.md`, so a decoy plan with the canonical text can no longer pass
beside a different, unchecked `tasks/{T}.md`.

## Requirements

FR1, FR5, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — the binding check of the correction entry
- `tests/test_final_path_correction.py` — new test classes for the binding (existing tests unchanged)
- `tests/test_gate_option_vocabulary.py` — in-place refresh of the validator byte pin

## Design

### Where the check runs

The binding is a per-item check of `_correction_entries_errors` (the entries
limit of the correction entry). It is written inside that function or in one
module-level helper that the function calls; either way it is part of the
code read of TS-8 below.

- It runs for every item that is a mapping, before and independently of the
  files check, the rendering check and the plan check, so an early
  `continue` of those checks never skips it and its error is reported in
  addition to theirs.
- It runs only where `_correction_entries_errors` runs, that is on the
  correction entry. The Re-planning path, patches without `path_corrections`
  and every other state are unchanged.

### Contract of the binding decision

Inputs: the item's key T, the item's `plan` value and the feature directory.

1. **Bound.** The item is bound when T is a string matching the task-id
   pattern, `plan` is a string that passes `is_safe_relative_path`, and the
   `path_segments` of `plan` equal the two segments `tasks` and `{T}.md`. So
   `tasks/{T}.md`, `./tasks/{T}.md`, `tasks//{T}.md`, `tasks/./{T}.md` and
   the backslash spelling are all bound.
2. **Existence of `tasks/{T}.md`.**
   - When T is not a string matching the task-id pattern, nothing is looked
     up and `tasks/{T}.md` counts as existing.
   - Otherwise the entry `tasks/{T}.md` under the feature directory is looked
     up in the working tree without following a final symlink.
   - Only a lookup that reports that no such entry exists counts as absent.
     A regular file, a directory, a symlink (a dangling one included) and
     any other entry kind count as existing. Any other lookup failure
     (permission denied, a `tasks` component that is not a directory, any
     other operating-system error) counts as existing (NFR2).
3. **Decision.** When `tasks/{T}.md` counts as existing and the item is not
   bound, the item is rejected with `path-correction-entries`, `task_id` T,
   path `tasks/{T}.md` (for a non-string key, the path field may be omitted),
   and a message that names the binding: the plan is not `tasks/{T}.md`
   while `tasks/{T}.md` exists. Otherwise the binding adds nothing.

This is the binding rule pinned in IMPLEMENTATION.md, Shared Components; the
error shape follows IMPLEMENTATION.md, Conventions.

### Constraints

- No git access and no process start in the binding (NFR1): the existing
  test `TestEntryLimits.test_entry_files_reach_git_only_through_the_base_readers`
  keeps passing, and a helper, when one is used, contains none of the four
  forbidden tokens either.
- The lookup is of the current working tree, not of the base commit (SPEC.md
  assumption A3).
- `_load_module` of the tests and the bytecode-free load of the validator
  stay as they are.

### Byte pin

After the validator change, `VALIDATE_WORKER_OUTPUT_SHA256` in
`tests/test_gate_option_vocabulary.py` is set to the new digest of the
validator file, with a new comment paragraph directly above the assignment
following the refresh convention in IMPLEMENTATION.md, Shared Components. The
comment names FR1 and the binding, and says that the other checks of the
entries limit are unchanged. `WORKFLOW_PATCH_SHA256` is not touched by this
task.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-1, TS-1): With a new correction-entry item for `task0003` whose
  plan is `tasks/task0003-safe.md` holding the `canonical_correction_plan`
  output, and an unregistered `tasks/task0003.md` holding other text, the
  patch yields a `path-correction-entries` error carrying `task_id`
  `task0003` and path `tasks/task0003.md`, both through
  `validate_workflow_patch` with the dry-run arguments and through
  `validate_worker_result`.
- [ ] AC-2 (TS-2): An item with plan `tasks/{T}.md` holding the canonical
  text, and no other plan file, yields no error.
- [ ] AC-3 (TS-3): An item with a free plan path holding the canonical text,
  while nothing exists at `tasks/{T}.md`, yields no error; the existing
  TestCreatedDocuments and TestEntryLimits tests pass unchanged.
- [ ] AC-4 (TM-1, TM-2, TS-4): With a plan other than `tasks/{T}.md`, the
  item is rejected with the error of AC-1 when `tasks/{T}.md` is a
  directory, a dangling symlink, a symlink to a file, or a regular file
  beside a `TASK.md` plan; and when the lookup is indeterminate (a `tasks`
  component that is a regular file, and a lookup failure other than
  not-found simulated with the standard library's mocking facility).
- [ ] AC-5 (TS-5): The spellings `./tasks/{T}.md`, `tasks//{T}.md`,
  `tasks/./{T}.md` and the backslash spelling of `tasks/{T}.md`, with the
  canonical text in `tasks/{T}.md`, yield no error.
- [ ] AC-6 (TM-2, TM-3, TS-6, TS-8): On the Re-planning path (both its cases)
  and for patches without `path_corrections`, a decoy plan beside an
  existing `tasks/{T}.md` raises no binding error. A new code-read test
  shows that `_correction_entries_errors`, and the helper when one is used,
  contain none of `_run_git`, `subprocess`, `ls-tree` and `cat-file`, and a
  key that is not a task id is rejected without a lookup.
- [ ] AC-7 (NFR3, NFR5): `python3 -m unittest discover -s tests` passes; the
  new tests import only the standard library; no existing test of
  `tests/test_final_path_correction.py` is edited; the refreshed
  `VALIDATE_WORKER_OUTPUT_SHA256` carries its new comment paragraph.

## Test Notes

- All new tests are new classes in `tests/test_final_path_correction.py`,
  built on the module's existing helpers (the demo repository, the workflow
  and patch builders, `new_entry`, `validate`, `worker_errors`). No existing
  helper or test is edited.
- AC-1 is the attack reproduction of SPEC.md US1; assert the code, the
  `task_id` and the path, not only the code.
- AC-4: the symlink cases need a platform with symlink support; skip them
  with a stated reason where symlinks cannot be created. The mocked lookup
  failure is the only way to reach the "other failure" branch without
  changing file permissions, and it must patch only the lookup the binding
  uses.
- A key that is not a task id (AC-6): assert both the rejection and that the
  lookup was not called.
- AC-6: the code read follows the pattern of the existing code-read test of
  TestEntryLimits; give it a negative proof that the token check fires on a
  forged source string.
- TDD order: write AC-1 first and observe it fail on the unchanged validator.
