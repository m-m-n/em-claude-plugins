# Task Plan: task0002 — Pin the I.2.b step 1 partial-artifact and third-case Residual outcomes

## Goal

A new test module pins that `implement-phase.md` I.2.b step 1 keeps its
partial-artifact recovery definition and its third-case Residual definition,
so a later edit cannot drop either one silently.

## Requirements

FR6, FR7, NFR1

## Scope

### Files to Create
- `tests/test_routeback_ssot_drift_i2b_retention.py` — retention tests over
  the I.2.b section of `em-workflow/references/implement-phase.md`, each with
  a non-vacuity proof.

### Files to Modify
No existing files are modified.

## Design

The pinned text already exists at the base revision (SPEC A1). This task
adds tests only; `implement-phase.md` is read, never edited
(IMPLEMENTATION.md D2).

Processing flow:
1. Read `em-workflow/references/implement-phase.md` from the repository
   root.
2. Slice the I.2.b section using the boundaries in IMPLEMENTATION.md Shared
   Components. When either heading is missing, the slice fails with an
   error naming the missing heading (never an empty-string match).
3. Normalize whitespace (IMPLEMENTATION.md Conventions).
4. Assert each pinned literal is present in the section.

Pinned content. Each literal is copied verbatim from the current I.2.b text
and defined once as a module-level constant:

- **Partial-artifact (FR6)**
  - the sentence that defines the partial-artifact state (the task worktree
    exists but the task branch does not, or the task branch exists but the
    task worktree does not) and says that a journal last event of
    `launched` together with either state also triggers the same recovery;
  - the statement that, with no candidate for the harness stop tool, this
    condition falls to the same Residual treatment as an unresolvable Agent
    index lookup: journal unchanged, task stays in-flight, route-back gate
    blocks, gate-rejected terminal.
- **Third case (FR7)**
  - the sentence that defines the third case: the Agent index lookup
    resolves to a candidate, but the harness stop tool stops nothing, or the
    stop-tool recorder does not append a terminal event for it;
  - the clause that this third case receives the same Residual treatment,
    not the failed handling.

Non-vacuity proofs: for each pinned literal, the same matcher is run
against a copy of the section with that literal removed and must report it
missing.

A pin that duplicates one in another existing test module is acceptable.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR6): A test asserts that the whitespace-normalized I.2.b section
  contains the partial-artifact definition covering both one-sided states,
  together with the statement that a `launched` last event with either
  state triggers the same recovery.
- [ ] AC-2 (FR6): A test asserts that the I.2.b section states this
  condition falls to the same Residual treatment, naming journal unchanged,
  task stays in-flight, route-back gate blocks, and the gate-rejected
  terminal.
- [ ] AC-3 (FR7): A test asserts that the I.2.b section contains the
  third-case definition (the stop tool stops nothing, or the stop-tool
  recorder does not append a terminal event).
- [ ] AC-4 (FR7): A test asserts that the I.2.b section states the third case
  receives the same Residual treatment, not the failed handling.
- [ ] AC-5: Every pinned literal has a non-vacuity proof (its matcher
  reports it missing from a copy of the section without it), and a test
  proves the section slicer fails when either boundary heading is absent.
- [ ] AC-6 (NFR1): `python3 -m unittest discover -s tests` exits 0 from the
  worktree root; the new module uses only the standard library; the task's
  diff contains only the new module.
