# Task Plan: task0004 — rework-planner version rules reference and plugin_versioning input

## Goal

rework-planner applies plan-writing's version rules to every task it
synthesizes, by reference, and receives the same orchestrator-resolved
`plugin_versioning` value as implementation-planner, counted in its
`input_digest` `value_inputs`; the rework-planner dispatch procedure
resolves and passes it.

## Requirements

FR4, FR5, FR7, NFR1, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_plan_version_rework.py` — regression tests for this task's documents (TS-4 and the rework half of TS-5)

### Files to Modify
- `em-workflow/agents/rework-planner.md` — names the input and cites the plan-writing section for synthesized tasks
- `em-workflow/references/contracts/rework-planner-contract.md` — defines the input by citation, value_inputs membership, mandatory and untrusted status, and cites the plan-writing section
- `em-workflow/references/rework-task-synthesis.md` — cites the plan-writing section where synthesized task rules are stated
- `em-workflow/skills/develop/SKILL.md` — predicted holder of the rework-planner dispatch procedure (see Design)

## Design

Citation targets are pinned in IMPLEMENTATION.md Shared Components: the
plan-writing section heading `Plugin Version Handling`, and planner-contract.md's
subsection heading `### plugin_versioning (dispatch-resolved value)`. This
task cites both by path and heading and restates neither.

1. **rework-planner.md**: the inputs description names `plugin_versioning`;
   a statement says every task the agent synthesizes follows plan-writing
   SKILL.md's "Plugin Version Handling" section, including its `files` rule.
2. **rework-planner-contract.md**:
   - rework-planner's worker-specific input gains `plugin_versioning`; its
     shape and resolution are defined by citing planner-contract.md's
     subsection.
   - Mandatory on every rework-planner dispatch; absence is answered with
     `invalid_input`.
   - Untrusted input under worker-envelope.md's Untrusted-Input Handling,
     limited to the fields of the cited definition (TM-1).
   - The contract's digest declaration lists `plugin_versioning` as a
     `value_inputs` member.
   - Synthesized task entries (plans and `files`) follow plan-writing's
     section.
3. **rework-task-synthesis.md**: where it states how rework tasks are
   synthesized, cite plan-writing's section as applying to every synthesized
   task.
4. **Rework-planner dispatch procedure**: the orchestrator resolves
   `plugin_versioning` per planner-contract.md at every rework-planner
   dispatch, passes it in rework-planner's input, adds it to `value_inputs`,
   and re-resolves it for the return-time digest recomputation.
   - Location: the document that instructs the orchestrator to build
     rework-planner's input envelope. The prediction is
     `em-workflow/skills/develop/SKILL.md`. If the procedure lives in
     rework-task-synthesis.md instead, make the change there and leave
     develop SKILL.md untouched. If it lives in neither, edit the document
     that does hold it and report a plan deviation. Never create a new
     document for it.
