# Task Plan: task0001 — plan-writing plugin version handling rules

## Goal

The plan-writing skill gains a "Plugin Version Handling" section. Under it,
every plan (create-plan and rework) is consistent with plugin-version-guard's
per-commit check in non-exempt repositories and carries no version
instruction in exempt repositories. Regression tests detect removal of the
rules or a permissive restatement of them.

## Requirements

FR1, FR2, FR3, FR7, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_plan_version_plan_writing.py` — regression tests for the new section (TS-1, TS-2, TS-3 and this task's half of the FR7 negative check)

### Files to Modify
- `em-workflow/skills/plan-writing/SKILL.md` — new level-2 section "Plugin Version Handling" plus matching Pre-Save Self-Verification Checklist items

## Design

This task owns the section pinned in IMPLEMENTATION.md Shared Components
("plan-writing Plugin Version Handling section"); the heading text and the
term definitions listed there are a contract other documents cite.

Section content, as behavior descriptions in English:

1. **Definitions** (single owner, D1): exempt repository / non-exempt
   repository, decided by the presence of
   `.github/workflows/plugin-version-bump.yml` at the repository root;
   "under a plugin" means under a directory that contains
   `.claude-plugin/plugin.json`; "greater" means strictly greater by
   per-component numeric comparison.
2. **Input**: the planner takes exemption state and plugin locations from
   the dispatch's `plugin_versioning` value (contract in IMPLEMENTATION.md;
   owned by planner-contract.md) and never discovers them itself. The section
   applies to implementation-planner and rework-planner alike.
3. **Non-exempt subsection**:
   - Every commit that changes a file under a plugin bumps the patch of that
     plugin's `plugin.json` version in the same commit.
   - When the same-named entry in `.claude-plugin/marketplace.json` carries
     a version, it is set to the same value in that commit.
   - When one task makes several such commits, the version advances on each
     commit.
   - The bumped value is greater than the value at the immediately preceding
     HEAD.
   - Outside scope: plugins newly added by the change (no `plugin.json` at
     base) and marketplace entries without a version are neither bumped nor
     aligned (A7).
   - Carriage (D4): every task plan whose files fall under a plugin carries
     the per-commit instruction for that plugin itself, so a task plan read
     on its own (including a rework task plan) is consistent with the guard.
   - Files rule: such a task's files include that plugin's `plugin.json`
     and, when `marketplace_versioned` is true, `.claude-plugin/marketplace.json`.
   - Prohibited instructions: anything that keeps the version unchanged on a
     plugin-changing commit. Name "only the first task bumps the version" and
     "subsequent tasks / rework tasks do not bump the version" as examples of
     what plans must not say.
   - Conflict-time commits: governed by worktree-task-workflow SKILL.md's
     parent-side adoption protocol (cited by path plus protocol name, not
     restated).
4. **Exempt subsection**: plans instruct no version change for any task.
   Only when a minor or major bump is intended does the plan name where to
   bump, never a concrete value.
5. **Checklist items** added to Pre-Save Self-Verification: non-exempt files
   rule and per-commit instruction present for every plugin-changing task; no
   keep-unchanged instruction anywhere; exempt plans carry no version-change
   instruction and no concrete version value.

Structural requirement for testability: the non-exempt rules and the exempt
rules sit in two distinct subsections of the section, so tests can scope
their positive and negative checks.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1): `em-workflow/skills/plan-writing/SKILL.md` has a heading whose exact text is `## Plugin Version Handling`, and its non-exempt subsection states all four elements: the patch bump of the plugin's `plugin.json` in the same commit as any change under that plugin; alignment of a same-named `marketplace.json` entry that carries a version; advancing on each such commit within one task; a value strictly greater than the value at the immediately preceding HEAD by per-component numeric comparison.
- [ ] AC-2 (FR1): the non-exempt subsection states that newly added plugins (no `plugin.json` at base) and marketplace entries without a version are neither bumped nor aligned.
- [ ] AC-3 (FR2): the section prohibits instructions that keep the version unchanged on a plugin-changing commit, naming "only the first task bumps the version" and "subsequent tasks / rework tasks do not bump the version" as prohibited examples; states that a plugin-changing task's files include that plugin's `plugin.json` and, when its marketplace entry carries a version, `.claude-plugin/marketplace.json`; and states that each such task plan carries the per-commit instruction itself.
- [ ] AC-4 (FR3): the section defines exempt and non-exempt repositories by the presence of `.github/workflows/plugin-version-bump.yml` at the repository root, and its exempt subsection states that plans instruct no version change and, for an intended minor or major bump, name only where to bump with no concrete value.
- [ ] AC-5 (FR5, NFR1): the section states that exemption state and plugin locations come from the dispatch's `plugin_versioning` value rather than the planner's own discovery, that it applies to both implementation-planner and rework-planner, and cites worktree-task-workflow SKILL.md's parent-side adoption protocol for conflict-time commits without restating that rule.
- [ ] AC-6 (FR2): the Pre-Save Self-Verification Checklist gains items for the non-exempt files and per-commit instruction rule, the absence of keep-unchanged instructions, and the exempt no-instruction rule.
- [ ] AC-7 (FR7, NFR2, NFR3, NFR4): `tests/test_plan_version_plan_writing.py` contains a negative check that fails when SKILL.md permits an unchanged version on a plugin-changing commit in a non-exempt repository; the check rejects an in-test permissive sample sentence and accepts the section's own prohibited-example quotations and exempt subsection; the section contains no fenced code block and no concrete version value; `python3 -m unittest discover -s tests` passes.

## Test Notes

- All criteria are unit tests over the text of SKILL.md: locate the section by
  its pinned heading, then each subsection, and assert the key terms each
  criterion lists (AC-1 to AC-6).
- The negative check (AC-7) is the TDD-awkward part. The prohibition itself
  quotes the forbidden phrases, and the exempt subsection legitimately says
  plans do not change the version, so a plain phrase search misfires. Scope
  the check to non-exempt text and exclude sentences that carry the
  prohibition, then prove the check in both directions with in-test sample
  text (one permissive sample rejected, the real section accepted).
- "No concrete version value" means no dotted numeric version literal inside
  the section.
- Follow IMPLEMENTATION.md Conventions for test mechanics: standard library
  only, repository root derived from the test file's location, no access to
  `~/.claude`, assertions only on this task's own documents.

## Out of Scope

- Changing any `version` in `em-workflow/.claude-plugin/plugin.json` or
  `.claude-plugin/marketplace.json` (NFR4: this repository is exempt).
- Defining the shape or resolution of `plugin_versioning` (owned by
  planner-contract.md per IMPLEMENTATION.md); this task only uses it by name.
- The conflict-time rule text, the contracts, the agent prompts and the
  dispatch procedures (owned elsewhere per IMPLEMENTATION.md Shared
  Components).
- `~/.claude/hooks/plugin-version-guard.py` (A5) and the suspended feature
  destructive-guard-heredoc-reset-hard (A4).
- Rules for coordinating two tasks that bump to the same value (A6: no
  additional handling).
