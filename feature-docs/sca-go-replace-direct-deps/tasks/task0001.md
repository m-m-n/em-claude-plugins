# Task Plan: task0001 — Go replace directives add replacement modules to the direct set

## Goal

When go.mod replaces a non-indirect require with another module, the Go SCA
treats the replacement module as direct, so its advisories become findings or
are counted under `go_severity_undetermined`. Regression tests cover both the
single-line and the block form of replace.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3

## Scope

### Files to Create
- `tests/test_sca_go_replace_direct_deps.py` — regression tests for replace handling (single-line and block form, selection rules, directory-path forms, edge forms, output safety)

### Files to Modify
- `em-workflow/scripts/scan-dependencies.py` — replace parsing and the direct set in the Go normalization section; the Go normalization section comment, the _go_mod_direct_modules docstring and the normalize_go docstring

## Design

### Contract: direct set of one Go scan unit (`_go_mod_direct_modules`)

- **Precondition**: the go.mod path was resolved through the script's existing
  project-relative confinement. Its content is untrusted.
- **Postcondition**: the returned set is the union of
  (a) every non-indirect require path (unchanged prior behaviour), and
  (b) for each non-indirect require entry, the replacement path of its
  applicable replace, when that replace is a module replacement.
  The original require path is never removed (FR4). The result does not
  depend on the order of require and replace directives in the file (FR2).
- **Unchanged**: what makes a go.mod unreadable, the indirect-marker rule,
  exact matching, quoted paths, the sibling-go.mod rule for a go.sum target,
  and stdlib/toolchain being direct (prior FR3 / FR4).

### Replace entry recognition (FR1)

1. Collect replace lines from the single-line form and from `replace ( ... )`
   blocks, applying the same comment splitting, double- and back-quote
   stripping and CRLF handling the require parsing already applies.
2. After tokenizing, a line is a replace entry only when its tokens are, in
   order: source path, optional source version, a standalone `=>` token,
   replacement path, optional replacement version. Any other token count or
   arrangement (missing right side, extra tokens, `=>` glued to a path)
   contributes nothing.
3. Unrecognized lines are skipped silently: no exception escapes, the go.mod
   is not treated as unreadable, and no skip reason or note is produced.

### Module replacement (FR3)

A replacement is a module replacement only when it has exactly a path and a
version and the path is not in directory-path form. Directory-path form:
equal to `.` or `..`; starting with `./`, `../`, `.\`, `..\`, `/` or `\`; or
an ASCII letter followed by `:` at the start. Replacement paths are compared
as strings only — they are never resolved against the filesystem and nothing
is opened from them.

### Applicable replace selection (FR2, FR3, FR5)

For each non-indirect require entry (path P, version V):

1. If a replace with source P and source version exactly equal to V exists,
   it is the applicable replace.
2. Otherwise, if a replace with source P and no source version exists, it is
   the applicable replace.
3. Otherwise there is no applicable replace.
4. If the applicable replace is a module replacement, add its replacement
   path. If it is not (a local directory or a directory path with a version),
   add nothing and do not fall back to an unversioned replace of P.

Contributing nothing: a replace whose source matches no require entry or
only an indirect one, a versioned replace whose version differs from V, and
a replacement of a replacement (replacements are applied once, never chained).

### Documentation (FR6)

The Go normalization section comment, the `_go_mod_direct_modules` docstring
and the `normalize_go` docstring describe the new behaviour (replace
contributes per FR1-FR5) and no longer state that replace contributes
nothing. The prior feature's documents under
`feature-docs/sca-go-govulncheck-real-output/` are not edited.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR2, FR4; TS1): With `require example.org/text v0.3.6` and the single-line `replace example.org/text => golang.org/x/text v0.3.6`, a govulncheck stub stream advisory on golang.org/x/text with a CVSS v3 critical/high vector yields exactly one finding whose package is golang.org/x/text; the same advisory without a CVSS v3 vector is counted in the `go_severity_undetermined` note; skipped is false in both runs.
- [ ] AC-2 (FR1, FR2; TS2): AC-1 holds with the replace written inside a `replace ( ... )` block, including a block that also holds other entries and comment lines.
- [ ] AC-3 (FR3, NFR3; TS3, TS12; TM-2): A direct require replaced by `./x`, `../x`, `/x`, `.\x`, `..\x`, `\x`, `C:\x`, `.`, `..` or `./x v1.0.0` adds nothing: an advisory on the replacement path is neither a finding nor counted and the result is completed clean. TM-2: when the local replacement resolves to an existing directory outside the project root that holds its own go.mod requiring module M, an advisory on M is neither a finding nor counted (no file is read from a replace directive's path).
- [ ] AC-4 (FR2, FR3, FR5; TS4, TS5): Nothing is added when the source require is `// indirect`, when no require of the source exists, or when a versioned replace's version differs from the require version. A versioned replace whose version equals the require version adds its replacement; when a matching versioned and an unversioned replace of the same module both exist, only the versioned replacement is added; when the matching versioned replace is local and an unversioned module replace also exists, nothing is added.
- [ ] AC-5 (FR1, FR4, FR5; TS6, TS7; TM-1): At parser level the direct set contains both the original require path and the replacement path, and is the same when the replace precedes the require; quoted paths on both sides, trailing comments and CRLF line endings are handled as for require; chained A=>B, B=>C adds only B for a direct require of A. TM-1: a glued `=>`, a missing right side and extra tokens each contribute nothing, raise no exception and leave the go.mod readable with the require-derived direct set intact.
- [ ] AC-6 (NFR3; TS11; TM-3): For the malformed and non-contributing go.mod cases of AC-3 to AC-5, the run result has skipped false, no skip reason, only summary note tokens that already exist with counts-only values, and a distinctive marker string written into the replace directives (source and replacement side) appears nowhere in the serialized run result.
- [ ] AC-7 (FR6; TS9): The Go normalization section comment, the `_go_mod_direct_modules` docstring and the `normalize_go` docstring describe replace contributing per FR1-FR5 and contain no statement that replace contributes nothing; no file under `feature-docs/sca-go-govulncheck-real-output/` is changed.
- [ ] AC-8 (NFR1, NFR2; TS8, TS10): The new test module uses only stdlib `unittest` plus the repository's existing test helpers, replays streams offline through the existing govulncheck stub harness, and is run by `python3 -m unittest discover -s tests`; that full run passes with every existing test module under `tests/` unchanged, and `python3 em-workflow/scripts/check-plugin-invariants.py .` passes.

## Test Notes

- AC-1 to AC-4 and AC-6 are integration-style unit tests: a temporary project
  with a go.mod and the existing govulncheck stub harness, asserting on the
  run result. AC-5 is a parser-level unit test of `_go_mod_direct_modules`
  asserting the exact direct set.
- AC-3's TM-2 case creates two sibling temporary directories (the project and
  an outside directory with its own go.mod); the outside go.mod's require must
  have no effect.
- AC-6 reuses the go.mod fixtures of AC-3 to AC-5; the marker check runs over
  the whole serialized result, not only the notes.
- The stub harness is reused, not copied. If a helper lives inside an existing
  test module, import only helpers from it so that discovery does not collect
  that module's existing test cases a second time from the new module.
- AC-7 is not test-translatable: it is checked by inspection of the three
  docstring/comment sites and by an empty diff under
  `feature-docs/sca-go-govulncheck-real-output/`.

## Out of Scope

  undetermined counting rule or the note vocabulary.
- Chained replacement resolution, reading a replacement module's own go.mod,
  or minimum-version selection (SPEC A2 limitation stays as specified).
- Editing existing test modules, including
  `tests/test_sca_go_govulncheck_real_output.py`.
- Editing the prior feature's documents under
  `feature-docs/sca-go-govulncheck-real-output/`.
