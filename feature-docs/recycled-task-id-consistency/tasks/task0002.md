# Task Plan: task0002 — Plugin version bump to 0.1.37 in both registries

## Goal

Carry the em-workflow plugin version to `0.1.37` in both places that record it —
the plugin manifest and the marketplace entry — and add a document-contract test
module that asserts both values and the protocol document's no-bare-git-commit
invariant.

## Requirements

FR7, FR8, FR9, NFR1, NFR3, NFR5

## Scope

### Files to Create
- `tests/test_recycled_task_id_version_bump.py` — TS-11: both registries report
  version `0.1.37` for em-workflow, and `implement-phase.md` has no bare
  `git commit` / `git add -A` line; plus negative-proof tests for both matchers.

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — `version` from `0.1.36` to `0.1.37`.
- `.claude-plugin/marketplace.json` — the `plugins[]` entry whose `name` is
  `em-workflow` gains `"version": "0.1.37"` (the key does not exist today).

This task writes NO other file. In particular it does not touch
`em-workflow/references/implement-phase.md` (task0001 owns it — this task only
READS it), any pre-existing module under `tests/`, or anything under
`feature-docs/implement-routeback-gate/`.

## Design

### Registry edits

| File | Key | Before | After |
|------|-----|--------|-------|
| `em-workflow/.claude-plugin/plugin.json` | `version` | `0.1.36` | `0.1.37` |
| `.claude-plugin/marketplace.json` | the `em-workflow` entry's `version` | key absent | `0.1.37` (key ADDED) |

Constraints:

- No other field of either file changes. The `em-review` entry of
  `marketplace.json` is not touched at all — not its description, not its
  ordering, and it gains no `version` key.
- Both files must still parse as JSON, keep their existing formatting style
  (two-space indent, key order preserved, trailing newline), and the added key
  sits inside the `em-workflow` entry alongside its sibling keys.

### Interaction with existing suites (no modification needed)

Three pre-existing modules assert the em-workflow plugin version. Each compares
it as a tuple against a fixed pre-feature baseline (`0.1.21`, `0.1.23` and
`0.1.27` respectively) with a strictly-greater relation, and one also requires
the version to stay on the `0.1.x` line. `0.1.37` satisfies all of them, so no
existing module changes. No pre-existing module reads `marketplace.json`, so
adding a key there breaks nothing (IMPLEMENTATION.md, D6). Confirm this by
running the full suite, not by reasoning alone.

### The new test module

`tests/test_recycled_task_id_version_bump.py`, following the conventions in
IMPLEMENTATION.md ("Test conventions"):

- Resolves both registry paths from the module file's own location.
- Parses each file as JSON (a parse failure is itself a reported failure, not an
  exception trace) and asserts the em-workflow version equals `0.1.37` in the
  plugin manifest and in the marketplace entry selected by `name == em-workflow`.
- Asserts the `em-review` marketplace entry carries no `version` key, so a
  careless edit to the wrong entry is caught.
- Asserts `em-workflow/references/implement-phase.md` has zero lines that, after
  stripping indentation and markdown backticks, begin with `git ` and contain
  `commit` or `add -A` — the NFR1 half of TS-11. This assertion holds both before
  and after task0001's edit, so it is green in this task's own worktree.
- Negative proofs: the version matcher flags a forged manifest still carrying the
  pre-bump value, and the bare-git-line matcher flags a forged line that is a
  real shell commit invocation while ignoring prose that merely mentions
  "git commit" inside a sentence.
