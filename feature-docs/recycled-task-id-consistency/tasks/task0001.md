## Design

### Why this is one task

`implement-phase.md` is a single file and every prose requirement edits it.
Splitting the prose requirements across tasks would guarantee a merge conflict on
every parallel run, so the whole document — and the tests asserting its content —
is one owner's responsibility (IMPLEMENTATION.md, D1).

### Site 1 — Step I.2.b step 3: write-back keyed off the reconciled state (FR1)

Present state: the sentence sets `tasks.{T}.status = merged` for every task
verified merged, and `= failed` "for every task whose last journal event is
`failed` or whose report is `failed`/malformed".

Required after the edit:

- The `failed` half is keyed off the classification step 1 produced — the
  step-1 RECONCILED STATE — not off the journal's last event directly. The
  completion-report half of the condition ("or whose report is
  `failed`/malformed") is retained.
- The `merged` half of the sentence is unchanged.
- The whitespace-normalized `### I.2.b` section no longer contains the phrase
  "for every task whose last journal event is `failed`".
- Readable consequence: a task step 1 classified as unlaunched through the
  recycled-task-id carve-out (journal last event `failed` while workflow.yaml
  `status` is `pending`) is NOT written back to `failed` in the same wake phase.

### Site 4 — I.2.c route-back: precondition and inapplicable branch (FR3, FR4)

**Precondition (FR3)**, stated before the ordered workflow.yaml write set:
route-back is admissible only when EVERY task whose status it would reset to
`pending` has a TERMINAL journal last event (`merged` or `failed`), checked by
replaying the journal. This is in addition to — never instead of — the existing
gate, whose sentence and wording ("applies only when no task has status
`merged`") are retained.

**Inapplicable branch (FR4)**: when the precondition fails, route-back is
INAPPLICABLE. No part of the write set is performed (no `create-plan` =
`needs_update`, no `implement` = `pending`, no task status reset), no
worktree/branch cleanup and no route-back commit happen, `implement` stays
`failed`, and the phase ends with a report naming each offending task id and its
non-terminal journal last event, returning control to the user via develop's
stop condition 3 — the same terminal as the bullet's existing "abort phase"
option. There is no partial-write path between the two outcomes.

**Placement constraints** (these are what keep the existing suite green — see
IMPLEMENTATION.md D3 and D4; verify with the TS-10 assertions):

1. The precondition text must not introduce the tokens `commit-docs.sh`,
   `git worktree remove --force`, or the phrase `End the phase with a`, because
   each of those is matched by FIRST occurrence and must keep its existing
   relative order (cleanup → commit → end-of-phase report).
2. If the precondition mentions `tasks.{T}.status` and thereby becomes the
   section's FIRST occurrence of that token, `pending` must appear within the
   following 60 whitespace-normalized characters. Wording the precondition as
   "every task whose status it would reset to `pending`" avoids the hazard
   entirely.
3. Neither `rework` nor `append` may appear anywhere in the I.2.c section.
4. The batch-mode paragraph stays the byte-identical last text of the section,
   and the heading `### I.2.c: Failed handling` stays byte-identical.

## Test Notes

- Every criterion is a unit-level document-contract assertion; there is no
  runtime behaviour to integration-test (the change is documentation-only).
- TDD order that actually produces a red: write TS-1 .. TS-6 first — they fail
  against the current document because the new wording is absent — then edit the
  document. TS-7 .. TS-10 are regression guards that are GREEN before the edit;
  their value is that they turn red the moment an edit reflows a protected
  literal or reorders the I.2.c section, so run the full suite after every
  document edit, not only at the end.
- The byte-identity literal for TS-9 is copied into the new module as its own
  constant. Do not import from `tests/test_implement_routeback_gate.py` and do
  not modify that file.
- Assert prose against a whitespace-normalized copy; assert byte identity
  against the raw text. Mixing the two is the known source of both false passes
  and false failures in this suite.
