# Task Plan: task0001 — Restrict substitution-head command-name evidence to resolver forms

## Goal

destructive-guard reads the body of a command-name substitution head as rm / git evidence only when the body is one of the resolver forms of SPEC.md FR1. Non-resolver bodies such as `dirname /opt/rm` are no longer denied, and `$(which rm)`, `$(command -v rm)` and `$(printf rm)` stay detected.

## Design

### Evidence reader contract (`read_command_name_evidence()`)

- Input: the raw substitution body (RAW_BODY), possibly absent.
- Output: a command name (the last path segment of NAME), or unreadable (None).
- Postcondition: pure string processing. The reader evaluates no substitution, starts no process and reads nothing from the file system (FR3).

Reading flow:

1. An absent, empty or whitespace-only body is unreadable.
2. Continuation lines (a backslash immediately followed by a newline) are removed exactly as the current implementation removes them. A backslash that is itself escaped does not start a continuation, as today.
3. Leading and trailing whitespace is dropped, newlines included.
4. A body that still holds a newline is unreadable.
5. The body is split into words on spaces and tabs only. A run of spaces and tabs is one separator, so no empty word is produced. No other character separates words.
6. The word sequence is matched against the accepted shapes below. No match means unreadable.
7. A NAME that begins with `-` is unreadable.
8. A NAME whose last path segment is empty (for example a NAME ending in `/`) is unreadable.
9. Otherwise the last path segment of NAME is returned.

Accepted shapes (NAME is exactly one word):

| Head word | Words after the head | How the head is compared |
|---|---|---|
| which | NAME; -a NAME; -- NAME; -a -- NAME | Equal to `which`, or a word that contains `/` and whose last segment is exactly `which` |
| command | -v NAME; -v -- NAME | Equal to `command` |
| printf | NAME | Equal to `printf` |

The option words `-a` and `-v` and the terminator `--` are compared exactly. When `-a` and `--` both appear, only the order `-a -- NAME` is accepted. Every other sequence, including a different option word, a different order, a second operand or a path-form `command` / `printf` head, is unreadable (FR2).

### Routing (`route_substitution_headed_statement()`)

Behavior is unchanged (FR4). Evidence rm enters the rm route, evidence git enters the git route, and any other value or unreadable enters no route: the statement is allowed there and never turned into ask (NFR1). For a statement whose evidence is not rm, the plain route still runs as today.

### Docstrings (FR6)

- The numbered reading steps of the reader's docstring are rewritten to the flow above. No step takes the last word of the body any more.
- Editing the routing function's docstring is optional. If it is edited, it keeps the phrases `held` and `one ordinal` and gains no phrase that a STALE pattern of `tests/test_destructive_guard_rm_reason_positions.py` matches.

### Case table (FR5)

The eleven cases of SPEC.md FR5 are added in the case format of `.claude/rules/hook-tests.md`. Each deny case carries the expected reason ID in its fourth element: `rm-recursive` for the rm cases, `git-reset-hard` for `$(command -v git) reset --hard HEAD`. No existing case is removed or changed.

### Unit test expectation (FR7)

In the lexer agreement test, the expectation for the body made of `which a`, two backslashes, a newline and `m` changes from `"m"` to None: the escaped backslash leaves the newline in place, so step 4 makes the body unreadable. The expectation that `which r`, a backslash-newline and `m` reads as `rm`, and the deny of that command, stay as they are.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, TM-1): The reader returns `rm` for each of `which rm`, `which -a rm`, `which -- rm`, `which -a -- rm`, `/usr/bin/which rm`, `which /usr/bin/rm`, `command -v rm`, `command -v -- rm` and `printf rm`, for `which` and `rm` separated by a tab, for `which` and `rm` separated by two spaces, and for `which rm` with a leading and a trailing newline; it returns `git` for `which git` and `command -v git`.
- [ ] AC-2 (FR2): The reader returns None for each of `dirname /opt/rm`, `ls -d /usr/bin/rm`, `readlink -f ./rm`, `basename /a/b git`, `echo rm`, `type rm`, `rm`, `which ls rm`, `which -s rm`, `which -- -a rm`, `command -V rm`, `/usr/bin/command -v rm`, `/usr/bin/printf rm`, and `which` and `rm` separated by a newline.
- [ ] AC-3 (FR3): The reader returns None for an absent body, an empty body, a whitespace-only body, a NAME that begins with `-` (`which -rm`, `command -v -- -rm`) and a NAME whose last path segment is empty (`which /usr/bin/`).
- [ ] AC-4 (FR3, FR7, TM-2): In `tests/test_destructive_guard_lexer_agreement.py`, `which r` + backslash-newline + `m` still reads as `rm` and its command is still denied, the expectation for `which a` + two backslashes + newline + `m` is None instead of `"m"`, and no other expectation of that file changes.
- [ ] AC-5 (FR4, FR5, NFR1, TM-1): The case table holds the FR5 cases: allow for `$(dirname /opt/rm) -rf /home/user/valuable`, `$(ls -d /usr/bin/rm) -rf /home/user/valuable`, `$(readlink -f ./rm) -rf /home/user/valuable`, `$(basename /a/b git) clean -fd`, `$(which ls rm) -rf /home/user/valuable` and `$(rm) -rf /home/user/valuable`; deny with reason ID `rm-recursive` for `$(command -v rm) -rf /home/user/valuable`, `$(which -a rm) -rf /home/user/valuable`, `$(/usr/bin/which rm) -rf /home/user/valuable` and `$(command -v -- rm) -rf /home/user/valuable`; deny with reason ID `git-reset-hard` for `$(command -v git) reset --hard HEAD`. No existing case is removed or changed, and `python3 em-workflow/hooks/tests/run-destructive-guard.py` passes every case, the existing `$(which ...)` / `$(printf rm)` cases (TS-9) and the plain-route deny of `$(true) rm -rf /home/user/valuable` (TS-10) included.
- [ ] AC-6 (FR6): The reader's docstring states the reading flow of FR1 to FR3 and no longer contains the phrase `LAST word` (asserted in the new test module). If the routing function's docstring is edited, it still contains `held` and `one ordinal`, and `tests/test_destructive_guard_rm_reason_positions.py` still passes.
- [ ] AC-7 (NFR4, TS-11): `python3 -m unittest discover -s tests` reports the same set of failing and erroring test IDs as at the task's base commit (the new tests pass), and no file named `failed-run-cleanup-guard.py` is changed.
