# Task Plan: task0002 — Register the interactive-guard hook on every codex exec launch

## Goal

Every `codex exec` launch from both `run_codex_exec.sh` wrappers carries the PreToolUse hook registration and `--dangerously-bypass-hook-trust`. This covers em-workflow's default path and `--litellm` path, and em-review, each in readonly and readwrite modes. All argument properties the existing tests pin stay as they are.

## Requirements

FR1, FR2, FR3, FR4, FR14, NFR3, NFR4, NFR5

## Scope

### Files to Create
- `tests/test_codex_hook_wrapper_args.py` — stub-codex argument tests for all launch paths, and the path-quoting test

### Files to Modify
- `em-workflow/scripts/run_codex_exec.sh` — add the hook registration and the bypass flag to the default and litellm launches
- `em-review/scripts/run_codex_exec.sh` — add the hook registration and the bypass flag to its launch

## Design

### What each launch gains

Each launch gains two things:

1. A `-c` argument whose value sets `hooks.PreToolUse` to a one-element array, in the A6 form of SPEC.md. The element's matcher is `Bash`, and its hooks list holds one command-type hook. That hook's command runs the Python 3 interpreter on the absolute path of `codex-hook-interactive-guard.py` in the same `scripts/` directory as the wrapper (IMPLEMENTATION.md D1).
2. The flag `--dangerously-bypass-hook-trust`.

### Path resolution

- The path is resolved from the wrapper's own location at run time, never from the caller's working directory.
- The wrapper does not check that the hook file exists (A5, IMPLEMENTATION.md Conventions).
- The hook file itself is task0001's deliverable. This task references it by path only (IMPLEMENTATION.md Shared Components, D2).

### Confirming the form on Codex 0.160.0 (A6)

Before fixing the value, confirm with a minimal manual probe on an installed Codex 0.160.0:
- the exact key names inside the array element
- whether Codex runs the hook command through a shell or splits it some other way

Choose the escaping to match what you observe, and record the observed facts in the task report. If a real Codex 0.160.0 cannot be reached from the implementer environment, implement the A6 form as written and report the confirmation as outstanding. VERIFICATION.md M-1 re-checks it. The test suite never runs real Codex (NFR4).

### Escaping (TM-3)

The absolute path is quoted for the command-execution layer you confirmed, and the resulting command is then quoted as a TOML string. As a result, a path containing spaces, single or double quotes, backslashes or shell metacharacters always resolves back to exactly that path.

### Preserved properties (NFR3, NFR5, A3, A4)

- the existing `-c` overrides (reasoning effort, otel)
- `--ignore-user-config` on every launch that has it today (em-workflow's default path), and its continued absence on the `--litellm` path
- `--ignore-rules` on every launch that has it today
- `-p litellm -m MODEL` stays contiguous: the new arguments never go between those four words
- exactly one `codex` invocation per wrapper run
- no `2>&1` anywhere in the wrapper text
- usage text and accepted flags unchanged
- in em-review's wrapper, `codex exec` appears exactly once across non-comment lines
