## Design

### Contract

This task implements the "Interactive-guard hook" row of IMPLEMENTATION.md Shared Components: invocation, stdin and stdout shape, exit status 0, no side effects, and byte-identical copies. The deny reason follows the "Interactive-mode alternatives wording" row. Neither contract is restated here.

### Processing flow

Port the parse procedure from `em-workflow/hooks/interpreter-mismatch-guard.py`: heredoc removal, splitting into simple commands, redirect removal and wrapper skipping. Copy the procedure and adapt it; never import the file (A8).

1. Read all of stdin and parse it as JSON. If parsing fails or the value is not an object, pass.
2. Take `tool_input.command`. If it is absent or not a string, pass.
3. Remove heredoc bodies. An unterminated heredoc means pass.
4. Split into simple commands at `;`, `&&`, `||`, `|` and newlines. Characters inside quotes and comments are not separators. Unbalanced quoting means pass. Note for each simple command whether it sits on the right side of a pipe.
5. For each simple command:
   1. Split it into words with shell quoting rules.
   2. Drop redirections, and note whether one of them redirects standard input (`<`, `<<`, `<<<`, including the explicit fd-0 forms).
   3. Skip, in any combination: leading variable assignments; the option-less wrappers `env`, `nohup`, `nice`, `exec`, `command`, `time`, `sudo` (assignments after `env` are skipped too); and `timeout` followed by one duration word. If a wrapper is followed by an option word (for example `env -i`, `nice -n 5`, `timeout -s KILL 5`, `command -v`), pass this simple command (FR11).
   4. Match the basename of the command word against the family table below (FR8).
   5. For a shell-family launch whose code option `-c` (alone or bundled, as in `-lc`) is followed by a literal string, run steps 3–6 on that string exactly once. No deeper nesting is evaluated. The inner commands count as having standard input connected when the outer launch had it connected.
   6. Apply FR6, then FR7, using the family table.
6. If any simple command is denied, print one deny object (FR12). Otherwise print nothing. Always exit 0.
7. Any unexpected error at any step means pass: no output and exit 0. Nothing is written to stdout or stderr.

### Family table

A name matches when the command word's basename is exactly the known name, or the known name followed by a suffix made only of digits and dots (FR8). So `python3.14`, `ipython3`, `node22` and `lua5.4` match, while `python3-config` and `bashcov` do not.

| Family | Known names | Deny on `-i` (FR6) | Deny on no program source (FR7) | Code-passing options |
|--------|-------------|--------------------|---------------------------------|----------------------|
| python | python | yes | yes | `-c`, `-m` |
| node | node | yes; `--interactive` counts as `-i` | yes | `-e`, `-p`, `--eval`, `--print` |
| shell | bash, sh, zsh, dash, ksh | yes | yes; `-s` without connected stdin counts as options only | `-c` |
| lua | lua | yes | yes | `-c`, `-m`, `-e` (FR7 general set; A9 gives none) |
| ruby | ruby | no (in-place edit) | yes | `-e` |
| perl | perl | no (in-place edit) | yes | `-e`, `-E` |
| deno | deno | no | yes | `-c`, `-m`, `-e` (FR7 general set) |
| irb | irb | no | yes | `-c`, `-m`, `-e` (FR7 general set) |
| ipython | ipython | no | yes | `-c`, `-m`, `-e` (FR7 general set) |

Names outside this table are never classified. `php -i` and `sed -i` therefore pass.

### Option reading (FR6 and FR7)

- Options are read left to right after the command word. Reading stops at the first operand. An operand is a word that does not start with `-`, the lone word `-`, or the word after `--`. Reading also stops at the value of a code-passing option.
- In a bundle of short options (`-Bi`, `-ic`), each letter is an option. If a letter takes a value, the rest of the bundle is its value, or the next word is when the letter is last. For example, `-ic` means `-i` then `-c`, while `-ci` means `-c` with the value `i`. Letters after a value-taking letter are never read as `-i`.
- Options that take a separate value consume the next word, so the value is not mistaken for an operand. Examples: python `-W`, `-X`; node `-r`; shells `-o`, `-O`; lua `-l`; ruby and perl `-I`, `-r`, `-M`. When the hook is unsure whether an option takes a value, it chooses the reading that leads to pass (NFR2).
- **FR6 deny**: the family denies on `-i`, and `-i` (or node's `--interactive`) appears before reading stops.
- **FR7 deny**: all of the following hold.
  - There is no operand, including `-`.
  - No code-passing option is present.
  - Standard input is not redirected.
  - The command is not on the right side of a pipe.
  - None of `--version`, `-V`, `-h` or `--help` is present.
  - None of the family's informational / one-shot options is present: node `-v`, `--test`, `--check`, `--run`; perl `-v`; python `-VV`. (Orchestrator amendment, batch Codex consultation: option B — a small per-interpreter allowlist of non-interactive options; every other option-only launch stays denied.)

  A launch with options only, such as `python3 -B`, is denied.

### Deny output (FR12)

The deny object is a JSON object whose `hookSpecificOutput` member carries:
- `hookEventName`: `PreToolUse`
- `permissionDecision`: `deny`
- `permissionDecisionReason`: a Japanese sentence

The reason says that interactive mode cannot be used here and points to `python3 -c`, a script file, or `python3 - <<EOF`.

## Test Notes

- Every hook test runs a copy as a separate process: the PreToolUse JSON (with `tool_name` set to `Bash`) goes in on stdin, and the test checks stdout, stderr and the exit status. Never import the hook module, because a bytecode cache would be left inside the distributed plugin directory (IMPLEMENTATION.md Conventions).
- Heredoc cases need real multi-line command strings: the body line plus the terminator line.
- Add the AC-3 nesting edge as a `silent` case: a second-level shell literal (a `bash -c` literal that itself contains a `bash -c` literal) is not evaluated.
- AC-6's static check is a source-level test, not a runtime trace.
