# Task Plan: task0001 — Final-score evaluator and threshold/fallback rules

## Goal

The evaluator decides the tier from one final score object, validates its four
bucket probabilities before any threshold row is evaluated, keeps the
availability fallbacks, and no longer knows about two readings or their
disagreement. The rule table's threshold rows, tolerance and fallback matrix
match that behavior.

## Requirements

FR3, FR4, FR5, FR8, FR9, NFR1, NFR2, NFR3

## Scope

### Files to Create
- `tests/test_decide_tier_final_score.py` — evaluator behavior and rule-table tests for this task

### Files to Modify
- `em-workflow/scripts/decide-tier.py` — single final-score input, probability validation, decision order
- `em-workflow/references/tier-rules.yaml` — only the sections this task owns per IMPLEMENTATION.md SC-5

## Design

Contracts used here are pinned in IMPLEMENTATION.md and are not restated:
SC-1 (evaluator input/output and decision order), SC-2 (score object), SC-3
(`decided_by` vocabulary), SC-5 (which rule-table sections this task owns),
D4 (legacy input rejected), D5 (owned-scope absence checks), D6
(pre-existing tests).

### Rule-table changes (owned sections only)

- Threshold rows, over the final bucket probabilities, evaluated top-down with
  the first match winning:
  1. minimal: bucket 0 at or above 0.80
  2. reduced: bucket 0 plus bucket 1 at or above 0.85; no lower bound on
     bucket 0 alone (the former bucket-0 floor on this row is removed)
  3. full: every other case
- No row references `expectation_clear` or `confidence`.
- New member `probability_sum_tolerance`, initial value 0.02.
- `fallback_matrix`: the row that forces full when two readings disagree is
  removed; the `jev_only_usable` row's action becomes full; the
  `jev_unusable` row stays full.
- Any rule-table member that exists only to support the two-reading
  comparison is removed.
- `jev_exit_codes` and the decision-basis values stay unchanged.

### Evaluator behavior

- Decision order is SC-1's steps (0) to (4). The rule table is read first; a
  missing or malformed threshold row, lower bound or tolerance gives full
  with a reason naming that member. No numeric value for any of them is held
  in the evaluator.
- Probability validation rules:
  - The four bucket keys `"0"` to `"3"` must all be present; a key outside
    that set is invalid.
  - Booleans and strings are not numbers. NaN and positive or negative
    infinity are not finite. Each value must lie in [0, 1].
  - The absolute difference between the four-bucket sum and 1 must not
    exceed `probability_sum_tolerance`; the boundary value itself passes.
  - Reason text names the offending bucket key for a missing, extra,
    non-numeric, non-finite or out-of-range bucket, and states the computed
    sum for a sum failure. The sum check runs only after every bucket passed,
    so the stated sum is always finite.
- Floating-point boundary: a bucket value, or a two-bucket sum, that equals a
  row's lower bound when both are written in decimal satisfies the row (the
  TS-4 boundary inputs). This must hold without adding a numeric epsilon
  constant to the evaluator (NFR1).
- Output is strict JSON in every case; no input value that is non-finite is
  echoed as a NaN or Infinity token.
- The evaluator makes no model call, spawns no process and opens no network
  connection.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR4; TS-1, TS-2, TS-3, TS-4): with both flags true, final bucket probabilities 0.09 / 0.90 / 0.01 / 0.00 give reduced with `decided_by` `threshold_rows:reduced`; 0.37 / 0.59 / 0.03 / 0.01 give reduced; 0.85 / 0.10 / 0.05 / 0.00 give minimal both with `expectation_clear` 0.1 and without `expectation_clear`; 0.50 / 0.30 / 0.15 / 0.05 give full; boundary 0.80 / 0.10 / 0.05 / 0.05 gives minimal; boundary 0.50 / 0.35 / 0.10 / 0.05 gives reduced.
- [ ] AC-2 (FR3, NFR1; TS-5): a final score missing bucket `"3"`, one with bucket 2 set to NaN, one with bucket 1 at 1.2, and one whose four buckets sum to 1.10 each give full; the reason names bucket `"3"`, `"2"`, `"1"` respectively, or states the sum; stdout is accepted by a JSON parser that rejects NaN and Infinity; the exit code is 0 in every case.
- [ ] AC-3 (FR5; TS-6): an input carrying the legacy `readings` member gives full as invalid input; the string `readings_disagree` appears neither in `em-workflow/scripts/decide-tier.py` nor in `em-workflow/references/tier-rules.yaml`; `fallback_matrix` has no row keyed on disagreement between readings.
- [ ] AC-4 (FR8; TS-7): `codex_available` false with a final score that would otherwise be minimal gives full with `decided_by` `fallback_matrix:jev_only_usable`, not a `threshold_rows:` value; the rule table's `jev_only_usable` row action is full.
- [ ] AC-5 (FR9; TS-8): `jev_available` false gives full with `decided_by` `fallback_matrix:jev_unusable`, both with `codex_available` true and with it false; `jev_exit_codes` classifies each of the exit codes 1, 2 and 75 as unusable.
- [ ] AC-6 (NFR1, NFR2; TS-13): the rule table holds exactly the three threshold rows above in that order with lower bounds 0.80 and 0.85, declares `probability_sum_tolerance` as 0.02, and has no row on `confidence` or `expectation_clear`; given a rules table lacking the tolerance, or lacking a threshold row's lower bound, the evaluator gives full with a reason naming the missing member; the evaluator source references no process-spawning, network or model facility.
- [ ] AC-7 (NFR3): `python3 -m unittest discover -s tests` passes in this task's worktree; pre-existing tests that assert the two-reading input, the bucket-0 floor on the reduced row or the disagreement fallback are rewritten to the new contract (IMPLEMENTATION.md D6); every raw-text matcher in this task's tests has a negative proof and a non-vacuity guard.

## Test Notes

- Exercise the evaluator as a black box through its normal invocation
  channel, so the exit code and the exact stdout bytes are observed. The
  strict-JSON check parses stdout with non-finite constants rejected.
- AC-2's NaN case needs an input whose bucket 2 is non-finite. Build that
  input so the evaluator actually receives a non-finite value rather than a
  string.
- AC-6's missing-member cases need a modified rules table. If the evaluator
  offers no way to point at a different table, run a copy of the evaluator
  beside a modified copy of the table in a temporary directory that mirrors
  the plugin layout. Never modify the real table in a test.
- Raw-text scans (absence of `readings_disagree`, no row on `confidence`, no
  process or network facility in the evaluator source) each get a forged
  snippet containing the forbidden text on which the same matcher must fail,
  and a guard that the scanned file was read and is non-empty.
- Boundary inputs in AC-1 are exact decimal values as written; do not
  perturb them in the test.
