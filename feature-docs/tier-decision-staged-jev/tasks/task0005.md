# Task Plan: task0005 — em-workflow plugin version bump to 0.2.10

## Goal

The em-workflow plugin version is raised from 0.2.9 to 0.2.10, identically in
the plugin manifest and in the marketplace entry, so installed copies pick up
this feature.

## Requirements

NFR3, NFR5

## Scope

### Files to Create
- `tests/test_em_workflow_version.py` — version consistency test for the two manifests

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — version 0.2.9 becomes 0.2.10
- `.claude-plugin/marketplace.json` — the em-workflow entry's version 0.2.9 becomes 0.2.10

## Design

- Target value and ownership are IMPLEMENTATION.md SC-7.
- Only the em-workflow entry of the marketplace file changes; every other
  plugin entry and every other member stays as it is.
- A version is compared as dot-separated integer components, left to right;
  0.2.10 is greater than 0.2.9.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (NFR5; TS-12): the `version` in the em-workflow plugin manifest equals the `version` of the em-workflow entry in the marketplace file.
- [ ] AC-2 (NFR5; TS-12): that version is greater than 0.2.9 under component-wise integer comparison, and the test proves its comparison is numeric by ranking 0.2.10 above 0.2.9, an ordering a plain text comparison gets wrong.
- [ ] AC-3 (NFR3): both manifests still parse as JSON; `python3 -m unittest discover -s tests` passes in this task's worktree using only standard-library `unittest`.

## Test Notes

- The test locates the em-workflow entry in the marketplace file by its
  plugin name, and fails (rather than passing vacuously) when the entry or
  either `version` member is missing.
- The test must keep holding after future version bumps: it asserts equality
  and "greater than 0.2.9", never equality with 0.2.10.

## Out of Scope

- Versions of other plugins in the marketplace file.
- Any change under `em-workflow/` other than the plugin manifest.
