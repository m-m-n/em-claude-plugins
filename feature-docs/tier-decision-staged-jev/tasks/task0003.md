# Task Plan: task0003 — Staged tier-decision procedure in develop SKILL.md Step A

## Goal

The Step A tier-decision section of the develop skill runs Jev on the task
description alone, then the read-only Codex pre-survey, then a final Jev call
on the description plus both JSON results; it hands the evaluator one final
score with availability flags and records the outcome as tier.yaml
schema_version 2, with no disagreement rule, no threshold literal, and no gate
or question.

## Requirements

FR1, FR2, FR5, FR6, FR8, FR9, FR10, FR12, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_develop_tier_staged_procedure.py` — raw-text conformance tests for the Step A tier-decision section

### Files to Modify
- `em-workflow/skills/develop/SKILL.md` — only the Step A tier-decision section, per IMPLEMENTATION.md SC-6

## Design

Contracts pinned in IMPLEMENTATION.md and not restated: SC-1 (evaluator
payload), SC-2 (score object and Jev usability), SC-3 (`decided_by`
distinction), SC-4 (record members and presence rules), SC-6 (this task's
section), D2 (evaluator always invoked), D3 (call-skipping rules), D7 (resume
reuse).

### Procedure the section describes

1. Resume: when a tier.yaml already exists (schema_version 1 or 2), it is
   reused as-is; no call is made and the record is not rewritten.
2. First Jev call, basis `description_only`: judgment skill `~/.claude/skills/jev`
   with `--json-input` / `--json-output`; input is the task description plus
   the bucket descriptions from the rule table's `question_set` (cited by
   name, not restated). An unusable result (SC-2) is noted and the procedure
   continues.
3. Codex read-only pre-survey through `run_codex_exec.sh readonly`, asked for
   the facts of the rule table's `codex_output_schema` (cited by name). Step
   6 of the section defines Codex usability: a non-zero exit, output that
   does not parse as JSON, or a missing required field makes it unusable.
4. When the pre-survey is usable and reports no remaining work, the existing
   no-work-required stop ends the run here: before the final Jev call and
   before any workflow step.
5. Final Jev call, basis `description_plus_code`, made only when the first
   Jev call and the pre-survey were both usable: input is the task
   description, the first Jev call's full JSON result including its
   confidence, the Codex JSON, and the `question_set` bucket descriptions.
   A non-zero exit (per `jev_exit_codes`) makes Jev unavailable.
6. Evaluator invocation with the SC-1 payload: `final_score` when obtained,
   `codex_available`, `jev_available`. The evaluator is invoked on every
   path, fallbacks included, and decides the tier (D2).
7. Record `phase-state/tier.yaml` as schema_version 2 per SC-4: a `bases`
   entry only for each usable Jev call, `pre_survey_estimate` only when the
   pre-survey was usable, and `fallback_reason` when `decided_by` does not
   start with `threshold_rows:`.

### Removals and constraints inside the section

- The two-reading comparison, the disagreement fallback and the string
  `readings_disagree` are removed.
- No decimal threshold literal, no `P(0)` and no `expectation_clear` appear in
  the section; thresholds are cited from the rule table (NFR2).
- No gate_id, no AskUserQuestion and no user question on this path, in
  interactive and batch mode alike (NFR4).
- Jev exit codes are cited from `jev_exit_codes`, not listed.
