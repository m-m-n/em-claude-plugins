## Goal

Document the cross-repo-write-guard hook in `em-workflow/README.md` (guardrail
hook table, PreToolUse(Bash) count and order, opening sentence) and add the
`## cross-repo-write-guard` section to `.claude/rules/hook-tests.md`,
consistent with IMPLEMENTATION.md contracts C1, C2 and C3.

## Requirements

FR13, FR15

## Scope

### Files to Create
- `test-docs/cross-repo-write-guard/task0002.tests.yaml` — per-task test record, when the implement phase produces one for a documentation-only task (format owned by the implement phase)

### Files to Modify
- `em-workflow/README.md` — hook table row, Bash hook count and order, opening sentence
- `.claude/rules/hook-tests.md` — new ## cross-repo-write-guard section

## Design

- **Source of truth**: this task's worktree contains neither the hook nor its
  registration; both are built in parallel. Every statement about the hook is
  taken from IMPLEMENTATION.md C1 (path, registration groups and positions),
  C2 (behavior) and C3 (test module, run command, `CASES` shape) — not from
  this worktree's `hooks.json`, which still holds the pre-change 9 Bash
  entries (IMPLEMENTATION.md D2).
- **README hook table**: one row for `cross-repo-write-guard.py` whose event
  column names both PreToolUse(Bash) and PreToolUse(Write|Edit|MultiEdit), in
  whatever way the table already expresses an event. The summary states, in
  the table's existing language and tone: a write whose destination lies
  outside the cwd's git toplevel is sent to confirmation (`ask`), downgraded
  to `deny` under unattended runs; destinations under `/tmp` and
  `~/.claude/` and the listed `/dev` sinks are not judged; destinations that
  cannot be resolved statically are not judged.
- **README Bash count and order**: every place that states how many
  PreToolUse(Bash) hooks there are says 10, and every place that lists their
  order puts `cross-repo-write-guard.py` immediately after
  `loop-command-guard.py` and immediately before `destructive-guard.py`.
- **README opening sentence**: the sentence carrying the outdated "4 本同梱"
  count is rewritten so it states no number of hooks (SPEC A-14). No rows are
  added for `muse_guard.py` or `heredoc-stdin-guard.py`.
- **hook-tests.md section**: appended after the existing sections and shaped
  like the `## loop-command-guard` section: a change to
  `em-workflow/hooks/cross-repo-write-guard.py` requires running the C3 run
  command in the same change; cases live in the C3 module's `CASES` as
  `(期待する判定, ラベル, コマンド)`; the expected decision is `ask` or
  `silent`.
