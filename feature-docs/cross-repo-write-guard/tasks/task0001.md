## Design

### Processing flow (one invocation)

1. Read all of stdin and parse it as JSON. Anything other than a JSON object →
   no output.
2. Validate: `tool_name` is one of `Write`, `Edit`, `MultiEdit`, `Bash`;
   `cwd` is a non-empty string; `tool_input` is an object; `file_path`
   (Write / Edit / MultiEdit) or `command` (Bash) is a non-empty string. Any
   failure → no output.
3. Collect candidate destinations:
   - Write / Edit / MultiEdit: the `file_path` as one literal path (no shell
     interpretation other than the leading-tilde rule of step 4).
   - Bash: the result of the command analysis below. A command that cannot be
     parsed as a whole → no output.
4. Expand a leading `~` alone or a leading `~/` (unquoted, for Bash) using
   `HOME` from the process environment; when `HOME` is unset or empty such a
   destination is unresolvable. `$HOME` / `${HOME}` are variable expansions,
   not tildes.
5. Drop destinations marked unresolvable (FR9), and drop destinations that
   are still relative after step 4 and carry the "relative destinations
   suppressed" flag (FR10). Other destinations of the same command keep being
   judged.
6. Make relative paths absolute against the payload `cwd`, then normalize `.`
   and `..` literally.
7. Drop `/dev/null`, `/dev/stdout`, `/dev/stderr`, `/dev/tty` and anything
   under `/dev/fd/` by literal comparison of the step-6 path (before any
   symbolic-link resolution). Other `/dev` paths continue.
8. Resolve each remaining path with real-path semantics: resolve symbolic
   links along the longest existing prefix and append the non-existent
   remainder. Resolve the exclusion roots `/tmp` and `HOME/.claude` the same
   way and drop destinations equal to or below either root, comparing at
   path-component boundaries.
9. No destination left → no output, and git is never started (NFR2).
10. Start git exactly once: `rev-parse --show-toplevel` with the payload `cwd`
    as the working directory, as an argument vector with no shell (payload
    text never becomes command-line text), located through `PATH`, under a
    fixed time limit shorter than the hook's 15-second timeout (NFR3).
    Missing git, non-zero exit, empty output, time-limit expiry (the git
    process is terminated) or any error → no output. Resolve the toplevel
    with the step-8 semantics.
11. A destination is outside when it is neither equal to nor below the
    resolved toplevel at a path-component boundary (`/repo` does not contain
    `/repo-other`). A linked worktree's toplevel is its own directory, so a
    write from it into the main working tree is outside (FR3). No outside
    destination → no output.
12. Emit exactly one decision per C2: `ask`, reason beginning with
    `[cross-repo-write-guard]`, listing each outside destination's resolved
    absolute path once and the toplevel. When `CLAUDE_BATCH` holds any value
    other than empty, `0`, `false` or `no`, emit `deny` instead and append a
    notice that the decision was downgraded. Never emit `allow`.
13. The whole flow is guarded: any unexpected exception → no output. The exit
    code is 0 on every path.

### Bash command analysis

The analysis reads the command text statically and yields either
"unparseable" or an ordered list of destinations. Each destination is a
literal word (with whether its leading tilde was unquoted) or the marker
"unresolvable", and carries a flag "relative destinations suppressed".

**Lexical rules**
- Single quotes are literal. Double quotes are literal except for `$`,
  backquote and backslash. Outside quotes a backslash escapes the next
  character; backslash-newline continues the line.
- `$'…'` and `$"…"` quoting is not handled: a word containing it is
  unresolvable.
- An unquoted `#` at the start of a word starts a comment that runs to the
  end of the line.
- Statements are separated by newline, `;`, `&`, `&&`, `||`, `|` and `|&`.

**Expansions and bodies (FR8, FR9)**
- `$( … )`, `$(( … ))`, backquotes, `<( … )` and `>( … )` are consumed
  (honoring nesting and quoting) only to find their end; their bodies are
  never analyzed as commands. A word containing one is unresolvable.
- A word containing a `$` parameter expansion (`$NAME`, `${…}`, `$1`, …) is
  unresolvable. A word containing an unquoted `*`, `?` or `[` is
  unresolvable.
- The string argument of `bash -c` (and similar) is an ordinary word, so its
  content is never analyzed; redirections of that statement are judged.

**Heredocs**
- `<<` and `<<-` with a quoted or unquoted delimiter: the body lines are
  skipped up to the delimiter line (leading tabs stripped for `<<-`). A
  missing delimiter line makes the whole command unparseable. `<<<` is input.

**Grouping (FR8, FR10)**
- `( … )` is a subshell and `{ … }` a brace group (`{` and `}` recognized at
  command position). Commands inside both are analyzed. Redirections written
  after the closing `)` or `}` apply to the group and are judged.
- Unterminated quotes, unterminated substitutions and unbalanced grouping
  make the whole command unparseable.

**Redirections (FR7 a)**
- Destinations: the word after `>`, `>>`, `>|`, `&>`, `&>>`, and after a digit
  sequence immediately followed by `>`, `>>` or `>|`. The word may be
  attached to the operator or follow whitespace.
- `>&N`, `N>&M`, `>&-` and `N>&-` duplicate or close descriptors and yield no
  destination. Input redirections yield no destination.
- Redirections are judged on every simple command whatever its command name.

**Command position (FR7 b–d, FR8)**
- Skip leading assignments (`NAME=value` words). Skip the wrappers `sudo`,
  `env`, `nohup`, `time`, `command`, `nice` together with their options
  (an option that takes a separate argument consumes it; `env`'s
  `NAME=value` words are assignments). Wrapper options that change the
  working directory (`env -C` / `--chdir`, `sudo -D` / `--chdir`) set the
  statement's suppression flag (FR10).
- The command name that remains selects:
  - `tee`: every non-option word is a destination (after `--`, every word).
  - `sed`: only when in-place editing is requested per GNU sed (`-i` with an
    optional attached suffix, `--in-place` with an optional `=SUFFIX`, or a
    short-option cluster containing `i`). The script comes from `-e` /
    `--expression` / `-f` / `--file` when present, otherwise it is the first
    non-option word; every remaining non-option word is a destination.
  - `cp`, `mv`: the directory of `-t DIR`, `-tDIR`, `--target-directory=DIR`
    or `--target-directory DIR` when present; otherwise the last operand
    when there are two or more operands. `mv`'s sources are never
    destinations.
  - Any other command yields no command-based destination.

**Working-directory tracking (FR10)**
- A statement whose command name is `cd`, `pushd` or `popd` sets the
  suppression flag on every later statement at the same nesting level and on
  everything nested inside those later statements.
- A brace group shares the shell: a `cd` inside it keeps suppressing after
  the closing `}`. A subshell confines a `cd` inside it to the subshell.
- Absolute and tilde-expanded destinations are judged regardless of the flag.

## Test Notes

- Locate the hook relative to the test file's own location, so both
  `python3 -m unittest tests.test_cross_repo_write_guard` and
  `python3 -m unittest discover -s tests` find it. Run it with the current
  interpreter.
- Build each hook run's environment explicitly: `HOME` set to a temporary
  directory outside `/tmp` and outside the fixture repository (so an
  unquoted `~/x` is judged outside); `CLAUDE_BATCH` removed unless the test
  sets it (the suite itself may run under an unattended session that sets
  it); inherited git location variables such as `GIT_DIR` and
  `GIT_WORK_TREE` removed.
- Fixture repositories live under a temporary root outside `/tmp` (for
  example under `/var/tmp`, SPEC A-13): under `/tmp` every destination would
  be excluded and no `ask` case could be produced. Fixture commits (needed
  before `git worktree add`) supply the author identity explicitly instead of
  relying on any global git configuration.
- `CASES` commands are static strings run with the fixture repository as
  `cwd`: inside destinations as relative paths; outside destinations as
  absolute paths outside the fixture root, `/tmp` and the substituted `HOME`
  (a placeholder replaced by a fixture-derived outside path is acceptable).
  Symbolic links, worktrees and the `repo` / `repo-other` boundary need real
  fixtures and go in dedicated tests.
- Assert exit code 0 for every run, and that no run's output contains an
  `allow` decision.
- AC-9 uses a stub git placed first on `PATH`: it records each invocation to
  a file in its own temporary directory and prints a toplevel. For the
  time-limit case the stub waits far longer than the limit as a single
  process (it replaces itself with the waiting program), so terminating it
  on expiry leaves nothing behind. The shell-metacharacter case uses a
  directory name containing command-substitution and separator characters
  that would create a marker file if executed, and asserts the marker is
  absent.
- The time-limit test lasts about as long as the chosen limit; keep the limit
  well below 15 seconds.
- AC-3's "cwd does not exist" case exercises the failure containment of
  FR11.
