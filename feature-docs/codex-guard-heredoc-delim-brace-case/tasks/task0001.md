# Task Plan: task0001 — Case-aware skip of `$( )` inside a heredoc delimiter's `${ }` range

## Goal

In both copies of codex-hook-interactive-guard, an unquoted `$( ... )`
(`$(( ... ))` included) inside the `${ ... }` range of a `<<` / `<<-`
delimiter is skipped by the case-aware substitution skip and kept as written,
quotes inside it included. The registered delimiter then equals the one zsh
uses, and an interactive launch after the real terminator line is denied
again.

## Design

### Current behaviour (the defect)

At the delimiter position, `_dollar` hands an unquoted `${` to
`_remove_range_quotes` in its braced reading, with the end of the input as the
limit. At an unquoted `$(` inside that range, the braced reading locates the
close with the paren scan (`_skip_parens` / `_scan_parens`). The paren scan
counts parentheses and does not read case statements. In
`${v:-$(case x in x) echo "x";; esac)}` the pattern's `)` ends the scan, the
rest of the substitution is read as ordinary range text, and its double quotes
are removed. The registered delimiter differs from the terminator line zsh
compares with, the terminator line is taken as body, and the launch after it
is passed over (no output).

### Reading after the change

1. Braced range (`braced` true), unquoted `$` directly followed by `(`
   (so `$((` too): the range reading hands it to the shared reader
   `_read_quoted_unit`, held to the range's limit, appends the text it
   returns, and goes on at the index it returns. The dynamic indication is
   ignored there, as for the other units. The unquoted `$'` / `$"` check keeps
   priority over this branch, as it has now.
2. `_read_quoted_unit` accepts one more start: an unquoted `$` directly
   followed by `(`. For that start it:
   - skips the substitution with `_skip_substitution`, starting at the `$`;
   - raises the undecidable signal when the skip ends beyond `limit`, and lets
     the undecidable signal of `_skip_substitution` propagate unchanged;
   - otherwise returns the original characters from the `$` through the end
     of the skip, unchanged; the index just after the skip; and dynamic true.
   The backslash, single-quote and double-quote starts keep their reading.
3. Parenthesised range (`braced` false): an unquoted `$(` keeps the paren
   scan. Nothing changes there.
4. These readings do not change (FR3): a `$( ... )` written directly in the
   delimiter word, outside any `${ ... }` (read by `_dollar` with the paren
   scan); a `${ ... }` in a word that is not a delimiter; a backquote inside a
   delimiter's `${ ... }` (an ordinary character); the rule that an unquoted
   `$'` / `$"` at the delimiter position is undecidable; substitutions inside
   double quotes in the delimiter.

### Contract of `_read_quoted_unit` after the change

- Precondition: `start < limit`. The character at `start` is a backslash, a
  single quote, a double quote, or an unquoted `$` directly followed by `(`.
  Only the braced reading of `_remove_range_quotes` passes a `$(` start.
  `parse` never does, because it hands an unquoted `$` to `_dollar`, so
  `parse`'s calls behave as before.
- Postcondition: the returned index never lies beyond `limit`. For a `$(`
  start, the returned text equals the original characters of the
  substitution and dynamic is true.
- Raises the undecidable signal in the cases listed in step 2, in addition to
  its existing cases.

### Call structure (NFR2)

- `_read_quoted_unit` stays the only `_Parser` method that calls
  `_skip_substitution`. `_remove_range_quotes` never calls it directly.
- No method reachable from `_skip_substitution` is `_skip_substitution`,
  `_read_quoted_unit`, `parse` or `_remove_range_quotes`. The new path is the
  one-way chain `_remove_range_quotes` → `_read_quoted_unit` →
  `_skip_substitution`. It has no recursion and no call cycle.
- `_skip_substitution`'s own reading is not expected to change. If a test row
  shows that it must change, report it as a plan deviation.

### Linear time (NFR1)

Each `$( ... )` in the range is skipped once by `_skip_substitution`. The
range reading goes on after the end of the skip and never re-reads a character
of the substitution. A skip that ends beyond the limit ends the whole reading
(undecidable), so it happens at most once.

### Docstrings (FR5)

- Module docstring, delimiter-position passage: an unquoted `$( ... )` or
  `$(( ... ))` inside a delimiter's `${ ... }` range is skipped by the same
  case-aware skip used for a substitution inside double quotes. A case
  statement inside it is read, and its pattern's `)` does not end it. It is
  kept as written, with its quotes. The string is undecidable when that skip
  cannot locate the close. Inside a parenthesised range, and in a `$( ... )`
  written directly in the delimiter word, the reading is unchanged.
- `_remove_range_quotes`: which reader reads an unquoted `$(` in each kind of
  range, and the resulting undecidable cases.
- `_read_quoted_unit`: the new start, what it returns, and its undecidable
  cases. The statement that limits the start character to a backslash, a
  single quote or a double quote is removed.
- `_skip_substitution`: its opening sentence no longer limits the substitution
  to one inside double quotes, and it names the unquoted `$(` of a delimiter's
  `${ ... }` range as the other place it is reached from.
- Every marker sentence the existing documentation tests look for stays
  present, and no sentence those tests list as stale comes back.
