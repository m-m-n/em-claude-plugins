# Task Plan: task0001 — Section-scoped exemption registry in a shared test helper

## Goal

Only rows inside the `## Exemption registry` section of the registry
document can exempt a gate from the correspondence sweep, and invalid rows
raise. The extractor, parser, validator and loader exist once, in a non-test
helper under `tests/`, and both gate-vocabulary test modules use it.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create
- `tests/_gate_vocabulary.py` — shared non-test helper holding the section extractor, row parser, row validator and exemption loader

### Files to Modify
- `tests/test_gate_option_vocabulary_doc.py` — import the extractor, parser and validator from the helper, delete the local parser and validator, route every registry-section lookup through the shared extractor
- `tests/test_gate_option_vocabulary.py` — import the loader from the helper, delete the local loader, pass the select gate-id set at the sweep call site, rewrite the existing registry fixtures, add the hermetic regression tests, update stale wording

## Design

The helper's callable surface, its contracts, the gate_id derivation rule and
the error-handling policy are pinned in IMPLEMENTATION.md (Shared Components,
Conventions). This section covers only what this task does in each file.

### Helper module

- Implements the four callables exactly per IMPLEMENTATION.md Shared
  Components.
- Holds no `TestCase` subclass and imports only standard-library modules.
- Its module docstring states that it is a non-test helper, why its file
  name does not match `test*.py`, and the degrade / raise policy (three
  fail-safe empty-set conditions; everything else malformed raises).

### Doc-side module (`test_gate_option_vocabulary_doc.py`)

1. Remove the local definitions of the row parser and row validator; import
   both, plus the section extractor, from the helper under the same names.
2. The registry-section accessor used by `TestExemptionRegistryStructure`,
   and the section lookup inside
   `test_the_real_documents_zero_rows_produce_zero_violations`, both obtain
   the section through the shared extractor. When the extractor returns its
   no-section result for the real document, the accessor fails the test with
   a message saying the section is missing. It never hands a no-section
   result to the parser.
3. Every other section lookup (Correspondence rule, Why it matters,
   Canonical declaration format, Issuing-site map, Scope) keeps using the
   module's own generic slicer, unchanged.
4. The restricted-subset `gate_policies:` parser and the select-id helper
   stay local to this module.
5. The module docstring's AC-4 paragraph now says the registry validator
   lives in the shared helper.
6. All existing assertions of the AC-3 and AC-4 test classes stay as they
   are. They are the regression net for the parser and validator behaviour.

### Consumer-side module (`test_gate_option_vocabulary.py`)

1. Remove the local loader; import it from the helper.
2. Correspondence sweep call site: pass the set of `action: select` gate ids
   derived from the policy that `TestRepositoryCorrespondence` already parses
   in its class setup.
3. `TestExemptionRegistryDegrade`, existing tests:
   - Absent-file test: passes an explicit select set and still expects an
     empty set.
   - Present-file test (FR7): the fixture uses the level-2
     `## Exemption registry` heading and one row naming a real select gate id
     (for example `create-spec.feature-identity`) with a non-empty reason and
     a non-empty guarantee. The passed select set contains that id, and the
     test expects exactly that id.
   - Zero-row test (FR7): same heading rewrite, and it still expects an empty
     set.
   - Real-repository test (FR8, SPEC A-5): renamed, with a new comment, so
     that both say the registry is present with zero rows. It asserts that
     the real registry file exists. It also asserts that the loader, given
     the select set derived from the real `batch-policies.yaml`, returns an
     empty set.
4. New hermetic regression tests (FR6, plus the FR1/FR2 edge cases), in
   `TestExemptionRegistryDegrade` or a new sibling class. Each builds a
   synthetic registry document in a temporary directory and calls the loader
   with an explicit select set:
   - (a) a `## Gate option vocabulary`-style table, whose data row names
     `create-spec.feature-identity`, placed before a zero-row
     `## Exemption registry`, gives an empty set;
   - (b) the registry holds one valid row for select gate X, and a later
     `## Scope` section holds a table whose row names a different select gate
     Y. The result is exactly {X};
   - (c) four separate documents: a row missing its reason, a row missing its
     guarantee, a row naming a gate outside the select set, and a row with 2
     cells. Each one makes the loader raise `ValueError`. The three
     validation cases also assert that the message contains the matching
     violation substring;
   - (d) one valid row for a select gate gives exactly that gate id;
   - (e) an absent file gives an empty set;
   - a `### ` subheading inside the registry section, followed by the table,
     still yields the table's valid row;
   - a document whose only registry-like heading is `### Exemption registry`
     (holding a valid-looking row) gives an empty set, and so does a document
     that mentions `## Exemption registry` only mid-line in prose;
   - a present `## Exemption registry` section with prose but no table
     raises `ValueError`.
5. Stale wording (SPEC A-5): the module docstring paragraph saying the
   registry is absent "in this task's own worktree" is updated to say it is
   present with zero rows. The paragraph also says exemption parsing lives
   in the shared helper. The class docstring of `TestExemptionRegistryDegrade`
   is updated the same way.
6. `ISSUING_SITE_MAP`, `D1_PAIRED_GATES`, the `## Gate option vocabulary`
   block parser, and every `TestFrozenMachineReadSurface` constant stay
   untouched.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR4, NFR1, NFR5): `tests/_gate_vocabulary.py` exists. Its file name does not match `test*.py`, it defines no `TestCase` subclass, and it imports only standard-library modules. It is the only module under `tests/` that defines `extract_exemption_registry_section`, `parse_exemption_table_rows`, `validate_exemption_rows` and `load_exempt_gate_ids`. Both `tests/test_gate_option_vocabulary_doc.py` and `tests/test_gate_option_vocabulary.py` obtain the names they use from the helper, and neither test module imports the other.
- [ ] AC-2 (FR1): Hermetic tests show the shared extractor's section boundaries. The section starts after the first line that is exactly `## Exemption registry`. It ends before the next line beginning with `## `, or at end of text. A `### ` subheading inside it does not end it. A `### Exemption registry` heading and a mid-line mention of `## Exemption registry` are not section starts. A document without the heading gives the no-section result, which the loader turns into an empty set.
- [ ] AC-3 (FR2): Hermetic tests show that the row parser skips the header and separator rows and returns one 3-tuple of stripped cells per data row. It raises `ValueError` for a data row with a cell count other than 3, and for a section that holds no pipe-table line. The existing doc-side tests `test_registry_holds_zero_rows` and the `TestExemptionRegistryValidatorAgainstSyntheticRows` cases pass with their assertions unchanged.
- [ ] AC-4 (FR3): `validate_exemption_rows` returns an empty list for a valid row. For the matching defects it returns violation strings containing `missing a reason`, `missing a compensating guarantee` and ``not an `action: select` entry``. When that list is non-empty, `load_exempt_gate_ids` raises `ValueError` whose message contains every violation string.
- [ ] AC-5 (FR5, FR6): Hermetic synthetic-document tests of `load_exempt_gate_ids` with an explicit select set cover the following cases. (a) An unrelated `## Gate option vocabulary`-style table naming `create-spec.feature-identity` (a member of the passed select set), placed before a zero-row `## Exemption registry`, gives an empty set. (b) A table in a `## Scope` section after the registry is not counted; with one valid registry row for gate X, the result is exactly {X}. (c) A row missing its reason, missing its guarantee, naming a gate outside the select set, or having a wrong cell count each raises `ValueError`. (d) A valid row gives exactly its gate id. (e) An absent file gives an empty set. The (a) and (b) tests each assert, as a non-vacuity precondition, that their fixture holds a pipe-table line naming the unrelated gate outside the extracted registry section.
- [ ] AC-6 (FR7, FR8): Both existing `TestExemptionRegistryDegrade` registry fixtures use the level-2 `## Exemption registry` heading. The present-file fixture names a real select gate id and returns exactly that id. The real-repository test asserts that `em-workflow/references/gate-option-vocabulary.md` exists and that the loader, given the select set derived from the real `batch-policies.yaml`, returns an empty set. Its name, its comment and the module docstring no longer say the registry is absent. The correspondence sweep passes the select gate-id set to the loader and still checks every gate in `ISSUING_SITE_MAP`.
- [ ] AC-7 (NFR2, NFR3, NFR4): `python3 -m unittest discover -s tests` passes. The task's diff touches only the three files in Scope. Nothing under `em-workflow/` changes, and neither `em-workflow/.claude-plugin/plugin.json` nor `.claude-plugin/marketplace.json` is edited. `ISSUING_SITE_MAP` remains defined in `tests/test_gate_option_vocabulary.py`. `TestFrozenMachineReadSurface` passes with its digest constants unchanged.

## Test Notes

- TDD order: first write the regression tests and the extractor-boundary
  tests in the consumer module against the new loader signature (path plus
  select set). They fail until the helper exists and the local loader is
  gone. The old whole-document scan returns `create-spec.feature-identity`
  for case (a), which is the ticket's reproduction.
- Non-vacuity for (a) and (b): assert inside the test that the synthetic
  document holds a pipe-table line naming the unrelated gate, and that this
  line is not inside the extractor's returned section. A mis-built fixture
  then fails instead of passing vacuously.
- Hermetic select sets are explicit literal sets holding real gate ids (for
  example `create-spec.feature-identity`, `create-plan.existing-files`).
  They do not read `batch-policies.yaml`. Only the real-repository test and
  the sweep use the parsed policy.
- Loader tests write synthetic documents to a temporary directory, because
  the loader reads from disk. Extractor and parser tests may use in-memory
  strings.
- AC-2 cases may be asserted on the extractor directly or through the
  loader. The no-section case must be observed through the loader, because
  the empty-set degrade is the loader's behaviour.
- Import check (SPEC A-6): run the canonical discover command, and also run
  each edited test module directly as a script. Both must resolve the
  helper. Report any other invocation that fails as a plan deviation. Do not
  work around it silently.
- AC-7's file-set and version checks are diff inspections, not unit tests.
  The implementer confirms them before handing off.
