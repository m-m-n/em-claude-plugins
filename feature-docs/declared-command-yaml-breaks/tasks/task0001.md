# Task Plan: task0001 — declared_commands に YAML 改行文字を端から除いた形を足し、回帰テストを追加する

## Goal

A workflow.yaml `*_command` declaration whose quoted value has U+0085, U+2028 or U+2029 at either end is denied as unapproved by the bash_guard hook in its raw, YAML-parsed and end-stripped forms, with no allow path widened. A subprocess-level regression test pins this.

## Requirements

FR1, FR2, FR3, FR5, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `tests/test_bash_guard_declared_yaml_breaks.py` — new regression test module with its own fixture: a repository with declarations, a repository without declarations, and an isolated approval store holding only /usr/bin/true.

### Files to Modify
- `em-workflow/hooks/bash_guard.py` — declared_commands adds form (b) for every extracted value.
- `tests/test_bash_guard_unicode_whitespace.py` — no change expected. It is listed so that, if an existing assertion turns out to pin a no-verdict outcome for a form FR1 now denies, adjusting that one assertion stays inside this task's file set. Any such change is named in the implementer's report. The assertions at lines 418 and 422 and the declared_lines fixture stay byte-identical in every case.

## Design

### `declared_commands` after the change

Contract (IMPLEMENTATION.md Shared Components, "Declared-set end-stripped form"):

1. Read workflow.yaml and extract values exactly as today (`strip_yaml_quotes`, then the existing exclusion of empty, `"null"` and `"~"` values).
2. For each remaining value, add `trim_blanks(value)` when non-empty (form (a), unchanged).
3. For the same value, add the value with every leading and trailing character from the end-strip set (U+0020, U+0009, U+0085, U+2028, U+2029) removed, when the result is non-empty (form (b)).
4. Identical entries collapse; everything else about the returned set is as before.

Constraints on step 3:
- Only the five characters are removed. The language's default whitespace strip, which removes every whitespace character, is not used on the value.
- Form (b) gets no extra `"null"` / `"~"` exclusion (SPEC A4).

Line reading stays as it is: lines end only at LF, CR and CRLF, so U+0085, U+2028 and U+2029 remain inside the value (SPEC A3). No line splitter that also breaks at those three characters is introduced.

### Unchanged behavior (FR3)

`trim_blanks`, `is_matchable`, `approved_for`, the exact-match allow and the cd-prefix allow in `hook_main`, `read_stdin_commands`, and `--record` / `--remove` / `--list`. The declared set keeps being used only for the workflow-relevance judgment and the unapproved deny (IMPLEMENTATION.md, D1).

### Source constraints

- The end-strip set may be a module-level constant. Its name, its value and any comment next to it contain no substring `status`; U+0085, U+2028 and U+2029 are written as escape sequences, never as raw characters.
- No new top-level function; the order `strip_yaml_quotes`, `trim_blanks`, `is_matchable`, `declared_commands` is kept.
- Module docstring phrases pinned by tests stay: `after removing surrounding spaces and tabs only`, `any other whitespace at either end is never allowed`, and the cd-prefix approval item. If the docstring describes how declared commands are extracted, it may be extended to mention form (b) under the same constraints.

### Expected decisions (approval store holds only `/usr/bin/true`)

| Declared value (quoted) | Command passed to the hook | Expected |
|---|---|---|
| U+0085 + `./unapproved` | U+0085 + `./unapproved` (raw) | deny, unapproved (form (a)) |
| U+0085 + `./unapproved` | one space + `./unapproved` (YAML-parsed) | deny, unapproved (the hook trims the space; form (b)) |
| U+0085 + `./unapproved` | `./unapproved` (end-stripped) | deny, unapproved (form (b)) |
| `./unapproved` + U+0085 | `./unapproved` + U+0085 / `./unapproved` + one space / `./unapproved` | deny, unapproved |
| U+2028 or U+2029 at either end of `./unapproved` | raw form (identical to the YAML-parsed form) / end-stripped form | deny, unapproved |
| U+00A0 + `make lint` | `make lint` | no verdict (FR2, unchanged) |
| `/usr/bin/true` with U+0085 / U+2028 / U+2029 at one end | that padded form | deny where declared; no verdict in the repository without declarations |
| any | bare `/usr/bin/true` | allow by exact match |

YAML-parsed forms, written as literals in the test (no PyYAML): inside double quotes, U+0085 becomes one U+0020 at the same end; U+2028 and U+2029 are kept, so the parsed form equals the raw form (SPEC AC3).

### Test fixture

- Its own fixture inside the new file; the existing test file's fixture is not reused by modification.
- Hook driven as a subprocess in a temporary git repository. The approval store is isolated through `EM_WORKFLOW_APPROVALS` and holds only `/usr/bin/true`; `CLAUDE_PROJECT_DIR` is removed from the hook's environment.
- Each (character, position) case is checked against a workflow.yaml that declares only that case's value (for example one repository per case, or one distinct command string per case), so a deny cannot be credited to another case's declaration.
- workflow.yaml is written as UTF-8 with the three characters present as raw characters; the test source expresses them as escape sequences.
- For the payload shape, the store registration and the repository layout, follow the subprocess approach of `tests/test_bash_guard_unicode_whitespace.py` by reading it.
- Direct calls to `declared_commands` load the module without writing bytecode, the same way that file's `_load_guard_module` does.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR5, TM-1; SPEC AC1): With a declaration whose double-quoted value is a raw U+0085 followed by `./unapproved`, and a store holding only `/usr/bin/true`, the hook subprocess denies each of: U+0085 + `./unapproved`, one space + `./unapproved`, and `./unapproved`. Each deny reason contains 未承認.
- [ ] AC-2 (FR1, FR5, TM-1; SPEC AC2): With `./unapproved` + a raw U+0085 declared inside double quotes, the hook denies `./unapproved` + U+0085, `./unapproved` + one space, and `./unapproved`, each as unapproved.
- [ ] AC-3 (FR1, FR5, TM-1; SPEC AC3): For U+2028 and for U+2029, placed raw at the leading end and at the trailing end of a double-quoted value, the hook denies both the raw form and the end-stripped form as unapproved.
- [ ] AC-4 (FR1, TM-1; SPEC TS3): A single-quoted declaration and an unquoted declaration with one of the three characters at an end also put the end-stripped form into the declared set. A value that becomes empty after end-stripping (for example a double-quoted value that is only U+0085) contributes no form (b) entry, and its `trim_blanks` form is still contributed.
- [ ] AC-5 (FR2; SPEC AC4, TS2): A direct call to `declared_commands` on the declaration `test_command:` immediately followed by U+00A0 + `make lint` returns a set that contains U+00A0 + `make lint` and does not contain `make lint`. U+000B, U+000C, U+2000 to U+200A and U+3000 placed at an end inside a double-quoted value are likewise not removed. The assertions at lines 418 and 422 of `tests/test_bash_guard_unicode_whitespace.py` pass with those lines unchanged.
- [ ] AC-6 (FR3, TM-2; SPEC AC5): With the AC-1 to AC-3 declarations present, no command among `./unapproved` and `./unapproved` padded at either end with U+0020, U+0009, U+0085, U+2028, U+2029 or U+00A0 is allowed. `/usr/bin/true` with U+0085, U+2028 or U+2029 at its leading or trailing end is denied in a repository that declares that padded form, and gets no verdict in the repository without declarations. Bare `/usr/bin/true` is allowed by exact match in the repository with declarations.
- [ ] AC-7 (NFR1, NFR2, NFR3, NFR4, NFR5, NFR6, TM-2; SPEC AC7): `python3 -m unittest discover -s tests` passes, including the existing pinned tests (standard-library-only imports, no `status` substring, helpers defined once and in order, `trim_blanks` removing spaces and tabs only, pinned docstring phrases). `bash_guard.py` contains no raw U+0085, U+2028 or U+2029 character. The new test module imports only standard-library modules (no PyYAML), writes every non-ASCII character as an escape sequence, isolates the store through `EM_WORKFLOW_APPROVALS`, removes `CLAUDE_PROJECT_DIR` from the hook's environment, and uses a temporary git repository. The task's diff does not touch `em-workflow/.claude-plugin/plugin.json` or `.claude-plugin/marketplace.json`.

## Test Notes

- AC-1, AC-2, AC-3 and AC-6 are subprocess integration tests. One subtest per character × position × command form keeps a failure attributable.
- AC-4 and AC-5 inspect the declared set through a direct call. AC-4 can also be confirmed through the hook (end-stripped form denied).
- A deny is read from the hook's decision output; no verdict means no decision is emitted. The reason substring 未承認 is written with escape sequences in the test source.
- AC-7's raw-character check reads `bash_guard.py` as UTF-8 text and asserts the three characters are absent. If no existing test covers it, add it to the new module, along with a scan of the new module's own source for non-ASCII characters and PyYAML imports.
- Write the tests first. Before the change, the raw forms in AC-1 to AC-3 are already denied, while every YAML-parsed form that differs from the raw form and every end-stripped form gets no verdict; those cases, and AC-4, fail until the change lands.
