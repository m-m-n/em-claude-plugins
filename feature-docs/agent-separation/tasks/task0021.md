# Task Plan: task0021 — 不変条件チェックの実効化

## Goal

Make the repository invariants actually enforced by the test suite instead of only exercised against synthetic trees, and stop the checker from reading the whole repository twice.

## Requirements

FR30, NFR6

## Scope

### Files to Modify
- `em-workflow/scripts/check-plugin-invariants.py` — single-pass traversal, scan restrictions, allowed-prefix correction
- `tests/test_check_plugin_invariants.py` — repository-level enforcement case
- `tests/test_reference_sweep.py` — widen the stale-reference sweep beyond the task allowlist

## Design

Findings addressed: `as2` and `as22`. Full text in `feature-docs/agent-separation/reviews/round1.yaml`; read it first.

**This task runs last, after every other rework task has merged.** Its central assertion is that the checker exits cleanly against the real repository, which only becomes true once the dispatch wiring, the batch jurisdiction and the stale reference are fixed by their owning tasks. The orchestrator holds it back deliberately; do not weaken the assertion to make it pass early, and do not modify files this task does not own in order to make it pass.

**Enforce against the real repository.** Every current case builds a synthetic tree in a temporary directory, and the repository root constant the file already defines is never used as a target. That is why the suite reports success while the checker fails on the same tree. Add a case that runs the checker against the repository root and asserts a clean exit, so the invariants become invariants. Keep the synthetic cases — they are what make each individual check's pass and fail branches testable.

**Widen the sweep.** The stale-reference test scans only a task-owned allowlist, which excludes the very file that still carries the deleted agent's name. Scan the whole plugin directory instead.

**Fix the allowed-prefix set.** The checker's stale-reference check currently flags other features' historical records and this feature's own test literals, neither of which should be rewritten: past feature records are history, and a test that asserts a string's absence must contain that string. Adjust the exclusions so the integrated tree can pass honestly, without excusing a real occurrence under the plugin directory. As of this task's branch point the only occurrence under the plugin directory is the checker's own constant naming the string it searches for, which it already excludes.

**Fix the gate-identifier extraction.** The reference side of the coverage check only counts an identifier when it appears near a literal "gate ID" or "gate_id" phrase — a heuristic adopted to avoid mistaking dotted tokens like package manifest names for identifiers. It is too narrow: on the integrated tree it reports six identifiers as never referenced when all six do appear, in the analyst contract and prompt, the create-spec phase protocol, the batch-mode table and the planner prompt. Replace the proximity heuristic with a rule that cannot produce that false report — for example, treating the identifier set declared by the policy file as the vocabulary and searching for those exact strings — while still not counting a mention inside the policy file itself as a reference.

**Single pass.** Two checks each walk the tree and read every file. Traverse once, run both text checks per file, restrict scanning to relevant extensions and roots, exclude the usual dependency and build directories, and bound individual reads.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A test runs the checker against the repository root and asserts a clean exit.
- [ ] AC-2: The stale-reference test scans the whole plugin directory rather than a task-owned allowlist.
- [ ] AC-3: The checker's exclusions let other features' historical records and absence-asserting test literals pass, while any occurrence under the plugin directory still fails.
- [ ] AC-4: The repository is traversed once for the two text checks, with scanning restricted by extension and root and individual reads bounded.
- [ ] AC-5: Every existing synthetic pass and fail case for each check still passes.
- [ ] AC-6: The gate-identifier coverage check counts an identifier as referenced wherever its exact string occurs outside the policy file, and a synthetic case proves an identifier mentioned without a nearby "gate ID" phrase is no longer reported as unreferenced.
- [ ] AC-7: Running the checker against the repository root exits cleanly, and the full test suite passes.

## Test Notes

AC-7 is the criterion that cannot be satisfied inside an isolated worktree until the sibling rework tasks have merged; that is why this task is dispatched last. Write the repository-level case first and let it fail for the right reason, then confirm it passes once the branch point already contains the sibling fixes.

For AC-4, assert the traversal count rather than timing — for example by counting how many times the traversal helper is invoked during a run over a synthetic tree.

## Out of Scope

- Fixing any invariant violation the checker reports; each belongs to the task that owns the offending file.
- The worker output validator — task0016.
