# Task Plan: task0015 — フェーズプロトコルの dispatch 形式・分岐・検証コスト修正

## Goal

Make the two phase protocols dispatch their workers through the Task tool, split the design-system cross-product branch the way the other three documents define it, and stop the scope procedure from hashing the whole checkout on every dispatch.

## Requirements

FR19, FR22, FR31, NFR8

## Scope

### Files to Modify
- `em-workflow/references/phases/create-spec-phase.md` — explicit Task dispatch for analyst and spec-writer; pre-dispatch containment validation; snapshot cost; cache/analysis reuse at the resolution point
- `em-workflow/references/phases/create-plan-phase.md` — explicit Task dispatch for the planner; two-branch cross-product precondition; planning-invariant accuracy; canonical validator invocation
- `tests/test_phase_protocols.py` — assertions for all of the above

## Design

Findings addressed: `as1` (critical), `as9`, `as10`, `as12`, `as14` (resolution-point half), `as20`. Their full text is in `feature-docs/agent-separation/reviews/round1.yaml`; read it first.

**Dispatch form** — the three sites currently say "Dispatch `requirements-analyst` …" in prose. Write them in the same explicit form the design step already uses in `skills/develop/SKILL.md`, naming the subagent type string. This is what makes the agent definition set and the dispatch reference set equal.

**Cross-product branch** — split the precondition into the two branches `designer-contract.md` and `skills/develop/SKILL.md` define: no design system recorded but tokens present goes to the reclassification gate; the em-workflow kind with the source token file absent and its generated sheet present aborts with the offending paths and waits for the user. The current single branch cannot terminate for the second case.

**Snapshot cost** — the clean-worktree precondition already guarantees the tracked working tree matches the index, so the index blob identifiers carry the same identity the content hashing recomputes. Drop the working-tree-content row from the snapshot table, and hash only paths that the porcelain status and the index-versus-working-tree comparison report as changed. Deletions, mode changes and file/symlink kind changes must remain detectable.

**Pre-dispatch containment** — validate every write-policy target and allowed root before launching, rejecting absolute paths, parent-directory segments, case collisions and symlink segments. State plainly that the post-dispatch comparison is an audit and cannot recover a write made outside the worktree.

**Resolution point** — say where globs are resolved that the cached resolution is reused unless one of the three documented re-resolution triggers fired.

**Planning invariants** — restrict the machine-checked list to what the validator actually implements, mark the rest as human review, state which validation layers belong to the script and which to the orchestrator, and record the canonical validator invocation with a note that omitting an optional argument silently narrows validation.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: All three dispatch sites name their subagent type in the explicit Task form, matching the form used for the design step.
- [ ] AC-2: `create-plan-phase.md` defines two distinct cross-product branches, and the token-source-absent case aborts with the offending paths instead of entering the reclassification gate.
- [ ] AC-3: The pre-dispatch snapshot no longer hashes every tracked path; content hashing is limited to paths reported as changed, and deletions, mode changes and kind changes remain detectable.
- [ ] AC-4: The scope procedure validates targets and allowed roots before launching and states that post-dispatch comparison cannot recover an out-of-worktree write.
- [ ] AC-5: The analyst dispatch loop states that glob-derived categories come from the cached resolution unless a documented re-resolution trigger fired.
- [ ] AC-6: `create-plan-phase.md` section 9 lists only the invariants the validator implements, marks the others as human review, states the layer split, and records the canonical validator invocation.
- [ ] AC-7: `tests/test_phase_protocols.py` asserts each of the above and still asserts every section required by the design.
