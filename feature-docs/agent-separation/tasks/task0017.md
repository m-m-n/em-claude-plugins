## Design

Findings addressed: `as3` and `as4`. Full text in `feature-docs/agent-separation/reviews/round1.yaml`; read it first, including the list of eight relocated gates and eight referrer sites.

**Choose the jurisdiction, then make everything agree.** The recommended direction is the one the documents already claim: the policy file covers only gates a worker expresses as a question packet, and gates the orchestrator opens directly stay in the batch-mode document. That keeps the eight existing referrers valid and needs no gate-identifier annotation at sites that never produce a packet. The alternative — keeping them in the policy file — is acceptable only if every originating site gains a gate identifier and the batch resolution sequence is extended to cover orchestrator-opened gates; do not leave the code base half-way between the two.

**Narrow the catch-all.** Whatever remains as a general rule must not be able to override a default that a phase protocol or the policy file already states. Today it converts implement's documented retry-once-then-abort, review's skip-site and apply-as-is, and the completion step's keep-branch into a Codex consultation, which in an unattended run turns a documented abort into a swallowed failure.

**Repoint the references.** Each of the eight sites naming the deleted decision table must name a section that exists — the relevant phase protocol's inline rule, the policy file entry, or the rework synthesis document for the rework rule. The plugin description must stop asserting that every gate resolves per the batch-mode document.

**The Codex reference** at the diff-size gate row must point at the unlisted-gate fallback rather than the deleted agent definition. The fallback's substance is task0018's work; this task only repoints.
