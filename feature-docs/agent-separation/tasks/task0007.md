# Task Plan: task0007 — 計画・デザイン側 worker 契約（planner / rework-planner / designer）

## Goal

Define the input/output contracts for the three workers that produce plans and design decisions, including the design-system branch table that governs designer dispatch.

## Requirements

FR6, FR7, FR8

### Files to Modify

(none)

## Design

All three extend the common envelope by reference and add only worker-specific content. All three cite the write-policy model owned by `contracts/spec-writer-contract.md` by path rather than restating it.

**planner-contract.md** renders design-input.md 5.4.3 and the planner row of 5.0 R1: responsibility (analysis, IMPLEMENTATION.md, task plans, VERIFICATION.md); no user questions and no workflow.yaml writes; the `planning_inputs` fields and the `write_policy`; the rule that TBD, license conflict and existing-file questions go into one packet unless license discovery depends on a TBD answer; the `completed` output comprising written artifacts, a workflow patch and a task index; the `digest_inputs` set; and the prohibition on setting `branch`, `notes`, running statuses or `completed_at_commit`. It names the plan-writing skill as the source of decomposition, complexity and domain criteria, and `review-rules.yaml` as the `domains` vocabulary SSOT.

**rework-planner-contract.md** renders design-input.md 5.4.4: responsibility (plan only the additional tasks, never rewrite the whole plan); the `rework_source` input with its review and verify variants, `existing_tasks`, `next_task_id`, `verification_index` and the three document paths; the grouping rule that reuses the normal decomposition rules; the document update scope table; the mandatory `rework_index` coverage declaration with the four validation checks and the prohibition on a task declaring neither existing coverage nor new scenarios; the mandatory `shared_contract_rationale` explaining why IMPLEMENTATION.md was or was not extended; the specification-change transition, which returns a question rather than tasks and drives a fixed five-step orchestrator sequence; and the three conditions under which any other packet may be returned. It references `rework-task-synthesis.md` as the contract the output must satisfy.

**designer-contract.md** renders design-input.md 5.4.5 and 4.2: responsibility (execute the existing designer process as a Task); fully autonomous, returning neither a question packet nor a workflow patch, with the reason for the latter; the `design_inputs` fields; the write-policy targets for DESIGN.md, the two token files and any existing mockup, with new mockups covered by `allowed_write_roots`; the reason `design-system/` is not an allowed root; the token yaml/html linkage expressed through `regenerate` with bidirectional verification; the rule that existing tokens are always `extend_only` and the html always `regenerate`, so `replace_authorized` never applies; the complete `kind` × token-existence table with the two abort cases and the reclassification gate for the `none`-with-tokens case, including that the gate is executed in place rather than by returning to create-spec and that it is shared between the design and create-plan entry points; the exclusion of the two token files from `digest_inputs` under `project_native`; and the `design_summary` payload.
