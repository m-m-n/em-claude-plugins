# Task Plan: task0012 — develop skill の再配線

## Goal

Rewire the develop orchestrator so create-spec, design and create-plan run through phase protocols and Task dispatch, the verify rework branches use the rework SSOT, and legacy features are backfilled before a design-system-dependent step begins.

## Requirements

FR27, FR17, FR32, FR1

## Scope

### Files to Create
- `tests/test_develop_skill_rewiring.py` — develop skill の再配線アサーション

### Files to Modify
- `em-workflow/skills/develop/SKILL.md` — step table, design step dispatch and cross-product check, verify rework branches, design-system backfill branch, and the commit-semantics wording

## Design

The changes are confined to one file and are additive to the existing Step 0 / Step A / Step A.5 / Step B / Step C structure.

**Step table**: the create-spec, design and create-plan rows stop instructing the orchestrator to read an agent definition and follow it inline. create-spec and create-plan point at their phase protocols; design points at a Task dispatch of the designer subagent. No row retains inline-execution wording.

**Design step branch**: immediately before dispatching the designer, the orchestrator performs the design-system cross-product check between the recorded `kind` and the actual existence of the two token files, aborting on the two inconsistent combinations and running the reclassification gate for the case where no design system is recorded yet tokens exist. The gate updates workflow.yaml, commits it, then resumes from the same step's preconditions without changing the step's status.

**Verify rework branches**: both the interactive and the batch verify failure branches reference the rework synthesis SSOT and the rework-planner rather than describing synthesis inline. The interactive branch keeps its three-way user choice; the batch branch keeps its counter-capped automatic rework. Both must satisfy the invariant that a pending rework task exists before implement returns to pending.

**Backfill branch**: between selecting the next incomplete step and updating it to in-progress, the orchestrator checks whether the selected step is design or create-plan and whether the design-system field is absent; if so it runs the backfill, then re-reads workflow.yaml and restarts step selection. The document states why the status update must not precede the backfill: an interruption during the backfill question would leave a step in progress with no phase state to resume from.

**Commit semantics**: the `completed_at_commit` wording is restated in the terms of the normative rule without changing its meaning, and the existing exit-4 recovery discipline is retained.
