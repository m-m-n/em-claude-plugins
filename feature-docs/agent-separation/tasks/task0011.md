## Design

Both documents address the orchestrator, not a worker. Each follows the section order given in design-input.md (5.7 for create-spec, 5.8 for create-plan) and references the schema, contract and policy documents by path instead of restating them.

**create-spec-phase.md** covers: ownership split; inputs and preconditions including feature identifier validation and the clean-worktree requirement; the bootstrap and durable-state boundary, which moves worktree creation forward to immediately after the feature name is fixed so that every subsequent answer is persisted; reconcile on entry; the analyst dispatch loop; question normalization; interactive answer handling, including converting selections to option identifiers, separating verbatim free text from its normalization, raising a follow-up question rather than guessing at an ambiguous answer, and never advancing past an unanswered blocking question; batch answer handling by reference; spec-writer dispatch with write-policy construction; artifact validation; workflow.yaml construction by the orchestrator without a worker patch; the mandatory design-system determination step, which runs even when the design step is skipped, with the single exception that a skipped design step with zero candidates may record `none` without asking; the command approval gate; and completion with the rule R2 commit sequence.

It states the termination conditions with no fixed round limit, and the loop-stop conditions based on a progress fingerprint computed each iteration. On stopping, the user is offered continue, record-as-TBD, or abort; converting an unresolved item to an assumption is permitted only when the user explicitly chooses it.

**create-plan-phase.md** covers: ownership split; preconditions including create-spec completed, design completed or skipped, the required source documents, requirements agreement with the specification, the clean-worktree requirement, and the design-system cross-product check with its in-place reclassification branch; reconcile on entry; planner dispatch with its inputs; the question loop; packet normalization by reference; the planner's completion output; the seven validation layers; the machine-checked planning invariants; atomic patch application followed by the rule R2 commit sequence; and completion, including treating artifacts-without-applied-patch as a resumable partial completion.

**Scope verification** is written once, in the create-spec document, and referenced from the create-plan document, since the procedure is identical. It covers: the clean-worktree precondition as a fail-closed check performed at every dispatch, with the list of reasons the tree may not be clean, and abortion with the offending paths rather than automatic cleaning; the pre-dispatch snapshot contents; the layer separation whereby the change set is computed from the index and working tree only and the HEAD layer serves solely for staleness; the ordered post-dispatch comparison — compute the change set, judge permitted scope by splitting paths on pre-dispatch existence, remove violations, then evaluate HEAD movement, then handle staleness — and the reason for that order; the path normalization and containment rules; the removal procedure including the trash step and the abort when the trash tool is unavailable; and the exclusivity assumption with its precise applicability window and its acknowledged limit.
