# Task Plan: task0016 — 検証スクリプトの実効性修正

## Goal

Close the validation holes that let unsafe or incomplete worker output pass: prefix-based containment, an unverified rework coverage declaration, a vocabulary parse that admits complexity values, an unconstrained plan path, and unenforced per-status payload rules.

## Requirements

FR9, FR10, FR11, NFR4, NFR8

## Scope

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — containment, type checks, rework index completeness, vocabulary parse, plan path, status payload exclusivity, question cross-checks
- `em-workflow/references/fixtures/` — invalid fixtures pinning each fixed hole, plus the missing valid status fixtures
- `tests/test_validate_worker_output.py` — coverage generated from the worker capability table

## Design

Findings addressed: `as5`, `as6`, `as15`, `as16`, `as17`, `as21`, and the validator half of `as8`. Full text in `feature-docs/agent-separation/reviews/round1.yaml`; read it first — several findings record the exact reproduction.

**Containment** — replace string prefix matching for written artifacts with normalized project-relative segment comparison. Reject absolute paths, parent-directory segments, NUL and non-string entries, and type-check the artifact list itself. Both reproduced escapes (sibling directory, traversal) must become validation errors, and a malformed entry must produce a machine-readable error rather than a traceback.

**Rework coverage** — pass the patch's task entry keys into the rework index check and error when a task is missing from the index, or when the index names a task the patch does not create. Add the shared-contract rationale to the required payload set.

**Vocabulary parse** — terminate the domains comment scan the way the invariant script does, so complexity values cannot enter the domain vocabulary. Prefer one shared helper over two parsers of the same file.

**Plan path** — require the plan path to be a normalized relative path under the feature directory, reject absolute paths and parent segments, compare resolved segments, reject symlink segments before opening, and bound the read size.

**Question cross-checks** — enforce that a question whose category is specification change, security or licensing carries the blocking unanswered behaviour, so a worker cannot choose a value that disables the batch abort.

**Status payload exclusivity** — enforce the envelope contract's rule that the five non-completed statuses carry no payload.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Both reproduced containment escapes are rejected, and a written-artifact entry lacking a usable path yields a machine-readable validation error rather than a traceback.
- [ ] AC-2: A patch that creates a rework task absent from the rework index is rejected, as is an index naming an uncreated task; the shared-contract rationale is required.
- [ ] AC-3: The domain vocabulary contains exactly the eight documented values, and a task declaring a complexity value as a domain is rejected.
- [ ] AC-4: A plan path that is absolute, escapes the feature directory, or traverses a symlink segment is rejected before the file is opened.
- [ ] AC-5: A question whose category is specification change, security or licensing is rejected unless its unanswered behaviour is blocking.
- [ ] AC-6: A result carrying a payload alongside any of the five non-completed statuses is rejected.
- [ ] AC-7: Fixture coverage is generated from the worker capability table so that every worker and permitted status pair has a valid fixture, and each fix above has an invalid fixture; all valid fixtures exit 0 and all invalid ones exit 1.
