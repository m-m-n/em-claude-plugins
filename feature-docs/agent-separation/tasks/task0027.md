# Task Plan: task0027 — 不変条件チェッカーの自己参照除外

## Goal

Stop the gate coverage check from counting the checker's own comments as references.

## Requirements

FR30, NFR6

## Scope

### Files to Modify
- `em-workflow/scripts/check-plugin-invariants.py` — self-exclusion on the reference direction
- `tests/test_check_plugin_invariants.py`

## Design

Finding addressed: `bs11`. Read `feature-docs/agent-separation/reviews/round2.yaml` first.

The reference direction of the gate coverage check scans the plugin directory and treats any occurrence of a policy key as a reference, excluding only the policy file itself. The checker is inside that directory, and its own comments name two gate identifiers, so those two are reported as referenced no matter what the rest of the plugin says — they would survive every other document dropping them. The stale-reference check already maintains a self-exclusion set for exactly this reason; this direction does not use it.

Apply the same exclusion set to the reference direction. Changing the comments to avoid the match is not equivalent: it would fix today's two identifiers while leaving the next comment that names one to reintroduce the hole.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The reference direction excludes the checker itself, using the same exclusion set the stale-reference check already maintains.
- [ ] AC-2: A synthetic tree in which a policy key appears only inside the checker's own file reports that key as unreferenced.
- [ ] AC-3: The two identifiers currently named in the checker's comments are still reported as referenced, because other documents genuinely reference them.
- [ ] AC-4: Every existing synthetic case for both directions still passes.
- [ ] AC-5: The checker still exits cleanly against the repository root.

## Test Notes

Build the AC-2 case as a synthetic tree containing a policy file, a copy of the checker naming one key in a comment, and no other mention of it; assert that key is reported. For AC-3, assert against the real repository that neither identifier appears in the unreferenced list, which distinguishes a genuine reference from the self-match this task removes.

## Out of Scope

- The worker output validator — task0023.
- Any invariant violation the checker reports; each belongs to the task owning the offending file.
