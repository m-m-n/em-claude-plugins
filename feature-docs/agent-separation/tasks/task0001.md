## Goal

## Design

Both documents are rendered from `feature-docs/agent-separation/design-input.md`, which is present in this worktree.

**worker-envelope.md** implements design-input.md 5.3 and the applicability rule in 2.3. It states:

- Which workers the envelope applies to and which keep their current form.
- The input fields, their meaning, and which are mandatory.
- The output fields and the six `status` values with the exclusivity constraints that each status imposes on `question_packet`, `payload`, `blocking_reason` and artifacts.
- The `mode_echo` rule: workers with a mode input copy it verbatim; all others emit null.
- `written_artifacts` reporting: every written path with its sha256.
- The read-restriction rule: a worker reads only the explicitly supplied fixed-path inputs and the entries of `resolved_input_paths`, and never performs its own discovery.
- The exclusivity assumption for the integration worktree during dispatch and the interval over which it applies (design-input.md 5.11.3).

**question-packet-schema.md** implements design-input.md 5.1 and 5.2. It states:

- Packet fields, the `packet_id` and `question_id` identifier patterns, and the size limits.
- The full `category` vocabulary.
- Per-question fields including `gate_id`, `priority`, `blocking`, `answer_mode`, `options`, `why_needed`, `evidence`, `depends_on`, `supersedes`, `on_unanswered`.
- That the packet is question-request-only and does not express "no questions" — the worker's overall state is carried by the result `status`.
- That `on_unanswered` has no value meaning "convert to an assumption automatically".
- The answer object fields, the `source` vocabulary, and consistency rules 1–7, marking rules 1–5 as machine-verified.
- How `options` map onto the AskUserQuestion tool's options and header.

Neither document restates content owned by another document; both link to `design-input.md` sections and to sibling references by path.

- [ ] AC-6: The packet document states that no `on_unanswered` value converts an unanswered question into an assumption.
- [ ] AC-7: Neither document copies a table or rule owned by another SSOT listed in design-input.md 10.5; cross-references are path references.

## Test Notes

These deliverables are specification documents, so the acceptance criteria are verified by structural assertions rather than behavioural tests. Write `tests/test_worker_contract_docs.py` asserting, per criterion: the files exist; every `status` value, every `category` value, and every envelope field name from design-input.md appears in the corresponding document; the `on_unanswered` prohibition sentence is present; and no document contains a heading that duplicates a table owned by another SSOT (check by asserting the absence of the specific section titles owned elsewhere, e.g. the workflow patch application-rule list). Derive the expected vocabularies by parsing `feature-docs/agent-separation/design-input.md` in the test so the assertions cannot drift from the design.

Edge case worth covering: a field present in the document but spelled differently (assert exact tokens, not substrings of prose).
