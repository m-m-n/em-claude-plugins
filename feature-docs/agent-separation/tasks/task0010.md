# Task Plan: task0010 — 既存 worker 定義の改修（designer / implementation-planner）

## Goal

Bring the two existing agent definitions into the new contract: structured envelope input and output, read-only workflow.yaml, no user questions, and no commits.

## Requirements

FR17, FR18

## Scope

### Files to Create
- `tests/test_refitted_worker_agents.py` — 改修 worker 定義の frontmatter と規律アサーション

### Files to Modify
- `em-workflow/agents/designer.md` — structured input/output, workflow read-only, returns no patch, no commits, path-level write policy
- `em-workflow/agents/implementation-planner.md` — remove AskUserQuestion, return a question packet and a workflow patch proposal, state the domains SSOT

## Design

**designer.md** keeps its existing autonomous process and design judgement, and changes only its interface and boundaries:

- Input arrives as the common envelope plus `design_inputs`; the project-native design system, other features' design documents and any visual inputs arrive through `resolved_input_paths`, so the agent performs no discovery of its own.
- Output is the common envelope with the design summary payload; the agent returns neither a question packet nor a workflow patch, and the body states why the latter carries no information the orchestrator lacks.
- workflow.yaml is read-only and the agent never commits; the existing statement that the orchestrator commits after return is retained and made consistent with Task dispatch.
- The path-level write policy governs DESIGN.md, the two token files and any existing mockup, while new mockups are covered by the allowed write roots; the body states that `design-system/` is deliberately not an allowed root.
- The `kind` branch is referenced from the designer contract rather than restated.

The frontmatter's `model` and `effort` are retained; the body's autonomy statements are retained because they remain correct under Task dispatch.

**implementation-planner.md** changes its interaction model:

- AskUserQuestion is removed from the tool list, and the three interactive decision points (TBD resolution, license conflict, existing files) become questions in a single packet, with the exception that license discovery depending on a TBD answer may be deferred to a later iteration.
- workflow.yaml writes are replaced by a proposed workflow patch; the body states that the orchestrator applies it and that the agent never sets `branch`, `notes`, running statuses or `completed_at_commit`.
- Commit instructions are removed; the orchestrator commits after return.
- The batch section's per-gate three-way handling is removed in favour of a reference to the gate policy SSOT.
- The `domains` vocabulary SSOT is stated as `references/review-rules.yaml`.
- Its existing planning content — the plan-writing skill preload, the document responsibilities, the license constraint on technology choices, and the requirements mapping duty — is retained.
