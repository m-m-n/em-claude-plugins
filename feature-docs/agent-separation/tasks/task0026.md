## Design

Finding addressed: `bs4`. Read `feature-docs/agent-separation/reviews/round2.yaml` first.

The cross-product table has two abort rows with two different outcomes: no design system recorded but a token file present runs the reclassification gate, while the em-workflow kind with the source token file absent and its generated sheet present aborts outright and waits for the user, because re-settling the kind cannot restore a missing file. That split was applied to the create-plan protocol, the develop skill and the owning contract's own reclassify step during the previous rework, but the backfill procedure — the source of truth for the legacy compatibility path every pre-existing feature enters — kept a single rule covering both rows and looped back to its own earlier question.

For the second row that loop cannot terminate: the question re-settles the kind, the token source is still missing, and the same inconsistency reappears. Under batch it is worse, because the gate the backfill returns to resolves to the top-candidate-or-none policy, which with zero candidates yields the same value that caused the inconsistency, whereas the reclassification gate's batch default resolves to the other kind precisely so that it terminates.

Replace the looping step with a pointer to the owning table's two outcomes, and state that the backfill itself never returns to its earlier step — the ordinary cross-product check runs at the next step entry and handles both rows there. That matches how the develop skill's backfill branch already terminates, by re-reading the workflow file and restarting step selection.
