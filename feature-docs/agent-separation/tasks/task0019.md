## Design

Findings addressed: `as7`, `as11`, `as18`, `as19`. Full text in `feature-docs/agent-separation/reviews/round1.yaml`; read it first.

**Ship the digest rule.** The normalization procedure — sorted keys, the compact separators, non-ASCII left unescaped, then the hash — exists only in the design document, which is not part of the distributed plugin, while four shipped files defer to it. Write the procedure and the digest source structure into the envelope contract as substance, and note the recomputation-and-comparison timing that makes staleness detection work. The companion commit rule was correctly absorbed into the schema document earlier; this is the same move for the one that was left behind. Do the same for the validation layer table, stating which layers the script owns and which the orchestrator owns. References to the design document become provenance notes, never the place a reader must go to resolve normative content.

**Analyst gate identifiers.** The analyst produces every create-spec question packet yet neither its contract nor its prompt mentions gate identifiers, so two policy entries are unreachable and a batch create-spec falls into the fallback on every clarification. Add a decision-point to gate-identifier table in the format the planner already uses, covering at least requirement clarification and the design-step recommendation, and mirror it in the prompt. Correct the packet schema's ownership sentence, which currently names a document that holds no identifiers.

**Designer digest exception.** Under a project-native design system the two em-workflow token files must leave the digest inputs and must not serve as decision inputs; the planner contract states this and the designer contract — which owns the cross-product table — does not. Add it, and say that project-native files arrive only through the resolved input paths.

**Tool grants.** Both workers declare they never write and never commit, yet both carry a shell tool that no contract justifies, and a worker commit defeats the scope procedure because the staleness reset targets the very branch the commit advanced. Remove the grant from both. If a genuine use exists, it must be documented in the contract instead — but the round record found none.
