# Task Plan: task0020 — 探索コスト規則の出荷と backfill キャッシュ

## Goal

Ship the exclusion list and extension allowlist that keep design-system discovery bounded, and give an interrupted backfill somewhere durable to keep its discovery result.

## Requirements

FR13, FR32, NFR9

## Scope

### Files to Modify
- `em-workflow/references/phase-state.md` — discovery exclusions and extension allowlist; backfill discovery persistence
- `tests/test_phase_state_doc.py` — assertions for both

## Design

Findings addressed: `as13` and `as23`. Full text in `feature-docs/agent-separation/reviews/round1.yaml`; read it first.

**Ship the missing controls.** Of the three cost controls the design defines, only the file-count and size cap was written into a shipped document. The exclusion roots — the dependency directory, the vendored directory, the git directory, the worktree root and anything the ignore file covers — and the directory-enumeration allowlist of source and style extensions exist only in the design document. Without them, a JavaScript or TypeScript project matches the candidate patterns heavily inside its dependency directory, and an asset-heavy directory match enumerates images, fonts and build output; the cap is then reached on noise, and the documented behaviour at the cap is to abort an unattended run. Write both controls into the discovery rules and state that filtering happens during enumeration, so filtered files never count toward either limit.

**Persist the backfill discovery.** The backfill path is deliberately given no phase state, yet it dispatches the analyst to discover candidates. A session ending after discovery but before the choice is committed repeats the whole search on resume even though no re-resolution trigger fired, and has nowhere to keep the generation digest or the truncation flag. Define where that result lives — either a durable backfill record or the cache attached to the pending phase's state — and state that an ordinary resume reuses it.

Keep the existing statement that a backfill answer given but not yet committed is lost; that is a separate, accepted trade-off about the answer, not about the discovery result.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The discovery rules name every exclusion root the design defines.
- [ ] AC-2: The discovery rules name the directory-enumeration extension allowlist and state that filtering happens during enumeration, before files count toward either limit.
- [ ] AC-3: The existing file-count and size cap, and its interactive and unattended behaviours, remain unchanged.
- [ ] AC-4: The document defines where a backfill's discovery result is persisted, covering the resolved paths, their digests, the generation digest and the truncation flag.
- [ ] AC-5: The document states that an ordinary resume reuses the persisted backfill discovery rather than repeating the search.
- [ ] AC-6: `tests/test_phase_state_doc.py` asserts AC-1, AC-2, AC-4 and AC-5, deriving the exclusion and extension lists from the design document rather than restating them.
