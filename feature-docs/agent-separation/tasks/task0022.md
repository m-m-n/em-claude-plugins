## Design

Findings addressed: `bs2` (document half), `bs3`, `bs6`, `bs8`. Read `feature-docs/agent-separation/reviews/round2.yaml` first — each carries the reviewers' reasoning, and `bs2` records two reproduced spoofs.

**The criterion.** Split by whether a gate carries a gate identifier, never by who raises it. A gate with an identifier is resolved by the batch sequence against the policy file, whether a worker returned it in a packet or the orchestrator opened it directly. Only gates with no identifier at all — feature selection, the review diff-size gate, the command-approval fallback when the hook is inactive, and similar — belong to the batch-mode table. Apply the criterion in every place that currently states or implies the old one: the batch-mode premise sentence and its rows, the policy file's scope header, the develop skill's argument processing, and the batch sequence's own entry condition, which today begins by assuming a worker returned a packet and therefore cannot describe an orchestrator-opened gate. Bring the artifact-overwrite family back under one source of truth.

The previous round's instruction from the orchestrator recommended the opposite direction. It was wrong; this criterion supersedes it.

**The classification.** Move it above both branches — immediately after the gate is identified, before any policy lookup — so a listed gate is classified too. The unlisted fallback then references it instead of restating it. Without this, a security or licensing question in create-spec never reaches the abort, because the analyst's only two gates are both listed.

**The consultation budget.** Give the consultation a bound that does not scale with question count: either a per-phase ceiling on consultations, or one consultation per packet covering its unresolved questions together. Add the literal-string cache to the batch per-command fallback, matching what the interactive side already defines. Cap or summarize the history re-sent on each turn rather than resending the whole exchange.

**The schema constraint.** State in the packet schema that a question whose category is specification change, security or licensing must carry the blocking unanswered behaviour, and name the script that enforces it. Remove the attribution to a feature-docs task identifier, which does not exist in a distributed plugin.
