# Task Plan: task0001 — Skip backslash pairs in the unquoted-backquote closing search

## Goal

Both copies of the codex hook interactive guard deny an explicit
`python3 -i` even when the command has, outside quotes, a backquote span
that nests backslash-escaped backquotes. A case-table row pins the
reproduction command as deny.

## Requirements

FR1, FR2, FR3, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/scripts/codex-hook-interactive-guard.py` — the parse routine's closing-backquote search for an unquoted backquote skips backslash pairs
- `em-review/scripts/codex-hook-interactive-guard.py` — the same change; the file stays byte-identical to the em-workflow copy
- `tests/test_codex_hook_interactive_guard.py` — one new deny row in the CASES table for the reproduction command, plus the tests the Acceptance Criteria below need

## Design

Cross-task conventions (two copies, one change; unchanged decision
vocabulary; cases are only added) are in IMPLEMENTATION.md and are not
restated here.

### Where the change goes

The parse routine handles a backquote it meets outside any quotes. Today it
takes the next backquote after the opening one as the closing one and
ignores backslashes in between.

### Closing-backquote search (contract)

- **Precondition**: parse is at an unquoted opening backquote.
- **Search**: scan forward from the character after the opening backquote.
  A backslash and the single character after it, whatever that character
  is, are consumed together as one pair. A pair never ends the search. The
  first backquote that is not consumed as part of a pair is the closing
  backquote.
- **Found**: the text from the opening backquote through the closing one is
  added to the current word as one dynamic chunk, as today. Only the end
  position of the span changes. Parsing resumes after the closing backquote.
- **Not found**: the end of the text is reached first, which includes text
  that ends in a lone backslash. Parse returns the `quote` undecidable
  result, as today.
- **Same rule as `_skip_substitution`**: this is the pair rule the `b`
  context of `_skip_substitution` already applies, so mirror it. Reusing that
  logic is acceptable only if `_skip_substitution`'s own behaviour and every
  existing test decision stay unchanged.
- **Parity consequence**: a backquote preceded by an even-length run of
  backslashes (zero included) closes the span. A backquote preceded by an
  odd-length run does not close it.
- **Scope (SPEC A-2)**: every unquoted backquote that parse reads, not only
  those inside an anonymous function's argument list.

### Complexity bound (NFR1, NFR2)

One forward pass that examines each character at most once, with no
recursion. No import outside the standard library.

### Reproduction command (test input data, not code)

These are the raw characters exactly as the hook receives them in
`tool_input.command`:

```
zsh -c 'setopt nonomatch nobareglobqual; function { python3 -i; } foo(`echo \`echo x\``)'
```

Structure check: the command has exactly two backslashes, each directly
followed by a backquote, and four backquotes in total. A source-level string
literal in the test module must decode to exactly these characters, so each
backslash has to be written escaped there.

Under the new rule, the span that opens after `foo(` runs to the final
backquote, because both escaped backquotes are consumed as pairs. The `)`
then closes the argument list, and the explicit `-i` in the anonymous
function body is denied. Under the old rule the span closed at the first
escaped backquote, the last backquote was read as unclosed, and the result
was undecidable (silent).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR2, TM-1): Each copy is fed, on its standard input, a hook-input JSON whose `tool_input.command` is the reproduction command. Each copy outputs a JSON whose `permissionDecision` is `deny`.
- [ ] AC-2 (FR3): The CASES table contains exactly one row with the reproduction command, with expected decision `deny`, and `python3 -m unittest tests.test_codex_hook_interactive_guard` passes against both copies.
- [ ] AC-3 (FR1, NFR1, TM-2): An unquoted backquote is read as unclosed when no closing backquote is left once backslash pairs are consumed. This covers every later backquote being backslash-escaped, text that ends in a lone backslash, and a span of deep-input length made only of backslash pairs. Parse returns the `quote` undecidable result for each, and the hook gives each the same fail-open output it gives any other `quote` undecidable command.
- [ ] AC-4 (FR1): Inside an unquoted backquote span, a backquote preceded by an even-length run of backslashes (zero included) closes the span. A backquote preceded by an odd-length run does not.
- [ ] AC-5 (FR2, TM-1): The two copies are byte-identical (`TestCopies.test_the_two_copies_are_byte_identical` passes).
- [ ] AC-6 (NFR1, NFR2, NFR3, TM-2): `python3 em-workflow/hooks/tests/run-destructive-guard.py && python3 -m unittest discover -s tests` passes, including TestNoRecursion, TestMalformedAndDeepInput, TestStaticConstraints and TestFailOpen, and no existing CASES row is edited or removed.

## Test Notes

- **Red step first**: add the AC-1 / AC-2 row before the fix and confirm it
  is silent (fails). This is the regression's red step.
- **AC-1 and AC-2**: the CASES table runs every row against both copies. If
  the harness drives the copies through standard input, the one row covers
  AC-1 as well. Otherwise add a standard-input-level check for AC-1.
- **Where to place probe backquotes (AC-3, AC-4)**: a dynamic chunk among
  `python3`'s own arguments is fail-open by design (TestFailOpen's backquote
  case). Put the probe backquote where it is not an argument of `python3`,
  for example in the anonymous function's argument list as in the
  reproduction command, so the difference between deny and silent can be
  observed.
- **Asserting the `quote` result (AC-3)**: a parse-level assertion on the
  `quote` reason is the most direct test if the test module already reaches
  the parse routine. If not, compare the hook output with that of an
  existing unclosed-backquote case.
- **Deep-input case (AC-3)**: use the same input scale as the existing
  deep-input tests. The case must finish and return the `quote` result.
  Assert on the result, not on timing.
- **Escaping**: see the structure check under the reproduction command when
  writing new string literals.

## Out of Scope

  span's content is treated stays as it is. Only the span's end position
  changes.
- The behaviour of `_skip_substitution` and of the other quoting contexts
  (single quotes, double quotes, dollar-parenthesis substitutions).
- Plugin version fields (`plugin.json`, `marketplace.json`).
