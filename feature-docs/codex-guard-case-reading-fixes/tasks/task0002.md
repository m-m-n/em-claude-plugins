# Task Plan: task0002 — Command position after compound closings, function heads and loop/coproc heads

## Goal

Inside `$( )`, the substitution reader of codex-hook-interactive-guard reads
the word after a compound-command closing, a function head, or a loop or
coproc head as being at command position, and the word after a word-internal
closing or an argument-position head word as an argument, in both plugin
copies. A `case` statement after them then opens and closes where the
shell's does, and `CASES` rows plus linear-time tests pin SPEC scenarios
TS23–TS60.

## Requirements

## Design

Starting point: the integration branch already carries the merged
command-position reader — per-context command-position state, the case
open/close rule, the pattern-comment rule and continuation handling, pinned
by rows TS1–TS19 and tests TS20–TS22. This task keeps all of it and widens
where command position comes from. Cross-task contracts (two-copy identity,
the `CASES` row shape, the reader's signature/result/recursion/linearity
contract, the command-position state contract), scope limits (D2) and the
forward-state decision (D3) are in IMPLEMENTATION.md and are not restated
here. Notation: `<NL>` is a newline, `\<NL>` a continuation pair (backslash
directly followed by a newline).

### 1. Per-context state added (NFR1, SPEC A9)

Each command-list context (the body of a `$(`, the body of a nested `(`, a
case item body) gains, next to its command-position flag, a fixed set of
constant-size fields:

- for a context opened by `(`: whether that `(` was read at command
  position, and whether it is a zsh for word list (section 4);
- whether a `[[` read as a standalone word at command position is open in
  this context with its `]]` not yet read;
- one head state taken from a fixed, small set of values: none; after a
  command-position first word (a possible `name()`); after `function`; after
  the function name; after `for` / `select`; after the `for` / `select`
  name; after `coproc`; after the coproc's first word; after `repeat`.

No field grows with the input. `[[` is tracked only to recognise the `]]`
that closes it; words inside `[[ … ]]` are read as today (A9).

### 2. Compound-command closings (FR9, FR1, FR2, SPEC A2, A3, A10)

The next word is at command position after:

- the `)` that closes a `(` opened at command position — a subshell, and the
  `((` … `))` arithmetic command (`if (:) then`, `while (false) do`,
  `if ((1)) then`);
- a standalone `]]` while a command-position `[[` is open in the same
  context, wherever it stands inside the conditional (`if [[ x ]] then`, zsh
  `if [[ x ]] {`);
- the `esac` that closes a case statement, whether read in an item body or
  at the pattern position — the context that holds the statement gets
  command position (`if case y in y) :;; esac then`);
- a standalone, unquoted `fi`, `done` or `}` read at command position
  (`fi then`, `done then`, `} then`).

These give no command position and the word goes on, as today: a closing
substitution (`$( )`, backquote), a closing quote, a closing `${ }`, and a
`)` that closes a `(` not opened at command position (zsh glob qualifier
`x(N)`, `<(` / `>(`). A `]]` with no open command-position `[[`, and `fi` /
`done` / `}` at argument position, are ordinary argument words. After a
closing, a redirection and its target follow A3: the word after the target
is not at command position.

### 3. Function heads (FR10, SPEC A11)

- `name()`: when the first word of a simple command (an ordinary word read
  at command position) is followed, directly or after blanks, by `(`, only
  blanks, and `)`, that `)` ends a function head and the next word is at
  command position (`f() {`, `f () {`). Deciding whether the parentheses are
  empty re-reads the blanks between them a bounded, constant number of
  times (NFR1). When they are not empty, the `(` is read exactly as it is
  today.
- `function name`: a standalone `function` that is unquoted, unescaped and
  read at command position (decided on the pair-stripped sequence, section
  6) starts a head. The next word is the name: an ordinary word, never read
  as a keyword or reserved word (`case`, `esac`, `for`, …). After the name
  the next word is at command position. An empty `()` directly after the
  name or after blanks belongs to the head, and the word after it is at
  command position (`function f {`, `function f() {`). A `(` after the name
  that does not form an empty `()` is read at command position (a subshell
  body).
- A `function` at argument position, quoted or escaped, is an ordinary word
  and starts no head. Multi-name zsh definitions and function-name validity
  are not considered (A11).

### 4. Loop and coproc heads (FR11)

A head starts only from a standalone word that is unquoted, unescaped, read
at command position, and spells the head word once continuation pairs are
removed. The same word at argument position, quoted or escaped, is an
ordinary word and starts no head.

- `for` / `select`: the next word is the name — an ordinary word, never a
  keyword (`for case in x` opens no case). After the name the next word is
  at command position (`for x do`, `select x do`). In `for x in a b; do`,
  `in` and the words after it are ordinary words up to the separator.
- Arithmetic for: a `((` directly after `for` (blanks allowed) counts as
  opened at command position, so its `))` gives command position by
  section 2 (`for ((i=0;i<1;i++)) do`).
- zsh `for name (words)`: a `(` directly after the `for` name (blanks
  allowed) opens a word list. No word inside it is at command position, so
  nothing inside opens a case, acts as a compound closing or starts a head.
  Its `)` gives the enclosing context command position (`for x (a) {`).
  This form applies to `for` only.
- `coproc`: the next word is at command position (`coproc {`). When that
  word is an ordinary word (a NAME or a command name), the word after it is
  at command position as well (`coproc c {`).
- zsh `repeat`: the next word (the count) is an ordinary word, never a
  keyword; the word after it is at command position (`repeat 1 {`).

### 5. Head lifetime

A head state lasts only until its head completes or the next character
rules it out (for `name()`, anything other than blanks followed by `(`). A
separator (`;`, `&`, `|`, newline) or the end of the context ends any head
state still pending, and the position after it follows FR1's separator
rule.

### 6. Reserved words on the pair-stripped sequence (FR1, FR5, FR11)

Every word whose identity changes the reading is decided on the character
sequence with continuation pairs removed: the FR1 reserved words (`then`,
`do`, `else`, `elif`, `if`, `while`, `until`, `time`, `!`, `{`), the closing
words (`fi`, `done`, `}`, `]]`) and `[[`, `function`, and the head words
(`for`, `select`, `coproc`, `repeat`). The rules are the ones already applied
to `case` / `in` / `esac`:

- pairs between the characters or directly after the word do not prevent
  recognition (`th\<NL>en`, `f\<NL>i`, `f\<NL>or`);
- a sequence that does not spell the word once the pairs are removed is not
  that word;
- a pair inside a word never splits it.

The linear bound carries over: a match starts only at a word start and
examines only the word's characters plus the pair runs between and directly
after them, and a failed match is not retried inside the same word.

### 7. Docstrings and copies (FR6, FR7, NFR2, NFR3)

- The `_skip_substitution` docstring, phase descriptions included, is
  rewritten to state sections 2–6. The sentence "A list that goes on after a
  nested context closes (a substitution, a subshell, quotes, a case
  statement) goes on inside a word, so its state is false." is replaced by a
  statement that separates word-internal closings (no command position) from
  compound closings (command position).
- If `_keyword_end` or `_read_command_word` remains, its docstring is
  rewritten to the pair-stripped rule of section 6.
- Phrases pinned by `TestSubstitutionSkipDocumentation` that predate this
  feature stay (READ_MARKERS, UNDECIDABLE_MARKERS, MODULE_SENTENCE, and the
  absence of STALE_SENTENCE). The RULE_MARKERS added earlier in this feature
  may be rewritten in the same commit as the docstring.
- No recursion is introduced: no method reachable from `_skip_substitution`
  is `_skip_substitution`, `_read_quoted_unit`, `parse` or
  `_remove_range_quotes`. Only the standard library is used. The em-review
  copy is made byte-identical to the em-workflow copy in the same commit.
