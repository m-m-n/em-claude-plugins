# Task Plan: task0001 — Fix case-statement reading in the guard's substitution reader

## Goal

The substitution reader of codex-hook-interactive-guard reads a `case`
statement inside `$( )` correctly when it meets an argument-position
`case` / `esac`, a comment directly after a pattern `)`, or a line
continuation, in both plugin copies, and `CASES` plus linear-time tests pin
every reproduction and derived input.

## Design

Cross-task contracts (two-copy identity, the `CASES` row shape, the
reader's signature/result/recursion/linearity contract) and scope limits
(D2) are in IMPLEMENTATION.md and are not restated here. Notation: `<NL>` is
a newline, `\<NL>` a continuation pair (backslash directly followed by a
newline).

### 1. Command-position state (FR1, SPEC A1–A3)

- Each command-list context the reader keeps — the body of a `$(`, the
  body of a nested subshell `(`, and each case item body — carries one
  constant-size piece of state: whether the next word is at command
  position.
- It becomes true when the context opens (list start); after `;`, `&` or
  `|` (including `&&` and `||`); after a newline; after a subshell `(`; and
  after a standalone word `then`, `do`, `else`, `elif`, `if`, `while`,
  `until`, `time`, `!` or `{` that was itself read at command position.
- It becomes false after any other word: a reserved word or `!` read at
  argument position, an ordinary command word, a `time` option, an
  assignment, a redirection target (A3 behavior unchanged). A word that
  contains a substitution counts as an ordinary word.
- The backward look at the previous word's characters
  (`_at_command_position`) is no longer the basis of any decision; the
  method is removed or reduced to reading this state.

### 2. Opening and closing a case statement (FR2)

- `case` opens a statement only when it is a standalone word read at
  command position in a command-list context.
- In an item body, `esac` closes the statement only when it is a standalone
  word read at command position. Where the reader waits for a pattern
  (after `in`, after an item terminator), `esac` closes the statement as it
  does today.
- `case` / `esac` at argument position — including after a reserved word or
  `!` that is itself at argument position — is an ordinary word and neither
  opens nor closes anything (`_is_case_keyword` and any other keyword check
  follow the same rule).

### 3. Comment directly after a pattern `)` (FR3, SPEC A5, A8)

- When the `)` that closes an item's pattern is immediately followed by
  `#` (no blank in between), the `#` starts a comment that runs to the
  newline. Nothing inside it — `esac`, `)`, quotes — closes a statement,
  closes a substitution, or opens a quote. After the newline the item body
  starts at command position.
- `#` after any other `)` and the body-internal `x\<NL>#c` reading keep
  their current handling (A5); zsh extendedglob `(x)#` is not considered
  (A8).

### 4. Continuation pairs in waiting phases and in keywords (FR4, FR5, NFR1)

- Waiting phases: before the subject word, after the subject word (waiting
  for `in`), the pattern position, after a pattern's leading `(`, and the
  item-body start. In each, a continuation pair is skipped without starting
  a word, and the phase is kept.
- `case`, `in` and `esac` are decided on the character sequence with
  continuation pairs removed:
  - pairs between the keyword's characters are skipped (`ca\<NL>se`,
    `i\<NL>n`, `es\<NL>ac` are keywords);
  - pairs directly after the keyword are skipped before the standalone-word
    check looks at the next character (`case\<NL> x`, `in\<NL> x)`,
    `esac\<NL>)`);
  - a sequence that does not spell the keyword once the pairs are removed
    is not a keyword (`ca\<NL>sex`, `es\<NL>acx`);
  - a pair inside a word never splits it (`x\<NL>case` is one word, not a
    keyword).
- Linear bound: a keyword match starts only at a word start and examines
  only the keyword's characters plus the pair runs between and directly
  after them. A failed match is not retried from inside the same word; the
  reader consumes the rest of that word once as an ordinary word. The
  number of matches that re-read the same pair run is bounded by a
  constant. No recursion is introduced (NFR2).

### 5. Docstrings and copies (FR6, FR7, NFR3)

- The `_skip_substitution` docstring, phase descriptions included, is
  rewritten to state rules 1–4 above; every phrase pinned by
  `TestSubstitutionSkipDocumentation` stays. A keyword-check method that
  remains gets its docstring rewritten to the pair-stripped rule.
- Only the standard library is used. The em-review copy is made
  byte-identical to the em-workflow copy in the same commit.
