# Task Plan: task0002 — plugin version bump to the next patch level

## Goal

The installed plugin cache stops serving the previous hook, because both
plugin manifests declare the same new patch version for this plugin.

## Requirements

FR7

## Scope

### Files to Create

This task creates no new file.

### Files to Modify

- `em-workflow/.claude-plugin/plugin.json` — the plugin's own version field is raised to the next patch level
- `.claude-plugin/marketplace.json` — the version field of this plugin's marketplace entry is raised to the same value

## Design

The cross-task contract for these two fields (single owner, identical value,
no other plugin's version moves) is in IMPLEMENTATION.md and is not restated
here.

- Current value in both places: 0.1.55. Target value in both places: 0.1.56.
  The step is one patch level because the feature is a behaviour fix, per the
  project's version-bump rule.
- The plugin manifest carries the version of this plugin only. The
  marketplace manifest lists several plugins; only the entry whose source
  points at this plugin is edited.
- Both files are JSON. Only the two version values change — no key is added,
  removed or reordered, and the surrounding formatting is preserved so the
  diff is two lines.
- This task depends on no code produced by any other task and produces nothing
  any other task consumes.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The plugin manifest's version field reads 0.1.56.
- [ ] AC-2: This plugin's entry in the marketplace manifest has a version
      field reading 0.1.56.
- [ ] AC-3: The two values are identical, and no other plugin's version in the
      marketplace manifest changed.
- [ ] AC-4: Both files still parse as JSON, and the diff for this task is
      confined to the two version values.

## Test Notes

- No unit test exists for a manifest version field; the criteria are verified
  by parsing each file and comparing the two values, and by inspecting the
  diff. Record that check in the task's test record.
- The repository-wide unit test suite is run as a regression guard: a
  malformed manifest must not be introduced.
- The freshness of the installed plugin cache after this bump is an optional
  environment-dependent check recorded in VERIFICATION.md, not a criterion of
  this task.

## Out of Scope

- Any change to the hook, the case table or the suite runner (task0001 owns
  those).
- Any version change to a plugin other than this one.
- Publishing, installing or refreshing the plugin cache.
- Changelog or documentation edits.
