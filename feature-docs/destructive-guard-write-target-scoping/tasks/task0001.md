# Task Plan: task0001 — write-target scoping of the self-modification judgment

## Goal

The guard stops judging read-only commands that merely mention the Claude Code
configuration directory, while every self-config write still asks and every
transcript write still denies — achieved by matching the two detection
patterns against an assembled set of write-target paths instead of the whole
command segment, with the false-positive cases added to the expectation suite
first.

## Requirements

## Design

Cross-task conventions (judgment vocabulary, append-only expectation data,
static-analysis-only rule, standard-library-only rule, error-handling policy)

### Step 1 — the failing cases

Five commands are appended to the case table, all with an allow expectation,
in the table's existing three-element form (expected judgment, label,
command). Their commands are exactly the ones enumerated in FR1: a recursive
grep over the skills directory with standard error discarded; a directory
listing of the same with standard error discarded and piped into a pager-like
stage; a copy of the settings file made by reading it and redirecting standard
output into a temporary path; a transcript file read with standard error
discarded; and a transcript glob searched with standard error discarded. The
labels follow the naming style already used in the table. With only this step
applied, the suite is expected to fail on these five and only these five.

### Step 2 — the write-target set

The self-modification judgment stops asking "does this segment perform a
write, and does the segment text mention a protected path" and instead asks
"which paths does this segment write to, and is any of them protected". Its
signature may change; it has a single caller.

For one segment, the set is assembled from exactly three sources:

| Source | What enters the set | What must not enter |
|---|---|---|
| Output redirects | The target side of each redirect that is not the operator, for output and append forms alike | Input redirect forms (here-documents and here-strings included); the operator tokens themselves |
| In-place writers and the in-place stream editor | Each non-flag argument of a command in the in-place writer family, and of the stream editor when invoked with an in-place flag | Flags, including the attached-value variants of the in-place flag |
| File-manipulating commands | For copy, move and link: the last non-flag argument only, which is the destination. For remove, mode change and ownership change: every non-flag argument | Flags in every position |

The two detection patterns are then applied to the members of that set only,
in the existing order: the self-config pattern yields the existing ask
judgment with its existing reason, and the transcript pattern yields the
existing deny judgment with its existing reason. Neither pattern's own
definition changes; the leading boundary alternative of the self-config
pattern already matches at the start of a standalone token.

Flow for one segment:

1. Split the segment into its command word, arguments and redirects, as today.
2. Assemble the write-target set from the three sources above.
3. If the set is empty, return without performing either judgment.
4. Otherwise test each member against the self-config pattern, then against
   the transcript pattern, and emit the corresponding judgment on the first
   match.
5. If no member matches, no judgment is emitted for this segment.

Behavioural consequences that must hold by construction:

- A command whose only redirect target is the null device ends up with a set
  whose only members are that device and, for a descriptor-duplicating
  redirect, a bare descriptor number. Neither matches either pattern.
- A protected path appearing only as a read source — as an argument of a
  reading command, or as the source of a copy — never enters the set.
- Segments are still judged one at a time; each stage of a pipeline is its own
  segment.
- A non-path token in the set is harmless, so the assembly must tolerate one
  rather than assume every member is a path.
- A target that cannot be statically resolved (a glob or a variable) is
  handled without raising; the deletion-side rules that already judge such
  commands are untouched and continue to fire first.

### Step 3 — nothing else moves

The deletion judgment and its allowance rule are read-only for this task. So
are the two plugin manifests.

## Test Notes

- The suite runner is the single test vehicle for every criterion above; it is
  the project's expectation suite for this hook, and it is run before the fix
  (AC-2, expected red) and after it (AC-3, expected green). Write the cases
  first, observe red, then implement — the red observation is itself an
  acceptance criterion and cannot be skipped or reconstructed afterwards.
- AC-4 is verified from the diff, not from a test run: a passing suite does
  not by itself prove the existing cases were left alone.
- Edge cases worth an explicit case or an explicit reasoning note: a
  descriptor-duplicating redirect, whose target side is a bare number; append
  redirect forms, which are writes and must keep their ask; input redirect
  forms including here-strings, which must stay out of the set so the existing
  here-string allowance survives; an in-place writer invoked with a flag
  before the target, where the flag must not be taken for the target; a copy
  whose destination is a temporary directory (allow) versus one whose
  destination is the settings file (ask); a move with several sources, where
  only the last argument is the destination; a symbolic link creation, where
  the created path is the last argument; the attached-value and empty-suffix
  variants of the in-place editor flag, where the editing script may end up in
  the extracted arguments without matching either pattern; a segment whose
  assembled set is empty, which must return without raising.
- Adding cases beyond the five FR1 ones is allowed and encouraged where an
  edge case above is not already represented, subject to the append-only rule.
- Nothing here is TDD-awkward: every criterion is expressible as a case in the
  existing table or as a diff inspection.
