# Task Plan: task0003 — write-target set completeness (move sources, flag-borne destinations, redirect provenance)

## Goal

The write-target set contains every path a segment actually destroys or
overwrites, so that the judgments the guard emitted before this feature are all
still emitted: a move consumes its sources, a destination named by a flag is a
destination, and a data word that merely looks like a redirect operator no
longer displaces the real redirect target.

## Provenance

- `source`: review
- `review_round`: 1
- `source_ids`: `f11305d4611accd7`, `4eb3d5ac5355b1e5`, `2a1195baa7a2e0d1`,
  `3e3993733fd77a92`, `66fb7959516d7243`

All five findings report the same root cause from four review perspectives: the
assembled write-target set omits paths the segment writes, and because an
unmatched command is allowed outright and skips the auto-mode classifier, every
omission is a detection gap rather than a nuisance.

## Design

Cross-task conventions (judgment vocabulary, append-only expectation data,
static-analysis-only rule, standard-library-only rule, error-handling policy)
and the detection-floor decision are in IMPLEMENTATION.md and are not restated
here. The floor is what this task restores: a command that was ask or deny
before this feature, and is not one of the false positives the feature was
created to remove, must not be allow.

### Part 1 — a move writes to its sources as well as its destination

Copy and link create something at the destination and only read their sources;
move unlinks each source. The destination-only rule is therefore correct for
copy and link and wrong for move.

| Command family | Write targets |
|---|---|
| copy, link | the destination only (the last non-flag argument) |
| move | every non-flag argument — each source is unlinked, and the destination is written |
| remove, mode change, ownership change | every non-flag argument (unchanged) |

Postconditions:

- A move whose source is under the protected configuration tree asks, and a
  move whose source is a session transcript denies, whatever its destination is.
- A copy whose only protected path is its source stays allow — the read-source
  allowance is scoped to paths that are genuinely only read, and a move's source
  is not one of them.

### Part 2 — a destination named by a flag is still a destination

The set is assembled today from non-flag arguments only, so a destination
supplied as the value of a target-directory flag is invisible: the flag token
itself is filtered out as a flag, and its value is either a separate token that
is filtered as the flag's value or is fused into the flag token by an `=` sign.
The value is a destination in both spellings.

Postconditions:

- For copy, move, link and the in-place installer, a target-directory flag's
  value enters the set in both the separate-token spelling and the
  attached-`=` spelling.
- The flag's own token never enters the set.
- A positional destination continues to be found exactly as before; the
  flag-borne form is an addition, not a replacement.

### Part 3 — a redirect operator is recognized from syntax, not from text

The redirect-derived source of the set walks a flat token list and decides what
is an operator by testing each token's text against the operator shape. Quote
and escape provenance is already gone by then, so a data word whose text
happens to be an operator is indistinguishable from a real operator: the walk
pairs the data word with the token after it, falls out of step, and the real
redirect's target never enters the set. A command that writes to a protected
path is then allowed.

Contract for this part:

- The token stream the redirect separation and the target derivation consume
  carries, per token, whether that token came from unquoted shell operator
  syntax or is a data word. Both consult only that marking; neither infers
  operator-ness from a token's text.
- A data word never pairs with the token that follows it, and never displaces a
  real redirect's target.
- A real redirect's target enters the set even when a data word of operator
  shape appears earlier in the same segment.
- A quoted string that contains operator-shaped text but no real redirect
  produces no write target at all from the redirect source — the existing
  allowance for such a command is preserved.
- On the one path where a segment cannot be lexed at all (the existing
  parse-failure fallback), provenance is unavailable, so that segment is judged
  conservatively by matching the protected patterns against the whole segment
  text — the behaviour that path had before this feature. Failing closed there
  is deliberate: an unlexable segment must not end up with an empty set and an
  outright allow. This applies to the parse-failure path only and never to a
  segment that lexed successfully.

### Part 4 — the one corrected expectation

The case table currently carries an entry expecting a move out of the protected
hooks directory to be allow. It is not one of the pre-existing entries the
feature is required to leave untouched; it was added while this feature was
implemented, and it pins the exact gap this task repairs. Its expected judgment
becomes ask. Every pre-existing entry, and every entry expecting ask or deny,
is left exactly as it is.

## Test Notes

- The expectation suite is the single test vehicle for AC-1 through AC-5, and
  the repository-wide unit suite for AC-6. Write the cases first, observe red,
  then change the judgment — the red observation is itself an acceptance
  criterion (AC-1) and cannot be reconstructed afterwards.
- AC-3, AC-4 and AC-7 are verified from the diff, not from a run: a green suite
  does not by itself prove that an existing entry or an untouched judgment was
  left alone.
- Worth an explicit case or an explicit reasoning note beyond AC-1: a move with
  several sources where a protected path is not in the last position; a link
  creation, whose created path remains the last argument; a copy whose
  destination is the settings file, which must stay ask; a target-directory flag
  whose value is a directory rather than a file; a segment combining a
  target-directory flag with a redirect; a descriptor-duplicating redirect,
  whose target side is a bare number and must remain harmless; append redirect
  forms, which are writes and keep their ask; input redirect forms including
  here-strings, which must stay out of the set.
- Any new false positive discovered while doing this gets its own allow case
  added before it is fixed, per the project's hook-test rule.
