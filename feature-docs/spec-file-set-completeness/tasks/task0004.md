# Task Plan: task0004 — Invariant guards for the declared change set

## Goal

A single document-contract module pins the four invariants this feature
asserts about documents it does NOT edit: no verify-side exclusion rule
exists anywhere in the phase/contract documents, the already-consistent
`recycled-task-id-consistency` feature-docs are not regressed, the
default-membership enumeration is not restated by a third document inside
the plugin directory, and nothing added by this feature imposes the new
section on SPECs that never declared a closed file set.

## Requirements

FR6, FR7, FR8, NFR1, NFR2, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `tests/test_declared_change_set_invariants.py` — the four guards (TS-8,
  TS-9, TS-11, TS-12) with the negative proofs and non-vacuity guards TS-13
  requires.

### Files to Modify

None — this task edits no existing file; every document it reads is a
document this feature must leave untouched.

## Design

Every assertion here holds in this task's own worktree, where no sibling
edit exists, and becomes stronger — never weaker — once the sibling
branches merge (IMPLEMENTATION.md **D2**, **D7**).

### G1 — No verify-side exclusion rule (TS-8, FR6)

Scanned documents: `em-workflow/references/implement-phase.md`,
`review-phase.md`, `review-protocol.md`, `phases/create-spec-phase.md`,
`phases/create-plan-phase.md`, `rework-task-synthesis.md`, and every file
directly under `em-workflow/references/contracts/`.

The matcher looks for a statement that removes workflow-generated artifacts
from the observed change set at verification time. It requires all three of
these in one proximity window, not merely an exclusion word:

1. an exclusion expression (exclude / excluded from / subtract / ignore /
   除外),
2. a workflow-artifact-root token (`feature-docs/`, `test-docs/`, or a
   phrase naming workflow-generated artifacts), and
3. a change-set or verification token (change set / 変更集合 / containment /
   verification).

**Known near miss — do not "fix" it.** `phases/create-spec-phase.md`
contains a sentence about excluding the HEAD layer from the scope-snapshot
computation, in the same document as the phrase "the worker's change set".
That is about which snapshot layer the scope check reads, not about
subtracting artifacts from the observed change set, and the document is one
FR6 forbids modifying. If the matcher flags it, narrow the matcher — never
edit the document.

The guard asserts the offender list is empty, plus a non-vacuity guard that
every scanned path exists and was actually read.

### G2 — Retention pin for the already-consistent feature (TS-9, FR7)

Reads `feature-docs/recycled-task-id-consistency/SPEC.md` and
`feature-docs/recycled-task-id-consistency/REQUIREMENTS.md` by explicit
literal path (never by wildcard — see G4) and asserts each still enumerates
`test-docs/recycled-task-id-consistency/**` in its change-containment
statement: in the SPEC within both the FR8 and the AC-8 statements, and in
the REQUIREMENTS document within the corresponding constraint. This is a
retention matcher: it is green before and after this feature, and it needs
no negative proof — record the exemption in the module docstring.

### G3 — No third restatement of the default membership (TS-11, NFR2)

Uses IMPLEMENTATION.md's **Contract MK**: a file carries the enumeration if
and only if it contains BOTH `feature-docs/{feature}/**` and
`test-docs/{feature}/**`. The guard walks every text file under the
`em-workflow/` plugin directory, collects the carriers, and asserts that set
is a SUBSET of the two template paths of Contract AN. In this worktree the
carrier set is empty (neither template is edited here); after the sibling
branches merge it is exactly the two templates, which is what makes the
subset form the correct per-worktree statement (D2).

Contract MK exists because the single-literal form is wrong:
`review-phase.md` already contains the feature-docs root literal and
`implement-phase.md` already contains a test-docs path without the
double-star form. Both must remain non-carriers under this matcher.

Non-vacuity: assert the walk visited a non-trivial number of files, and
prove the carrier detector works by running it over a synthetic sample that
contains both literals.

### G4 — No retroactive obligation on existing SPECs (TS-12, NFR6)

Walks every module under `tests/` as it exists in the current tree and
asserts that none of them combines (a) a wildcard, glob or directory walk
over SPEC paths under `feature-docs/` with (b) a requirement that the
Declared Change Set section be present. A module that reads one named SPEC
by literal path — as G2 does — is not an offender; the distinction is the
wildcard.

Non-vacuity: assert the walk found at least the modules that exist, and
prove the detector works by running it over a synthetic module text that
contains both halves.

## Test Notes

- Integration level in the repository's sense: the assertions range over
  many files rather than one document, but they are still document-contract
  checks in the project's unit-test harness; no E2E harness exists.
- This task has no production edit, so the tdd-testing red phase is produced
  against the synthetic violating samples rather than against the
  repository: each matcher must be shown to flag its sample BEFORE the
  repository-wide assertion is accepted as meaningful. A guard that has
  never been seen to fire is not a guard (IMPLEMENTATION.md D7).
- Edge case: file walks must skip binary and non-text content gracefully and
  must not follow anything outside the repository root.
- Edge case: the carrier walk is scoped to the plugin directory. This
  feature's own SPEC legitimately contains both root literals
  (IMPLEMENTATION.md D6), so the scan root must be asserted explicitly
  rather than left implicit.
- Edge case: the contracts directory may gain files later; scan the
  directory rather than a hard-coded file list, and assert it is non-empty.

## Out of Scope

- Both template edits and the version bump — sibling tasks own them; this
  worktree must not contain either edit.
- Asserting that the two templates DO carry the enumeration (that is the
  presence half, owned by the template tasks per IMPLEMENTATION.md D2).
- Editing any document this module reads — every one of them is a file FR6
  or FR7 forbids modifying. A failing guard is fixed by narrowing the
  matcher or by reporting a genuine finding, never by editing the scanned
  document.
- Editing any pre-existing module under `tests/` (NFR4).
