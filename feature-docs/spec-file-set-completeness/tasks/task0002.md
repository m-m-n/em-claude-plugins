## Design

### The inserted subsection

Position is fixed by IMPLEMENTATION.md's **Contract AN**: the heading
`### 9.4 宣言された変更集合`, placed under the existing `## 9. 制約条件`,
after `### 9.3 スケジュール制約` and before `## 10. 想定される課題とリスク`,
inside the template's fenced body. Content is fixed by **Contract DM**
(rows DM-1 .. DM-9). This task realises the Japanese half:

1. The subsection provides a placeholder list for the feature-specific paths
   the author enumerates, in the template's existing placeholder convention
   (DM-8).
2. It states the fixed default membership: both root literals verbatim
   (DM-1), the feature-docs members and the test-docs member enumerated
   verbatim (DM-2, DM-3), each attributed to the document that owns its
   generation by citation only (DM-4).
3. It states the two semantics: default-unless-explicitly-removed (DM-5)
   and superset/containment with the zero-implement-task instance
   (DM-6, DM-7).
4. It carries no rationale beyond what the requirements state, and
   introduces no rule that subtracts anything from the observed change set
   at verification time (DM-9).

Why a subsection and not a new top-level section (FR2): the template's
top-level sections are numbered `## 1. 概要` .. `## 15. 参考資料`, and every
document rendered from it — plus every reference that cites a section by
number — depends on those numbers. Adding a subsection under
`## 9. 制約条件` adds the content without renumbering anything.

Style (NFR3): Japanese, the `### N.M` numbering form, and the whole
addition INSIDE the fenced template body — the body opened by the file's
first fenced-markdown line and closed by the file's final fence line
(IMPLEMENTATION.md **D5**; the body already contains nested fenced and
front-matter blocks, so the boundary is taken from the first opening and
last closing fence).

### The document-contract module

Responsibilities, in the repository pattern named by IMPLEMENTATION.md's
Conventions:

| Responsibility | Behaviour |
|---|---|
| Position (TS-3) | The subsection anchor exists, its offset lies after the `### 9.3 スケジュール制約` anchor and before the `## 10. 想定される課題とリスク` anchor, and it lies strictly between the outer opening and closing fences |
| Numbering guard (TS-4) | Every pre-existing top-level heading from `## 1. 概要` through `## 15. 参考資料` is present with its number and title unchanged, and their relative order is unchanged |
| Root literals (TS-5, requirements half) | The sliced subsection contains both root literals of Contract MK |
| Enumeration and citation (TS-6, requirements half) | The sliced subsection names every DM-2 member and the DM-3 member, and cites `implement-phase.md` and the phase-state / phase documents |
| Semantics (TS-7, requirements half) | The sliced subsection states DM-5, DM-6 and DM-7, including the zero-implement-task instance |
| Negative proofs (TS-13) | Each NEW matcher above is exercised against a verbatim captured pre-change sample of the corresponding template text and reports absence; each sample carries a retained anchor asserted positively. The numbering guard is a retention matcher and is exempt — record the exemption explicitly in the module docstring |

Section slicing runs from the subsection anchor to the following anchor
(Contract AN). Prose assertions read the whitespace-normalized slice;
position and fence assertions read raw offsets.

The pre-change sample for the position and content matchers is the
constraints section as it reads at this task's base revision — its three
existing subsections are the retained anchors, since all three survive the
edit unchanged.

## Test Notes

- All assertions are unit-level document-contract checks over one file.
- Write the module first (tdd-testing): with the template unedited, the
  position and content matchers must FAIL, while the numbering guard and the
  negative proofs PASS. That split is itself informative — the numbering
  guard is expected to be green before and after, which is why it is
  declared a retention matcher rather than given a negative proof.
- Edge case: the heading text contains Japanese; assertions must compare the
  exact heading literal of Contract AN, not a normalized or partial form, so
  a renamed subsection is detected.
- Edge case: the constraints heading and the following top-level heading
  must each occur exactly once for the slice to be well-defined; assert
  uniqueness where the slice depends on it.
- Run the whole suite before reporting done — `tests/test_reference_sweep.py`
  and `tests/test_check_plugin_invariants.py` read this template.
