# Task Plan: task0001 — Allow only canonical absolute paths in the cd prefix path check

## Goal

The hook's cd prefix path check accepts only canonical absolute paths
strictly below an allowed area that itself lies inside the main worktree.
It refuses over-long paths before any file-system access and no longer
contains the stage walk, the physical-path fallback or the /proc and
/dev/fd handling. The two normative statements of the condition, the hook's
tests and past features' test records match the new check.

## Design

This task owns the enforcement side and the Path-condition statement of
IMPLEMENTATION.md (Shared Components, D1). It implements the enforcement
half of the Canonical worktree path contract (D2).

### Path condition (`is_below(path, area)`)

- Name and parameters stay as they are (SPEC Architecture).
- Precondition: `area` is an area that the area containment rule below has
  accepted.
- Postcondition: returns True only when every one of the following holds,
  and False otherwise. It never raises.
  1. The length bound below accepts the path.
  2. (a) The path is absolute, with no empty, `.` or `..` component other
     than the root.
  3. (b) The path, as written, lies strictly below `area`, compared per
     component by the existing `strictly_below`.
  4. (c) The path equals its own strict realpath (every component exists,
     links resolved).
  5. (d) The path is an existing directory.
- The path is never normalized before these checks. The text as written is
  what gets compared.
- Order: the length bound first (SPEC FR2). The lexical checks (a) and (b)
  come next, so text that is non-canonical or outside the area never reaches
  a file-system probe. Then (c), then (d).
- Any OSError or ValueError raised by any step makes the result False
  (FR3).

### Length bound (FR2)

- The bound is the path-length limit that the operating system reports for
  the root directory, obtained at run time (SPEC FR2).
- The length is the byte length of the path in the file-system encoding.
- Length greater than or equal to the bound: not allowed.
- Bound unobtainable (an error) or not positive: not allowed.
- A path that cannot be encoded: not allowed.
- One helper decides this. It is used at two places:
  - first in the cd prefix candidate decision (`is_cd_prefixed_approved`),
    before `worktree_area()` is called;
  - first in `is_below`, so a direct caller never reaches a probe with an
    over-bound path.
- An error raised while the bound is obtained or the path is encoded never
  escapes the caller (TM-3).

### Area containment (FR5)

- `worktree_area(common_dir)` keeps its "resolved area, or None" contract,
  narrowed as follows.
  - It returns the resolved `<main worktree>/.claude/worktrees/em-workflow`
    only when that resolution lies strictly below the realpath of the main
    worktree (the parent of the git common dir).
  - Otherwise it returns None.
  - It never raises.
- The caller already returns False for a None area, so the decision table
  does not change.

### Allowed scope (FR6)

Every existing canonical directory strictly below the area, at any depth.
The area itself is not below it.

### Removal (FR4)

- Remove `_stage_walk_refuses`, `_under_proc_or_dev_fd`,
  `FOLLOWED_LINK_LIMIT` and `resolves_to_directory`.
- Remove the dual logical/physical check: the comparison after normpath and
  the lenient realpath of the path as written.
- Remove imports that only served them.

### Unchanged (FR3)

- `CD_PREFIX_RE`, `cd_remainder_excluded` (E1 to E10) and `cd_prefix_allowed`
  stay as they are.
- Refusal patterns are still applied to the whole command first.
- `hook_main`'s decision table does not change.
- A form whose path is not allowed is judged as if it had no cd prefix,
  with no new deny.

### Normative statements (FR7, Path-condition statement)

- Hook module docstring: rewrite only the `path:` item of the
  `cd prefix:` paragraph. Keep the paragraph's shape: one paragraph, the
  items `syntax:`, `path:`, `approval:`, `operators:`, `safe side:`, and the
  statements after them.
- `is_below` docstring: state the new condition only.
- Protocol, `## Verbatim execution rule`: rewrite only the path bullet of the
  implementer exception list. Leave every other bullet and the rest of the
  section as they are.
- Both path items state the same content:
  - the area, and where it comes from (the main worktree is the parent of
    the git common dir; the area is its `.claude/worktrees/em-workflow`,
    used only when its realpath lies strictly below the realpath of the main
    worktree);
  - conditions (a) to (d), using the term "canonical absolute path"
    (IMPLEMENTATION.md Conventions);
  - that the path is never normalized and then accepted;
  - the length bound and its failure handling;
  - the any-depth scope;
  - that any resolution error counts as not below;
  - that the path is only resolved and never used as a child process's
    directory or argument.
- Remove every description of the logical path, the physical path, /proc,
  /dev/fd, the stage walk, the link-target rule and the stall continuation.

### Test clean-up principles (FR9)

1. A test that calls, patches or names a removed symbol is removed, or
   rewritten against the new check.
2. A test that asserts allow for a form the new check refuses becomes a
   silent case. This covers the former `FALLBACK_ALLOW_CASES` and the
   relative-link forms (SPEC TS3).
3. A test that pins the old path-condition wording is replaced by the new
   wording tests. This covers the two-sided logical/physical condition, the
   /proc and /dev/fd statement, the link-target rule and the stall
   continuation.
4. A test whose assertion still holds under the new check is kept as it
   is. Examples: silent through the hook, syntax, approval, guidance,
   refusal, NUL, standard library only.
5. A test that pins internal mechanics that no longer exist is removed.
   Examples: recordings proving nothing under /proc is probed, the order of
   the realpath calls, independence from strict-mode realpath, the
   followed-link bound.
6. The test module's docstring lists what the module now covers, this
   feature included.

### Past features' test records (FR10)

- In each record listed under Files, delete the IDs of deleted tests.
- Where a remaining or new test verifies the same acceptance criterion, put
  its ID in place of a deleted one.
- An acceptance criterion with nothing left keeps an empty `tests` list.
- No other field of a record is edited. Past features' feature-docs are not
  touched.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR6; TS1): Through the hook, `cd "<p>" && <approved string>`
  is allowed for each of these canonical existing directories:
  `<area>/task0001`, `<area>/task0001/sub/deeper`, a directory whose name
  holds a space, a directory whose name holds `&&`, and a git worktree below
  the area. Each is checked twice: once with the hook's cwd at the main
  worktree, once at a git worktree below the area.
- [ ] AC-2 (FR1, FR4, FR9; TS2, TS3, TS4; TM-1): Through the hook, each of
  the following forms is silent, and a direct `is_below` call returns False
  for each, so no form is accepted after normalization:
  - non-canonical text: `<in>/`, `<area>//task0001`, `//` followed by the
    rest of `<in>`, `<in>/.`, `<area>/./task0001`, `<in>/..`,
    `<in>/sub/../sub`;
  - links: a link inside the area to a directory inside the area, a link to
    a directory outside the area, a broken link, a link to a file, and every
    form of the former `FALLBACK_ALLOW_CASES` and of the relative-link
    tests;
  - other paths: `/`, the area itself, a sibling sharing the area's name
    prefix, another repository's area, a nonexistent path, a regular file,
    and each /proc and /dev/fd form the module already exercises.
- [ ] AC-3 (FR2, NFR4; TS5, TS6, TS13; TM-2):
  - For the text `/dev/null` followed by 32000 repetitions of `/x`, and for
    the area followed by 32000 repetitions of `/x`, both the cd prefix
    candidate decision and `is_below` return False. Recording doubles show
    that neither `worktree_area()` nor any file-system probe or resolution
    ran.
  - With the bound source replaced by a double, the result is False when it
    raises OSError, when it returns 0 and when it returns a negative value.
  - A path whose encoded length equals the bound is False. A path one byte
    shorter passes the length check and is decided by the remaining
    conditions.
  - For an existing canonical directory below the area, the number of
    file-system calls the check makes grows no faster than linearly with the
    number of components.
- [ ] AC-4 (FR5; TS7; TM-4): The fixture repositories cover three layouts.
  - `.claude/worktrees/em-workflow` is a link to a directory outside the main
    worktree: a canonical directory beyond it is silent through the hook.
  - An ancestor, `.claude`, is such a link: the same result.
  - `.claude/worktrees/em-workflow` is a link to a directory inside the main
    worktree: the cd prefix form that names the resolved canonical path is
    allowed, and the form that names the path through the link is silent.
- [ ] AC-5 (FR3, NFR2, NFR3, NFR5; TS8, TS15; TM-3):
  - Each of the following makes the path check False without raising: a

  - A cd prefix form whose remainder matches a refusal pattern still

  - The existing syntax, operator and safe-side tests pass unchanged, and

## Test Notes

- Unit level: run against the module loaded without writing bytecode,
  through the existing loader helper. This covers `is_below`, the candidate
  decision, `worktree_area` and the length helper for AC-2, AC-3, AC-5 and
  AC-6.
- Integration level: run the hook as a subprocess through the existing
  `Fixture.run_hook` for AC-1, AC-2, AC-4 and AC-5. Add fixture repositories
  for the AC-4 layouts next to the existing ones. Approvals are recorded
  through the record CLI for each new repository key.
- AC-3:
  - Over-bound paths: replace `worktree_area()` and the file-system entry
    points the check can reach with recording doubles, and assert they
    recorded nothing.
  - Boundary lengths: replace the bound source with a double that returns a
    small value. Do not build multi-kilobyte directory trees for this.
  - Linear growth: compare the number of recorded file-system calls for two
    sizes of existing directory chains. Use no wall-clock thresholds and no
    repeated-timing loops (no intentional CPU load).
- AC-5:
  - A character the file-system encoding cannot encode reaches the hook
    through JSON as an unpaired surrogate escape.
  - The length check in the candidate decision must contain that
    encoding error itself: it runs before `is_below`'s own guard.
- AC-6: follow the document-test convention of IMPLEMENTATION.md. Extract
  the path items the same way the current wording tests do: the module
  docstring between the `  - path:` and `  - approval:` lines, and the
  protocol path bullet inside `## Verbatim execution rule`.
- Constraints from tests outside this module, which must keep passing:
  - `tests/test_bash_guard_cd_prefix_operators.py` (the `cd prefix:`
    paragraph's statement list);
  - `tests/test_cd_prefix_exception_docs.py` (the protocol section contains
    "realpath", "double-quoted absolute path" and
    `.claude/worktrees/em-workflow/` after "below", "under" or "deeper" in
    the same sentence);
  - `tests/test_cd_prefix_operator_exclusion_docs.py` ("realpath" in the
    section);
  - the existing guard against the substring "status" in the hook's
    executable text.
- Red phase: the AC-2 non-canonical and link forms and the AC-4
  outside-link layout show red against the current hook, because some of
  them are allowed today. Record what was observed in the task's test
  record.
