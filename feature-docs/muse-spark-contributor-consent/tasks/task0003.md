# Task Plan: task0003 — written pre-dispatch criteria, with the review chains untouched

## Goal

Write, into both plugins' review registry and review protocol documents, the
criteria a dispatching LLM applies before dispatch to decide whether the
contributor tier may be used — while leaving every perspective's primary chain
byte-identical.

## Requirements

FR9, FR11, NFR3, NFR6

## Scope

### Files to Create
- `tests/test_contributor_tier_criteria.py` — asserts the written criteria and the
  chain immutability across both plugins.

### Files to Modify
- `em-workflow/references/reviewers.yaml` — add the criteria prose; chains unchanged.
- `em-review/references/reviewers.yaml` — the same, for this plugin.
- `em-workflow/references/review-phase.md` — add the exception to the

- `em-review/references/review-phase.md` — the same, for this plugin.
- `tests/test_reviewers_primary_chains.py` — extend only if the existing chain

## Design

### What is written, in all four documents

Four elements. Each must be identifiable as its own passage.

1. **The read-mapping rule.** When `muse-spark` is the chain entry the registry
   selected, reading it as the contributor tier is permitted only after two checks
   both pass: (a) consent for this project is recorded — mechanical, decided by the
   consent store, not by prose; and (b) this particular dispatch may use it —
   a per-dispatch judgment made by the dispatching LLM. The chain itself is never
   edited to reach the contributor tier; the registry defines exactly one permitted
   reading and no other.

2. **The exception to the substitution prohibition**, written into the review
   protocol document next to the clause forbidding the reviewer from substituting a
   model of its own choosing. It points at the read-mapping rule, states that the
   rule defines a single permitted reading rather than a free choice, and states
   that the judgment happens **before** dispatch — not inside the reviewer, and not
   after a hop has been spent.

3. **Per-dispatch: do not use — exactly one item.** A change whose core is an
   unpublished idea: a new feature whose design or approach is the project's own
   differentiator. The per-dispatch default is to use the contributor tier; this is
   not a fail-closed gate, and the security perspective is not excluded from it.

4. **Outside the scope of consent — exactly three items**, under their own separate
   heading, never merged with and never interleaved with item 3:

   - secrets present in the diff (API keys, credentials, internal endpoints,
     customer data);
   - third-party work (vendored code, externally supplied patches, contributors'
     pull requests);
   - the repository being private, or its license no longer being one the consent
     was reasonable under.

   The third item is phrased as a **present-state test performed at dispatch time**
   — "if the repository is currently private, or its license is no longer the one
   the consent was reasonable under, do not use the contributor tier" — and never
   as a comparison against a value recorded when consent was given. The consent
   store holds no such value, so such a comparison would be unimplementable as well
   as wrong.

The one-versus-three distinction is structural, not rhetorical: two distinct
headings, one bullet under the first, three bullets under the second
(IMPLEMENTATION.md Cross-task Design Decisions, D-D).

### Where the prose may go in the registry

The registry has a restricted parser with tests over it. Confine new prose to the
locations that parser tolerates — the header comment block, or outside the
perspectives block — and do not introduce the `cross_validation` literal into the
em-workflow registry, which currently contains none.

### What must not change

- Every perspective's primary chain, byte for byte, in both plugins. No entry is
  added, removed, reordered or re-modeled; the plain `muse-spark` entry stays where
  it is.
- No chain entry names the contributor tier anywhere.
- Per-perspective hop budgets are untouched, because the chain length is unchanged
  and the decision happens before dispatch.
- No new occurrence of the interactive-question tool name in any review-phase or
  develop-phase document (IMPLEMENTATION.md Shared Components, Interactive-question
  budget). The criteria are applied by the dispatching LLM without asking anyone.

### Consistency between the two plugins

The two review protocol documents are genuinely different documents and are not
being unified. Write the same four elements into each, in each document's own
voice and structure; the test asserts the elements' presence per file rather than
byte equality between plugins.

## Test Notes

- Write the test first: it is what makes "textually distinguishable" objective.
  Locate each document's consent section, then count bullets under each of the two
  headings and assert the counts are exactly one and exactly three.
- Assert the present-state phrasing positively (the dispatch-time condition is
  present) and negatively (no phrasing that compares against a recorded value).
- For chain immutability, compare the parsed chains against a literal expected
  structure written into the test, not against a value recomputed from the same
  file — a self-referential comparison would pass no matter what changed. Assert
  the contributor tier appears in no chain entry.
- Parameterize every assertion over both plugins.
- If `tests/test_reviewers_primary_chains.py` already pins the chains literally,
  leave it alone and assert only what it does not cover; if it recomputes, add the
  literal pinning in the new module rather than rewriting the existing one.

## Out of Scope

- Editing any chain, adding a contributor-tier chain entry, or changing hop
  budgets.
- Unifying the two plugins' review protocol documents or registries.
- Any executable enforcement of the three out-of-scope conditions — they are
  written criteria applied before dispatch, deliberately not machine-checked; the
  guard sees consent presence only.
- Touching the guard, the skill, or any version field.
- Updating documentation in other repositories that currently forbids the
  contributor tier for review.
