## Design

### Terms

- **Host statement**: the statement that holds the heredoc's own `<<`
  operator, as the guard's existing destination decision selects it.
- **Enclosing statement**: a statement around the substitution that holds
  the host statement, at each level up to the outermost, as the existing
  destination decision walks them.
- **Python name**: a command word whose match against `SINK_WORD_RE` is that
  pattern's Python alternative (`python`, `python3`, `python3.12`, ...). The
  Python vocabulary is taken from that one pattern, not from a second list
  that could drift from it.
- **Closed ordinary literal**: a Python string literal written with `'`,
  `"`, `'''` or `"""`, with no prefix or a prefix made only of the letters
  r, b and u in any case and combination, whose closing quote sequence is
  found in the body.
- **Masked text**: the body with the content of every closed ordinary literal
  replaced as defined under "Literal scan and masking".

### Component 1: Python-program eligibility (FR2, TM-1, TM-2, TM-3)

The guard's destination decision gains one new outcome, "Python program",
for a heredoc that meets every condition below. Whenever any condition fails,
the outcome is exactly what the decision returns today (sink, data or
undetermined), so no other shape changes (FR7). Every condition is
fail-closed: a shape the condition does not positively recognise fails it.

1. The host statement is lexed and its command word, after wrappers and
   assignments are skipped the way the existing decision skips them, is a
   Python name (FR2 (a)).
2. The words skipped before that command word do not make a destination
   undetermined under the guard's existing skipped-word rule: no sink among
   them, no `env` split-string option. Today that rule is applied only to a
   non-sink command word; here it is also required of the Python host
   (TM-2).
3. Python takes its program from this heredoc and from nothing else (TM-3):
   - the heredoc's operator carries no file-descriptor number, or carries 0;
   - it is the only heredoc of the host statement, and the host statement
     has no here-string;
   - every other redirect of the host statement is an output redirect to a
     file: `>`, `>>`, `>|`, `&>` or `&>>`, optionally preceded by a
     file-descriptor number other than 0. Any input redirect (`<`, `<>`),
     any duplication, move or close of a file descriptor (every `<&` and
     `>&` form, `2>&1` and `<&-` included), any redirect whose
     file-descriptor number is 0, and any redirect with a named file
     descriptor fails this condition;
   - every word after the command word, redirects excluded, is either the
     lone `-` or a short-option cluster: one `-` followed by letters only,
     containing neither `c` nor `m`. A script operand, `-c`, `-m`, a long
     option, or an option value written as its own word fails this
     condition.
4. The host statement's downstream pipeline, including the downstream of any
   group open at it, has no sink stage and no undetermined stage, and the
   host statement holds no process substitution (FR2 (b), TM-1).
5. Every enclosing statement is lexed, has no sink command word, has no sink
   or undetermined stage downstream, holds no process substitution, and is
   either assignment-only or headed by a word in `DATA_COMMANDS` (FR2 (c),
   TM-1).

### Component 2: Literal scan and masking (FR1, FR3, FR4, FR6, NFR1, NFR2)

Contract — input: one heredoc body as written. Output: either
"undecidable", or the masked text.

Postconditions of the masked text:

- It has exactly the body's length, and every line feed sits at the same
  position as in the body.
- Every character outside the content of a closed ordinary literal is
  unchanged: quote sequences, prefix letters, comments and all code between
  literals.
- Every other character of a closed ordinary literal's content is replaced
  by one fixed filler character that has no meaning to shell or Python
  quoting: not a quote, backslash, `$`, backtick, `#`, shell operator
  character or whitespace.

Scan rules, applied in one left-to-right pass over the body:

1. Outside any literal, `#` starts a comment that ends at the next line
   feed; a quote inside a comment opens nothing (FR3).
2. Outside any literal, `'` or `"` opens a literal. When the next two
   characters are the same quote, the literal is triple-quoted.
3. The prefix of a literal is the run of identifier characters (letters,
   digits, `_`) immediately before its opening quote. An empty prefix, or
   one made only of r, b and u in any case, makes it an ordinary literal,
   which is masked. Any other prefix — every prefix containing f or t in
   any case included — makes the whole body undecidable at that point, and
   the scan stops (FR4, FR6). This is fail-closed: an f-string or t-string
   may nest quotes of its own kind inside a replacement field, so its extent
   is never guessed, and no text of a body holding one is masked.
4. A backslash inside a literal, raw or not, consumes the next character
   (a line feed included) for the purpose of finding the closing quote.
5. A single-quoted or double-quoted (non-triple) ordinary literal closes at
   the next unconsumed quote of the same kind. Reaching an unconsumed line
   feed first makes the body undecidable.
6. A triple-quoted ordinary literal closes at the next unconsumed run of its
   three quotes and may span lines.
7. Reaching the end of the body inside any literal makes the body
   undecidable (FR6).
8. Whether the whole body is valid Python is not checked (FR3).

No part of the body is evaluated, compiled, executed or imported, the
running interpreter's own tokenizer or parser is not used, and only the
standard library is used (NFR1, TM-7). Each character is visited a bounded
number of times (NFR2, TM-6).

### Component 3: Body handling (FR1, FR5, FR6, TM-2, TM-5)

For a heredoc whose outcome is "Python program" and whose body is not blank:

1. When a command-name override construct (the guard's existing reading:
   a function definition, `alias` / `hash` / `enable`, a PATH assignment)
   has already been seen in the command, the body is handled exactly as a
   sink body is today (TM-2).
2. Otherwise the literal scan runs. "Undecidable" means the body is handled
   exactly as a sink body is today (FR6).
3. Otherwise the masked text is queued whole in place of the body, at the
   anchor a sink body gets today. The masked text is the only version of this
   body that any later stage reads — the statement reading, the parse-failure
   fallback's raw-text matching, and the chunk-level sink-word match (FR1) —
   except for the two uses in steps 4 and 5.
4. When the delimiter is unquoted, the substitutions of the original,
   unmasked body are also extracted and queued exactly as the guard does for
   a data heredoc body with an unquoted delimiter: outermost `$( )`,
   backticks and the command forms of `${`, an escaped opener not counted,
   and the whole original body queued when an opener does not close (FR5,
   TM-5). A substitution outside literals may be reached by both routes;
   that does not change the decision.
5. The original body is parked so that, when a command-name override
   construct is seen later in the same command, the original body is queued
   whole, through the same deferral the guard already uses for data heredoc
   bodies. The flag is raised once, so a parked body is queued at most once
   (TM-2).

Masked text replaces the body rather than being added to it, so the
existing relative scan budget is unchanged for every command without an
override construct (NFR2, TM-6).

### Test cases

Every new case uses the three-element form (decision, label, command) with
no fourth element. Each label is a Japanese label in the style of the
existing labels, stating the shape and the outcome, unique in the file. No
command holds a machine-specific path or a home-directory path. In the
lists below, each command is given line by line; the lines are joined by
single line feeds with no line feed after the last line, and in the case
file the line feeds are written as JSON escapes.

In TS-2 the two characters before the closing quote of the `f.write`
argument are a backslash and `n` (written `\\n` in the JSON string), not a
line feed; a line feed there would leave that literal unclosed.

The body line ``x = "`git branch -D example`"`` is called the **probe line**
below.
