# Task Plan: task0002 — Stop literal masking on name- or state-changing statements read through nested builtin / command

## Goal

A command that holds a statement replacing a command name, changing shell
state or variable attributes, or having a command word that cannot be fixed
statically as a single word — read after any number of nested `builtin` /
`command` words with their options and `--`, and judged on the word as
written — never has a Python-program heredoc body masked, whether that
statement stands before or after the heredoc. The words that stop masking are
derived from the command-name override vocabulary, and the code of a
Python-program body re-read as shell does not trigger the undeterminable-word
rule.

## Requirements

FR7, FR8, FR9, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/hooks/destructive-guard.py` — the word reading, the command-word peel, the derived stop vocabulary, the masking-stop check and the Python-body mark below
- `em-workflow/hooks/tests/destructive-guard-cases.json` — the new deny and allow cases and the pinned TS-31 case below, added before the guard is changed

## Design

### Starting point

The guard as merged already has the Python-program outcome, the literal
masking and the run-wide masking-stop flag with its parking of original bodies
(IMPLEMENTATION.md, Shared Components: "Python-program masking path" and
"Masking-stop flag"). This task changes what raises that flag, and adds the
Python-body mark to the chunks that path queues.

Today the per-statement check that raises the flag
(`_python_mask_unsafe_words`) reads token values after quote removal, removes
at most one `builtin` or `command` word and reads no option and no `--` after
it, keeps its own list of state builtins (`PYTHON_MASK_STATE_BUILTINS`) that
leaves out the override builtins, spells the override variable name a second
time, treats only `$`, a backtick and a substitution leftover as unreadable,
and starts from the command-word reading, which passes over a word built
entirely from a substitution. So `builtin builtin declare`,
`builtin command declare`, `builtin -- declare`, `builtin builtin alias`,
`{declare,-i}`, `decl?re` and `$(printf declare)` all leave masking on. This
task replaces that check and that list.

Terms used below:

- **Override reading**, **command-word reading**: IMPLEMENTATION.md, Shared
  Components.
- **Override vocabulary**: the override builtin set (`alias`, `hash`,
  `enable`; today `OVERRIDE_BUILTINS`) and the override variable name
  (`BASH_CMDS`) that the override reading matches.
- **Word as written**: the characters of a word in the chunk text its
  statement was lexed from, before quote removal, escape processing and
  expansion, together with the lexer's region kinds over those characters
  (the quote kinds, the substitution kinds, parameter and arithmetic
  expansion, array subscript).
- **Python-body chunk**: a chunk carrying the mark of Component 5
  (IMPLEMENTATION.md, D4).

### Component 1: Word reading (FR9 (3))

Contract — input: one word as written. Output: either the restored word (the
one fixed word the shell passes on) or "undeterminable".

The word's constituents are read left to right:

| Constituent of the word as written | Result |
|---|---|
| Unquoted characters with none of the meanings below | kept as written |
| A backslash outside quotes | escapes the next character, which is kept; a backslash-newline pair is removed, as bash removes it |
| A single-quoted region | its content as written |
| A double-quoted region | its content, with a backslash before `$`, a backtick, `"`, `\` or a newline resolved; an unescaped `$` or backtick inside makes the word undeterminable |
| An ANSI-C quote (`$'...'`) | its content decoded, when every escape in it is one the decoder supports and decodes as bash does; any other escape makes the word undeterminable |
| A locale quote (`$"..."`) | undeterminable |
| A parameter expansion (a name, `${...}`, a positional or special parameter), a command substitution in any form (`$( )`, a backtick pair, the command forms of `${`, a substitution leftover, a word built entirely from a substitution), an arithmetic expansion, a process substitution | undeterminable |
| An unquoted `*` or `?`, or an unquoted `[` with a later unquoted `]` in the same word (pathname expansion) | undeterminable |
| An unquoted `?`, `*`, `+`, `@` or `!` written directly before a `(` with no blank between (an extended-glob pattern: bash with extglob on reads it and the parenthesised part as one word, which the tokenizer splits at the parenthesis) | undeterminable |
| An unquoted `{` with a later unquoted `}` in the same word (brace expansion; counted whether or not a comma or a sequence expression is present — fail-closed) | undeterminable |
| An unquoted `~` as the word's first character (tilde expansion) | undeterminable |

Further rules:

1. The decision reads the word as written. It is never taken from a token's
   value after quote removal, which cannot tell `'decl?re'` (one fixed word)
   from `decl?re` (a pattern).
2. A word whose as-written reading or region information is not available
   (the parse-failure fallback's plain whitespace split) is undeterminable
   unless it holds no quote character, backslash, `$`, backtick, `*`, `?`,
   `[`, `{`, `}` or `(`, and does not begin with `~`.
3. A `[` with no later unquoted `]` in the same word (a lone `[`, `[[`) is
   not pathname expansion.
4. Each character of the word is read a bounded number of times (NFR2), and
   nothing is evaluated, executed or imported to restore or decode a word
   (NFR1).

### Component 2: Command-word peel (FR9, NFR5)

Contract — input: the words of one statement from its command position, as
statement shaping leaves them, each read through Component 1, and the words
shaping consumed before that position. Output: "undeterminable", the restored
effective command word, or none when no word is left.

1. In a loop, the peel passes over, in whatever order they come:
   - assignment words, recognised where the command-word reading recognises
     them, and also when the name carries an array subscript the lexer read
     as one; an assignment is passed over whatever its subscript and value
     hold;
   - wrapper words of the command-word reading's vocabulary (referred to by
     name), each with its option words and the value word each value-taking
     option consumes, and mise / asdf exec prefixes, as the command-word
     reading passes them;
   - `builtin` and `command` words, each with the option words after it (a
     word that begins with `-` and is not `-` alone); a `--` is passed over
     and ends that word's options.
2. Every word the loop reads as a possible command word, as the name of a
   wrapper, `builtin` or `command`, or as an option of one of them, is read
   through Component 1 first, and the first undeterminable one ends the peel
   with "undeterminable". The value word a wrapper option consumes and the
   value of an assignment are not judged.
3. A word built entirely from a command substitution at a command-word
   position is undeterminable. The command-word reading passes over such a
   word for the other checks; the peel does not.
4. A `!` that statement shaping consumed as pipeline negation, written
   directly before a `(` with no blank between, makes the result
   undeterminable (the extended-glob row of Component 1).
5. The names `builtin`, `command` and the wrapper names are compared with the
   restored word.
6. Any number of nested levels is removed, and each word is visited at most
   once (NFR2).
7. This is the only place the FR9 check removes `builtin` / `command`
   (IMPLEMENTATION.md, D3). The command-word reading and the override
   reading's one-level `builtin` reading are not replaced by it.

### Component 3: Derived stop vocabulary (NFR5)

- **Stop command words**: the override builtin set joined with the FR9 (2)
  state builtins `declare`, `typeset`, `local`, `export`, `readonly`, `let`,
  `shopt`, `set`, `unset`, `source`, `.` and `eval`. The definition refers to
  the override builtin set by name; none of its words is written again.
- **Stop variable names**: the override variable-name definition joined with
  `BASH_ALIASES`. `BASH_CMDS` is written once, as a named definition that both
  forms of the override reading and the stop vocabulary refer to.
- No word is written both in the override vocabulary and in the stop
  vocabulary's own additions. Today's separate state-builtin list is replaced
  by the stop command words, not kept beside them.
- The lexer's set of declaration builtins (the words after which bash parses
  assignment arguments) serves word parsing, is not one of the two
  vocabularies NFR5 names, and is not changed. The override reading's own
  condition on `export` with a PATH argument is a condition of that reading,
  not a vocabulary list, and is not changed (SPEC A-5).

### Component 4: Masking-stop check (FR9)

For every statement the traversal reads, in every chunk, lexed or through the
parse-failure fallback, the masking-stop flag is raised when any of these
holds:

1. The override reading (either form) flags the statement, so every statement
   it flags also stops masking (NFR5).
2. A word of the statement holds one of the stop variable names, in its value
   as today or in its restored form when Component 1 gives one.
3. The peel result is one of the stop command words, compared by its last
   path segment as the command-word reading compares a command word.
4. The peel result is "undeterminable", and the statement is not in a
   Python-body chunk.

A statement that meets none of these does not raise the flag; a peel result
of none meets neither condition 3 nor condition 4. Everything that follows a
raised flag is unchanged: it is raised at most once, the parked originals are
queued whole once, masking stops for the rest of the command, statements
before and after the heredoc are both covered, and the FR7 override flag is
never raised by this check (IMPLEMENTATION.md, D1).

### Component 5: Python-body mark (FR9, last paragraph)

- **Marked**: every chunk queued from the body of a heredoc whose destination
  is "Python program": the masked text, the original queued whole (literal
  range not settled, or masking already stopped), and the parked original
  queued when the flag is raised.
- **Inherited**: every chunk derived from a marked chunk — its substitution
  bodies, unclosed command-form contents, `-c` / eval / here-string payloads,
  heredoc bodies, and everything derived from those — is marked as well,
  except as below.
- **Not marked**: the chunks the FR5 extraction queues from the original body
  of an unquoted-delimiter heredoc; the substitution bodies and unclosed
  command-form contents found in the body chunk of a Python-program heredoc
  whose delimiter is unquoted (the shell evaluates them before Python reads
  the body); and everything derived from these.
- The mark changes only condition 4 of Component 4. What is queued, and how
  each chunk is read, are unchanged.

### Test cases

Every new case uses the three-element form (decision, label, command) with no
fourth element. Each label is a Japanese label that starts with
`destructive-guard-heredoc-literal` and the scenario ID (a letter suffix per
case where a scenario has several, as the existing labels do), states the
shape and the outcome, and is unique in the file. Commands are given line by
line below; the lines are joined by single line feeds with no line feed after
the last line, and in the case file the line feeds are written as JSON
escapes. In `decl\are`, `$'decla\x72e'` and `ec\ho` the backslash is one
character of the command (two in the JSON string).

Named parts:

- the **probe line**: ``x = "`git branch -D example`"``
- the **subscript line**: `print('a[$(git branch -D example)]')`
- the **assignment tail**: the three lines that follow a first line ending in
  `x="$(python3 <<'PY'`: the subscript line / `PY` / `)"`
- a **word case** for a word W: the first line `W; x="$(python3 <<'PY'`, then
  the assignment tail

## Out of Scope

- Changing the words the override reading matches, its one-level `builtin`
  reading, the command-word reading, or how data heredoc bodies are judged
  (SPEC A-5).
- Changing the literal scan, the Python-program eligibility conditions, the
  FR5 extraction or the body handling, beyond the mark of Component 5 and what
  raises the masking-stop flag.
- Changing the lexer, including its declaration-builtin set and its reading
  of extended-glob parentheses.
- Changing `_command_word_pieces` or `_piece_is_static`, which decide another
  feature's static-word question for single-quote candidates.
- Applying FR9 (3) to words other than a statement's command word and the
  words passed while finding it (arguments, redirect targets, assignment
  values, wrapper option values).
- Changing the runner `run-destructive-guard.py` or any file outside Scope.
- New detection for a Python program's output or for literals Python later
  hands to a shell (SPEC A-3).
- Any plugin version change.
