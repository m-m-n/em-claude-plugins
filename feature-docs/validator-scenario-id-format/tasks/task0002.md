# Task Plan: task0002 — State the scenario ID format rule in plan-writing SKILL.md

## Goal

`em-workflow/skills/plan-writing/SKILL.md` states the scenario ID format
rule: the TS-n form for new VERIFICATION.md files, the TSn form as also valid
and recognized by the validator, and literal-string comparison.

## Requirements

FR3, NFR2

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/skills/plan-writing/SKILL.md` — scenario ID format rule in the VERIFICATION.md Template section

## Design

- Location: the `## VERIFICATION.md Template (feature-wide)` section, as
  prose outside the fenced template block (immediately before or after it).
- Content:
  1. New VERIFICATION.md files use the TS-n form for scenario IDs (`TS`, a
     hyphen, one or more digits).
  2. The TSn form (`TS` immediately followed by one or more digits, no
     hyphen) is also a valid scenario ID that
     `em-workflow/scripts/validate-worker-output.py` recognizes.
  3. Scenario IDs are compared as literal strings, so `TS13` and `TS-13` are
     distinct IDs.
- The two forms are exactly the Scenario ID grammar in IMPLEMENTATION.md
  Shared Components.
- Planners copy the fenced template into VERIFICATION.md, and the validator
  reads scenario IDs from its `### Test Scenarios from SPEC.md` section. The
  rule text, including any example ID, therefore stays outside the fenced
  template. The template's existing `TS-N` placeholder stays as it is.
- The rest of the skill (the requirement ID note, the template, the
  checklist) is unchanged.
