# Task Plan: task0001 — Recognize hyphen-less scenario IDs in the worker-output validator

## Goal

`em-workflow/scripts/validate-worker-output.py` extracts VERIFICATION.md
scenario IDs in both the TS-n and the TSn form, so a rework that adds a
TSn-form scenario passes the rework_index novelty check, and regression tests
pin this behavior.

## Requirements

FR1, FR2, FR4, FR5, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — scenario ID pattern and the docstring of the scenario ID extraction function
- `tests/test_validate_worker_output.py` — regression tests for hyphen-less and mixed-form scenario IDs

## Design

### Scenario ID extraction

- The module-level scenario ID pattern (`_TS_ID_RE`) implements the Scenario
  ID grammar pinned in IMPLEMENTATION.md Shared Components: both forms, all
  consecutive digits consumed, literal strings.
- Recognition of hyphenated IDs is unchanged: for any input text, every ID
  the current hyphenated-only pattern finds is still found, with the same
  literal value. No word-boundary or other new constraint is added.
- `extract_verification_scenario_ids` keeps its scoping: only the
  `### Test Scenarios from SPEC.md` section is read, after fenced code blocks
  and HTML comments are removed (SPEC.md assumption a3). Only the pattern
  changes.
- The docstring of `extract_verification_scenario_ids` names the two accepted
  forms (TS-n and TSn) and states that IDs are literal strings. It carries no
  line-range citation of `plan-writing/SKILL.md`.

### Rework-index novelty check

- The logic of `_validate_rework_index` is unchanged: the new IDs are the IDs
  extracted from the current VERIFICATION.md minus the IDs extracted from the
  baseline VERIFICATION.md, both through `extract_verification_scenario_ids`.
- A declared `new_scenarios` entry outside that set yields the existing error
  `new_scenarios '<id>' is not a new VERIFICATION.md scenario`, with the
  message text unchanged (THREAT-MODEL.md TM-1).
- No normalization between forms anywhere in this flow.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR4; TS-1, TS-3): Extraction over a
  `### Test Scenarios from SPEC.md` section whose rows carry TS1, TS2 and TS13
  returns exactly {TS1, TS2, TS13}. A section whose only row carries TS13
  returns exactly {TS13} (no TS1).
- [ ] AC-2 (FR1, FR4; TS-2): Extraction over a section mixing TS-1 and TS2
  returns exactly {TS-1, TS2}.
- [ ] AC-3 (FR2, FR4; TS-4): `_validate_rework_index` with a baseline
  VERIFICATION.md holding TS1 through TS12, a current VERIFICATION.md holding
  TS1 through TS13, a rework_index entry for task0007 with `new_scenarios`
  [TS13], `requirements_patch` `tests_append` [TS13], and task0007 in
  `tasks_patch` returns no errors.
- [ ] AC-4 (FR2, TM-1; TS-5, TS-6): TM-1 — novelty is the literal set
  difference between the current and the baseline VERIFICATION.md, both read
  through the one extraction rule, so an already-existing ID is rejected.
  With TS12 in both documents and `new_scenarios` [TS12],
  `_validate_rework_index` reports
  `new_scenarios 'TS12' is not a new VERIFICATION.md scenario`. With TS-13 in
  the baseline, TS13 in the current document and `new_scenarios` [TS13], it
  reports no `is not a new VERIFICATION.md scenario` error.
- [ ] AC-5 (FR4; TS-10): The tests for AC-1, AC-2 and AC-3 fail when the
  scenario ID pattern is the hyphenated-only form.
- [ ] AC-6 (FR5; TS-11): The docstring of `extract_verification_scenario_ids`
  names both accepted forms (TS-n and TSn) and does not contain the citation
  `SKILL.md 131-139`.
- [ ] AC-7 (NFR1, NFR2; TS-7, TS-9): The new tests use only the Python
