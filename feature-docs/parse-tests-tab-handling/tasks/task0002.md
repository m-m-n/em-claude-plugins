# Task Plan: task0002 — Self-sufficient module-level run of the record check module

## Goal

`python3 -m unittest tests.test_tests_yaml_id_resolution`, run from the
repository root with no `PYTHONPATH`, exits 0: the record check module itself
makes the helper modules that live directly in `tests/` importable by bare
name, so the per-record tests of other features' records resolve their IDs
exactly as they do under `python3 -m unittest discover -s tests`.

## Design

IMPLEMENTATION.md is not produced for this feature (reduced tier); this task
introduces no contract shared with task0001, and every decision it needs is
stated here.

### Defect being fixed

Verify failed item TS-5. Run from the repository root as a module-level
command, the module's per-record tests (the record resolution test case) for
other features' records fail with `ModuleNotFoundError` for a helper module
that lives directly in `tests/` (for example `_gate_vocabulary`): the test
modules those records name import such helpers by bare name, which works only
when `tests/` is on the module search path. `discover -s tests` puts it there;
the module-level command does not. The failure already exists at
`workflow.implement.base_commit` and disappears with `PYTHONPATH=tests`.

### Contract

- When the module is imported, before any ID is resolved by import, the
  directory that contains the module (`tests/`, as an absolute path) is an
  entry of the module search path.
- The entry is added only when no existing entry already resolves to that
  directory; existing entries are neither removed nor reordered. Under
  `discover -s tests` the module therefore leaves the search path as it found
  it.
- The directory is derived from the module's own file location, never from
  the current working directory or an environment variable.
- Only standard-library facilities are used (NFR1).
- The record parser, the resolver's resolution rules, every reason string and
  every existing test are unchanged.

### Regression test

One new test in `tests/test_tests_yaml_id_resolution.py`, following the
module's docstring convention and citing this feature's FR5 / TS-5. It starts
a child interpreter (the same interpreter executable as the running test) with
the repository root as its working directory and with `PYTHONPATH` removed
from its environment; the child imports `tests.test_tests_yaml_id_resolution`
and then imports a helper module that lives directly in `tests/` by its bare
name. The test asserts that the child exits 0. Only standard-library modules
are used. The test does not run the full module-level suite in the child.
