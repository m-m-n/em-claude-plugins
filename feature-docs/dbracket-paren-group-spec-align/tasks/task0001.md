## Design

### The judgment being pinned (no hook change)

`em-workflow/hooks/destructive-guard.py` is not changed, and neither is its
command-level reading. The hook reads `[[ ( a == b ) && true ]]` as uncertain:

- The `(` boundary makes `a == b` a simple command. Its name `a` is not an
  allow-list name (`true`, `false`, `echo`, `:`, `mcp-bridge`, `fi`, `done`),
  so the command-level reading reads that command as uncertain, as it did
  before the dbracket-opener-arith-scan feature.
- The conditional reading that feature added (the scan, in the statement that
  opens `[[`, of the words between the opener and the closer for the
  arithmetic comparison operators and `-v`) finds no operator word in this
  form, reports no uncertain statement, and adds nothing.
- Because the chunk is uncertain, a canonical notion call with
  `--session "$SID"` that follows it gets no notion-pair exclusion. It is
  KIND_INSPECTED: its `--args-json` command is decoded and judged, and
  `git branch -D example` is denied with reason ID `git-branch-force-delete`.

This task records that judgment in tests. It changes no reading.

### The judgment command

The new tests and the new case row use one command, made of these parts in
order:

1. The array assignment `A=(json --mcp desktop-commander --tool start_process); `
2. `[[ ( a == b ) && true ]]`
3. `; `
4. The canonical notion call with `--session "$SID"` whose `--args-json`
   command is `git branch -D example`, built the same way as in the existing
   dbracket-opener-arith-scan deny tests of the same test module.

The command string in the case row is byte-for-byte the command the new test
runs.

### Test-description alignment

The comment on the PAREN_FORM constant (around lines 4271-4272 of
`tests/test_destructive_guard_args_json.py`) and the docstring of
`test_a_parenthesised_comparison_without_an_operator_word_reports_no_uncertain_statement`

- the conditional reading reports no uncertain statement for this form,
  because the form holds no operator word;
- the chunk is nonetheless uncertain from the command-level reading, for the
  reason stated above;
- the following notion call with `--session "$SID"` is KIND_INSPECTED.

Neither text refers to a "SPEC discrepancy" or to a task plan as its basis.
The test keeps its name and its assertions.

### The case row

One row is added to the case table:

- decision `deny`;
- a label that starts with `dbracket-paren-group-spec-align`. It does not
  start with `args-json-deferred-eval-bypass TS-16:` or
  `args-json-deferred-eval-bypass TS-17:`
  (`test_every_case_of_this_task_is_in_the_table_with_its_decision` requires
  exactly 30 labels with those two prefixes), and it does not start with
  `dbracket-opener-arith-scan`;
- the judgment command as its command string, equal to no existing row's
  command;
- a fourth element holding only the `rule` key, with the value
  `git-branch-force-delete`.

### The membership test

A test in `tests/test_destructive_guard_args_json.py` reads the case table,
finds the row whose label starts with `dbracket-paren-group-spec-align`, and
checks its decision, its rule and its command against the judgment command
the regression test uses. It reads the table the same way the existing
table-membership tests of the module do.

## Test Notes

- AC-1, AC-2 and AC-4 are tests in the existing args-json test module,
  placed alongside the PAREN_FORM test. AC-3 is exercised by the case-table
  runner. AC-5 is a reading check; the unchanged assertions of the PAREN_FORM
  test keep passing. AC-6 is the full suite plus the diff.
- TDD-awkward: the judgment already holds at the base commit (the hook is not
  changed), so the new tests pass on their first run and there is no red
  phase to observe. Do not modify `em-workflow/hooks/destructive-guard.py`,
  or any other file outside Scope, to produce one. Each assertion compares
  against the exact expected value (`[KIND_INSPECTED]`, the decision `deny`,
  the reason ID `git-branch-force-delete`), so a later change that read the
  form as certain (the notion call becoming KIND_NOTHING, or the hook
  allowing the command) fails these tests.
- The case row's command must equal the test's command exactly, including
  the double quotes around `$SID`, written with the escaping the case table's
  format requires.
