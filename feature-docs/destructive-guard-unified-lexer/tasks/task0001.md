# Task Plan: task0001 — Unified single-pass lexer for destructive-guard

## Goal

destructive-guard.py reads `$'...'`, `${...}`, `$((...))`, `((...))`, `$[...]` and the process substitutions `<(...)` / `>(...)` the way bash does, through one single-pass lexer that is the only source of quote / comment / expansion / substitution judgments. A destructive statement after such a context, or inside a process substitution, is then never hidden as a quote, comment, swallowed separator, arithmetic or heredoc body. The attack forms are pinned as cases first, and a new agreement test, anchored to hand-written expectations, proves every reader agrees with the lexer.

### Per-chunk flow (replaces the current flow inside statements())

1. Lex the popped chunk once in `shell` mode. The result holds the regions, the real heredoc operators with their body line ranges, the single-quote substitution candidates, and the unopened openers with the start of the re-read tail.
2. strip_heredocs() builds the body-stripped chunk and its HeredocRecord list from the lexer's real operators. It keeps the existing delimiter-line index lookup (NFR3) and its existing behavior for several operators on one line and for operators whose delimiter never appears. It also yields the original-to-stripped part of the position map, each removed body being one replaced segment. _OperatorContext is deleted.
3. scan_structure() keeps its signature and its five return values (spans, parent_of, unmatched, opaque, containing_span) for every caller: the chunk-wide scan with checkpoints, the honor_single_quotes=False scan, _statement_info_at(), and _extract_heredoc_body_substitutions() in `heredoc-body` mode. It derives them from the lexer's output, not from its own character rules:
   - spans come from the command-substitution, backtick-substitution and process-substitution regions, at every nesting level (inside parameter-expansion and arithmetic regions included, FR4; D5);
   - with honor_single_quotes=False, spans also include the lexer's single-quote substitution candidates (P8); the candidate rule itself is owned by the lexer, so the current helper for that search either moves behind `lex_shell` or is deleted;
   - opaque ranges also cover top-level parameter-expansion and arithmetic regions;
   - the case-pattern awareness that keeps a case pattern's `)` from closing a `$(` belongs to the lexer, because the lexer decides substitution ranges.
4. Substitution marking runs on the stripped chunk and yields the stripped-to-marked part of the position map, each marked substitution being one replaced segment whose marker may be longer or shorter than the substitution.
5. The masked view of the marked text is built from the lexer's output translated into marked coordinates. Marker residue stays intact. Comments become blank up to their newline. _blank_comments() is deleted.
6. _lex_layout() tokenizes the masked view with _TrackingLexer (commenters stay off). It maps each token's span back through the position map and restores each Tok's value and flags per IMPLEMENTATION.md. Statement layout and `<<` operator records keep their current meaning and shape.
7. tokens(segment) lexes SEGMENT, builds its masked view (comment text dropped), tokenizes it without shlex comment handling, and restores values. Only when tokenization still fails does it keep the existing whitespace split as its last resort. The raw text never reaches a comment-stripping tokenizer, the parse-failure path of _lex_layout() included.

### Process substitution (D5)

- Each process-substitution body is queued as its own chunk, anchored at its opener, the way a `$(...)` body is. A heredoc operator inside it is attributed to the statement holding it inside the body (P6, P9).
- The statement holding the process substitution still shows the opener to _has_process_substitution(), so the heredoc destination analysis reads has_process_sub as it does today. How the host statement's tokens represent the body (which part of the construct the marker replaces) is this task's choice; the choice is stated in the docstring of the marking step.

### Reading rules worth calling out (beyond P1-P9)

- Special parameters (`$$`, `$?`, `$#`, `$!`, `$-`, `$@`, `$*`, `$0`-`$9`) are consumed as a unit, so `$$'...'` is `$$` followed by an ordinary single quote, and the `#` of `$#` / `${#x}` / `${x#pat}` is never a comment.
- `$"..."` is a locale-quote with double-quote rules inside. Its token value stays what shlex gives today; it is not masked.
- Contexts may span lines (a double quote, `${...}` or `$'...'` running over a newline), and several contexts may share one line; both shapes are in the fixed expectations.
- The `((` of `for ((...))` is the arithmetic-for header; its inner `;` are not separators, and the `do ... done` body after `))` is ordinary command text.
- Command position is a grammar state the lexer carries forward (P3). A separator, a listed reserved word, a group opener, a case-pattern `)`, a function-definition head, `coproc`, or a process-substitution opener sets it; whitespace keeps it; the first other word read clears it, except that the `-p` option directly after `time` keeps it. A redirection operator never sets it.

### Unclosed-opener settlement (D4)

The approach is the implementer's choice, within these limits: deciding that an opener never closes must not rescan the remaining text once per opener, total lexing work stays linear in the input length, and the re-read tail (P4) is read in the same linear bound. When the bound is exceeded, the hook issues the existing scan-budget "ask" decision.
