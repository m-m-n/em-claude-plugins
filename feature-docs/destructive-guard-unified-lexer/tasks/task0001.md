# Task Plan: task0001 — Unified single-pass lexer for destructive-guard

## Goal

destructive-guard.py reads `$'...'`, `${...}`, `$((...))`, `((...))` and `$[...]` the way bash does, through one single-pass lexer that is the only source of quote / comment / expansion judgments, so a destructive statement after such a context is never hidden as a quote, comment, swallowed separator or heredoc body. The attack forms are pinned as cases first, and a new agreement test proves every reader agrees with the lexer.

## Design

The cross-task contracts (the unified lexer `lex_shell(text, mode)` with postconditions P1-P7, the position map, the masked view and value restoration, decisions D1-D4) are in IMPLEMENTATION.md. This section covers how this task applies them.

### Per-chunk flow (replaces the current flow inside statements())

1. Lex the popped chunk once in `shell` mode. The result holds the regions, the real heredoc operators with their body line ranges, and the unopened openers.
2. strip_heredocs() builds the body-stripped chunk and its HeredocRecord list from the lexer's real operators. It keeps the existing delimiter-line index lookup (NFR3) and its existing behavior for several operators on one line and for operators whose delimiter never appears. It also yields the original-to-stripped part of the position map. _OperatorContext is deleted.
3. scan_structure() keeps its signature and its five return values (spans, parent_of, unmatched, opaque, containing_span) for every caller: the chunk-wide scan with checkpoints, the honor_single_quotes=False scan, _statement_info_at(), and _extract_heredoc_body_substitutions() in `heredoc-body` mode. It derives them from the lexer's regions, not from its own character rules:
   - spans come from the command-substitution and backtick-substitution regions, at every nesting level (inside parameter-expansion and arithmetic regions included, FR4);
   - opaque ranges also cover top-level parameter-expansion and arithmetic regions;
   - the case-pattern awareness that keeps a case pattern's `)` from closing a `$(` belongs to the lexer, because the lexer decides `$( )` ranges.
4. Substitution marking runs unchanged on the stripped chunk and yields the stripped-to-marked part of the position map.
5. The masked view of the marked text is built from the lexer's regions translated into marked coordinates. Marker residue stays intact. Comments become blank up to their newline. _blank_comments() is deleted.
6. _lex_layout() tokenizes the masked view with _TrackingLexer (commenters stay off). It maps each token's offsets back through the position map and restores each Tok's value and flags per IMPLEMENTATION.md. Statement layout and `<<` operator records keep their current meaning and shape.
7. tokens(segment) lexes SEGMENT, builds its masked view (comment text dropped), tokenizes it without shlex comment handling, and restores values. Only when tokenization still fails does it keep the existing whitespace split as its last resort. The raw text never reaches a comment-stripping tokenizer, the parse-failure path of _lex_layout() included.

### Reading rules worth calling out (beyond P1-P7)

- Special parameters (`$$`, `$?`, `$#`, `$!`, `$-`, `$@`, `$*`, `$0`-`$9`) are consumed as a unit, so `$$'...'` is `$$` followed by an ordinary single quote, and the `#` of `$#` / `${#x}` / `${x#pat}` is never a comment.
- `$"..."` is a locale-quote with double-quote rules inside. Its token value stays what shlex gives today; it is not masked.
- Contexts may span lines (a double quote, `${...}` or `$'...'` running over a newline), and several contexts may share one line; both shapes are in the fixed expectations.
- The `((` of `for ((...))` is an arithmetic-command region; its inner `;` are not separators, and the `do ... done` body after `))` is ordinary command text.

### Unclosed-opener settlement (D4)

The approach is the implementer's choice, within these limits: deciding that an opener never closes must not rescan the remaining text once per opener, and total lexing work stays linear in the input length. When the bound is exceeded, the hook issues the existing scan-budget "ask" decision.

## Test Notes

- **Order (TDD, FR11)**: (1) append the 17 cases and commit — at least the AC-1 forms fail against the unchanged hook; (2) write the agreement test with its fixed expectations (red); (3) implement the lexer and rewire; (4) run `python3 em-workflow/hooks/tests/run-destructive-guard.py` and `python3 -m unittest discover -s tests` until both pass.
- **Loading the hook**: the agreement test reads internal functions, so it loads destructive-guard.py from its file path (test/README.md: targets are referenced by path; there is no package). The verdict, linearity and determinism checks run the hook through its stdin JSON / stdout contract.
- **Fixed expectations (TS-8)**: each edge form has hand-written expected regions (kind, start, end) and, where relevant, expected heredoc operators. They are literals in the test and are never computed by invoking a shell. Forms:
  - `$'` inside double quotes (`echo "$'x'"`)
  - `$"..."`
  - `$$'...'` and `$?'...'`
  - `\\` and `\'` inside `$'...'`
  - `${#x}`, `${x#pat}`, `$#`
  - `${x:-"}"}`
  - `${x:-${y}}`
  - `$((...))` versus `$( (...) )`
  - `( (cmd) )`
  - `a[1] <<EOF` outside arithmetic (a real heredoc)
  - `<<<`
  - a real heredoc inside a command substitution
  - several contexts on one line, and a context spanning lines
  - each unclosed opener from P4
  - process substitution followed by a subshell (`cat <((rm -rf /home/sakura/valuable))`), which is not arithmetic
- **Stage agreement properties (TS-5)**, checked on every cases.json command, every attack form and every benign control:
  - (a) scan_structure()'s spans and top-level opaque ranges coincide with the lexer's regions, translated to stripped coordinates.
  - (b) every separator _lex_layout() reports lies outside every lexer region, and every unescaped newline outside regions and heredoc bodies is a separator.
  - (c) _lex_layout()'s `<<` operator records, mapped back, equal the lexer's real heredoc operators that are not inside a substitution region.
  - (d) Tok provenance matches the contract.
  - (e) inspection values carry no mask character, and spans without masked regions equal their shlex reading.
- **Benign controls**: `rm -rf /tmp/safe$'\t'`, `echo "${x:-a(b}"; cat <<'EOF'\ngit reset --hard HEAD\nEOF`, `echo $((1<<2)); cat <<'EOF'\nrm -rf /tmp/zz\nEOF`, `for ((i=0; i<3; i++)); do echo $i; done`, `echo "$'x'"`. Each must also keep its allow verdict through the hook.
- **Runtime**: the agreement loop over all cases.json commands should stay within a few minutes. The ~60KB cases are checked for agreement but timed only by AC-2 / AC-6.
