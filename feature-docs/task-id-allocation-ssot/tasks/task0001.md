- no longer assumes that re-planning recycles or renumbers task ids;
- cites workflow-patch.md 'Re-planning task-id allocation' and states that a task's journal terminal events are its own;
- re-grounds the three recycled-task-id countermeasures and records their re-judgment;
- aligns the re-scope sentence with the carried-verbatim rule.

Tests pin the new wording.

## Design

Read IMPLEMENTATION.md Conventions C1 to C6 first. They fix the citation form, the shared own-id vocabulary, the exact phrases to remove, the labels to keep, and the test conventions.

### I.2.c edit flow

1. **Remove the premise sentences (FR2).** Remove each C3 phrase for I.2.c. Where a sentence exists only to state the recycling premise, remove the whole sentence. Where a sentence also carries a still-valid statement (such as wording matched by a THIRD_CONJUNCT anchor), keep that statement and remove only the premise.
2. **State ownership (FR1, FR3).** Add a statement that task ids are never re-issued, citing workflow-patch.md 'Re-planning task-id allocation' the same way I.2.a already cites it. Then state the consequence: no task carries another task's journal terminal event, and every terminal event a task has is its own.
3. **Third-conjunct rationale (FR4).** Keep the conjunct and its four anchors (opening, source, independence, never-narrowed) byte-identical. Replace the recycled-id rationale with the own-id rationale in IMPLEMENTATION.md D2. It must mention both the task's own `merged` event and the launch guard's denial.
4. **Carve-out rationale (FR4, FR6).** Keep the 'recycled-task-id carve-out' label. Explain it with the C2 description: route-back returns the task's own `failed` status to `pending`, and the re-planning `replace_all` carries that id verbatim (cite the owning section).
5. **`deny_already_merged` rationale (FR4).** State that it prevents a second launch of the task's own merged id and does not depend on id reuse.
6. **Re-judgment record (FR4).** Add one explicit passage stating that all three countermeasures remain necessary under the owning rule. It names each of `deny_already_merged`, the third conjunct and the failed+pending carve-out, each with its own-id reason from steps 3 to 5.
7. **Re-scope sentence (FR5).** Replace 'The planner re-scopes the failed task (split it, change the approach)' with text that says:
   - the reset failed task keeps its id, and is carried verbatim with its plan, files and `pending` status (cite the owning section);
   - any additional work is added as new tasks with fresh ids above the high-water mark (cite the owning section);
   - dropping a requirement still goes through the ordinary SPEC.md update path first.

   The replacement grants the planner no action the owning section does not already permit.

### Constraints

- **NFR4**: I.2.c must not contain the high-water-mark expression, an enumeration of the carried record's full field list, or the rejection conditions. Step 7 may name plan, files and status as the consequence that matters for the reset task. It must not reproduce the full list.
- workflow-patch.md is not edited.
- The rewrite changes rationale only. The route-back gate's conditions, the carve-out's condition and the launch guard's decision stay as they are.
