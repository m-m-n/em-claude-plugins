## Design

Read IMPLEMENTATION.md Conventions C1 to C7 first. They fix the citation form, the shared own-id vocabulary, the exact phrases to remove, the labels to keep, behaviour invariance, test conventions and version ownership.

### Stop-guard docstring (FR6)

- Rewrite the passage that explains the pending+failed exception. Describe it with the C2 wording: the task's own id, returned from `failed` to `pending` by route-back.
- Remove 'a recycled task id left behind by a route-back re-plan' (C3).
- Keep every reference label ('recycled-task-id carve-out', 'recycled-task-id rule') that the docstring contains before the change (C4).
- The docstring may cite workflow-patch.md 'Re-planning task-id allocation'. It must not restate the rule (C1).

### Validator comment (FR7)

- Today the comment says a re-planning `replace_all`'s `entries` must re-declare every registered id. Rewrite it to describe what the code under it actually enforces:
  - registered ids are listed in `tasks_patch.carried_task_ids` and carried over;
  - `entries` names only ids that are not yet registered;
  - the two sets are disjoint.
- Cite workflow-patch.md 'Re-planning task-id allocation'. Do not restate the high-water-mark expression or the carried field list (C1).

### Version bump (FR8)

1. Read the current em-workflow version from plugin.json. This is the pre-change version.
2. Increment its patch component by one.
3. Write the result to plugin.json and to the em-workflow entry in marketplace.json.
4. Leave every other plugin entry in marketplace.json untouched.

### Behaviour invariance (NFR2, C5)

- In the two Python files, only docstring and comment lines change.
- Do not reformat code, reorder code or change whitespace in code lines.
- Leave the other hook files alone.

### Test design

- **Docstring**: read the stop guard's module docstring by parsing the module source, not by importing it, so no hook side effects run.
- **Validator comment**: locate the comment block that belongs to the re-planning allocation check through its 'replace-all-task-id-reused' identifier, and inspect only that contiguous comment block.
- **Pre-change samples**: capture both samples verbatim before editing and embed them as literals (C6). Each matcher then gets its negative proof against the sample.
- **Version test**:
  - It compares versions numerically, component by component. String comparison is wrong here, because it orders "0.10.0" before "0.9.0".
  - It pins the pre-change em-workflow version as its own baseline. That value must be at least the largest baseline pinned by the existing version-bump test modules.
  - It asserts that the plugin.json version equals the marketplace.json version and is strictly greater than that largest baseline.
