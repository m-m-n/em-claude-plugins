# Task Plan: task0001 — 語一覧の語の先頭のプロセス置換をコマンド列として読む

## Goal

codex-hook-interactive-guard の 2 つのコピーで、zsh の `for name (words)` の語一覧（文脈 w）の最も外側の項目の語の先頭にある、引用・エスケープの無い `<(`・`>(`・`=(` をコマンド列 p として読む。それ以外の `(` は今の読みを保ち、再現入力と境界の入力を CASES に加え、docstring とコメントを新しい読みに合わせる。

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4

## Scope

なし。

### Files to Modify

- `em-review/scripts/codex-hook-interactive-guard.py` — 上と同じ変更を入れ、2 ファイルをバイト単位で同一にする
- `tests/test_codex_hook_interactive_guard.py` — CASES に TS-1〜TS-14 の行を加え、文書の検査に新しい文の目印を加える

## Design

用語は SPEC.md の用語定義（文脈 w、コマンド列 p、最も外側の項目、入れ子の w、語の先頭、継続行）をそのまま使う。変更するのは `_skip_substitution` の文脈 w の読みだけ。

### 1. 語の先頭の状態

最も外側の項目を読む間、「いまの位置が語の先頭か」を、読みながら持つ定数サイズの状態として持つ。読み終えた文字を見返して決めない（NFR1）。

語の先頭になるもの:

- 最も外側の項目を開く `(`
- 引用・エスケープされていない区切り（空白、タブ、改行、`;`、`&`、`|`）。項目の中のコメントを終える改行も含む

語の途中になるもの:

- エスケープした文字（エスケープした空白を含む）
- 引用の開始（`'`、`$'`、`"`）
- 置換の開始（`$(`、`$((`、`${`、バッククォート）
- 入れ子の項目を開く `(`
- その他の語の文字
- 入れ子の文脈（引用・置換・入れ子の項目・プロセス置換の p）から最も外側の項目へ戻ったこと（同じ語の続き）

状態を変えないもの:

- 継続行（バックスラッシュ + 改行）

### 2. `(` の分岐

文脈 w で `(` を読んだとき、次のすべてが成り立つときだけ p を積む。

- 最も外側の項目である
- 直前の文字が、引用・エスケープの無い `<`・`>`・`=` である
- その `<`・`>`・`=` を語の先頭で読んだ

`<`・`>`・`=` を語の先頭で読んだかどうかも、読んだ時点で状態として持つ（NFR1）。それ以外の `(` は今のまま入れ子の w を積み、入れ子の w の中では今のまま `#` を語の文字として読む（FR2）。

### 3. 積んだ p

- コマンドの位置で始まり、コメント・引用符・置換・case 文などを既存のコマンド列の規則で読む。
- p の `)` は語の中の閉じとして扱い（コマンドの終わりとして扱わない。SPEC.md FR1）、読みを w に戻す。戻った後は語の途中（1 のとおり）。

### 4. 変えないもの

- 最も外側の項目で `#` がコメントを始める条件（SPEC.md 9.1）。
- 最も外側の項目の判定（`codex-guard-for-wordlist-glob-qualifier` で入れた条件）。
- 読みが線形で再帰を使わないこと（TestNoRecursion と TestSubstitutionSkipCallStructure の前提）。

### 5. docstring とコメント（FR4）

- docstring の語一覧 w の段落（「A `(` read in w opens a nested entry of w (a glob qualifier as in `*(N)`) ...」の文）と、`(` 分岐・w 分岐のコメントに次の 3 点を書く。
    - 最も外側の項目の語の先頭にある、引用・エスケープの無い `<(`・`>(`・`=(` は p を開く
    - その `)` は語の中の閉じである
    - 語の先頭の決め方（エスケープした空白は語の文字、継続行は語を区切らない）
- 既存の RULE_MARKERS と WORD_LIST_HASH_MARKERS が検査する文は、文字列を変えずに残す。新しい内容は文を足す形で書く。

### 6. 2 つのコピー（FR3）

同じ変更を両方のコピーに入れ、バイト単位で同一にする（IMPLEMENTATION.md Conventions）。

### 7. テスト（FR5）

- CASES に TS-1〜TS-14 を、SPEC.md の Test Scenarios の期待する判定とコマンドどおりに `(期待する判定, ラベル, コマンド)` の行として加える。コマンドは SPEC.md の Python 文字列リテラル表記をそのまま使う。
- ラベルは、既存の「置換読み TS-n」と重ならない接頭辞に、このフィーチャーの TS-n を続ける（例: 「語一覧プロセス置換 TS-1」）。
- TestSubstitutionSkipDocumentation に、5 で足した文の目印の組を、既存の目印の組と同じ形で加え、両コピーで検査する。
