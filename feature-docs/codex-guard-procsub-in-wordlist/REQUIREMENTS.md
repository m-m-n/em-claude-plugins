# codex-guard-procsub-in-wordlist - 要件定義書

## 1. 概要

### 1.1 背景

codex-hook-interactive-guard は、zsh の `for name (words)` の語一覧（文脈 w）の中にある `(` をすべて入れ子の w として読んでいる。語一覧の中のプロセス置換 `<(`・`>(`・`=(` の中身もコマンド列ではなく語として読むため、その中のコメントが原因で拒否漏れ（fail-open）と誤拒否が起きる。

### 1.2 目的

- codex-hook-interactive-guard の両コピーで、zsh の `for name (words)` の語一覧の中にあるプロセス置換 `<(`・`>(`・`=(` の中身を、zsh と同じくコマンド列として読む
- プロセス置換の中のコメントが原因の拒否漏れ（fail-open）と誤拒否をなくす

### 1.3 スコープ

- 対象
    - `em-workflow/scripts/codex-hook-interactive-guard.py` と `em-review/scripts/codex-hook-interactive-guard.py` の `_skip_substitution`
    - `_skip_substitution` の docstring とコメント
    - `tests/test_codex_hook_interactive_guard.py` の `CASES`
- 対象外
    - 語の途中の `<(`・`>(`・`=(` と、入れ子の項目の中の `<(`・`>(`・`=(`（入れ子の w のまま読む。既知の制限として記録する）
    - 最も外側の項目で `#` がコメントを始める条件

## 2. ビジネス要件

### 2.1 ビジネス目標

- 語一覧の最も外側の項目で、語の先頭にあるプロセス置換の中身を zsh と同じくコマンド列として読む
- プロセス置換の中のコメントが原因の拒否漏れと誤拒否をなくす

### 4.2 機能詳細

#### FR1: 語一覧の最も外側の項目で、語の先頭にあるプロセス置換はコマンド列 p として積む

**説明**: `_skip_substitution` で、文脈 w の最も外側の項目（`stack[-2] != "w"`）の語の先頭に、引用・エスケープの無い `<(`・`>(`・`=(` があるときだけ、入れ子の w ではなくコマンド列 p として積む。

**ビジネスルール**:
- 語の先頭は字句状態で判定する。
    - 最も外側の項目を開いた `(` の直後、または引用・エスケープされていない区切り（空白、タブ、改行、`;`、`&`、`|`）の後で、その語の文字・引用・置換をまだ読んでいない位置を語の先頭とする。
    - エスケープした文字（`a\ =(` のエスケープした空白を含む）、引用（`'...'`、`$'...'`、`"..."`）、置換（`$(`、`$((`、`${`、バッククォート）、入れ子の項目、その他の語の文字は語を始める。
    - 継続行（バックスラッシュ + 改行）は語を始めも区切りもせず、直前の状態を保つ。`a\<改行>=(` は語の途中、`a \<改行><(` は語の先頭。
- 積んだ p はコマンドの位置で始まり、コメント・引用符・置換・case 文などをコマンド列として読む。
- p の `)` は語の中の閉じ（close_command False）として扱う。読みは w に戻り、その後の文字は同じ語の続きになる。
- 判定は後ろの文字を見返さず、読みながら持つ状態で行う。

#### FR2: それ以外の ( は今の読みを保つ

**説明**: 文脈 w の中のその他の `(` は今のまま入れ子の w を開く。

**ビジネスルール**:
- 対象は次のとおり。
    - 入れ子の項目（glob 修飾子 `*(#qN)` やグループ）の中の `(`・`<(`・`>(`・`=(`（例: `a(=(: #c))`、`a(<(b #c))`）
    - 語の途中の `<(`・`>(`・`=(`（例: `a=(`、`a<(x)`、`<(a)<(b)` の 2 つ目、`<->(`、`a\ =(`、`a\<改行>=(`）
    - エスケープや引用符で囲まれた `<`・`>`・`=` の後の `(`（例: `\<(`、`"<"(`）
- 入れ子の w では今のまま、すべての `#` を語の文字として読む。
- 既知の制限: zsh は語の途中や入れ子の中の `<(`・`>(` もプロセス置換として読むので、そこに空白の後の `#` コメントがあると読みのずれが残る。これを仕様に記録する。

#### FR3: 2 つのコピーをバイト単位で同一に保つ

**説明**: `em-workflow/scripts/codex-hook-interactive-guard.py` と `em-review/scripts/codex-hook-interactive-guard.py` を同じ変更の中で一緒に直し、バイト単位で同一に保つ。

#### FR4: docstring とコメントを新しい読みに合わせる

**説明**: `_skip_substitution` の docstring の語一覧 w の段落（「A `(` read in w opens a nested entry of w (a glob qualifier as in `*(N)`) ...」の文）と、`(` 分岐・w 分岐のコメントに、次のことを書く。

- 最も外側の項目の語の先頭にある引用・エスケープの無い `<(`・`>(`・`=(` が p を開くこと
- その `)` が語の中の閉じであること
- 語の先頭の決め方（エスケープした空白は語の文字、継続行は語を区切らない）

**ビジネスルール**:
- 既存のテストが検査している文（`TestSubstitutionSkipDocumentation` の RULE_MARKERS と WORD_LIST_HASH_MARKERS）は残す。

#### FR5: 再現入力と検証行を CASES に追加する

**説明**: `tests/test_codex_hook_interactive_guard.py` の `CASES` に、再現手順の 2 入力と、12.2 のテストシナリオの各行を `(期待する判定, ラベル, コマンド)` の行として追加する。表は両コピーに流す。

- 拒否漏れの入力 `zsh -c 'echo "$(for x (<(: # "<改行>)) { :; })"; python3 -i'` は deny
- 誤拒否の入力 `zsh -c 'echo "$(for x (<(printf x # )))"; python3 -i; echo "<改行>)) { :; })"'` は silent

## 12. テストシナリオ

### 12.1 テスト観点

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| 文脈 w | `_skip_substitution` の読みの文脈のうち、`for name (words)` の語一覧 |
| コマンド列 p | `_skip_substitution` の読みの文脈のうち、コマンド列 |
| 最も外側の項目 | 文脈 w のうち、`stack[-2] != "w"` の項目 |
| 入れ子の w | 文脈 w の中の `(` が開く、入れ子の語一覧の項目 |
| 語の先頭 | 最も外側の項目を開いた `(` の直後、または引用・エスケープされていない区切りの後で、その語の文字・引用・置換をまだ読んでいない位置 |
| 継続行 | バックスラッシュ + 改行 |
