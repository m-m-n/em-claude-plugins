# Task Plan: task0002 — Open quoted values only at real value-start positions in flow plain scalars and plain-scalar continuation lines

- source: review

## Goal

The multi-line value body tracking in the Stop hook stops treating two kinds
of plain-scalar text as the opening of a quoted scalar or flow collection: a
quote that follows a `:` or `?` inside a plain flow scalar (for example
`[retry:'failed]`, `{a:'b}`), and an item indicator, quote or bracket at the
start of a plain-scalar continuation line. Genuine records and tasks after
such values are read again, and regression tests pin the behavior.

## Design

### 1. Mapping indicators inside a flow collection (finding 6bd6c5a5788b3ddf)

Location: the flow-collection scan (`_scan_flow`, reported at line 328).

Today a quote inside a flow collection opens an inner quoted string whenever
the previous significant character is `:` or `?`. New rule:

- A `:` is a mapping value indicator only when either:
  1. the character after it is a space, a tab or the end of the line; or
  2. the last significant character before it (whitespace ignored) is the
     closing quote of an inner quoted string or the closing bracket of a
     nested collection (a JSON-like key, for example `{"a":'b'}`).
- A `?` is a mapping key indicator only when the character after it is a
  space, a tab or the end of the line.
- Any other `:` or `?` is an ordinary plain-scalar character: a quote
  directly after it does not open an inner quoted string, and it becomes the
  previous significant character exactly like any other plain character.
- Unchanged: a quote at the start of a flow entry (after the opening bracket
  or a `,`, whitespace allowed between) opens; a quote after a real mapping
  indicator (whitespace allowed between) opens; a quote inside a plain flow
  scalar after a letter (for example `it's`) does not open.

### 2. Plain-scalar continuation lines (finding b342ff634000d263)

Location: the per-line reading that decides value-start positions
(`_read_line`, reported at line 230, where an item indicator always counts as
a value-start position).

New state, carried line to line together with the existing tracking state:

- **Entering.** The state is set, with a parent indentation, when:
  1. a mapping key's value on the same line (a direct key, a nested key, or a
     key after an item indicator) is a plain scalar — parent indentation is
     the key's column;
  2. a sequence item's content on the same line is a plain scalar (no key) —
     parent indentation is the item indicator's column;
  3. a key's value starts on the next line (the key line has nothing after
     the colon but whitespace or a comment) and that first non-blank,
     non-comment line deeper than the key is a plain scalar (not an item
     indicator, not a key line, not a quote or bracket opening, not a block
     scalar header) — parent indentation is the key's column.
  A "plain scalar" here is a value whose first character is none of: a
  quote, `[`, `{`, `|`, `>`, `#`, `&`, `!`, `*`.
- **Continuation lines.** While the state is set, every non-blank,
  non-comment line indented deeper than the parent indentation is a
  continuation line. A continuation line is never a value-start position: an
  item indicator, a key, a quote or a bracket on it never opens a quoted
  scalar or flow collection, and it never makes the next line a
  value-start line. Continuation lines are otherwise handled exactly as today
  (they are not body lines; they are still seen by the consumers).
- **Leaving.** Blank lines and comment lines neither continue nor end the
  state. The first non-blank, non-comment line indented at or shallower than
  the parent indentation ends the state and is then processed with the
  normal rules (it may itself open a value, or enter the state again).
- The state is never set while a quoted or flow body is open, or inside a
  block scalar body.

### Constraints
