# Task Plan: task0002 — Protocol, README and workflow-schema: state the cd prefix exclusion

## Goal

`command-execution-protocol.md` states the full cd prefix exclusion rule and
the implementer's handling of an excluded approved string; the README and
workflow-schema summaries say that approved strings with top-level `&` / `;`
/ `||` are not covered, and leave the details to the protocol.

## Requirements

FR6, FR8, FR10, NFR4, NFR6, NFR7

## Scope

### Files to Create
- `tests/test_cd_prefix_operator_exclusion_docs.py` — document tests for FR6 and FR8

### Files to Modify
- `em-workflow/references/command-execution-protocol.md` — Verbatim execution rule section, Implementer bullet: exclusion conditions and implementer handling
- `em-workflow/README.md` — numbered item for the runtime enforcement: exclusion summary
- `em-workflow/references/workflow-schema.md` — Command approval store section: exclusion summary

## Design

### command-execution-protocol.md, Verbatim execution rule (FR6)

- The sub-bullet list under the Implementer bullet ("The hook allows this
  form when all of the following hold") gains the conditions of
  IMPLEMENTATION.md C1, in prose:
  - no lone `&`, `;`, `||` or line break at the top level of the remainder;
    the scan model (quoting states, backslash escapes, the single-quote and
    double-quote escape rules) and the recognized tokens `&&`, `|&`, `>&`,
    `<&`, `&>`, `&>>` whose `&` is not counted;
  - none of the safe-side constructs E5–E10, each with the position C1 gives
    it, and the statement that nesting is not parsed.
- A sentence in the same bullet states the handling (C4): an approved string
  that these conditions exclude is not run by the implementer, in any form,
  and is reported in `notes`.
- The existing sub-bullets and sentences stay. The Runtime enforcement
  section needs no row change (IMPLEMENTATION.md D3) and keeps its rows and
  their order.

### README.md, the 実行時強制 item (FR8)

- Inside the existing parenthetical about the implementer exception, add
  that an approved string with a lone `&` / `;` / `||` / 改行 at its
  トップレベル is 対象外 (C4). The citation of
  `references/command-execution-protocol.md` for the details stays.
- The item stays one numbered item with no blank line inside.

### workflow-schema.md, Command approval store (FR8)

- In the paragraph on the implementer's cd prefix form, add that an approved
  string with a lone `&`, `;`, `||` or line break at its top level is not
  covered (C4). The line "Details: `references/command-execution-protocol.md`."
  stays.
- No new heading and no new bullet in this section (the bullet extraction of
  `tests/test_failed_items_category.py` ends at this section's heading).

### Constraints from existing tests (NFR6)

`tests/test_cd_prefix_exception_docs.py` must keep passing unedited. In
particular:

- Keep `cd "{worktree_path}" &&` with `<approved string>`, "single Bash
  call", "double-quoted absolute path", "realpath",
  `.claude/worktrees/em-workflow/`, and the sentences "everything after the
  first `&&` … approved string" and "after `&&` … approved string …
  exactly" with no full stop between their parts.
- Never claim that the command holds only, exactly or at most one `cd`
  (English or Japanese).
- Keep the role split (bold Orchestrator / Implementer), the environment
  assignment ban, and "Never split, join, quote-wrap, or "improve" the
  string".
- README: keep 承認済み文字列と完全一致 → allow, workflow.yaml 記載かつ未承認
  → deny, 禁止パターン, 承認済みでも deny, `implementer`, and 1 回の Bash
  呼び出し.
- Schema: keep "approved exact string → allow", "declared-but-unapproved →
  deny" and "single Bash call".
- The headings of IMPLEMENTATION.md C3 stay as they are.
