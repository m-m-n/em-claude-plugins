# Task Plan: task0003 — implementer.md and worktree-task-workflow SKILL.md: do not run excluded approved strings

## Goal

The implementer's two instruction sources tell it that an approved string
the cd prefix form does not cover (top-level `&`, `;`, `||` or a line break,
and the other conditions in the protocol) is not run, and is reported in
`notes`.

## Requirements

FR7, FR10, NFR4, NFR5, NFR6, NFR7

## Scope

### Files to Create
- `tests/test_implementer_cd_prefix_exclusion_docs.py` — document tests for FR7

### Files to Modify
- `em-workflow/agents/implementer.md` — Step 3: handling of an approved string the cd prefix form does not cover
- `em-workflow/skills/worktree-task-workflow/SKILL.md` — Command execution gate section: the same handling

## Design

### Content to add (both documents)

Per IMPLEMENTATION.md C4, in each target section:

- Name the four top-level operators — a lone `&`, `;`, `||` or a line break
  at the top level of the approved string — and cite
  `references/command-execution-protocol.md` (its Verbatim execution rule
  section) for the full list of conditions. Do not restate the safe-side
  constructs E5–E10.
- State the handling: such an approved string is not run — not with the
  `cd "{worktree_path}" &&` prefix, not without it, and not rewritten or
  split — and the implementer reports it in `notes`.
- In implementer.md, the text goes in "Step 3: Verify the worktree"; in
  SKILL.md, in "Command execution gate (workflow.yaml strings)", as part of
  the first obligation bullet or as a new bullet of the obligations list.

### Constraints from existing tests (NFR5, NFR6)

`tests/test_implementer_cd_chain_docs.py` and
`tests/test_worktree_skill_instruction_source.py` must keep passing unedited.
Sentences are split at a full stop followed by whitespace, so each rule below
is about one sentence:

- Anywhere in either document: no sentence holds both the word `separate`
  and the word `cd`; no sentence holds `chain`, `&&` and one of never / not /
  don't; no sentence holds `may reset` or `may have reset`.
- SKILL.md gate section: `(byte-for-byte)` stays exactly once; no other
  `byte`, no `identical to`, no `equal to the line`; the new text adds no
  sentence holding all of "The only prefix allowed is",
  `cd "{worktree_path}" &&` and "same Bash call"; none holding both "cwd" and
  "does not persist between Bash calls"; none holding both "Never prefix" and
  "environment assignments"; none holding "JSON-decoded value"; none holding
  "decoded value", "verbatim rule" and "approval rule"; none holding "empty
  string" and "no such command". The text "Untrusted input" does not appear
  in the gate section.
- implementer.md Step 3: the new text adds no sentence holding both "cwd" and
  "does not persist between Bash calls"; none holding all of
  `cd "{worktree_path}" && <command>`, "single Bash call", "tests", "builds",
  "formats" and `merge_script`; none holding both `git -C "{worktree_path}"`
  and "for git"; none holding all of `<command>`, "approved string" and
  "environment assignment"; none holding both "main tree" and
  `base_branch`. The sentence "You MUST NOT read from or write to any path
  outside `worktree_path` except: …" stays as it is, and "Step 4" does not
  appear inside Step 3.
- The headings of IMPLEMENTATION.md C3 stay as they are.
