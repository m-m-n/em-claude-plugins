# Task Plan: task0003 — implementer.md and worktree-task-workflow SKILL.md: do not run excluded approved strings

## Goal

The implementer's two instruction sources tell it that an approved string
the cd prefix form does not cover (top-level `&`, `;`, `||` or a line break,
and the other conditions in the protocol) is not run, and is reported in
`notes`; when that string is the test command, the report's `tests` is
`"fail"`.

## Requirements

FR7, FR10, NFR4, NFR5, NFR6, NFR7

## Scope

### Files to Create
- `tests/test_implementer_cd_prefix_exclusion_docs.py` — document tests for FR7

### Files to Modify
- `em-workflow/agents/implementer.md` — Step 3: handling of an approved string the cd prefix form does not cover, and the tests value when it is the test command
- `em-workflow/skills/worktree-task-workflow/SKILL.md` — Command execution gate section: the same handling and the same tests value

## Design

### Content to add (both documents)

Per IMPLEMENTATION.md C4, in each target section:

- Name the four top-level operators — a lone `&`, `;`, `||` or a line break
  at the top level of the approved string — and cite
  `references/command-execution-protocol.md` (its Verbatim execution rule
  section) for the full list of conditions. Do not restate the safe-side
  constructs E5–E10.
- State the handling: such an approved string is not run — not with the
  `cd "{worktree_path}" &&` prefix, not without it, and not rewritten or
  split — and the implementer reports it in `notes`.
- State the report value when the string the cd prefix form does not cover
  is the test command (`project_commands.test`): the test command is not
  run at any point, the baseline run included; the report sets
  `tests: "fail"`; and `notes` says that the test command was not run
  because the cd prefix form does not cover it.
- In implementer.md, the text goes in "Step 3: Verify the worktree"; in
  SKILL.md, in "Command execution gate (workflow.yaml strings)", as part of
  the first obligation bullet or as new bullets of the obligations list.
  The existing deny bullet of the gate section ("Run nothing, set
  `tests: "fail"`, and explain in `notes`") stays as it is; the new
  statement is about the not-covered test command, not about a hook deny.

## Test Notes

- Follow the document-test method of IMPLEMENTATION.md Conventions. The
  section slicing and sentence splitting of
  `tests/test_implementer_cd_chain_docs.py` are the model; copy the approach
  into the new module, do not import it.
- A missing heading must fail loudly, so a renamed section never lets an
  absence assertion pass on empty text.
- Match operator tokens in their backtick form, so the `&&` already present
  in both sections does not satisfy the `&` assertion.
- AC-4 is sentence-scoped: `tests: "fail"`, `project_commands.test` and
  `notes` must sit in the same sentence. Pair it with a forged-text case
  holding only the existing deny wording ("Run nothing, set
  `tests: "fail"`, and explain in `notes`"), which the matcher must not
  accept, so the gate section's deny bullet cannot satisfy AC-4 by itself.
- Before finishing, re-run the two existing modules of AC-6; their sentence
  counts are the easiest thing to break with one added sentence.
