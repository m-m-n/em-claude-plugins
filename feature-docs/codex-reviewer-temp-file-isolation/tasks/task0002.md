## Findings to resolve (verbatim from round 1)

### F-1 — high — `em-workflow/agents/codex-reviewer.md` line 86 (stable_id 36899c2852f97ad4)

**Title**: mktemp テンプレートの `$SCRATCHPAD_DIR` が未定義で、FR3 の「発明せずに
従える具体機構」を満たしていない

**Description**: SPEC FR3 requires that an agent following the definition
produces a compliant path without inventing one. The implemented example is
`mktemp "$SCRATCHPAD_DIR/codex-reviewer-prompt.XXXXXX"`, but `SCRATCHPAD_DIR`
is defined nowhere in either plugin and is not exported into the environment.
An unset variable expands to empty, so the command becomes
`mktemp "/codex-reviewer-prompt.XXXXXX"`, which fails at the filesystem root and
routes into the FR5 fail-closed path — the codex review for that perspective is
then silently skipped every time. `em-review/agents/codex-reviewer.md` carries
the same text. The orchestrator inspected the file and confirmed this.

**Suggestion**: Make the example self-contained. Either use SPEC A1's form
(`mktemp "${TMPDIR:-/tmp}/codex-reviewer-prompt.XXXXXX"`), or keep a scratchpad
directory but state in the same section where its value comes from and give a
fallback for the unset case. Apply the identical fix to both plugins.

### F-2 — medium — `em-workflow/agents/codex-reviewer.md` line 72 (stable_id aaf9e2f8255166a5)

**Title**: 規律の適用範囲が `$PROMPT` の temp ファイルだけに狭められており、FR1 が
列挙する schema copy / intermediate output を覆っていない

**Description**: FR1 covers any temp file written into the session scratchpad —
the Codex prompt, a schema copy, intermediate output. The implemented heading and
opening sentence narrow the rule to the `$PROMPT` file with an explicit "only",
so writing a schema copy under a fixed name reads as permitted. FR6's intended
scope is "no temp file → rule does not apply", not "anything other than the
prompt → rule does not apply".

**Suggestion**: Widen the heading and opening sentence to FR1's enumeration and
demote `$PROMPT` to an example, while keeping FR6's scope. Add a test assertion
covering the widened scope.

### F-3 — medium — `em-workflow/agents/codex-reviewer.md` line 99 (stable_id d38afcf39e01e430)

**Title**: 失敗時 skip オブジェクトの summary が SPEC の Error Handling 表と一致して
いない

**Description**: SPEC's Error Handling table pins

**Suggestion**: Align the two agent definitions to the SPEC string, or update
the SPEC table (and FR5's loose `skipped: ...`) to the implementation string.
Either direction is acceptable; pick one and make all three files agree. Add a
test assertion on the summary string so it cannot drift again.
