# Task Plan: task0003 — Step A tier decision, persistence and the no-work stop

## Goal

Make the develop orchestrator decide the tier immediately after the feature
name is settled, persist that decision where an interrupted bootstrap can
recover it, and end the run before any workflow step when the pre-survey
reports that no work remains.

## Requirements

FR5, FR6, FR7, FR13, FR14, FR15, FR20, FR23, NFR1, NFR3, NFR5, NFR6, NFR7

## Scope

### Files to Create

- `tests/test_tier_decision_step_a.py` — conformance tests for the Step A procedure, the persistence record and the stop wiring

### Files to Modify

- `em-workflow/skills/develop/SKILL.md` — add the Step A tier-decision procedure, the no-work stop trigger, and the retrospect decision record
- `em-workflow/references/phase-state.md` — document the tier record file, its fields, and its resume behaviour

## Design

**Region ownership.** IMPLEMENTATION.md D3 splits the develop skill between
this task and task0005 and the split is binding. This task edits Step A, and
the retrospect section only. It does not touch the turn-ending conditions
list, the Step B discipline or phase table, the carve-out enumeration, the
Step C entry condition, or the phase-boundary table — task0005 owns all of
those, including the list entry that names this task's stop point.

**Procedure placement.** The decision runs inside Step A, after the feature
name has passed the identifier gate and before any `workflow.yaml` is built.
It runs on both Step A routes — the new-feature route and the resumed-feature
route whose bootstrap check finds no `workflow.yaml` yet.

**External invocations.** Two, and only two: the readonly Codex wrapper for
the pre-survey, and the external judgement skill with its JSON input and JSON
output switches. The raw Codex subcommand is named nowhere as an invocation
route. The estimate's members and the judgement skill's question set are cited
from `references/tier-rules.yaml`; neither external skill's text is
reproduced.

**Two decision bases.** The judgement skill is consulted twice against the
same question set: once on the task description alone, and once with the
pre-survey estimate merged into its state. Both readings, with their observed
values, are recorded as the decision's bases. The tier itself comes from the
evaluator, called with the collected values per IMPLEMENTATION.md Shared
Components.

**Fallback.** The availability matrix is applied by citing the rules file. Any
non-zero exit status from the judgement skill means unusable. An unusable
judgement skill, an unusable pre-survey with disagreeing readings, or any
condition the matrix does not resolve, all give the tier that removes nothing.

**Persistence.** Immediately after the decision, and before anything else
happens, the record is written to the feature's phase-state tier file and
committed with the existing documents-commit script — no script change is
needed, because that script already stages the whole feature-docs tree. The
phase-state document gains this file under the same not-owned-by-one-phase
exemption it already grants the design-system backfill record, with its
fields, its place in the file-layout listing, and the rule that a resume reads
it rather than re-running the decision.

**No-work stop.** When the pre-survey's work-remaining member reads false-y,
Step A ends the run before any workflow step. The terminal result carries the
stopped state, the no-step sentinel, and resume guidance that is non-empty and
says in words that no resumption is needed. The rationale from the pre-survey
is carried in the recovery text. The reason-code literal itself is never
written into this file — that literal belongs to
`references/batch-terminal-line.md` alone, which this file points at. The stop
point's hyphenated name may appear here; the underscored code may not.

**Retrospect record.** The retrospect section's collected signals gain the
decided tier, the rationale, the observed probability values and the
pre-survey estimate. Threshold tuning and learning are explicitly out.

**Standalone parity and gates.** The procedure states that the rules are
identical on the standalone route, where the run starts from a `workflow.yaml`
and no external task service is involved. Nothing on this path introduces a
gate identifier or a user question, in either mode.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Step A carries a tier-decision procedure placed after the
      identifier gate and before `workflow.yaml` construction, reachable from
      both Step A routes; it names the readonly Codex wrapper and the
      judgement skill with its two JSON switches, never names the raw Codex
      subcommand as an invocation route, consults the judgement skill on the
      description alone and again with the estimate merged into its state, and
      records both readings as decision bases (TS-13).
- [ ] AC-2: the procedure resolves availability by citing the rules file,
      restates no threshold value, reproduces no sentence from either external
      skill, and states that every unresolved condition — including any
      non-zero exit status of the judgement skill — gives the tier that
      removes nothing.
- [ ] AC-3: the procedure writes the decision to the feature's phase-state
      tier file and commits it with the existing documents-commit script;
      `references/phase-state.md` lists that file in its layout, defines its
      fields, places it under the existing not-owned-by-one-phase exemption,
      and states that a resume reuses it instead of re-deciding (TS-8).
- [ ] AC-4: when the pre-survey reports no work remaining, Step A ends the run
      before any workflow step, and the described result carries the stopped
      state, the no-step sentinel, non-empty resume guidance saying no
      resumption is needed, and the pre-survey rationale in the recovery text;
      the underscored reason-code literal appears nowhere in
      `em-workflow/skills/develop/SKILL.md`.
- [ ] AC-5: the retrospect section's collected signals include the decided
      tier, the rationale, the observed probability values and the pre-survey
      estimate, and state that threshold tuning is out of scope (TS-17).
- [ ] AC-6: the procedure states that the standalone route follows the same
      rules with no service-presence branch (TS-20), and neither the decision
      path nor the stop path introduces any gate identifier or user question
      (TS-18, TS-22).
- [ ] AC-7: `tests/test_tier_decision_step_a.py` asserts AC-1 through AC-6
      against raw document text, is discovered by
      `python3 -m unittest discover -s tests`, imports only standard-library
      modules, and pairs each matcher with a negative proof and a non-vacuity
      guard.

## Test Notes

- Every assertion is document conformance. The forbidden-literal assertion for
  the reason code is the important one: it reads the whole develop skill file
  and its negative proof forges a copy carrying the literal, proving the
  matcher fires.
- The hyphen/underscore distinction needs an explicit pair of assertions —
  the hyphenated stop-point name present, the underscored code absent — so a
  future rename cannot satisfy one by breaking the other silently.
- The "reproduces no external-skill sentence" check has the same decidable
  form as task0001's: a structural half asserted unconditionally (the skills
  are named by path), and a text-overlap half that records a skip reason when
  the external documents are not readable in the run environment.
- Region-ownership regression: assert that the turn-ending conditions list,
  the Step B phase table, the carve-out enumeration and the Step C heading are
  not the sections this task's diff touched, by pinning their anchor sentences
  as unchanged.
