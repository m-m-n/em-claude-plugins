# Task Plan: task0007 — the spec perspective's absence rule on the develop-driven route

## Goal

Extend the existing "no spec document, so drop the spec perspective with a
skip notice" rule from the standalone review route to the develop-driven
route, without adding any tier-conditional branch to perspective selection.

## Requirements

FR17, NFR2, NFR7

## Scope

### Files to Create

- `tests/test_tier_spec_perspective.py` — conformance tests for the widened rule and for the untouched baseline

### Files to Modify

- `em-workflow/references/review-phase.md` — relax the develop-driven spec-location step and state the floor's behaviour when the spec document is absent on that route
- `em-workflow/references/review-rules.yaml` — update the header comment that asserts the spec document always exists on the specification-driven flow

## Design

**What is actually wrong today.** The review rules' header states that the
spec perspective is included unconditionally because the specification-driven
flow guarantees the spec document exists, and that the drop-with-a-skip-notice
behaviour applies only to the standalone command. The review phase's input
resolution says the same thing from the other side: on the develop-driven
route the spec document must exist. Once a tier can legitimately omit that
document, both sentences are false, and no amount of not-producing the
document makes the floor drop the perspective on its own.

**The change is a route extension, not a tier branch.** The condition stays
"the spec document is absent". What changes is that the develop-driven route
can now reach that condition. Nothing anywhere tests the tier to decide which
perspectives run.

**Review phase.** The spec-location step keeps resolving the committed copy
inside the integration worktree as canonical, and keeps refusing to resolve
from the main tree. Its "must exist" clause becomes "absent means the
availability flag reads false", identical to the standalone arm. The floor
description gains the same conditional for the develop-driven route that it
already carries for the standalone-without-a-workflow-file case. The fan-out
step already skips perspectives that require a spec when the flag is false and
renders them as skipped; that machinery is reused unchanged and must not be
duplicated.

**Review rules.** The header comment's sentence is rewritten so the
unconditional inclusion is conditioned on the document's availability on both
routes, with the skip-notice behaviour named once. The baseline list itself
is not edited: the security perspective stays in it, and no rule row is
added, removed or reordered.

**Boundary.** The unreviewed-perspective disclosure already excludes a
spec-requiring perspective skipped for this reason. That exclusion is checked
for correctness under the widened rule and, if it is already correct, left
alone.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: the review phase's spec-location step states that an absent spec
      document on the develop-driven route sets the availability flag false,
      and keeps both existing constraints — the integration-worktree copy is
      canonical, and the main tree is never resolved from.
- [ ] AC-2: the floor description states that the spec perspective is dropped
      with a skip notice when the availability flag is false, on the
      develop-driven route as well as the standalone one (TS-7).
- [ ] AC-3: the review rules' header no longer claims the specification-driven
      flow guarantees the spec document exists, and no longer scopes the
      drop-with-a-skip-notice behaviour to the standalone command alone.
- [ ] AC-4: the baseline perspective list is byte-identical to its pre-change
      value and still contains the security perspective; the rule rows are
      unchanged in content and order (NFR2).
- [ ] AC-5: with the availability flag false, the resulting floor still
      contains the security and comprehensive perspectives and does not
      contain the spec perspective (TS-7).
- [ ] AC-6: neither file gains a condition that reads the tier; asserted by an
      absence check over both files whose negative proof fires on a forged
      copy carrying one.
- [ ] AC-7: `tests/test_tier_spec_perspective.py` asserts AC-1 through AC-6,
      is discovered by `python3 -m unittest discover -s tests`, imports only
      standard-library modules, and pairs each matcher with a negative proof
      and a non-vacuity guard.

## Test Notes

- AC-4 is a saved-constraint assertion and carries the most weight here: it is
  the mechanical expression of "the security perspective cannot be removed".
  Capture the baseline's pre-change text from the base commit and compare.
- AC-5 evaluates the floor the way the rules file's header specifies — union
  semantics over the declared task metadata — with the availability flag
  false. That evaluation belongs in the test, since no script performs it.
- AC-6's absence check must cover both files, including comments, and must
  search for the tier vocabulary rather than a single spelling.
- Worth covering: the fan-out step's existing skip behaviour is not
  duplicated. Assert that the phrase describing it appears exactly once in the
  review phase document.

## Out of Scope

- Any change to perspective selection driven by the tier. The tier is not read
  by either file.
- Changes to the fan-out or disclosure machinery beyond confirming they still
  hold under the widened rule.
- The standalone review command's behaviour, which is already correct.
