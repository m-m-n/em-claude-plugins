# Task Plan: task0002 — workflow.yaml schema for tier and non-design skipped

## Goal

Define the tier field and the tier decision block in the workflow schema, and
widen the status semantics so a step other than design may legitimately carry
the skipped status.

## Requirements

FR2, FR3, FR12, NFR7

## Scope

### Files to Create

- `tests/test_tier_workflow_schema.py` — conformance tests for the two schema changes

### Files to Modify

- `em-workflow/references/workflow-schema.md` — add the tier field and the decision block to the structure and its worked example; widen the status semantics section; state the upgrade-only rule

## Design

**Tier field.** A top-level field holding one of the three tier labels. Its
write owner is the orchestrator, exactly like every other field of this file —
the single-writer rule is unchanged and must be restated nowhere.

**Decision block.** A sibling mapping with exactly four sub-fields: the agent
that decided, the confidence record, the decision timestamp, and the list of
subtractions applied. The confidence record holds the observed probability
values rather than a single confidence scalar, so that nothing in the schema
invites a confidence-only threshold (AC-4's schema half). The block's content
is a record of a decision already made; the rules that produced it live in
`references/tier-rules.yaml`, cited by path and not restated.

**Status semantics.** The current text states that the skipped status is valid
only for the design step and that the workflow is complete when every step is
completed except that design may be skipped. Both sentences are rewritten so
that any step may carry skipped when a tier subtracted it, that a skip reason
stays mandatory in every case, and that a skipped step is passed over by the
step-selection rule exactly as before. The design step keeps its own
create-spec-decided skip as a named case, so its existing behaviour is
described, not deleted.

**Upgrade-only rule.** The schema states that the tier field's value may be
raised and never lowered, and that a re-transcription from persisted state
must not lower it. The mechanism that performs the raise — returning skipped
steps to pending — belongs to the develop skill and is cited, not described
here.

**Boundary.** This task changes no behaviour document. The develop loop's own
discipline for skipped steps is task0005's; the tier's production and
persistence are task0003's. Where this document needs those facts it cites
them.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: the schema document defines the tier field with its three-value
      domain, and the decision block with exactly its four named sub-fields —
      no more and no fewer (TS-12).
- [ ] AC-2: the schema's worked structure example carries both, positioned so
      that a reader sees them alongside the other top-level blocks.
- [ ] AC-3: the status semantics section no longer restricts the skipped
      status to the design step, states that a skip reason is mandatory
      whenever the status is skipped, and states that a skipped step is passed
      over by step selection.
- [ ] AC-4: the completion rule in the same section is restated so that a
      workflow with skipped non-design steps can be complete, with the design
      step's own case still described rather than removed.
- [ ] AC-5: the document states that the tier may be raised and never
      lowered, and that re-transcription from persisted state must not lower
      it; it cites the mechanism's owner rather than describing the mechanism.
- [ ] AC-6: the decision block's description contains no threshold and no
      confidence-only criterion, and cites the rules file as the owner of the
      thresholds.
- [ ] AC-7: `tests/test_tier_workflow_schema.py` asserts AC-1 through AC-6
      against the raw document text, is discovered by
      `python3 -m unittest discover -s tests`, imports only standard-library
      modules, and pairs each matcher with a negative proof and a non-vacuity
      guard.

## Test Notes

- All assertions are document conformance against raw text, following the
  pattern the existing schema-related modules in `tests/` use.
- The four-sub-field assertion must be exact in both directions: a missing
  sub-field and an extra one both fail, so the negative proof forges one of
  each.
- The status-semantics assertions need care about non-vacuity: prove that the
  matcher for "no longer restricted to design" actually fires against a forged
  copy carrying the old sentence, so a passing assertion is not merely a
  missing string.
- Worth covering: the document must still describe the design step's
  create-spec-decided skip, so a test proves that case was not deleted while
  the general restriction was lifted.

## Out of Scope

- Any change to the develop skill, the phase protocols, or the review
  documents. This task touches one document plus its test module.
- Defining how the tier is decided or persisted.
- Adding any new status value. The upgrade path reuses pending.
