# Task Plan: task0001 — tier decision rules and deterministic evaluator

## Goal

Establish the single place that holds the tier decision's questions,
thresholds, Codex output schema and availability fallback matrix, and a
deterministic evaluator that turns observed values into a tier without any
model inference.

## Requirements

FR1, FR4, FR5, FR13, NFR1, NFR5, NFR7

## Scope

### Files to Create

- `em-workflow/references/tier-rules.yaml` — the rules single source of truth: the Jev question set, the three threshold rows, the Codex output schema, and the availability fallback matrix
- `em-workflow/scripts/decide-tier.py` — the deterministic evaluator described in IMPLEMENTATION.md Shared Components
- `tests/test_tier_rules.py` — conformance tests for the rules file and behavioural tests for the evaluator

### Files to Modify

None.

## Design

**Rules file contents.** Four top-level groups, each named so a consumer can
cite it: the question set sent to the external judgement skill, the threshold
rows, the Codex pre-survey output schema, and the availability fallback
matrix. The question set and any model-behaviour guidance are expressed as a
reference to the external skills by path, never as reproduced text (NFR5).

**Threshold rows.** Evaluated in this fixed order; the first match wins.

1. The first-bucket probability is at or above 0.80 AND the clarity member is
   at or above 0.5 → the tier that removes the most.
2. The first-bucket probability is at or above 0.40 AND the sum of the first
   two bucket probabilities is at or above 0.85 → the middle tier. The
   first-bucket floor is what keeps a low first bucket carried by a high
   second bucket out of the middle tier (FR4, resolved per IMPLEMENTATION.md
   Resolved Questions).
3. Otherwise → the tier that removes nothing.

No threshold anywhere may be expressed against the confidence member alone
(AC-4). Where a needed member is absent, the row does not match and evaluation
falls through to row 3.

**Codex output schema.** The schema names the members the pre-survey must
return: the files expected to be touched, an approximate changed-line count,
whether new functions, new files or new dependencies are needed, whether
covering tests already exist, the spill-over into other modules, and the
member stating whether work remains at all. The schema states the readonly
wrapper as the only invocation route and names the raw subcommand as
forbidden.

**Availability fallback matrix.** Three rows: both tools usable → decide from
description plus real code; only the judgement skill usable → decide from the
description, and where the two available readings disagree fall to the tier
that removes nothing; the judgement skill unusable → the tier that removes
nothing regardless of the other tool. Any non-zero exit status from the
judgement skill counts as unusable, with no per-status distinction.

**Evaluator contract.** Exactly as pinned in IMPLEMENTATION.md Shared
Components: one JSON mapping in on standard input, one JSON mapping out on
standard output, an optional rule-table path argument defaulting to the
plugin's own rules file, a safest-tier result with a naming reason for every
incomplete input, and no interactive behaviour at all.

**What this task does not decide.** The subtraction list per tier belongs to
the develop skill (IMPLEMENTATION.md D4), and the persisted decision record's
shape belongs to task0003. This task's rules file must not restate either.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `em-workflow/references/tier-rules.yaml` parses as YAML and
      carries all four named top-level groups — question set, thresholds,
      Codex output schema, fallback matrix.
- [ ] AC-2: the rules file names the external judgement skill and the
      external model-guidance skill by path and reproduces no sentence from
      either; the file also names the readonly Codex wrapper and does not name
      the raw Codex subcommand as an invocation route.
- [ ] AC-3: the evaluator returns the most-removing tier for a first bucket of
      0.81 with a clarity member of 0.6; the middle tier for a first bucket of
      0.50 with a second bucket of 0.40; and the removes-nothing tier for a
      first bucket of 0.37 with a second bucket of 0.59 — the last one only
      because of the first-bucket floor, since that pair sums to 0.96 (TS-10,
      verbatim as SPEC states it).
- [ ] AC-4: no threshold expressed against the confidence member alone appears
      in the rules file or in the evaluator, proved by an absence assertion
      that its own negative proof shows would fire on a forged copy carrying
      one.
- [ ] AC-5: for every combination the fallback matrix marks unusable —
      including each documented non-zero exit status of the judgement skill —
      the evaluator returns the removes-nothing tier and names the reason
      (TS-9).
- [ ] AC-6: a missing, malformed, or incomplete input yields the
      removes-nothing tier with a reason naming what was missing, on a zero
      exit status, and produces no prompt.
- [ ] AC-7: `tests/test_tier_rules.py` is discovered by
      `python3 -m unittest discover -s tests`, imports only standard-library
      modules directly, and each of its matchers has a negative proof paired
      with a non-vacuity guard.

## Test Notes

- Unit: every threshold row, every fallback-matrix row, and the degraded-input
  path are direct calls into the evaluator, loaded the way the existing
  `tests/test_check_plugin_invariants.py` loads a plugin script.
- Conformance: the rules file's group presence, the external-skill
  non-duplication check, and the confidence-only absence check read the raw
  file text so a violation hidden inside a comment still fails.
- The non-duplication check needs a decidable form: assert that no line of the
  rules file longer than a short threshold is also present verbatim in the
  external skills' documents when those documents are readable, and skip that
  half with a recorded reason when they are not — the structural half (the
  file names them by path) is asserted unconditionally.
- Edge case worth covering: a first bucket exactly at 0.80 with the clarity
  member exactly at 0.5, a first bucket exactly at 0.40, and a bucket sum
  exactly at 0.85 — the rows use "at or above", so all three must match.

## Out of Scope

- Invoking the judgement skill or the Codex wrapper. The evaluator never
  performs an invocation; the orchestrator's procedure is task0003's.
- The subtraction list per tier, the persisted decision record, and the
  `workflow.yaml` field definitions.
- Threshold auto-tuning or learning of any kind.
