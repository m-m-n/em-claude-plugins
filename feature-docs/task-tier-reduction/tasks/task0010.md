## Design

**The defect.** The task document carries exactly two sections (the change
being made and the expected result). The validator applies two checks to
whatever document a task entry's `plan` names — reconciliation of the
entry's declared file set against the plan's Files sections, and the
presence of a non-empty mandatory Acceptance Criteria section — with no
branch on what the plan is. At the most-reducing tier both checks therefore
fail every time, and the round-1 auto-fix loop added the exemption to the
phase document only, so the SSOT and its mechanical enforcer now disagree.

**The exemption's trigger.** One criterion is chosen and used on both
sides: the `plan` value's final path segment equals the task document's file
name. The alternative (passing the tier into the validator) is rejected —
this call site receives a workflow patch and a feature directory and has no
tier input, and adding one would put a worker-influenced tier value in
control of which checks run. The chosen criterion keeps the decision inside
data the phase document already fixes.

**What the exemption covers, and what it must not.** Skipped for an exempt
plan: the Files-section reconciliation and the Acceptance Criteria presence
check. Still applied, in their existing order and with their existing error
kinds: the relative-path safety and symlink rejection, the containment
re-check against the feature directory's real path, the plan file's
existence, the stat and the size limit, and the read itself. The exemption
is a relaxation of two content checks only; it never becomes a way for a
patch-supplied path to skip containment.

**The document side.** Section 2a's sentence is rewritten so that its
trigger is the same criterion, in the same words, as the implemented one —
the drift the review found is a wording drift as much as a behavioural one.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: When a task entry's `plan` names the task document, the
      validator emits neither the files-mismatch error nor the
      acceptance-criteria error for that entry.
- [ ] AC-2: For the same entry, a plan path that is absolute, contains a
      parent-directory segment, traverses a symlink at any segment, does not
      exist, or exceeds the size limit still produces exactly the error kind
      it produces today.
- [ ] AC-3: A task entry whose `plan` names an ordinary task plan still
      produces the files-mismatch error when the declared file set and the
      plan's Files sections differ, and still produces the
      acceptance-criteria error when that section is absent or empty.
- [ ] AC-4: `create-plan-phase.md` section 2a states the exemption's trigger
      as the plan's final path segment being the task document's file name,
      and the validator's own branch is expressed on that same criterion.
- [ ] AC-5: An end-to-end check invokes the validator the way the phase
      invokes it — against a feature directory holding a real two-section
      task document and a single-task patch whose entry points at it — and
      the run reports no error.
- [ ] AC-6: `tests/test_tier_task_document_plan.py` covers AC-1 through AC-5,
      each positive assertion paired with the negative proof in AC-3, and
      imports standard-library modules only.
- [ ] AC-7: `python3 -m unittest discover -s tests` reports no failure that
      is not already present at the integration branch's base commit, and no
      existing validator error kind is renamed or removed.

## Test Notes

AC-1/AC-2/AC-3/AC-5 are exercised by loading the validator module the way
`tests/test_check_plugin_invariants.py` already loads a plugin script and
driving it over temporary feature directories built by the test itself. The
symlink case in AC-2 is the one worth constructing explicitly: the exemption
must not be reached before containment is decided, so the test forges a plan
value whose final segment is the task document's file name but whose path
escapes the feature directory, and requires the path error rather than a
pass.

AC-4 is a document-conformance assertion over both files' raw text, with a
forged sample carrying the pre-change wording as its negative proof.
