The contract-literal absence guards cover the new code `unmapped_stop`. The
pointer documents `skills/develop/SKILL.md`, `references/batch-mode.md` and
`references/implement-phase.md` are proven, whole-file, not to restate it.

FR9, FR11, NFR1

## Scope

None.

### Files to Modify
- `tests/test_batch_stop_contract_skill_wiring.py` — the absence-only reason-code tuple and its member-count test (see Design).
- `tests/test_develop_once_option.py` — the SC5 reason-code absence list (see Design).

## Design

The identifier is fixed in IMPLEMENTATION.md SC1, and pin ownership in SC3.

- **`tests/test_batch_stop_contract_skill_wiring.py`**:
  - The `REASON_CODES` tuple is used for absence checks only and is never
    asserted against the contract document. It gains `unmapped_stop`, for 14
    unique members.
  - The member-count class and test go from 13 to 14. Where the class name
    carries the count word, rename the class.
  - A membership test asserts `unmapped_stop` is in the tuple.
  - A comment next to the addition names this feature as its provenance.
  - The module's existing whole-file guards over `skills/develop/SKILL.md`,
    `references/batch-mode.md` and `references/implement-phase.md` now cover
    the new literal. These guards run through the contract-literal absence
    matcher.
- **Widening proof**: Add one test showing the widened domain actually takes
  part in the matcher: a synthetic pointer-document excerpt naming
  `unmapped_stop` is flagged. The matcher's shape is unchanged, so its
  existing negative proofs stay as they are.
- **`tests/test_develop_once_option.py`**: The `SC5_REASON_CODES` absence
  list gains `no_work_required` and `unmapped_stop`, and its absence
  assertions run against the same documents as before. If the module pins the
  list's size, or lists its members in prose, those follow.
- **No document edits**: No document is edited by this task.

## Test Notes

- **TDD order**: The count and membership tests go red first (13 members,
  `unmapped_stop` missing), then green once the tuple is widened.
- **Worktree independence**: Both lists are absence-only, so they pass in this
  task's worktree whether or not the contract already defines `unmapped_stop`.
  Keep it that way. Assert nothing about `batch-terminal-line.md` here.
- **Unexpected contract assertion**: `test_develop_once_option.py` was not read
  at planning. If it also asserts `SC5_REASON_CODES` against the contract's
  reason-code table, that assertion would fail here until the contract change
  merges. Report it to the orchestrator as a plan deviation instead of editing
  the contract.
- **Existing convention**: Widening an existing matcher's domain needs no
  second negative proof. AC-3's flagged-excerpt test is the non-vacuity
  evidence for the widening.
