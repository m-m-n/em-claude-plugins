# Task Plan: task0001 — Catch-all reason code, refusal-pattern row and fallback rule

## Goal

`em-workflow/references/batch-terminal-line.md` binds every batch-terminating
stop to exactly one reason code by construction, through three additions:

- a catch-all code `unmapped_stop` with its coverage row;
- a lowest-precedence fallback rule;
- a named row that maps the command-approval refusal-pattern hard fail to
  `gate_fail_closed`.

The pins that depend on the code and row sets are synced. New tests prove the
catch-all's precedence, resolution and scope.

### 3. `## Stop point coverage`

- **Opening**: Replace the sentence "Every terminating stop point is bound to
  exactly one reason code above." with a statement that holds by construction.
  Every batch-terminating stop binds to exactly one code:
  - the code of the row that names it, with the Precedence rule settling a
    stop that two named rows match;
  - otherwise `unmapped_stop`, through the fallback rule below, when no other
    row names it.

  The following sentence about the third column ("names the document ...")
  stays as is.
- **Table**:
  - Insert `command-refusal` | `gate_fail_closed` |
    `references/batch-policies.yaml` directly after the
    `policy-option-unavailable` row.
  - Append `unmapped-terminating-stop` | `unmapped_stop` |
    `references/batch-terminal-line.md` as the last row.
  - Existing rows are unchanged.
- **Untouched**: The Precedence rule paragraph and the `context_budget_reached`
  paragraph.
- **Appended after the `context_budget_reached` paragraph**, in this order:
  1. **Fallback rule**, opening with the label "Fallback rule:".
     - A batch-terminating stop that no other row names binds to
       `unmapped_stop`.
     - Every other row takes precedence over the catch-all, including the
       generic `stop-condition-N` rows and the `command-refusal` row.
     - The catch-all applies last, after the Precedence rule has settled any
       match among named rows.
     - The paragraph names non-exhaustive examples, each cited by its owning
       document path:
       - `references/contracts/designer-contract.md`: the `kind: none` ×
         token-present abort, including its batch abort when candidate
         discovery is truncated;
       - the same contract's `em_workflow` × `tokens.html`-only abort before
         dispatch;
       - `references/phase-state.md`: the unknown `schema_version` abort;
       - the remaining untabled aborts of
         `references/question-resolution.md` and
         `references/batch-policies.yaml`.
  2. **Scope**: The fallback applies only to stops that end a batch run with
     `state` `stopped`. It never applies to:
     - a wait turn: develop's stop condition 5, or implement's launch and wake
       turns (see `## No result on a wait turn`);
     - normal completion;
     - a `--once` phase boundary (`phase_done`);
     - the infra auto-resume, which is not a stop;
     - the 64 KiB size-collision outcome. It emits no result, and per
       `## Consumer constraints` it adds no reason code and no coverage row.
  3. **Catch-all result**:
     - When `reason` is `unmapped_stop`, `detail` names the stop site (the
       owning document, and the step or section where the stop occurred)
       and the concrete cause.
     - `resume_conditions` stays mandatory and non-whitespace, as for every
       `stopped` result.
