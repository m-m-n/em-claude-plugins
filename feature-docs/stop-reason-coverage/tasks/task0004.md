# Task Plan: task0004 — em-workflow version bump to 0.2.1

## Goal

The em-workflow plugin version moves from 0.2.0 to 0.2.1, identically in both
registries, so installed caches pick up the contract change. A durable test
proves the bump.

## Requirements

FR10, NFR1, NFR4

## Scope

### Files to Create
- `tests/test_stop_reason_coverage_version_bump.py` — the durable version-bump test module (see Design).

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — the plugin version field (see Design).
- `.claude-plugin/marketplace.json` — the version field of the em-workflow plugin entry (see Design).

## Design

This task alone edits the version fields (IMPLEMENTATION.md D7).

- **Registry edits**:
  - The `version` of `em-workflow/.claude-plugin/plugin.json` changes from
    `0.2.0` to `0.2.1`.
  - The `version` of the `plugins[]` entry named `em-workflow` in
    `.claude-plugin/marketplace.json` changes from `0.2.0` to `0.2.1`.
  - Only these two values change. Names, descriptions, the `em-review` entry
    and every other field are unchanged.
  - Both files remain valid JSON with their existing formatting.
- **New test module**:
  - It reads both files as parsed JSON, never by pattern-matching text.
  - Baseline matcher: the version parses as X.Y.Z. Under per-component numeric
    comparison it is strictly greater than (0, 2, 0). It is never compared to
    a fixed major.minor or a literal string, so a later bump keeps it green.
  - Equality matcher: the marketplace em-workflow entry's version equals the
    plugin manifest's version as a string.
  - Negative proofs: a forged `0.2.0` is rejected by the baseline matcher. A
    forged pair of differing versions is rejected by the equality matcher.
  - Non-vacuity guards: each forged value parses as a well-formed X.Y.Z, so the
    proofs exercise the comparison rather than a parse failure.
  - It imports the standard library only and no other test module.
- **Existing module**: `tests/test_batch_stop_contract_version_bump.py` is not
  edited. It stays green, because 0.2.1 is past its baseline.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `em-workflow/.claude-plugin/plugin.json` parses as JSON, its
  `version` reads `0.2.1`, and its `name` reads `em-workflow`.
- [ ] AC-2: `.claude-plugin/marketplace.json` parses as JSON. The `em-workflow`
  entry's `version` reads `0.2.1` and equals the manifest's. The `em-review`
  entry is unchanged.
- [ ] AC-3: The new baseline matcher accepts the live versions and rejects a
  forged `0.2.0`, with a non-vacuity guard showing the forged value parses.
- [ ] AC-4: The new equality matcher accepts the live pair and rejects a forged
  differing pair, with a non-vacuity guard. The module imports the standard
  library only.
- [ ] AC-5: `tests/test_batch_stop_contract_version_bump.py` passes
  unmodified, and `python3 -m unittest discover -s tests` passes.

## Test Notes

- **TDD order**: The baseline test goes red on the un-bumped 0.2.0 tree, then
  green after both edits.
- **Literal versions**: AC-1 and AC-2's literal `0.2.1` is confirmed by the
  verify phase reading both files. The durable test never pins that literal.

## Out of Scope

- Any change to the em-review version or entry.
- Description text in either registry.
- Any contract or test change of the other tasks.
