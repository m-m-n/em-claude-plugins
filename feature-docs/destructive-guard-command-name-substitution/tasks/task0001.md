# Task Plan: task0001 — statically-unknown command word, quote-aware payload extraction, and the published version bump

## Goal

The destructive guard stops treating a statement whose command word is produced
by a command substitution as unjudgeable, matching the remaining tokens against
the destructive shapes it already knows; its payload argument position
distinguishes quoted from unquoted substitutions so the quoted form no longer
produces a false positive; and the plugin version is advanced in the same change
so the fix actually reaches installed caches.

### Statically-unknown command word (FR1, FR2, FR3)

When command-word determination skips a substitution-only token at the command
word position, the next token decides the classification:

1. If that next token begins with a dash, a real shell could never have used it
   as a command name, so the statement's command name is classified as
   **statically unknown**.
2. Otherwise, the token is a possible real command word and the current
   behaviour applies unchanged — it is used as the command word, and none of the
   routes below are entered.

For a statement classified as statically unknown, the remaining tokens are
offered to the existing shape matchers along two routes, both of which reuse the
matchers' own verdict stage and reason id — no new stage, no new reason id, and
no verdict produced by the classification itself:

- **rm route** (FR1): the remainder is passed to the rm matcher only when it
  carries a recursion flag, a force flag, and at least one non-flag operand.
  Short and long spellings of both flags count, including flags bundled into one
  argument. A remainder that satisfies fewer than all three conditions is not
  passed on, and the statement keeps its current verdict. Because the matcher is
  reached unchanged, its safe-route exceptions apply exactly as they do today.
- **git route** (FR2): the remainder is also offered to the git matcher, whose
  subcommands are bare words and therefore never reach the dash-leading test
  above. A remainder the git matcher does not recognize yields no verdict.

Both spellings of substitution (dollar-parenthesis and backtick) reach this
classification identically, because the pre-lexical marking stage already
normalizes them to the same marker.

### Quote-aware payload extraction (FR4, FR5)

At the payload argument position of the shell-command-string option, the
evaluation builtin, and the here-string operator — and nowhere else — the raw
pre-lexical text decides whether the substitution at that position was enclosed
in quotes:

- **Quoted**: the word survives even when the substitution expands to nothing,
  so the substitution itself is the payload. The current promotion to the next
  word does not happen, and the following argument is left alone — matching the
  real shell, where that following argument is the shell's own zeroth argument
  rather than script text.
- **Unquoted**: the word disappears on empty expansion, so the current promotion
  to the next word is preserved unchanged (FR5).

The marker structure and the token attribute trio are not changed, and this
quote knowledge must not leak into the command-word determination or the shape
matchers — they keep working from tokens alone.

### Declared out-of-scope range (FR7)

A form whose substitution output becomes the script body cannot be resolved
without evaluating the substitution, which is forbidden (NFR1). State that as a
single scope sentence, and place the same statement in two locations: the case
label of the corresponding entry and the payload-extraction docstring. The
verdict for that form stays `allow`, and the declaration is what makes the
`allow` readable as a decision rather than an oversight.

### Published version bump (FR10)

Both version-carrying files hold the same value today; after this task both hold
that value with the patch component advanced by exactly one, major and minor
unchanged. Read the current value from the files themselves rather than from any
document — this plan deliberately names no version number, so that a value

correctly. Only the em-workflow entry of the marketplace definition changes;
every other plugin's version there is independent. No field other than the two
version values is touched, and neither file is reformatted or re-sorted.

If the two files are found to disagree before the edit, do not silently pick
one — report it as a plan deviation, since the contract's precondition (both hold
the same value) does not hold.

## Test Notes

- The case table is the primary test surface: write the new entries first (they
  express the target behaviour as expected verdicts) and run the case suite
  before changing the judgement, so the currently-failing set is the exact set
  this task must turn green. The FR6 flip belongs in that first step too — it
  will fail until quote awareness lands, which is the point.
- AC-1 through AC-5 map to case-suite entries. AC-6's wording agreement and the
  mirror-script check are not expressible as case entries; verify them by reading
  the two changed files and confirming the two mirror scripts are untouched.
- Verify reason ids, not just verdicts, for AC-1 and AC-2 — reusing the existing
  reason id is what distinguishes the required behaviour from a new blanket deny.
- AC-8 has no unit test of its own and none is added: the deliverable is two
  declared values, and the plugin invariants check is the mechanism that verifies
  them. Run that check before the bump (green on the current state) and after
  (still green); that before/after pair is this criterion's equivalent of a
  failing-then-passing test. Compare the two values as strings after the edit
  rather than trusting the edit — a mismatch between the two files is the exact
  failure mode the repository rule exists to prevent.
- Edge cases worth covering while implementing: bundled flag spellings for the rm
  route; a remainder whose only operand is itself a substitution marker; a git
  remainder the matcher does not recognize (it must produce no verdict, not a
  fallback); a payload position where the substitution is quoted and is the last
  word of the command.
- Regression guard for AC-7: before changing anything, capture the current
  verdict and reason of the case table's substitution-free entries, and compare
  after — the requirement is identical stage and identical reason text, not
  merely an identical verdict.
