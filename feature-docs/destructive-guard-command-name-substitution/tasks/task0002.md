# Task Plan: task0002 — evidence-gated substitution-head routing, whole-word payload quote judgement, and the case-table delta

## Goal

The destructive guard enters its rm and git routes for a substitution-headed
statement only when the command name read statically out of the substitution says
so, judging that spelling exactly as it judges the plain spelling; and the
payload argument position distinguishes quoting only when the payload word is a
substitution in its entirety, so a body that merely contains a quoted
substitution is still rescanned.

### Command-name evidence (FR11)

For a statement whose command-word position held a substitution token that the
command-word resolution skipped, recover the substitution's raw text from the
pre-lexical segment body and read a command name from it:

1. Take the substitution body — the text between the opening and closing
   delimiters, in either substitution spelling.
2. Split it on whitespace and take the **last** word.
3. Take everything after that word's final path separator — its basename — as the
   statically read command name.

Worked outcomes the implementation must produce: a body whose last word is a bare
`rm` reads as rm; a body ending in an absolute path to rm reads as rm; a body
whose last word is an option-taking lookup of rm still reads as rm; a body whose
last word is a subcommand of an unrelated tool reads as that subcommand's name
and therefore matches no route.

The reading reports **unreadable** — and no route is entered — in each of these
cases: the body is empty or whitespace-only; the last word begins with a dash;
the token position cannot be mapped back to a raw occurrence; nesting makes the
raw extent indeterminable. Mapping relies on the substitution occurrences in the
segment body appearing in the same order as their markers; if that correspondence
cannot be established, the answer is unreadable, never a guess.

Two prohibitions, both load-bearing:

- The reading is string processing only. No substitution is executed, no
  subprocess is launched, no path is resolved or stat-ed, nothing is read from
  the filesystem.
- Evidence is never taken from any word of the body other than the last one. A
  body in which an rm or git word appears as some other command's argument must
  not produce a route entry.

### Evidence-gated routes (FR1, FR2, FR3)

The remaining tokens after the skipped command-word position are handed to a
route **only** on the evidence above:

- Evidence reads as rm: the remainder goes to the existing rm shape matcher,
  unchanged and unfiltered. Both of the pre-gates currently standing in front of
  it are removed — the one requiring the next token to begin with a dash, and the
  pre-screen requiring recursion and force flags and a non-flag operand. The
  matcher's own threshold decides, and its safe-route exceptions apply exactly as
  they do for the plain spelling.
- Evidence reads as git: the remainder goes to the existing git shape matcher.
  The current behaviour of calling that matcher whenever a substitution was
  skipped is removed. A remainder the matcher recognizes nothing in yields no
  decision — not a fallback verdict.
- Evidence reads as anything else, or is unreadable: no route is entered and the
  statement keeps its blanket `allow`.

The tier and the reason id are whatever the matcher returns. Nothing in this task
creates a tier or a reason id, and no route-side floor is added (IMPLEMENTATION.md
R3, R5).

### Single entry point (FR13)

The classification above — judging the skip result, reading the evidence, and
handing off to either route — lives in one named function placed where the
deleted pre-screen helper was. The dispatch loop retains only the call. The
pre-screen helper that filtered the rm route, having lost its purpose, is deleted
rather than left unreferenced. The point of the extraction is that the route's
entry condition ends up in one place that can be read and tested on its own.

### Whole-word payload quote judgement (FR4, FR5, FR12)

At the payload argument position of the shell-command-string option, the
evaluation builtin and the here-string operator, the quote distinction is
evaluated **only when the word at that position is a substitution in its
entirety**:

- Whole-word **quoted** substitution: the word survives even when the
  substitution expands to nothing, so the substitution is the payload. No
  promotion to the next word happens and that position is the payload boundary;
  the following argument is the real shell's zeroth argument, not script text.
- Whole-word **unquoted** substitution: the word disappears on empty expansion,
  so today's promotion to the next word is preserved exactly.
- **Anything else**, including a word that merely contains a quoted substitution
  somewhere inside it: today's behaviour is unchanged and the body is still
  pushed back for rescanning. The current containment test that stops on a quoted
  substitution appearing anywhere inside the word is the defect being removed —
  it disables the rescan of ordinary bodies that interpolate a directory name, a
  date or a working directory next to a destructive command.

Make the shell-command-string side symmetric with the here-string side, which
already tests the whole-word property first. One consequence must be accepted
rather than worked around: a here-string whose target is a whole-word quoted
substitution, followed by a destructive-looking trailing argument, becomes
`allow`. That is correct — the here-string body executes and the trailing
argument is the zeroth argument — and it is pinned as a case in the same change.

### Declared out-of-scope range (FR7)

the case labels of the two corresponding entries and in the payload-extraction
docstring, with the same scope in each location. The `allow` for both forms is
what the declaration makes readable as a decision rather than an oversight.

## Test Notes

- The case table is the primary test surface. Write the new entries and the
  inversion first and run the case suite before touching the analyzer: the
  currently-failing set is then exactly the set this task must turn green, and
  the allow-side entries are in place before the gate widens.
- Write the allow-side false-positive guards (the eight recursion-plus-force
  commands and the two git-subcommand shapes) before the deny-side additions.
  They are the entries whose absence let the first generation's regression pass a
  green suite.
- Verify reason ids, not just verdicts, for the rm and git routes. Reusing the
  existing reason id is what distinguishes the required behaviour from a new
  blanket deny.
- For AC-4, run each substitution-headed command and its plain-spelling twin
  through the guard and compare tier and reason id. Treat any pair where the
  substitution-headed side is stricter as a failure, even when both are `deny`
  with different reason ids.
- Edge cases worth covering while implementing: a substitution body whose last
  word is an absolute path; a body whose last word is an option rather than a
  command name; a body in which an rm or git word appears as an argument of
  another command; a nested substitution; a remainder whose only operand is
  itself a substitution marker; a payload position where the whole-word quoted
  substitution is the last word of the command; a body that contains a quoted
  substitution and a destructive command in the same statement.
- Regression guard for AC-8: before changing anything, capture the verdict and
  the reason text of every substitution-free entry in the table, and compare
  after. The requirement is identical tier and identical reason text, not merely
  an identical verdict. Capture the failing-test-ID set of the repository
  unit-test discovery in the same before pass — the comparison is per test ID,
  not per count.
- AC-9 has no unit test of its own and none is added: the deliverable is two
  declared values and the plugin invariants check is the mechanism that verifies
  them. Run that check before the bump and after; compare the two values as
  strings after the edit rather than trusting the edit.
