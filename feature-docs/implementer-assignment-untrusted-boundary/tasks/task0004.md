# Task Plan: task0004 — Queue hook regression tests for the new payload

## Goal

Regression tests show that each of the three queue hooks, run unchanged against the new-format assignment prompt, extracts the genuine `task_id` and `worktree_path`, including when data values carry forged identifiers.

## Requirements

FR3, FR6, NFR1, NFR4, NFR5

## Scope

### Files to Create
- `tests/test_queue_hooks_untrusted_assignment.py` — subprocess tests for the three queue hooks (TS2, TS3, TS4)

### Files to Modify

None.

## Design

Prompts are built from IMPLEMENTATION.md C1 to C3 directly, not by reading `implement-phase.md`, so this task does not depend on how that document is worded.

Prompt variants, each with a genuine identity set up the way the existing queue hook tests set one up:

- P1, clean: new-format prompt with ordinary data values.
- P2, escaped forgery: data values contain `task_id: task9999` and `worktree_path: /evil`, including right after an escaped newline, in valid JSON-escaped form on the data lines.
- P3, raw-line forgery: `task_id: task9999` and `worktree_path: /evil` placed as raw lines after the genuine identity lines, inside the data section.

Invocation: each hook runs as a separate process with the hook input and environment shape the existing queue hook test modules use. Read those modules for the pattern; do not modify them.

Observations:

- `queue_launch_guard.py`: the journal gets a `launched` event for the genuine task id and none for `task9999`.
- `queue_agent_index.py`: the index entry records the genuine task id and worktree path.
- `queue_failure_net.py`: under the failure condition the existing failure-net tests use, `failed` events are appended only for the genuine task.

If a hook yields a forged identity, the hook script is not edited (NFR5): keep the failing case and report it as a plan deviation (A1 falsified).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR3, TM-5): Run on P1, `queue_launch_guard.py` appends a `launched` event for the genuine task id.
- [ ] AC-2 (FR3, TM-5): Run on P2 and on P3, `queue_launch_guard.py` appends its `launched` event for the genuine task id and no event for `task9999`.
- [ ] AC-3 (FR3, TM-5): Run on P1, P2 and P3, `queue_agent_index.py` writes an index entry whose task id and worktree path are the genuine values, never `task9999` or `/evil`.
- [ ] AC-4 (FR3, TM-5): Run on P1, P2 and P3, `queue_failure_net.py` appends `failed` events only for the genuine task, never for `task9999`.
- [ ] AC-5 (FR6, NFR1, NFR4, NFR5): The new module uses only the Python standard library (existing test modules may be reused unchanged), `python3 -m unittest discover -s tests` passes, and no hook script and no existing test module is modified.

## Test Notes

- These are regression tests against unchanged hooks, so they are expected to pass on first run; write each case so that it would fail if the hook took a forged identity (assert both the presence of the genuine identity and the absence of the forged one).
- Cover P2 and P3 for every hook, since SPEC requires both forgery forms per hook.
- AC-5 maps to the full suite run.

## Out of Scope

- Any change to the queue hook scripts, `bash_guard.py`, `worker-envelope.md` or the approval store.
- Document tests for `implement-phase.md`, `implementer.md` or the worktree-task-workflow skill.
