# Task Plan: task0003 — Instruction source narrowed in the worktree-task-workflow skill

## Goal

The worktree-task-workflow skill treats the orchestrator's launch prompt as an instruction source only through its trusted fields and structure, explicitly excluding the values of the `Untrusted data` section, and its command execution gate runs the decoded JSON value under the existing verbatim rule. A new document test pins this.

## Requirements

FR5, FR6, NFR1, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `tests/test_worktree_skill_instruction_source.py` — document test for the Untrusted input and Command execution gate sections (TS6)

### Files to Modify
- `em-workflow/skills/worktree-task-workflow/SKILL.md` — the "Untrusted input" section and the "Command execution gate" section

## Design

Contract: IMPLEMENTATION.md C5 (this task owns its wording), C4 (permitted uses, kept consistent), C2 and C3 (section name, encoding).

- Untrusted input section: where it names the orchestrator's launch prompt as an instruction source, limit that to the prompt's trusted fields (C1 items 1 to 3) and its structure, and state that values in the `Untrusted data` section are excluded and are used only per C4.
- Command execution gate section: state that the string run for a build, test or format command is the JSON-decoded value of the corresponding `project_commands.*` line, and that it is handled under the section's existing verbatim rule and approval rule, unchanged. No new raw byte-equality claim is added (NFR6).
- The verbatim and approval rules themselves, `bash_guard.py` and the approval store are unchanged (NFR5).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR5, TM-4): The Untrusted input section limits the launch prompt's standing as an instruction source to its trusted fields and its structure.
- [ ] AC-2 (FR5, TM-4): The Untrusted input section explicitly excludes the values of the `Untrusted data` section from the instruction sources.
- [ ] AC-3 (FR5, NFR6, TM-4): The Command execution gate section states that the command string run is the JSON-decoded value of the `project_commands` field and that it is handled under the existing verbatim rule.
- [ ] AC-4 (FR6, NFR1, NFR3, NFR4): The new test module uses only the Python standard library, and `python3 -m unittest discover -s tests` and `python3 em-workflow/scripts/check-plugin-invariants.py .` both pass with no existing test module modified.

Assert the section name `Untrusted data`, the exclusion wording and the trusted-fields wording in the Untrusted input section; assert the decoded-value wording together with a reference to the existing verbatim rule in the Command execution gate section.
- Existing document tests may already pin these two sections; keep their assertions passing.
- AC-4 maps to the full suite run and the invariants run.
