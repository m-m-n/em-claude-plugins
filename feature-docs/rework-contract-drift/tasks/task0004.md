# Task Plan: task0004 — Origin identity rename, closed vocabularies, and the gate's category check

## Goal

The question packet's evidence entries name the origin identifier by its current name
across the schema and every consumer in one atomic change; the classification gate's
category check cites the owning definition instead of reading a field that could not
exist; the gate's fail-closed abort is stated in non-overridable wording; the gate's
independence declaration agrees with its own reversibility arm; and the validator
enforces both closed vocabularies.

## Design

**Why this is one task.** The rename is all-or-nothing: no committed state may exist in
which the packet producer and the origin-verification consumer disagree on the field
name. Splitting the schema, the consumers, the fixtures and the tests across parallel
tasks would create exactly that state. The validator, the fixtures and the validator's
test module are additionally bound to this task by the single-owner rule for
digest-pinned files in IMPLEMENTATION.md.

**The rename.** The evidence entry's origin field takes the current name of the origin
identifier. The pair's definition stays owned by the synthesis document's invariant and
is cited by the packet schema, never restated. Every consumer named above reads the same
name. See IMPLEMENTATION.md Shared Components for the pair's contract. Broadening the
retired field's description in place is explicitly not adopted.

**The category check.** The gate's category check currently reads a category from every
member of the bound set. For a verify-sourced origin the bound set is the verify step's
failing items, which carried no such field — the check read something that could not
exist. It is rewritten to cite the owning definition of that field and its vocabulary
(task0003 writes the definition; this task cites it and restates neither the field nor
its values).

**The gate-side abort.** The check states that the gate aborts when any bound-set
member's category is a security, license or sentinel value, and equally when the value
is missing, unreadable, or outside the vocabulary. The wording matches the
non-overridable form the membership check already uses: final, non-overridable,
recording its reason and the evidence considered, and never raising an unanswerable
confirmation in an unattended run. The verify phase does not abort — it records the
sentinel and lets the case reach this gate; that side is task0003's and is referred to
here by citation only.

**The independence contradiction.** The check declares that it derives nothing from any
worker-supplied field, while the same paragraph reads a reversibility marker that is
worker-supplied. Resolve the contradiction so the declaration and the arm agree, without
weakening either: the orchestrator-held sources stay orchestrator-held, and whatever
the arm reads is stated accurately as to its provenance and its fail-closed handling.
Resolving it by deleting the arm is not acceptable — the arm is a fail-closed abort.

**Validator enforcement.** The origin kind gains closed-vocabulary enforcement,
mirroring the enforcement the classification fields already have, so the asymmetry
disappears. A failing item whose category is missing, empty or out of vocabulary is
rejected on the invocation path that already reads the workflow document; each of the
seven vocabulary values is accepted. The retired name is removed from the script,
including from its comments.

**Coverage.** An owner-scoped absence scan proves the retired name is gone from every
document, script, fixture and test module this task owns, built per the scan contract in
IMPLEMENTATION.md Shared Components so it never matches itself, and with the stated
exclusions named explicitly. New validator cases cover both vocabularies. The two new
fixtures cover the packet that passes origin verification and the pre-change packet that
does not. Every byte-identity pin over a file this task changes is refreshed; no other
pinned constant is touched.
