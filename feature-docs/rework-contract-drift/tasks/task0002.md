## Design

**Authorization condition.** The condition that decides whether a re-planning
authorization is unspent currently names a retired single-field identifier that no
producer writes any more. It is rewritten to require the record to carry a reason, the
origin pair (kind and identifier), and the recording commit, all non-empty, alongside
the existing boolean authorization flag. The pair's meaning stays owned elsewhere and
is cited, not restated — see IMPLEMENTATION.md Shared Components for the pair's
contract. The retired name is removed from this document; it is the last normative
occurrence outside task0004's set.

**Develop skill alignment.** The skill's instruction to record the interruption reason
together with a finding identifier is aligned to record the same pair. The skill states
the field names by citing this document; it defines nothing itself.

**Rule-18 recovery and idempotency.** The application rule that spends the
authorization runs after the rules that write the patch and commit it. An interruption
between them leaves the patch applied and the authorization unspent, and no rule says
what a resumed run must do. Add a rule that makes the consumption recoverable and
idempotent: state how a resumed run recognizes that the patch it is about to spend an
authorization for has already been applied, state that spending an
already-spent authorization is a no-op rather than an error, and state that the
resulting state after any number of resumptions is the same as after one uninterrupted
run. The rule is written here, in the document that owns the application rules; it
cites the phase-state document for where the flag lives and restates nothing from it.

**Ownership boundary.** The ownership-boundary section says only which parts of the
workflow document are orchestrator-updated. It gains coverage of the fact that the
authorization-spending rule writes into phase-state, naming which side owns the write
and under what conditions the crossing is permitted, citing the phase-state document
for the record's own definition.

**Coverage.** The existing assertion pinning the authorization condition asserts the
retired name and must move in this same change, or the suite goes red. The replacement
reads the document live and asserts the condition names both members of the origin pair.
New assertions cover the recovery rule's presence and its idempotency statement, and
the ownership-boundary section's coverage of the crossing. An owner-scoped absence scan
proves the retired name is gone from this task's two documents and its own test module,
built per the scan contract in IMPLEMENTATION.md Shared Components. The byte-identity
pin over this document is refreshed in the same change; no other pinned constant is
touched.
