# Task Plan: task0006 — Plugin version bump

## Goal

Both plugin manifests carry the same raised version, so the installed plugin cache
picks up this feature's changes to files under the plugin directory.

## Requirements

NFR5, NFR6

## Scope

### Files to Create
- `tests/test_rework_contract_drift_version_bump.py` — asserts the two manifests carry the same version and that it is raised over the pre-change value

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — the plugin version is raised by one patch level
- `.claude-plugin/marketplace.json` — the matching plugin entry is raised to the same value

## Design

Files under the plugin directory change in this feature, so the version obligation
applies. The bump is patch-level: every change in this feature is a behavior fix to an
existing document or script, not a feature addition and not a compatibility break.

This task is the single owner of both manifests (IMPLEMENTATION.md Shared Components).
No other task writes either file, so the two values cannot diverge through parallel
edits.

The repository already carries one version-bump test module per feature. This task adds
its own, following that existing shape: read both manifests, assert the plugin entry in
the marketplace manifest and the plugin manifest agree exactly, and assert the value is
strictly greater than the pre-change value with only the patch component changed. The
pre-change value is pinned in the module so a later unrelated bump does not silently
satisfy this feature's obligation.

Reporting this change to the user must note that a restart is required for the new
version to take effect; that note belongs in the completion report, not in a file.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The plugin manifest and the matching entry in the marketplace manifest carry
      exactly the same version string.
- [ ] AC-2: That version is strictly greater than the pre-change value, differing only in
      its patch component.
- [ ] AC-3: No other plugin's entry in the marketplace manifest is modified.
- [ ] AC-4: The new test module fails against the pre-change manifests and passes after
      the bump, and the full suite is green under the project's own runner with no
      third-party import added.

## Test Notes

- Pin the pre-change value explicitly rather than comparing against whatever is currently
  on disk, so the assertion has something to fail against.
- Compare the version components numerically, not as strings, so an ordering assertion
  behaves correctly across a component rollover.
- Follow the shape of the existing per-feature version-bump modules rather than inventing
  a new one.

## Out of Scope

- Any file under `em-workflow/` other than the plugin manifest. This task changes no
  document, no prompt, no script and no fixture.
- Deciding whether the increment should be larger than patch level. It is patch level
  for the reason stated above.
- The two rejected findings — the alleged fixture migration gap and the performance
  findings — must not be reintroduced here in any form.
