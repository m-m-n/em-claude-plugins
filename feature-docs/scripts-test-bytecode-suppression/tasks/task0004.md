# Task Plan: task0004 — Bytecode-free report-name-entry.py tests (in-process load and child launch)

## Goal

`tests/test_report_name_entry.py` writes no bytecode under
`em-workflow/scripts/`: its in-process load of `validate-worker-output.py`
turns bytecode writing on only for that load, and every child process it
launches for `report-name-entry.py` — which loads its sibling
`validate-worker-output.py` into its own process — carries bytecode
suppression in that single launch.

## Requirements

FR1, FR2, FR3, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `tests/test_report_name_entry.py` — its validator loader gains the suppression form, its child-process helper passes the interpreter's no-bytecode option, and new probe and launch test classes are added

## Design

### In-process load

The module-level loader `_load_validator` loads
`em-workflow/scripts/validate-worker-output.py` through the module-level path
constant VALIDATOR_PATH, and its result is kept in the module constant VWO at
import. Apply IMPLEMENTATION.md C1 inside the loader body and nothing else
(C2). The loader of `em-workflow/hooks/queue_stop_guard.py` inside the test
that compares the line rule with the stop guard stays untouched
(IMPLEMENTATION.md D4).

### Child-process launch

`run_entry`, the helper method of the shared test-case base class, builds the
argument list for one launch: the running interpreter, the script path
(by default the real `report-name-entry.py`, or a copy given by the caller),
then the flags. The launched script loads its sibling
`validate-worker-output.py` by file path, which writes that file's bytecode
next to it unless the child process has bytecode writing off.

Decision: the interpreter's `-B` option is placed in that argument list,
directly after the interpreter and before the script path. The environment
passed to the launch stays the one the module's git-environment helper
builds; that helper is also used for every git command in the module, so
adding a variable there would widen the change beyond the single launch.
The helper's parameters, defaults and return value stay unchanged (C2), and
the process-wide `os.environ` is never touched (NFR2).

### New test classes (in the same module)

1. Probe class for `_load_validator`, following IMPLEMENTATION.md C3:
   replace VALIDATOR_PATH on this module itself for one call with a probe in
   a test-owned temporary directory, and observe O1–O4 for the starting
   values False and True. Take the recursive listing of
   `em-workflow/scripts/` before the class's tests and compare it after.
2. Launch class, built on the shared test-case base class:
   - Argument check: intercept the process launch made by `run_entry` for one
     call and inspect the argument list and environment it was given — once
     with the default script and once with an explicit script path.
   - Behavioral check: copy `report-name-entry.py` and
     `validate-worker-output.py` side by side into a test-owned temporary
     directory, with the same setup as the existing test that locates the
     validator as a sibling file, run the copy through `run_entry`, and
     inspect that temporary directory afterwards. This check never writes
     under `em-workflow/`, even when the launch lacks suppression.
   - Environment check: compare a snapshot of the process-wide environment
     taken before `run_entry` with one taken after.

## Test Notes

- Write the new classes first. Before the edits, AC-1 fails for the starting
  value False, AC-4 fails (no `-B`), and AC-5 fails because the copy's
  validator bytecode appears in the copy's temporary directory — never under
  `em-workflow/` — unless the shell running the tests already sets the
  bytecode environment variable; AC-4 is the check that does not depend on
  the inherited environment.
- Intercept the launch only for the call under test, and let the rest of
  the module's launches (including git) run unchanged.
- AC-6's run-alone part is checked by execution: before the run, make sure
  `em-workflow/scripts/__pycache__` is absent in the task worktree (move a
  leftover from a red-phase run to the trash). Record the command and result
  in the report.
- AC-7 is checked by the full suite plus a review of the diff.
