# Task Plan: task0003 — Bytecode-free loads of the remaining em-workflow scripts in tests

`em-workflow/scripts/` other than `scan-dependencies.py` (and, for

## Design

path constant the loader reads when it runs, plus — for a memoizing loader —
its module-level cache, set to empty for that call so the loader really
loads; for row 17, the path argument the loader accepts. "When" says where
the loader is called today: at module level (the result is kept in a module
constant) or during tests.

Row 17 is reference-only: its loader already has the C1 form
(IMPLEMENTATION.md D4) and its module is not edited. Its loader binds its
default path when it is defined, so the probe check passes the probe path as
the argument instead of replacing a constant. The probe check calls every
other loader with no arguments.

### Loader edit (rows 1 to 16)

Apply IMPLEMENTATION.md C1 inside the loader body and nothing else (C2, C5).
For the memoizing loaders (rows 13, 14, 15) the suppression wraps the
module-body execution inside the first-use branch; the cache behavior stays
as it is. A module that does not yet import the standard-library `sys`
module gains that import.

`tests/test_merge_ci_wait.py` sets the flag True at module level and never
restores it. That line stays (IMPLEMENTATION.md D4). Its loader still
records and restores the value it finds, so the loader is correct on its own
and does not depend on that line (FR3).

The "during tests" rows are the ones a whole run hides today: by the time
they run, the flag leaked by `tests/test_merge_ci_wait.py` is already True.
Their run-alone check (AC-5) is what shows them fixed.

### Probe test module

Responsibilities, following IMPLEMENTATION.md C3 and C4:

1. Hold the 17-row site table above as data: test module file name, loader
   name, redirect kind, redirect attribute names.
2. Once per test class, load each target test module by file path under a
   private name, with the flag forced True during the load and restored
   afterwards (this also keeps the module-level assignment of
   `tests/test_merge_ci_wait.py` from leaking out of the load); record the
   recursive listing of `em-workflow/scripts/` first.
3. For each row, each starting value (False, True) and each probe body (one
   that records the flag, one that raises with the flag value in its
   message): write the probe into a fresh test-owned temporary directory, set
   the starting value, apply the row's redirect for one call (for row 16 as
   a plain string path), call the loader, and record O1–O3; then check O4 on
   the probe's directory.
4. Report each observation per row (subtests or separate methods), so a
   failure names the row.
5. Check the table has 17 rows and every loader and redirect attribute
   exists on its loaded target; check the `em-workflow/scripts/` listing is
   unchanged after the class's tests.

## Test Notes

- AC-1 to AC-4 are unit tests in the new probe module. Write it first: before
  the loader edits, AC-1 fails for the starting value False on rows 1 to 16
  (row 17 already passes), and O4 fails too (the probe's cache appears in the
  probe's own temporary directory, never under `em-workflow/`).
- Loading `tests/test_merge_ci_wait.py` as a target sets the flag True inside
  its body; the probe module's own restore after the load is what keeps that
  from reaching the observations.
- AC-5 is checked by execution: run each module alone, one after another
  (never in parallel), and look at `em-workflow/scripts/` after each run.
  Before the first run, and after any red-phase run, make sure
  `em-workflow/scripts/__pycache__` is absent in the task worktree (move a
  leftover to the trash). Record the commands and results in the report.
- AC-6 and AC-7 are checked by the full suite plus a review of the diff.
- If a target module needs to be present in the interpreter's module
  registry while its body runs, register it under its private name for the
  duration of that load only.
