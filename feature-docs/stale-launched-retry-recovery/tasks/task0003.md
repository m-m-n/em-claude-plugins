## Design

### What each site must say

The reason-code spellings, the evidence order and the CLI-flag policy are
IMPLEMENTATION.md's (Shared Components SC6, decision D-A, D-B, and the
Conventions section's documentation-wording rule). Documentation states the
evidence that must be proven and the reason codes verbatim; it never spells
CLI flag names, so nothing here couples to the decision layer's argument
surface.

1. **I.2.b Orphan recovery block** — the owning section for the evidence
   order and every reason code. It gains: that the same-session residual is
   no longer necessarily terminal when the orchestrator can supply explicit
   evidence; the two conjuncts that alone prove same-session death (explicit
   harness evidence that THIS launch's execution terminated, and an explicit
   not-running/absent stop-tool result for the SAME bound agent identity);
   the statement that no elapsed-time threshold and no transcript or
   output-file idle interval substitutes for either conjunct; the six new
   codes, each paired with the condition whose failure emits it, in the fixed
   order — `task-artifacts-missing`, then `agent-identity-unproven`, then
   `agent-termination-unproven` / `agent-still-live`, then
   `stop-result-unproven`, then `launch-changed`; that the recorded session
   identity is never the stop target; and that the helper is invoked with
   reason `stale-launched` on this branch. The existing sentences describing
   the `orphaned` invocation, the marker emission, the D2 precedence, the
   existing nine codes and the sole-append statement are preserved verbatim.
2. **Stale-`launched` caveat** — today it enumerates four gap-closing
   mechanisms and explicitly does not cover a stop that delivers neither a
   subagent-stop nor a stop-tool event. It gains the fifth mechanism: the
   extended same-session branch of the same I.2.b orphan-recovery attempt,
   covering exactly that stop, still inside the one narrowly-scoped writer
   exception and adding no writer. The existing sentence naming the
   orphan-recovery attempt as the sole exception is preserved verbatim.
3. **Abort-phase bullet (FR12)** — the external-cause `failed_kind` value is
   attributed when the failing task's failure originates from a journal
   `failed` event whose reason is `orphaned` OR the new reason value. The
   batch-mode second-failure override paragraph is NOT touched: it keeps
   writing the decision-required value unconditionally and applies to the new
   value identically.
4. **Writer-set paragraph** — the writer set string itself is unchanged
   (`merge-task.sh`, `queue_launch_guard.py`, `queue_failure_net.py`,
   `queue_taskstop_net.py`, plus the one `journal-append-failed.py`
   exception). The paragraph states that the helper appends `failed` with
   reason `orphaned` or the new reason value, both additive values of the
   existing `failed` reason field, and that no writer is added.

### Editing discipline (D-G)

Additive editing. Existing pinned sentences are extended at their end or
followed by new sentences, never rewritten in place, so the verbatim phrases
other modules already pin stay byte-identical. After editing, run the whole
suite: a broken pin means the edit was not additive enough, and the first
remedy is to restructure the edit, not to re-anchor the pin.

## Test Notes

- TS8 maps to AC-1 through AC-5. Follow the pattern already used by the
  documentation-pinning modules in `tests/`: module-level constants for each
  literal, read once by a positive test and once by a negative-proof test, so
  no literal is spelled twice.
- Order assertions are done by comparing index positions of the six code
  literals inside the block's own text slice, not across the whole file.
- The writer-set "unchanged" assertion is best expressed as the exact set of
  writer names present in that paragraph, so both an addition and a removal
  fail it.
- The abort-phase byte-identity assertion for the batch paragraph reuses the
  existing pre-change literal rather than introducing a second copy: read the
  paragraph from the file and compare against the constant this module
  declares.
- Red-first is available for every criterion: each assertion fails against
  the current, unedited documents.
