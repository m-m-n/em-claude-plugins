# Task Plan: task0002 — decision layer: the evidence-gated same-session recovery chain

## Goal

`em-workflow/scripts/recover-orphaned-task.py` gains an opt-in chain that,
when the caller supplies explicit termination evidence, evaluates seven
conditions in a fixed order and — only when every one holds — invokes the
journal helper once with reason `stale-launched` and the launch identity,
while an invocation supplying no evidence behaves exactly as it does today.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR9, FR13, NFR1, NFR3, NFR5, NFR6

## Scope

### Files to Create

- `tests/test_stale_launched_recovery_chain.py` — the new chain: the
  recovered path against an injected stub helper, one case per unmet
  condition, the insufficient-evidence pins, and the stop-target security
  pin.

### Files to Modify

- `em-workflow/scripts/recover-orphaned-task.py` — six new residual reason
  codes; seven new optional evidence inputs; the opt-in chain; helper
  invocation parameterised by reason and launch identity; module docstring
  updated to describe both chains and the full reason-code set.
- `tests/test_recover_orphaned_task.py` — extend: the legacy no-evidence
  invocation keeps its pinned outcomes (including the `same-session` case and
  the payload-shape assertion), and the helper-invocation tests account for
  the reason now being a parameter of the invocation.

## Design

### Contract

The CLI surface, the evidence-input table and their closed token
vocabularies, the agent-identity binding rule, and the helper's outcome
vocabulary are IMPLEMENTATION.md's Shared Components (SC3′, SC6, the
Evidence inputs table, the Agent-identity binding rule) and its decisions D-A
through D-F. The journal helper is built in parallel by another task against
that same text — do not read or assume anything about its implementation
beyond that contract, and do not modify it.

### Chain entry (D-A)

The new chain runs when at least one of the seven evidence inputs is present.
When none is present, today's pipeline runs unchanged end to end, including
its `same-session` outcome. Recorded-identity equality is not an entry
condition.

### Fixed evidence order (FR3)

Evaluated in this order; the FIRST unmet condition ends the run with the
named outcome and nothing further is read, assembled, opened or invoked.

1. **Artifacts and journal state.** Both artifact-presence inputs read `yes`
   (anything else — `no`, absent, unrecognised — is `task-artifacts-missing`,
   decided before any agent index read, any path assembly and any file open).
   Then the task's last journal event: a terminal event is `noop_terminal`;
   any event other than `launched` is `journal-not-launched`.
2. **Agent index entry.** The task's newest entry exists (else
   `no-agent-entry`) and satisfies the existing launch-binding rule against
   the last `launched` event (else `stale-agent-entry`). Both the selection
   rule and the binding rule are the ones already implemented; reuse them
   rather than restating them.
3. **Session identity.** The entry carries a session identity (else
   `no-session-id`), it passes the existing format-validation rule (else
   `invalid-session-id`), and the current session's identity and start
   resolve by the existing resolution rule (else
   `current-session-unknown`).
4. **Bound stop target.** The binding rule in IMPLEMENTATION.md holds (else
   `agent-identity-unproven`). The recorded session identity is never read as
   a candidate and never becomes the stop target on any path.
5. **Harness termination of THIS launch.** The termination token is
   `terminated` (the `running` token is `agent-still-live`; every other
   value, including the explicitly-insufficient ones and an absent input, is
   `agent-termination-unproven`).
6. **Stop result for the SAME bound target.** The stop-result token is
   `not-running` AND the stop-result target equals the bound identity (else
   `stop-result-unproven`).
7. **In-lock launch identity.** The helper is invoked once with the task id,
   reason `stale-launched`, and the raw `at` of the last `launched` event as
   the launch identity. Its outcomes map: `appended` → `recovered`;
   `noop_terminal` → `noop_terminal`; `launch_changed` → `residual` with
   reason `launch-changed`.

No elapsed-time threshold and no idle-interval input exists anywhere in this
chain. Nothing in the chain derives a duration from any timestamp for the
purpose of proving termination.

### Reason-code set (FR4)

The existing ten module-level codes keep their spelling, their values and
their emission conditions. Six are added:
`task-artifacts-missing`, `agent-identity-unproven`,
`agent-termination-unproven`, `agent-still-live`, `stop-result-unproven`,
`launch-changed`.

### Helper invocation (NFR3, D-E)

The helper stays a child process invoked at most once, at the sibling path by
default and overridable by the existing override input. The reason value and
the launch-identity argument become parameters of that invocation: the legacy
chain passes `orphaned` and no launch identity; the new chain passes
`stale-launched` and the launch identity. A non-zero helper exit, unparsable
helper stdout or an unrecognised helper outcome stays a non-zero exit of this
script and is never reported as `recovered`. This script writes nothing
itself.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR2, FR3, NFR3): with all seven evidence inputs supplied and
      proving, against a fixture whose journal last event is `launched`,
      whose newest agent index entry is launch-bound and records the same
      identity as the supplied current session, and with a stub helper
      injected, stdout is one JSON line reading outcome `recovered`, task the
      task id, reason the empty string; exit code is 0; and the stub is
      invoked exactly once with the task id, reason `stale-launched`, the
      journal path, and the launch identity equal to the last `launched`
      event's raw `at`.
- [ ] AC-2 (FR3, FR4, FR9): one case per unmet condition, in the order above,
      each asserting the exact reason string and a byte-identical journal:
      terminal journal → `noop_terminal`; non-`launched` journal event →
      `journal-not-launched`; worktree input `no` → `task-artifacts-missing`;
      branch input `no` → `task-artifacts-missing`; no agent entry →
      `no-agent-entry`; entry outside the binding tolerance →
      `stale-agent-entry`; absent/empty identity → `no-session-id`;
      malformed identity → `invalid-session-id`; unresolvable current session
      → `current-session-unknown`; ambiguous or mismatched identity binding →
      `agent-identity-unproven`; unproven termination →
      `agent-termination-unproven`; `running` → `agent-still-live`; stop
      result not proving → `stop-result-unproven`; helper reporting the
      in-lock mismatch → `launch-changed`. No helper invocation occurs in any
      case before step 7.
- [ ] AC-3 (FR2, NFR1): the three insufficient-evidence tokens
      (launch-acceptance, generic error, output-idle) each independently
      yield `agent-termination-unproven`; and a fixture whose only
      distinguishing feature is a very old `launched` timestamp still yields
      `agent-termination-unproven`, never `recovered` — no elapsed-time
      threshold exists in the chain.
- [ ] AC-4 (FR2, FR3, security): a fixture whose recorded session identity is
      byte-equal to a harness agent-identifier candidate yields
      `agent-identity-unproven` and derives no stop target from that field;
      pinned at source level (the session-identity field is never read into
      the candidate set) as well as behaviour level.
- [ ] AC-5 (FR5, NFR5, FR1): an invocation supplying none of the seven new
      inputs, against a task whose recorded identity equals the current one,
      still reports residual `same-session` with a byte-identical journal;
      and every other pre-existing residual reason code keeps its current
      emission condition — proven by the pre-existing tests in
      `tests/test_recover_orphaned_task.py` continuing to pass, including the
      identity-equality case and the payload-shape assertion.
- [ ] AC-6 (FR7, FR9): the artifact check decides before any agent index read
      or any file open — proven by a case whose agent index path does not
      exist at all and whose artifact input reads `no`, still yielding
      `task-artifacts-missing`.
- [ ] AC-7 (FR9, NFR3): every residual and every `noop_terminal` in AC-2 and
      AC-3 leaves the journal byte-for-byte identical and creates neither the
      file nor its parent directory; a non-zero exit is likewise never
      accompanied by a write.
- [ ] AC-8 (NFR6): the script imports only the standard library, and both
      test modules import no third-party package.

## Test Notes

- TS1 maps to AC-1, TS2 to AC-2, TS3 to AC-3, TS4 to AC-4; AC-5 is the FR5
  half of TS2.
- The stub-helper injection pattern already exists in
  `tests/test_recover_orphaned_task.py` (the existing default-helper wiring
  case) — reuse it, and have the stub record its own argument vector so AC-1
  can assert the argument shape without the real helper being present in this
  worktree. The real pair is exercised after merge, as an integrated
  verification item (IMPLEMENTATION.md D-F).
- `launch-changed` is reachable in this task's tests only through a stub that
  reports the mismatch outcome; that is the intended seam, and it is what
  proves the mapping.
- Fixtures live in per-test temporary directories; the transcripts directory
  input is always supplied explicitly so no test can reach real `~/.claude`
  state.
- TDD-awkward: the seven-input surface makes each negative case a one-value
  mutation of one shared proving fixture — build that fixture helper first,
  then drive every AC-2 case from it, so a case that passes for the wrong
  reason is visible.

## Out of Scope

- Any change to `em-workflow/scripts/journal-append-failed.py`, to any hook,
  to any documentation file, or to any version field.
- Any time-based or idle-based proxy for termination.
- Re-deriving worktree or branch existence inside this script.
- Lifting the new chain out of the same-session branch. FR3 scopes it to that
  branch, which is reached only under `recorded_session_id == current_id`
  (`em-workflow/scripts/recover-orphaned-task.py:564-565`); that position is
  what guarantees the chain never runs for another session's launch
  (IMPLEMENTATION.md D-A).
- Changing any existing residual reason code's spelling or emission
  condition.
