# Task Plan: task0001 — Space/tab-only trim on the command path (preflight check 7, hook entry, cd prefix, declared commands)

## Goal

merge-preflight.py check 7 and the bash_guard.py hook judge an incoming
command value by the C1 approval trim rule (IMPLEMENTATION.md), so a value
padded with any whitespace other than spaces and tabs is never approved, and
the two scripts still agree on every value.

## Design

Cross-task contracts used here: C1 (approval trim rule), C2 (bash_guard.py
trim helpers, with their fixed names and placement), C3 (approved set,
consumer rule) and decisions D1-D5 in IMPLEMENTATION.md. They are not
restated.

### merge-preflight.py

- `collect_commands`: a string value is skipped only when it is C1-empty. Any
  other string value is collected; a non-matchable one is collected as not
  approvable. The existing rules stay: invalid component name, non-string
  value and a raw value holding LF or CR make the entry not approvable.
- `check_approval`: an entry is approved only when it is approvable, its C1
  Trim is matchable, and that trimmed form is a member of the set read
  through `bash_guard.py --list`. Every other entry is named in the
  `commands_unapproved` detail as today. The `command` in the `proceed`
  output stays the untrimmed original.
- Module docstring, "Approval rule (check 7)" paragraph: replace the
  description of the full whitespace strip with the C1 rule — only spaces and
  tabs are removed, and a value with any other whitespace at either end is
  not approved. The comment inside `check_approval` says the same.

### bash_guard.py

- Add the two C2 helpers at the C2 placement.
- `hook_main`: a command that is C1-empty gives no decision (as today). The
  command is replaced by its C1 Trim only; LF and every other non-space/tab
  character stay. A non-matchable command is never allowed — neither by the
  exact-match branch nor by the cd prefix branch. It still reaches the
  refusal-pattern deny and the unapproved-declared deny in their existing
  order; when neither applies it gives no decision.
- `is_cd_prefixed_approved` and `cd_remainder_excluded`: the remainder is
  trimmed by C1 Trim only. A non-matchable remainder is never a cd prefix
  candidate, and `cd_remainder_excluded` reports it as excluded. The
  `CD_PREFIX_RE` separators are unchanged.
- `declared_commands`: the key/value separator and the trailing-blank class
  of `COMMAND_KEY_RE` accept spaces and tabs only, and the extracted value is
  trimmed by C1 Trim only. A non-matchable value stays in the declared set,
  so the hook denies it as unapproved.
- Module docstring: the hook-mode summary states that the command is compared
  after removing surrounding spaces and tabs only and that a command with any
  other whitespace at either end is never allowed; the cd prefix "approval"
  bullet (currently "with surrounding blanks removed") states the same for
  the remainder.
- `approved_for`, `read_stdin_commands` and the CLI modes are not changed by
  this task (task0002 owns them, C3 consumer rule).

### Processing flow (hook entry)

1. Not a Bash call, unparseable input, non-string or C1-empty command: no
   decision.
2. Trim the command by C1 Trim.
3. Collect the declared set and the approved set as today.
4. Workflow relevance and the refusal-pattern deny as today.
5. Exact-match allow and cd prefix allow only when the command is matchable.
6. Unapproved-declared deny as today; otherwise no decision.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR2, TM-1): With `/usr/bin/true` approved, a `test_command`
  carrying U+00A0, U+000B or U+000C before, after or on both sides of it —
  alone and mixed with spaces or tabs — makes merge-preflight.py stop with
  `commands_unapproved` naming `main.test_command`. Reproducing the attack
  scenario (`test_command` = U+00A0 followed by `/usr/bin/true`, and an
  executable file at the work-tree-relative path U+00A0 + `/usr/bin/true`)
  also stops with `commands_unapproved`.
- [ ] AC-2 (FR2, FR3, TM-2): A `test_command` made only of U+00A0 is not
  skipped and stops with `commands_unapproved`; one made only of spaces and
  tabs is still skipped; a raw value holding LF or CR still stops; a value
  approved after the space/tab trim proceeds and its `command` in the output
  is the untrimmed original.
- [ ] AC-3 (FR1, FR4, FR8, TM-3, TM-5): With `/usr/bin/true` approved, the
  hook never allows a command carrying U+00A0, U+000B or U+000C before, after
  or on both sides of it. When the same value is declared as a `*_command` in
  a working-tree `feature-docs/*/workflow.yaml` the hook denies it as
  unapproved; when it is not declared the hook gives no decision. The attack
  scenario reproduced through the hook gets no allow. A command that is empty
  after the space/tab trim gives no decision.
- [ ] AC-4 (FR4, FR5, TM-3, TM-4): An approved string followed by a trailing
  LF, or by a backslash and LF, is not allowed, either as a standalone command
  or as the remainder of the cd prefix form. In the cd prefix form, a
  remainder with U+00A0, U+000B or U+000C before or after the approved string
  is not allowed. The case "surrounding whitespace on the command" in
  `tests/test_bash_guard_cd_prefix.py` and
  `test_ac2_surrounding_blanks_and_a_trailing_line_feed_allow` in
  `tests/test_bash_guard_cd_prefix_operators.py` expect a decision other than
  ALLOW.
- [ ] AC-5 (FR2, FR4): In
  `test_fr4_ac3_preflight_agrees_with_bash_guards_own_approval_decision`, the
  form-feed-and-vertical-tab case and the no-break-space case are labelled and
  asserted as not approved by both merge-preflight.py and the hook; the test
  still asserts agreement on every case and still exercises both verdicts.
- [ ] AC-6 (FR1): Spaces and tabs alone around a command still approve it in
  merge-preflight.py, in the hook's exact match and in the cd prefix form (the
  existing space/tab cases keep passing). U+0085, U+2000, U+3000 or U+001F
  before or after the command is not approved by merge-preflight.py nor
  allowed by the hook. `make<U+00A0>test` does not match an approved
  `make test` in either script.
- [ ] AC-7 (FR9, NFR1, NFR2, NFR3): The bash_guard.py module docstring and
  the merge-preflight.py module docstring and `check_approval` comment state
  the space/tab-only trim and the non-approval of other surrounding
  whitespace, and no longer describe the full strip. bash_guard.py imports
  standard-library modules only and contains no substring `status`. New tests
  use unittest only and isolate the store with `EM_WORKFLOW_APPROVALS`.
  `python3 -m unittest discover -s tests` passes.
