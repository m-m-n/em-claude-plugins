# Task Plan: task0003 — Space/tab-only trim in command-execution-protocol.md

## Goal

`em-workflow/references/command-execution-protocol.md` states the C1 approval
trim rule (IMPLEMENTATION.md) wherever it describes trimming: only spaces and
tabs are removed, and a value with any other whitespace at either end is not
approved.

## Requirements

FR9, NFR3, NFR4

## Scope

### Files to Create
- `tests/test_approval_trim_docs.py` — document test for the protocol wording this task changes

### Files to Modify
- `em-workflow/references/command-execution-protocol.md` — the three trim statements named in SPEC.md FR9

## Design

Cross-task contracts used here: C1 (approval trim rule) and D4
(documentation ownership) in IMPLEMENTATION.md. The document states C1 in
prose; it does not restate the per-path table.

Statements to change (all in the protocol document):

1. Approval gate, step 1 — currently "Trim surrounding whitespace; skip
   empty". New content: only spaces and tabs are removed from both ends; a
   value empty after that is skipped; a value that still has any other
   whitespace character at either end is never approved on any path
   (bash_guard.py and merge-preflight.py refuse it and `--record` refuses an
   input that carries it).
2. "Verbatim execution rule", first sentence — currently "(after trimming)".
   New content: the comparison is exact after removing surrounding spaces and
   tabs only, and a command with any other surrounding whitespace is never
   allowed.
3. Same section, cd prefix condition on the remainder — currently
   "(surrounding whitespace aside)". New content: surrounding spaces and tabs
   aside; any other whitespace at either end of the remainder excludes the
   cd prefix allow.

Every phrase that `tests/test_cd_prefix_operator_exclusion_docs.py` pins
stays as it is; the headings of the document do not change.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR9): The approval gate's step 1 states that only spaces and tabs
  are removed from both ends, that a value empty after that is skipped, and
  that a value with any other whitespace at either end is never approved.
- [ ] AC-2 (FR9): The "Verbatim execution rule" section states the
  space/tab-only trim for the exact-string comparison and for the cd prefix
  remainder, and that other surrounding whitespace is never allowed. The
  phrases "Trim surrounding whitespace; skip empty", "(after trimming)" and
  "(surrounding whitespace aside)" no longer appear in the document.
- [ ] AC-3 (FR9, NFR3): A new document test checks AC-1 and AC-2 by locating
  text by heading and asserting stable phrases on whitespace-normalized text,
  never by line number, using the standard library only.
  `tests/test_cd_prefix_operator_exclusion_docs.py` passes unchanged, and
  `python3 -m unittest discover -s tests` passes.

## Test Notes
