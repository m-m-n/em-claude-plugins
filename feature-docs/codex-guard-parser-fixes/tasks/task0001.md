## Goal

hidden behind shell `-c` bundles, `--` / `-`, and shell `-h` / `-V`. They must

### Rules for the whole task

- **Indeterminate means silent**: when the parser meets a construct it cannot
  follow with certainty, the whole judgment ends as `silent` (no output,
  exit 0). It never guesses towards `deny` (NFR1). The verdict vocabulary is
  defined in IMPLEMENTATION.md Conventions.
- **Two copies, one change**: edit one copy, then make the other copy
  byte-identical before every commit, so both copies change in the same
  commit (FR6).
- **Static constraints**: no import outside the standard library, and no
  access to files, network or child processes. The verdict depends only on
  the command string, never on the working directory or the environment
  (NFR2, enforced by the existing static-constraint tests).

### FR1 — shell `-c` is a flag that takes no value

Location hint: the shell `-c` handling (around line 517). This applies only
to the shell family: bash, sh, zsh, dash, ksh.

Option reading, left to right, after the shell name:

1. A short-option bundle (one `-` followed by letters) is read one letter at
   a time. `c` turns on command-string mode and takes no value. `i` anywhere
   in the bundle makes the launch interactive, so the verdict is `deny`.
   Each `o` / `O` letter takes the next word as its value; that word is not
   an operand.
2. The long options `--rcfile` and `--init-file` take the next word as their
   value. Other long options keep their current handling, including the
   information long options.
3. Separate later option words (`-i`, `-x`, `-o pipefail`, and so on) before
   the first operand are read under the same rules. So an `i` in any of them
   is also `deny`.
4. `--` or a lone `-` ends option reading. The word after it is the first
   operand.
5. In command-string mode with a first operand, that operand is judged once,
   as a command string (one level only, A4), and it inherits the outer
   command's stdin connection. Words after it are positional parameters and
   are never read as options (A3).
6. In command-string mode with no operand at all, the verdict is `silent`
   (A5).
7. Interpreters outside the shell family keep their current reading of
   `-c` / `-m` / `-e` (A2).

### FR2 — information short options are defined per interpreter

Location hint: `INFO_LETTERS` and its comments (around line 530).

- The single letter set shared by all interpreters is replaced by a
  per-interpreter definition. It follows the "Information short-option rule"
  in IMPLEMENTATION.md Shared Components.
- The shell family has no information short options. Shell `-h` / `-V` are
  then ordinary flags, and a shell launched with only these flags gets the
  existing no-operand interactive-launch judgment (`deny`).

### FR3 — command substitution inside double quotes is read as one chunk

Location hint: `_double_quoted` (around line 267).

1. Inside a double-quoted span, the reader takes each of these as one chunk,
   up to its matching close: `$(` ... `)`, including the arithmetic form
   `$((` ... `))`, and a backtick span.
2. Inside the chunk, the reader follows quoting (single quotes, double
   quotes, backslash escapes) and nested substitutions. A `"` or `)` that
   belongs to them closes neither the chunk nor the outer double quote.
3. The word that contains the chunk is dynamic. The chunk's contents are not
   judged (A1).
4. An unclosed chunk is indeterminate. So is any nesting whose close the
   reader cannot locate with certainty.
5. After the chunk, double-quote reading resumes. After the closing `"`,
   ordinary parsing resumes, so a launch outside the quotes is still judged.

### FR4 — groups inherit stdin connection

Location hint: the subshell parenthesis handling (around line 406).

1. A group is a subshell `( ... )` or a brace group `{ ...; }`. `{` and `}`
   delimit a group only when each is a standalone word at command position.
   A brace that is part of a larger word, such as `{a,b}`, is not a group
   delimiter (A9).
2. A group is connected when either condition holds:
   - it is the right-hand side of `|` or `|&`;
   - a stdin redirect follows its close: `<`, `<<`, `<<<`, `<&` or `0<`.
3. These never connect a group: other redirects (such as `2>` or `>`), and a
   pipe on the group's right.
4. A connected group passes its connection to every command inside it,
   nested groups included.
5. The redirects that decide connection come after the group's close. So the
   verdict for a command inside a group is settled only once the group's
   connection state is known.
6. A heredoc after a group's close has its body read as heredoc body, not as
   commands.
7. A launch with `-i` is denied even when its group is connected.
8. A group that cannot be read to its close (unclosed or unbalanced) is
   indeterminate.
9. `while` / `for` / `until` / `if` / `case` compound commands keep their
   current behaviour.

### FR5 — a pending pipe survives empty lines

Location hint: `_separator` (around line 212).

- After `|` or `|&`, while the right-hand command is still awaited, these
  keep the pending pipe connection: newlines, blank lines, comment-only
  lines, and an intervening heredoc body, as long as they yield only empty
  commands. The next non-empty command is the pipe's right-hand side.
- A newline after `&&` or `||` never creates a connection.
