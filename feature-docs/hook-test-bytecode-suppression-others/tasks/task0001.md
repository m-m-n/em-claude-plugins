# Task Plan: task0001 — Suppress bytecode in the five em-workflow hook loaders

## Goal

The five test modules that load hooks from `em-workflow/hooks/` into the test
process run each load inside a suppression window, so that running any one of
them alone leaves no `__pycache__` beneath `em-workflow/hooks/` or
`em-review/hooks/`.

## Requirements

FR1, FR2, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_queue_stop_guard.py` — loading site TestQueueStopGuardOwnershipAmbiguity._load_hook_module (loads queue_stop_guard.py); add regression tests
- `tests/test_queue_stop_guard_routeback_record.py` — loading site load_hook_module (loads queue_stop_guard.py); add regression tests
- `tests/test_failed_run_cleanup_guard.py` — loading site load_hook_module (loads failed-run-cleanup-guard.py, also reached through run_hook_in_process); add regression tests
- `tests/test_hooks_registration.py` — loading site load_hook_module (loads queue_launch_guard.py, queue_agent_index.py and queue_failure_net.py); add regression tests
- `tests/test_queue_failure_net_cross_hook.py` — loading site _load_module_from_path (loads queue_failure_net.py and queue_launch_guard.py); add regression tests

## Design

### Loading sites

Each loading site above applies the suppression window defined in
IMPLEMENTATION.md, Conventions, "Suppression window", around its module
execution step. Nothing else about the site changes: the same path is loaded,
under the same module name, and the same module object is returned.

Flow of one load:

1. Record the bytecode flag's current value V.
2. Turn the flag on.
3. Run the module execution step for the hook file.
4. Whether step 3 returned or raised, set the flag back to V.
5. If step 3 raised, let the exception propagate; otherwise return the module.

### In-process `main()` call (SPEC.md EC2)

`run_hook_in_process` in `tests/test_failed_run_cleanup_guard.py` loads the
hook through `load_hook_module` and then calls the hook's `main()` in the test
process. If the single-module run (AC-4) shows a `__pycache__` written by that
call, the same suppression window, with the same contract, also wraps the
`main()` call (IMPLEMENTATION.md, "Residual write sites", rule 1).

### Child-interpreter runs (SPEC.md A3)

If the single-module run of any of the five modules shows a `__pycache__`
written by a hook started as a child interpreter, that spawn site starts the
child with bytecode writing disabled and changes nothing else about the call
(IMPLEMENTATION.md, "Residual write sites", rule 2). Otherwise spawn sites are
left unchanged.

### Regression tests

One test class per module, added to that module, following IMPLEMENTATION.md,
Conventions, "Regression tests". Each class exercises the module's own loading
site with the flag's starting value set inside the test to off and to on, and
restores the process's original flag value afterwards.

### Version

No file under a plugin directory is modified by this task.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: In each of the five modules, with the bytecode flag's starting value set to off, the loading site runs the hook's module execution step with the flag on, so no bytecode file for the loaded hook is written beneath `em-workflow/hooks/`. (FR1, TS-3)
- [ ] AC-2: In each of the five modules, after the loading site returns, the bytecode flag equals the starting value set by the test, for both starting values off and on. (FR1, FR2, TS-3)
- [ ] AC-3: In each of the five modules, when the module execution step raises, the exception propagates out of the loading site and the bytecode flag equals the starting value set by the test afterwards. (SPEC.md EC1)
- [ ] AC-4: Starting with no `__pycache__` anywhere beneath `em-workflow/hooks/` and `em-review/hooks/`, running each of the five modules alone from the repository root with `python3 -m unittest tests.<module>` exits with code 0 and leaves no `__pycache__` anywhere beneath either directory, including what the in-process `main()` call of `run_hook_in_process` and any child-interpreter hook run in these modules would write. (FR1, FR2, TS-1)
- [ ] AC-5: `python3 -m unittest discover -s tests` exits with code 0; the five modules import nothing outside the Python standard library; no file under `em-workflow/` or `em-review/` is changed. (NFR1, NFR2, TS-2)

## Test Notes

- AC-1 to AC-3 are unit tests inside each module's new regression test class.
  AC-1 may be observed either as the flag being on at the module execution
  step or as no cache file appearing for the loaded hook; the starting value is
  always set inside the test, never inherited (the full-suite run leaves the
  flag on). AC-3 needs the module execution step to raise: make it raise inside
  the test (for example by substituting the execution step for the duration of
  the test) rather than by editing any hook file.
- AC-4 is a command-level check, not a unit test: run the five single-module
  commands one after another from a state with no `__pycache__` beneath either
  hook directory and inspect both directories after each run. This is the
  check that detects SPEC.md EC2 and A3; the Design sections above say what to
  change if it fails.
- AC-5 is the existing full suite plus a review of the modules' imports and of
  the diff's file list.
- Every regression test restores the process's original flag value whatever
  its outcome.
