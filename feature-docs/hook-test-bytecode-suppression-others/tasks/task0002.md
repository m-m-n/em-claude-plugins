# Task Plan: task0002 — Suppress bytecode in the two muse_guard loaders

## Goal

The two test modules that load `muse_guard.py` from both `em-workflow/hooks/`
and `em-review/hooks/` into the test process run each load inside a
suppression window, so that running either of them alone leaves no
`__pycache__` beneath `em-workflow/hooks/` or `em-review/hooks/`.

## Requirements

FR1, FR2, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `tests/test_muse_guard.py` — loading site _load_guard_module (loads muse_guard.py of em-workflow and of em-review); add regression tests
- `tests/test_consultation_harness_chain.py` — loading site _load_guard (loads muse_guard.py of em-workflow and of em-review); add regression tests

## Design

### Loading sites

Each loading site above applies the suppression window defined in
IMPLEMENTATION.md, Conventions, "Suppression window", around its module
execution step, for both plugins' `muse_guard.py`. Nothing else about the site
changes: the same path is loaded, under the same module name, and the same
module object is returned.

Flow of one load:

1. Record the bytecode flag's current value V.
2. Turn the flag on.
3. Run the module execution step for the hook file.
4. Whether step 3 returned or raised, set the flag back to V.
5. If step 3 raised, let the exception propagate; otherwise return the module.

### Child-interpreter runs (SPEC.md A3)

If the single-module run (AC-4) of either module shows a `__pycache__` written
by a hook started as a child interpreter, that spawn site starts the child
with bytecode writing disabled and changes nothing else about the call
(IMPLEMENTATION.md, "Residual write sites", rule 2). Otherwise spawn sites are
left unchanged. An in-process call made after a load returns that writes a
`__pycache__` is handled by rule 1 of the same section.

### Existing directory-guard test (SPEC.md EC4)

`test_neither_plugins_hooks_tests_directory_gained_a_file` in
`tests/test_muse_guard.py` inspects only `em-workflow/hooks/tests` and
`em-review/hooks/tests`. It keeps its behavior unchanged; the new regression
tests create no file in either of those directories. The hook-directory
`__pycache__` check is AC-4, not that test.

### Regression tests

One test class per module, added to that module, following IMPLEMENTATION.md,
Conventions, "Regression tests". Each class exercises the module's own loading
site for both plugins' `muse_guard.py`, with the flag's starting value set
inside the test to off and to on, and restores the process's original flag
value afterwards.

### Version

No file under a plugin directory is modified by this task.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: In both modules, for both `em-workflow/hooks/muse_guard.py` and `em-review/hooks/muse_guard.py`, with the bytecode flag's starting value set to off, the loading site runs the hook's module execution step with the flag on, so no bytecode file for the loaded hook is written beneath its hook directory. (FR1, TS-3)
- [ ] AC-2: In both modules, for both plugins' `muse_guard.py`, after the loading site returns, the bytecode flag equals the starting value set by the test, for both starting values off and on. (FR1, FR2, TS-3)
- [ ] AC-3: In both modules, when the module execution step raises, the exception propagates out of the loading site and the bytecode flag equals the starting value set by the test afterwards. (SPEC.md EC1)
- [ ] AC-4: Starting with no `__pycache__` anywhere beneath `em-workflow/hooks/` and `em-review/hooks/`, running each of the two modules alone from the repository root with `python3 -m unittest tests.<module>` exits with code 0 and leaves no `__pycache__` anywhere beneath either directory, including what any child-interpreter hook run in these modules would write. (FR1, FR2, TS-1)
- [ ] AC-5: `test_neither_plugins_hooks_tests_directory_gained_a_file` in `tests/test_muse_guard.py` still passes, and the new regression tests create no file in `em-workflow/hooks/tests` or `em-review/hooks/tests`. (SPEC.md EC4)
- [ ] AC-6: `python3 -m unittest discover -s tests` exits with code 0; the two modules import nothing outside the Python standard library; no file under `em-workflow/` or `em-review/` is changed. (NFR1, NFR2, TS-2)

## Test Notes

- AC-1 to AC-3 are unit tests inside each module's new regression test class.
  AC-1 may be observed either as the flag being on at the module execution
  step or as no cache file appearing for the loaded hook; the starting value is
  always set inside the test, never inherited (the full-suite run leaves the
  flag on). AC-3 needs the module execution step to raise: make it raise inside
  the test (for example by substituting the execution step for the duration of
  the test) rather than by editing any hook file.
- AC-4 is a command-level check, not a unit test: run the two single-module
  commands one after another from a state with no `__pycache__` beneath either
  hook directory and inspect both directories after each run. This is the
  check that detects SPEC.md A3; the Design sections above say what to change
  if it fails.
- AC-5 is the existing test plus a check that the new tests write nothing into
  those two directories.
- AC-6 is the existing full suite plus a review of the modules' imports and of
  the diff's file list.
- Every regression test restores the process's original flag value whatever
  its outcome.
