# Task Plan: task0001 — Rename-aware coverage backed by the document diff

## Goal

The validator accepts a covered_by_existing ID through a declared scenario rename only when the baseline and post-change VERIFICATION.md confirm that rename. It never accepts the old ID that a rename removed. When the diff is available, it rejects every covered ID that is missing from the post-change VERIFICATION.md.

## Requirements

## Design

### Where the change sits
The change goes in the rework-index check of rework-planner worker-result validation, where covered_by_existing IDs are accepted. It implements IMPLEMENTATION.md D2: the definitions, the four-row decision order, unreadable-file handling and message distinction. Every rejection uses code `rework-index`. No CLI option and no envelope field is added.

### Scenario-ID sets
- Post set: from `{feature-dir}/VERIFICATION.md`. Baseline set: from `{baseline-dir}/VERIFICATION.md`, empty when that file is absent.
- If the validator already derives a scenario-ID set from a VERIFICATION.md (for its cross-artifact checks), reuse that derivation so both checks agree. Otherwise, the defined IDs are the scenario IDs in the first cell of the document's table rows. Both forms count (TS-n, TSn), matched as whole tokens and compared as literal strings.

### Decision flow per covered ID
1. Collect the declared pairs: well-formed `from`/`to` string pairs under payload.doc_corrections[].scenario_renames.
2. Decide whether the diff is available. If it is, build the post set and the baseline set. A file that exists but cannot be read as text yields one `rework-index` error that names it.
3. For each covered_by_existing ID, apply the first matching row of D2 (from-of-pair, verification_index key, to-of-pair, other).
4. For a to-of-pair ID with the diff available, every declared pair with that `to` must meet all four conditions. The message names the first failed condition and the pair.

### Messages
Each of the following messages is distinguishable from the others, and every one carries code `rework-index`:
- (a) no rename declared (the existing message; wording unchanged)
- (b) diff unavailable: the rename cannot be confirmed because the document diff is unavailable. It names what is missing: `--feature-dir`, `--baseline-dir`, or feature-dir's VERIFICATION.md.
- (c) declared rename not confirmed: names the failed condition
- (d) the ID is the old ID of a declared rename
- (e) the ID is absent from the post-change VERIFICATION.md
- (f) a VERIFICATION.md cannot be read

### Fixture runner
`TestFixtures._run` passes `{fixture}/feature-dir` as `--feature-dir` when that directory exists, and `{fixture}/baseline-dir` as `--baseline-dir` when that one exists, independently. A fixture with neither runs exactly as before.

### Fixtures
Every fixture below is derived from `valid-mixed-round-renamed-scenario-declared`, is placed next to it and follows its internal layout. Each new invalid- fixture follows the single-defect convention (IMPLEMENTATION.md Conventions).

| Fixture | Change from the source fixture | Expected |
|---|---|---|
| `valid-mixed-round-renamed-scenario-declared` (existing) | Add `feature-dir/VERIFICATION.md`, which defines TS-3 and every other covered_by_existing ID of the fixture but not TS3. Add `baseline-dir/VERIFICATION.md`, which defines TS3. | accepted, exit 0 (TS-6) |
| `invalid-mixed-round-rename-to-missing` | The declared rename's `to`, and the matching covered ID, become an ID that the post-change VERIFICATION.md does not define (for example TS-9999). Supporting data is adjusted so that this is the only defect. | `rework-index`, exit 1 (TS-1) |
| `invalid-mixed-round-rename-without-diff` | No `feature-dir/` and no `baseline-dir/` | `rework-index` with message (b), exit 1 (TS-4) |
| `invalid-mixed-round-rename-from-covered` | TS3 (the declared `from`, a verification_index key) is added to covered_by_existing | `rework-index` with message (d), exit 1 (TS-7) |

TS-2, TS-3, TS-5, TS-8 and TS-9 can be either further fixtures or tests that build the directories in a standard-library temporary directory.

If another existing valid- fixture turns out to depend on rename-based acceptance, give it the same `feature-dir/` / `baseline-dir/` pair and report this as a plan deviation.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (TM-1, FR1) With the diff available, a covered_by_existing ID that is not a verification_index key is accepted through a declared pair only when all four conditions hold. Each failing condition yields `rework-index` and exit 1: `to` absent from the post set (TS-1), `from` still in the post set (TS-2), `from` absent from the baseline set (TS-3), `from` not a verification_index key. `valid-mixed-round-renamed-scenario-declared` with its new directories is accepted with exit 0 (TS-6).
- [ ] AC-2: (TM-1, FR1) When `--feature-dir` or `--baseline-dir` is missing, or feature-dir has no VERIFICATION.md, no ID is accepted through a rename: the result is `rework-index` and exit 1 (TS-4, TS-5). The message states that the diff is unavailable, names what is missing, and differs from the no-declaration message.
- [ ] AC-3: (TM-2, FR2) A declared pair's `from` listed in covered_by_existing is rejected with `rework-index` both with and without the diff, even when it is a verification_index key (TS-7).
- [ ] AC-4: (TM-2, FR2) With the diff available, any covered_by_existing ID absent from the post set is rejected with `rework-index`, including verification_index keys unrelated to any rename (TS-8). Without the directories, an unrelated verification_index key is accepted as before (TS-9).
- [ ] AC-5: (FR6) Fixtures `invalid-mixed-round-rename-to-missing`, `invalid-mixed-round-rename-without-diff` and `invalid-mixed-round-rename-from-covered` exist. The fixture tests reject each with exit 1 and `rework-index`.
- [ ] AC-6: (FR7, NFR2, NFR3) `TestFixtures._run` passes `feature-dir/` / `baseline-dir/` when present, and every existing valid- fixture is accepted with exit 0 (TS-20). The tests added or changed by this task import only the standard library and repository-local modules. `python3 -m unittest discover -s tests` passes from the repository root.
- [ ] AC-7: (TM-5, NFR1) None of the following raises an exception; each ends with exit 1 and JSON error details, never exit 2 (TS-21, rename/VERIFICATION.md part): scenario_renames that is not a list, a pair that is not a mapping, a non-string or missing `from` / `to`, a non-string covered_by_existing entry, a VERIFICATION.md path that is a directory, and a VERIFICATION.md whose bytes cannot be decoded as text.
