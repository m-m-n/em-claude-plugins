### rework-task-synthesis.md Section 12
- **Rename-aware coverage item** states:
  - when the diff is available: `--feature-dir` and `--baseline-dir` both given, and feature-dir has VERIFICATION.md
  - the four conditions a declared pair must meet before its `to` is accepted as covered_by_existing

  - that with no diff a rename is never accepted (fail-closed), and the rejection message differs from the no-declaration case

  - that an unreadable VERIFICATION.md is a rejection
- **Docs-only `append_rework` item** states:
  - that step_patches is exactly one entry, for the origin step, with set.status pending
  - where the origin comes from: the envelope's rework_source.type when present, otherwise verify or review, and that a malformed rework_source fails closed
  - that an implement entry is rejected whatever its status
  - that the check is structural, applies with and without `--dry-run-apply`, and applies to both `--kind worker-result` and `--kind workflow-patch`
  - which code each violation reports
