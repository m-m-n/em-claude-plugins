# Task Plan: task0003 — Reject overlapping tests_replace pairs

## Goal

The validator rejects a requirements_patch entry when its tests_replace from set and to set share an ID, so a sequential application can never lose a scenario reference.

## Requirements

FR4, FR6, FR7, NFR1, NFR2, NFR3

## Scope

### Files to Create
- `em-workflow/references/fixtures/**` — the new fixtures in Design → Fixtures

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — the tests_replace part of requirements_patch validation
- `tests/test_rework_docs_only_validator_rules.py` — new class TestTestsReplaceOverlap

## Design

### Check
This implements IMPLEMENTATION.md D4:
1. For each requirements_patch entry whose set.tests_replace is a list, take its pairs that are mappings.
2. From those pairs, collect the from set (string `from` values) and the to set (string `to` values).
3. A non-empty intersection yields one `requirements_patch` error. The error names the requirement ID and the overlapping IDs.

The check runs in the structural layer, so it runs with or without `--dry-run-apply`. It runs on every route that validates requirements_patch: the result's workflow_patch (`--kind worker-result`) and a patch given directly (`--kind workflow-patch`).

Pairs that share a `to` (TS1→X, TS2→X) do not overlap and stay under the existing "to already present" application rule. Values that are not strings never enter the sets, and malformed pairs stay with the existing shape checks. Nothing raises.

### Fixtures
Both fixtures are derived from `valid-docs-only-round`, are placed next to it and follow its internal layout. Each follows the single-defect convention (IMPLEMENTATION.md Conventions). Neither joins the fixture set that `test_ac6_no_fixture_uses_tests_replace` targets.

| Fixture | Change from the source fixture | Expected |
|---|---|---|
| `invalid-docs-only-round-tests-replace-chain` | One entry's tests_replace is TS-1→TS-2 and TS-2→TS-3 | `requirements_patch`, exit 1 (TS-17) |
| `invalid-docs-only-round-tests-replace-swap` | One entry's tests_replace is TS-1→TS-2 and TS-2→TS-1 | `requirements_patch`, exit 1 (TS-18) |

Adjust the supporting data so that the overlap is the only defect: tests_contains lists every `from`, the requirement's current tests contain them, and any rename declarations that the validator cross-checks against tests_replace agree with the pairs.

- [ ] AC-5: (FR6, FR7, NFR2, NFR3) The two fixtures in Design → Fixtures exist and are rejected with exit 1 and `requirements_patch`. `test_ac6_no_fixture_uses_tests_replace` still passes.
