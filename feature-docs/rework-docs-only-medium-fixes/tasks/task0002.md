# Task Plan: task0002 — Docs-only round step_patches check

## Goal

The validator accepts a docs-only round only when step_patches is exactly one origin-step entry with set.status pending. The origin step comes from the envelope's rework_source.type, or is verify / review when that is not available. Any step patch that targets implement is rejected, whatever its status.

## Requirements

FR3, FR6, FR7, NFR1, NFR2, NFR3

## Scope

### Files to Modify
- `em-workflow/scripts/validate-worker-output.py` — the docs-only round's step_patches check

## Design

### Applicability
The check applies to an `append_rework` patch whose tasks_patch.entries is absent or empty. It runs in the structural layer, so it runs with or without `--dry-run-apply`. It runs both on the result's workflow_patch (`--kind worker-result`) and on a patch given directly (`--kind workflow-patch`). It implements IMPLEMENTATION.md D3.

### Origin step resolution
1. If the validator holds the run's input envelope, read rework_source from it.
2. rework_source is a mapping with `type` exactly `review` or `verify`: the origin step is that value.
3. There is no envelope, rework_source is absent, or rework_source is a mapping without a `type` key: the origin step is either `verify` or `review`.
4. rework_source is present but not a mapping, or `type` is present with any other value (null, a non-string, another string): there is no origin step, and the origin match fails (fail-closed).

### Checks
The two checks are independent, and both may report on the same patch:
- **Implement entry**: each step_patches entry whose step_id is `implement` yields `docs-only-implement-reset`, whatever its set.status is. This extends the existing check to every status.
- **Shape**: `docs-only-step-patches` is reported once per patch unless step_patches is a list of exactly one mapping whose step_id matches the origin step and whose set.status is the string `pending`. The message names the violated condition: count, step_id against origin, or status.

Malformed shapes are rejected and never raise. These include step_patches that is not a list, an element that is not a mapping, a set that is not a mapping, a non-string step_id or status, a non-mapping rework_source, and a non-string type. An existing shape check or `docs-only-step-patches` can report them.

### Fixtures
Every fixture below is derived from `valid-docs-only-round`, is placed next to it and follows its internal layout. Each one follows the single-defect convention (IMPLEMENTATION.md Conventions) and has no `feature-dir/` or `baseline-dir/`.

| `invalid-docs-only-round-implement-completed` | step_patches is a single implement entry with set.status completed | `docs-only-implement-reset` (and `docs-only-step-patches`), exit 1 (TS-10) |
| `invalid-docs-only-round-no-step-patches` | step_patches is empty | `docs-only-step-patches`, exit 1 (TS-11) |

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (TM-3, FR3) In a docs-only round, every step patch that targets implement yields `docs-only-implement-reset` and exit 1, whatever its set.status is: completed (TS-10) and pending (the existing `invalid-docs-only-round-resets-implement`).
- [ ] AC-2: (TM-3, FR3) In a docs-only round, each of the following yields `docs-only-step-patches` and exit 1: empty step_patches (TS-11), two or more entries (TS-12), and a single origin entry whose set.status is not pending (TS-13).
- [ ] AC-3: (TM-3, FR3) With an envelope whose rework_source.type is verify, a single review entry with pending is rejected with `docs-only-step-patches`, and the reverse is rejected too (TS-14). A single entry whose step_id equals rework_source.type, with pending, is accepted.
- [ ] AC-4: (TM-3, FR3) Without an envelope rework_source.type, a single verify entry with pending is accepted and a single review entry with pending is accepted. Any other step_id is rejected (TS-15). A rework_source that is not a mapping, or a type that is null, a non-string or a string other than review / verify, is rejected with `docs-only-step-patches` (fail-closed).
- [ ] AC-5: (TM-3, FR3) Every rejection in AC-1 and AC-2 happens both with and without `--dry-run-apply`, and both through `--kind worker-result` and through `--kind workflow-patch` (TS-16).
- [ ] AC-6: (FR6, FR7, NFR2, NFR3) The five fixtures in Design → Fixtures exist and are rejected with exit 1 and their expected codes. `valid-docs-only-round` and every other existing valid- fixture are accepted with exit 0 (TS-20). The tests added or changed by this task import only the standard library and repository-local modules. `python3 -m unittest discover -s tests` passes from the repository root.
- [ ] AC-7: (TM-5, NFR1) None of the following raises an exception; each ends with exit 1 and JSON error details, never exit 2 (TS-21, rework_source/step_patches part): a non-mapping rework_source, a non-string type, step_patches that is not a list, a non-mapping step_patches element, a non-mapping set, and a non-string step_id or status.
