# Task Plan: task0003 — Record ID cleanup, range2 (e-p)

## Goal

Every `acceptance_tests.*.tests` element of every record in range2 (IMPLEMENTATION.md SC-4) is a canonical ID that passes SC-1, every removed or replaced ID is recorded in `test-docs/tests-yaml-test-id-resolution/id-mapping-range2.md` (SC-3), and the content of `test-docs/exit4-tip-argument/task0002.tests.yaml` that NFR3 fixes stays unchanged.

## Requirements

FR1, FR2, FR3, FR4, NFR3

## Scope

### Files to Create

- `test-docs/tests-yaml-test-id-resolution/id-mapping-range2.md` — the SC-3 ID mapping record for range2

### Files to Modify

- `test-docs/**/*.tests.yaml` — only the records in range2 (SC-4): their tests elements, plus FR2 suffix appends to existing red_reason values (SC-5)

## Design

Inputs: the range2 records at this task's base, the repository's git history, and the test modules under `tests/`.

### Flow per record in range2

1. Read the record's ACs and `tests` elements under SC-2. When a `tests` value uses a form outside SC-2, rewrite that `tests` value as a block list. Never rewrite anything outside `tests` values, apart from SC-5 appends.
2. Classify each element, taking the first case that applies:
   1. Already canonical, passes SC-1 and its loader result contains at least one test: keep it unchanged.
   2. A mechanical conversion yields an ID that passes SC-1: add the `tests.` prefix to an ID that resolves without it, or convert a `path::Class::method` or file-path form to dot form. Basis `normalized`.
   3. A non-unittest element (a runner script path, another runner's command, free-text description), handled per FR2: when an existing unittest verifies the same target, replace the element with that test's ID (basis `runner-replaced`); otherwise remove it and append its text per SC-5 (basis `non-unittest-removed`).
   4. Any other unresolved element, handled in FR3 order: (1) an abbreviation defined in the same record is expanded to the full name (basis `abbreviation`); (2) a rename or merge found in git history, through the history of the test module and of the test name, maps to the current ID (basis `renamed`, evidence the commit id); (3) a wildcard that identifies specific targets is expanded to every existing canonical ID it identifies (basis `wildcard`); (4) otherwise the element is deleted (basis `no-counterpart`).
3. A replacement keeps the element's position; an expansion is inserted at that position; a replacement already present in the same AC is not duplicated. An AC left without elements becomes `tests: []`, and its `red_confirmed` and `red_reason` stay unchanged apart from SC-5 appends (A4).
4. Write one SC-3 row per removed old-ID occurrence.
5. Verify the range with a scratch check outside the repository that implements SC-1 (including the at-least-one-test condition) and SC-2 (IMPLEMENTATION.md D3), and inspect the base-to-HEAD diff of the range. Then run the project test command to confirm that no failure absent from the baseline appeared.

### NFR3 record

`test-docs/exit4-tip-argument/task0002.tests.yaml` is pinned by `tests/test_exit4_ac2_test_id_drift.py`. Its number of IDs per AC, the one-line quoted form of its AC-2 `red_reason`, and its `red_confirmed: true` stay unchanged, and SC-5 is never applied to it. An element there may only be replaced one-for-one by a canonical ID that passes SC-1. When an element there would need deleting or expanding, leave the file unchanged and report the conflict instead.

### Constraints

- No record outside range2 changes (SC-4).
- `baseline_failures`, `final_failures`, `red_confirmed` and every other key stay unchanged; no `red_reason` key is added (FR4, SC-5).
- Tests under `tests/` are never renamed, added or deleted to make a record resolve.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR6): Every element of every `tests` list of every range2 record starts with `tests.`, is dot-separated, passes SC-1, and its loader result contains at least one test; the scratch check reports zero failures over range2.
- [ ] AC-2 (FR2): No range2 `tests` list contains a runner script path, free text, an abbreviation or a wildcard. Each removed non-unittest element is either replaced by an existing unittest ID that verifies the same target, or removed with its text appended per SC-5; an AC left without elements is `tests: []`.
- [ ] AC-3 (FR3, TM-4): `id-mapping-range2.md` follows SC-3. Its row count equals the number of removed old-ID occurrences in the base-to-HEAD diff of the range2 records; every row's File, AC and Old ID match one removed occurrence; every row's basis is an SC-3 category; every `renamed` row cites a commit id (TM-4).
- [ ] AC-4 (FR4, FR2, TM-5): In the base-to-HEAD diff of the range2 records, only `tests` elements change, plus SC-5 appends to existing `red_reason` values whose parsed pre-existing value is the exact prefix of the parsed new value. `red_confirmed`, `baseline_failures`, `final_failures` and every other key are unchanged, and no `red_reason` key is added (TM-5).
- [ ] AC-5 (SC-2): Every range2 record is read without any extraction error by the scratch check.
- [ ] AC-6 (SC-4): No record outside range2 and nothing under `tests/` changes, and the full test suite shows no failure absent from the baseline.
- [ ] AC-7 (NFR3): `test-docs/exit4-tip-argument/task0002.tests.yaml` keeps its number of IDs per AC, the one-line quoted form of its AC-2 `red_reason` and `red_confirmed: true`, and `tests.test_exit4_ac2_test_id_drift` passes with `tests/test_exit4_ac2_test_id_drift.py` unchanged.
