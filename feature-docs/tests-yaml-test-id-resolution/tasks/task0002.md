# Task Plan: task0002 — Record ID cleanup, range1 (0-9, a-d)

## Goal

Every `acceptance_tests.*.tests` element of every record in range1 (IMPLEMENTATION.md SC-4) is a canonical ID that passes SC-1, and every removed or replaced ID is recorded in `test-docs/tests-yaml-test-id-resolution/id-mapping-range1.md` (SC-3).

## Requirements

FR1, FR2, FR3, FR4

## Scope

### Files to Create

- `test-docs/tests-yaml-test-id-resolution/id-mapping-range1.md` — the SC-3 ID mapping record for range1

### Files to Modify

- `test-docs/**/*.tests.yaml` — only the records in range1 (SC-4): their tests elements, plus FR2 suffix appends to existing red_reason values (SC-5)

## Design

Inputs: the range1 records at this task's base, the repository's git history, and the test modules under `tests/`. Range1 includes the destructive-guard features, whose runner-script entries are the FR2 example: the tests in `tests/test_destructive_guard_command_substitution.py` wrap that runner.

### Flow per record in range1

1. Read the record's ACs and `tests` elements under SC-2. When a `tests` value uses a form outside SC-2, rewrite that `tests` value as a block list. Never rewrite anything outside `tests` values, apart from SC-5 appends.
2. Classify each element, taking the first case that applies:
   1. Already canonical, passes SC-1 and its loader result contains at least one test: keep it unchanged.
   2. A mechanical conversion yields an ID that passes SC-1: add the `tests.` prefix to an ID that resolves without it, or convert a `path::Class::method` or file-path form to dot form. Basis `normalized`.
   3. A non-unittest element (a runner script path, another runner's command, free-text description), handled per FR2: when an existing unittest verifies the same target, replace the element with that test's ID (basis `runner-replaced`); otherwise remove it and append its text per SC-5 (basis `non-unittest-removed`).
   4. Any other unresolved element, handled in FR3 order: (1) an abbreviation defined in the same record is expanded to the full name (basis `abbreviation`); (2) a rename or merge found in git history, through the history of the test module and of the test name, maps to the current ID (basis `renamed`, evidence the commit id); (3) a wildcard that identifies specific targets is expanded to every existing canonical ID it identifies (basis `wildcard`); (4) otherwise the element is deleted (basis `no-counterpart`).
3. A replacement keeps the element's position; an expansion is inserted at that position; a replacement already present in the same AC is not duplicated. An AC left without elements becomes `tests: []`, and its `red_confirmed` and `red_reason` stay unchanged apart from SC-5 appends (A4).
4. Write one SC-3 row per removed old-ID occurrence.
5. Verify the range with a scratch check outside the repository that implements SC-1 (including the at-least-one-test condition) and SC-2 (IMPLEMENTATION.md D3), and inspect the base-to-HEAD diff of the range. Then run the project test command to confirm that no failure absent from the baseline appeared.

### Constraints

- No record outside range1 changes (SC-4). No record under `test-docs/tests-yaml-test-id-resolution/` changes apart from this task's own record.
- `baseline_failures`, `final_failures`, `red_confirmed` and every other key stay unchanged; no `red_reason` key is added (FR4, SC-5).
- Tests under `tests/` are never renamed, added or deleted to make a record resolve.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR6): Every element of every `tests` list of every range1 record starts with `tests.`, is dot-separated, passes SC-1, and its loader result contains at least one test; the scratch check reports zero failures over range1.
- [ ] AC-2 (FR2): No range1 `tests` list contains a runner script path, free text, an abbreviation or a wildcard. Each removed non-unittest element is either replaced by an existing unittest ID that verifies the same target, or removed with its text appended per SC-5; an AC left without elements is `tests: []`.
- [ ] AC-3 (FR3, TM-4): `id-mapping-range1.md` follows SC-3. Its row count equals the number of removed old-ID occurrences in the base-to-HEAD diff of the range1 records; every row's File, AC and Old ID match one removed occurrence; every row's basis is an SC-3 category; every `renamed` row cites a commit id (TM-4).
- [ ] AC-4 (FR4, FR2, TM-5): In the base-to-HEAD diff of the range1 records, only `tests` elements change, plus SC-5 appends to existing `red_reason` values whose parsed pre-existing value is the exact prefix of the parsed new value. `red_confirmed`, `baseline_failures`, `final_failures` and every other key are unchanged, and no `red_reason` key is added (TM-5).
- [ ] AC-5 (SC-2): Every range1 record is read without any extraction error by the scratch check.
- [ ] AC-6 (SC-4): No record outside range1 and nothing under `tests/` changes, and the full test suite shows no failure absent from the baseline.

Every criterion is checked by the scratch check (outside the repository, never committed) plus inspection of the git diff. The integrated checks are TS-1, TS-2 and TS-3 in VERIFICATION.md.
