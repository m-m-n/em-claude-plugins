# Task Plan: task0006 — minor version bump of em-workflow and em-review

## Goal

em-workflow and em-review each get a minor version bump. Each plugin's
manifest and its marketplace entry carry the same new value.

## Requirements

NFR4, NFR5

## Scope

### Files to Create
- `tests/test_review_perspective_model_effort_version_bump.py` — asserts the bump and the agreement below.

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — raise the minor component of the version.
- `em-review/.claude-plugin/plugin.json` — raise the minor component of the version.
- `.claude-plugin/marketplace.json` — the em-workflow and em-review entries take the same version values as their manifests.

## Design

The repository is exempt from per-commit bumps (`.github/workflows/plugin-version-bump.yml`
raises the patch on push). This feature adds a capability, so the minor is
raised by hand, per `.claude/rules/core-plugin-version-bump.md` and
IMPLEMENTATION.md Conventions ("Version"). No other task touches a version.

- Bump rule for each of the two plugins: take the version at this task's base
  commit, raise its minor component by one, and set its patch component to 0.
  The major component is unchanged.
- In `.claude-plugin/marketplace.json`, the entries are found by `name`. Only
  the `version` of the `em-workflow` and `em-review` entries changes; the
  `plugin-dev` entry and every other field stay byte-identical.
- No other field of either `plugin.json` changes, so the existing tests that
  pin the non-version content of these files keep passing.

**Test module:**
- It records the two base-commit versions as its baselines, read from the
  base commit when the module is written.
- It asserts that each manifest version parses as three numeric components,
  has the same major, a minor one greater than the baseline's and a patch of
  0, and equals its marketplace entry's version.
- It compares by numeric components, never as strings, and carries negative
  proofs: a patch-only bump, a disagreeing marketplace entry, and a
  string-ordering trap.
