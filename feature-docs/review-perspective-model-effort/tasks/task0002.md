# Task Plan: task0002 — per-perspective model and effort in both registries

## Goal

Every codex entry in both `reviewers.yaml` files names the model and effort
from SPEC FR2's table. The header comments document the `effort` key, and the
tests pin the new values.

## Requirements

FR1, FR2, NFR4, NFR6

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/references/reviewers.yaml` — codex entries, header comment.
- `em-review/references/reviewers.yaml` — codex entries, header comment.
- `tests/test_codex_wrapper_model_flag.py` — registry half only (IMPLEMENTATION.md Shared Components C5).
- `tests/test_reviewers_primary_chains.py` — EXPECTED_CHAINS and the entry-shape check.
- `tests/test_contributor_tier_criteria.py` — EM_REVIEW_EXPECTED_CHAINS.

## Design

Implements IMPLEMENTATION.md Shared Components C1.

**Entry values (SPEC FR2):**

| perspective | model | effort |
|---|---|---|
| security | gpt-6.2-astra | xhigh |
| comprehensive | gpt-6.2-astra | high |
| architecture | gpt-6.2-astra | high |
| spec | gpt-6.2-sol | xhigh |
| performance | gpt-6.2-sol | xhigh |
| license | gpt-6.2-sol | low |

- em-workflow: all six perspectives.
- em-review: security, performance, architecture, spec. em-review has no
  license perspective, and its comprehensive `cross_validation` stays `[]`.
- Each codex entry is one line in flow form, keys in the order `harness`,
  `model`, `effort`. Every second entry (`{harness: litellm, model:
  muse-spark}`) is byte-for-byte unchanged. The perspective order, the chain
  order and the `version:` keys (em-workflow 3, em-review 2) are unchanged.

**Header comments (both files):**
- Add two statements:
  - a codex entry's `effort` is handed to the reviewer verbatim and becomes
    the wrapper's `--effort`;
  - a codex entry without `effort` runs at xhigh.
- Where the header describes chain entries as `{harness, model?}`, it now
  reads `{harness, model?, effort?}`.
- Keep every phrase `tests/test_reviewers_primary_chains.py`'s header tests
  require. Do not introduce text those tests forbid in the em-workflow header
  (`cross_validation`, `cross-model reviewer`, `em-workflow:reviewer`,
  `rate_limited`, `budget_exhausted`, `harness_unavailable`, `agreement
  scoring`).

**Tests:**
- `tests/test_codex_wrapper_model_flag.py`, registry half:
  - The chain-entry pattern reads an optional `effort` after `model`.
  - The codex-entry reader returns model and effort per perspective.
  - `SecurityModelPinTest` is replaced by a class that pins, per plugin, each
    codex entry's model and effort to the literal FR2 values above (TS-7).
  - A second check asserts that em-workflow and em-review give the same model
    and effort for every perspective present in both.
  - The module docstring's registry bullet is updated to match.
- `EXPECTED_CHAINS` and `EM_REVIEW_EXPECTED_CHAINS` give every codex entry its
  `model` and `effort`.
- `test_chain_entries_well_formed` asserts that every codex entry has a
  non-empty `model` and `effort`, and that a litellm entry has a `model` in
  `LITELLM_MODEL_NAMES` and no `effort`. The module docstring's AC-2 line
  follows suit.
- Each replaced pin carries a "Refreshed by
  feature-docs/review-perspective-model-effort/tasks/task0002.md (FR1, FR2)"
  comment (NFR6).
