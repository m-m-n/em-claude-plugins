# Task Plan: task0003 — codex-reviewer passes `effort`, protocol Inputs documents it

## Goal

Both codex-reviewer agents pass an orchestrator-supplied `effort` to the
wrapper as `--effort`. Both review protocols list `effort` among the reviewer
inputs. The pinned digests of the changed ranges are refreshed.

## Requirements

FR6, FR7, NFR4, NFR6

## Scope

### Files to Create
- `tests/test_codex_reviewer_effort_docs.py` — asserts the Step 5 and Inputs statements below for both plugins.

### Files to Modify
- `em-workflow/agents/codex-reviewer.md` — Step 5 prose.
- `em-review/agents/codex-reviewer.md` — Step 5 prose.
- `em-workflow/references/review-protocol.md` — the Inputs (all reviewers) section gains the effort item.
- `em-review/references/review-protocol.md` — the same.
- `tests/test_reviewer_roles_protocol.py` — refresh the Inputs digest in FROZEN_SECTIONS and CODEX_REVIEWER_STEPS_SHA256.
- `tests/test_reproduction_reviewer_instructions.py` — refresh the tail digest of both plugins in UNCHANGED_RANGE_SHA256.
- `tests/test_codex_reviewer_temp_file_isolation.py` — listed in SPEC TS-11; no edit expected (see Design, Pinned digests).

## Design

Implements IMPLEMENTATION.md Shared Components C2 (consumer side) and C4,
and decisions D1 and D4.

**codex-reviewer Step 5 (both copies, same new text):**
- Directly after the existing `model` paragraph, add a paragraph saying:
  - when the orchestrator supplies `effort`, add `--effort "<effort>"` right
    before `"$PROMPT"`, with the value passed verbatim;
  - without `effort`, add no `--effort`, and the wrapper uses its readonly
    default;
  - never choose an effort yourself;
  - when Codex rejects the effort, the existing Step 6 non-JSON rule applies
    and the run skips with `harness_unavailable`. Add no new Step 6 rule.
- When both are supplied, `-m "<model>"` and `--effort "<effort>"` both come
  before `"$PROMPT"`.
- The fenced wrapper lines, the heredoc paragraphs, the timeout sentence and
  every other Step stay byte-identical.

**review-protocol.md Inputs (both copies):**
- Directly after the `model` item, add an `effort` item saying:
  - only the codex reviewer receives it, and only when the registry entry
    names `effort`;
  - it is passed to the wrapper as `--effort <effort>`, verbatim;
  - when absent, readonly runs at xhigh;
  - the Claude reviewer and the litellm-harness reviewer never receive it.
- Nothing outside the Inputs section changes. In em-workflow, the
  harness-description bullets above it (the `PROTOCOL_BULLETS_SHA256` range)
  stay byte-identical (FR7).

**Pinned digests (NFR6):**
- `tests/test_reviewer_roles_protocol.py`:
  - The Inputs entry of `FROZEN_SECTIONS` and `CODEX_REVIEWER_STEPS_SHA256`
    are recomputed from the edited files.
  - Each gets a "Refreshed by
    feature-docs/review-perspective-model-effort/tasks/task0003.md" comment
    naming FR6 or FR7 and the added text.
  - `PROTOCOL_BULLETS_SHA256` is not touched and must still pass.
  - Adding `effort` to that module's documented input field names is allowed.
- `tests/test_reproduction_reviewer_instructions.py`:
  - Only the two `tail` digests change (Step 5 sits in that range). They get
    the same kind of comment.
  - The `head`, `step3`, `step4pre` and `step4rest` digests must pass
    unedited.
- `tests/test_codex_reviewer_temp_file_isolation.py` pins the Step 5
  invocation line, which stays byte-identical (C4), so no edit is expected.
  It is edited only if a pin it holds actually covers changed text.
