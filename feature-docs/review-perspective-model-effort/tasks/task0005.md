wrapper. The security-review-model skill describes setting effort through
the registry instead of a wrapper-fixed xhigh.

## Design

Describes IMPLEMENTATION.md Shared Components C1 and C3 for users. No other
task reads these files.

**Chain tables (FR9):**
- em-workflow's table puts every perspective on codex → litellm `muse-spark`;
  the performance / spec / architecture row changes from litellm-first to
  codex-first.
- em-review's table puts performance / spec / architecture on codex →
  litellm/muse-spark.
- Each README keeps its own existing notation: backticked `muse-spark` with
  "litellm " in em-workflow, `litellm/muse-spark` in em-review. Merging rows
  or keeping two rows is the implementer's choice, as long as every
  perspective name and its chain string appear in the table.

**Effort sentence (FR9):** in each README, directly after the sentence
saying the reviewer passes the model handed by `reviewers.yaml` straight to
`-m`, add one sentence. It says that a codex entry's `effort` takes the same
path and reaches the wrapper's `--effort`. Write it in Japanese, matching the
README.

**Skill (FR10):** the skill stays about the security perspective.
- Policy line 11, "other perspectives write no `model`", is replaced by a
  statement that each perspective's codex entry in `reviewers.yaml` names its
  model and effort.
- Policy line 12, "the wrapper-fixed xhigh", is replaced by a statement that
  the security entry's reasoning depth is the entry's `effort`.
- The "指定している場所" example shows the codex entry with `effort`.
- Procedure step 2 checks that the target model supports the entry's effort,
  instead of xhigh.
- Procedure step 3's confirmation command uses the entry's effort as a
  placeholder, instead of the literal `model_reasoning_effort="xhigh"`.
- Steps 1 and 4–6 are unchanged.

**Pinned literal (NFR6):** `PINNED_CHAINS` in
`tests/test_llm_led_review_user_docs.py` gives performance, spec and
architecture "codex → litellm `muse-spark`". Add a "Refreshed by
feature-docs/review-perspective-model-effort/tasks/task0005.md (FR9)" comment.
