## Goal

Both `run_codex_exec.sh` copies accept `--effort LEVEL`, validate it, and
launch `codex exec` with that reasoning effort. Without the option, every
launch stays exactly as it is today.

## Design

Implements IMPLEMENTATION.md Shared Components C3 and decisions D2, D3 and
D5. THREAT-MODEL.md TM-1 is this task's to implement.

**Option handling (both copies, identical):**

1. `--effort` is one more case of the existing option loop, shaped like the
   `-m` case: it takes the next argument as its value.
2. When fewer arguments remain than the option, its value and a prompt, the
   wrapper writes `ERROR: --effort requires an effort argument` to stderr and
   exits 1. Nothing is launched.
3. When the value does not match `^[a-z]+$` (the whole value — the empty
   string included), the wrapper writes exactly one stderr line,
   `ERROR: --effort value must match ^[a-z]+$`, and exits 1. Nothing is
   launched. The line never echoes the rejected value, so it stays one line
   whatever the input holds.
4. A later `--effort` replaces an earlier one; only the last value is used.
5. After the loop:
   - With a valid value, the effort pair (the two argv elements `-c` and
     `model_reasoning_effort="LEVEL"`) replaces whatever the mode chose: the
     xhigh pair in readonly, nothing in readwrite.
   - Without the option, the mode's choice stands: one xhigh pair in
     readonly, none in readwrite.

   The pair is placed where the effort pair sits in the launch today
   (immediately after the sandbox pair), so the rest of the argv keeps its
   order.
6. em-workflow only: `--effort` combines with `--litellm`. On that route the
   given effort replaces xhigh the same way. The existing rule that rejects
   `-m` together with `--litellm` is unchanged.

**Text changes (both copies):**
- Usage line, with `[--effort LEVEL]` right after `[-m MODEL]`:
  - em-workflow: `Usage: run_codex_exec.sh <readonly|readwrite> [-C DIR] [--output-schema F] [-m MODEL] [--effort LEVEL] [--litellm MODEL] "prompt"`
  - em-review: `Usage: run_codex_exec.sh <readonly|readwrite> [-C DIR] [--output-schema F] [-m MODEL] [--effort LEVEL] "prompt"`
- Header comment:
  - Add a usage example and an options entry for `--effort LEVEL`: the value
    must match `^[a-z]+$`, it becomes the `model_reasoning_effort` override,
    and it is accepted in both modes.
  - Rewrite the "Reasoning effort:" paragraph: readonly defaults to xhigh and
    readwrite to the model's own default, unless `--effort` is given.
- New code lines do not contain the text `codex exec` (D5). Comment lines may.

**Pinned literals (NFR6):** `WORKFLOW_USAGE` and `REVIEW_USAGE` in
`tests/test_codex_hook_wrapper_args.py`, and `USAGE_MESSAGE` in
`tests/test_codex_wrapper_single_invocation.py`, become the new usage lines.
Each gets a "Refreshed by feature-docs/review-perspective-model-effort/tasks/task0001.md (FR3)"
comment. The xhigh-default checks in those modules are not edited.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: For both copies, `readonly --effort high "prompt"` launches once.
      The argv holds the adjacent pair `-c` / `model_reasoning_effort="high"`
      exactly once and holds no `model_reasoning_effort="xhigh"` element
      (TS-1).
- [ ] AC-2: For both copies, without `--effort`, the readonly argv holds
      exactly one `model_reasoning_effort` element, equal to the xhigh pair
      directly after the sandbox pair. The readwrite argv holds no
      `model_reasoning_effort` element. On em-workflow, the same holds on the
      `--litellm` route. The existing argv tests
      (`tests/test_codex_hook_wrapper_args.py`,
      `tests/test_codex_litellm_launch_home_location.py`,
      `tests/test_codex_repo_hook_trust.py`) pass without their argv
      assertions being edited (TS-2, NFR1).
- [ ] AC-3: For both copies, `readwrite --effort low` launches with exactly
      one `model_reasoning_effort="low"` pair. On em-workflow,
      `readonly --litellm M --effort low` launches with exactly one low pair
      and no xhigh pair, and `-m` together with `--litellm` still exits 1
      without launching (TS-3, TS-4).
- [ ] AC-4 (TM-1): For both copies, `--effort` with no value exits 1, stderr
      contains `ERROR: --effort requires an effort argument`, and nothing is
      launched. A value with a double quote, an uppercase letter, a space, a
      backslash, or the empty string exits 1, stderr holds the line
      `ERROR: --effort value must match ^[a-z]+$`, and nothing is launched.
      Both copies give byte-identical messages (TS-5, NFR2, NFR3).
- [ ] AC-5: For both copies, `--effort` combined with `-m`, `-C` and
      `--output-schema`, in more than one order, keeps each flag pair
      adjacent and the prompt last. `--effort low --effort high` gives one
      high pair and no low pair (TS-6).
- [ ] AC-6: Both usage lines read as in Design. The three pinned usage
      literals are refreshed in place with their comments, and every other
      assertion in those modules passes unedited. Each wrapper's non-comment
      code contains `codex exec` exactly once (TS-10, NFR6).
- [ ] AC-7: The new tests use only the standard library and the `PATH` stub,
      and `python3 -m unittest discover -s tests` passes (NFR4).
