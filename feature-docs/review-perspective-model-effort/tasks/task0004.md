# Task Plan: task0004 — review phase sends `effort` and records it

## Goal

Both `review-phase.md` documents add a codex entry's `effort` to the
reviewer input block in Phase R2, and record it on the codex runs that
received it.

## Requirements

FR7, FR8, NFR4, NFR6

## Scope

### Files to Create
- `tests/test_review_phase_effort_docs.py` — asserts the R2 and record statements below for both plugins.

### Files to Modify
- `em-workflow/references/review-phase.md` — Phase R2 codex bullet; Phase R3a perspectives_dispatched; Phase R5 perspective_runs example and its comment.
- `em-review/references/review-phase.md` — Phase R2 codex bullet; the round record's perspective_runs example and its comment.
- `tests/test_tier_record_schema_v2.py` — refresh REVIEW_PHASE_SHA256.

## Design

Implements IMPLEMENTATION.md Shared Components C1 (reader side) and C2
(sender side), and decisions D1, D2 and D4.

**Phase R2 codex bullet (both copies):**
- Today the bullet adds `model: M` when the entry names it. Extend it the
  same way: when the entry names `effort: E`, add `effort: E` to the input
  block, passed through verbatim, with no allow-list check.
- The litellm bullet does not change and never adds `effort`.
- In em-workflow the bullet is the `{harness: codex}` item under "Walk that
  perspective's registry `primary_chain`". In em-review it is the item under
  "When `cross_validation` fired".
- Where the surrounding text names the chain entry shape as `{harness,
  model?}`, it reads `{harness, model?, effort?}`.

**Phase R2b and R4 (both copies):** unchanged. Their "same input block"
sentences cover `effort`. Because `effort` is added only by the codex bullet,
a hop to a litellm entry does not carry it (C2).

**Records:**
- em-workflow Phase R3a, `perspectives_dispatched`: the entry description
  also lists `effort` for codex runs given an `effort`, next to the existing
  `model` wording.
- em-workflow Phase R5 `perspective_runs`, and em-review's round-record
  `perspective_runs`:
  - At least one codex example row carries `effort` (with `model`, as a codex
    run given both would).
  - The Japanese comment that says when `model` is attached also says that
    `effort` is attached only to a codex run that was given `effort`, never to
    a litellm run and never to a codex run without it. Keep that comment's
    existing language and line style.

**Pinned digest (NFR6):** `REVIEW_PHASE_SHA256` in
`tests/test_tier_record_schema_v2.py` is the whole-file digest of
em-workflow's `review-phase.md`. Recompute it from the edited file. Add a
"Refreshed by feature-docs/review-perspective-model-effort/tasks/task0004.md
(FR7, FR8)" line to the existing comment run above it, saying R2's codex
bullet and the R3a / R5 records gained `effort`. `REVIEW_RULES_SHA256` is not
touched.
