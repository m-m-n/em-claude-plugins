## Design

This section is the owner of the non-packet escalation `source` (IMPLEMENTATION.md Shared Components). The gate identifying names it already states (`review.diff-size-gate`, `command-execution.per-command-approval-fallback`) are unchanged. The relaxed-route bullet is not touched (NFR3).

### 1. General mapping

The sentence that begins "For the other three writers below" gains the escalation case:

- `batch-codex-consultation` also covers a non-packet gate whose decision the Opus escalation made, including when the availability probe found no harness and no Codex consultation turn ran.
- The value is read as naming the consultation route and never as a claim that Codex itself was consulted — the same reading the relaxed-route bullet already uses.
- `batch-safe-default` stays the value when the minimum-side-effect option was taken.
- Both values come from `references/question-packet-schema.md`'s closed vocabulary; no value is added.

The phrases "For the other three writers below" and "the relaxed route's own bullet below states its complete three-way mapping instead" stay verbatim, and the old unscoped lead-in that the module's negative test guards against does not reappear.

### 2. Non-packet gates writer

The first writer bullet (the `references/batch-mode.md` Non-packet gates table entry) lists what its `resolution_note` names. That list additionally names whether the Opus escalation ran and its reasoning. The bullet's commit reach-point wording is unchanged.

### 3. Worked example

A second YAML example record with the same per-field shape as the existing one:

| Field | Value |
|---|---|
| `question_id` | `review.diff-size-gate` or `command-execution.per-command-approval-fallback` |
| `packet_id` | `null` |
| `answered_at` | RFC 3339 timestamp with an explicit offset |
| `source` | `batch-codex-consultation` |
| `answer_mode`, `selected_option_ids`, `freeform`, `normalized_answer` | Consistent with `references/question-packet-schema.md`'s answer consistency rules for the chosen answer mode |
| `resolution_note` | Codex was not consulted (no harness was available), the Opus escalation ran, and its reasoning |

Placement: outside the first writer bullet and outside the relaxed-route bullet — either after the general-mapping paragraph and before "Four writers append to this file", or after the append-only paragraph at the end of the section. The module's helpers bound the first bullet by the next bullet marker and the relaxed-route bullet by the blank line before "Records are append-only:", so an example placed inside either bullet changes what those helpers read.

### 4. Guards that stay satisfied

- "Four writers append to this file" occurs once.
- "step 7" occurs once in the section and stays scoped to `create-spec.command-approval`.
- No `question_id` is assigned `null`.
- The relaxed-route bullet keeps exactly one occurrence each of `batch-codex-consultation` and `batch-safe-default`.
- The existing YAML example is unchanged.
- phase-state.md contains no provider/model token and no usage-limit phrasing. That guard is a case-insensitive substring match over the whole file, so new wording is checked against it.
