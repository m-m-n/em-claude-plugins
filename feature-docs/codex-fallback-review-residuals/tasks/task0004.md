# Task Plan: task0004 — Regression test: --litellm MODEL passed verbatim

## Goal

A regression case in `tests/test_codex_wrapper_single_invocation.py` pins that `em-workflow/scripts/run_codex_exec.sh` turns `--litellm MODEL` into a single launch whose argv carries `-p litellm -m MODEL` as consecutive elements with MODEL unchanged.

## Requirements

FR7, NFR2, NFR5

## Scope

### Files to Create

None.

### Files to Modify
- `tests/test_codex_wrapper_single_invocation.py` — one new test class for the `--litellm` passthrough, with its matcher and non-vacuity proofs

## Design

The wrapper is not changed (NFR2). The new case reuses the module's existing subprocess harness: a stubbed `codex` first on PATH under an isolated HOME, appending each launch's argv to a JSON-lines log, read back by the module's existing log reader and checked by its existing launch-count matcher.

Flow of the case:

1. Choose MODEL: a clearly fictional identifier that occurs neither in the wrapper's text nor in `em-workflow/references/reviewers.yaml`, so the case cannot pass through a name hard-coded anywhere.
2. Run the wrapper in `readonly` mode with `--litellm` MODEL and a prompt, under the stub's success behaviour.
3. Assert exit 0 and exactly one launch.
4. Assert, with a consecutive-subsequence matcher, that the launch's argv contains `-p`, `litellm`, `-m`, MODEL as four adjacent elements in that order, MODEL byte-identical to the input.

Matcher contract: given an argv list and an expected sequence, it holds exactly when the sequence occurs as adjacent elements in order; a sequence present only as scattered elements does not satisfy it.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR7, NFR2): the new case runs the wrapper as `readonly --litellm MODEL "prompt"` under the module's stub harness and asserts exit 0 and exactly one launch using the module's existing launch-count matcher.
- [ ] AC-2 (FR7): the case asserts that the launch argv carries `-p`, `litellm`, `-m`, MODEL as four consecutive elements, with MODEL byte-identical to the value passed.
- [ ] AC-3 (FR7): the case asserts that MODEL occurs in neither the text of `em-workflow/scripts/run_codex_exec.sh` nor the text of `em-workflow/references/reviewers.yaml`.
- [ ] AC-4 (FR7): non-vacuity — the consecutive-subsequence matcher rejects a forged argv in which the model value was replaced by another value, rejects one in which the model value was dropped, and accepts a well-formed forged argv.
- [ ] AC-5 (NFR2, NFR5): `em-workflow/scripts/run_codex_exec.sh` is unchanged; `tests/test_codex_wrapper_provider_fallback.py` still does not exist; every pre-existing case in the module (including its AC-1, AC-3 and AC-7 cases and the standard-library-only import guard) passes unchanged; `python3 -m unittest discover -s tests` passes.
