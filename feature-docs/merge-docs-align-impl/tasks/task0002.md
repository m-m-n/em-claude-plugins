# Task Plan: task0002 — State the gh pr merge exception conditions in the README

## Goal

The `hooks/destructive-guard.py` row of the hook table in `em-workflow/README.md`
states the two conditions of the `gh pr merge` exception as implemented, and a
test in `tests/test_destructive_guard_merge_allow.py` detects drift in that row.

## Requirements

FR5, FR6, NFR1, NFR2, NFR4, NFR5

## Scope

### Files to Create

None.

### Files to Modify

- `em-workflow/README.md` — the destructive-guard row of the hook table
- `tests/test_destructive_guard_merge_allow.py` — drift detection for FR6 (c)

## Design

### README row

The row states these two conditions of the `gh pr merge` exception, in the
language the table already uses:

- (a) The canonical form is the only statement in the command
  (正規形がコマンドの中で唯一の文であること).
- (b) The working directory is a registered integration worktree or is under one
  (作業ディレクトリが登録済みの integration worktree か、その配下であること).

The row also states that the exception does not hold when the same command has
another statement, before or after, and that a deny in another statement gives
that verdict.

「同じコマンドの後続の区間も通常どおり判定する」 is removed.

The row stays one line starting with `hooks/destructive-guard.py` and keeps
`gh pr merge` and `integration worktree`. It states only these two conditions: not
symlinks or nested repositories under the worktree, and not the registration
check details.

### Test in `tests/test_destructive_guard_merge_allow.py`

| Scenario | Check |
|----------|-------|
| TS-5 | The destructive-guard row contains the terms of conditions (a) and (b) and does not contain 「後続の区間も通常どおり判定する」. A forged row keeping the original sentence makes the check fire |

The behavior the row claims is verified in the same file: the canonical form plus
`&& echo done` is ask, and deny in batch, and an unregistered working directory is
ask.
