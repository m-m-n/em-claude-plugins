# Task Plan: task0001 — Fall back to the group reading when an argument range holds a backquote

## Goal

In both copies of `codex-hook-interactive-guard.py`, a `(`...`)` range among
the arguments of a zsh anonymous function that holds a triggering backquote is
no longer read as one argument word: its `(` opens a provisional group, as for
an unquoted `;`, `&` or newline, so the anonymous body's explicit `python3 -i`
is denied again. The regression is pinned by `CASES` rows, docstring markers
and a performance shape, all run against both copies.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR9, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `em-workflow/scripts/codex-hook-interactive-guard.py` — the range scan reports the backquote trigger, the argument-paren reader falls back to the group reading on it, and four docstrings state the rule
- `em-review/scripts/codex-hook-interactive-guard.py` — the same change, byte-identical to the em-workflow copy
- `tests/test_codex_hook_interactive_guard.py` — new CASES rows, backquote-rule docstring markers, and one more performance shape

## Design

### Which backquote is a trigger

The range is what `_scan_parens` reads from the `(` up to the `)` that closes
it. Within it:

| Backquote position | Trigger |
|---|---|
| Outside quotes, not right after a backslash | yes (FR1) |
| Inside double quotes, not right after a backslash | yes (FR2) |
| Inside single quotes | no (FR3) |
| Outside quotes, right after a backslash | no (FR3) |
| Inside double quotes, right after a backslash | no (FR3) |
| Inside a `$(` within the range, unquoted | yes (SPEC A3; falls out of the scan, which gives `$(` no special reading) |
| After the range's closing `)` | not examined (SPEC A1) |

Whether the backquotes in the range are balanced does not matter (FR4): any
trigger sends the range to the group reading.

### Range scan contract (`_scan_parens`)

Decision on SPEC assumption A5: the trigger is reported as its own result
element, not folded into `separated`. `separated` keeps its documented meaning
(the existing `;` `&` newline trigger stays exactly as it is, FR5), and each
trigger gets its own docstring sentence.

- Signature: `_scan_parens(start, limit=None)` returns
  `(end, separated, backquoted, reached)`.
- Precondition: `start` is the index of a `(` (unchanged).
- Postcondition: `end`, `separated` and `reached` are, for every input,
  exactly what the current scan returns. `backquoted` is true exactly when the
  scan read a trigger backquote (table above) between the `(` and its closing
  `)`. When `end` is None (no `)` found, an unbalanced quote, or `limit`
  reached), both flags are false, as `separated` is today.
- A backquote is noticed, never interpreted: it changes neither the nesting
  depth, nor the quoting state, nor where the scan stops. Locating the `)`
  still skips backslash pairs, single-quoted text and double-quoted text only
  (FR5).
- Noticing it costs constant work per scanned character; no recursion (NFR1).
- `_skip_parens` keeps using only `end`, so its result and behaviour for `$(`
  and process substitution are unchanged (FR5).

### Argument-paren reader (`_read_argument_parens`)

1. Scan the range and charge `paren_budget` with the characters read
   (unchanged).
2. When the scan found the `)` and neither `separated` nor `backquoted` is
   set, read the range as one argument word (unchanged).
3. Otherwise step past the `(` and open a provisional group (the existing
   fallback path).
4. From there the existing provisional-group, rescue and connection rules apply
   unchanged; no new reading is added (SPEC A2). A backquote the group reading
   then finds unclosed makes the string undecidable through the existing
   unbalanced-quote rule, giving no output (FR6).

### Docstrings (both copies, English)

| Docstring | What it gains |
|---|---|
| Module docstring step 4 (the paragraph with "The matching `)` is found by ...") | A range that holds a trigger backquote, one inside double quotes included, opens a group like a range with an unquoted `;`, `&` or newline |
| `_Parser` class docstring (the "unless the range holds ..." sentence) | The backquote trigger among the conditions under which the `(` opens a group |
| `_scan_parens` | The meaning of the new result element, including which backquotes count and which do not |
| `_read_argument_parens` | The backquote trigger among the cases in which the `(` opens a group instead |

- Keep these existing marker phrases verbatim, or change the test markers in
  the same change: "holds an unquoted `;`, `&` or newline, the `(` opens a
  group" and "a backquote and a comment get no special reading" (the latter
  stays true of how the `)` is located). Write the backquote rule as its own
  sentence or clause so the first marker stays a contiguous phrase.
- The `_skip_parens` docstring is unchanged.
- No docstring may use the phrase "fully quote-aware" (an existing negative
  test).

  rows of AC-1 and AC-2 print nothing; that is the failing state. The `silent`

  the end.
