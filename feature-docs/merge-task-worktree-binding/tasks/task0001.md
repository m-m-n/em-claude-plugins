# Task Plan: task0001 — Bind merge-task.sh to the named task's own worktree and branch

## Goal

merge-task.sh merges only when it runs inside the named task's own worktree of
the em-workflow layout with that task's branch checked out; every other
invocation ends with exit 2 before the merge lock. The script's tests and its
content pins match the new behavior.

## Requirements

## Scope

- `tests/test_merge_task_journal.py` — former AC-5 merge-only test converted into a rejection test; new rejection, ordering, fail-closed and subdirectory tests
- `tests/test_merge_unverified_exit_doc_contract.py` — merge-task.sh content pin updated; line-slice test replaced by a case-name test; comment-phrase absence test added

## Design

### Identity binding (merge-task.sh)

The binding runs after the existing usage and work-tree checks and before the
merge lock, the clean-tree precondition, and any merge-tree, commit-tree or
update-ref (FR4). It applies to every invocation: the branch that lets a run
outside the layout merge with no binding is removed (FR1). Each step below
rejects through the script's existing error path (one `ERROR:` line on
stderr, exit 2):

1. Resolve the worktree's top-level directory. A failure or an empty result is
   a rejection (NFR1). A run from a subdirectory resolves to the same
   top-level and continues (SPEC.md A4).
2. Layout shape: the last segment matches the task-id pattern, its parent
   segment (the feature) matches the feature pattern, and the segment above
   that is `em-workflow` — the same three conditions the script already uses
   (FR1). No match is a rejection whose message names the resolved top-level
   and says the script must run from the task's own worktree. This rejects the
   main working tree, the feature's integration worktree and every other path.
3. The last segment equals the task-id argument; otherwise the existing
   task-id mismatch rejection, keeping its "does not match" wording.
4. The parent-branch argument equals the feature's integration branch derived
   in step 2; otherwise the existing rejection, keeping its "integration
   branch" wording (FR2).
5. HEAD's symbolic ref resolves and equals the task branch's full ref,
   `refs/heads/em-workflow/{feature}/{task-id}`. A detached HEAD, another
   branch, or a resolution failure is a rejection whose message names the
   expected ref and what was found (FR3, NFR1).

Everything after step 5 is unchanged (FR5): the lock, the clean-tree
precondition, the parent lookup, the already-contained, fast-forward,
merge-commit and conflict paths, the journal append and its warning, and the
serialization of concurrent merges. The "Parent already contains us" case
keeps the case-marker contract in IMPLEMENTATION.md Shared Components.

### Journal append

Behavior unchanged. Its comment no longer names manual invocation or
merge-only tests as reasons the append is skipped; it states that the identity
binding guarantees the layout for every run that reaches the append, and that
the append's own re-derivation remains as a defensive silent skip.

### Comments (FR6)

The header's caller description and its exit-code-2 line, and the identity
binding comment, state that a run outside the task's own worktree layout, or
with any branch other than the task branch checked out, ends with exit 2
before any lock or ref update. No comment describes an out-of-layout merge as
permitted.

### Tests

- `tests/test_merge_task_journal.py`: the former AC-5 test becomes a rejection
  test, and its name no longer claims success. New tests cover TS1, TS2, TS4,
  TS5, TS8, TS9 and TS10 (VERIFICATION.md). The shared setUp and the helpers
  the existing tests call keep their behavior; new tests may add helpers of
  their own. Existing in-layout test bodies are not edited.
- `tests/test_merge_unverified_exit_doc_contract.py`, only within the region
  IMPLEMENTATION.md Shared Components assigns to the task that owns

  module's original base commit; the line-slice test is replaced by a test of
  the case-marker contract; a new class, placed directly after the pin class,
  asserts the FR6 phrase absence.

## Test Notes

- Red first: TS1, TS2, TS3, TS4, TS5, TS8 and TS9 fail against the current
  script (it merges outside the layout and checks no branch; TS8's
  main-working-tree run blocks on the held lock; TS9 exits 0 through the
  already-contained path). TS10 passes before and after; it guards against a
  check based on the working directory instead of the top-level. Record that
  in the task's tests record.
- A branch can be checked out in only one worktree, and the shared fixture
  keeps the main working tree on the integration branch. TS1 and TS2 therefore
  move the main working tree to another branch inside their own test body.
- TS8 takes the lock on the merge lock file in the repository's git common
  directory (the file merge-task.sh and commit-docs.sh both lock) from the
  test process itself. The bounded wait is a few seconds; a run still blocked
  at the bound fails the test and is ended by the test's own timeout handling,
  never by killing processes from outside.
- TS9: depending on the git version, top-level resolution inside a git
  directory either fails or yields nothing. Assert only the outcome (exit 2,
  `ERROR`, unchanged ref, no journal).
- For out-of-layout placements, journal absence is checked across the whole
  temporary directory, as the former AC-5 test does, not only at the feature's
  journal path.
- Compute the content pin after the final edit of merge-task.sh, and recompute
  it after any later edit.
