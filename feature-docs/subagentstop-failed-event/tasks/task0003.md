# Task Plan: task0003 — em-workflow version bump to 0.2.4

## Goal

em-workflow's version reads 0.2.4 in both the plugin manifest and the marketplace entry, pinned by a version-parity test.

## Requirements

FR9, NFR2, NFR7

## Scope

### Files to Create

- `tests/test_subagentstop_failed_event_version_bump.py` — version-parity and bump-over-baseline test for this feature

### Files to Modify

- `em-workflow/.claude-plugin/plugin.json` — version value from 0.2.3 to 0.2.4
- `.claude-plugin/marketplace.json` — em-workflow entry version value from 0.2.3 to 0.2.4

## Design

- The version value is fixed by IMPLEMENTATION.md D4. Only the two `version` values change; every other key, the em-review entry, the long description strings and the file formatting stay byte-identical.
- The test module follows `tests/test_stale_launched_version_bump.py`:
  - the marketplace entry is located by its `name` field, never by position, and the lookup fails loudly when no entry has that name;
  - versions are parsed into three numeric components and compared per component, never as raw strings;
  - this feature's baseline is 0.2.3, and the check is "strictly greater than the baseline" with no fixed major.minor pin, so a later minor bump does not break it;
  - every matcher (equality, bump over baseline, version parse) has a negative proof against forged data, plus a well-formedness guard on the forged sample;
  - a standard-library-only self-check of the module's own imports.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The version in `em-workflow/.claude-plugin/plugin.json` equals the version of the `.claude-plugin/marketplace.json` entry whose name is `em-workflow`.
- [ ] AC-2: That version parses as three numeric components and is strictly greater than 0.2.3 under per-component numeric comparison.
- [ ] AC-3: The value this task writes is 0.2.4 in both files, and the diff of both files touches only these two version values.
- [ ] AC-4: The marketplace lookup fails loudly for a missing name; each matcher has a negative proof against forged data; the module imports only the standard library.
- [ ] AC-5: `python3 -m unittest discover -s tests` passes, including the pre-existing `tests/test_stale_launched_version_bump.py`.

## Test Notes

- AC-1, AC-2 and AC-4 are permanent assertions in the new module.
- AC-3 is checked by diff inspection and recorded in the task's test record. It is not a permanent exact-value assertion, which would fail at the next legitimate bump.
- Run the full suite after the bump. If a pre-existing module pins the exact prior value 0.2.3 and fails, that file is outside this task's set: report it as a plan deviation instead of editing it.

## Out of Scope

- The em-review version.
- Any hook, documentation or test change other than the new module.
- LICENSE generation or relicensing.
