# Task Plan: task0001 — SubagentStop failure net: task identification, atomic append and diagnostics

## Goal

`queue_failure_net.py` records exactly one `failed` event for every implementer stop that never reached merge (it recognizes the unprefixed agent type, finds the assignment block in any user message, falls back to the agent index, parses exactly like the launch guard, and replays and appends atomically), and it leaves one diagnostics line per invocation.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6, NFR7

## Scope

### Files to Create

- `tests/test_queue_failure_net_cross_hook.py` — tests that drive this hook together with the launch guard and the stop-tool recorder: parser parity, concurrency, retry reachability, fallback agreement

### Files to Modify

- `em-workflow/hooks/queue_failure_net.py` — new identification flow, launch-guard-identical parser copy, agent-index fallback, single critical-section replay and append, diagnostics log, rewritten module docstring
- `tests/test_queue_failure_net.py` — single-hook tests for the new identification paths, the diagnostics log, preserved behavior, the SubagentStop registration and the docstring

## Design

This task implements IMPLEMENTATION.md SC1 (identification and outcome flow), SC2 (diagnostics log record) and SC3 (unchanged `failed` line) exactly. They are referenced here, not restated. The hook stays one standalone script that imports only the standard library (NFR2).

### Components inside the hook

| Component | Responsibility | Contract |
|---|---|---|
| Agent-type gate | SC1 step 2 (FR1) | Accepted values after trimming: `em-workflow:implementer`, `implementer`. Any other non-empty string ends the flow with `not-implementer-type`. |
| Prompt-text finder | SC1 steps 3 and 4 (FR2) | Returns the text of the first inline field, else of the first transcript user-role message, that contains a header line. It also reports whether any prompt text was seen at all, which separates `no-prompt-text` from `no-assignment-block`. The transcript is read line by line and the scan stops at the first match. User-message text extraction keeps today's tolerance of both the string-content shape and the text-block-list shape. |
| Assignment parser | SC1 step 6 (FR4) | A copy of `queue_launch_guard.py`'s `extract_task_assignment`, under the same name, with its header, task-id-line and worktree-path-line patterns byte-identical to the launch guard's, and the same return contract: no header gives two absent values; a missing line gives an absent value for that field; values are exactly what the patterns capture. Only text after the first header line is searched. |
| Agent-index resolver | SC1 step 5 (FR3) | Identifier = payload `agent_id`, trimmed. Reproduces the rules of `queue_taskstop_net.py` listed below. Returns a (task id, worktree path) pair, or nothing. |
| Identity validator | SC1 step 7 | Task id is `task` followed by digits. Worktree path is non-empty, absolute and has no `..` segment. |
| Journal critical section | SC1 steps 8 and 9 (FR5, NFR6) | Opens the journal with the open flags FR5 names (read-write, create, append, no-follow), mode 0644; takes an exclusive lock on that descriptor; replays the whole file through the same descriptor from the start, skipping malformed lines; appends at most one `failed` line; flushes it to disk; releases the lock and closes the descriptor on every path. No journal read outside this section decides an append. |
| Outcome record | SC1 | Carries source, validated task id, validated worktree path (used only for diagnostics root resolution, never logged), outcome and exception class name. It is filled step by step, so an `error` keeps what was already known. |
| Diagnostics writer | SC2 (FR6) | Resolves the root, builds one line from the outcome record and the payload, appends it with the SC2 write discipline, and swallows every failure. |
| Entry point | NFR1 | Reads stdin; runs the flow inside a catch-all that turns any exception into outcome `error`; then runs the diagnostics writer inside its own catch-all; always exits 0. |

### Agent-index resolution rules (FR3, same as queue_taskstop_net.py)

1. Search root: the nearest directory, walking up from the payload `cwd`, that contains `.claude/worktrees/em-workflow`. A missing, non-string or non-absolute `cwd` yields no root, and the lookup is unresolved.
2. Read the `agents.jsonl` of every immediate child directory of that root, in sorted directory order. Unreadable files and malformed lines are skipped.
3. Before matching, an entry is discarded when its candidate list is longer than the stop-tool recorder's cap (5), or when its `worktree_path` does not normalize to a direct child of the directory that holds that `agents.jsonl`.
4. An entry matches when the identifier equals any non-empty string element of its candidate list, or, only when the entry has no candidate list, its representative key (`agent_id`, then `agentId`).
5. Matches that span two or more distinct (index file, task) pairs: unresolved.
6. Otherwise the last matching entry wins, unless a later surviving entry for the same (index file, task) pair exists: unresolved (stale).
7. The resolved task id and worktree path then pass SC1 step 7 like any other source.

### Module docstring (FR8, docstring part)

Rewrite the module docstring so it states: the SC1 identification order (agent type; then an inline prompt field or the first transcript user message that contains the header; then the agent-index fallback by the payload agent id); post-header-only parsing shared with the launch guard; the single critical-section compare-and-append; the diagnostics log location and file name; the nine outcome codes and the three identification sources; that a missing diagnostics line alone does not distinguish a hook that did not run from a hook that ran but could not write the log; that the log is not a journal. Keep the fail-open statement.

### Constraints

- `FAILED_REASON` keeps its value and stays a single-line, double-quoted, module-level constant (NFR4).
- The journal `failed` line keeps exactly the keys `event`, `task`, `at`, `reason` (NFR4).
- `hooks.json` and the other queue hooks are not modified (NFR5, IMPLEMENTATION.md D5).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1): For a task whose last journal event is `launched`, with a valid assignment block for it, exactly one `failed` line for that task is appended when `agent_type` is `em-workflow:implementer`, when it is `implementer`, and when it is absent. When `agent_type` is `Explore`, the journal is unchanged.
- [ ] AC-2 (FR2): With no inline prompt field, a transcript whose first user-role message has no header and whose second user-role message carries a valid block leads to exactly one `failed` line for the second message's task. An inline field whose text has no header does not prevent this transcript scan, and an inline field that carries a block takes precedence over a transcript block naming a different task.
- [ ] AC-3 (FR3): With no inline prompt, a missing, unreadable or block-less transcript, a `cwd` inside a temporary worktrees root and an `agents.jsonl` entry matching the payload `agent_id`, exactly one `failed` line is appended for that entry's task. For each refusal fixture (identifier matching two tasks, a superseded entry of a relaunched task, an entry whose worktree path lies outside its feature directory, an oversized candidate list, no matching entry), nothing is appended. For every fixture of this criterion, `queue_taskstop_net.py` run on an identical fresh fixture with the same identifier and `cwd` produces the same journal change (same events for the same tasks).
- [ ] AC-4 (FR4): A prompt with `task_id: task0099` and a worktree-path line before the header, and a real task after it, leads to a `failed` line for the post-header task only. For every prompt in a fixture set of at least eight cases (see Test Notes), this hook's parser returns exactly what `queue_launch_guard.py`'s parser returns. The launch guard, given the same prompt, appends `launched` for the same task id this hook marked `failed`.
- [ ] AC-5 (FR5, NFR6): In each of several rounds, concurrently started `queue_failure_net.py` and `queue_taskstop_net.py` subprocesses (at least five of each) for the same `launched` task leave exactly one `failed` line for that task, and every journal line parses as JSON. When the journal path is a symlink, the link target is never written and the exit code is 0.
- [ ] AC-6 (FR6): For fixtures whose `cwd` lies inside a temporary worktrees root, each invocation appends exactly one line to that root's `subagent-stop-diagnostics.jsonl`, carrying the SC2 keys (with `at` in RFC 3339 form with an offset) and the expected `outcome`, `source` and `task_id` presence, for each of the nine outcomes: `appended`, `already-terminal`, `not-implementer-type`, `no-prompt-text`, `no-assignment-block`, `invalid-identity`, `index-unresolved`, `journal-dir-missing`, and `error` with a non-empty `error_class` (journal-symlink fixture). When `cwd` yields no root but the validated worktree path does, the line lands in the worktree path's root. When neither yields a root, no diagnostics file is created anywhere in the temporary tree.
- [ ] AC-7 (FR6, NFR1, NFR3, NFR6): When the diagnostics log path is a symlink, or is a directory, the hook exits 0, the journal ends identical to the same fixture without the obstruction, and a symlink's target is never written. A sentinel string placed in the prompt text never appears in the diagnostics file, and the journal never contains a diagnostics line. After concurrent invocations, every diagnostics line parses as JSON.
- [ ] AC-8 (FR7): After this hook appends `failed` for a task whose last event was `launched` (agent_type `implementer`), `queue_launch_guard.py` given an `em-workflow:implementer` launch with the same assignment exits 0 with no deny output, and the journal's last line is a new `launched` event for that task.
- [ ] AC-9 (NFR1, NFR2, NFR4, NFR5, NFR7): Every pre-existing test case in `tests/test_queue_failure_net.py` and `tests/test_queue_taskstop_net.py` keeps its assertions and passes (merged, failed, Explore, absent journal directory creates nothing, malformed and edge stdin exit 0). `FAILED_REASON` keeps its value as a single-line double-quoted constant. The `hooks.json` SubagentStop registration is one group with no matcher and one command hook whose command is `python3 "${CLAUDE_PLUGIN_ROOT}"/hooks/queue_failure_net.py` with timeout 15. The hook and both test modules import only the standard library. `python3 -m unittest discover -s tests` passes.
- [ ] AC-10 (FR8): The hook's module docstring names all nine outcome codes, the diagnostics file name `subagent-stop-diagnostics.jsonl`, and the three identification sources `inline`, `transcript` and `agent-index`.

## Test Notes

- **Placement**: single-hook behavior (AC-1, AC-2, AC-3 without the recorder comparison, AC-6, AC-7, AC-9, AC-10) goes in `tests/test_queue_failure_net.py`; tests that run another hook (AC-3's recorder comparison, AC-4 parity, AC-5, AC-8) go in the new cross-hook module. The cross-hook module duplicates the fixture helpers it needs instead of importing another test module.
- **Helpers**: extend the existing ones with a transcript writer that takes several messages (user and assistant, string or text-block-list content), an `agents.jsonl` writer, and a payload builder that accepts `cwd`, `agent_id`, `agent_type` and inline prompt fields.
- **Isolation**: the pre-existing tests use `cwd` `/tmp`; keep them. New tests always use a `cwd` inside the per-test temporary directory. A validated worktree path under the temporary tree's `.claude/worktrees/em-workflow` makes the root fallback find a root, so the "no line anywhere" case needs a worktree path and a `cwd` outside any worktrees root, or a fixture that never validates a worktree path (for example `not-implementer-type`) with `cwd` outside any root.
- **Outcome fixtures**: `no-prompt-text` has no inline field, no transcript path and no `agent_id`; `no-assignment-block` has a transcript without a header and no `agent_id`; `index-unresolved` has an `agent_id` that matches nothing; `invalid-identity` uses a block with task id `not-a-valid-id` and must produce a line without a `task_id` key; `journal-dir-missing` has an existing worktrees root without the feature directory, which must stay absent; `error` places a symlink at the journal path (assert `error_class` is a non-empty string, not a specific class name).
- **Unwritable log**: place a directory at the log path; permission bits do not stop a root user.
- **Parser parity set** (at least eight): no header; header with both lines; both lines only before the header; lines before and after the header; header with trailing whitespace; header without the space after the hash sign; worktree path containing spaces; missing worktree-path line; two headers; carriage-return line endings; non-string input. Load each hook's module by file path through the standard library's import machinery without running its entry point, and compare return values.
- **Concurrency**: build a fresh fixture per round, start every thread before joining any, run one subprocess per thread, join with a generous timeout, and assert per round.
- **Recorder comparison (AC-3)**: for each fixture, build two identical fresh temporary trees; run this hook with a SubagentStop payload (no transcript, `agent_id` = identifier, `cwd` = temporary root) on one, and `queue_taskstop_net.py` with a TaskStop PostToolUse payload whose tool input `task_id` is the identifier and whose `cwd` is the same on the other; compare the event/task sequences of the two journals (the `at` and `reason` values differ by design).
- **Docstring (AC-10)**: read the hook source as text and take the module docstring through the standard library's syntax-tree parser.
- **Not observable in tests**: the flush to disk after the append; it is checked in review.
