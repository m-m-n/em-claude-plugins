# Task Plan: task0002 — implement-phase.md: SubagentStop failure net bullet and Stale-launched caveat

## Goal

`em-workflow/references/implement-phase.md` describes the failure net's identification order, atomic compare-and-append and diagnostics log, and its Stale-`launched` caveat states how a stop that delivers no SubagentStop event is covered, both pinned by a new documentation-contract test.

## Design

The content to document is fixed by IMPLEMENTATION.md SC1 (identification and outcome flow), SC2 (diagnostics log record) and SC3 (unchanged `failed` line). This task states that contract in prose; it does not read or depend on the hook's code.

### Passage 1: the SubagentStop failure net bullet

Location: under "Supporting cast: journal, hooks, resume", the bullet that starts with the bold label "SubagentStop failure net" and ends where the bullet with the bold label "Stop-tool recorder" begins. Extend it so it states, in this order:

1. Trigger and stance: fires on every subagent stop, always exits 0, never blocks the stop.
2. Identification order: the agent type (`em-workflow:implementer` or `implementer`; any other non-empty type means the hook does nothing); then the assignment block from an inline prompt field or from the first transcript user message that contains the `# Task assignment` header, with the task id and worktree path taken only from the text after the header, parsed exactly as the launch guard parses it; then the agent-index fallback by the payload's agent id, resolved with the stop-tool recorder's rules.
3. Atomic compare-and-append: replay and append happen inside one exclusive-lock critical section on the journal; `failed` is appended only when the task's last event is neither `merged` nor `failed`; together with the stop-tool recorder, at most one `failed` line results.
4. Diagnostics log: `.claude/worktrees/em-workflow/subagent-stop-diagnostics.jsonl`, one line per invocation, the nine outcome codes of SC1, prompt text never logged; it is not a journal, has no task-status meaning and adds no journal writer.
5. Meaning of absence: a stop with no diagnostics line alone does not distinguish "the hook did not run" from "the hook ran but could not write the log"; a line that is present separates "the hook fired but could not identify the task" (its outcome code) from a successful append.

### Passage 2: the Stale-`launched` caveat

Add a statement that a stop delivering no SubagentStop event (and no stop-tool event) is covered by the existing extended same-session branch of I.2.b step 1's orphan-recovery attempt, adding no writer, and that such a stop is observable as a missing diagnostics line. The two phrases `tests/test_stale_launched_doc_contract.py` pins in this paragraph stay verbatim: "a stop that delivers neither a subagent-stop nor a stop-tool event" and "orphan-recovery attempt's extended same-session branch".
