# Task Plan: task0001 — Delimiter-position ${ ... } reading in codex-hook-interactive-guard

## Goal

codex-hook-interactive-guard registers a `<<` / `<<-` delimiter containing `${ ... }` as the same string zsh uses, so an interactive launch after the real heredoc terminator is denied; delimiter forms whose zsh reading the guard cannot reproduce become undecidable instead of being registered under a guessed string.

## Design

Cross-task conventions (mirrored copies, regression table, error policy) are in IMPLEMENTATION.md. This section covers this task only.

### Where the new reading applies

- **Delimiter position** = the word read as the operand of `<<` or `<<-`. Only that word gets the new reading.
- Unchanged everywhere else (FR5): ordinary words, `<<<` and `<` targets, where `_dollar` keeps closing `${` at the first `}` and keeps the written characters as a dynamic word (A-4 keeps the non-delimiter `${v:-"a}b"}` reading as is); `$'` / `$"` outside the delimiter position; anonymous-function argument quote removal (`_remove_range_quotes` over the `(`...`)` range).
- Unchanged inside the delimiter word (FR5): a double-quoted unit, including a `${ ... }` written inside double quotes, keeps the current quoted-unit reader; a `$( ... )` written directly in the delimiter word (outside any `${ ... }`) keeps its current reading; a backslash-escaped character keeps its current reading.

### Unquoted `${` at the delimiter position (FR1, FR2, FR3)

Flow:

1. On an unquoted `${` in the delimiter word, start a close search right after it with nesting depth 1. The search runs to the end of the command text, not the end of the line (a quote may span lines).
2. Each character is classified with a quote state that matches `_remove_range_quotes`'s classification of the same text:
   - Backslash outside quotes: the next character is escaped and ordinary (an escaped `}` does not close, an escaped `$` does not start `$'` / `$"`).
   - Single quote: opens a span that ends at the next single quote; nothing inside counts.
   - Double quote: opens a span that ends at the next unescaped double quote; nothing inside counts for depth or for the `$'` / `$"` check.
   - Unquoted `$(` or `$((`: skipped as one unit up to its matching close; its contents, quotes included, are not interpreted.
   - Unquoted `${`: depth plus one. Unquoted `}`: depth minus one; depth zero is the close.
   - Unquoted, unescaped `$` immediately followed by a single or double quote: undecidable (FR3).
   - Backquote: an ordinary character, neither a quote nor a substitution (A-1).
3. Undecidable when the text ends before depth reaches zero, when a quote span is still open at the end of the text, or when a `$(` / `$((` has no close (FR2).
4. On the close, the range from `${` to its `}` is converted with the FR1 rules (the `_remove_range_quotes` rule: unquoted backslash removed keeping the next character, backslash-newline removed entirely; `'` and `"` removed; single-quoted content kept; inside double quotes a backslash removed only before `$`, backquote, `"`, backslash or newline; `$( ... )` / `$(( ... ))` kept as written; everything else, nested `${`, `#`, `:-` included, kept as written). The result is appended to the delimiter being built, and delimiter-word reading resumes right after the close, so text before and after the range is concatenated unchanged.

Postconditions (registered delimiter for a given delimiter word, from SPEC.md FR1 / FR2 and A-2):

| Delimiter word | Registered delimiter |
|----------------|----------------------|
| `${v:-"x"}`, `${v:-'x'}`, `${v:-\x}` | `${v:-x}` |
| `${v:-"x"y}` | `${v:-xy}` |
| `${v#"x"}` | `${v#x}` |
| `foo${v:-"x"}bar` | `foo${v:-x}bar` |
| `${v:-"a}b"}` | `${v:-a}b}` |
| `${v:-\}}` | `${v:-}}` |
| `${a:-${b:-"x"}}` | `${a:-${b:-x}}` |
| `${v:-$(echo "x")}`, `${v:-$(echo "}")}` | as written |
| `${v:-"$'"}` | `${v:-$'}` |
| `${v:-\$'x'}` | `${v:-$x}` |
| `${v:-$'x'}`, `${v:-$"x"}`, `${v:-"a}` (open quote to end of text) | undecidable |

### Unquoted `$'` / `$"` outside `${ ... }` (FR4)

In the delimiter word, an unquoted, unescaped `$` immediately followed by a single or double quote anywhere outside a `${ ... }` range, at the start of the word or in the middle (`foo$'x'`), makes the reading undecidable. The current treatments (keeping `$'x'` as written; dropping the `$` of `$"`) are not used at the delimiter position and stay as they are elsewhere. `$'` / `$"` inside double quotes and a backslash-escaped `$` are not reasons for undecidable.

### Undecidable (FR6)

Raised through the existing `_Undecidable` mechanism; no new outcome type. The existing checkpoint rule then judges commands up to the last checkpoint and emits nothing when there is none.

### Linear time (NFR2)

Total work is proportional to the length of the `${ ... }` range, independent of nesting depth: a single forward scan that finds the close and builds the quote-removed text together; a nested `$( ... )` is skipped once as a unit and never re-read; no construct is rescanned per nesting level. Prefer sharing the quote-state handling with `_remove_range_quotes` (for example through a common helper) over a second, independent copy of the rule. If `_remove_range_quotes` is restructured for that, its behaviour for anonymous-function arguments stays identical.

### Module docstring (NFR3)

Update the decision-procedure description: delimiter-position `${ ... }` close search and quote removal, and the delimiter forms that are undecidable. Keep every string the docstring marker tests look for (`DELIMITER_RANGE_MARKERS`, `CHECKPOINT_MARKERS`, `CHECKPOINT_PASSAGES` and the others) and leave those tests unedited. Any new `-> no output` statement goes inside the section that states the checkpoint rule.
