# codex-guard-heredoc-delim-brace-quote - 要件定義書

## 1. 概要

### 1.1 背景

codex-hook-interactive-guard は、`<<` / `<<-` の区切り語に書かれた `${ ... }` を、引用を除かずに書かれたままの文字で区切り語として登録している。zsh は区切り語の `${ ... }` の中の引用を除いて読むため、両者の終端行が食い違う。その結果、heredoc の終端行の後にある `python3 -i` などの対話起動を見逃す（TS1 は今のコードで silent）。

### 1.2 目的

- codex-hook-interactive-guard が、`<<` / `<<-` の区切り語に書かれた `${ ... }` を zsh と同じ区切り語として登録し、heredoc の終端行の後にある `python3 -i` などの対話起動を見逃さないようにする。
- 区切り語の位置で zsh の読みを再現できない形（引用されていない `$'` / `$"`）は、誤った区切り語を登録せず判定不能にする。

### 1.3 スコープ

対象:

- `em-workflow/scripts/codex-hook-interactive-guard.py` と `em-review/scripts/codex-hook-interactive-guard.py` の、`<<` / `<<-` の区切り語の読み
- モジュール docstring の判定手順の説明
- `tests/test_codex_hook_interactive_guard.py` の `CASES`

対象外:

- 区切り語の位置にない `${ ... }` / `$'` / `$"` の読み（FR5）
- 区切り語の位置にない `${v:-"a}b"}` が最初の `}` で閉じる今の読み（A-4）
- プラグインの version（NFR6）

## 2. ビジネス要件

### 2.1 ビジネス目標

- 区切り語の位置の `${ ... }` を zsh と同じ区切り語として登録し、heredoc の終端行の後の対話起動を deny する。
- 区切り語の位置で zsh の読みを再現できない形は、誤った区切り語を登録せず判定不能にする。

### 2.2 対象ユーザー

該当なし（UI の無いフックの判定ロジックの修正）。

### 2.3 期待される効果

- 区切り語の位置の `${ ... }` の中の引用（`"`、`'`、`\`）を除いた行で heredoc の本文が閉じ、その後の対話起動が deny になる（AC1、AC2）。
- 区切り語の位置の引用されていない `$'` / `$"` で、誤った区切り語を登録しない（AC4、AC5）。

## 3. ユースケース

該当なし（UI の無いフックの判定ロジックの修正）。

### 4.2 機能詳細

#### FR1: 区切り語の位置の `${ ... }` の引用除去

`<<` または `<<-` の区切り語として読んでいる語の中で、引用の外にある `${` から閉じの `}` まで（FR2）の範囲に `_remove_range_quotes` と同じ規則を当てて、区切り語を登録する。範囲の外の部分の読みは変えない。

規則:

- 引用の外のバックスラッシュは除いて次の文字を残す（バックスラッシュと改行は両方除く）。
- `'` と `"` は除く。
- 単引用符の中はそのまま残す。
- 二重引用符の中のバックスラッシュは `$`、バッククォート、`"`、`\`、改行の前でだけ除く。
- `$( ... )` と `$(( ... ))` は、中の引用も含めて書かれたまま残す。
- それ以外の文字（入れ子の `${`、`#`、`:-` など）は書かれたまま残す。

例:

| 区切り語 | 登録する区切り語 |
|----------|------------------|
| `${v:-"x"}`、`${v:-'x'}`、`${v:-\x}` | `${v:-x}` |
| `${v:-"x"y}` | `${v:-xy}` |
| `${v#"x"}` | `${v#x}` |
| `foo${v:-"x"}bar` | `foo${v:-x}bar` |
| `${v:-$(echo "x")}` | 書かれたまま |

#### FR2: 区切り語の位置の `${ ... }` の閉じの探し方

区切り語の位置に限り、`${` の閉じの `}` は次のどれにも当たらない最初の `}` とする。

- 単引用符・二重引用符の中の `}`
- バックスラッシュで逃がした `}`
- 入れ子の `${ ... }` の閉じ（深さで数える）
- `$( ... )` / `$(( ... ))` の中の `}`

例: `${v:-"a}b"}` → `${v:-a}b}`、`${a:-${b:-"x"}}` → `${a:-${b:-x}}`。

次のときは判定不能にする。

- 入力が終わるまで閉じが見つからない
- 閉じる前に入力が終わる引用がある
- `$(` が閉じない

区切り語の位置にない `}` の探し方（`_dollar` が最初の `}` で閉じる今の読み）は変えない。

#### FR3: 区切り語の位置の `${ ... }` の中の引用されていない `$'` / `$"`

区切り語の位置の `${ ... }` の範囲の中に、引用の外の `$'` または `$"` があるときは判定不能にする。二重引用符の中の `$'` / `$"` と、バックスラッシュで逃がした `$` は判定不能の理由にしない（`_remove_range_quotes` と同じ）。

#### FR4: 区切り語の位置の `${ ... }` の外の引用されていない `$'` / `$"`

`<<` / `<<-` の区切り語として読んでいる語で、`${ ... }` の外にある引用されていない `$'` または `$"` は判定不能にする。語の途中にあるもの（例: `foo$'x'`）も同じ。二重引用符の中の `$'` / `$"` と、バックスラッシュで逃がした `$` は判定不能の理由にしない。今の読み（`$'x'` を書かれたまま登録する、`$"` の `$` を落とす）は区切り語の位置では使わない。

#### FR5: 区切り語の位置にない読みは変えない

次の読みは変えない。

- 区切り語の位置にない `${ ... }`（最初の `}` で閉じて、書かれたままの文字を dynamic な語にする）
- 区切り語の位置にない `$'` / `$"`
- `<<<` と `<` のリダイレクト先
- 区切り語の中の二重引用符の中にある `${ ... }`（今の引用付き単位の読み手で読む）
- 匿名関数の引数の `(`...`)` の範囲の引用除去（`_remove_range_quotes`）
- 区切り語の位置の `$( ... )`

#### FR6: 判定不能はチェックポイントの規則に従う

FR2 から FR4 で判定不能になった文字列は、今の `_Undecidable` の規則で扱う。最後のチェックポイントまでのコマンドは判定し、チェックポイントの無い文字列は出力しない。

- 区切り語の行より前の行にある `python3 -i` は、改行がチェックポイントになっていれば deny する。
- 判定不能な区切り語と同じ行にある `python3 -i` は判定しない（silent）。

#### FR7: 回帰テスト

`tests/test_codex_hook_interactive_guard.py` の `CASES` に、12 章のテストシナリオの各行を `(期待する判定, ラベル, コマンド)` の形で足す。期待する判定は `deny` か `silent`。`CASES` は今のテストで 2 つのコピーの両方に流す。

- [x] 区切り語の位置の `${ ... }` の閉じ: 区切り語の位置に限り、引用の中の `}` を飛ばす（`${v:-"a}b"}` → `${v:-a}b}`）。入れ子の `${...}`・エスケープ・`$( )` の中の `}` も区別し、閉じ位置を確定できなければ判定不能にする。区切り語でない位置の `}` の探し方は変えない。
- [x] 区切り語の位置の `${ ... }` の外の引用されていない `$'` と `$"`: 判定不能（出力なし）にする。
- [x] デザインステップ: 省略する（UI の無いフックの判定ロジックの修正で、デザインシステム候補が無い）。
- [x] zsh 5.9 での区切り語の終端（実測）: `${v:-"x"}`・`${v:-'x'}`・`${v:-\x}` → `${v:-x}`、`${v:-$'x'}` → `${v:-x}`、`${v:-$(echo "x")}` → 書かれたまま、`${v:-"a}b"}` → `${v:-a}b}`、`${a:-${b:-"x"}}` → `${a:-${b:-x}}`、外側の `$'x'` → `x`、外側の `$"x"` → `$x`。
- [x] A-2（確認済み）: TS11 と TS15 の終端は zsh 5.9 で実測して確かめた。`${v:-\}}` は `${v:-}}` で終わり、`${v:-$(echo "}")}` は書かれたままで終わる。あわせて `${v:-"$'"}` は `${v:-$'}`、`${v:-\$'x'}` は `${v:-$x}` で終わる。

### 14.2 前提

- A-1: 区切り語の位置の `${ ... }` の中の引用されていないバッククォートは、`_remove_range_quotes` と同じく普通の文字として扱う。閉じの探索でも特別に読まない（FR2 の列挙に入っていない）。TS34 の今の deny は変わらない。
- A-3: zsh は `${v:-$'x'}` と外側の `$'x'` を `x` として読むが、回答に従って判定不能にする（これらの形は見逃しとして受け入れる）。
- A-4: 区切り語の位置にない `${v:-"a}b"}` が最初の `}` で閉じる今の読みは、このフィーチャーの範囲外として残す。
- A-5: 判定不能はチェックポイントまでを判定する。これは今の `CASES` とモジュール docstring の marker テストで固定されている。
