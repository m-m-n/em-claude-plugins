# Task Plan: task0002 — Bump the em-workflow plugin version to 0.1.37

## Goal

`em-workflow/.claude-plugin/plugin.json` declares version `0.1.37`, so the
installed-plugin cache picks up this feature's protocol-document change.

## Requirements

FR6, NFR1, NFR3

## Scope

### Files to Create

None — this task creates no file.

### Files to Modify
- `em-workflow/.claude-plugin/plugin.json` — the version field only, raised
  from 0.1.36 to 0.1.37.

## Design

The plugin's version field is the sole signal Claude Code uses to decide
whether its extracted plugin cache is stale. A protocol-document change that
ships without a bump leaves the cache serving the previous text, so the bump is
part of the feature rather than release bookkeeping.

Increment size: patch, per this repository's convention (the change fixes
behavior in existing protocol prose and adds no capability).

Scope boundaries:

- The version field is the only thing that changes. The `name`, `description`
  and `author` fields, and the file's formatting (indentation, key order,
  trailing newline), stay as they are, so the diff is a single line.
- The repository-root `.claude-plugin/marketplace.json` carries no version
  field for the em-workflow entry, so there is nothing to synchronise there
  and the file must not be edited (FR6, IMPLEMENTATION.md D2).
- This task owns the bump exclusively (IMPLEMENTATION.md D1). No other task
  touches this file, and this task touches no other file.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR6): `em-workflow/.claude-plugin/plugin.json` parses as JSON and
      its version value is exactly the string `0.1.37`.
- [ ] AC-2 (FR6): every other key in that file (`name`, `description`,
      `author`) holds the same value as before the change, and the file's
      formatting is otherwise unchanged — the diff is the single version line.
- [ ] AC-3 (FR6, NFR1): the repository-root `.claude-plugin/marketplace.json`
      is unmodified, and the diff contains no file other than
      `em-workflow/.claude-plugin/plugin.json`.
- [ ] AC-4 (NFR3): `python3 -m unittest discover -s tests` exits 0 from the
      repository root, with no test skipped, deleted or modified by this task.

## Test Notes

- No new test is written for this task, and this is deliberate: an assertion
  pinning an exact version string would have to be edited on every future
  bump, and FR5 forbids adding new mechanical checkers. The existing sweep
  suite already covers the invariants that matter across bumps (the file
  parses as JSON, and the version compares strictly greater than the recorded
  baseline) — run it as the regression net.
- AC-1 is verified by the existing suite plus a direct read of the version
  field; AC-2 and AC-3 are verified by inspecting the task branch's diff
  before reporting completion (diff-scope checks are not automatable here
  without adding a checker).
- The TDD red-first cycle does not apply to a task whose whole delta is one
  configuration value with no new behavior to specify; record that explicitly
  in the task's test-docs entry rather than inventing a throwaway assertion.

  `.claude-plugin/marketplace.json`.
- Changing the plugin description to mention this feature.
- Adding a version-consistency check, hook or script (FR5).
- Choosing a minor/major increment, or bumping any other plugin in this
