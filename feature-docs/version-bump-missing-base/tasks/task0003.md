## Design

This task describes Shared Component C1 and writes parts (b) and (c) of C3 of IMPLEMENTATION.md. Both documents keep their existing language and style; nothing else in them changes.

### create.md 「動き」
Rewrite the description so that it states, in this order:
1. The triggers: push to main, and workflow_dispatch, which runs the version update only on main.
2. The push-time base determination: BEFORE when it is present in the clone; otherwise one fetch of BEFORE from origin; otherwise AFTER's first parent with a `::warning::` line (also when BEFORE is all zeros or malformed); a non-zero exit with no file change when AFTER has no first parent.
3. Changed-plugin detection: the nearest ancestor directory holding `.claude-plugin/plugin.json` of each changed file.
4. The comparison rules: AFTER lower than or equal to the base takes the greater version with its patch raised by 1 in both plugin.json and the marketplace entry; AFTER higher stays; a new plugin or a version not in MAJOR.MINOR.PATCH form is skipped; a marketplace entry without a version is not rewritten.
5. workflow_dispatch: the inputs plugin and min_version, and the outcomes of C1, including the non-zero exits for an unregistered plugin, a malformed min_version, and a different major or minor.
6. The bumped output and the pull request create/merge that follows it for both triggers.

Any statement that the workflow ends successfully with a skip when the base commit is unavailable is removed.

### README.md maintenance section
Order (a), (b), (c):
- (a): a short paragraph pointing to `.github/rulesets/README.md` by that repository-relative path for creating and confirming the ruleset main-non-fast-forward (D2). The steps themselves are not restated (C3).
- (b): a general sentence on recovering a lost Actions version-update commit with workflow_dispatch, followed by the concrete run for the lost em-workflow update: ref main, plugin em-workflow, and min_version set to the version that the lost update commit recorded. Read that value from the lost commit's subject, whose commit id and subject are recorded in the 発生事例 part of this feature's goal (the goal field of feature-docs/version-bump-missing-base/workflow.yaml). Write the commit id beside the value so a reader can trace it. Per A6 this procedure is the only place the value is written. Then the confirmation: the run's pull request is merged into main, and after pulling main, em-workflow's version in its plugin.json and in its marketplace.json entry are equal and greater than min_version. Also state that when the current version already exceeds min_version, the run changes nothing and succeeds.
- (c): update the marketplace in Claude Code and restart Claude Code; confirm that the installed cache under `~/.claude/plugins/cache/<marketplace>/em-workflow/` has a directory for the version from (b), and that files in it match main, for example the two em-workflow reference files named in the incident (references/phases/create-plan-phase.md and references/contracts/planner-contract.md).
