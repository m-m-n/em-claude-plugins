# Task Plan: task0001 — Workflow base fallback, workflow_dispatch recovery and regression tests

## Goal

`.github/workflows/plugin-version-bump.yml` bumps changed plugins even when the push's base commit is unavailable, can recover a lost bump through workflow_dispatch, stays byte-identical to the plugin-dev template, and a unittest module detects any regression of this behavior.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR10, NFR1, NFR2, NFR3, NFR4, NFR5

FR10 is covered here for everything except the ruleset content check. NFR5 holds for this plan: it and its criteria carry no concrete version value.

## Scope

### Files to Create
- `tests/test_plugin_version_bump_workflow.py` — regression tests: heredoc extraction, workflow and template identity, YAML wiring checks, and runs of the extracted heredoc in temporary repositories

### Files to Modify
- `.github/workflows/plugin-version-bump.yml` — base determination (FR1), comparison rules (FR3), the workflow_dispatch trigger and its handling (FR4), the bumped output and the pull request steps for both triggers (FR5)

## Design

This task implements Shared Component C1 of IMPLEMENTATION.md; the observable contract is stated there and is not repeated here. Tests follow C4 of IMPLEMENTATION.md.

### Workflow wiring (outside the heredoc)
- Keep the existing push trigger on main and the existing pull request create/merge steps. Add workflow_dispatch with the two required string inputs of C1.
- Restrict the version-update step (or its job) so that under workflow_dispatch it runs only when the ref is main (TM-4). Push runs are already limited to main by the trigger.
- The checkout makes the full history available, so AFTER's first parent is present whenever it exists. A missing first parent then means AFTER is a root commit, not a shallow-clone artifact.
- Map every value the script needs (the event name, BEFORE, AFTER, and the two dispatch inputs) to environment variables in the step's env block. The heredoc reads only these variables and GITHUB_OUTPUT; its text contains no Actions expression (TM-1).
- Condition the pull request create/merge steps only on bumped being non-empty, so that they run for both triggers (A3).
- The YAML holds exactly one heredoc in total (NFR2). If another step uses a heredoc today, rewrite that step without one.
- Remove the branch that prints a skip message and exits 0 when the base commit is unavailable.

### Script (the single heredoc)
Python standard library and git only (NFR1). One entry point that branches on the event name.

Push flow:
1. Check BEFORE's form: 40 hexadecimal characters and not all zeros. A value that fails the check goes to step 4 (A1).
2. If the commit exists in the clone, the base is BEFORE.
3. Otherwise attempt one fetch of BEFORE from origin. On success the base is BEFORE; on failure go to step 4. There is no retry.
4. Fallback: if AFTER has a first parent, the base is that parent, and a line starting with `::warning::` is printed to stdout naming the reason (BEFORE unavailable, all zeros, or malformed) and the commit used. If AFTER has no first parent, print the reason and exit non-zero before any file is touched.
5. Collect the files changed between the base and AFTER and map each to its nearest ancestor directory that contains `.claude-plugin/plugin.json`. A file with no such ancestor contributes nothing. A plugin whose plugin.json is absent at AFTER has nothing to write and is not bumped.
6. For each changed plugin, read the version at the base and at AFTER (the checked-out tree), compare them as integer triples and decide per C1. All decisions are made before any write.
7. Write the decided versions to plugin.json and to the same-named marketplace entry when that entry carries a version. Keep the serialization convention the current workflow uses for these files, so that the resulting diff shows only version values.
8. Write bumped to GITHUB_OUTPUT.

Dispatch flow:
1. Check that min_version fully matches three dot-separated non-negative integers with nothing before, between or after them (TM-3).
2. Check that plugin equals a name in the plugins list of marketplace.json exactly (TM-2). Only after that, locate the plugin's plugin.json from repository data (the registered entry), never by building a path from the raw input.
3. Read the current version. If it is not in MAJOR.MINOR.PATCH form, exit non-zero with no file changed (see IMPLEMENTATION.md Open Questions).
4. Decide per C1: current lower than or equal to min_version with equal major and minor writes min_version with its patch raised by 1 to plugin.json and to the marketplace entry when it carries a version; current lower than or equal to min_version with a different major or minor exits non-zero with nothing written (A2); current higher than min_version writes nothing and exits 0.
5. Write bumped to GITHUB_OUTPUT, empty when nothing was written.

Failure policy: every check that can end in a non-zero exit runs before the first file write, so a non-zero exit always leaves both JSON files exactly as they were. Each non-zero exit prints a message naming its reason (SPEC.md Error Codes ERR_001-ERR_004).

### Template
Once the workflow is final, the template becomes a byte-for-byte copy of it.

### Test fixture and heredoc extraction
- Heredoc extraction: find the heredoc openings in the workflow text, require exactly one, take its body up to its terminator line, remove the YAML block indentation, and run the body with the interpreter running the tests.
- Push cases: a bare repository inside the temporary directory, a seed history with a root marketplace.json and plugins that each hold `.claude-plugin/plugin.json`, and a clone made with git clone --no-local. The extracted heredoc runs in the clone with the environment variable names the workflow step defines, and GITHUB_OUTPUT points to a file in the temporary directory.
- Dispatch cases: a temporary repository holding marketplace.json and plugins is enough; no bare repository is needed.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With BEFORE present in the clone (TS-4), and with BEFORE absent from the clone but served by the bare repository after being removed from every ref, with uploadpack.allowAnySHA1InWant enabled on the bare repository (TS-5), the script uses BEFORE as the base, raises the patch of each changed plugin per C1, prints no `::warning::` line and exits 0; in the TS-5 case it attempts the fetch exactly once.
- [ ] AC-2: With BEFORE absent from the bare repository as well (TS-6, after exactly one failed fetch attempt), all zeros (TS-7), or not 40 hexadecimal characters, the script uses AFTER's first parent as the base, prints a line starting with `::warning::` to stdout, bumps the changed plugins and exits 0.
- [ ] AC-3: When BEFORE cannot be the base and AFTER is a root commit (TS-8), the script exits non-zero and plugin.json and marketplace.json are byte-identical to their state before the run; neither the workflow nor the template contains a branch that ends with exit 0 because the base commit is unavailable.
- [ ] AC-4: For changed plugins (TS-10, TS-11, TS-12, TS-14): AFTER lower than or equal to the base writes the greater version with its patch raised by 1 to plugin.json and to the same-named marketplace entry; AFTER higher leaves the version unchanged; a plugin without plugin.json at the base, or with a version not in MAJOR.MINOR.PATCH form, is not bumped; a marketplace entry without a version is not rewritten; a change outside every plugin bumps nothing; a change in a nested directory is attributed to its nearest plugin; bumped lists each bumped plugin as name@version separated by commas, and is empty when nothing is bumped.
- [ ] AC-5: The reproduction scenario (TS-9): after an update commit is added on main and main is then replaced by a merge commit that does not contain it, running the script for the next push leaves AFTER's version greater than the base's version, with plugin.json and marketplace.json holding the same value; this holds both when the bare repository serves the dropped commit and when it does not.
- [ ] AC-6: workflow_dispatch (TS-13): current lower than or equal to min_version with equal major and minor leaves plugin.json and marketplace.json both holding min_version with its patch raised by 1, and bumped names it; current higher than min_version changes no file, leaves bumped empty and exits 0; current lower than or equal to min_version with a different major or minor exits non-zero with no file changed; an unregistered plugin, including a value shaped like a relative path, exits non-zero with no file changed (TM-2); a malformed min_version, including one with trailing text and one containing a line break, exits non-zero with no file changed and writes no bumped value (TM-3).
- [ ] AC-7: The workflow YAML (TS-15, TS-16, TS-17) declares workflow_dispatch with the required inputs plugin and min_version; runs the version-update step under workflow_dispatch only when the ref is refs/heads/main (TM-4); conditions the pull request create/merge steps on bumped being non-empty without limiting them to push; and defines in the step's env every variable the heredoc reads for the event name, BEFORE, AFTER and the dispatch inputs, while the heredoc body contains no Actions expression (TM-1).
- [ ] AC-8: The workflow YAML contains exactly one heredoc (TS-1); the workflow and the template are byte-identical (TS-2); the heredoc imports only standard-library modules and runs no external command other than git (TS-18); the new test module follows the C4 isolation rules (TS-19); `python3 -m unittest discover -s tests` exits 0; and this task changes no version field in any plugin.json or in .claude-plugin/marketplace.json (TS-22).

## Test Notes

- Write the tests first. Against the current workflow, the fallback cases (TS-6, TS-7) and the dispatch cases should fail, which shows the tests detect the reported behavior.
- Unit tests on the YAML text: AC-7, the second half of AC-3, and the heredoc count, file identity and import checks of AC-8. The import check compares the heredoc's imported top-level modules against the interpreter's list of standard-library module names. The "only git" half of TS-18 is checked by review.
- Integration tests on temporary repositories: AC-1 to AC-6.
- TS-5 fixture: commit and push, then move main in the bare repository away from that commit without garbage collection, and clone only after that, so the clone lacks the commit while the bare repository still stores it. Enable uploadpack.allowAnySHA1InWant on the bare repository only in the cases that need the commit served.
- TS-6 and TS-8: use a 40-hex value that exists in no repository.
- Fetch attempt count (AC-1, AC-2): observe it through git's own trace output written to a file inside the temporary directory. If this proves unreliable, report it as a plan deviation rather than dropping the check.
- TS-9: run the scenario twice, once with the dropped commit served by the bare repository and once without; assert in each that the written version exceeds the base's version and that both JSON files agree.
- "No file changed" means the bytes of plugin.json and marketplace.json read before the run equal those read after it.
- bumped with several plugins: compare its items as a set, since the order follows the current workflow's order.
- Fixture versions inside the temporary repositories are test data, not plan text.
