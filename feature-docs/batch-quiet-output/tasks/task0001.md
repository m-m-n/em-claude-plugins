# Task Plan: task0001 — Define the batch output-suppression discipline in batch-mode.md

## Goal

`em-workflow/references/batch-mode.md` becomes the sole definition site of
the batch output-suppression discipline — activation condition, suppressed
scope, exceptions, the non-terminal marker line, and the audit-item source
map — and `em-workflow/references/batch-terminal-line.md` gains one
non-normative cross-reference that leaves its contract untouched.

## Design

Add ONE new level-2 section to `batch-mode.md`, as the document's last
level-2 section (IMPLEMENTATION.md D3). It carries, in this order:

1. **Activation** — the discipline applies exactly when the current
   invocation's arguments contain `--batch`, consistent with the document's
   existing "Purpose & activation" rule; the `batch` block never activates
   it; an interactive launch is unaffected (FR1, NFR1).
2. **What is suppressed** — the eight kinds of main-context output SPEC FR4
   lists: phase start/completion narration; forwarding of sub-agent reports
   (implementer / reviewer / each worker); per-step interim summaries; the
   review phase's Phase R6 report body; the reconcile results the implement
   wake turn enumerates; the verify result-summary body; design-step
   progress; the running presentation of Step A.5's command-approval
   results.
3. **What suppression does NOT touch** — main-context assistant text only:
   file writes and commits, gate resolution, the auto-rework caps, the
   counters and workflow.yaml status transitions all follow the same path as
   before (FR9, FR10).
4. **Non-terminal turns** — a turn that ends without the run reaching any
   terminal state the terminal-line contract defines emits the marker line
   and nothing else. The turns in scope are stop condition 5's wait turn,
   the implement phase's launch turn, and its wake turn (FR2).
5. **The marker line** — the format fixed in IMPLEMENTATION.md D1: the
   prefix literal, one ASCII space, then exactly two `key=value` fields in
   fixed order (`phase`, `point`) with their value domains, always one
   physical line. State the non-collision property relationally per D2 —
   name `references/batch-terminal-line.md`, never reproduce its prefix
   literal, and state that the contract's "absence of the line means an
   abnormal outcome" signal is preserved (FR3, NFR2).
6. **Exceptions** — three, stated once each: (a) a stop or abort turn keeps
   its full output (cause / affected paths / recovery hints), expressed as a
   set-level rule over the terminal-line contract's stop-point coverage
   table per D7, without enumerating stop points individually and without
   any reason-code literal (FR6, NFR3); (b) Step C's completion processing
   emits its final report in full, with the terminal line appended after it
   (FR5); (c) a `--once` phase-boundary turn emits the terminal line and
   withholds all other narration (FR8).
7. **Audit-item source map** — a table binding each audit item `## Reporting`
   requires to its persisted source, exactly as IMPLEMENTATION.md D4 fixes
   them, including the newly defined source for the auto-approved command
   strings (FR11).

`## Reporting` itself gains one sentence pointing at that map; its audit-item
list, wording and order stay as they are (FR5).

In `batch-terminal-line.md`, add exactly one sentence inside the existing
`## No line on a wait turn` section stating that what such a turn emits
INSTEAD is owned by `references/batch-mode.md`. No heading is added,
renamed, reordered or removed; no field, value domain, reason code, stop-point
row or emission condition changes; the marker prefix literal does not appear
there (FR7, IMPLEMENTATION.md D6(c)).

Constraints that already hold over these two files and must keep holding:
IMPLEMENTATION.md D6 (a)-(d).

## Test Notes

`tests/test_batch_quiet_output_discipline.py` is a unit-level
document-contract module over raw file text, following
`tests/test_batch_stop_contract.py`'s form: standard library only, no import
from another test module, constants re-declared locally. It reads both
documents, so it may hold BOTH prefix literals — that is how AC-4's
non-collision check is realized (TS-3) while the documents themselves stay
literal-free of each other's prefix.

Every new matcher (section slicer, marker-format matcher, non-collision
matcher, exception set-level-rule matcher, source-map matcher) carries a
negative proof over a forged sample plus a non-vacuity guard showing the
forged sample is well-formed and found. Regression assertions over retained
pre-change wording (the ten-row gates table, the Reporting item list, the
contract document's headings) are pure regression guards and need no negative
proof.

TDD-awkward: there is no runtime behaviour to exercise, so "red" means the
assertion fails against the current document text. Write the module first and
observe each new assertion failing before editing either document.
