# Task Plan: task0003 — Wire the phase protocols to the suppression discipline

## Goal

`implement-phase.md`, `review-phase.md` and the two phase protocols under
`references/phases/` apply the batch output-suppression discipline at their
own sites by reference, and the implement wake phase's declined-deviation
audit record gains a persisted channel so nothing auditable is lost when the
wake turn stops narrating.

## Requirements

FR2, FR4, FR6, FR9, FR10, FR11, FR12, NFR1, NFR3, NFR4

## Design

All edits follow IMPLEMENTATION.md D3's pointer convention: name
`references/batch-mode.md`, state WHERE the rule applies, never restate the
marker format, the suppressed-scope list or the exception list. No existing
rule, table row, heading or gate reference is rewritten or removed, and no
`gate_id` mention is added.

1. **implement-phase.md I.2.a (launch turn)** — the existing "End the turn
   immediately after launching" instruction gains a batch clause: in a
   `--batch` run that turn's final assistant message is the non-terminal
   marker line the discipline defines and nothing else (FR2). The launch
   guard, journal writes and the approval gate are untouched (FR9, FR10).
2. **implement-phase.md I.2.b (wake turn)** — same clause for the wake turn,
   plus: the reconcile enumeration, the cleanup listing and the refill
   narration are withheld from the main context in batch (FR4), while the
   reconcile itself, the wake commit and the worktree cleanup are unchanged
   (FR9).
3. **implement-phase.md deviation records** — the admitted-deviation audit
   record is unchanged (the appended `files` entry plus the wake commit). The
   DECLINED-deviation record moves, for a `--batch` run, from that wake turn's
   own report to the wake commit's message, naming which evidence part failed;
   the existing requirement that a batch run also list it in the run report is
   satisfied from that channel (IMPLEMENTATION.md D5, FR11). Interactive runs
   keep reporting it in the wake report exactly as today (NFR1).
4. **implement-phase.md I.2.c (failed handling)** — the drain and retry
   narration is withheld in batch (FR4), while the second-failure phase abort
   keeps its full output as a stop under the discipline's stop/abort
   exception (FR6, NFR3). The `implement` step's `failed` write and its
   commit are unchanged (FR9), and the batch gate behaviour (auto-retry once,
   abort on the second failure) is unchanged (FR10).
5. **review-phase.md Phase R6** — the Japanese report body is not emitted
   into the main context in a `--batch` run (FR4); the round record
   `reviews/roundN.yaml` keeps exactly the content it has today (FR9), which
   is what keeps deferred findings auditable from the Step C report.
6. **review-phase.md Phase R5** — one clause confirming that the batch
   auto-rework / defer-at-cap behaviour, its counters and its round-record
   writes are unchanged, and that any abort taken there falls under the
   stop/abort exception (FR6, FR10).
7. **phases/create-spec-phase.md and phases/create-plan-phase.md** — at each
   document's completion site, one pointer sentence: in a `--batch` run this
   phase's completion narration is withheld per the discipline, while its
   artifact writes, patch application, commits and status transitions are
   unchanged (FR4, FR9, FR12).

Constraint (IMPLEMENTATION.md D6): the marker line's prefix literal and every
terminal-line literal listed in D6(b) stay out of all four documents — each
names the owning document instead.

## Test Notes

`tests/test_batch_quiet_output_phase_wiring.py` is a unit-level
document-contract module over the raw text of the four documents, standard
library only, no import from another test module, constants re-declared
locally. The marker prefix literal is declared locally for ABSENCE checks
only — this module never asserts what `batch-mode.md` defines, since
task0001's file may not have merged into this worktree yet.

New matchers (pointer-site matcher, marker-only-turn matcher, withheld-with-
unchanged-writes matcher, decline-channel matcher) each carry a negative proof
over a forged section plus a non-vacuity guard. Assertions that merely pin
retained pre-change wording (gate rows, R5 cap wording, journal rules) are
pure regression guards and are exempt.

TDD-awkward: no runtime behaviour exists; "red" means the assertion fails
against the current document text. Write the module first and observe each new
assertion fail before editing.
