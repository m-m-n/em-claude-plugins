# Task Plan: task0005 — Persist batch audit records instead of routing them to output or commit messages

## Provenance

- `source`: review
- `source_ids`: `1cd0e6ab9dba1fef`, `48ac1e2b5f7d90c3`, `b0f4c7d2e819a635`,
  `2a6b8f0c3d5e7192`, `9d1f4e6a2c8b0537`, `7e3a95c14b0d82ff`
- `review_round`: 1

All six findings share one root cause: two batch audit records — the
non-packet unlisted-gate fallback resolutions and the implement wake phase's
declined `files` deviations — were routed to channels that are not persisted
state (an unsuppressed output line; a batch-only commit message body), which
contradicts FR11's artifact sourcing, FR4/FR2's suppression scope and FR9's
"file writes and commits are unchanged". One channel fixes all six.

## Goal

Both batch audit records land in a persisted, committed source under
`feature-docs/{feature}/phase-state/`, so Step C can rebuild the batch final
report from artifacts alone across `--once` boundaries, context compaction
and resumption — and the fourth suppression exception plus the batch-only
wake commit-message construction, which existed only to carry those records,
are removed.

## Design

### 1. The persisted source (new shared contract; IMPLEMENTATION.md D9)

`feature-docs/{feature}/phase-state/batch-audit.yaml` — one file per feature,
not owned by any single phase, following the precedent
`references/phase-state.md` already sets with `backfill.yaml` ("no phase file
of its own to live in"). It holds exactly the batch audit records that no
phase-state file owns:

- an `answers`-shaped entry per non-packet unlisted-gate fallback resolution
  (the review phase diff-size gate; the per-command approval fallback), whose
  `resolution_note` carries gate site / options / choice / whether Codex was
  consulted — the same fields `## Reporting` already requires;
- one entry per declined `files` deviation from the implement wake phase,
  naming the `task_id` and which of the three evidence parts was missing or
  unresolved.

Constraints this file must satisfy:

- It lives under `phase-state/`, so it is inside FR11's already-named source
  (`phase-state/*.yaml`'s `answers` / `resolution_note`) and inside
  `commit-docs.sh`'s existing `ARTIFACT_PATHS` — no script change.
- Its entries reuse the existing `answers` entry shape; no field of the
  per-phase schema changes, and no existing phase-state file's content,
  write frequency or write timing changes (FR9).
- It is written at resolution time and committed no later than the writing
  phase's next existing `commit-docs.sh` call. It is never itself a reason to
  create a commit that would not otherwise happen (FR9). For the wake
  decline that call is I.2.b step 3's own wake commit, which — because the
  file now carries a diff — also closes the case where a decline produced no
  `workflow.yaml` change and the commit was a nothing-to-commit no-op.
- Records are appended; an existing record is never rewritten or removed.

### 2. batch-mode.md

- The source map's `Every unlisted-gate fallback resolution` row's Persisted
  source becomes the file above, named as a `phase-state` path with its
  `answers` / `resolution_note` fields, matching the row above it.
- The Exceptions section's fourth bullet (a turn that resolves a non-packet
  unlisted-gate fallback emits that resolution line unsuppressed) is deleted.
  The exception set returns to exactly the three the SPEC defines — stop /
  abort, Step C, the `--once` boundary — so a non-terminal turn again ends
  with one marker line and nothing else (FR2, FR4).
- The two Non-packet gates rows whose Batch behavior ends "Record the
  resolution in the run report" instead name the persisted record site, with
  the run report stated as assembled FROM it. Both rows keep every phrase a
  pre-existing module pins (`unlisted-gate fallback`,
  `question-resolution.md`, `per literal command string`), the table keeps
  exactly ten data rows, and its catch-all paragraph is untouched.
- The `## Batch quiet output` section gains no second table: a pre-existing
  assertion counts every table row in that section against `## Reporting`'s
  six audit items.

### 3. implement-phase.md

- I.2.b step 3's commit instruction returns to one mode-independent
  `commit-docs.sh` call with the single-line subject it had before, with no
  batch-only message body and no `DECLINED …` line anywhere; `$RECONCILE_TIP`
  keeps its role as `expected_base_tip`.
- The wake phase's "Batch mode" paragraph states that a decline's audit
  record is written to the persisted source of section 1 in the same wake
  commit, and that the `--batch` run-report obligation is satisfied by
  reading it from there rather than from this wake phase's own (suppressed)
  report. The admitted-deviation record and the interactive behaviour stay
  exactly as they are (NFR1), and the pre-existing "Where the decision
  persists" paragraph and run-report-obligation sentence stay intact.

### 4. phase-state.md

One new subsection, sibling in spirit to "Backfill discovery persistence":
what the file is for, its shape, who writes it, when it is committed, and
that it introduces no change to any per-phase file's schema. The File layout
block gains the file with a one-line "present only in a `--batch` run that
recorded one of these" comment. No existing field, table row or rule is
edited.

### 5. Reader side

`skills/develop/SKILL.md` Step C already assembles the audit items from
batch-mode.md's source map and already delegates the decline source to
`implement-phase.md`; both pointers keep resolving after this change, so
SKILL.md is deliberately NOT in this task's file set.

### 6. Version bump (FR13)

Files under `em-workflow/` change again, so both registries move to the same

stays green without modification.

## Test Notes

`tests/test_batch_quiet_output_audit_persistence.py` is a unit-level
document-contract module over the raw text of `batch-mode.md`,
`implement-phase.md` and `phase-state.md`: standard library only, no import
from another test module, every constant re-declared locally (including the
record file's path literal, which is this task's own new shared literal).

Red first: AC-1's row assertion is already red in the current tree
(`TestAuditItemSourceMap.test_source_map_has_one_row_per_audit_item`,
`item='unlisted-gate fallback resolution'`); that module must NOT be edited —
watching it turn green unmodified is this task's primary red-to-green signal.
For AC-2 and AC-4 the new module's absence assertions must be observed
failing against the current text before any edit.

Each new matcher (persisted-source-row matcher, exception-set matcher,
mode-independent-commit matcher, decline-persistence matcher) carries a
negative proof over a forged sample plus a non-vacuity guard that the forged
sample is well-formed and actually found. Assertions that pin retained
pre-change wording (the ten gate rows, the catch-all, the "Where the decision
persists" paragraph, phase-state.md's existing fields) are pure regression
guards and are exempt.

TDD-awkward: there is no runtime behaviour here, so "red" means the assertion
fails against the current document text.
