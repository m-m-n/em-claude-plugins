## Goal

In both copies of `codex-hook-interactive-guard.py`, the `#` comment-start decision of `_skip_substitution` reads the newline that ends a comment as an unescaped newline, even when the comment's last character is a backslash. A `#` at the start of the next line then starts a comment again, as it did at the base commit, and the interactive launch after the substitution is denied.

## Design

Shared contract: IMPLEMENTATION.md D4. The comment-start decision itself (effective previous character, escaped characters, the sites) stays as task0001 defined it; this task changes only how a newline in the look is classified.

### The defect

The look in front of a `#` leaves out every newline that follows an odd run of backslashes, as a continuation pair. A backslash inside a comment is comment text, so the newline that ends that comment is a plain newline: bash, zsh and dash do not join the lines. The reader itself ends a comment at the first newline. The look does not know this, so in `: a #b\<newline># x` it leaves out the newline, reaches `b`, and reads the second `#` as a word character. The quotes and parentheses on that line are then read as code.

### The comment-end position

- The reader keeps one value: the index of the newline that ended the last comment it read. It starts as "none".
- Every branch that reads a comment sets it to the index of the newline that ends that comment, in the same step. When the comment runs to the end of the input there is no such newline and the value is left as it is. This covers every site of IMPLEMENTATION.md D2 that reads a comment: the general comment branch of p and 8, the pattern and the group, the outermost entry of w, and the waiting phases 1, 3, 4, 5 and 7.
- The value is an absolute index into the string.
- In the look in front of a `#`, a newline whose index equals the value is an unescaped newline, whatever run of backslashes is in front of it: the look stops there and the `#` starts a comment. Every other newline is classified as task0001 defined.
- One value is enough. The look crosses only backslashes and newlines, so a comment that ends inside the stretch it crosses is the last comment the reader read.
- The rule-9 re-read restores the value to its value at the `((`, like every other value the reader keeps (IMPLEMENTATION.md Shared Components).
- The per-entry saved state of the stack does not hold the value.

### Bounded work (NFR1)

Recording the value is one assignment per comment, and the comparison is one per newline the look crosses. The look itself is unchanged, so the work stays within a constant times the string length.

### Documentation (FR7)

- The `_skip_substitution` docstring paragraph on the comment-start decision, and the docstring or comment of the helper that makes it, state that the decision reads the one comment-end position kept while reading, and that the newline that ends a comment is never part of a continuation pair.
- Remove the sentences that say the decision keeps no state, "It keeps no state" and "The decision carries no state through the reading" included.
- The comments at each comment branch describe the recording.
- Keep every marker pinned in sentences this task does not change.
