### The comment-start decision

At a site where a comment can start, a `#` starts a comment exactly when its effective previous character is a space, a tab, a newline, `;`, `&`, `|` or `(`, and that character is not escaped. Otherwise the `#` is a word character.

- **Effective previous character**: the character right before the `#` once every continuation pair directly in front of the `#` is left out, a run of several pairs included. A continuation pair is a newline that is the second character of a backslash pair. Examples: in `: a\<newline>#x` the effective previous character is `a`, so the `#` is a word character. In `: \<newline>#x` it is the space, so the `#` starts a comment.
- **Escaped**: a character is escaped when it is the second character of a backslash pair, that is, when the run of backslashes directly in front of it has odd length. `\ #` has an escaped blank, so the `#` is a word character. In `\\ #` the two backslashes form one pair, the blank is not escaped, and the `#` starts a comment.
- **Unchanged**: a `#` whose effective previous character is `)`, `<`, `>` or any other character stays a word character, as now. The one exception is rule 3: in phase 7 a `)` that closes the pattern still lets the `#` start a comment.

### Sites

All the sites below use the one decision, so they cannot drift:

1. The word-start condition of the lists p and 8: a `#` that starts a comment does not begin a word.
2. The general comment branch of p and 8. It sees the same `#` as site 1 in the same step, and the two must agree.
3. The pattern (6) and the group (g).
4. The outermost entry of the word list w.
5. The waiting phases 1, 3, 4, 5 and 7, with phase 7's rule-3 acceptance of `)` kept.

These contexts keep their reading, and a `#` never starts a comment in them: the nested entries of w, the word parenthesis W (rule 10), double quotes, backticks, `${ ... }` and the arithmetic contexts.

### No carried state, bounded look (NFR1)

- The decision is computed only from the characters directly in front of the `#`. It carries no state through the reading (IMPLEMENTATION.md Shared Components), so the rule-9 re-read, the per-entry saved state and the initialisation before the main loop are not touched.
- The look crosses only the continuation pairs directly in front of the `#` and the run of backslashes in front of the effective previous character. Every other character stops it.
- That stretch belongs to one `#` only: any `#` further on is itself a character that is not part of a pair, so its own look stops there. The work summed over the skip is therefore within a constant times the string length.
- A look that runs back to the start of the chunk, or anything else unbounded, is not acceptable.
- A helper used for the decision keeps no state, raises nothing and calls no other `_Parser` method. The existing structural tests must still pass: no recursion, and nothing reachable from the skip is the skip again or one of the readers.
