# Task Plan: task0001 — Isolate MergePrTestCase from inherited GIT_ variables

## Goal

Running `tests/test_merge_pr.py` never writes to a git repository outside each
test's temporary directory, even when the invoking environment carries
`GIT_`-prefixed variables (for example inside a git hook), and a regression
test in the same file detects any loss of that isolation.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `test-docs/merge-pr-test-git-env-isolation/task0001.tests.yaml` — the per-task test record the implement protocol requires.

### Files to Modify
- `tests/test_merge_pr.py` — environment construction in the shared fixture setup, plus one new regression test class.

## Design

### Environment construction in MergePrTestCase.setUp (FR1, FR2, FR4)

Responsibility: build `self.env` (passed to the `merge-pr.py` child) and
`self.real_env` (derived from `self.env`, passed to the fixture-building git
calls) so that neither carries a variable inherited from the invoking process
whose name starts with `GIT_`.

Processing order:

1. Copy the process environment.
2. Remove from the copy every key whose name starts with exactly `GIT_`, in
   the same form `tests/test_merge_preflight.py` uses for its git environment:
   scan a snapshot of the key list and delete each key that has the prefix.
   The condition is that prefix test alone. No other prefix or key is added
   to it (for example `XDG_CONFIG_HOME`, `EM_WORKFLOW_APPROVALS`; SPEC.md A3).
3. Apply the existing removals of `GH_REPO`, `GH_TOKEN`, `GITHUB_TOKEN` and
   `EM_WORKFLOW_MERGE_PR_GH_TIMEOUT`, unchanged.
4. Add the existing values of `PATH`, `HOME`, `GIT_CONFIG_NOSYSTEM`,
   `GH_STUB_DIR` and `PYTHONDONTWRITEBYTECODE`, unchanged, and add
   `GIT_CONFIG_GLOBAL` set to `os.devnull` next to `GIT_CONFIG_NOSYSTEM`.
5. Derive `self.real_env` from `self.env` as today (only `PATH` differs).

Postconditions after setUp, whatever the invoking environment holds:

- The set of `GIT_`-prefixed keys in `self.env` is exactly
  {`GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL`}, and the same holds for
  `self.real_env`.
- `GIT_CONFIG_GLOBAL` equals `os.devnull` in both.
- Every other key and value setUp produced before this task is produced
  unchanged. The fixture repository keeps receiving `user.name`, `user.email`
  and `commit.gpgsign` through its local git configuration. No
  `GIT_AUTHOR_*` or `GIT_COMMITTER_*` variable is added to setUp's
  environment (SPEC.md A4).

### Regression test class (FR3, NFR3)

One new TestCase class in `tests/test_merge_pr.py`. It does not run
MergePrTestCase's fixture for itself. Each check creates a separate
MergePrTestCase instance and drives that instance's setUp and its registered
cleanups inside the same process. The suite is never started as a
subprocess (SPEC.md A1).

Isolation rules for the regression test itself (NFR3):

- Every path it creates, the decoy repository included, lives inside its own
  temporary directory, which a cleanup removes.
- Its own git calls (building the decoy, recording the decoy, reading the
  driven instance's fixture repository) use an explicit environment of its
  own: a copy of the process environment with every `GIT_` key removed, with
  no system configuration and with the global configuration pinned to
  `os.devnull`. Each call addresses its repository explicitly, so a decoy
  variable or an outer `GIT_` variable cannot redirect it.
- It changes the process environment only through a scoped
  environment-patching mechanism from the standard library (SPEC.md NFR3
  names one), and the process environment is restored when the scope ends,
  also when an assertion inside it fails.
- The driven instance's cleanups run even when an assertion fails before the
  check reaches them.

Flow of the decoy-repository check (TS-1):

1. Create the own temporary directory and the decoy repository inside it,
   with exactly one commit. The decoy's local configuration holds no
   `user.name`, `user.email` or `commit.gpgsign` entry once it is built:
   the identity of the decoy's one commit comes from the regression test's
   own environment for that call, not from the decoy's configuration. A later
   appearance of any of those entries can then come only from setUp.
2. Record the decoy's refs (every ref with its object id), HEAD, and local
   configuration listing.
3. Inside the scoped environment change, set `GIT_DIR` to the decoy's git
   directory, `GIT_WORK_TREE` to the decoy, and `GIT_INDEX_FILE` to the
   decoy's index file (SPEC.md A2).
4. Inside that scope, run the driven instance's setUp. While its temporary
   directory still exists, read whether the fixture repository under that
   temporary directory has a commit with the subject `initial`, reading it
   with the regression test's own environment. Then run the driven
   instance's cleanups.
5. After the scope ends, record the decoy again in the same way and compare
   it with step 2.

Flow of the environment-key check (TS-2): inside a scoped environment change
that sets `GIT_DIR`, `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_PARAMETERS` (a
well-formed configuration entry), run the driven instance's setUp, read the
`GIT_`-prefixed key sets and the `GIT_CONFIG_GLOBAL` value of its `self.env`
and `self.real_env`, then run its cleanups. Every path-valued variable this
check injects points inside the regression test's own temporary directory.
The same driven setUp can also carry the FR4 check of AC-6: inject the four
removed variables and read the preserved values.

Because every injected path points inside the regression test's own
temporary directory, the red run against the unmodified setUp (AC-4) also
writes only there.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (FR1, TM-1) After setUp runs under a process environment that
  holds `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_CONFIG_GLOBAL` and
  `GIT_CONFIG_PARAMETERS`, the set of `GIT_`-prefixed keys in both
  `self.env` and `self.real_env` is exactly {`GIT_CONFIG_NOSYSTEM`,
  `GIT_CONFIG_GLOBAL`}. The removal condition is the `GIT_` prefix alone, in
  the form `tests/test_merge_preflight.py` uses. (TS-2)
- [ ] AC-2: (FR2, TM-2) After setUp, `GIT_CONFIG_GLOBAL` equals `os.devnull`
  in both `self.env` and `self.real_env`, also when the process environment
  held a different `GIT_CONFIG_GLOBAL`, and `GIT_CONFIG_NOSYSTEM` is `1`.
  (TS-2)
- [ ] AC-3: (FR3, TM-1) With `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE`
  pointing at a decoy repository that has one commit, running setUp and the
  cleanups of a MergePrTestCase instance leaves the decoy's refs, HEAD and
  local configuration listing identical to the record taken before. The
  decoy has no new commit and no `user.name`, `user.email` or
  `commit.gpgsign` entry. The fixture repository under the driven instance's
  temporary directory has a commit with the subject `initial`. (TS-1)
- [ ] AC-4: (FR3) Run against setUp as it was before this task, the
  regression test fails. After the change it passes. Both runs are recorded
  in the task's test record as the red and green observations.
- [ ] AC-5: (NFR3, TM-3) The regression test creates the decoy and every
  other path it injects inside its own temporary directory, using an
  environment without any `GIT_` key, and changes the process environment
  only through a scoped mechanism. After each of its tests ends, passing or
  failing, the process environment equals its state before that test. When
  the TS-1 flow runs while the process environment already carries
  `GIT_DIR` and `GIT_WORK_TREE` pointing at a second repository inside the
  regression test's own temporary directory, that second repository's refs,
  HEAD and local configuration listing are unchanged afterwards.
- [ ] AC-6: (FR4) After setUp runs under a process environment that also
  holds `GH_REPO`, `GH_TOKEN`, `GITHUB_TOKEN` and
  `EM_WORKFLOW_MERGE_PR_GH_TIMEOUT`, none of the four is in `self.env`.
  In `self.env`, `PATH` starts with the driven instance's stub binary
  directory, `HOME` is the driven instance's home directory, `GH_STUB_DIR`
  is its stub directory, and `GIT_CONFIG_NOSYSTEM` and
  `PYTHONDONTWRITEBYTECODE` are `1`. `self.real_env` has the process
  environment's `PATH`. `python3 -m unittest tests.test_merge_pr` passes in
  full when the environment holds no `GIT_` variable. (TS-3)
- [ ] AC-7: (NFR1, NFR2, NFR4) Apart from the task's own test record, the
  only changed file is `tests/test_merge_pr.py`. No file under
  `em-workflow/` changes. The test code uses only the Python standard
  library, and no test touches the network or the real `~/.claude`.

## Test Notes

- All criteria are unit tests in `tests/test_merge_pr.py`, run in-process.
  AC-1, AC-2 and AC-6 can share the TS-2 setUp run. AC-3 is the TS-1 check.
  AC-5's restoration can be asserted by comparing the process environment
  before and after the scoped change. AC-5's outer-variable case can reuse
  the TS-1 flow inside one more scoped change that is entered before the
  decoy is built.
- Write the TS-1 and TS-2 tests first and observe them fail against the
  unmodified setUp (AC-4 red). In that red run the decoy is reinitialized
  and receives setUp's configuration and commit. This is expected, and it
  stays inside the regression test's own temporary directory.
- Read the fixture repository in TS-1 with the regression test's own
  environment, not with the driven instance's git helper. Before the fix,
  that helper's environment still points at the decoy, and the `initial`
  check would pass against the decoy instead of failing.
- AC-6's full-suite run and the repository-wide
  `python3 -m unittest discover -s tests` both pass with no `GIT_` variable
  in the environment. AC-7 is checked against the task's diff.

## Out of Scope

- Removing any prefix or key other than `GIT_` (for example
  `XDG_CONFIG_HOME`, `EM_WORKFLOW_APPROVALS`).
- Adding `GIT_AUTHOR_*` / `GIT_COMMITTER_*` to setUp's environment, or
  moving the fixture identity out of local git configuration.
- Changes to `em-workflow/scripts/merge-pr.py` or any other file under
  `em-workflow/`, and changes to other test modules
  (`tests/test_merge_preflight.py` is read as the reference form only).
- Running the suite as a subprocess from the regression test.
